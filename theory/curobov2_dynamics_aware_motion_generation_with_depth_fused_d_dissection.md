### 1.2 关键机制 (Key Mechanism)

**为什么用 B 样条？**  
传统方法将轨迹参数化为每个 timestep 的关节位置，需要显式的加速度/加加速度正则化来保证平滑性。B 样条的局部支撑性意味着改变一个控制点只影响相邻 4 段曲线，且三次 B 样条天然保证 C² 连续（位置、速度、加速度都连续）。这带来两个好处：
1. 优化变量大幅减少（控制点数 << timestep 数）
2. 无需显式平滑约束，优化问题条件数更好

**为什么 GPU 原生 ESDF 重要？**  
现有方案（如 nvblox）只在稀疏分配的块内计算距离，工作空间大部分区域没有距离信息。cuRoboV2 用 Parallel Banding Algorithm (PBA+) 按需生成稠密 ESDF，实现 O(1) 距离查询，且整个流水线可 CUDA Graph 捕获（无动态分支）。

**为什么需要可微分逆动力学？**  
大多数规划器把扭矩约束当作事后检查，导致规划 - 执行循环。cuRoboV2 将 RNEA（Recursive Newton-Euler Algorithm）嵌入优化循环，梯度可反向传播到轨迹控制点，实现真正的动力学感知规划。

⚡ **Eureka Moment**：**轨迹的 B 样条表示 + 可微分 RNEA 的组合**——前者隐式保证平滑性并减少优化变量，后者将扭矩约束从"事后检查"变为"优化目标"，两者结合使得动力学感知规划的开销仅 +7ms（35ms → 42ms），却将 3kg 负载下的成功率从 77% 提升到 99.7%。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
min_U  Σ_t [γ_s·‖θ̈_t‖² + γ_ℓ·‖θ̇_t‖² + γ_e·‖(θ̇_t ⊙ τ_t)dt‖²]  s.t.  τ⁻ ≤ τ_t ≤ τ⁺
```

**优化目标**：在满足扭矩约束的前提下，最小化平滑度 + 路径长度 + 能量消耗。

**变量说明**：

| 符号 | 含义 | 单位 |
|------|------|------|
| U ∈ R^{d×K} | B 样条控制点（优化变量） | rad |
| Θ_t = [θ_t, θ̇_t, θ̈_t, θ‴_t] | t 时刻机器人状态 | rad, rad/s, rad/s², rad/s³ |
| τ_t ∈ R^d | t 时刻关节扭矩（由 RNEA 计算） | N·m |
| γ_s, γ_ℓ, γ_e | 平滑度/长度/能量权重 | - |
| τ⁻, τ⁺ | 关节扭矩上下限 | N·m |
| d | 关节自由度 | - |
| K | 每条轨迹的控制点数 | - |

**直觉**：传统方法先规划无碰撞轨迹，再检查扭矩是否超限——失败则重规划。cuRoboV2 把扭矩约束直接嵌入优化问题，用可微分 RNEA 计算 ∂τ/∂U，使得优化器能"感知"动力学约束并主动避开不可行区域。

**B 样条求值公式**（三次均匀 B 样条）：

```
Θ_t = B(α) · U_k,  其中 B(α) = T · P(α) · C

T = diag(1, dt_u⁻¹, dt_u⁻², dt_u⁻³)  # 时间缩放
P(α) = [α³, α², α, 1; 3α², 2α, 1, 0; 6α, 2, 0, 0; 6, 0, 0, 0]
C = (1/6) · [-1, 3, -3, 1; 3, -6, 3, 0; -3, 0, 3, 0; 1, 4, 1, 0]
```

**控制点梯度**（链式法则）：

```
∂L/∂U_k = B(α)ᵀ · g,  其中 g = ∂L/∂Θ_t 是上游梯度
```

> 符号与本文/相关文档保持一致：θ 为关节角，τ 为扭矩，Θ 为状态向量（含速度/加速度/加加速度）。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 7-DoF 机械臂（如 Franka Panda），规划从起点到终点的避障轨迹：

**步骤 1：初始化**  
- 控制点数 K = 20（每条关节轨迹）
- 优化变量 U ∈ R^{7×20} = 140 个标量
- 初始猜测：直线插值的关节角，速度/加速度为零

**步骤 2：B 样条求值**  
- 每段轨迹采样 N_interp = 4 个点
- 总 timestep 数 T = (K-3) × 4 = 68 个
- 对每个 t，计算 Θ_t = [θ_t, θ̇_t, θ̈_t, θ‴_t]

**步骤 3：正向运动学 + 逆动力学**  
- FwdKin(θ_t) → 各连杆位姿 + 碰撞球位置
- RNEA(θ_t, θ̇_t, θ̈_t) → τ_t（7 个关节扭矩）
- 假设 t=10 时，关节 3 的扭矩 τ_3 = 45 N·m，而扭矩上限 τ⁺_3 = 40 N·m → 违规！

**步骤 4：损失计算**  
- 平滑度损失：γ_s · ‖θ̈_t‖² = 0.1 × (2.5)² = 0.625
- 能量损失：γ_e · ‖(θ̇_t ⊙ τ_t)dt‖² = 0.01 × (1.2 × 45 × 0.01)² = 0.00029
- 扭矩违规惩罚（软约束）：λ · max(0, |τ_t| - τ⁺)² = 100 × (45-40)² = 2500

**步骤 5：反向传播**  
- ∂L/∂τ_3 = 2 × 100 × (45-40) = 1000
- ∂τ_3/∂θ̈_3（由 RNEA VJP 计算）≈ 0.05 N·m/(rad/s²)
- ∂θ̈_3/∂U_k（由 B 样条公式计算）≈ 6/dt_u²
- 链式法则：∂L/∂U_k = 1000 × 0.05 × 6/dt_u² = 300/dt_u²

**步骤 6：L-BFGS 更新**  
- 根据梯度 ∇_U L 更新控制点 U
- 新轨迹在 t=10 时的关节 3 加速度降低 → τ_3 降至 38 N·m → 满足约束

**关键洞察**：传统方法会在步骤 3 发现扭矩违规后"回退"并重新规划（可能多次迭代）。cuRoboV2 通过可微分 RNEA 将扭矩违规直接转化为梯度，优化器在一步更新中就"知道"如何调整轨迹以降低扭矩。

**为什么 kernel 时间 +5.69ms 但端到端只 +7ms？**

| 组件 | 分辨率 | 内存 |
|------|--------|------|

**量化误差**：TSDF 和 ESDF 使用 float16 存储（2 bytes/体素），距离查询误差 < 0.1mm（远小于典型碰撞球半径 5-10mm）。

**部署约束**：
- **GPU 要求**：NVIDIA GPU（依赖 CUDA），推荐 RTX 3090/4090 或 A100

### 6.1 隐含假设 (Hidden Assumptions)

**假设 1：准确的机器人模型**  
RNEA 需要准确的质量、质心、惯性张量。如果 URDF 参数不准（如负载未知），扭矩预测会偏差，导致规划出的轨迹实际执行时仍可能失败。

**假设 2：静态环境或慢速变化**  
ESDF 的 frustum-aware decay 假设环境变化主要发生在相机视野内。快速移动的障碍物（如人突然伸手）可能来不及更新 ESDF，导致碰撞。

**假设 3：深度相机覆盖工作空间**  
ESDF 质量依赖深度相机的视野和分辨率。遮挡区域或反光表面会导致 ESDF 空洞，规划器可能"穿过"未观测到的障碍物。

**假设 4：扭矩限制是主要动力学约束**  
论文只考虑了扭矩限制，未考虑电流限制、热约束、齿轮箱背隙等实际硬件限制。真实部署可能需要额外的事后验证。

## 附錄：與 VLA 研究的關聯

**为什么 VLA 研究者应该关注 cuRoboV2？**

VLA（Vision-Language-Action）系统的典型架构是：多模态模型输出动作指令 → 底层控制器执行。但"动作指令"是什么形式？

- **如果 VLA 输出关节位置/速度**：需要底层规划器将离散指令转换为平滑、可执行的轨迹。cuRoboV2 的 B 样条优化可以直接作为 VLA 的"动作解码器"。
- **如果 VLA 输出末端执行器位姿**：需要 IK 求解关节角。cuRoboV2 的碰撞感知 IK（99.6% 成功率，人形）比传统 IK 更可靠。
- **如果 VLA 部署到人形机器人**：48-DoF 的全身控制是 cuRoboV2 的核心优势，现有方案（PyRoki 等）在此规模下完全失败。

**潜在集成点**：
1. **VLA → cuRoboV2 接口**：VLA 输出目标位姿/抓取姿态 → cuRoboV2 规划动力学可行轨迹
2. **闭环控制**：cuRoboV2 的 30Hz+ 规划频率支持 MPC 式闭环，可融合 VLA 的高层指令与底层反馈
3. **仿真训练**：cuRoboV2 的 GPU 并行特性支持批量轨迹生成，可用于 VLA 的仿真数据增强

**局限性**：cuRoboV2 不提供感知 - 动作的端到端学习，它只是一个确定性的运动生成栈。VLA 研究者需要自己设计高层策略与底层规划的接口。
