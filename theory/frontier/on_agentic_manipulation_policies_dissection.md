## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

论文把操作策略分为四类：learned policies（VLA / WAM）、skill orchestration、offline program synthesis、以及本文的 AMPs。四类的差别不在“用不用大模型”，而在**模型是否留在控制环内**以及**模型对机械臂有多大的直接控制权**。

| 类别 | 代表 | 模型在环? | 控制粒度 | 能力上限由谁决定 |
|------|------|-----------|----------|------------------|
| Learned policy | π0.5、FLUX 3 Action、Lakeside | 否（前向策略） | 端到端动作 | 机器人示范数据 |
| Skill orchestration | Harness VLA、HarnessPAI | 是（选技能） | 调用低层技能 | 技能库可靠性 |
| Offline program synthesis | ASPIRE（程序精化） | 否（部署前写程序） | 程序内感知+反馈 | 程序写得好不好 |
| AMP（本文） | AMP1 / AMP1+ | 是（持续闭环） | 直接下发定时 TCP 路径点 | 通用模型 + harness |

AMP1 的内部模块划分（论文 §4A、Fig. 6）：

| 模块 | 输入 | 输出 | 频率 / 时序 | 训练 |
|------|------|------|-------------|------|
| 通用 AI 模型 | 指令、图像、深度、标定、本体状态、场景模型 | Python 代码 | 每“回合”一次，回合内可多次工具调用 | 权重固定，无梯度更新 |
| 持久 Python 解释器 | 模型代码 | 打印输出、traceback、显示图像 | episode 内跨回合保留变量与函数 | 无 |
| Robot server / SDK | SDK 调用 | 图像、深度、点云、物体分割、运动执行 | 场景模型在无运动时后台更新 | 无 |
| 场景模型 | 融合点云 | 物体集合 o_j、网格 M_j、障碍区 O | 每次新帧、每次碰撞检查前 | 无（几何算法） |
| 记忆 M（仅 AMP1+） | 反思产物 | Markdown 笔记 + Python 库 | 每 episode 开始时读取 | 无（非参数化） |

### 1.2 关键机制 (Key Mechanism)

- **代码即动作接口**：模型不输出动作 token，而是写 Python 调用 SDK；SDK 只提供 sensing / perception / motion 三类函数，basic harness 明确不提供抓取、放置、推动原语（§4A.3）。因此“抓哪里、怎么放”全部由模型自己在代码里构造。
- **运动表示为定时路径点**：模型给出 `{w_i = (T_i, t_i, g_i)}`，即 TCP 位姿、到达时间、夹爪命令；harness 负责插值、逆解、可达性与速度检查、可选碰撞检查，拒绝时返回原因和受影响步，供模型修复。
- **感知是可修正的场景模型**：点云体素聚类 + 高度图拉伸成闭合网格，物体有稳定 ID 并在更新间做最小代价匹配；模型可以自己增删改物体，系统提示明确警告“感知可能合并/拆分物体”，要求模型对照图像修正而不是在规划里补偿。
- **观察由模型主动发起**：图像只有被代码显示时才进入上下文；上下文图像超量后旧图被替换为文件指针，可重新加载。这是“上下文记忆”，与权重记忆、与 AMP1+ 的文件记忆是三种不同东西。
- **经验学习不改权重**：AMP1+ 把反思写进跨 episode 的文件夹 M，通常是 Markdown 笔记 + Python 库；少样本在单任务多布局上练，持续学习按随机任务序列走一遍。

⚡ **Eureka Moment**：把“策略”的可靠性来源，从“用机器人数据训练一个动作映射”，换成“让一个会写代码的通用模型在每个 episode 里现写一个闭环控制器”，harness 只负责把它接到真实机械臂上。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
a_{1:N} = Code( LLM(instruction, o_t) ),   o_{t+1} = Robot(a_{1:N})
```

即：策略不是 `o_t → a_t` 的固定映射，而是“模型根据当前观测现写一段程序，程序产生一段带时间的动作序列”。

论文真正给出的数学主要在运动插值（§4A.3）。目标是：把若干离散路径点变成关节空间轨迹 τ，并在每个控制步解出关节角。

```
路径点:  w_i = (T_i, t_i, g_i),  i = 1..N
         T_i = (p_i, R_i) ∈ SE(3),  g_i ∈ {0,1}

段内归一化时间:
         u = (t - t_{i-1}) / (t_i - t_{i-1}) ∈ [0,1]

位置插值:
         p(t) = p_{i-1} + σ(u) · (p_i - p_{i-1})

姿态插值（测地线）:
         R(t) = R_{i-1} · exp( σ(u) · log( R_{i-1}^T R_i ) )

五次时间缩放（最小 jerk）:
         σ(u) = 10u³ - 15u⁴ + 6u⁵

每控制步:
         q_k = DampedLeastSquaresIK( T(k·Δt) ),  以 q_{k-1} 为初值
```

变量说明：

| 符号 | 含义 |
|------|------|
| `T_i, p_i, R_i` | 第 i 个路径点的 TCP 位姿、位置、姿态 |
| `t_i` | 期望到达时间 |
| `g_i` | 夹爪命令（0 开 / 1 闭） |
| `σ(u)` | 五次多项式时间缩放，σ(0)=0, σ(1)=1, σ'(0)=σ'(1)=0 |
| `Δt` | 控制步时长（仿真中由各基准的控制频率决定） |
| `q_k` | 第 k 步的关节角 |
| `τ` | 关节空间轨迹 |

直觉：位置和姿态分开插值（decoupled path），姿态走 SO(3) 上的测地线，时间用最小 jerk 曲线，保证起停平滑；harness 只在“每个控制步的位置/姿态误差在容差内、关节速度不超限”时才执行，否则把原因退回给模型修。

论文没有给出损失函数、没有梯度更新、没有 RL 目标；训练相关的数学在这篇里不存在，这是它与 VLA 论文的根本差别。

## 3. 带数字走一遍：玩具例子 (Worked Example)

以下数值均为**假设的玩具例子**，只用于验算论文公式与论文报告的比例关系，不是论文实验数据。

**例 1：路径点插值**

假设两个路径点：`p_0 = (0, 0, 0)`，`p_1 = (0.10, 0, 0)` 米，`t_0 = 0`，`t_1 = 2` 秒。取 `t = 1` 秒，则 `u = 0.5`。

```
σ(0.5) = 10(0.5)³ - 15(0.5)⁴ + 6(0.5)⁵
       = 10(0.125) - 15(0.0625) + 6(0.03125)
       = 1.25 - 0.9375 + 0.1875
       = 0.5
p(1) = (0,0,0) + 0.5 · (0.10,0,0) = (0.05, 0, 0)
```

验算端点：`σ(0)=0`，`σ(1)=10-15+6=1`；`σ'(u)=30u²(1-u)²`，在 u=0 与 u=1 处均为 0。所以起停速度为 0，中点恰好是几何中点——这与论文“最小 jerk 五次缩放”的描述一致。

**例 2：真实世界失败率倍数**

论文 Table 1：AMP1 104/108，FLUX 3 Action 49/108，π0.5 30/108。

```
AMP1 失败次数 = 108 - 104 = 4
FLUX 失败次数 = 108 - 49  = 59   → 59 / 4 ≈ 14.75 ≈ 15×
π0.5 失败次数 = 108 - 30  = 78   → 78 / 4 = 19.5  ≈ 20×
成功率: 104/108 = 96.30% ≈ 96.3%
        49/108  = 45.37% ≈ 45.4%
        30/108  = 27.78% ≈ 27.8%
```

这与论文“相对 VLA 与 WAM 基线分别把失败率降低 20× 和 15×”的表述一致：VLA（π0.5）对应 20×，WAM（FLUX）对应 15×。注意这是**失败次数比**，不是成功率比。

**例 3：RoboLab-120 的计数一致性**

```
85.6% × 1200 = 1027.2 → 论文报告 1027 成功 / 173 失败
82.8% × 1200 =  993.6 → 论文报告  994 成功 / 206 失败
96.2% ×  950 =  913.9 → 论文报告  914 成功 / 950  trial（95 个无基准伪影任务）
```

三处都能对上，说明论文的成功率是按 trial 计数而非按任务平均。

**关于“记忆窗口”的口径（条件性说明，非论文内容）**：本篇没有 K 帧均匀采样、没有 Δt 帧间隔、没有未来动作 chunk 长度这些超参，因此**不能**把任何单一设置的步长或 chunk 长度写成它的“记忆窗口”。一般地，均匀间隔下 K 个采样帧的首末跨度是 `(K-1)×Δt`；若从当前参考 t 预测 t+1 至 t+H，终点距当前参考是 `H×Δt`。这两个式子在本篇不适用：AMP1 的“历史”是持久解释器里的变量与图像指针，“未来”是一段由代码生成的定时路径点，二者都不是定长帧窗口。AMP1+ 的 M 是跨 episode 的文件，也不能换算成帧数。

| 夹爪未释放 | 3 | 4 | 碗沿/杯柄卡在指关节 |
| 感知错误 | 3 | 0 | 类别或几何误判 |
| Provider 安全过滤 | 5 | 0 | API 层拦截 |

**真实机器人上的失败**：108 次中 4 次失败——两次是倒方块时方块落到盘外，两次是碗滚下桌；主要干扰是碰撞触发 Franka 碰撞反射。

**能力边界**：慢；不能在轨迹执行中重规划；评测以准静态为主；对 verifier 语义的依赖在 LIBERO-Goal 上暴露得很清楚（模型以为成功、verifier 判失败）。

### 6.1 隐含假设 (Hidden Assumptions)

- **基础模型可用且稳定**：整套方法假设能持续调用前沿模型 API；provider 安全过滤在 Gemini 上造成 5 次 trial 失败，说明这不是纯技术假设。
- **“零样本”可审计**：作者定义为零演示、零训练、零练习，但闭源模型的预训练语料不可见，无法排除基准污染。
- **仿真时间可暂停**：仿真在模型推理时暂停，只有执行动作计入时限；这个口径让 AMP 的时间劣势在仿真里被隐藏，真实世界的 5 分钟预算也不含推理。
- **标定误差可估计**：去标定条件下模型靠 SIFT + 最小二乘自标定成功，但这依赖腕相机可移动到已知位姿，不是所有平台都满足。
- **verifier 是地面真值**：作者一方面用 verifier 判成功，一方面指出 verifier 会误判；这两件事同时成立时，成功率数字应带条件读。
- **场景基本准静态**：论文自述评测主要覆盖准静态场景，动态目标与滑动对象未验证。

## 8. 精读建议 (Reading Guide)

- **值得精读原文的人**：
  1. 做 VLA / WAM 基准对比、需要判断“agent 路线是否被高估”的研究者——重点看 §2A、§2D、§S6 的失败归因。
  2. 要搭机器人 harness 的工程师——重点看 §4A（SDK 三类函数、运动校验、场景模型更新与 ID 维护）。
  3. 做非参数化经验学习的人——重点看 §2C 的少样本/持续学习协议与 §4E 的 seed 划分。
- **建议章节路径**：先读 §1 + §2A.1 建立主张与数字 → 再看 §2D 看控制变量实验（模型 > harness、辅助例程帮弱模型害强模型、图像不可被文本替代）→ 再看 §4A.3 与 §4B 看工程接口 → 最后读 §S6 看失败归因，判断数字该打多少折。§3B 与 §S7 可快速扫过。
- **不值得精读的理由**：如果你不做机器人学习、或已经熟悉 code-as-policies 与 agent harness 这类工作，读摘要与 §2A 的数字即可；本文的novelty在范式组织与系统集成，不在单一算法。
