## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

HELP 将分布式软件架构分为三层，每层职责清晰：

| 层级 | 组件 | 输入 | 输出 | 职责 |
|------|------|------|------|------|
| 集中式 GPU 层 | VLA 策略 $\pi_\theta$ | 多机器人多模态观测 $s_t^i$ | 动作块 $a_t^i$ | 并行推理 + 持续策略优化 |
| 集中式 GPU 层 | 接管预测模型 $\varphi$ | 状态 $s_t^i$ | $\gamma_t^i \in \{0,1\}$ | 预测是否需要人类接管 |
| 集中式 GPU 层 | 任务终止模型 $\psi$ | 状态 $s_t^i$ | $d_t^i \in \{0,1\}$ | 估计任务是否完成 |
| 集中式 GPU 层 | VLAC-CUT 分割器 | 完整轨迹 + 任务指令 | 分段标签 | 轨迹切分为 progress/idle/failure/recovery |
| 分布式客户端 | 机器人客户端 (×12) | 本体感知 + 相机图像 | 流式到 GPU 层 | 硬件控制 + 命令执行 + 状态机管理 |
| 操作台 | Teleoperator 控制台 | VR 视频流 + Web UI | 遥操作指令 | 高质量 recovery 数据采集 |
| 操作台 | Floor Operator 界面 | 蓝牙键盘 + 现场监视 | takeover/reset 信号 |  fleet 监控 + 场景重置 |

### 1.2 关键机制 (Key Mechanism)

**角色分工的核心洞察**：传统方案中，同一个操作员既要跑现场（搬东西、重置场景），又要做高精度遥操作。HELP 将其拆为：

- **Teleoperator（远程操作员）**：经过数周至数月训练的高级人才， stationary 坐在 VR 前，只做高价值数据采集。不移动、不重置、不切换任务。
- **Floor Operator（现场操作员）**：用蓝牙键盘触发 takeover/reset，在 12 台机器人之间巡视，负责物理重置和发现重复性失败模式。

这种分工的三个直接好处：
1. **降低任务切换成本**：每人只做一件事，认知负荷下降
2. **降低培训门槛**：Floor Operator 不需要掌握精细操作技能
3. **扩大失败模式覆盖**：同时观察 12 台机器人的行为，重复失败更容易被识别

⚡ **Eureka Moment**：VLA 后训练的真正瓶颈不是样本数量，而是人类劳动效率——把"每单位人类时间带来的策略提升"作为优化目标，而不是"每单位机器人交互带来的样本提升"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
Human Efficiency = ΔPolicy_Performance / (Human_Labor_Time + Human_Training_Cost)
```

**目标**：最大化每单位人类劳动和时间带来的策略性能提升（成功率和吞吐量）。

**核心方程**（论文 Eq. 1）：

```
a_t^i = π_θ(s_t^i)     # VLA 策略输出动作块
γ_t^i = φ(s_t^i)       # 接管预测: 0=自主, 1=需要接管
d_t^i = ψ(s_t^i)       # 任务终止: 0=继续, 1=完成
```

**变量说明**：

| 符号 | 含义 | 类型 |
|------|------|------|
| $s_t^i$ | 机器人 i 在时刻 t 的多模态状态 | 观测向量 |
| $a_t^i$ | 动作块（action chunk） | 连续/离散动作 |
| $\gamma_t^i$ | 接管标志 | 二值 |
| $d_t^i$ | 任务终止标志 | 二值 |
| $\pi_\theta$ | VLA 策略网络 | 可训练 |
| $\varphi$ | 接管预测模型 | 可训练 |
| $\psi$ | 任务终止模型 | 可训练 |

**VLAC-CUT 分割逻辑**（非公式化描述）：

给定任务指令 + 可选任务计划 + 机器人执行视频，VLAC-CUT 对轨迹进行过程级分段：

```
原始轨迹 → [progress] [idle] [failure] [progress] [recovery] [idle]
              ↑保留     ↑丢弃   ↑丢弃     ↑保留      ↑保留     ↑丢弃
```

保留的段（progress + recovery）与 HITL 数据混合，进入下一轮训练。

> 符号与本文保持一致：$\pi_\theta$ 为 VLA 策略，$\varphi$ 为接管预测，$\psi$ 为终止检测，VLAC-CUT 为轨迹分割器。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个测试管插入任务，单轮后训练流程如下：

**场景设置**：
- 12 台机器人并发执行"将测试管插入方形孔"
- 每台机器人自主运行，2 Hz 采样

**第 1 轮：基线评估**
- 12 台机器人各跑 100 个 episode
- 总自主 rollout: 1200 个
- 成功率: 35%（基线模型）
- 人类劳动: 0 小时（纯自主）

**第 2 轮：HITL 介入（无 VLAC-CUT）**
- Floor Operator 巡视，发现 3 个重复失败模式
- 触发 200 次 takeover，Teleoperator 提供 recovery 演示
- 人类劳动: Teleoperator 2 小时 + Floor Operator 4 小时 = 6 人时
- 训练数据: 200 条 HITL 轨迹（全量使用）
- 成功率: 62%（提升 27pp）
- 吞吐量: 基线的 $1.7\times$

**第 3 轮：HITL + VLAC-CUT**
- 同样 200 次 takeover，6 人时
- VLAC-CUT 对 1200 条自主轨迹自动分段：
  - progress 段: 340 段（保留）
  - recovery 段: 85 段（保留）
  - idle 段: 420 段（丢弃）
  - failure 段: 355 段（丢弃）
- 训练数据: 200 HITL + 425 自动分段 = 625 条高质量样本
- 成功率: 85%（提升 23pp，相对 +37%）
- 吞吐量: 基线的 $4.2\times$
- **人类监督放大因子**: 吞吐量 $2.43\times$，成功率 $1.80\times$（相比 HITL-only）

**关键洞察**：同样的 6 人时人类劳动，加上 VLAC-CUT 的自动轨迹筛选，额外获得了 425 条高质量自主数据——相当于把人类劳动的效率放大了 2.43 倍。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/设计 | 工程含义 |
|------|-----------|----------|
| 机器人并发数 | 12 台 | 需要 12 路视频流 + 12 路状态流同时传输 |
| 通信中间件 | ZeroMQ + UDP | 低延迟命令路由；VR 遥操作用 UDP，事件用 ZeroMQ |
| 采样频率 | VLAC-CUT 默认 2 Hz | 支持 2-20 Hz 可调；高频更精细但计算开销大 |
| VLAC-CUT 基座 | Qwen3-VL-30B-A3B | 30B 参数 MoE 架构，实际激活约 3B 参数 |
| 分布式框架 | Ray | GPU 层用 Ray 做动态负载均衡 + 异步训练 |
| 客户端设计 | 双进程 + 异步多线程 | 硬件控制环与网络 I/O 解耦，避免通信延迟影响控制 |
| 训练-推理解耦 | 异步参数广播 | 训练更新 $\theta$ 后异步广播到推理 worker，消除训练诱导延迟 |
| VR 遥操作延迟 | 动态 UDP 路由 | 高频率遥测流（>60Hz）直接路由到目标机器人 |

**部署约束**：
- 需要集中式 GPU 服务器（支持 Ray 分布式推理）
- 每台机器人需要 onboard 计算单元（运行客户端 + 采集传感器）
- Teleoperator 需要 VR 设备 + 稳定网络
- Floor Operator 需要蓝牙键盘 + 物理访问机器人区域

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

| 能力 | 场景 | 原因 |
|------|------|------|
| 大规模并发后训练 | 12 台机器人同时收集数据 | 角色分工降低认知负荷 |
| 自动轨迹质量过滤 | 混合质量 rollout 自动分段 | VLAC-CUT 非单调进度估计 |
| 重复失败模式发现 | 同时观察 12 台机器人行为 | 并发执行放大失败信号 |

| 零样本泛化 | 跨任务/场景/视角 | VLAC-CUT 基于 Qwen3-VL 预训练先验 |

### 不能做什么 / 失败模式

| 失败模式 | 原因 | 缓解建议 |
|----------|------|----------|
| 仅验证 4 个桌面操作任务 | 实验范围有限 | 需扩展到移动/双臂/人形平台 |
| VR 遥操作依赖网络质量 | UDP 延迟/丢包影响操控 | 论文附录 B 有 VLA 辅助模块缓解 |
| VLAC-CUT 对极端遮挡敏感 | 视频输入依赖视觉可见性 | 可能需要融合本体感知 |
| 2 人 12 机配置门槛高 | 需要 VR 设备 + GPU 集群 + 物理空间 | 小规模团队可仅用 VLAC-CUT 组件 |
| 接管预测模型 $\varphi$ 可能误报 | 过度接管降低自主效率 / 欠接管导致失败 | 需根据任务调整 $\gamma$ 阈值 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **人类劳动是主要瓶颈**：论文假设在大规模部署中，人类时间比机器人硬件时间更昂贵。这在小团队（1-2 台机器人）中可能不成立——此时样本效率可能更重要。

2. **角色分工优于通用操作员**：假设专业化培训（Teleoperator 数周训练）的 ROI 高于培养全能型操作员。这在任务多样性高时可能受限——Teleoperator 需要为每种新任务重新训练。

3. **VLAC-CUT 的分割质量足够可靠**：假设自动分段器能准确区分 progress/recovery/idle/failure。如果误判率高（如把 recovery 判为 failure），会损失有价值数据或引入噪声。

4. **12 台机器人并发是最优配置**：论文未探索不同并发数的 trade-off。更多机器人可能超出 Floor Operator 的监控能力，更少则吞吐量不足。

5. **桌面操作任务的结论可推广**：4 个任务都是桌面操作，未验证动态环境、双臂协调、或移动操作场景。
