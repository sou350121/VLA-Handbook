### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **显式注意力 vs 隐式注意力**: 传统 DP/ACT 的视觉特征是黑盒——CNN 提取的全局特征可能关注背景噪声。DP-GA 用 DETR-style 的 learnable queries 显式预测 N_k 个关键点坐标，强制模型"指出"它认为重要的位置。

2. **特征监督动作生成 vs 坐标直接条件化**: Default 变体用注意力特征 f_i（来自 Transformer decoder 的 query embedding）条件化 Diffusion，而非直接用坐标 p_i。这保留了特征的丰富性，同时通过坐标预测损失约束特征的空间对齐。

3. **一次纠正 + 自动跟踪**: 人类只需在初始帧点击纠正，后续由 Co-Tracker 自动传播。这平衡了交互成本和鲁棒性——不需要每帧都干预。

⚡ **Eureka Moment**: 视觉注意力不必是黑盒——把它显式建模为可预测、可纠正的 2D 关键点，既提升了 OOD 鲁棒性，又给了人类一个"轻量级干预接口"（只需点一次）。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L_total = L_action + λ_kp · L_kp + λ_feat · L_feat
L_kp = (1/N_k) Σ_i ‖p_i − p_i^gt‖²₂    (关键点 MSE)
L_feat = (1/N_k) Σ_i ‖f_i − h⁻¹(p_i^gt)‖²₂  (特征对齐)
```

**目标**: 让注意力特征 f_i 既空间上对齐任务相关结构（通过 L_kp），又在正向预测和逆向恢复之间保持一致（通过 L_feat），从而条件化 Diffusion Policy 生成更鲁棒的动作。

**公式详解**:

| 符号 | 含义 | 维度 |
|------|------|------|
| p_i | 第 i 个关键点的预测 2D 坐标 | ℝ² |
| p_i^gt | 第 i 个关键点的地标坐标（人工标注+跟踪） | ℝ² |
| f_i | 第 i 个关键点的注意力特征（来自 Transformer decoder query） | ℝ^{d_f} |
| h_θ(·) | 线性坐标头: p_i = A·f_i + b | ℝ^{d_f} → ℝ² |
| h_θ⁻¹(·) | 逆向映射: f_i = A⁺·(p_i − b)，A⁺ 为 Moore-Penrose 伪逆 | ℝ² → ℝ^{d_f} |
| z_i | 实际用于条件化 Diffusion 的特征（预测路径或纠正路径） | ℝ^{d_f} |
| N_k | 预定义的关键点数量（实验中为 2） | 标量 |

**直觉**: 关键点坐标 p_i 是"人看得懂的"，特征 f_i 是"策略用得上的"。L_kp 确保特征编码了正确的空间信息，L_feat 确保人纠正坐标后能一致地映射回特征空间。两者结合，让"人可解释"和"机器可使用"不再矛盾。

> 符号与本文保持一致。论文未明确给出 L_action 的具体形式（标准 DP 的噪声预测 MSE），也未给出 λ_kp 和 λ_feat 的具体权重值。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 Cable 任务场景：

**设置**: N_k = 2 个关键点（动态：电缆末端；静态：柱子底部）。d_f = 256（特征维度）。

**训练阶段第 t 步**:

1. AttnEnc 预测:
   - p_1 = (120, 200) — 电缆末端（地标: p_1^gt = (118, 198)）
   - p_2 = (300, 400) — 柱子底部（地标: p_2^gt = (302, 402)）

2. 计算 L_kp:
   ```
   L_kp = (1/2) × [‖(120,200)−(118,198)‖² + ‖(300,400)−(302,402)‖²]
        = (1/2) × [8 + 8] = 8.0
   ```

3. 特征对齐（假设 f_1 来自 decoder query，h⁻¹(p_1^gt) 通过伪逆恢复）:
   ```
   L_feat = (1/2) × [‖f_1 − h⁻¹(p_1^gt)‖² + ‖f_2 − h⁻¹(p_2^gt)‖²]
          ≈ 0.5（训练初期较大，随训练收敛）
   ```

4. 随机特征路由（训练时 50% 概率用预测路径，50% 用纠正路径）:
   ```
   z_1 = f_1  (预测路径，概率 0.5)
   或 z_1 = h⁻¹(p_1^gt)  (纠正路径，概率 0.5)
   ```

5. Diffusion 条件化: [z_1, z_2, 关节状态] → U-Net 去噪 → 动作序列

**推理阶段（OOD 场景，人类纠正）**:

1. 初始帧: AttnEnc 预测 p_1 = (150, 220) — 但注意力漂移到了背景（因为外观 OOD）
2. 人类点击纠正: p_1^corrected = (115, 195)
3. 逆向映射: z_1 = h⁻¹(p_1^corrected) = A⁺·(p_1^corrected − b)
4. Co-Tracker 传播: 后续帧中 p_1[t] = G(p_1^corrected, I[t], I[t-1])
5. Diffusion 用 z_1 条件化，成功生成抓取动作

**结果**: 在 Appearance OOD 条件下，DP-GA Default 自主执行成功率 45.6%，人类纠正后提升至 76.7%（+31.1 pp）。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/估计 | 工程含义 |
|------|-----------|----------|
| 视觉编码器 | ResNet-18 + Transformer Enc-Dec | 比纯 ResNet 略重，但 DETR-style query 机制可并行处理多关键点 |
| 关键点数量 | N_k = 2（实验设置） | 少关键点 = 低计算开销 + 低标注成本；但复杂任务可能需要更多 |
| 跟踪模块 | Co-Tracker（预训练，冻结） | 额外推理开销；在变形/遮挡场景下可能失效 |
| 推理延迟 | DP 基础延迟 + AttnEnc 前向 + Co-Tracker | AttnEnc 约增加 10-20ms（ResNet-18）；Co-Tracker 约 5-10ms/帧 |
| 训练数据需求 | 30-32 次演示/任务 | 与标准 DP/ACT 相当；额外只需标注初始帧关键点 |
| 人类纠正成本 | 每 rollout 一次点击（可选） | 极低交互成本；但需要 UI 显示关键点叠加层 |
| 内存占用 | AttnEnc + DP U-Net + Co-Tracker | 约增加 100-200MB（ResNet-18 + Transformer） |
| 部署约束 | 需要稳定的相机标定 + 足够的帧率（≥10fps） | 跟踪模块对帧率敏感；低帧率下 Co-Tracker 可能丢失目标 |

**关键 trade-off**: 显式关键点表示增加了模块数量和推理延迟，但换来了可解释性（人能看到策略在看哪里）和可纠正性（人可以在 OOD 时干预）。对于延迟敏感的应用（如动态抓取），可能需要优化 Co-Tracker 或改用更轻量的跟踪方案。

### 6.1 隐含假设 (Hidden Assumptions)

1. **少量关键点足以表征所有任务相关结构**: 论文假设 N_k = 2 足够，但评估的任务都是"单物体操作 + 单目标"。对于多物体交互（如组装、整理桌面），2 个关键点可能不够。

2. **2D 关键点足够**: 论文没有处理深度或遮挡。在需要深度判断的任务中（如插入、堆叠），2D 投影可能产生歧义。

3. **Co-Tracker 足够可靠**: 论文依赖预训练的 Co-Tracker 进行关键点传播，但没有评估跟踪误差对最终成功率的影响（附录 A-B 有定量分析，但正文未深入讨论）。

4. **一次纠正足够**: 论文假设人类只需在初始帧纠正一次。但在长时间执行或动态环境中，注意力可能在执行过程中再次漂移。

5. **线性映射 h_θ 的逆向一致性**: 从 d_f 维特征到 2D 坐标的映射是欠定的（d_f > 2），Moore-Penrose 伪逆给出的逆向映射不是唯一的。L_feat 缓解了这个问题，但不能完全消除歧义。

- **建議章節路徑**: 先讀 §III（方法，特别是 III-A 架构 + III-C override 机制）→ 再看 §IV-A3（仿真结果 Table I/II）→ 可跳 §II（相关工作，除非你需要文献综述）→ 最后 §IV-B（真实世界实验）
