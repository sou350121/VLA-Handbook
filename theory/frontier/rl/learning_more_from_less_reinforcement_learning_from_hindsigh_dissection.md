### 1.2 关键机制 (Key Mechanism)

LfH 的核心流程分为两步，作用于低奖励 GRPO 组（平均奖励 < 阈值 η）：

1. **指令重标注（Instruction Relabeling）**：从失败轨迹中采样一个 anchor τ_i*，VLM 观察其观测-动作序列，生成一个描述"机器人实际做了什么"的事后指令 g'。同时 VLM 会过滤掉无意义的随机运动轨迹。

2. **奖励重标注（Reward Relabeling）**：用同一个事后指令 g' 对组内所有轨迹评分，得到 R̃_i ∈ {0, 0.5, 1}（完成/失败/模糊）。

**为什么必须用共享指令？** GRPO 在组内计算相对优势（normalized advantage），如果每条轨迹用不同的事后指令，它们的奖励无法比较。共享指令确保组内优势计算有意义。

⚡ **Eureka Moment**：「在一个指令下失败的 rollout，在另一个指令下是成功的——用语言重标注改变任务分配本身，而不是给同一任务分配更密集的反馈。」

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L_LfH(θ) = L_GRPO(θ) + λ · L_H-GRPO(θ)
         = 标准GRPO更新 + λ·VLM事后重标注组的GRPO更新
```

### 目标函数分解

**原始 GRPO 目标**（对高奖励组正常工作）：
```
L_GRPO(θ) = E[ (1/K) Σ_i Σ_t min(r_i,t · Â_i, r̄_i,t · Â_i) - β·D_i,t ]
```

其中：
- r_i,t = π_θ(a_i,t | o_i,t, g) / π_θold(a_i,t | o_i,t, g) — 标准重要性比
- Â_i = (R_i - μ_R) / (σ_R + δ) — 组内归一化优势
- D_i,t — 相对于参考策略的 KL 惩罚

**Hindsight GRPO 目标**（仅对低奖励组激活）：
```
L_H-GRPO(θ) = E[ (1/K) Σ_i Σ_t min(r̃_i,t · Ã_i, r̄̃_i,t · Ã_i) - β·D̃_i,t ]
```

关键差异在重要性比：
```
r̃_i,t(θ) = π_θ(a_i,t | o_i,t, g') / π_θold(a_i,t | o_i,t, g)
```

> 这里分子用 hindsight 指令 g' 计算，分母用原始指令 g 计算——因为动作是在 g 下采样的，但我们要对 g' 做策略优化。这是 hindsight policy gradient 的核心修正。

### 变量说明

| 符号 | 含义 |
|------|------|
| g | 原始指令（commanded instruction） |
| g' | 事后指令（hindsight instruction），由 VLM 生成 |
| τ_i | 第 i 条轨迹 = (o_0, a_0, ..., a_{T-1}, o_T) |
| R_i | 原始奖励（二值：1=成功，0=失败） |
| R̃_i | 事后奖励（三值：1/0.5/0） |
| η | 低奖励组阈值（平均奖励 < η 时触发重标注） |
| λ | 事后目标权重（超参） |
| M_ψ | VLM relabeler（本文用 Qwen3-VL-235B-A22B） |

> 符号与本文保持一致。π_0.5 指 Pi0.5 VLA backbone。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 GRPO 组，K=4 条轨迹，原始指令 g = "关闭微波炉"：

**步骤 1：原始评分**
```
τ_1: R_1 = 0（碰了杯子）
τ_2: R_2 = 0（推了盘子但没推对）
τ_3: R_3 = 0（抓了杯子但掉了）
τ_4: R_4 = 0（什么都没碰到）
平均奖励 = 0 < η → 触发 LfH
```

**步骤 2：指令重标注**
采样 anchor = τ_1（随机选一个失败轨迹）。VLM 观察 τ_1 的观测序列后生成：
```
g' = "拿起杯子"
```

**步骤 3：奖励重标注**
用 g' = "拿起杯子" 对组内所有轨迹评分：
```
R̃_1 = 1  （τ_1 确实拿了杯子）
R̃_2 = 0  （τ_2 推盘子，没拿杯子）
R̃_3 = 0.5（τ_3 抓了但掉了——模糊）
R̃_4 = 0  （τ_4 什么都没碰到）
```

**步骤 4：计算 hindsight 优势**
```
μ̃_R = (1 + 0 + 0.5 + 0) / 4 = 0.375
σ̃_R ≈ 0.43
Â_1 = (1 - 0.375) / (0.43 + δ) ≈ 1.39    → 正优势
Â_2 = (0 - 0.375) / (0.43 + δ) ≈ -0.83   → 负优势
Â_3 = (0.5 - 0.375) / (0.43 + δ) ≈ 0.28  → 微弱正优势
Â_4 = (0 - 0.375) / (0.43 + δ) ≈ -0.83   → 负优势
```

**步骤 5：重要性修正**
对于 τ_1，计算重要性比：
```
r̃_1,t = π_θ(a_1,t | o_1,t, g'="拿起杯子") / π_θold(a_1,t | o_1,t, g="关闭微波炉")
```
这意味着：虽然动作是在"关闭微波炉"指令下采样的，但梯度会推动策略在"拿起杯子"指令下更可能产生这些动作。

**关键洞察**：即使 g' = "拿起杯子" 与原始任务"关闭微波炉"语义无关，对比信号（τ_1 正优势 vs τ_2/τ_4 负优势）仍然帮助策略学会区分"相关行为"和"无关行为"——作者称之为 contrastive grounding signal。

## 4. 工程视角 (Engineering View)

| 工程维度 | 考量 |
|----------|------|
| VLM 推理开销 | 每组失败 rollout 需要 1 次指令生成 + K 次奖励评分调用。Qwen3-VL-235B 单次推理约数秒，但可批量处理 |
| 延迟影响 | VLM 重标注在 rollout 收集后离线进行，不阻塞策略前向传播 |
| 内存 | 需要存储原始组 + 事后组，内存翻倍；但组大小 K 通常较小（4-8） |
| 部署约束 | 物理机器人场景下，VLM 可部署在远程服务器，通过 API 调用 |
| 质量控制 | VLM 可能生成模糊/错误指令——需要"是否有意义行为"的预过滤 |
| 超参敏感 | λ（事后权重）和 η（触发阈值）需要调优；λ 过大会使策略偏离原始任务 |

**工程含义**：LfH 不改变控制频率或模块边界——它只是一个训练阶段的数据增强管道。部署时 VLM relabeler 不需要在线运行，仅需训练期可用。


## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **冷启动逃逸**：初始策略零成功率时，LfH 仍能提供学习信号（§5.1，图 2a）
- **跨 backbone 泛化**：在 π0.5、GR00T、OpenVLA-OFT 上均有效（§5.2，图 3c）
- **物理迁移**：Franka FR3 上 160 rollout 达到 56% 成功率 vs GRPO 22%（§5.4，图 4b）
- **超越密集奖励**：优于 GRPO+RoboMETER，说明"改变任务分配"比"同一任务给更密反馈"更有效

### 不能做什么（已知局限）
- **受限于策略行为多样性**：如果策略产生重复/无信息轨迹，没有有意义的 hindsight 目标可恢复（§6 Limitations）
- **VLM 重标注质量瓶颈**：错误/过于泛化的指令会引入噪声监督（§6 Limitations 明确承认）
- **仅在低奖励组激活**：高奖励组不重标注——这意味着策略成熟后 LfH 的收益递减
- **实验范围有限**：仅桌面操作（LIBERO + Franka），未测试移动/双臂/人形机器人

### 6.1 隐含假设 (Hidden Assumptions)

| 假设 | 说明 | 风险 |
|------|------|------|
| VLM 能准确描述机器人行为 | 依赖 Qwen3-VL-235B 的视觉理解能力 | VLM 可能生成错误/模糊指令，引入噪声 |
| 事后指令与原始任务有泛化关联 | 假设在 g' 上学到的策略能迁移到 g | 如果 g' 与 g 完全无关，迁移效果有限 |
| 失败轨迹包含"有意义行为" | VLM 预过滤丢弃无意义轨迹 | 早期策略可能确实只产生随机运动 |
| 共享 hindsight 指令足够 | 整个组用同一个 g' | 可能不是每条轨迹的最佳事后解释 |
