## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 训练阶段 | 是否冻结 |
|------|------|------|----------|----------|
| **VLA Backbone (π0.6)** | 4 路相机图像 + 语言指令 ℓ + 本体感知 sᵖ | 最终层 token 嵌入 z₁:ₘ + VLA 动作块 ã₁:ₕ | 预训练 + SFT 微调 | RL 阶段冻结 |
| **RL Token Encoder** | VLA 嵌入 z₁:ₘ + 特殊 token e_rl | RL Token z_rl（压缩表示向量） | 自回归重建损失 L_ro | RL 阶段冻结 |
| **RL Token Decoder** | RL Token z_rl | 重建 VLA 嵌入 z̄₁:ₘ | 与 encoder 联合训练 | RL 阶段冻结 |
| **Critic Q_ψ** | 组合状态 x = (z_rl, sᵖ) + 动作块 a₁:₍ | Q 值标量 | TD 离线策略学习 | 在线更新 |
| **Actor π_θ** | 组合状态 x + VLA 参考动作 ã₁:₍ | 高斯分布 N(μ_θ, σ²I) | 最大化 Q - β·‖a - ã‖² | 在线更新 |

### 1.2 关键机制 (Key Mechanism)

**RL Token 的核心设计哲学**：在 VLA 的庞大表示和轻量 RL 之间架设一座"窄桥"。

1. **压缩瓶颈**：RL Token 通过 encoder-decoder 架构训练，encoder 将 VLA 的高维 token 嵌入压缩为一个固定维度的向量 z_rl，decoder 尝试从 z_rl 自回归重建原始嵌入。这个瓶颈迫使 z_rl 保留最任务相关的信息。

2. **冻结 VLA + 轻量头**：RL Token 训练完成后，VLA 和 RL Token 模块全部冻结。在线 RL 只更新小型 actor-critic 网络（通常 < 1M 参数），大幅降低计算和样本成本。

3. **参考动作正则化**：Actor 以 VLA 采样的参考动作块 ã 为条件，并通过 L2 正则化 β·‖a - ã‖² 约束输出靠近参考动作。这使在线 RL 变成"局部动作编辑"而非无约束搜索。

4. **参考动作 Dropout**：为防止 actor 简单地复制 VLA 动作，训练时对随机子集的 batch 将参考动作替换为零向量，迫使 actor 维持独立的动作生成能力。

⚡ **Eureka Moment**：VLA 的内部表示已经包含了完成任务所需的大部分信息——关键是如何将其压缩成一个轻量 RL 算法能高效使用的表示。RL Token 就是这个"压缩-解压"瓶颈的产物。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L_total = L_ro(φ) + α·L_vla(θ_vla)     [阶段1: 压缩表示训练]
L_π(θ) = E[-Q_ψ(x, a₁:₍) + β·‖a₁:₍ - ã₁:₍‖²]  [阶段2: RL 策略优化]
```

**阶段 1：RL Token 自回归重建目标**

```
L_ro(φ) = E_D [ Σᵢ₌₁ᴹ ‖h_φ(d_φ([z_rl, z̄₁:ᵢ₋₁]))ᵢ - z̄ᵢ‖² ]
```

- z = f(s, ℓ; θ_vla)：VLA 最终层 token 嵌入
- e_rl = e_φ(<rl>)：可学习的特殊 token 嵌入
- z_rl = g_φ([z₁:ₘ, e_rl])_{M+1}：encoder 在特殊 token 位置的输出
- z̄ᵢ = sg(zᵢ)：stop-gradient 操作，防止梯度回传到 VLA
- d_φ：decoder transformer，自回归重建原始嵌入
- h_φ：线性输出投影

**阶段 2：Actor-Critic 优化**

```
L_Q(ψ) = E_B [(Q̂ - Q_ψ(x, a₁:₍))²]
Q̂ = Σₜ'₌₁ᶜ γᵗ'⁻¹·rₜ' + γᶜ·E_{a'~π_θ}[Q_ψ'(x', a')]

L_π(θ) = E_B [-Q_ψ(x, a₁:₍) + β·‖a₁:₍ - ã₁:₍‖²]
```

- x = (z_rl, sᵖ)：RL 状态 = 压缩表示 + 本体感知
- a₁:₍：RL 动作块（长度 C < H，VLA 的块长度）
- ã₁:₍ ~ π_vla(·|s, ℓ)：VLA 采样的参考动作块
- β：正则化系数，控制 actor 偏离 VLA 参考动作的程度
- γ：折扣因子
- Q_ψ'：目标 critic 网络（TD3 风格）

> 符号与本文保持一致：θ_vla = VLA 参数，φ = RL Token 参数，θ = actor 参数，ψ = critic 参数，H = VLA 动作块长度（50），C = RL 动作块长度（<50），M = VLA token 数量。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的螺丝安装任务：

**阶段 1 训练**：
- 收集 50 条 teleoperation 演示数据
- VLA 嵌入维度：M=64 个 token，每个 2048 维
- RL Token 维度：256 维（压缩比 512:1）
- 重建损失 L_ro 从初始 0.85 下降到 0.12（500 步后收敛）
- 可选 SFT 微调 VLA：L_vla 从 0.3 下降到 0.08

**阶段 2 在线 RL**：
- 初始化 replay buffer B：填入 200 条 VLA 自主 rollout 数据
- 参数设置：C=20（RL 块长度），γ=0.99，β=1.0，G=8（update-to-data ratio）
- Warmup 阶段（前 500 步）：执行 VLA 动作 ã 收集数据
- 之后：a ~ π_θ(x, ã)

**一个典型训练 step**：
```
状态 x_t = (z_rl(s_t), s_tᵖ)
VLA 参考 ã = [0.12, -0.05, 0.08, ...]（20 步动作块）
Actor 输出 a = [0.13, -0.06, 0.09, ...]（微调后的动作）
Critic 评估 Q_ψ(x, a) = 0.72（预测成功率 72%）
执行 a，观察 r_t = 0（中间步骤无奖励）
...  episode 结束，r_T = 1（成功）
TD target Q̂ = 0 + 0.99²⁰ × 1 = 0.82
Critic loss = (0.82 - 0.72)² = 0.01
Actor gradient: 最大化 Q - β·‖a - ã‖²
  = 最大化 0.72 - 1.0 × 0.003 = 0.717
```

经过 2 小时在线训练（约 7200 步），Critic 预测值从 ~0.3 提升到 ~0.65，与实际成功率吻合。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|-----------|----------|
| VLA 推理延迟 | ~50-100ms/步（π0.6） | 冻结后无需更新，仅前向推理 |
| RL Token 推理 | ~5ms | 小型 transformer，可忽略 |
| Actor-Critic 推理 | ~1ms | 小型 MLP，实时性无压力 |
| 总控制周期 | ~50-100ms | 由 VLA 主导，RL 头不增加显著延迟 |
| RL 块长度 C | 20（vs VLA 的 H=50） | 更短的块允许更高频重规划 |
| Update-to-Data Ratio G | 8 | 每步数据采集后做 8 次梯度更新 |
| Replay Buffer 容量 | 数万次 transition | 容纳 VLA + RL + human 数据 |
| 训练时长 | 2-4 小时真实机器人时间 | 包含 warmup + 在线采集 + 更新 |
| GPU 内存 | VLA 已加载，RL 头 < 100MB | 轻量，可在边缘设备运行 |
| 参考动作 Dropout 率 | 未明确（论文未披露） | TODO: 待补充 |

**部署约束**：
- 需要持续运行的 π0.6 VLA 推理（GPU）
- RL actor-critic 可部署在 CPU 上
- 每个新任务需要：① 少量演示数据训练 RL Token（~50 条） ② 数小时在线 RL

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **精密接触操作**：螺丝安装、zip tie 等需要毫米级精度的任务
- **速度优化**：不仅提高成功率，还显著加快执行速度
- **数小时自适应**：从 VLA zero-shot 到性能提升只需 2-4 小时在线实践
- **超越人类速度**：在部分灵巧操作阶段，RL 策略比 expert teleoperation 更快

### 不能做什么
- **未见过的任务类型**：仅针对 4 个特定任务微调，泛化到新任务需要重新训练 RL Token
- **长视距操作**：实验任务均为中等 horizon（数十秒级别），未验证分钟级长任务
- **无 VLA 先验的情况**：如果 VLA 对任务完全无能力（成功率接近 0），RLT 的参考动作正则化可能成为束缚

### 6.1 隐含假设 (Hidden Assumptions)

1. **VLA 已有基础能力**：RLT 假设 VLA 对目标任务至少有 ~20% 的基础成功率。如果 VLA 完全不会，RL Token 的重建目标可能无法捕获有效信息。

2. **固定语言指令**：实验中每个任务使用固定指令，因此跳过了语言嵌入。多指令/多任务场景未验证。

3. **单一机器人平台**：所有实验在同一机械臂上完成，未验证跨平台迁移（如不同自由度、不同相机布局）。

4. **稀疏二元奖励足够**：仅使用 episode 级别的 success/failure 信号。对于需要中间奖励的复杂任务，性能可能受限。

5. **演示数据质量**：RL Token 训练需要少量高质量演示。如果演示数据噪声大，压缩表示可能编码错误信息。

| 方法 | 更新范围 | 动作空间 | 样本效率 | 实验平台 | 关键差异 |
