💡 **X-Ray 开场**
工业机器人（如 ABB）通过高层控制接口暴露，更新率低、闭环响应慢，导致观测-推理-执行之间的时间间隙可达数百毫秒。这篇论文把「延迟」从实现细节提升为系统级核心问题：不修改策略本身，而是给策略输出的动作序列打上时间戳，只执行当前时间窗口内可行的动作。结果：在 100-500ms 推理延迟下，运动质量和接触力都接近专家演示水平。对 VLA 研究者的意义是——当 VLA 模型（推理延迟通常 50-500ms）部署到工业臂上时，延迟感知调度不是「锦上添花」，而是「不这样做就会力超调或任务失败」的必须项。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 阻塞式执行 (Blocking) | Naive 异步执行 | 延迟感知执行 (本文) |
|------|----------------------|----------------|---------------------|
| 推理与执行关系 | 串行：推理时暂停执行 | 并行：动作到达即发送 | 并行：按时间戳调度可行动作 |
| 动作缓冲 | 无 — 推理完执行固定步数 | 无 — 直接流式发送 | 有时间戳的动作缓冲区 |
| 延迟补偿 | 无（通过空闲时间自然吸收） | 无（执行过期动作） | 显式：τ_target = τ_now + δ_exec |
| 空闲时间 | 随推理延迟线性增长 | 极低 | 低（与 naive 相当） |
| 接触力超调 | 中等（启动-停止行为） | 严重（5.1-5.5× 基准） | 低（接近基准） |
| 任务时长 | 随延迟增长（18s→24s） | 最短但质量差 | 稳定（12s，接近基准 13.6s） |

### 1.2 关键机制 (Key Mechanism)

论文识别了三个延迟来源（Fig. 1）：

- **观测延迟**（~82ms 相机）：传感器采集 → 工作站可用的时间差，含曝光、处理、通信、中间件缓冲
- **推理延迟**（100-500ms）：策略处理观测并输出动作序列的时间，取决于模型架构和算力
- **执行延迟**（~225ms ABB EGM）：发送指令 → 机器人物理运动的时间差，含通信、缓冲、控制器动力学

> ⚡ **Eureka Moment**：给策略输出的每个动作分配意图执行时间戳 `τ = τ_obs + i·Δτ`，调度器只选择当前时间窗口内「尚未过期且尚未到达」的可行动作——不修改策略，只修改执行接口。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
a_exec = buffer[τ_now + δ_exec]    // 只执行时间戳匹配的可行动作
```

**目标**：在观测-执行间隙非零的情况下，确保物理执行的动作与机器人当前物理状态时间一致。

**核心方程**：

```
策略接口:  a_{t+1:t+Tₚ} = π(o_{t-T₀:t})
时间戳分配: τ_i = τ_obs + i·Δτ,   i = 1, ..., Tₚ
调度选择:  a_exec = buffer[τ_now + δ_exec]
```

**变量说明**：

| 符号 | 含义 | 本文取值 |
|------|------|----------|
| T₀ | 观测历史窗口 | 1 |
| Tₚ | 动作预测 horizon | 16 |
| Δτ | 策略执行周期 | 100ms (10Hz) |
| δ | 执行延迟估计 | ~225ms (ABB EGM) |
| τ_obs | 观测时间戳 | 连续时间 |
| τ_now | 当前调度周期时间 | 连续时间 |

> 符号与本文保持一致。策略接口是黑盒抽象——任何输出有限步动作序列的策略（BC、Diffusion、VLA）都适用。

**直觉**：策略每 100ms 输出 16 步动作（覆盖未来 1.6s）。延迟感知调度器维护一个按时间戳索引的缓冲区。每个控制周期，计算目标时间 `τ_now + δ`，从缓冲区中取出对应时间戳的动作。如果目标时间落在两个缓冲动作之间，线性插值。过期动作（时间戳 < τ_now）被丢弃。新推理结果到来时，整个缓冲区被替换——不回溯修改已执行的命令。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设当前时刻 τ_now = 5.000s，执行延迟 δ = 225ms：

```
步骤 1: 策略在 τ_obs = 4.900s 收到观测，输出 16 步动作
  时间戳分配:
    τ₁ = 4.900 + 1×0.100 = 5.000s  → a₁ = [Δx=0.01, Δy=0.00, Δz=0.02]
    τ₂ = 5.100s  → a₂ = [0.01, 0.01, 0.02]
    τ₃ = 5.200s  → a₃ = [0.02, 0.01, 0.01]
    ...
    τ₁₆ = 6.500s → a₁₆

步骤 2: 调度器在 τ_now = 5.000s 计算目标时间
  τ_target = τ_now + δ = 5.000 + 0.225 = 5.225s

步骤 3: 在缓冲区中查找 τ = 5.225s 对应的动作
  落在 τ₃ = 5.200s 和 τ₄ = 5.300s 之间
  线性插值: a_exec = a₃ + 0.25×(a₄ - a₃)
             = [0.02, 0.01, 0.01] + 0.25×([0.02, 0.02, 0.01] - [0.02, 0.01, 0.01])
             = [0.02, 0.0125, 0.01]

步骤 4: 发送 a_exec 到 ABB EGM 控制器
  同时丢弃 τ₁ = 5.000s（已过期，τ₁ < τ_now）
```

对比 naive 异步执行：策略在 4.900s 输出的 a₁（意图在 5.000s 执行），但实际到达控制器时已经是 ~5.225s——此时机器人状态已经变化，a₁ 相对于当前状态是「过期动作」，可能导致力超调或运动不连续。

对比阻塞执行：推理期间（4.900-5.000s，假设 100ms 延迟）暂停执行，产生空闲时间。任务总时长从 13.6s 膨胀到 18.4s（+35%）。

## 5. 数据与评测 (Data & Eval)

**任务**：木材角搭接装配（corner lap joint）——一个六轴机械臂将垂直木料插入固定水平木料的匹配槽中。包含自由空间运动、接触起始、持续滑动三个阶段。

**数据**：
- 20 条专家演示（VR 遥操作采集）
- 观测-动作同步到 10Hz 网格（Δτ = 100ms）
- 观测维度：9D 位姿 + 6D 力/力矩 + 600D HOG 视觉 = 615D
- 归一化：分位数归一化（qℓ=0.01, qu=0.99），模态维度缩放 1/√dₘ

**策略**：k-NN (k=5, T₀=1, Tₚ=16) ——确定性策略，消除策略随机性干扰

**推理延迟设置**：人工插入 100ms / 300ms / 500ms 固定延迟
- 参考：Diffusion Policy (10 DDIM steps) = 49±1ms；标准 DDPM (100 steps) = 466±9ms

**评测指标**（6 项）：

| 指标 | 定义 | 物理意义 |
|------|------|----------|
| Task Duration | 运动开始到完成的总时间 | 效率 |
| Idle Ratio | TCP 速度 <1mm/s 的时间占比 | 空闲浪费 |
| Contact Force (RMS) | 接触阶段（力 >5N）的力大小 RMS | 接触稳定性 |
| Peak Force | 接触阶段最大瞬时力 | 力超调风险 |
| Force Smoothness | 力大小时间导数的 RMS | 力振荡程度 |
| Motion Smoothness | Cartesian jerk 的 RMS | 运动流畅度 |

**实验总数**：3 种执行策略 × 3 种延迟 × 20 次重复 = 180 次 rollout，全部成功完成任务。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

- **在 100-500ms 推理延迟下保持稳定的任务时长**：延迟感知执行的任务时长在 12.08-12.18s 范围内波动（基准 13.6s），而阻塞式从 18.4s 增长到 23.6s
- **消除接触力超调**：接触力 RMS 在 35-45N 范围（基准 74N），远优于 naive 异步的 180-320N
- **保持运动平滑度接近基准**：jerk RMS 在 0.46-0.51（基准 0.47），而阻塞式在 0.70-0.85
- **不修改策略架构**：任何输出有限步动作序列的策略都可直接接入

### 不能做什么

- **不处理时变延迟**：离线校准假设观测和执行延迟恒定。如果网络抖动或控制器负载变化导致延迟漂移，调度精度下降
- **不提升策略本身的质量**：如果策略输出的动作序列本身质量差（训练数据不足、分布外泛化差），延迟感知调度无法补偿
- **不覆盖旋转控制**：当前实验限制为平移 TCP 运动，旋转控制未评估
- **不覆盖多模态消融**：单一任务、单一初始位姿，未评估不同任务类型或初始条件的鲁棒性
- **不处理多阶段长程装配**：未评估多个装配步骤串联时延迟累积效应

### 6.1 隐含假设 (Hidden Assumptions)

1. **延迟恒定假设**：观测延迟（82ms）和执行延迟（225ms）通过离线校准获得，假设任务期间不变。实际工业环境中网络负载波动、控制器温度漂移可能导致延迟变化 ±20-50ms
2. **线性插值足够假设**：缓冲区动作间用线性插值。论文承认高阶插值或轨迹平滑可能影响稳定性，但认为插值间隔短（100ms）时线性足够——这在高接触力场景下可能不成立
3. **k-NN 代理策略的泛化性**：用 k-NN 代替真实 VLA 策略来隔离执行效应。但 k-NN 的输出平滑性与 Diffusion/VLA 不同——真实策略的 action chunk 边界跳变可能更大
4. **单一机器人平台**：ABB IRC5 + EGM 接口。其他品牌（KUKA FRI、Fanuc CRX）的控制接口特性和延迟特性可能不同
5. **10Hz 控制频率足够**：选择 10Hz 是因为与 VLA 策略推理频率匹配。但对于高动态接触任务，可能需要 30-100Hz 的控制频率

## 7. 与相关工作对比 (Comparison)

| 方法 | 关注点 | 架构改动 | 训练改动 | 延迟处理 | 适用平台 |
|------|--------|---------|---------|---------|---------|
| Action Chunking (RT-1) | 减少推理频率 | 策略输出多步 | 否 | 隐式（chunk 吸收延迟） | 桌面级低延迟 |

| Real-time Flow Policy (Black et al.) | 异步 chunk 补全 | 策略 inpainting | 是 | 推理时重生成 | 需要额外推理 |

| Hierarchical VLA | 分层控制频率 | 规划+执行两层 | 是 | 分层管理 | 需要架构改动 |
| **本文** | **执行接口调度** | **否（黑盒）** | **否** | **显式时间戳调度** | **工业臂高延迟** |

> **面试 Tip**：当被问到「VLA 部署到工业臂的最大挑战是什么？」——回答「不是策略性能，而是观测-执行间隙。工业臂的高层控制接口和慢闭环动力学使延迟成为主导性系统约束。解决方案不一定需要改策略架构——时间戳对齐的动作调度（如本文的延迟感知执行）可以在零策略改动的前提下，将接触力超调降低 5-8 倍。」
