## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 问题背景与痛点

| 问题维度 | 具体表现 | 根本原因 |
| --- | --- | --- |
| **数据稀缺** | 动作标注视频极少，无法大规模训练 | 真实机器人/游戏动作标注成本高 |
| **迁移失败** | 在场景 A 学习的动作无法用于场景 B | 潜在动作纠缠场景特定线索 |
| **坐标系统一** | 同一语义动作（如"前进"）在不同环境中对应不同潜在方向 | 标准目标函数仅在 clip 内部操作，缺乏跨场景对齐机制 |

### 1.2 系统组件对比 (System Component Comparison)

| 组件 | 输入 | 输出 | 频率/时序 | 训练/推理差异 |
| --- | --- | --- | --- | --- |
| **冻结视频编码器** | 原始视频帧序列 | 自监督视频特征 | 每帧 | 固定权重，不更新 |
| **潜在动作编码器** | 视频片段 | 潜在动作序列 z_a | 每 T 帧 | 训练时学习 |
| **SeqΔ-REPA 对齐模块** | 潜在动作 + 视频特征差分 | 对齐损失 | 每个序列 | 仅训练时使用 |
| **世界模型解码器** | 潜在动作 + 当前状态 | 预测下一帧 | 每步 | 训练/推理一致 |

### 1.3 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **效果可观测，动作不可观测**: 虽然动作标签缺失，但动作引起的视频变化（效果）是可见的
2. **效果作为共享参考**: 使用冻结的自监督视频编码器提取的时序特征差分作为"效果方向"
3. **序列级对齐**: 不是单帧对齐，而是整个动作序列的轨迹对齐，捕获时间动态

## 2. 数学核心 (Math Core)

### 2.1 优化目标

**目标**: 学习潜在动作表示 z_a，使其与视频特征的变化方向 Δh 对齐

```
min_θ  L_align = E_{clips} [ 1 - cos(z_a, Δh) ]

其中:
  z_a = f_θ(clip)              # 潜在动作编码器输出
  h_t = φ(frame_t)             # 冻结视频编码器特征
  Δh = h_{t+T} - h_t           # 时序特征差分 (效果方向)
  cos(a, b) = (a·b) / (||a||·||b||)  # 余弦相似度
```

### 2.2 变量说明

| 符号 | 含义 | 维度 | 来源 |
| --- | --- | --- | --- |
| φ | 冻结的自监督视频编码器 | - | 预训练模型 (如 VideoMAE) |
| f_θ | 待学习的潜在动作编码器 | - | Olaf-World 训练 |
| h_t | t 时刻的视频特征 | d_model | φ(frame_t) |
| Δh | 效果方向 (特征差分) | d_model | h_{t+T} - h_t |
| z_a | 潜在动作表示 | d_action | f_θ(clip) |
| T | 动作持续时间 (帧数) | - | 超参数 |

### 2.3 直觉解释

- **传统方法**: 仅最小化重建误差，潜在动作可以编码任何能帮助重建的信息（包括场景外观）
- **SeqΔ-REPA**: 强制潜在动作与"变化方向"对齐，剥离静态场景信息，只保留动作语义
- **跨场景迁移**: 不同场景中的"前进"动作可能外观不同，但引起的特征变化方向相似

> 符号与本文/相关文档保持一致：Δ 表示差分，θ 表示可学习参数，φ 表示冻结编码器

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有一个简化的 2D 特征空间来说明对齐过程：

**场景设定**:
- 特征维度 d_model = 2
- 动作维度 d_action = 2
- 时间跨度 T = 10 帧

**步骤 1: 冻结编码器提取特征**
```
场景 A (第一人称游戏):
  h_0 = [0.5, 0.3]     # 初始帧特征
  h_10 = [0.8, 0.4]    # 10 帧后特征 (角色向前移动)
  Δh_A = h_10 - h_0 = [0.3, 0.1]

场景 B (第三人称游戏):
  h_0 = [0.2, 0.7]     # 初始帧特征 (不同视角/外观)
  h_10 = [0.4, 0.9]    # 10 帧后特征 (角色同样向前移动)
  Δh_B = h_10 - h_0 = [0.2, 0.2]
```

**步骤 2: 潜在动作编码器 (未对齐时)**
```
场景 A: z_a_A = [0.9, 0.1]  # 可能编码了场景 A 的特定外观
场景 B: z_a_B = [0.3, 0.8]  # 与 z_a_A 方向不同，无法迁移

cos(z_a_A, z_a_B) = 0.52  # 相似度低
```

**步骤 3: SeqΔ-REPA 对齐后**
```
场景 A: z_a_A' = [0.95, 0.32]  # 向 Δh_A 方向对齐
场景 B: z_a_B' = [0.71, 0.71]  # 向 Δh_B 方向对齐

cos(z_a_A', Δh_A) = 0.98  # 高对齐
cos(z_a_B', Δh_B) = 0.96  # 高对齐
cos(z_a_A', z_a_B') = 0.89  # 跨场景相似度提升
```

**步骤 4: 零样本迁移**
```
在场景 A 上训练线性探头: action = W · z_a + b
直接应用于场景 B: 准确率从 45% (未对齐) 提升到 78% (对齐后)
```

## 4. 工程视角 (Engineering View)

### 4.1 计算开销分析

| 模块 | 训练时 FLOPs | 推理时 FLOPs | 内存占用 |
| --- | --- | --- | --- |
| 冻结视频编码器 | ~30% (前向) | ~30% (前向) | 固定 (不存梯度) |
| 潜在动作编码器 | ~20% (前向 + 反向) | ~20% (前向) | 低 |
| SeqΔ-REPA 损失 | ~5% | 0 (推理不用) | 可忽略 |
| 世界模型解码器 | ~45% (前向 + 反向) | ~50% (前向) | 高 (主模型) |

### 4.2 延迟与吞吐

- **训练吞吐**: 受限于冻结编码器的前向传播 (可预先缓存特征加速)
- **推理延迟**: 潜在动作编码 + 世界模型解码，典型值 50-200ms/步 (取决于视频分辨率)
- **优化技巧**: 
  - 预计算并缓存视频特征 (离线处理)
  - 潜在动作可提前采样 (自回归解码时并行)

### 4.3 部署约束

| 约束 | 影响 | 缓解方案 |
| --- | --- | --- |
| 冻结编码器需与训练时一致 | 部署时必须携带完整 φ 模型 | 蒸馏到更小的编码器 |
| 时序窗口 T 固定 | 无法处理可变长度动作 | 多尺度训练或动态池化 |
| 特征维度 d_model 大 | 内存占用高 | 特征降维 (PCA/自编码器) |

## 5. 数据与评测 (Data & Eval)

### 5.1 训练数据

| 数据集 | 类型 | 规模 | 标注 |
| --- | --- | --- | --- |
| **MiraData** | 游戏视频 (第一/第三人称) | ~100K 视频 | 无动作标注 |
| **被动视频** | YouTube/网络爬取 | 大规模 | 无标注 |

### 5.2 评测任务

**1. 跨场景线性探测 (Cross-context Linear Probing)**
- 设置: 在场景 A (第一人称) 训练线性探头，在场景 B (第三人称) 测试
- 指标: 动作分类准确率
- 结果: SeqΔ-REPA 相比基线提升 ~15-20%

**2. 跨场景动作相似度 (Cross-context Action Similarity)**
- 设置: 计算每类动作的原型，可视化 1st-P vs 3rd-P 的余弦相似度矩阵
- 指标: 对角线优势 (diagonal-dominant)
- 结果: SeqΔ-REPA 产生更清晰的对角线，基线则呈现广泛高相似 (纠缠)

**3. 零样本动作迁移 (Zero-Shot Action Transfer)**
- 设置: 在源场景学习动作，直接应用于目标场景生成视频
- 指标: 人工评估 + VBench 自动评测
- 结果: Olaf-World 在动作一致性和视频质量上均优于 AdaWorld

**4. 高效适配 (Efficient Adaptation)**
- 设置: 使用 0/1/50 个标注视频进行适配 (~0 min / ~1 min / ~2 hours)
- 指标: 适配后动作跟随可靠性
- 结果: 在~1 min 预算下，Olaf-World 保持可控，DirectAct 过拟合，AdaWorld 跟随不可靠

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 6.1 能做什么

| 能力 | 场景示例 | 技术原因 |
| --- | --- | --- |
| **零样本动作迁移** | 将第一人称射击游戏的"开火"动作迁移到第三人称游戏 | 效果方向对齐剥离了视角依赖 |
| **数据高效适配** | 仅用 1 分钟标注视频适配新控制接口 | 潜在动作已有良好结构，只需微调 |
| **跨域动作组合** | 将"移动"+"射击"两个动作序列组合生成新视频 | 序列级对齐保持时间动态 |

### 6.2 不能做什么 / 失败模式

| 失败模式 | 表现 | 根本原因 |
| --- | --- | --- |
| **剧烈外观变化** | 源场景和目标场景视觉差异过大时迁移质量下降 | 冻结编码器的特征空间不够鲁棒 |
| **长序列动作** | 超长动作序列 (>100 帧) 的对齐效果减弱 | SeqΔ-REPA 的序列窗口有限 |
| **多动作并发** | 同时发生多个独立动作时难以解耦 | 潜在动作是单一向量，缺乏结构化分解 |
| **精细控制** | 需要亚像素级精度的动作 (如微操) 难以准确迁移 | 特征差分是粗粒度信号 |

## 7. 与相关工作对比 (Comparison)

### 7.1 方法对比

| 方法 | 关注点 | 架构 | 训练方式 | 适用场景 |
| --- | --- | --- | --- | --- |
| **DirectAct** | 直接动作回归 | 端到端 CNN/RNN | 监督学习 (需动作标注) | 标注充足场景 |
| **AdaWorld** | 自适应世界模型 | 扩散模型 + 条件嵌入 | 自监督 + 少量标注适配 | 单场景高效适配 |
| **LAMs (传统)** | 潜在动作建模 | VAE + 动力学模型 | 自监督 (重建误差) | 单场景表示学习 |
| **Olaf-World** | 跨场景动作对齐 | 冻结编码器 + SeqΔ-REPA | 自监督 (效果对齐) | **跨场景零样本迁移** |

### 7.2 关键差异

- **vs DirectAct**: Olaf-World 无需动作标注，DirectAct 需要大量标注
- **vs AdaWorld**: Olaf-World 强调跨场景迁移，AdaWorld 专注单场景高效适配
- **vs 传统 LAMs**: Olaf-World 引入外部参考系 (冻结编码器特征差分)，传统 LAMs 仅依赖内部重建
