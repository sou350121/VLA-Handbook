## 1. 核心架构/方法总览

### 1.1 系统对比概览

论文把系统拆成两个可独立演化的对象：harness H_r = (L_r, M_r, ρ_r) 与策略 π_θr。

| 组件 | 输入 | 输出 | 更新频率 | 训练/推理 |
|------|------|------|----------|-----------|
| 技能库 L_r | 任务指令、当前视角、失败定位 | 可执行程序（原子技能 + 组合技能） | 每轮 P2H 后合并 | 推理时执行，不训练 |
| 经验记忆 M_r | 失败上下文、尝试过的解、验证结论 | 检索用的经验条目（通用记忆 + 任务经验） | 每轮累积 | 纯文本检索，非参数 |
| 路由 ρ_r | 当前子目标、上一步执行状态 | 该步走 code 技能还是调 policy | 每轮按需改写 | 写在 agent 指令里的规则 |
| 策略 π_θr | 观测 + 指令 | 动作块（LIBERO-PRO 记录为 10 步） | 每轮 H2P 后 | SFT + CPD + EWC |
| 编码智能体 | 失败帧、记忆、技能源码 | patch / 新技能 / 记忆增量 | 每个失败项多次调用 | GPT-6 Astra（xhigh） |

初始 harness H_0 由 CaP-X 与 RATs 提供的机器人 API 与参数化代码技能构成；初始策略 π_θ0 是在示教数据 D_0 上微调的预训练 VLA 或 WAM。**注意归属**：LIBERO-PRO、RoboTwin C2R、MolmoSpaces、Unitree G1-D 上的策略主体是 π0.5；只有 LIBERO-PRO 对比表里额外出现了 FastWAM 变体。不要把 FastWAM 的属性算到 π0.5 头上。

### 1.2 关键机制

每轮四个阶段：

1. **Policy Rollouts**：当前策略独立跑任务，任务级验证器把轨迹切成成功集 S_r 与失败集 F_r。
2. **P2H（Policy-to-Harness）**：对每个失败 f，VLM 编码智能体并行探三条路线——Code（只改代码技能）、Code+ICL（额外给一条同任务但不同场景的示教）、Code+Policy（可把当前策略当作运动原语调用）。每条路线独立执行、反馈修复，最多留一个成功解，最后按归一化 jerk 最小者胜出。
3. **H2P（Harness-to-Policy）**：成功轨迹 + harness 生成的修复轨迹进 SFT 数据池；同状态的成功/失败配对进 CPD 偏好数据池。
4. **Evaluation & Selection**：在匹配的 dev 任务、初始状态与执行预算下比较新旧版本，只有对应成功率提升才保留更新。

⚡ **Eureka Moment**：失败不是要丢弃的噪声，而是“同一初始状态下的一条成功对照 + 一条失败对照”——这个配对天然构成反事实偏好数据，让策略学到“该做什么”之外的“不该做什么”。

## 2. 数学核心

📌 **Napkin Formula**（一行抓住本质）：

```
L_total = L_sup + λ_pref·(L_gap + λ_prox·L_prox) + (λ_EWC/2)·Σ_i F_i(θ_i − θ̄_i)²
```

目标是让策略在“成功修正 vs 失败原案”的相对损失上拉开一个 margin，同时不许离参考策略太远。

先看 CPD 的差值定义：

```
δ± = ℓ_θ(y± | x) − ℓ_θ̄r(y± | x)      # 相对冻结参考策略的损失变化
Δ  = δ+ − δ−                          # 成功/失败损失差的相对变化
```

再看两个约束项：

```
L_gap  = E[ ( max{Δ, −m} + m )² ]
L_prox = E[ [δ+]_+²  +  [δ− − κ]_+² ]      其中 [z]_+ = max(z, 0)
```

失败感知采样：

```
w_{r,k} = (1 − ŝ_{r,k})^γ
p_{r,k}^{(b)} = 1/(2|K_b|) + w_{r,k} / (2·Σ_j w_{r,j})
```

选解用的归一化 jerk：

```
J(τ) = D_τ^5 / (|A_g|·L_g²) · Σ_{a∈A_g} ∫_0^{D_τ} ‖p⃛_a(t)‖² dt
```

| 符号 | 含义 |
|------|------|
| ℓ_θ(y\|x) | 单样本训练损失 |
| θ̄_r | 轮次 r 开始时冻结的策略参数 |
| y+ / y− | 同一起始状态下的成功修正 / 失败动作目标 |
| m | 偏好 margin，配置为 m = 1/(2β)，β=0.5 → m=1.0 |
| κ | 允许的负样本损失上升上限，0.3 |
| λ_pref / λ_prox | 0.02 / 0.5 |
| γ | 失败权重指数，1 |
| F_{r,i} | EWC 参数重要性，用平方逐样本梯度估计 |

**直觉**：Δ 越负越好（成功目标的损失降得比失败目标多）。max{Δ, −m} 是个铰链——一旦 Δ ≤ −m 就归零，不再施压；L_prox 是单向刹车，只惩罚“成功目标变差”和“失败目标被打压过头”。J(τ) 里的 D⁵ 与 ‖p⃛‖² 的时间积分正好抵消，所以这个量对匀速放慢/加快不敏感，只惩罚真正的抖动。

## 3. 带数字走一遍：玩具例子

> 以下数值为**假设**，仅用于验算 CPD 的方向性与量级，不代表论文实测。

假设某轮某任务拿到一个同状态配对 (x, y+, y−)，参考策略对两者一视同仁：

```
参考策略：ℓ_θ̄(y+|x) = 0.40,  ℓ_θ̄(y−|x) = 0.40
当前策略：ℓ_θ(y+|x) = 0.30,  ℓ_θ(y−|x) = 0.55
```

计算：

```
δ+ = 0.30 − 0.40 = −0.10
δ− = 0.55 − 0.40 = +0.15
Δ  = −0.10 − 0.15 = −0.25
```

代入（m = 1.0，κ = 0.3）：

```
L_gap  = (max(−0.25, −1.0) + 1.0)² = (0.75)² = 0.5625
L_prox = [−0.10]_+² + [0.15 − 0.3]_+² = 0 + 0 = 0
L_pref = 0.5625 + 0.5×0 = 0.5625
```

反向假设——策略学歪了，成功目标反而变差：

```
ℓ_θ(y+|x) = 0.50 → δ+ = +0.10
ℓ_θ(y−|x) = 0.30 → δ− = −0.10
Δ = +0.20
L_gap  = (0.20 + 1.0)² = 1.44
L_prox = (0.10)² + [−0.10 − 0.3]_+² = 0.01
```

**验算结论**：方向错误时主项从 0.56 涨到 1.44，惩罚确实显著变大；且 δ+ 为正会额外触发 proximity 惩罚，形成双重压制。这也暴露一个量级问题——m=1.0 相对 0.1~0.5 量级的 per-sample 损失偏大，L_gap 在实际训练中更多是“恒定的软约束”而非精细 margin。这是**条件性分析**，论文未讨论该尺度选择。

**关于“记忆窗口”的一个常见误读**：动作块长度 10 指的是策略一次预测 t+1 至 t+10 这 10 个未来动作步，终点距当前参考是 10×Δt；它不是历史观测窗口。若均匀采样 K 帧作为历史上下文，其首末跨度是 (K−1)×Δt——10 帧历史只覆盖 9×Δt。两者单位相同、语义完全不同。harness 的 M_r 是文本经验库，与帧序列窗口无关。另外，动作块 10 只在 LIBERO-PRO 的训练配置里出现，RoboTwin / MolmoSpaces / G1-D 的表格未给出该值，不能把 10 写成所有实验共有的设定。

**延迟结构**：standalone 模式只有策略前向；hybrid 模式每一步都要经过 agent 路由（code staging → policy call → 重新观测）。所以 hybrid 的成功率更高但延迟与 API 成本也更高。论文用 8 轮把 hybrid 与 standalone 的差距从 19.4 个百分点压到 6.4 个百分点（30.4→90.5 vs 11.0→84.1），这正是“把 agentic 开销摊销进策略”的直接体现。

## 6. 能力与失败模式

**能做**：把策略自身失败转化为可复用代码技能与偏好数据；在分布偏移下逐轮提升；跨本体复用冻结 harness（ALOHA 45.8% / ARX-X5 42.5% / Franka-Panda 41.0%，衰减温和）。

**不能做/未验证**：

- 原子技能库固定，不含力控接触、手内重抓取（附录 H 作者自述）。
- 失败恢复依赖任务级二值成功验证器；真机上还依赖操作员复位，复位一致性未被量化。
- 跨本体只调“机器人专用控制接口”，形态差异更大的平台未测。
- 选解准则是 min J(τ)，低抖动 ≠ 高鲁棒，可能选中“平滑但在扰动下易崩”的解。
- RoboTwin 长尾任务仍很低：hanging_mug 31%、place_cans_plasticbox 35%、move_stapler_pad 50%。

### 6.1 隐含假设

1. **同状态可比性**：CPD 要求成功与失败从“相同起始状态、匹配执行条件”出发。仿真里可靠放动作即可复原；真机上靠人工近似复位，这一假设被弱化但未验证。
2. **验证器可信**：所有监督信号都来自任务级成功判定，验证器假阳性会直接污染 SFT 与 CPD 数据。
3. **harness 改进可叠加**：跨失败合并技能时只做兼容性检查与整体评测，未分析技能间冲突的累积效应。
4. **agent 能力上限即系统上限**：换 Qwen3.8-27B 后 standalone 从 84.1 掉到 76.0、hybrid 从 90.5 掉到 82.5（表 19），说明瓶颈部分在编码智能体而非策略。
5. **EWC 足以防遗忘**：消融显示关掉 EWC 后 LIBERO 从 92.5 掉到 72.0，而 LIBERO-PRO 几乎不变（84.1 vs 84.3）——说明 EWC 保护的是旧任务，不是新任务性能。
