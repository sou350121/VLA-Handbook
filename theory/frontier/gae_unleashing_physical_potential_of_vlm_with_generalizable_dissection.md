### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **接口极简主义**：GAE 的核心设计哲学是"动作专家不应理解语义"。传统双系统让动作专家处理视觉特征或抽象嵌入，这些信号既复杂又任务相关。GAE 改用"同空间"接口——VLM 输出 3D 位姿，GAE 输出也是 3D 位姿（密集化后）。动作专家的角色从"理解意图"降级为"几何运动细化"。

2. **相机坐标系输出**：大多数 VLA 在机器人基座坐标系下预测动作，要求 VLM 隐式学习相机→基座的变换。GAE 让 VLM 在相机坐标系下输出 2D 关键点+深度，这天然匹配 VLM 的图像预训练先验，降低了空间推理难度。

3. **APPF 两阶段训练**：动作专家需要同时掌握"轨迹跟踪"和"几何感知细化"两项技能。联合训练效率低且次优。APPF 先在大批量纯轨迹数据上预训练（batch size 高达 31,824），让模型学会基本运动跟随；再用点云数据微调，学习环境感知细化。

⚡ **Eureka Moment**：让 VLM 和 Action Expert 在同一个动作空间内通信——VLM 输出稀疏位姿，GAE 输出密集位姿。接口极简到"同一种语言的不同分辨率"，动作专家不再需要理解任何语义。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
GAE: π(a_t | S_t, P_g, O_pcd) = DiffusionReverse(ε_θ, f_t^A)
其中 f_t^A = concat(MLP(S_t), MLP(P_g), PointNet(O_pcd))
```

**目标**：给定稀疏引导位姿和实时点云，学习一个条件扩散策略，输出密集可执行动作。

**扩散训练目标**：
```
L_AE = E_{k~[1,K], a_t^0~D, ε~N(0,I)} [ ||ε - ε_θ(a_t^k, k, f_t^A)||^2 ]
```

其中：
- `a_t^k = sqrt(ᾱ_k) · a_t^0 + sqrt(1-ᾱ_k) · ε`（加噪过程）
- `ε_θ` 是噪声预测网络
- `f_t^A` 是条件特征向量

**变量说明**：

| 符号 | 含义 |
|------|------|
| S_t | 机器人本体状态（关节位置、夹爪状态） |
| P_g | 引导位姿（从 VLM 轨迹每 8 步采样） |
| O_pcd | 裁剪点云观察（无颜色，鼓励几何聚焦） |
| $f_t^A$ | 拼接后的条件特征向量 |
| $a_t^0$ | 地面真实动作（8步动作块） |
| $a_t^k$ | 第 k 步加噪后的动作 |
| $\varepsilon_\theta$ | 噪声预测网络（可学习参数 $\theta$） |
| $\bar{\alpha}_k$ | 噪声调度参数 |

> 符号与本文保持一致：扩散过程使用标准 DDPM  formulation，动作块大小为 8，动作空间为末端执行器 6-DoF 位姿。

**直觉**：GAE 本质上是一个"几何条件扩散策略"。它不关心"要做什么任务"，只关心"当前状态是什么 + 要去哪个位姿 + 周围环境几何如何"。这种极简的条件设定使得模型可以跨任务泛化——因为所有操纵任务的低层几何推理是共享的。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2D 抓取场景：

**场景设置**：
- 机器人基座在原点 (0, 0)
- 目标物体在 (0.3m, 0.2m)
- 障碍物在 (0.15m, 0.1m)

**VLM 输出（相机坐标系）**：
```
关键点 1: (u=150, v=200, d=0.5m) → 基座系 P₁ = (0.10, 0.05)
关键点 2: (u=200, v=180, d=0.4m) → 基座系 P₂ = (0.20, 0.15)
目标位姿: (u=220, v=170, d=0.35m) → 基座系 P_target = (0.30, 0.20)
```

**B-Spline 插值**（生成连续轨迹）：
```
T(0) = P₁ = (0.10, 0.05)
T(8) = (0.13, 0.08)   ← GAE 采样点 1
T(16) = (0.17, 0.12)  ← GAE 采样点 2（附近有障碍物）
T(24) = (0.22, 0.16)  ← GAE 采样点 3
T(32) = P_target = (0.30, 0.20)
```

**GAE 在 T(16) 处的推理**（障碍物附近）：
```
输入:
  S_16 = [关节角: 45°, 30°, 夹爪: 开]
  P_g = (0.17, 0.12)  ← 直接直线会撞到障碍物
  O_pcd = 点云显示障碍物在 (0.15, 0.10) 半径 0.05m 范围内

扩散去噪过程（K=10 步）:
  a_16^K ~ N(0, I) = 随机噪声动作
  ↓ ε_θ 迭代去噪
  a_16^0 = (0.18, 0.15, θ=10°)  ← 绕开障碍物的修正位姿

输出: 8步动作块，第一步执行 (0.18, 0.15) 而非原始引导 (0.17, 0.12)
```

**关键观察**：GAE 不需要知道"这是抓取任务"。它只看到"引导位姿指向障碍物附近 + 点云显示有障碍"，然后输出一个绕开的修正动作。这正是"几何运动细化"的核心——语义理解由 VLM 完成，几何推理由 GAE 完成。

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/设计 | 含义 |
|----------|-----------|------|
| 动作块大小 | 8 步 | 每 8 个控制周期重新采样一次引导位姿并推理 |
| 引导位姿采样频率 | 每 8 步 | VLM 轨迹经 B-spline 后，每 8 步取一个 P_g |
| 扩散推理步数 K | 论文未明确（典型 10-50） | 推理延迟与动作质量的 trade-off |
| GAE 训练 batch size | 最高 31,824（预训练阶段） | APPF 第一阶段可用超大 batch |
| VLM SFT 步数 | 详见 Table 3（数百到数千步） | 相比全量微调（数万步）大幅降低 |
| 点云处理 | 前景裁剪 + 均匀下采样 + 无颜色 | 减少计算量，强制几何聚焦 |
| GAE 推理时 | 冻结，跨任务复用 | 新任务无需重新训练 GAE |
| 闭环更新 | VLM 异步二次推理 | 执行当前轨迹时并行生成新计划 |

**工程含义**：
1. **部署友好**：GAE 冻结后，新任务只需轻量 VLM SFT，大幅降低部署成本。
2. **实时性**：动作块 8 步 + 每 8 步采样引导位姿，控制频率取决于底层执行器（通常 10-30Hz）。
3. **传感器依赖**：需要深度相机（RealSense D435）生成点云。无深度传感器的平台无法直接部署。
4. **计算分布**：VLM 推理（大模型） + GAE 扩散推理（中等模型）+ IK 求解（轻量）。主要瓶颈在 VLM。

### 6.1 隐含假设 (Hidden Assumptions)

1. **VLM 能可靠输出 3D 位姿**：论文假设经过轻量 SFT 后 VLM 能稳定输出准确的 2D 关键点+深度。但如果 VLM 对某些物体类别从未见过，深度估计可能严重偏差。

2. **点云足以表征操作几何**：使用无颜色点云是为了让 GAE 聚焦几何。但对于需要颜色区分的任务（如区分红色和蓝色积木），纯几何信息可能不足。

3. **B-Spline 插值足够平滑**：稀疏关键帧之间的 B-Spline 插值假设运动路径是光滑的。但对于需要非连续动作的任务（如先抓取再旋转再放置），插值可能产生中间态位姿。

4. **仿真→真实迁移可行**：150k 轨迹中包含大量仿真数据。仿真到真实的 domain gap 在点云层面依然存在（仿真点云更干净、无噪声）。
