### 1.2 关键机制 (Key Mechanism)

Riemann-1.0 的核心设计围绕三个关键机制：

1. **全因果自回归因子化**：动作预测和视觉潜变量生成严格遵循因果时序。在每一步 t，模型先基于历史 (z_{<t}, s_{<t}, a_{<t}) 预测当前动作 a_t，然后将 a_t 追加到因果上下文中，用于预测当前视觉潜变量 z_t。这精确匹配了真实机器人"先执行动作，后观测结果"的交互过程。

2. **Embodiment-Specific 接口**：不同机器人有不同的动作维度、状态维度、坐标系约定。Riemann-1.0 共享 Transformer 主干，但为每个具身类型（embodiment ID）使用独立的线性投影层和动作预测头。动作和状态向量被映射到具身特定的规范顺序，填充到固定维度，并通过有效性掩码（validity mask）处理变维动作——不强制异构具身共享同一物理动作空间。

3. **Flow Matching 统一优化**：视觉潜变量和动作都使用 Flow Matching 目标优化。两个预测头分别回归噪声潜变量和噪声动作的速度场，通过加权和联合训练。这种统一的优化框架避免了不同模态需要不同损失函数的适配问题。

⚡ **Eureka Moment**：把动作预测放在视觉潜变量生成之前——不是联合生成，不是视频优先——而是严格遵循"动作→观测"的因果顺序，让同一个模型天然同时成为可执行策略和世界模拟器。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
p(a_{1:T}, z_{1:T} | z_0, s_0, c) = ∏_{t=1}^{T} p(a_t | z_{<t}, s_{<t}, a_{<t}, c) · p(z_t | z_{<t}, s_{<t}, a_{≤t}, c)
```

**目标**：在给定任务条件 c、初始视觉潜变量 z_0 和初始状态 s_0 下，联合建模动作序列和视觉潜变量序列的因果演化过程。

**公式分解**：

```
L = (1 - λ) · L_z + λ · L_a

其中:
L_z = E[ ||v_θ^z(z_σ, σ, z_{<t}, s_{<t}, a_{≤t}, c) - (ε_z - z)||_2^2 ]
L_a = E[ ||v_θ^a(a_σ, σ, z_{<t}, s_{<t}, a_{<t}, c) - (ε_a - a)||_2^2 ]
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| z_t | t 时刻的视觉潜变量（Wan VAE 编码） |
| s_t | t 时刻的机器人状态（从环境观测，模型不生成） |
| a_t | t 时刻的动作 chunk |
| c | 任务条件（T5 编码的语言指令） |
| z_σ, a_σ | 插值样本 (1-σ)x + σ·ε |
| v_θ^z, v_θ^a | 视觉和动作的速度场预测头 |
| λ | 动作损失权重（三阶段训练中从 0.1 → 0.5 → 0.9） |
| ε | 高斯噪声 ~ N(0, I) |

**直觉**：动作预测只依赖历史信息（z_{<t}, s_{<t}, a_{<t}），而视觉潜变量预测额外依赖当前动作 a_t。这个微妙的不对称性是关键——它意味着动作既是策略输出，也是世界模拟的条件输入。动作 chunk 是连接策略和模拟的桥梁接口。

> 符号与本文保持一致：下标 <t 表示严格历史，≤t 表示包含当前时刻。Flow matching 框架下，模型预测的是从噪声到数据的速度场，而非直接预测数据本身。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2D 操作场景：

**设置**：
- 动作维度 d_a = 2（x-y 平面末端执行器位移）
- 状态维度 d_s = 2（当前末端位置）
- 视觉潜变量维度 d_z = 4（简化 VAE）
- 时间步 T = 3

**Step 0: 初始化**
```
z_0 = [0.1, -0.2, 0.3, 0.05]   (初始观测编码)
s_0 = [0.0, 0.0]               (末端在起点)
c = T5("pick up the red cube")
```

**Step 1: 预测动作 a_1**
```
a_1 的条件: z_{<1}=z_0, s_{<1}=s_0, a_{<1}=∅, c
→ 采样噪声 a_1_noise ~ N(0, I), σ=0.8
→ v_θ^a(a_σ, σ=0.8, z_0, s_0, ∅, c) = [-0.5, 0.3]  (速度场)
→ 去噪: a_1_clean = a_1_noise - 0.8 · [-0.5, 0.3] ≈ [0.4, -0.24]
→ 执行 a_1 共 apf=4 步低层控制
```

**Step 2: 预测视觉 z_1（条件为 a_1）**
```
z_1 的条件: z_{<1}=z_0, s_{<1}=s_0, a_{≤1}=a_1, c
→ 采样噪声 z_1_noise ~ N(0, I), σ=0.6
→ v_θ^z(z_σ, σ=0.6, z_0, s_0, a_1, c) = [0.2, -0.1, 0.15, -0.05]
→ 去噪: z_1_clean = z_1_noise - 0.6 · [0.2, -0.1, 0.15, -0.05]
→ 解码 z_1_clean → 模拟观测: 末端移动到了新位置
```

**训练损失计算**（假设一组假设值）：
```
L_z = ||[0.18, -0.08, 0.12, -0.04] - [0.2, -0.1, 0.15, -0.05]||^2 = 0.0008
L_a = ||[-0.48, 0.28] - [-0.5, 0.3]||^2 = 0.0008
L = (1-0.5)·0.0008 + 0.5·0.0008 = 0.0008  (Stage II, λ=0.5)
```

**关键观察**：a_1 在 L_z 的计算中作为条件出现（a_{≤t}），但在 L_a 的计算中不作为条件（a_{<t}）。这个因果顺序确保了训练时不会"偷看"未来动作信息。

## 4. 工程视角 (Engineering View)

| 工程维度 | 设计决策 | 含义 |
|----------|----------|------|
| 推理延迟 | Flow matching 多步去噪 | 每个动作 chunk 需要多步迭代去噪（典型 4-8 步），比确定性策略头（如 ACT 的 MSE head）更慢 |
| 控制频率 | apf (action per frame) | 每个视觉潜变量对应 apf 步低层控制。视觉更新频率 < 控制频率，动作流时间密度更高 |
| KV Cache 管理 | 固定窗口 + 重置机制 | 长程任务中 cache 满后重置，最近观测作为新 context。这引入了上下文截断误差 |
| 多具身共享 | 共享 Backbone + 独立投影头 | 参数量增加有限（仅投影头和预测头独立），但避免了强制统一动作空间的精度损失 |
| 训练稳定性 | Loss masking + 噪声注入一致性 | 填充通道在训练和推理时都保持零值，避免 train-test mismatch。这是多具身训练的关键细节 |
| 内存占用 | 多模态 token 序列化 | 序列结构: [context latent, clean latent, noisy latent, state, clean action, noisy action]。noisy tokens 仅在训练时需要 |
| 量化考虑 | Flow matching 对精度敏感 | 速度场回归是连续值优化，INT8 量化可能影响去噪质量。论文未讨论量化部署 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **LAM 伪动作质量足够**：Stage I 完全依赖 LAM 从视频对中提取的 32 维隐式动作表示。但 LAM 的隐式瓶颈是否真正编码了可迁移的"动作语义"，还是仅仅编码了视觉变化的统计关联？论文未提供 LAM 伪动作的可解释性分析或人类评估。

2. **具身 ID 足以区分控制语义**：通过 embodiment ID 选择独立投影头，假设同一 ID 下的所有数据共享相同的坐标系、单位、和动作约定。但实际机器人数据可能存在子变体（如同一型号的不同固件版本），论文未讨论这种细粒度差异。

3. **固定窗口 cache 重置不损害长程任务**：cache 满后重置，最近观测作为新 context。这在 RoboCasa-365（长程组合基准）上是否引入信息丢失？论文未报告 cache 窗口大小或重置频率。

4. **15 次演示足够微调**：真实世界每个任务仅 15 次遥操作演示（3 小时）。这个数据量在机器人学习领域属于极低数据设置。模型的高性能可能高度依赖预训练质量，而非微调策略本身。

  1. 做多模态具身 Agent 的研究者——因果 WAM 因子化是可直接复用的架构思想
  2. 要评估从人类视频到机器人策略知识迁移可行性的工程师——三阶段课程训练 + LAM 伪动作标注是完整方案
  3. 关注世界模型统一策略学习的研究者——Riemann-1.0 代表了 WAM 路线的最新收敛方向

- **建議章節路徑**：
  先读 §3.2（全因果因子化 + 公式 1-4）→ 再看 §4（三阶段课程训练，特别是 λ 调度策略）→ 可跳 §2（数据基础设施，除非你关心大规模数据工程细节）→ 最后看 §5.1.3（组合泛化和 OOD 结果，展示模型泛化能力）

- **不值得精讀的理由**：
  如果你不做机器人学习、已熟悉 WAM 路线（DreamZero/LingBot-VA/FastWAM），且不需要从人类视频迁移知识到机器人策略，读摘要和 §3.2 的因果因子化公式即可。
