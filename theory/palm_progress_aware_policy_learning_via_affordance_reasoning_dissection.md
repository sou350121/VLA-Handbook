💡 **X-Ray 开场**

这篇论文解决什么问题？现有 VLA 模型在长程多步任务（如"清理杂乱桌子"）中经常中途失败——重复动作、跳过步骤、提前终止。根本原因是缺乏内部表示来追踪"现在做到哪了"和"下一步该碰哪里"。

发现了什么？PALM 引入两个核心机制：(1) 预测 4 类结构化可供性作为中间推理层，(2) 联合预测动作和连续进度值 (0-1)。在 CALVIN ABCD 上平均完成长度从 3.98 提升到 4.48（+12.5%），LIBERO-LONG 成功率从 69% 提升到 91.8%。

对 VLA 研究者意味着什么？长程任务不需要复杂的分层规划器——端到端模型内部可以学习出有效的进度表示和交互线索，关键是设计合适的中间监督信号。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练/推理差异 |
|------|------|------|-----------|---------------|
| 多模态编码器 | 语言指令 l, 图像 o_t, 机器人状态 s_t | 文本/视觉/状态 tokens | 每步 t | 训练/推理相同 |
| 可供性查询集 | 融合后的多模态 tokens | 4 类可供性 latent F̂_{t+n} | 每步 t，预测未来 t+n | 推理时移除 4 个 heads，只保留 latent |
| 动作 - 进度查询集 | 上下文 tokens + F̂_{t+n} | 动作序列 â_{t:t+n-1} + 进度序列 p̂_{t:t+n-1} | 每步 t，预测 n 步轨迹 | 训练/推理相同 |
| 扩散 Transformer | 动作 - 进度 queries + 条件 | 去噪后的动作 - 进度序列 | 10 步采样 (Table 7) | 推理时迭代去噪 |

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **可供性作为中间表示**：直接映射观察→动作会混淆视觉上相似但任务阶段不同的状态。可供性提供任务相关的锚点，消歧义。

2. **4 类可供性互补**：
   - Global：哪个物体相关（物体级）
   - Local：接触几何在哪里（像素级）
   - Spatial：放置位置候选（空间级）
   - Dynamic：哪些像素会运动（时序级）

3. **进度信号作为时间正则化**：连续值 p_t ∈ [0,1] 编码子任务内完成度，解决"看起来一样但实际进度不同"的歧义。

⚡ **Eureka Moment**：长程任务失败的本质不是规划能力不足，而是缺乏**时间锚点**——PALM 用可供性锚定"下一步碰哪里"，用进度锚定"现在做到哪了"，两者形成闭环。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
PALM = 可供性预测 F̂_{t+n} = f_aff(l, o_t, s_t) + 进度感知策略 π(a_t, p_t | l, o_t, s_t, F̂_{t+n})
```

**目标函数分解**：

```
总损失 L = L_global + L_local + L_spatial + L_dynamic + L_DiT
```

**变量说明**：

| 符号 | 含义 | 维度/范围 |
|------|------|-----------|
| l | 语言指令 embedding | 512 (CLIP) |
| o_t | t 时刻视觉观察 | H×W×3 |
| s_t | t 时刻机器人状态 | 6-DoF + gripper |
| F̂_{t+n} | 预测的 t+n 时刻可供性 latent | 4 类 queries |
| a_t | t 时刻动作 | 7-DoF (6D pose + gripper) |
| p_t | t 时刻进度 | [0, 1] 标量 |
| n | 预测视野长度 | 3 (Table 7) |

**直觉**：可供性预测是"看下一步"，进度预测是"知道现在在哪"，两者结合才能稳定走完全程。

### 2.1 可供性损失细节

**Global (物体级)**：
```
L_global = L_Focal(M_{t+n}, M̂_{t+n}) + L_Dice(M_{t+n}, M̂_{t+n})
```
用 Grounding DINO + SAM 生成监督 mask。

**Local (接触级)**：
```
L_local = L_Focal(M_local, M̂_local) + L_KL(M̃_local, M̂̃_local)
```
接触点转为 Gaussian heatmap 监督 (参考 GLOVER++)。

**Spatial (放置位置)**：
```
L_spatial = (1/C) Σ_c min_m ||p̂^(m) - p^(c)||²
```
集合匹配损失，预测 M 个候选点对齐 C 个目标点。

**Dynamic (运动区域)**：
```
L_dynamic = E_z[-log P(x^M|z)] + β·KL(Q(z|x^M) || p(z))
```
VAE 式重构损失，用 CoTracker 追踪运动区域生成监督。

### 2.2 扩散损失

```
L_DiT = E_{t_d, ε} ||ε - ε_θ(ỹ_{t:t+n-1}, t_d | l, o_t, s_t, F̂_{t+n}, t_d)||²
```

其中 ỹ 是加噪的动作 - 进度序列，ε_θ 是噪声预测器。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设任务："把红色积木放到蓝色盒子里"（LIBERO-LONG 风格），n=3 步预测视野。

**t=0 时刻**：
- 输入：指令 l = "put red block in blue box"，观察 o_0（相机看到桌面），状态 s_0（机械臂在 home 位置）
- 可供性预测 F̂_3：
  - Global：红色积木 mask（置信度 0.92）
  - Local：积木顶部接触区域 heatmap（峰值在中心）
  - Spatial：蓝色盒子开口处 3 个候选放置点
  - Dynamic：机械臂 gripper + 红色积木的运动区域预测
- 动作 - 进度预测：
  - â_{0:2} = [接近积木，抓取，抬起]（3 步 7-DoF 轨迹）
  - p̂_{0:2} = [0.1, 0.3, 0.5]（"抓取子任务"完成度）

**t=1 时刻**（执行完第 1 步后）：
- 观察 o_1 更新（机械臂更接近积木）
- 重新预测 F̂_4（可供性更新，接触区域更精确）
- â_{1:3} = [抓取，抬起，移向盒子]
- p̂_{1:3} = [0.3, 0.6, 0.8]（进度单调递增）

**关键**：如果某步执行偏差（如抓取失败），进度 p_t 会停滞或回退，模型会重新规划而不是盲目继续。

**部署约束**：
- 推理时需要运行 4 个可供性 heads（训练时）或仅 latent 传递（推理时）——论文未明确推理延迟
- 扩散采样 10 步意味着每步动作需 10 次前向传播（可用蒸馏加速）
- 需要双相机配置（eye-on-base + eye-on-hand）——Table 6 提到双视角

**Trade-off**：
- 可供性 heads 增加训练复杂度，但推理时可移除（只传递 latent）
- 进度信号需要标注（论文用半自动方法：关键帧标注 + 线性插值）
- 3 步预测视野 vs 计算成本：n 越大规划越远，但扩散采样成本线性增长

### 6.3 隐含假设 (Hidden Assumptions)

1. **子任务边界清晰**：进度信号假设任务可分解为单调进展的子任务，但某些任务（如"清理桌子"）可能有循环/回溯。

2. **可供性可监督**：假设 Grounding DINO + SAM 能可靠生成全局 mask，CoTracker 能可靠追踪运动区域——这些工具本身有失败模式。

3. **视觉观测充分**：假设 RGB 相机（即使是双视角）足以捕捉所有相关状态——深度/触觉信息缺失可能限制接触推理精度。

4. **进度线性可插值**：关键帧之间线性插值假设任务进展均匀，但实际操作可能有加速/减速阶段。
