### 1.2 关键机制 (Key Mechanism)

GAE 的设计围绕三个核心洞察：

1. **接口极简主义**：动作专家不需要理解语义——它只需要知道"手要去哪里"。用稀疏 3D 位姿作为接口，输入和输出都在同一动作空间，专家的角色退化为"几何运动细化"。

2. **相机坐标系优先**：大多数 VLA 让 VLM 直接在机器人基座坐标系输出动作，这要求 VLM 隐式学习相机→基座的变换。GAE 让 VLM 在相机坐标系输出位姿，这与 VLM 的图像预训练天然对齐。

3. **APPF 两阶段训练**：动作专家的技能可分解为"轨迹跟随"和"点云感知细化"。先在大块纯轨迹数据上预训练（batch size 高达 31,824），再用点云数据微调——比联合训练收敛更快、数据利用率更高。

⚡ **Eureka Moment**：动作专家不需要理解"在做什么任务"——它只需要知道"手要去哪里"和"周围有什么"。把语义从接口中剔除，泛化性自然涌现。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
GAE:  a_t ~ π_θ(· | S_t, P_g, O_pcd)   where   P_g ~ Trajectory(VLM(I, cmd))
```

**目标**：训练一个条件扩散策略，将稀疏位姿引导 + 实时点云 + 本体状态映射为可执行动作。

**扩散去噪方程**：

```
训练：min_θ E[k, a_t⁰, ε] [ ||ε - ε_θ(a_t^k, k, f_t^A)||² ]

其中：
  a_t^k = √ᾱ_k · a_t⁰ + √(1-ᾱ_k) · ε    (加噪过程)
  f_t^A = concat(MLP(S_t), MLP(P_g), PointNet(O_pcd))
  ε ~ N(0, I)
```

**推理**：

```
a_t^K ~ N(0, I)
for k = K, K-1, ..., 1:
    a_t^{k-1} = denoise(a_t^k, k, f_t^A; θ)
→ a_t⁰ 即为生成的 8 步动作块
```

**变量说明**：

| 符号 | 含义 | 来源 |
|------|------|------|
| S_t | 机器人本体状态（关节位姿、夹爪状态） | 实时传感器 |
| P_g | 引导位姿，从 VLM 生成的连续轨迹 T(t) 中每 8 步采样 | VLM → B-spline |
| O_pcd | 裁剪的无色点云（局部环境几何） | 深度相机 → 预处理 |
| f_t^A | 条件特征向量 | 三编码器拼接 |
| ε_θ | 噪声预测网络（扩散策略核心） | 可学习参数 |
| a_t^k | 第 k 步的去噪动作 | 扩散过程变量 |
| K | 扩散步数 | 超参数 |

> 符号与论文原文保持一致。动作空间为末端执行器空间（end-effector space），动作块长度为 8。

**直觉**：扩散策略从纯噪声出发，在"本体状态+引导位姿+环境几何"的三重约束下，逐步"雕刻"出合理的动作。引导位姿提供"去哪里"的粗粒度方向，点云提供"怎么避开障碍"的细粒度信息。

**闭环轨迹更新方程**：

```
当 VLM 异步重规划时，合并新旧轨迹：

k* = argmin_i ||p_i' - T₀(t₂)||₂     (找最近新位姿)
γ = (p_k*' - T₀(t₂))ᵀ · v̂_path      (方向一致性检查)
要求 γ > 0（避免回溯）

→ 丢弃 k* 之前的所有位姿，用过渡 spline 连接
   (T₀(t₂), Ṫ₀(t₂)) 到剩余轨迹
```

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2D 抓取场景：

**场景设定**：
- 相机坐标系中，VLM 输出 3 个稀疏位姿：W₁=(0.1, 0.2), W₂=(0.3, 0.1), W₃=(0.5, 0.0)
- 夹爪最终目标：T_target = (0.6, 0.0)
- B-spline 插值后生成连续轨迹 T(t)

**GAE 推理过程**：

```
Step 0: 从轨迹 T(t) 采样 P_g₀ = (0.15, 0.18)
        传感器读取 S₀ = [关节角度: 1.2, 0.8, -0.3, ...; 夹爪: 开]
        点云 O_pcd₀ = 2048 个点（裁剪前景，无颜色）

Step 1: 编码 f₀^A = concat(MLP(S₀), MLP(P_g₀), PointNet(O_pcd₀))
        维度: [d_s] + [d_g] + [d_pcd] → [d_A]

Step 2: 扩散去噪
        a₀^K ~ N(0, I)  （K 步，假设 K=100）
        for k=100→1:
            a₀^{k-1} = ε_θ(a₀^k, k, f₀^A)
        → a₀⁰ = 8 步动作 [Δx₁, Δy₁, ..., Δx₈, Δy₈]

Step 3: 执行前 1-2 步动作，然后重复
```

**IK 对比**：如果直接用 IK 把 P_g 转成关节角：
- W₃=(0.5, 0.0) 附近的 IK 解可能因深度噪声产生 ±5mm 误差
- 在夹闭场景中，5mm 误差足以导致碰撞或抓取失败
- GAE 通过点云感知可以"看到"障碍物并微调轨迹

**数值假设**（基于论文趋势的合理估计）：
- IK 基线成功率（简单任务）：~60-70%
- GAE 成功率（同任务）：~85-95%
- 差距来源：点云引导的轨迹微调 + 对位姿噪声的鲁棒性

## 4. 工程视角 (Engineering View)

| 工程维度 | 分析 |
|----------|------|
| **推理延迟** | VLM 推理（稀疏位姿输出）是主要瓶颈；GAE 扩散策略每 8 步执行一次，K 步去噪可优化（论文未给出具体 ms 数） |
| **控制频率** | 每 8 步采样一个引导位姿——假设基础控制频率 30Hz，则引导频率 ~3.75Hz；VLM 异步推理进一步降低频率需求 |
| **内存占用** | GAE 冻结后不需梯度计算；PointNet 编码器 + 扩散噪声预测网络，估计 ~50-100M 参数（论文未明确给出） |
| **量化误差** | 深度估计噪声直接影响位姿精度；论文指出 IK 对位姿误差高度敏感，GAE 的点云细化部分缓解了此问题 |
| **部署约束** | 需要实时深度相机（RealSense D435）；点云预处理（裁剪+降采样）需要 CPU 计算 |
| **训练成本** | APPF 两阶段：Stage 1 纯轨迹预训练（batch 31,824，高效）；Stage 2 点云微调（较小 batch）。比联合训练显著节省 |
| **模块化优势** | GAE 冻结后跨任务复用——新增任务只需微调 VLM 输出稀疏位姿，避免重新训练整个动作策略 |

**工程含义**：GAE 的架构天然适合"云-边"部署——VLM 可在云端推理（低频、高算力），GAE 在边缘设备执行（高频、低算力）。接口（稀疏 3D 位姿）的数据量极小，网络延迟容忍度高。

### 不能做什么 / 失败模式

| 失败模式 | 原因 |
|----------|------|
| 高度依赖深度质量 | VLM 在相机系输出位姿，深度估计误差直接传递到动作空间 |
| 接触密集操作仍有限 | 点云无法捕捉触觉信息；精细触觉操作（如旋转螺丝）可能超出能力 |
| 极端视角泛化未验证 | 论文提到"跨相机视角"但未给出极端视角（如俯视 vs 侧视）的量化对比 |
| 动态环境适应有限 | 闭环重规划频率受 VLM 推理速度限制；快速移动物体可能超出响应能力 |
| 大尺度移动操作 | 实验集中在桌面操作；未涉及移动基座或人形全臂操作 |

### 6.1 隐含假设 (Hidden Assumptions)

| 假设 | 验证状态 | 风险 |
|------|----------|------|
| 深度估计足够准确 | 部分验证（IK 对比实验显示 GAE 能补偿噪声） | 若深度传感器质量下降（如室外光照），系统性能可能显著恶化 |
| 稀疏位姿足以描述任务 | 实验验证（IK vs GAE 对比） | 对于需要连续触觉反馈的任务（如装配、打磨），稀疏位姿可能不够 |
| 点云足以表征环境几何 | 实验验证 | 透明/反光物体在点云中可能缺失或畸变 |
| VLM 轻量微调不遗忘 | Table 5 显示语言理解保持 | 但空间推理能力的保持程度未充分量化 |
| 150k 轨迹足够泛化 | 实验显示跨任务有效 | 但"足够"的定义模糊——覆盖多少机器人平台/任务域才算充分？ |
