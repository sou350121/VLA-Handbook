### 1.2 关键机制 (Key Mechanism)

论文通过四个维度的机制分析解释了多视角为什么有效：

- **空间注意力偏移**：Grad-CAM 和输入梯度分析显示，多视角策略将注意力更多集中在末端执行器和被操作物体上，而单视角策略对背景区域更敏感（容易学到虚假相关）
- **非线性状态编码增强**：线性探测中多视角特征的 R² 更低（说明减少了脆弱的线性姿态捷径），但非线性探测中 R² 更高（说明保留了更丰富的非线性结构）
- **策略头鲁棒性提升**：固定 DINOv2 编码器后，多视角训练的策略头 MSE 损失更低，视觉→动作映射更可靠
- **优化动力学更稳定**：单视角训练在中间检查点出现不稳定峰值，多视角训练产生更平滑的改进曲线

⚡ **Eureka Moment**：多视角数据的价值不是"让策略学会视角不变性"，而是通过多视角监督迫使策略学到更丰富的非线性状态表征——这些表征在单视角推理时依然带来性能提升。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L_total = L_IL(0°) + L_IL(-k°) + L_IL(+k°)
        → 多视角联合优化 → 更丰富的非线性表征 → 单视角推理性能↑
```

### 2.1 深度对齐目标函数

RoboNVS 将 DepthCrafter 的相对深度对齐到 DA3 的度量深度，在逆深度空间做全局尺度-偏移变换：

```
α*, β* = argmin_{α,β} Σ_t ‖d_t^{-1} - (α·d̃_t^{-1} + β)‖²₂
```

其中：
- `d̃_t`：DepthCrafter 输出的相对深度（时间一致但无度量尺度）
- `d_t`：DA3 输出的度量深度（有尺度但可能时间不一致）
- 对齐后保留两者的优点：时间平滑 + 度量几何

### 2.2 掩码引导的视频补全

渲染 DW-Mesh 得到部分观察后，用掩码构造被遮挡帧：

```
Ĩ_t = I_t ⊙ (1 - M_t)
```

其中 `⊙` 是逐元素乘法，`M_t` 是渲染的遮挡掩码。

### 2.3 流匹配目标

条件于 `c = {I₁, Ṽ, M, p}`（参考帧、掩码视频、掩码序列、文本 prompt），扩散变换器预测速度场：

```
L = E_{τ,z_τ} [‖v_θ(z_τ, c, τ) - v*(z_τ, τ)‖²₂]
```

### 2.4 双向掩码训练

为缩小掩码分布差距，同时使用原始掩码和互补掩码：

```
M̄_t = 1 - M_t    （互补掩码，强制补全周围背景区域）
```

> 符号与本文保持一致：d = 深度, I = 图像帧, M = 掩码, v = 速度场, τ = 扩散时间步

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 Pick-and-Place 任务，单视角基线成功率为 40%。

**步骤 1：视角偏移实验**
- 添加 ±10° 视角 → 成功率 48%（+8）
- 添加 ±20° 视角 → 成功率 54%（+14，最佳）
- 添加 ±40° 视角 → 成功率 47%（+7，下降）
- 添加 ±60° 视角 → 成功率 42%（+2，几乎无增益）

直觉：±20° 提供了互补的几何信息（能看到机械臂侧面和物体的相对位置），但 ±60° 的视角变化太大，引入了与 canonical 视图不兼容的视觉变化（如机械臂完全被物体遮挡），策略难以 reconcile。

**步骤 2：缩放行为**
- 单视角 10 条 → 30%；50 条 → 45%；200 条 → 52%；640 条 → 54%（饱和）
- 多视角 (0°+±20°) 10 条/视角 → 38%；50 条/视角 → 58%；200 条/视角 → 68%（未饱和）

关键发现：单视角在 200 条后几乎不增长（+2%），而多视角在同样数据量下还有 10% 的增长空间。这意味着多视角数据的"有效信息密度"更高——同一轨迹从不同角度观察，提供了额外的几何约束。

**步骤 3：RoboNVS 合成效果**
- 单目 30 条真实演示 → Diffusion Policy 成功率 5%（Lego Pick-and-Place 真实环境）
- + EX-4D 合成 2 视角 → 15%
- + RoboNVS 合成 2 视角 → 55%

合成数据的质量差距直接反映在下游策略性能上。RoboNVS 的几何先验设计（而非端到端生成）是关键。

## 4. 工程视角 (Engineering View)

| 指标 | 数值 | 工程含义 |
|------|------|---------|
| RoboNVS 训练 | 8×H200, 1 周, batch=8 | 高门槛；需提前规划算力预算 |
| RoboNVS 推理 | 1×RTX 4090, ~50 秒/49帧 (320×192) | 单视频合成可行，批量合成需排队 |
| 视角偏移最佳 | ±20° | 多相机部署的实用指南：不需要广覆盖，适度偏移即可 |
| 每视角演示数 | 10→50 持续增益 | 增加每视角演示数比增加视角数性价比更高 |
| Diffusion Policy | ResNet-18, 3帧窗口 | 轻量视觉后端，适合实时部署 |
| VLA (π0+LoRA) | 5000 steps 微调 | 多任务预训练后可快速适配新视角数据 |

**部署约束**：
- 真实环境中，RoboNVS 推理 50 秒/视频意味着 30 条演示 × 2 视角 = 1000 秒 ≈ 17 分钟的数据合成时间
- 320×192 的低分辨率可能丢失精细操作细节（如小物体抓取），需注意与策略训练分辨率的匹配
- 多相机同步硬件成本：N 个相机 + 时间同步模块，但一旦部署完成，数据收集的边际成本极低

### 6.1 隐含假设 (Hidden Assumptions)

1. **相机布局可复用**：假设训练时的多相机布局在推理时至少保留一个 canonical 相机。如果部署环境相机完全不同，优势可能消失。
2. **视角偏移对称性**：实验使用对称的 ±k° 偏移，但未验证非对称布局（如只有 +20° 没有 -20°）的效果。
3. **合成数据的分布匹配**：假设 RoboNVS 合成的视角分布与真实多视角数据分布足够接近，使策略无法区分。但合成数据可能在某些边缘情况下（如快速运动模糊）与真实数据有 gap。
4. **DepthCrafter + DA3 的深度对齐适用于所有场景**：深度对齐假设两个深度模型在目标场景中都可靠。在反光表面、透明物体、或无纹理区域，深度估计可能同时失败。

**核心差异**：VISTA 关注 test-time 的跨视角泛化（推理时给多视角），本文关注 train-time 的多视角监督（推理时只给单视角）。RoboNVS 与 ReCamMaster/EX-4D 的区别在于"几何优先"设计——先渲染几何先验再补全缺失区域，而非端到端生成，这大幅减少了机器人结构畸变。
