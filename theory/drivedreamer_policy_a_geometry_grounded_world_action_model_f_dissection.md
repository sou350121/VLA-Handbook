### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **固定大小查询瓶颈**：LLM 输出固定数量的查询嵌入（64 深度 +64 视频 +8 动作），让下游生成器有稳定接口，便于模块化部署和计算控制
2. **因果条件化掩码**：深度查询→视频查询→动作查询的单向注意力，确保信息流是 3D 几何先于 2D 外观先于 1D 动作，符合物理世界的依赖关系
3. **像素空间深度 + 潜空间视频**：维度权衡——深度图边界保真度高且维度低，适合像素空间；视频时序信息丰富，潜空间更高效

⚡ **Eureka Moment**：世界 - 动作模型不应该只生成"看起来合理"的未来视频——显式生成深度作为 3D scaffold，让规划能直接访问几何信息（遮挡推理、距离估计、自由空间约束），这才是物理具身系统需要的。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L = λ_d·L_depth + λ_v·L_video + λ_a·L_action  (联合多任务流匹配损失)
```

**目标**：用一个统一的 LLM 主干产生几何感知（深度）+ 外观感知（视频）+ 控制（动作）的紧凑表征，通过因果条件化让下游任务按 3D→2D→1D 的顺序利用上游信息。

**公式细节**（流匹配训练）：

```
x_t = (1-t)·x_0 + t·x_1,  t ~ U(0,1)  (线性插值路径)
v_θ(x_t, t|c) → 预测速度场
L_FM = E[||v_θ(x_t, t|c) - (x_1 - x_0)||²]  (速度回归损失)
```

**变量说明**：

| 符号 | 含义 | 本文用法 |
|------|------|----------|
| x_0 | 数据样本（真实深度/视频/轨迹） | 训练时的目标 |
| x_1 | 噪声样本 | 训练时随机采样 |
| x_t | t 时刻的插值样本 | 扩散过程的中间状态 |
| c | 条件信息（LLM 嵌入 + 当前帧等） | 控制生成内容 |
| λ_d, λ_v, λ_a | 任务权重 | 默认 λ_d=0.1, 其余=1.0 |

> 符号与本文/相关文档保持一致：深度/视频/动作的流匹配公式形式相同，只是目标维度不同（深度=单通道图像，视频=多帧潜变量，动作=轨迹序列）

**直觉**：流匹配比传统扩散更稳定——它直接学习从噪声到数据的"速度场"，而不是逐步去噪。这对多任务联合训练很重要，因为三个生成器的收敛速度可以解耦。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个决策步的推理过程：

**输入**：
- 语言指令："在下一个路口左转"
- 3 个前视摄像头 RGB 图像（每图 256×144）
- 当前动作：直行，速度 10m/s

**Step 1: LLM 编码**
```
输入 token 总数 ≈ 512 (文本) + 768 (3×256 patch) + 32 (动作) + 136 (查询) = 1448
LLM 输出 → 64 个深度嵌入 (dim=768) + 64 个视频嵌入 + 8 个动作嵌入
```

**Step 2: 深度生成（可选）**
```
输入：噪声深度图 (144×256) + RGB + 64 个深度嵌入
流匹配 ODE 积分：20 步 → 输出深度图
深度范围归一化：[-0.5, 0.5] → 反 log 变换 → 相对深度
```

**Step 3: 视频生成（可选）**
```
输入：噪声视频潜变量 (9 帧) + 当前帧 CLIP 特征 + 64 个视频嵌入（已 attend 深度）
流匹配 ODE 积分：20 步 → 输出 9 帧未来视频潜变量 → VAE 解码 → RGB 视频
```

**Step 4: 动作生成（必须）**
```
输入：噪声轨迹 (8 步×4 维) + 8 个动作嵌入（已 attend 深度 + 视频）
流匹配 ODE 积分：10 步 → 输出轨迹序列
轨迹参数化：(x, y, cosθ, sinθ) 避免角度 wrap-around
```

**输出**：
- 深度图：144×256 单通道，AbsRel=8.1（相比 DA3 伪真值）
- 视频：9 帧 256×144 RGB，FVD=53.59
- 轨迹：8 步未来位置 + 朝向，PDMS 贡献≈89.2

## 4. 工程视角 (Engineering View)

**吞吐/延迟**：
- LLM 主干：Qwen3-VL-2B，单次前向≈50-100ms（取决于硬件）
- 深度生成：20 步 ODE，≈100-200ms（像素空间，分辨率低）
- 视频生成：20 步 ODE，≈300-500ms（潜空间，但 9 帧时序）
- 动作生成：10 步 ODE，≈50-100ms（维度最低）
- **规划-only 模式**：跳过深度 + 视频，总延迟≈150-250ms（可接受）

**内存**：
- 联合训练：8×H20 GPU，batch=32，100k steps
- 推理：2B LLM + 3 个 DiT，峰值显存≈8-12GB（取决于是否并行运行三个生成器）

**量化误差**：
- 深度归一化：log 变换 + 百分位归一化到 [-0.5, 0.5]，避免极端值
- 轨迹参数化：(x, y, cosθ, sinθ) 而非 (x, y, θ)，避免 θ 在±π 跳变

**部署约束**：
- 模块化设计允许"规划-only"部署（只跑 LLM+ 动作生成器）
- 深度/视频生成可按需激活（如需要可解释性或仿真数据合成）
- 视频分辨率固定 144×256（降低计算成本，但可能限制细节）

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- 在 Navsim 场景（城市道路、多车交互、交通灯）中生成合理的未来视频和轨迹
- 规划-only 模式下达到接近联合训练的性 能（PDMS 88.0 vs 89.2）
- 深度生成帮助视频生成更几何一致（FVD 从 65.82 降到 53.59）

**不能做什么**：
- 非驾驶场景（机器人操作、室内导航等）——传感器配置和任务域完全不同
- 长时序预测（只生成 9 帧视频，约 4.5 秒@2Hz）
- 无监督深度（依赖 DA3 伪真值，真实深度标注缺失）

### 6.1 隐含假设 (Hidden Assumptions)

1. **深度伪真值足够好**：假设 DA3 输出的深度可以作为训练标签——但 DA3 本身有误差，可能限制上限
2. **3D→2D→1D 因果流总是最优**：假设几何信息总是先于外观信息——但在某些任务中（如纹理依赖的抓取），外观可能更重要
3. **固定查询数量足够**：64+64+8 查询是经验选择，没有理论保证这是最优容量
4. **驾驶场景的几何主要是深度**：假设单目深度足够表征 3D 结构——但对于遮挡推理，可能需要更完整的 3D 表征（如 occupancy）
