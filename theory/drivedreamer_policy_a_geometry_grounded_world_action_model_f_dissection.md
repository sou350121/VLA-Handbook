### 1.2 关键机制 (Key Mechanism)

**因果查询排序 (Causal Query Ordering)**：
- 深度查询最先 → 视频查询可关注深度上下文 → 动作查询可关注深度 + 视频上下文
- 在同一个时间步内，注意力模式满足：`深度查询 → 视频查询 → 动作查询`
- 无需额外同步或迭代细化，单次前向传递完成信息流

**固定大小查询瓶颈 (Fixed-Size Query Bottleneck)**：
- 64 深度查询 + 64 视频查询 + 8 动作查询
- LLM 始终消费相同查询槽位，下游头读取对应嵌入生成输出
- 支持灵活操作模式：仅规划、想象增强规划、完整生成（离线仿真）

⚡ **Eureka Moment**：自动驾驶本质上是 4D 物理过程（3D 几何随时间演化）——世界模型不应只合成外观，而应保留对遮挡推理、距离估计、物理一致运动至关重要的几何结构。深度是紧凑的、直接与几何绑定的、可作为显式支架约束未来视频生成和规划决策。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L = λ_d·L_d + λ_v·L_v + λ_a·L_a   (联合多任务损失，λ_d=0.1, 其余=1.0)
```

**目标**：联合优化深度生成、视频生成、动作规划三个任务，通过共享 LLM 表征和因果查询排序实现几何感知的世界 - 动作建模。

**Flow Matching 基础**（用于深度和动作生成器）：

```
x_t = (1-t)·x_0 + t·x_1,  t ~ U(0,1)
L_FM = E_{x0,x1,t}[ ||v_θ(x_t, t|c) - (x_1 - x_0)||² ]
```

变量说明：
- `x_0`: 真实数据样本（深度图/轨迹）
- `x_1`: 噪声样本
- `x_t`: t 时刻的插值状态
- `v_θ`: 学习的时间依赖速度场
- `c`: 条件信息（LLM 世界嵌入）

直觉：flow matching 学习一个速度场，将简单分布（噪声）沿预定义路径输运到数据分布。推理时从噪声积分 ODE 回溯到 t=0 得到生成样本。

**深度归一化**（训练前处理）：

```
depth_normalized = log(depth) → 按分位数归一化到 [-0.5, 0.5]
```

> 符号与本文/相关文档保持一致：深度用 `d` 或 `D`，视频 latent 用 `z_v`，动作用 `a` 或轨迹 `(x, y, cosθ, sinθ)`

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2D 驾驶场景：

**输入**：
- 语言指令："在前方路口左转"
- 单视角 RGB（简化）：前方 50m 有路口，左侧有可行驶区域
- 当前动作：直行，速度 10m/s

**前向传递**：

1. **LLM 编码**：
   - 输入 token 总数 ≈ 512 (图像 patch) + 32 (指令) + 8 (动作) + 136 (查询) = 688
   - 输出：64 个深度嵌入 (每嵌入 512 维) + 64 个视频嵌入 + 8 个动作嵌入

2. **深度生成**（推理时 10 步 flow matching）：
   - 输入：噪声深度图 (144×256) + 当前 RGB + 64 个深度嵌入
   - 输出：归一化深度图，反变换后得到相对深度
   - 关键区域：路口边界深度跳变 ≈ 0.3（归一化后），对应实际深度差约 15m

3. **视频生成**（条件于深度嵌入）：
   - 输入：噪声视频 latent (9 帧×144×256×4) + 64 个视频嵌入（已关注深度）+ CLIP 视觉条件
   - 输出：9 帧未来视频，显示车辆逐渐接近路口、左侧道路逐渐清晰
   - FVD 贡献：深度条件使视频在路口几何结构上更一致（FVD 从 85.95 降至 53.59）

4. **动作生成**（条件于深度 + 视频嵌入）：
   - 输入：噪声轨迹 (8 步×4 维) + 8 个动作嵌入（已关注深度 + 视频）
   - 输出：轨迹序列，例如：
     ```
     步 0: (0, 0, 1.0, 0.0)      # 当前位置，朝北
     步 1: (0, 10, 1.0, 0.0)     # 直行 10m
     步 2: (0, 20, 0.97, 0.24)   # 开始左转 (θ≈14°)
     步 3: (-3, 28, 0.87, 0.50)  # 继续左转 (θ≈30°)
     ...
     步 8: (-15, 35, 0.50, 0.87) # 完成左转 (θ≈60°)
     ```
   - PDMS 贡献：深度信息帮助识别可行驶区域边界，视频信息预测其他车辆运动 → 轨迹更安全 (PDMS 从 88.0 提升至 89.2)

**可计算闭环**：深度误差 (AbsRel 8.1) → 视频质量 (FVD 53.59) → 规划安全 (DAC 97.1%) → 整体分数 (PDMS 89.2)

## 4. 工程视角 (Engineering View)

| 指标 | 数值/范围 | 含义 |
|------|-----------|------|
| 模型规模 | LLM 2B + 3 个生成器 (深度/视频/动作) | 可部署在 8×H20 训练，推理需优化 |
| 训练步数 | 100k steps, batch 32 | 约 3-5 天 (取决于 GPU 配置) |
| 空间分辨率 | 144×256 (深度/视频) | 降低计算成本，但细节有限 |
| 视频 horizon | 9 帧 @ 2Hz = 4.5 秒 | 适合短期规划，长期需滚动预测 |
| 查询 token 数 | 64+64+8 = 136 | 增加容量提升性能 (表 6)，但增加计算 |
| 推理延迟 | 模块化设计：可仅激活动作生成器 | 规划-only 模式延迟最低，完整生成延迟较高 |
| 量化误差 | 深度归一化到 [-0.5, 0.5] | 避免数值不稳定，反变换恢复度量/相对深度 |

**部署约束**：
- 训练需 8×H20 GPU，推理可降级到单卡（但延迟增加）
- 视频生成器从 Wan-2.1 初始化，需处理 license 合规
- 深度标签依赖 DA3 伪真值——实际部署需考虑域偏移

**吞吐/延迟 trade-off**：
- 规划-only 模式：仅激活动作生成器 → 延迟最低（适合实时控制）
- 想象增强规划：激活深度 + 动作 → 中等延迟，更好安全性
- 完整生成：全部激活 → 最高延迟，适合离线仿真/数据合成

## 5. 数据与评测 (Data & Eval)

**数据集**：
- Navsim v1/v2：源自真实驾驶日志，提供同步环绕视角传感器输入
- 训练集 (navtrain)：100k 样本 @ 2Hz
- 测试集 (navtest)：12k 样本 @ 2Hz
- 无额外数据集或预训练（除初始化骨干外）

**规划指标**：
- Navsim v1: PDMS (Predictive Driver Model Score)
  - 聚合：无责碰撞 (NC)、可行驶区域合规 (DAC)、碰撞时间 (TTC)、舒适 (C)、进展 (EP)
- Navsim v2: EPDMS (Extended PDMS)
  - 额外：方向合规 (DDC)、交通灯合规 (TLC)、车道保持 (LK)、头部舒适 (HC)、舒适 (EC)

**世界生成指标**：
- 视频：LPIPS (感知相似性)、PSNR (峰值信噪比)、FVD (Fréchet Video Distance)
- 深度：AbsRel (绝对相对误差)、δ1/δ2/δ3 (阈值准确率)

**基线对比**（论文 Table 1-3）：
- 视觉端到端：TransFuser, UniAD, DiffusionDrive
- VLA 方法：AutoVLA, RecogDrive, DriveVLA-W0
- 世界模型：LAW, DrivingGPT, WoTE, Epona, FSDrive, PWM

**关键结果**：
- PDMS (Navsim v1): 89.2 (SOTA，比 DriveVLA-W0 的 88.4 高 0.8)
- EPDMS (Navsim v2): 88.7 (SOTA，比 PWM 的 88.1 高 0.6)
- FVD: 53.59 (比 PWM 的 85.95 降低 38%)
- AbsRel: 8.1 (比 fine-tuned PPD 的 9.3 低 13%)

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- 联合生成深度、未来视频、动作轨迹（单次前向传递）
- 灵活操作模式：规划-only、想象增强规划、完整生成
- 在 Navsim 封闭环规划中达到 SOTA
- 生成几何一致的未来视频（深度条件减少遮挡错误）

**不能做什么**：
- 长期预测（仅 9 帧/4.5 秒）——需滚动预测或外部规划器
- 多智能体交互建模（隐式通过视频学习，但无显式 agent 表示）
- 域外泛化（仅在 Navsim 训练，未测试新城市/新传感器配置）
- 非驾驶场景（架构可迁移，但需重新训练）

### 6.1 隐含假设 (Hidden Assumptions)

1. **深度伪真值足够好**：训练使用 DA3 生成的深度作为标签——假设 DA3 在驾驶场景的误差不会影响下游任务。但 DA3 本身有域偏差，可能传播到规划器。

2. **因果信息流单向足够**：假设深度→视频→动作的单向条件足够——但某些场景可能需要动作反馈到视频（如"如果我急刹车，未来视频会怎样"）。

3. **固定查询容量足够**：136 个查询 token 对驾驶场景足够，但对更复杂场景（多智能体、长 horizon）可能不足。

4. **驾驶场景几何简单**：假设单目深度足以捕捉场景几何——但在低纹理、反光、透明物体场景可能失效。
