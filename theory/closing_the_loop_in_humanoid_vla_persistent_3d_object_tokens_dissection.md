### 1.2 关键机制 (Key Mechanism)

POT-VLA 的核心是一个"维持–动作–观察–验证–恢复"的闭环：

1. **角色绑定**：VLM 规划器或人工任务文件为每个子任务定义角色集（TARGET、DESTINATION、SUPPORT、HANDOVER_PARTNER），每个角色绑定一个持久槽位
2. **RGB-D 提升**：SAM3 分割掩码 + 深度反投影 → 机器人基座标系下的 3D 对象记录（质心、范围、置信度、可见性、关系特征）
3. **令牌序列化**：将对象记录编码为固定槽位张量 `x_t^obj ∈ R^{K×F}`（K=8, F=33），经 LayerNorm → Linear → GELU → Dropout → Linear 投影到 DiT 隐藏维度
4. **动作头注入**：对象令牌插入 DiT action-head 的自注意力序列（而非视觉-语言骨干），序列布局 `[Z_state, Z_obj, Z_action]`
5. **执行后刷新**：动作分块执行后，同一套对象记录用新 RGB-D 观测刷新
6. **谓词验证**：几何谓词（包含、支撑、接近度、位移等）检查刷新后的对象状态是否满足子任务完成条件

⚡ **Eureka Moment**：动作生成和结果验证不应该用两份不同的状态表示——让 VLA 的动作专家和谓词验证器共享同一份刷新的对象记忆，是解决"物体状态漂移"最简洁的方案。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
M_t^{τ_i} ──T()──► x_t^obj ──f_θ^obj()──► Z_t^obj ──π_θ()──► â_{t:t+H}
                                                              │
                                       刷新 M_{t+H}^{τ_i} ◄──┘ (执行后)
                                                              │
                                       Ψ_i(M_{t+H}^{τ_i}) ──► {done, in_progress, ...}
```

**目标**：让同一个对象记忆 M 同时驱动动作生成和结果验证，消除"用于动作的对象状态"和"用于验证的对象状态"之间的分歧。

**公式分解**：

1. **对象记录构建**：
```
M_t^{τ_i} = { m_t^e | e ∈ E_i }
```
其中 E_i 是子任务 τ_i 的相关实体集，每个记录 m_t^e 包含角色、短语、图像框、3D 质心、3D 范围、置信度、可见性、关系特征。

2. **令牌序列化**：
```
x_t^obj = T(M_t^{τ_i})  ∈ R^{K×F}
```
K=8 槽位，F=33 特征/槽位。槽位 k 包含：
```
[v_k, q_k, b_k, c_k, s_k, o_k, ρ_k]
 可见性  置信度  2D框   3D质心  3D范围  方向   关系特征
```

3. **对象令牌投影**：
```
Z_t^obj = f_θ^obj(x_t^obj) ∈ R^{K×d}
```
f_θ^obj = LayerNorm → Linear → GELU → Dropout → Linear

4. **动作序列组装**：
```
S_t = [Z_t^state, Z_t^obj, Z_t^action]
â_{t:t+H} = π_θ(S_t, Z_t^{vl})
```

5. **谓词验证**：
```
p = ⟨κ, α, op, ν, n⟩
φ(κ, α, M_ξ^{τ_i}) → {satisfied, unsatisfied, uncertain}
```
κ=谓词类型, α=对象记录参数, op=比较算子, ν=阈值, n=稳定性窗口。

> 符号与本文保持一致。所有 3D 坐标在机器人基座标系下表示，归一化后进入令牌。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设子任务"将球放入篮子"，角色集 E = {TARGET=球, DESTINATION=篮子}。

**步骤 1：初始对象记录（t=0）**

| 槽位 | 角色 | 可见性 v | 置信度 q | 3D 质心 c (m) | 3D 范围 s (m) | 关系 ρ |
|------|------|----------|----------|---------------|---------------|--------|
| 0 | TARGET | 1.0 | 0.95 | [0.5, 0.0, 0.3] | [0.05, 0.05, 0.05] | — |
| 1 | DEST | 1.0 | 0.92 | [0.8, 0.2, 0.0] | [0.15, 0.15, 0.10] | dist=0.32 |
| 2-7 | PADDING | 0 | 0 | [0,0,0] | [0,0,0] | — |

**步骤 2：动作生成**

对象令牌 x_0^obj 经投影后与状态 token、动作 token 拼接，DiT 动作头输出 10 步动作分块：
```
â_{0:10} = [reach_to(ball), grasp(ball), lift, navigate_to(basket), ...]
```

**步骤 3：执行 + 刷新（t=10）**

执行后新的 RGB-D 观测刷新对象记录：

| 槽位 | 角色 | 可见性 v | 置信度 q | 3D 质心 c (m) | 关系 ρ |
|------|------|----------|----------|---------------|--------|
| 0 | TARGET | 0.3 | 0.40 | [0.82, 0.18, 0.05] | dist_to_dest=0.03 |
| 1 | DEST | 1.0 | 0.90 | [0.8, 0.2, 0.0] | — |

球被抓取后部分遮挡（v=0.3, q=0.4），但质心已接近篮子。

**步骤 4：谓词验证**

```
p_containment = ⟨containment, α={TARGET, DESTINATION}, ≤, ν=0.05m, n=3⟩
φ(p_containment, M_{10}) = satisfied (dist=0.03m < 0.05m, 连续3帧稳定)
→ 子任务完成 ✓
```

**对比 Direct Baseline 的失败场景**：

Direct Baseline 没有持久对象记录。执行抓取后，VLA 模型从视觉特征中重新推断球的位置——但由于遮挡和视角变化，模型可能"忘记"了球已经被抓起，或者将另一个球误认为目标。结果：动作分块发出后直接推进到下一个子任务，即使球根本没被抓到。

## 4. 工程视角 (Engineering View)

| 维度 | Direct Baseline | POT-VLA | 工程含义 |
|------|----------------|---------|----------|
| 每步计算开销 | 仅 DiT forward | DiT + SAM3 分割 + 深度反投影 + 令牌投影 | 增加 ~100-200ms/步（取决于 SAM3 速度） |
| 内存占用 | VLA 特征缓存 | + K×F=264 维对象记录 × N 子任务 | 可忽略（<1KB） |
| 控制频率 | 取决于 DiT 推理速度 | 受限于感知刷新周期（RGB-D 帧率） | 实际瓶颈在感知，不在推理 |
| 模块边界 | 端到端黑盒 | 感知→令牌→动作→验证，清晰分层 | 每层可独立调试和替换 |
| 部署约束 | 需桌面 GPU 跑 DiT | 同 + 需 RGB-D 相机 + SAM3 推理 | SAM3 可缓存，实际增量低 |
| 容错能力 | 失败后需高层重规划 | 局部恢复（reobserve/reground/retry） | 大幅减少昂贵的 VLM 重规划调用 |
| 泛化代价 | 依赖模型隐式泛化 | 需为新角色定义谓词模板 | 谓词设计是手工活，但一次定义多次复用 |

**关键 trade-off**：POT 引入了显式的对象状态管理开销，但换来的是可验证性和可恢复性。在长程任务中，一次失败后的重规划成本远高于每步的感知刷新成本——POT 的 ROI 随任务长度递增。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **长程多步任务**：叠杯子、双球放置等需要维持多步 3D 关系的任务增益最大
- **遮挡恢复**：对象被遮挡时显式标记 uncertainty，触发重新观测而非盲目推进
- **结构化恢复**：失败时有 reobserve / reground / retry / replan 四级恢复策略
- **新物体泛化**：替换为未见物品时仍保持较高成功率（依赖 SAM3 的零样本分割能力）

### 不能做什么
- **无 RGB-D 场景**：完全依赖深度反投影，无深度则无法构建 3D 对象记录
- **SAM3 失效场景**：透明物体、极端反光、超出 SAM3 训练分布的物体类别
- **双臂精细协作**：Dex3-1 灵巧手的精细操作能力本身有限
- **动态环境**：实验中背景运动是"保留"而非主动处理，快速移动物体可能超出刷新频率

### 6.1 隐含假设 (Hidden Assumptions)

1. **SAM3 零样本分割足够可靠**：论文假设 SAM3 能可靠分割任意任务相关物体，但透明/反光/非常规物体可能失败
2. **相机标定稳定**：3D 对象记录依赖精确的相机内参和相机到基座的变换，标定漂移会直接污染对象位置
3. **子任务角色可预先定义**：POT 依赖 VLM 规划器或人工任务文件提供角色定义——如果规划器给错了角色，POT 会忠实地跟踪错误的对象
4. **几何谓词覆盖足够**：论文承认对于"物体类别歧义"或"递送接受"等语义条件，几何谓词不够用，需要可选的 VLM 验证器——但这部分在实验中未充分使用
5. **刷新频率足够**：假设 RGB-D 帧率和动作分块长度 H 的组合能捕获所有关键状态变化，但快速运动可能超出感知刷新能力

  1. 做人形机器人整机控制的研究者——POT 的对象令牌 schema 可直接集成到现有 VLA 管线
  2. 评估 VLA 执行验证可行性的工程师——谓词验证器的设计模式和恢复策略有直接参考价值
  3. 研究对象中心化表示的学者——POT 提供了一个"显式对象记忆 vs 隐式特征编码"的干净对比实验

- **建議章節路徑**：
  先读 §3.1（POT 方法核心：对象记录 + 令牌 schema）→ 再看 §3.3（谓词验证与恢复）→ 然后 §4.3（消融实验，量化各组件贡献）→ 可跳过 §2（相关工作）和 Appendix（实现细节）

- **不值得精讀的理由**：
  如果不做人形机器人或长程移动操作（例如只关心单臂桌面抓取），本文的全身控制框架和谓词验证体系与你的场景距离较远——读摘要和 Table 1 的结果即可。
