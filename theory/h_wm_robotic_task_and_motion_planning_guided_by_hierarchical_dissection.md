## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率 | 训练/推理 |
|------|------|------|------|-----------|
| 逻辑世界模型 (M_L) | 当前逻辑状态 X_m, 观测 obs_m | 候选动作 a_{m+1}, 预测逻辑状态 X_{m+1} | 每子任务 1 次 (低频) | Qwen3-4B-Instruct + LoRA, 10k steps |
| 视觉世界模型 | obs_m, a_{m+1}, X_{m+1}, 关节 q_m | 潜变量视觉子目标 f_pred^{m+1} ∈ R^2048 | 每子任务 1 次 (低频) | PaliGemma + 2 层 FC, 100k steps |
| 子任务完成预测器 | obs_t, a_{m+1} | 完成信号 (binary) | 每控制步 1 次 (高频) | 基于 understanding expert + CLS head |
| Guided VLA (π0.5) | obs_t, q_t, a_{m+1}, f_pred^{m+1} | 动作块 α^{t:t+k} | 每控制步 1 次 (高频) | PaliGemma 初始化，flow-matching 训练 |

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **分层时间尺度**：世界模型在子任务级别运行（低频），VLA 在控制步级别运行（高频）。这避免了逐帧预测的误差累积，同时保持对局部视觉反馈的响应性。

2. **逻辑 - 视觉对齐**：视觉世界模型的预测严格受未来逻辑状态转移约束。不是自由生成视频，而是预测"逻辑状态对应的视觉终点"。

3. **潜变量 vs 像素**：预测 2048 维潜变量特征而非像素图像。实验表明潜变量比 Stable Diffusion 像素生成成功率高 10%+，因为避免了重建噪声和不必要细节。

4. **单向信息流**：action expert 可以 attend 到 understanding 和 goal experts，但反向信息流被显式禁止。这保持了分层结构并稳定训练。

⚡ **Eureka Moment**：这篇论文最核心的想法是——**用逻辑世界模型保证长视野一致性，用视觉世界模型提供可执行的感知锚点，两者在潜变量空间对齐而非在像素或语言空间对齐**。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
H-WM 核心：P(X_{m+1}, f_pred^{m+1} | X_m, obs_m, q_m) = P(X_{m+1} | X_m) × P(f_pred^{m+1} | X_{m+1}, obs_m, q_m)
```

**目标分解**：

1. **逻辑世界模型目标**：学习符号状态转移动力学
```
L_logic = -Σ_m log P_ML(a_{m+1}, X_{m+1} | X_m, obs_m, q_m)
```

2. **视觉世界模型目标**：对齐预测潜变量与真实子目标潜变量
```
L_visual = SW(f_pred^{m+1}, f_goal^{m+1})
```
其中 SW 是 Sliced Wasserstein 距离，f_goal^{m+1} = ϕ(g_goal^{m+1}) 是用冻结视觉编码器 ϕ 编码的真实子目标图像。

3. **VLA 策略目标**：Flow Matching 生成动作块
```
L_policy = E_t[||α^t - v_θ(obs_t, q_t, a_{m+1}, f_pred^{m+1}, t)||^2]
```

**变量说明**：

| 符号 | 含义 | 维度/类型 |
|------|------|-----------|
| X_m | 子任务 m 的逻辑状态（ground atoms 集合） | 符号集合 |
| a_{m+1} | 子任务 m→m+1 的逻辑动作 | PDDL action schema |
| obs_m | 子任务 m 起点的 RGB 观测 | H×W×3 |
| q_m | 子任务 m 起点的关节配置 | R^dof |
| f_pred^{m+1} | 预测的潜变量视觉子目标 | R^2048 |
| f_goal^{m+1} | 真实子目标图像的潜变量 | R^2048 |
| ϕ(·) | 冻结视觉编码器 (SigLIP) | 图像→R^2048 |
| α^{t:t+k} | VLA 输出的 k 步动作块 | R^{k×action_dim} |

**直觉解释**：

逻辑世界模型负责"做什么"（符号规划），视觉世界模型负责"做成什么样"（视觉锚点），VLA 负责"怎么做"（低层控制）。三者解耦但通过对齐的潜变量空间连接。

> 符号与本文/相关文档保持一致：逻辑状态 X 用花体，潜变量 f 用小写，动作 α 用希腊字母。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 LIBERO-LoHo 任务："把黄油和巧克力布丁放进抽屉，然后关上抽屉"（5 步）。

**步骤分解**：

```
子任务 0: 初始状态
  X_0 = {OnTable(butter), OnTable(pudding), Closed(drawer), ...}
  obs_0 = [相机图像]
  q_0 = [关节角度]

子任务 0→1: 逻辑世界模型预测
  输入: X_0, obs_0, q_0
  输出: a_1 = Pick(butter), X_1 = {Holding(butter), OnTable(pudding), Closed(drawer), ...}

子任务 1: 视觉世界模型预测
  输入: obs_0, a_1, X_1, q_0
  输出: f_pred^1 ∈ R^2048 (对应"抓握黄油成功"的视觉特征)

子任务 1 执行: Guided VLA 运行
  每步 t: 输入 obs_t, q_t, a_1, f_pred^1 → 输出 α^{t:t+8} (8 步动作块)
  子任务完成预测器持续监测 → 检测到"抓握完成" → 触发 m=1→m=2

子任务 1→2: 逻辑世界模型预测
  输入: X_1, obs_1, q_1
  输出: a_2 = Place(butter, drawer_top), X_2 = {...}

... 重复直到子任务 5 完成
```

**数值示例**（假设）：

- 逻辑世界模型 beam search: beam_size=5，每步扩展 5 个候选动作，MLeval 评分后选 top-1
- 视觉世界模型：迭代去噪 50 步，从 N(0,I) 采样到 f_pred^1
- VLA：每步输出 k=8 步动作块，控制频率 10Hz，子任务平均执行时间 8 秒
- 无引导 π0.5：5 步任务成功率约 32%（误差累积导致后几步崩溃）
- H-WM 引导 π0.5：5 步任务成功率约 81%（每步有视觉锚点纠正）

## 4. 工程视角 (Engineering View)

**吞吐/延迟/步数/抖动/量化误差/内存等 trade-off**：

| 指标 | 数值 | 工程含义 |
|------|------|----------|
| 世界模型推理频率 | ~0.1-0.2 Hz (每子任务 1 次) | 低频调用，CPU 可承载 |
| VLA 控制频率 | 10 Hz (每步 100ms) | 需 GPU 实时推理 |
| 视觉潜变量维度 | 2048 (PaliGemma 隐藏层) | 比像素生成节省 99%+ 带宽 |
| 逻辑模型大小 | Qwen3-4B + LoRA (~100MB 额外参数) | 可 CPU 推理，延迟 <500ms |
| 视觉模型大小 | PaliGemma 3B + 2 层 FC | 需 GPU，但可共享 VLA 骨干 |
| 训练数据需求 | LIBERO 逻辑标注版 + RoboCerebra | 标注成本：每 episode 约 2-4 小时人工校验 |
| 训练步数 | 逻辑 10k / 视觉 100k / VLA 60k | 约 3-5 天单卡训练 |

**部署约束**：

1. **逻辑状态估计**：需要 off-the-shelf VLM (Qwen3-VL-2B) 从观测估计 X_m。这引入额外延迟和误差传播风险。

2. **子任务边界检测**：完成预测器需每步查询，若误检会导致过早/过晚切换子任务。论文未报告误检率。

3. **内存占用**：同时加载逻辑模型 (4B)、视觉模型 (3B)、VLA (3B) 需约 20-30GB GPU 内存（量化后可降低）。

**工程含义**：

- 适合离线规划 + 在线执行场景（世界模型预计算子任务序列）
- 不适合高动态环境（世界模型假设子任务内环境静止）
- 逻辑标注是主要落地瓶颈（需为每个新任务域设计谓词集）

| 场景 | 能力 | 原因 |

### 不能做什么

| 场景 | 限制 | 原因 |
|------|------|------|
| 高动态环境 | ❌ 弱 | 世界模型假设子任务内环境静止 |
| 连续接触任务 | ❌ 弱 | 符号离散化不适合精细力控 |
| 无逻辑标注新域 | ❌ 弱 | 需重新设计谓词集和标注 |
| 移动/双足/人形 | ⚠️ 未验证 | 实验仅在 UR5e 机械臂上验证 |

### 6.1 隐含假设 (Hidden Assumptions)

**X-Ray 批判视角**：

1. **任务可符号化**：假设所有任务能用 PDDL 风格谓词完整描述。对于需要连续推理的任务（如"倒水到半满"），符号化会丢失关键信息。

2. **逻辑状态可估计**：假设 VLM 能从观测准确估计 X_m。论文用 Qwen3-VL-2B + one-shot prompting，但未报告估计错误率及其对规划的影响。

3. **子任务边界清晰**：假设子任务完成可被可靠检测。对于模糊边界（如"抓取中"vs"抓取完成"），完成预测器可能震荡。

4. **视觉 - 逻辑对齐充分**：假设 2048 维潜变量能充分编码逻辑状态对应的视觉信息。对于复杂场景，可能有信息瓶颈。

5. **训练 - 测试分布一致**：实验在同一数据集内评估，未测试跨数据集泛化（如在 RoboCerebra 训练，在 LIBERO 测试）。
