## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练/推理差异 |
|------|------|------|-----------|---------------|
| 视觉编码器 (ViT) | 初始 RGB 图像 $I_0$ | 视觉 token 序列 | 单次前向 | 冻结参数 |
| 语言模型骨干 | 视觉 token + 指令 L | bbox 预测 + 动作 token | 自回归生成 | 更新参数 |
| 动作解码器 | 离散动作 token | $(\Delta\theta_1, \Delta\theta_2, \Delta z)$ 连续值 | 贪心解码 | 确定性映射 |
| PTZ 执行器 | 连续动作三元组 | 新视角图像 $I_1$ | 物理执行 | 真实硬件 |

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **离散化而非连续回归**：VLM 本质是 next-token 预测，直接回归连续值难以收敛（论文实验：连续回归在测试集上接近 0% 完成率）
2. **层次化编码**：将角度分解为"十位 + 个位"，每位再用{5,2,1}基表示——类似找零钱，保证 token 数最少
3. **Bbox CoT 引导**：先预测目标框再生成动作——强制模型显式定位，避免"图像→动作"黑盒映射
4. **IoU 过滤迭代**：每轮 SFT 后用预测 bbox 与真值 IoU 筛选数据——伪标签质量逐步提升

⚡ **Eureka Moment**：把 PTZ 相机控制问题重新表述为"离散 token 预测问题"，利用 VLM 已有的语言建模能力，无需额外控制头即可实现物理动作输出。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
a* = argmax_a  R(I₁(a), L)  其中 a = (Δθ₁, Δθ₂, Δz) 用层次化 token 编码
```

**目标**：找到相机动作 $a$，使得执行后的新视角 $I_1$ 对指令 $L$ 的信息增益最大。

**层次化动作编码**（核心创新）：

对于目标角度 $x \in \mathbb{Z}_{\geq 0}$，先分解为十进制位：

```
x = Σ_{ℓ=0}^{L-1} x^(ℓ) · 10^ℓ,  其中 x^(ℓ) ∈ {0,1,...,9}
```

每位再用基 D = {5, 2, 1} 的线性组合表示：

```
x^(ℓ) = Σ_{d∈D} a_d^(ℓ) · d,  a_d^(ℓ) ∈ ℤ≥₀
```

编码目标是最小化 token 数：

```
min_{a_d^(ℓ)} Σ_{d∈D} a_d^(ℓ)  subject to  Σ_{d∈D} a_d^(ℓ) · d = x^(ℓ)
```

**变量说明**：

| 符号 | 含义 | 取值范围 |
|------|------|----------|
| x | 目标角度或 zoom 值 | 非负整数 |
| ℓ | 数位层级（0=个位，1=十位） | 0, 1 (L=2 覆盖 98.6% 样本) |
| d | 基元素 | 5, 2, 1 |
| $a_d^{(\ell)}$ | 基 d 在位ℓ的系数 | 非负整数 |

**直觉**：这等价于"找零钱问题"——用{5,2,1}硬币凑出 0-9 的数字，要求硬币数最少。贪心算法（先拿 5，再拿 2，最后 1）保证最优解。

**示例**：$x = 7 \to 7 = 5 + 2 \to$ token 序列 $[5, 2]$（2 个 token）；若均匀离散化需 7 个 token。

**GRPO 目标函数**（RL 阶段）：

```
J(θ) = (1/N) Σ_i [min(s_i(θ), clip(s_i(θ), 1-ε, 1+ε)) · A_i - β · D_KL(π_θ || π_ref)]
```

其中 $s_i(\theta) = \pi_\theta(o_i|q) / \pi_{\theta_{\text{old}}}(o_i|q)$ 是重要性采样比率。

**奖励函数**：

```
R = (1/4) · (R_IoU + R_θ1 + R_θ2 + R_zoom)
```

- R_IoU：预测 bbox 与真值的 IoU
- R_θ1, R_θ2：角度误差<1°时线性从 0 到 1，>1°时线性降到 0
- R_zoom：类似，但容忍窗口更宽（zoom 精度要求较低）

> 符号与本文/相关文档保持一致：$\Delta\theta_1=\text{pan}$（水平），$\Delta\theta_2=\text{tilt}$（垂直），$\Delta z=\text{zoom}$（仅正向）

## 3. 带数字走一遍：玩具例子 (Worked Example)

**场景**：指令"盒子里的笔是什么品牌？"，初始图像中笔在右下角，距离较远。

**步骤 1：Bbox 预测**
- 模型预测 bbox: [0.72, 0.65, 0.88, 0.85]（归一化坐标）
- 对应图像中右下角区域

**步骤 2：动作计算**（伪标签生成逻辑）
- Pan ($\Delta\theta_1$)：bbox 中心 $x=0.80$，图像中心 $x=0.50$ → 需向右转
  - 归一化偏差 = 0.80 - 0.50 = 0.30
  - 映射到角度：假设视野 60° → 0.30 × 60° = 18°
  - 层次化编码：$18 = 10 + 5 + 2 + 1$ → token $[10, 5, 2, 1]$（4 个 token）

- Tilt ($\Delta\theta_2$)：bbox 中心 $y=0.75$，图像中心 $y=0.50$ → 需向下转
  - 归一化偏差 = 0.75 - 0.50 = 0.25
  - 映射到角度：0.25 × 60° = 15°
  - 层次化编码：$15 = 10 + 5$ → token $[10, 5]$（2 个 token）

- Zoom ($\Delta z$)：bbox 面积占比 $= 0.16\times0.20 = 0.032$，目标占比 $0.25$
  - zoom 比率 $= 0.25 / 0.032 \approx 7.8$
  - 假设 $90$ 单位$=1\times$ → $\Delta z \approx 7.8 \times 90 \approx 700$
  - 层次化编码：$700 = 500 + 200$ → token $[500, 200]$（2 个 token）

**步骤 3：自回归生成**
```
输入：[图像 token] + "指令：盒子里的笔是什么品牌？" + "Bbox:"
输出：" [0.72,0.65,0.88,0.85] " + "Action:" + "[10,5,2,1]" + "[10,5]" + "[500,200]"
```

**步骤 4：执行与验证**
- PTZ 执行：右旋 18°、下旋 15°、zoom 7.8×
- 新图像中笔占据画面中心 25% 区域
- 人类评估：任务完成 ✅

**关键闭环**：如果第一次动作后 IoU < 0.95，该样本在下一轮 SFT 中被过滤掉，不会污染训练数据。

## 4. 工程视角 (Engineering View)

| 工程指标 | 数值/设计 | 含义 |
|----------|-----------|------|
| Token 效率 | 平均 2.3 token/动作 | 比均匀离散化（12.7）节省 82% 上下文长度 |
| 推理延迟 | 单次前向（~200ms on A100） | 无需迭代搜索，一次生成即可执行 |
| 样本效率 | 500 真样本 + 50K 伪标签 | RL 阶段仅需 450 真样本（450 train / 50 test） |
| 动作空间覆盖 | ±29° 覆盖 98.6% 真实需求 | 两位十进制足够，无需扩展到百位 |
| 量化误差 | 角度 1° 容忍窗口 | 对应物理执行器精度要求 |
| 内存占用 | Qwen2.5-VL 7B + 43 新 token | 新增 embedding 随机初始化，联合优化 |

**部署约束**：

1. **硬件依赖**：需要真实 PTZ 相机（两轴云台 + 变焦镜头），无法纯软件仿真
2. **标定需求**：角度 - 像素映射关系需预先标定（论文用 Random Forest 学习）
3. **安全边界**：pan/tilt 有物理限位，推理时需 clip 到安全范围
4. **实时性**：单次前向 $200\,\text{ms}$ + PTZ 执行时间（$\sim500\,\text{ms}$）→ 端到端$\sim700\,\text{ms}$

**Trade-off**：

- **离散化粒度**：更细粒度（如增加小数位）→ token 数增加 → 上下文长度压力
- **IoU 阈值**：SFT2 用 $0.7$，SFT3 用 $0.95$ → 阈值越高数据越少但质量越好
- **RL 强度**：$\beta$（KL 惩罚）过大 → 策略更新慢；过小 → 偏离预训练知识

**真样本采集流程**（论文 §3.3）：
1. 人工操作 PTZ 相机对准目标

4. 记录执行后图像 $I_1$  
5. 覆盖多室内场景、多物体类别、多距离/尺度

**评测任务设置**：

- **测试集**：50 个未见过的真实场景（与训练集无重叠）
- **评估轮次**：5 次独立运行（消除随机性）
- **成功标准**：人类评估——目标物体在画面中清晰可识别且居中
- **指标**：
  - MAE（平均绝对误差）：$\Delta\theta_1$(°), $\Delta\theta_2$(°), $\Delta z$(单位)  
  - CR（任务完成率）：成功次数 / 总次数

### 6.1 隐含假设 (Hidden Assumptions)

**X-Ray 批判视角**：

1. **假设：初始视野包含目标**——如果目标完全在初始画面外，bbox 预测无法定位（论文未讨论）
2. **假设：PTZ 运动学是理想的**——实际执行器有 backlash、延迟、非线性，RL 部分补偿但未建模
3. **假设：单步足够**——复杂场景可能需要多步感知（如"先看桌面，再看抽屉里"）
4. **假设：指令是明确的**——模糊指令（如"看看有什么"）未测试
5. **假设：室内场景**——户外光照变化、大尺度场景未验证

## 7. 与相关工作对比 (Comparison)

| 工作 | 关注点 | 架构 | 训练方式 | 适用场景 |
|------|--------|------|----------|----------|
| OpenVLA (2024) | 机械臂操作 | VLM + 动作头 | 行为克隆 | 抓取/放置 |
| Active-O3 (2025) | 软件裁剪 | VLM + 算法选择 | 纯软件 | 静态图像分析 |
| VG-AVS (2025) | 离散 NBV | 级联模块 | RL | VQA 视角选择 |
| **EyeVLA (本文)** | **PTZ 相机控制** | **端到端 VLA** | **SFT+RL** | **具身主动感知** |

**关键差异**：

- OpenVLA 预测末端执行器位姿，EyeVLA 预测相机参数——前者是"操作"，后者是"感知"
- Active-O3 纯软件（裁剪已有图像），EyeVLA 控制真实硬件——后者有物理约束
- VG-AVS 用离散网格预定义视角，EyeVLA 连续空间（离散编码）——后者更灵活

**面试 Tip**：被问到"EyeVLA 和 OpenVLA 有什么区别"时，回答："OpenVLA 解决'怎么操作物体'，EyeVLA 解决'怎么获取更好的观察'——感知是操作的前置条件，EyeVLA 证明用离散 token 编码可以把预训练 VLM 直接转为感知策略，无需额外控制头。"
