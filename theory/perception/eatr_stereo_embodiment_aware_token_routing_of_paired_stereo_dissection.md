### 1.2 关键机制 (Key Mechanism)

**设计动机**：人形机器人双足行走时，头载相机经历三重扰动——步态震动传递到相机、头部/腰部运动持续改变视角、手臂运动产生构型相关的自遮挡。长时程任务中，某一阶段丢失的证据会传播到后续所有阶段。立体视觉的互补性恰好能缓解这个问题——在一个视角被遮挡的内容可能在另一视角可见。

**关键洞察**：现有方法（如 StereoPolicy）用融合后的立体表示**替换**原始图像Token，丢弃了预训练VLM的单目Token结构。EATR-Stereo 选择**保留**主视图Token不变，将辅助视图信息构建为一个独立的、与主视图索引对齐的辅助Token流（CVAT），然后通过路由门控选择性注入。

⚡ **Eureka Moment**：「不修改主视图Token，而是让主视图Token去查询辅助视图，构建一个平行的辅助Token流，再用机器人身体姿态来决定每条辅助Token该用多少」——这是全文最核心的一个想法。

**CVAT构造流程**：
1. 冻结的 Cosmos VLM 分别编码主视图和辅视图，得到 M_t 和 A_t（共享隐藏空间，维度 N×d）
2. 主序列 M_t 提供 Query，辅序列 A_t 提供 Key 和 Value，通过多 headed cross-view attention（借鉴 StereoPolicy）
3. 多头输出拼接后经投影 + FFN残差块，得到 C_t——其Token索引跟随主序列
4. C_t 被送入 Token 路由模块

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
C̃_{t,i} = σ(f_r([LN(M_{t,i}); LN(C_{t,i}); |M̄-C̄|; M̄⊙C̄; h_t^s])) · C_{t,i}
```

每条辅助Token的注入强度由一个标量门控 r ∈ (0,1) 控制，该门控同时依赖主辅Token的特征关系和机器人身体状态。

**目标**：让VLA在生成动作时，能够根据当前机器人构型和主辅视图差异，动态决定「需要多少辅助视角信息」。

**公式拆解**：

1. **CVAT构造**（交叉视图注意力）：
```
Q_h = LN(M_t) W_h^Q,   K_h = LN(A_t) W_h^K,   V_h = LN(A_t) W_h^V
O_h = softmax(Q_h K_h^T / sqrt(d_h)) V_h
C_t = Concat_h(O_h) W^O + MLP(LN(Concat_h(O_h) W^O))
```

2. **身体分段编码**（5组：腿/臂/头/腰/机器人姿态）：
```
z_{t,g} = f_g(LN_g(Flatten(s_{t-K+1:t,g}))) + e_g,  g=1,...,5
α_{t,g} = exp(f_attn(z_{t,g})) / Σ_j exp(f_attn(z_{t,j}))
h_t^s = f_fuse([Σ α_{t,g} z_{t,g}; (1/G)Σ z_{t,g}])
```

3. **Token级路由门控**：
```
q_{t,i} = [M̄_{t,i}; C̄_{t,i}; |M̄_{t,i} - C̄_{t,i}|; M̄_{t,i} ⊙ C̄_{t,i}; h_t^s]
r_{t,i} = σ(f_r(q_{t,i})),   C̃_{t,i} = r_{t,i} · C_{t,i}
```

4. **VLA上下文拼接**：
```
E_t^VLA = [L_t; M_t; C̃_t]
```

5. **Flow Matching 训练目标**：
```
L_FM = E_{t,τ} [||v_θ(Y_t^τ, τ | E_t^VLA, S_t) - u_τ||_2^2]
```

> 符号说明：
> - M_t, A_t ∈ R^{N×d}: 主/辅视图Token序列（N个Token，d维隐藏）
> - C_t ∈ R^{N×d}: 交叉视图辅助Token，索引跟随主序列
> - K=6: 本体感受历史帧数
> - G=5: 身体分段数（腿/臂/头/腰/姿态）
> - r_{t,i} ∈ (0,1): 第i条辅助Token的门控标量
> - H=30: 动作块步数
> - v_θ: flow matching预测的速度场

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设在抓取阶段的某一控制步 t：

**场景设定**：机器人右手正在接近瓶子，右手臂在左相机（主视图）中完全遮挡了瓶子，但右相机（辅视图）从侧面仍能部分看到瓶子。

**数值推演**：

| 变量 | 数值/维度 | 说明 |
|------|-----------|------|
| M_t（主视图Token） | [0.82, -0.15, 0.43, ...] | 编码了「被手臂遮挡的场景」 |
| A_t（辅视图Token） | [0.31, 0.72, -0.28, ...] | 编码了「可见瓶子的场景」 |
| \|M̄ - C̄\|（差异特征） | [0.51, 0.87, 0.71, ...] | 大差异 → 辅视图提供了不同信息 |
| M̄ ⊙ C̄（点积特征） | [0.25, -0.11, -0.12, ...] | 低/负值 → 信息互补性高 |
| h_t^s（本体聚合） | [0.65, 0.88, 0.12, ...] | 手臂段激活高（正在运动），腿段低 |

**路由门控输出**：

假设路由MLP对某条关键Token（对应瓶子区域）计算出：

```
f_r(q) = 1.85  →  r = σ(1.85) ≈ 0.86
```

这意味着该Token的辅助信息被**高度启用**（86%权重注入），因为：
- 主辅视图差异大（|M̄-C̄| 大）→ 辅视图有主视图缺少的信息
- 手臂段本体状态激活高 → 系统知道手臂正在运动，自遮挡概率大
- 点积低 → 信息互补而非冗余

而对另一条不相关Token（如背景天花板区域）：

```
f_r(q) = -2.10  →  r = σ(-2.10) ≈ 0.11
```

几乎关闭（11%），因为主辅视图在该区域无差异，不需要辅助信息。

**最终上下文**：

```
E_t^VLA = [L_t (10 tokens); M_t (196 tokens); C̃_t (196 tokens, 部分门控)]
```

总上下文约 402 个Token送入 GR00T1.7 Action Expert，输出30步连续动作。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **长时程人形操作**：100秒以上的搜索-抓取-放置-返回全流程，在真实人形机器人上60%成功率
- **严重自遮挡恢复**：当手臂完全遮挡主视图时，80%恢复率（vs CVAT的30%）
- **跨平台泛化**：在Franka臂仿真上同样领先（43.33% vs 次优39.44%）
- **语义遵从**：80%的篮子颜色遵从率（语言条件放置）

### 不能做什么
- **单视角退化**：如果立体相机之一故障，系统退化为单目（但主视图Token保留，至少不会崩溃）
- **跨平台迁移**：仅在HONOR Omega 1.0上做了物理验证，未在其他人形平台上测试
- **动态主辅切换**：主/辅视图固定分配，无法根据实时遮挡情况动态切换

### 6.1 隐含假设 (Hidden Assumptions)

1. **主视图始终提供足够的语义基础**：设计假设主视图Token足以支撑VLM的语义理解，辅助视图只是「补充」。如果主视图质量持续差（如镜头脏污），可能影响整体性能
2. **立体相机标定稳定**：假设左右相机之间的几何关系在机器人运动过程中保持稳定。步态震动可能导致标定漂移，文中未讨论
3. **本体感受无延迟/无噪声**：路由依赖精确的关节状态。真实系统中本体感受可能有延迟和噪声，影响门控准确性
4. **5段身体分段的通用性**：腿/臂/头/腰/姿态的分段在HONOR Omega上有效，但换到不同构型的人形（如双臂vs单臂、有无腰部自由度）需要重新设计分段

- 做人形机器人/双足平台VLA感知接口设计的研究者——身体分段路由是直接可复用的思路
- 评估立体视觉在预训练VLA中增值空间的研究者——消融实验清晰地拆解了CVAT和路由各自的贡献
- 需要部署VLA到物理平台、关注Token级接口设计的工程师——B-Spline动作过渡和异步缓冲的工程细节有参考价值

**建議章節路徑**：
1. 先读 §III-B（CVAT构造）→ 理解核心Token操作
2. 再看 §III-C（身体分段路由）→ 理解本体感受如何条件化门控
3. 然后 §IV-C（物理人形结果）→ 看真实数据
4. 可跳 §II（相关工作）—— 除非你需要写related work

**不值得精讀的理由**：
- 如果你只做机械臂桌面操作，人形机器人特有的步态扰动和自遮挡问题与你的场景距离较远
- 如果你已经熟悉 StereoPolicy + GR00T 架构，这篇的创新主要在路由模块，其余部分是已有工作的组合
