### 1.2 关键机制 (Key Mechanism)

**核心问题诊断**：VLM 在 cluttered 场景中的视觉幻觉不是"注意力不够"，而是"不知道应该关注什么"。一步聚焦（直接告诉模型看哪里）之所以失败，是因为：
- 有效聚焦需要深度场景理解 — 不理解全局就无法判断局部重要性
- 复杂场景中存在多个相似 distractor — 需要跨对象比较才能确认目标

**解决方案的三层设计**：

1. **粗阶段 — 场景图引导的图推理**：用 OvSGTR 生成场景图，将对象标注为 `<ref>`、空间关系为 `<pred>`、位置为 `<box>`，输入 VLM 做高层推理。VLM 是"真理唯一来源"，图只是推理引导 — 不一致时 VLM 可选择邻近节点、丢弃无关项、或保留模糊候选。

2. **细阶段 — Agentic 自主探索**：VLM 按粗阶段路线逐个"放大"子场景，用受限感知域验证相关性。三种自主行为：确认（对齐$\to$继续）、语义 zoom（模糊$\to$缩小视野）、局部空间搜索（缺失$\to$扫描邻域）。

3. **焦点调制 — 像素级注意力引导**：将验证对象 bbox 光栅化为 Focus Score Map，对背景区域同时衰减亮度和高频细节（高斯模糊），保留前景清晰明亮。

⚡ **Eureka Moment**：有效的聚焦不是"直接看关键物体"，而是"先理解全局场景结构，再逐层分解验证" — 聚焦本身就是一个需要推理的认知过程。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
I_out = s ⊙ I_dim + (1-s) ⊙ B_σ(I_dim)
其中 I_dim = I ⊙ (β + (1-β)·s)
```

**目标**：生成一张调制后的图像，让任务相关物体保持清晰明亮，背景 distractor 被柔化变暗，从而引导 VLM 的注意力。

**公式分解**：

1. **Focus Score Map**（二元掩码）：
```
s_{u,v} = I[∃k∈C: (u,v) ∈ b_k]
```
候选对象 bbox 内的像素为 1，背景为 0。

2. **亮度衰减**：
```
I_dim = I ⊙ (β + (1-β)·s)
```
$\beta$ 是可见性底线（防止背景完全黑掉）。前景像素保持原亮度，背景像素亮度降至 $\beta$ 倍。

3. **高频模糊**：
```
I_out = s ⊙ I_dim + (1-s) ⊙ B_σ(I_dim)
```
前景保留原始细节，背景用高斯模糊 $B_\sigma$ 平滑高频信息。

**变量说明**：

| 符号 | 含义 | 典型值 |
|------|------|--------|
| s | Focus Score Map ($H \times W$) | 二元 {0,1} |
| $\beta$ | 可见性底线 | 论文未明确给出 |
| $\sigma$ | 高斯模糊核大小 | 论文未明确给出 |
| C | 验证对象集合 | 动态（细阶段输出） |
| b_k | 第 k 个对象 bbox | 场景图提供 |

$>$ 符号与论文 §3.4 保持一致。$\beta$ 和 $\sigma$ 的具体超参论文未给出，待补充。

**直觉**：这不是"裁剪掉背景"，而是"让背景变模糊变暗" — 保留环境上下文但降低其视觉显著性。类比人眼：你看到整个房间，但注意力集中在桌上的物体上。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个机器人操作场景：桌面上有 8 个物体（4 个绿色方块、2 个红色圆柱、1 个蓝色底板、1 个机械臂夹爪）。任务：找到绿色方块并放到底板上。

**Step 1: 场景图生成**
```
OvSGTR 检测到 8 个节点:
  N1: green_block @ [120,80,180,140]  mass=0.35
  N2: green_block @ [250,200,310,260] mass=0.32
  N3: green_block @ [50,300,110,360]  mass=0.28
  N4: green_block @ [gripper]         mass=0.30
  N5: red_cylinder @ [300,100,340,180] mass=0.20
  N6: red_cylinder @ [80,200,120,280]  mass=0.18
  N7: blue_board @ [400,350,500,400]   mass=0.50
  N8: gripper @ [150,50,200,100]       mass=0.15
  边: N4-on-N8, N1-near-N5, N7-below-N2, ...
```

**Step 2: 粗阶段图推理**
VLM 收到场景图文本 + 任务指令"找到绿色方块放到底板"，推理：
- "任务涉及绿色方块和蓝色底板"
- "N1, N2, N3, N4 是绿色方块候选"
- "N7 是底板"
- "N4 在夹爪上 — 可能是已抓取的，需要检查是否正确"
- 输出子场景候选：[N4, N1, N2, N3, N7]

**Step 3: 细阶段自主探索**
VLM 逐个验证：
- N4（夹爪上的绿色方块）：放大检查 → 形状正确但方向错误，需要旋转 → 保留
- N1：放大检查 → 是目标形状 → 保留
- N2：放大检查 → 是目标形状 → 保留
- N3：放大检查 → 被遮挡，语义 zoom → 确认是目标 → 保留
- N7（底板）：确认位置 → 保留
- 验证集合 C = {N1, N2, N3, N4, N7}

**Step 4: 焦点调制**
假设图像 $640 \times 480$，$\beta = 0.3$，$\sigma = 5$：
- 5 个 bbox 覆盖约 $15\%$ 像素 → $s$ 中 $15\%$ 为 $1$
- I_dim：前景保持 100% 亮度，背景降至 30%
- I_out：前景保留原始细节，背景高斯模糊
- 结果：VLM 看到的图像中，5 个关键物体清晰明亮，其余区域暗淡模糊

**Step 5: VLM 最终决策**
调制后图像输入 VLM，VLM 不再被红色圆柱 distractor 干扰，正确输出：
"旋转夹爪中的绿色方块（N4），然后放到蓝色底板（N7）上"

## 4. 工程视角 (Engineering View)

| 维度 | 两阶段推理路径 | 适配器蒸馏路径 |
|------|---------------|---------------|
| 延迟 | 每步需 2 次 VLM 调用（粗+细）+ OvSGTR 前向 | 单次 VLA 前向 + 适配器前向 |
| 吞吐 | 受 VLM 推理速度限制（~1-2s/步） | 接近原生 VLA（~100ms/步） |
| 内存 | 需维护场景图 + 候选列表 | 适配器额外参数 ~数 M |
| 计算开销 | 显著增加（2-3× VLM 调用） | 仅 2.64% 额外开销（论文 §4.3） |
| 部署约束 | 适合离线/半实时决策 | 适合在线实时控制 |
| 降级策略 | 场景图失败时可跳过粗阶段 | 熵门控：不确定时 bypass 掩码 |

**工程含义**：
- 两阶段路径适合"深思熟虑"的高层决策（如任务规划），每步有秒级预算
- 适配器路径适合"快速反应"的低层控制（如抓取调整），需要毫秒级响应
- OvSGTR 后端是外部依赖 — 如果场景图质量差，整个 pipeline 性能下降
- 熵门控是关键安全机制：当掩码不确定性过高时，直接喂原始图像给 VLA，避免错误聚焦导致更差决策

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **Cluttered 场景中的多对象区分**：当场景中有多个相似 distractor 时，通过逐个子场景验证正确识别目标
- **跨模态指令理解**：支持自然语言、常识性指令、复杂长指令、视觉属性描述四种指令类型
- **VLA 实时控制**：适配器蒸馏后可用于在线决策，开销仅 2.64%
- **多模型泛化**：在 Qwen2.5-VL、InternVL2.5、gpt-4o-mini、gemini-2.5-flash 上均有效

### 不能做什么（失败模式）
- **场景图严重错误时**：如果 OvSGTR 漏检关键对象或产生大量假阳性，粗阶段推理基于错误图，细阶段可能无法恢复
- **极端遮挡场景**：当目标被完全遮挡时，场景图无法检测到，两阶段都无法定位
- **需要全局关系推理的任务**：如"把最左边的绿色方块放到最右边的底板上" — 场景图的空间关系可能不足以支持这种推理
- **动态场景**：论文假设静态场景；如果物体在决策过程中移动，场景图可能过时

**面试 Tip**：当被问到"SceneDiver 和 SoM 的区别"时，回答："SoM 是'把所有对象都标记出来让模型自己选'，SceneDiver 是'先用场景图理解全局结构，再自主探索验证，最后只聚焦确认的目标'——前者是标记，后者是推理。"
