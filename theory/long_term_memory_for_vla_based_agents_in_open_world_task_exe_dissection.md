### 1.2 关键机制 (Key Mechanism)

**双层记忆架构**：
- **短期工作记忆（Dashboard）**：结构化压缩当前场景信息（物体状态、工具索引、任务进度），采用即时覆盖策略减少上下文占用
- **长期情景记忆**：跨会话保存历史对话与执行轨迹，支持语义检索复用成功经验，定期提取操作偏好画像

**进度感知 VLA（Skill-VLA）**：
- 在 GR00T 基础上附加轻量 Progress Head
- 输入：机器人状态 St（query）+ VLM 隐藏状态（key/value）
- 输出：连续进度标量 pt∈[0,1]
- 训练：MSE Loss，真值为子任务时间步归一化位置
- 推理：pt 超过阈值 → 自动触发下一子任务

**异步连续推断**：
- 解耦模型推断与控制循环，防止推断延迟导致危险停顿
- 使用预测的未来状态 st+d 作为边界约束（而非当前状态 st）
- Training-time RTC：固定 flow matching timestep=1.0 掩蔽前缀，优化后缀

⚡ **Eureka Moment**：**让 VLA 自己判断"这一步做完了没"** —— 通过附加一个轻量进度预测头，将开环执行变为闭环自主切换，无需人工标注时间阈值或固定步数。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
pt = σ(MLP(CrossAttn(St → VLM_hidden)))  ∈ [0,1]
```

**目标**：实时估计当前子任务的完成进度，用于自主触发子任务切换。

**公式**（Progress Head 前向传播）：

```
1. Query 投影：q = Linear(St)              # St: 机器人状态
2. Cross-Attention：h = CrossAttn(q, K=VLM_hidden, V=VLM_hidden)
3. 残差融合：h' = LayerNorm(h + q)
4. MLP 输出：pt = Sigmoid(MLP₂(h'))        # pt ∈ [0,1]
```

**训练损失**：

```
L_progress = MSE(pt, p_gt)
其中 p_gt = (frame_current - frame_start) / (frame_end - frame_start)
```

**异步推断平滑**（Training-time RTC）：

```
vθ(xτ, τ, c) 在 τ=1.0 时固定（掩蔽前缀 d 步）
优化目标：仅对后缀 (H-d) 步进行去噪
边界约束：使用预测状态 st+d 而非当前状态 st
```

**变量说明**：

| 符号 | 含义 | 维度/范围 |
|------|------|-----------|
| St | 机器人状态（关节角 + 末端位姿） | R^6+6 |
| VLM_hidden | Eagle VLM 最终隐藏表示 | R^seq×d_model |
| pt | 预测进度标量 | [0,1] |
| p_gt | 真值进度（帧归一化位置） | [0,1] |
| H | 动作块大小（action horizon） | 50（本文设置） |
| d | 推断延迟步数 | d ≤ s < H |
| τ | Flow matching timestep | [0,1] |
| vθ | DiT 速度估计器 | - |

> 符号与 GR00T 原文保持一致：GR00T 使用 Flow Matching 训练 Diffusion Transformer，本文在其基础上附加 Progress Head。

**直觉**：Progress Head 本质上是一个"时间感知器"——它不预测具体动作，只回答"这一步走到哪了"。通过将机器人状态与 VLM 语义表示做 cross-attention，模型学会将物理状态（如"夹爪已闭合"）与语义进度（如"抓取完成 80%"）对齐。

## 4. 工程视角 (Engineering View)

**推断延迟与异步控制**：

| 参数 | 设置 | 工程含义 |
|------|------|----------|
| 动作块大小 H | 50 步 | 每次推断生成 50 步动作，平衡平滑性与响应性 |
| 执行视界 s | 30 步 | 实际执行 30 步后触发下一次推断 |
| 推断延迟 d | ~5 步 | 模型推断耗时，需在动作块中截弃前 d 步过期动作 |
| Progress Head 权重 | 0.1 | 与动作损失联合训练时的权重配比 |
| 完成阈值 | 0.95 | pt>0.95 时判定子任务完成（可调超参） |

**部署约束**：

- **硬件**：UR3 协作机器人 + VIVE 控制器（遥操作数据采集）+ RTX 5090（推断）
- **训练**：8×A100，40,000 步/任务
- **推断延迟**：云 API（Doubao-1.6）受网络影响大，建议本地部署 Qwen3-VL-Flash
- **内存占用**：Dashboard 结构化压缩后上下文占用减少约 60%（论文声称）

**Trade-off 分析**：

| 设计选择 | 收益 | 成本 |
|----------|------|------|
| 异步推断 | 消除控制停顿，轨迹平滑 | 需维护状态缓冲区，实现复杂度 + |
| Progress Head | 自主切换，无需人工阈值 | 需标注进度真值（帧归一化） |
| 双层记忆 | 减少幻觉，支持经验复用 | 向量检索延迟，存储开销 |
| MCP 封装 | 标准化工具调用，易扩展 | RPC 通信开销 |

**关键工程洞见**：

> "固定时间步切换"在真实环境中必然失败——化学实验的每一步耗时随环境状态变化（如瓶盖松紧、液体粘度）。Progress Head 让系统学会"看状态而不是看钟表"。
