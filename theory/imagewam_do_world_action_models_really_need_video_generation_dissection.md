### 1.2 关键机制 (Key Mechanism)

ImageWAM 的核心设计决策有三层：

1. **用图像编辑替代视频生成作为世界建模先验**
   - 视频生成模型被训练来合成完整的未来视频序列——包括外观细节、背景变化、相机运动等大量与动作预测弱相关的因素
   - 图像编辑模型被训练来根据语言指令变换源图像——这个目标天然匹配机器人策略的核心需求："在给定指令下，当前场景应该发生什么任务相关的视觉变化？"

2. **不解码目标帧，直接用编辑 KV cache 作为世界-动作上下文**
   - 推理时不运行完整的编辑去噪轨迹，也不解码最终编辑图像
   - 只选择一个固定的去噪时间步 τ*，执行一次编辑分支前向传播，提取各层 transformer 的 KV cache
   - 这些 cache 已经包含了视觉潜在变量与任务指令交互后的变换感知表征

3. **双分支联合训练 + 随机去噪时间步采样**
   - 图像编辑分支：flow matching 损失，预测目标帧的 velocity field
   - 动作专家：flow matching 损失，以编辑 cache 为条件预测动作 velocity field
   - 训练时随机采样 τ，使动作专家暴露于编辑过程不同阶段的 cache，增强鲁棒性

⚡ **Eureka Moment**：编辑模型的 KV cache 天然编码了"当前状态到目标状态的变换信息"——这正是机器人策略需要的世界建模中间表示，不需要也不应该去解码完整的未来视频或编辑图像。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
π_θ(a | o, l) ≈ 用编辑骨干的 KV cache C_edit 替代视频生成轨迹:
  (o, l) → C_edit^τ* → a  而非  (o, l) → ô_{t+1:t+H} → a
```

### 目标
让策略模型 π_θ 在给定当前观测 o_t 和任务指令 l 的条件下，预测动作块 a_{t:t+H}，同时引入一个紧凑的世界建模中间表示来替代昂贵的多帧视频生成。

### 公式

**动作预测目标**（标准策略学习）：
```
π_θ(a_{t:t+H} | o_t, l)
```

**Video-WAM 的中间步骤**（多帧视频生成）：
```
(o_t, l) → ô_{t+1:t+H+1} → a_{t:t+H}
```

**ImageWAM 的中间步骤**（单帧编辑变换）：
```
(o_t, l) → C_edit^τ* = {K_ℓ^τ*, V_ℓ^τ*}_{ℓ=1}^L → a_{t:t+H}
```

**图像编辑 flow matching 损失**：
```
L_img = E[z*, ε_z, r] [|| u_φ(z_r, r | o_t, l) - (ε_z - z*_t+H+1) ||²_2]
```

**动作 flow matching 损失**：
```
L_act = E[a*, ε_a, s, τ] [|| v_θ(a_s, s | o_t, l, C_edit^τ) - (ε_a - a*_t:t+H) ||²_2]
```

**联合优化**：
```
L = L_act + L_img
```

### 变量说明

| 符号 | 含义 |
|------|------|
| o_t | t 时刻的图像观测 |
| l | 任务指令（语言） |
| a_{t:t+H} | 动作块，H 为动作视界 |
| C_edit^τ | 编辑骨干在去噪时间步 τ 的 KV cache |
| τ | 训练时随机采样的编辑去噪时间步 |
| τ* | 推理时固定的编辑去噪时间步 |
| z*_{t+H+1} | 目标未来帧的 VAE 潜在表示 |
| ε_z, ε_a | 图像/动作高斯噪声 |
| r, s | 图像/动作 flow matching 时间 |
| u_φ | 图像编辑分支的 velocity 预测器 |
| v_θ | 动作专家的 velocity 预测器 |

> 符号与原文保持一致。L_img 和 L_act 均为 flow matching 的 velocity matching 形式，目标是将噪声分布逐步变换到数据分布。

### 直觉
- L_img 保持编辑分支预测任务相关未来帧的能力，确保提取的 cache 编码有用的视觉变换信息
- L_act 让动作专家学会从编辑 cache 中解读"应该发生什么变化"，并将其转化为可执行动作
- 训练时随机采样 τ 是关键：动作专家看到编辑过程不同阶段的 cache，推理时只需一个固定 τ* 的单步前向

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2D 桌面操作场景：

**场景设定**：
- 当前观测 o_t：一张 224×224 的 RGB 图像，机械臂在左侧，目标杯子在右侧
- 指令 l："把杯子移到中间的托盘"
- 动作视界 H = 16 步

**ImageWAM 推理流程**：

1. **编辑骨干前向**（τ* 固定）：
   - 输入：o_t + l
   - 编辑骨干执行一次去噪前向，提取 L=28 层 transformer 的 KV cache
   - 每层 cache 尺寸：假设 head_dim=64, num_heads=16, seq_len=196（14×14 patch）
   - 单层 cache 大小 ≈ 2 × 16 × 64 × 196 × 4 bytes ≈ 160 KB
   - 总 cache ≈ 28 × 160 KB ≈ 4.5 MB（紧凑！）

2. **动作专家去噪**：
   - 输入：初始动作噪声 ε_a ~ N(0, I)，维度 H×7（7 DoF 机械臂）
   - 以 KV cache 为条件，通过 joint attention 融合编辑表征
   - Flow matching 去噪：从 s=1（纯噪声）到 s=0（干净动作），假设 4 步去噪
   - 输出：â_{t:t+16}，16 步动作序列

3. **对比 Video-WAM**：
   - 需要生成 8 帧未来视频，每帧 14×14×C tokens
   - 假设 C=1024，则视频 tokens ≈ 8 × 196 × 1024 ≈ 1.6M tokens
   - ImageWAM 的 cache 只有 28 × 196 × 128 ≈ 700K tokens（且是直接可用的 KV，不需要再 attention）
   - **Token 量级对比**：ImageWAM 的中间表示约为 Video-WAM 的 1/2-1/3，且无需视频解码

4. **性能数字**（来自论文 Table 1/2）：
   - RoboTwin 2.0 平均成功率：ImageWAM 93.38% vs FastWAM 91.83%（+1.55%）
   - LIBERO 平均成功率：ImageWAM 98.4% vs FastWAM 97.6%（+0.8%）
   - 推理延迟：263ms vs 302ms（1.15× 更快）vs 1081ms（4.1× 更快）

### 6.1 隐含假设 (Hidden Assumptions)

1. **编辑模型的 instruction-to-change 先验可以直接迁移到机器人控制** — 论文通过实验验证了有效性，但尚未分析哪些编辑预训练数据分布对策略学习最有利
2. **单帧编辑变换足以捕获策略所需的世界模型信息** — 对于需要多步因果推理的复杂任务（如可变形物体多阶段形变），单帧变换可能信息不足
3. **固定的 τ* 对所有任务类型都最优** — 训练时随机采样 τ 增强了鲁棒性，但推理时固定 τ* 可能不是所有任务的最优选择
4. **编辑骨干的 frozen VLM 提供足够强的语言-视觉条件** — 如果任务指令涉及编辑预训练未见过的语义概念，frozen VLM 可能成为瓶颈
