### 1.2 关键机制 (Key Mechanism)

FocusPool 的核心设计围绕两个正交组件：

1. **机器人状态条件化（State Conditioning）**：用 FiLM 变换将本体状态 `p = [o_eef, o_grip]`（末端执行器位姿 + 夹爪状态）调制到可学习 token `z₀` 上，生成初始 query `q₀`。这使注意力查询携带了"当前机器人正在做什么"的上下文。

2. **迭代精炼（Iterative Refinement）**：query 不是单次做交叉注意力就结束，而是经过 S 步循环精炼——每一步用上一层的注意力上下文 `cₛ` 通过 FiLM 更新 query 自身：`qₛ₊₁ = FiLM(LayerNorm(cₛ), qₛ)`。这让 query 逐步与任务进展对齐。

⚡ **Eureka Moment**：中间层 CNN 特征已经包含了足够的空间局部信息——不需要两阶段裁剪或输入预处理，只需要一个能"读懂"当前机器人状态并迭代精炼的注意力机制，就能隐式地学会选择性地读取控制相关区域。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
q_0 = (1 + γ(p)) ⊙ z_0 + β(p)    →    q_{s+1} = FiLM(LN(c_s), q_s)    →    z_t = c_S
   状态条件化初始 query                迭代精炼                       紧凑表征
```

**目标**：从中间层 CNN 特征图中，用机器人本体状态引导的注意力机制，选择性聚合控制相关的局部空间区域，输出一个紧凑向量供策略头使用。

**核心方程**：

```
初始化：q_0 = FiLM(p, z_0) = (1 + γ(p)) ⊙ z_0 + β(p)

第 s 步交叉注意力（h 个头并行）：
  Q_h = q_s W_Q^h,  K_h = X W_K^h,  V_h = X W_V^h
  A_h = softmax(d^{-1/2} · Q_h K_h^T)
  C_h = A_h V_h
  c_s = Mean_h(C_h)

Query 更新：
  q_{s+1} = FiLM(LayerNorm(c_s), q_s)

最终输出：z_t = c_S（S 步精炼后的头平均上下文）
```

**变量说明**：

| 符号 | 含义 | 维度 |
|------|------|------|
| `p` | 机器人本体状态（末端执行器位姿 + 夹爪） | R^d_p |
| `z_0` | 可学习初始 token | R^d |
| `γ(·), β(·)` | FiLM 线性投影网络 | R^d → R^d |
| `F^l` | ResNet 第 l 层特征图 | R^{C_l × H_l × W_l} |
| `x_n` | 第 n 个图像 token（特征 + 傅里叶位置编码） | R^{C_l + 2B} |
| `X` | 所有图像 token 堆叠 | R^{N × (C_l + 2B)}, N = H_l × W_l |
| `q_s` | 第 s 步精炼后的 query | R^d |
| `A_h` | 第 h 头的注意力权重矩阵 | R^{1 × N} |
| `c_s` | 头平均上下文向量 | R^{d_v} |
| `S` | 精炼步数 | 标量 |

**直觉**：query 不是静态的——它像一个"可调节的探照灯"，初始时由机器人状态（"我在哪里、手在干什么"）点亮，然后每轮注意力精炼根据看到的视觉内容调整自己的方向，S 轮后聚焦到任务最相关的局部区域。

**早期注意力正则化**（训练稳定器，非推理必需）：

```
高斯目标热图：G^m(i,j) ∝ exp(-||(i,j) - u^{m,grid}||² / (2σ²))

先验损失：L_prior = -1/|V| · Σ_{m∈V} Σ_{i,j} G^m(i,j) · log(A̅^m(i,j) + ε)

总损失：L = L_policy + λ(k) · L_prior

其中 λ(k) 从 λ_0 线性衰减到 0（5000 步后完全移除）
```

> 符号与论文保持一致。FiLM = Feature-wise Linear Modulation（特征级线性调制），傅里叶位置编码频率带数 B 论文未明确给出具体值。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：

- 单视角 76×76 RGB 图像，ResNet-18 取 L2 层（10×10 特征图，C=128 通道）
- N = 100 个空间 patch，query 维度 d = 256，S = 2 步精炼

**Step 0 — 初始化 query**：

```
z_0 = [0.1, -0.3, 0.5, ...]  (可学习 token, 256-d)
p = [0.2, -0.1, 0.8, 0.0]    (eef_x, eef_y, eef_z, grip_open)

γ(p) = W_γ · p = [0.05, -0.02, 0.08, ...]
β(p) = W_β · p = [0.1, 0.05, -0.03, ...]

q_0 = (1 + γ) ⊙ z_0 + β
    ≈ [0.1·1.05+0.1, -0.3·0.98+0.05, 0.5·1.08-0.03, ...]
    ≈ [0.205, -0.244, 0.514, ...]
```

**Step 1 — 第一次交叉注意力**：

```
Q = q_0 · W_Q → R^{1×64}
K = X · W_K → R^{100×64}    (100 个 patch)
V = X · W_V → R^{100×64}

A = softmax(d^{-1/2} · QK^T) → R^{1×100}

假设注意力集中在 (row=3..5, col=4..6) 区域（对应图像中物体接触点）：
A ≈ [0.001, 0.002, ..., 0.08, 0.12, 0.15, 0.12, 0.08, ..., 0.001]
    ↑ 背景          ↑ 高注意力区域        ↑ 背景

c_0 = Mean_h(A · V) → R^{64}（加权聚合的局部特征）
```

**Step 2 — Query 精炼**：

```
c_0 经过 LayerNorm 后，通过 FiLM 更新 q_0：
q_1 = FiLM(LN(c_0), q_0)

精炼后，query 从"机器人说我要抓那个物体"
     变为"我看到了物体，我的注意力应该聚焦在接触点附近"

第二次交叉注意力：
A' 的注意力峰值更尖锐（例如集中在 3×3 区域），背景权重进一步下降

c_1 = Mean_h(A' · V) → 最终视觉表征 z_t
```

**Step 3 — 策略头**：

```
â_t = π_θ(z_t=c_1, p_t)

假设 Diffusion Policy：z_t 作为条件注入去噪网络，
输出 8 步动作 chunk（末端执行器 6-DoF + 夹爪）。
```

**关键观察**：整个过程中没有任何硬裁剪——注意力权重 `A` 是一个软掩码，自然地对所有 100 个 patch 加权，但高权重集中在控制相关区域。这就是"隐式裁剪"的含义。

## 4. 工程视角 (Engineering View)

| 工程维度 | FocusPool | 含义 |
|----------|-----------|------|
| 可训练参数量 | 5.8% of ResNet-18 | 仅训练 FiLM 层 + 交叉注意力投影层；编码器冻结 |
| 推理延迟增加 | 每步 S 次交叉注意力 | S=2 时约增加 2 次 QKV 投影 + softmax，对 10×10 patch 矩阵运算量很小 |
| 内存占用 | 中间层特征 F^l 需保留 | L2 特征图 10×10×128 ≈ 12.8KB/视图，可忽略 |
| 训练稳定性 | 早期正则化 λ_0=2×10^{-4}，5000 步衰减 | 防止初始化敏感导致注意力发散；主要提升 mean success 6.5 个百分点 |
| 部署约束 | 需要实时本体状态 p_t | 所有视觉运动策略的通用要求，非额外约束 |
| 与策略头解耦 | 输出紧凑向量 z_t，可接 Diffusion / Flow Matching | 即插即用，不绑定特定策略架构 |
| 多视角扩展 | 每视图独立池化后拼接/平均 | 论文使用固定第三人称 + 眼在手相机双视角 |

**工程含义**：FocusPool 的核心优势是"轻量级改造"——编码器完全冻结，只训练一个小型注意力池化模块。这意味着：
1. 可以在预训练视觉编码器上即插即用，不需要重新训练整个编码器
2. 推理时不增加输入预处理管线（对比 RVT-2 需要两阶段裁剪）
3. 训练数据效率提升 2 倍（一半数据达到基线性能），直接降低数据采集成本

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

- **小物体高精度操作**：Giraffe Build 上成功率从 20-35% 提升到 65-70%（Table 4），因为局部关注能捕捉稀疏的控制信号
- **低数据效率场景**：100 demo 预算下平均提升 36.2%，50 demo 时优势更大（Fig. 3）
- **复杂视觉背景**：Table Cleanup 中空间 Softmax 产生噪声关键点，FocusPool 保持选择性注意力掩码（Fig. 6c）
- **正则化目标偏移时自适应**：Coffee Transport 中正则化目标（关键帧末端执行器位置）与实际控制相关区域（勺尖）不重合，FocusPool 在端到端训练中自行修正焦点
- **跨编码器泛化**：在 ViT-S + DINOv3 预训练上也优于 [CLS] token 和 AFA（Table 5）

### 不能做什么 / 局限

- **对 ImageNet 预训练有依赖**：无预训练时性能下降（Fig. 5a），因为中间层特征需要预训练的低级视觉先验（边缘检测器等）
- **正则化目标完全错误时可能受影响**：虽然有一定鲁棒性，但如果关键帧位姿误差过大（>16.7% 工作空间），注意力收敛可能变慢
- **ViT 适配尚不成熟**：Table 5 中 ViT 实验是初步探索，最优读取层、预训练选择等未系统研究
- **仅 ResNet-18 系统分析**：更深 ResNet、EfficientNet 等 backbone 的中间层特性未探索
- **单机器人平台验证**：真实实验仅在 UFactory xArm 7 上完成，未验证移动机器人、双臂或人形平台

### 6.1 隐含假设 (Hidden Assumptions)

| 隐含假设 | 说明 | 风险 |
|----------|------|------|
| 本体状态包含足够的任务上下文 | FiLM 调制依赖 `p = [o_eef, o_grip]` | 如果状态信息不足以区分任务阶段（如两个相似位姿对应不同子任务），query 可能歧义 |
| 中间层特征在所有任务中都保留足够局部性 | 选择 L2 作为默认读取层 | 对于需要更高级语义理解的任务（如"找到红色物体"），L2 可能语义不足 |
| 傅里叶位置编码足以编码空间信息 | 使用正弦/余弦位置编码 | 未与可学习位置编码或其他空间编码方式对比 |
| 单 query 足够 | 只用一个可学习 token | 如果任务需要同时关注多个空间区域（如双手操作），单 query 可能不够 |
| 早期正则化先验足够"弱" | λ_0 = 2×10^{-4} 很小 | 在空间变化极小的任务中，即使很小的先验也可能引导注意力偏向错误区域 |
