💡 **X-Ray 开场**

扩散策略（Diffusion Policy）是当前 VLA 具身智能中最主流的 visuomotor 策略之一，但它有一个隐藏假设：所有动作都可以用单一坐标系来表示。这篇论文指出这个假设在双臂移动操作中是不成立的——同一个动作在末端执行器坐标系下可能很简单，但在基座坐标系下可能很复杂，反之亦然。MoF 的核心想法是：与其让设计师手动选择最优帧，不如让策略在每个去噪步骤中同时从多个帧的专家那里获取噪声预测，然后融合。


## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 维度 | 标准 Diffusion Policy | MoE-DP | MoF (本文) |
|------|----------------------|--------|------------|
| 动作帧 | 单一固定帧 | 单一固定帧 | 多帧并行（左/右末端/基座/相对轨迹） |
| 去噪位置 | 单帧内 | 单帧内 | 每个专家在自己的帧内去噪，然后在规范帧融合 |
| 融合方式 | N/A | conditioning 路径的 MoE | 每步去噪后在规范帧加权融合噪声预测 |
| 动作表示 | 行向量 6D 旋转 | 行向量 6D 旋转 | 列向量 6D 旋转（支持无正交化变换） |
| 推理延迟 | 1× denoiser | 1× denoiser + MoE routing | 4× denoisers 并行 + fusion |
| 训练目标 | 单帧噪声 MSE | 单帧噪声 MSE | 融合后噪声 MSE（同标准 DP） |
| 适用场景 | 通用 | 行为多样性高的任务 | 双臂移动操作（帧需求随任务阶段变化） |

### 1.2 关键机制 (Key Mechanism)

MoF 的核心流程在每个去噪步骤 k 中：

1. **规范帧状态**: 维护一个规范帧 $F_c$ 中的噪声动作样本 $x_c^k$
2. **帧变换**: 将 x_c^k 变换到每个专家帧 Fm，得到 m_T_c(x_c^k)
3. **专家去噪**: 每个帧专家 $\varepsilon_m^\theta$ 在自己的帧中预测噪声
4. **噪声回变换**: 将预测噪声变换回规范帧 c_T_m(ε_m^θ(...))
5. **加权融合**: 按权重 $w_m$ 融合所有噪声预测，得到 $\varepsilon^c$
6. **标准 DDIM 更新**: 用 $\varepsilon^c$ 执行标准去噪步骤  

⚡ **Eureka Moment**：与其让策略在一个帧里学习所有动作分布的复杂性，不如让每个帧的专家只学习自己帧中最简单的分布，然后在规范帧中融合——因为"同一个动作在不同坐标系下的分布复杂度可以完全不同"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
ε^c = Σ_{Fm∈F} w_m · c_T_m( ε_m^θ( m_T_c(x_c^k), o, k ) )
```

**目标**: 在规范帧中融合多个帧专家的噪声预测，使融合后的预测尽可能接近真实噪声 $\varepsilon_c$。  

**训练损失**:

```
L_mix(θ) = E_{k, ε_c, o} [ || ε_c - Σ_{Fm∈F} w_m · c_T_m( ε_m^θ( m_T_c(x_c^k), o, k ) ) ||^2 ]
```

**变量说明**:

| 符号 | 含义 |
|------|------|
| $x_c^k$   | 规范帧 Fc 中第 k 步的噪声动作样本 |
| $\varepsilon_c$   | 添加到 $x_c^0$ 的原始高斯噪声   |
| $\varepsilon_m^\theta$   | 帧 Fm 的专家 denoiser（参数 $\theta$）   |
| m_T_c(·) | 将规范帧动作变换到专家帧 Fm 的算子 |
| c_T_m(·) | 将专家帧噪声向量变换回规范帧的算子 |
| w_m | 帧专家权重，Σ w_m = 1 |
| o = (I, q) | 观测：RGB 图像 I + 本体感知 q |
| k | 扩散步骤索引 |

**直觉**: 标准扩散策略只有一个 denoiser 在固定帧中预测噪声。MoF 相当于在同一个扩散轨迹上，让 4 个专家从不同"视角"看同一个噪声样本，各自给出最优噪声估计，然后加权平均。列向量旋转表示是关键——它允许在噪声动作（不在 SO(3) 流形上）上直接做帧变换，而不需要正交化投影。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的双臂操作场景：

- **规范帧**: 左末端执行器帧
- **专家帧**: 左帧、右帧、基座帧（3 个专家）
- **动作维度**: 每臂 7 维（3 位置 + 2 列向量 + 1 夹爪），双臂共 14 维
- **扩散步骤**: K=10，当前 k=5

**步骤 1**: 规范帧中的噪声动作 $x_c^5 \in \mathbb{R}^{14}$  

```
x_c^5 = [p_c; c_c^1; c_c^2; g]_left  ⊕  [T_left→right · (p; c^1; c^2; g)]_right
```

**步骤 2**: 变换到各专家帧

```
左帧专家: x_left = x_c^5  (规范帧=左帧，恒等变换)
右帧专家: x_right = T_left→right(x_c^5)  (应用 SE(3) 变换)
基座帧专家: x_base = T_left→base(x_c^5)  (应用 SE(3) 变换)
```

列向量旋转的关键优势：即使 $x_c^5$ 中的 $c_c^1, c_c^2$ 不是正交的（因为有噪声），变换 $c_m^i = R \cdot c_c^i$ 仍然良定义——只是 3D 向量的矩阵乘法。  

**步骤 3**: 各专家预测噪声

```
ε_left^θ(x_left, o, 5) = [0.12, -0.03, 0.08, ...]  (在左帧中)
ε_right^θ(x_right, o, 5) = [0.10, -0.05, 0.07, ...]  (在右帧中)
ε_base^θ(x_base, o, 5) = [0.11, -0.04, 0.09, ...]  (在基座帧中)
```

**步骤 4**: 噪声回变换 + 融合（假设 w = [0.4, 0.3, 0.3]）

```
ε^c = 0.4 · ε_left + 0.3 · T_right→base(ε_right) + 0.3 · T_base→base(ε_base)
    = [0.11, -0.04, 0.08, ...]  (融合后)
```

**步骤 5**: DDIM 更新

```
x_c^4 = DDIM_Update(x_c^5, ε^c, k=5)
```

重复直到 k=0，得到去噪后的动作。

## 4. 工程视角 (Engineering View)

| 工程维度 | 标准 DP | MoF | 影响 |
|----------|---------|-----|------|
| 推理吞吐量 | 1× forward   | 4× forward   | 推理延迟增加 $\sim 4\times$（但可并行）   |
| 显存占用 | 1× model | 4× model | 显存增加 $\sim 4\times$（4 个 denoiser 参数） |
| 训练时间 | 1 epoch | $4\times$ forward + $1\times$ loss | 训练时间增加 $\sim 3\text{--}4\times$ |
| 步数/延迟 | 10 步 DDIM | 10 步 DDIM $\times 4$ 专家 | 每步延迟增加，但步数不变 |
| 量化误差 | 标准 | 列向量旋转无正交化 | 列向量表示避免了正交化引入的非线性失真 |
| 部署约束 | 单 GPU | 多 GPU 或大显存单 GPU | 需要 4 个 denoiser 同时驻留 |
| 并行化潜力 | 低 | 高（4 专家可并行） | GPU 上 $4$ 专家 batch forward 可接近 $1\times$ 延迟 |

**工程含义**: MoF 的主要工程代价是推理和训练时的 $4\times$ 模型前向传播。但在 GPU 上，$4$ 个专家的 forward 可以 batch 在一起，实际延迟增加远低于 $4\times$。列向量旋转表示是一个轻量级改动——只是改变了存储顺序和变换方式，不增加计算量。

### 6.1 隐含假设 (Hidden Assumptions)

1. **帧集合已知且充分**: 假设设计师能预先定义一组覆盖任务需求的帧（左/右/基座/相对轨迹）。如果最优帧不在这个集合中，MoF 也无法利用。
2. **本体感知精确**: 帧变换依赖精确的 proprioception（关节角度、连杆长度）。在真实机器人上，标定误差会直接影响变换精度。
3. **列向量噪声不会累积误差**: 列向量表示允许噪声旋转列直接变换，但长期扩散过程中，这些噪声列可能偏离有效旋转空间很远，影响 denoiser 的学习。论文未分析这个效应。
4. **权重和为 1 的线性融合足够**: 线性加权融合可能不足以处理多模态动作分布中的复杂交互。

**面试 Tip**: 当被问到"MoF 和 MoE 的区别"时，回答："MoE-DP 在 conditioning 路径使用 MoE，但去噪仍在单一帧中进行；MoF 在去噪过程本身使用多帧并行，每个专家在自己的帧中预测噪声，然后在规范帧中融合。这是'条件多样性'和'动作空间多样性'的本质区别。"
