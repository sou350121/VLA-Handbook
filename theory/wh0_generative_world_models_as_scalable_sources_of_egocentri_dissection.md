### 1.2 关键机制

Wh0 的核心创新在于**将世界模型定位为「可控数据生成引擎」而非「环境动力学模拟器」**。具体来说：

- **场景对齐**：从机器人工作空间拍摄背景照片，用图像编辑插入目标物体，确保生成的视频视角、分辨率、尺度与策略输入一致
- **身体形态对齐**：将生成视频中的人类手替换为机器人手外观，让策略学习动作语义而非执行者身份
- **双 Agent 指令生成**：Agent 1 持续发现新物体名词和属性形容词；Agent 2 优先采样低频词，确保词汇覆盖的「广度 + 深度」平衡
- **混合训练比例**：每 batch 中 28% 遥操作数据 + 68% WM-H 合成数据 + 4% 身体形态编辑帧——对稀缺的机器人数据过采样

⚡ **Eureka Moment**：世界模型不需要精确模拟机器人动力学——它只需要生成视觉上多样化、场景对齐的人类手部操作视频，然后通过视觉编辑和统一动作空间，让预训练的 VLA 模型「解锁」已有的灵巧操作能力。

## 2. 数学核心

### 📌 Napkin Formula

```
L_total = L_MSE + λ_align · L_EA + λ_teleop · L_teleop
```

核心思想：在统一 MANO 动作空间上，用扩散模型的噪声预测损失 + 身体形态编辑帧的辅助损失 + 遥操作数据的部署约束损失，三者联合优化。

### 目标函数

扩散动作解码器的训练目标是标准噪声预测 MSE 损失：

```
L_MSE = E_[ε~N(0,I), i] [ ||ε_hat_i - ε||_2^2 ]
```

其中 ε_hat_i 是扩散步 i 的预测噪声。

### 动作空间定义

动作在相机坐标系下定义为：

```
a_t = [Δt^l, Δr^l, θ_h^l, Δt^r, Δr^r, θ_h^r] ∈ R^102
```

| 符号 | 维度 | 含义 |
|------|------|------|
| Δt | R^3 | 连续帧之间手腕相对平移 |
| Δr | R^3 | 连续帧之间手腕相对旋转（欧拉角） |
| θ_h | R^(15×3) | 15-DoF MANO 手部模型的关节旋转 |
| l, r | — | 左手/右手标记（本文聚焦右手操作） |

> 符号与本文/相关文档保持一致：采用 VITRA 的 MANO 统一动作空间设计，将机器人关节 retarget 到 MANO 参数空间，复用 VITRA 从大规模人类视频预计算的归一化参数。

### 直觉

关键在于**统一动作空间**——无论是人类手部视频还是机器人遥操作数据，都被映射到同一个 MANO 参数空间。这避免了用有限机器人数据从头学习归一化参数，保持了机器人动作与人类动作空间的对齐。

## 3. 带数字走一遍：玩具例子

假设我们有一个简单的「抓取红色方块」任务：

**步骤 1 — 指令生成**
- Agent 1 发现 noun: "block", adj: "red"
- Agent 2 组合指令: "pick the red block"

**步骤 2 — 视频合成**
- 场景拍照：机器人工作空间背景，手作为尺度锚点
- Qwen-Image-Edit 插入红色方块到首帧
- Wan-I2V 生成 8 帧视频：手从空闲 → 接近 → 抓取

**步骤 3 — 运动提取**
- HaWoR 对每帧回归 MANO 参数：
  - 帧 1: θ_h = [0, 0, ..., 0]（张开）
  - 帧 5: θ_h = [0.3, -0.2, ..., 0.1]（半握）
  - 帧 8: θ_h = [0.5, -0.4, ..., 0.2]（紧握）

**步骤 4 — 训练**
- 扩散解码器接收当前观察 + 指令 + 当前手部状态
- 加噪声到目标动作 a_t
- 预测噪声 ε_hat，计算 MSE 损失
- 梯度更新（视觉编码器冻结）

**步骤 5 — 推理**
- 部署时看到红色方块 + 收到 "pick the red block" 指令
- 扩散解码器去噪 4 步（LightX2V 加速）
- 输出 8 帧手部动作序列 → 执行

## 4. 工程视角

| 维度 | 数值 | 工程含义 |
|------|------|----------|
| 视频生成成本 | 5.44 GPU-hrs / 1k 视频 | 50k 视频约 272 GPU-hours（约 11 天单卡 A100） |
| 视频生成步数 | 4 步（LightX2V LoRA） | 相比原始步数减少 ~4×，但可能牺牲质量 |
| 训练数据规模 | 50k WM-H + 400 teleop | 125:1 比例，遥操作数据每样本被采样 312 次 |
| 学习率 | 1e-5 | 较小的 LR，适合微调而非从头训练 |
| VLM weight decay | 0.10 | 标准正则化强度 |
| 动作维度 | 102 | 双手各 51 维（3 平移 + 3 旋转 + 45 MANO 关节） |
| 评估任务数 | 18 | 覆盖抓取、放置、工具使用，20 次/任务 |

**部署约束**：
- 视觉编码器冻结 → 推理时只需运行扩散解码器，延迟可控
- 需要头载第一人称相机（与训练时视角一致）
- 机器人手外观需与编辑帧中的外观匹配（否则 embodiment gap 重现）

### 6.1 隐含假设 (Hidden Assumptions)

1. **HaWoR 手部重建足够准确**：合成视频中的手部姿态质量直接决定训练信号质量，但论文未量化重建误差
2. **Qwen-Image-Edit 编辑不引入伪影**：机器人手替换后，手部-物体接触关系可能微妙变化，影响动作语义
3. **Wan-I2V 生成的手部运动物理合理**：视频生成模型不一定遵循真实物理约束（如穿透、滑动）
4. **MANO 足以表示 Inspire 灵巧手**：MANO 是 15-DoF 人手模型，Inspire 手可能有不同自由度配置
5. **冻结视觉编码器不会丢失关键特征**：冻结可能保留预训练先验，但也可能限制对新场景的适应
