## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练/推理差异 |
|------|------|------|-----------|---------------|
| Stage I: 状态合成 | 单张闭合图像 $I_0$ | 合成打开状态图像 $\hat{I}_1$ | 一次性前向 | 训练时用真实配对数据，推理时自主生成 |
| Stage II: 关节估计 | $(I_0, \hat{I}_1)$ 双状态图像对 | 关节参数集合 {类型，轴，原点，范围} | 一次性集合预测 | 训练用监督关节标注，推理无标注 |
| Stage III: 状态合成 | $I_0$ + 估计关节参数 | 任意中间状态图像 | 条件生成 | 下游能力，非核心目标 |

### 1.2 关键机制 (Key Mechanism)

**核心洞察**：现有方法陷入"先验依赖悖论"——合成模型需要部件引导才能生成可动状态，但关节预测器又需要这些部件信息。DailyArt 打破循环的方式是：
1. 合成时不依赖任何部件级引导，直接生成"最大打开状态"
2. 从双状态差异中提取运动线索，而非直接从单图像回归
3. 用集合预测 (set prediction) 同时恢复所有关节，无需预设关节数量

⚡ **Eureka Moment**：与其直接从遮挡严重的闭合图像回归关节（病态问题），不如先合成一个能暴露运动线索的打开状态，把"单图像推理"转化为"双状态对比估计"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
joints = f_discrepancy( I₀, G(I₀) )
```

其中 G 是合成网络，f_discrepancy 是从双状态差异推断关节的函数。

**问题形式化**：

```
给定：单张闭合状态图像 I₀ ∈ R^(H×W×3)
目标：估计关节参数集合 J = {j₁, j₂, ..., jₙ}
其中每个关节 jᵢ = (typeᵢ, axisᵢ, originᵢ, rangeᵢ)
  - typeᵢ ∈ {revolute, prismatic}  (旋转/平移关节)
  - axisᵢ ∈ R³  (单位向量，关节轴方向)
  - originᵢ ∈ R³  (关节原点，物体坐标系)
  - rangeᵢ = [minᵢ, maxᵢ] ⊂ R  (运动范围)
```

**合成阶段**：

```
Î₁ = G(I₀; θ_syn)
G 学习映射：闭合状态 → 最大打开状态
训练目标：min_θ_syn L_syn(G(I₀), I₁_real)  (当有配对数据时)
```

**关节估计阶段**：

```
J = F(Φ(I₀), Φ(Î₁); θ_joint)
Φ 是 3D 提升网络，将图像映射到密集点云
F 是集合预测器，输出不定长关节集合
训练目标：min_θ_joint L_match(J_pred, J_gt)  (Hungarian matching)
```

> 符号说明：本文使用物体中心世界坐标系 (object-centered world coordinates)，关节参数在归一化空间 $[-1, 1]^3$ 内表示。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设输入是一张"关闭的笔记本电脑"图像 $I_0$：

**Step 1 - 合成打开状态**：
```
I₀ = [笔记本闭合的 RGB 图像，256×256]
Î₁ = G(I₀) = [合成的笔记本打开 180° 图像，同一视角]
```

**Step 2 - 3D 提升**：
```
Φ(I₀) → P₀ ∈ R^(H×W×3)  (闭合状态的密集点云)
Φ(Î₁) → P̂₁ ∈ R^(H×W×3)  (打开状态的密集点云)
```

**Step 3 - 差异分析**：
```
屏幕区域在 P₀ 和 P̂₁ 中有显著位移
键盘区域基本不变
→ 推断存在一个旋转关节，轴沿屏幕底部边缘
```

**Step 4 - 集合预测输出**：
```
J = {
  j₁: type=revolute, 
      axis≈(1, 0, 0),  // 沿 x 轴
      origin≈(0, -0.3, 0),  // 屏幕底部中心
      range=[0°, 180°]
}
```

**Step 5 - 验证**：
```
用估计的 J 作为条件，生成中间状态 t=0.5：
I₀.₅ = H(I₀, J, t=0.5)
→ 应生成笔记本打开 90° 的图像
```

## 4. 工程视角 (Engineering View)

| 工程考量 | 细节 | 含义 |
|----------|------|------|
| 推理延迟 | 三阶段串行：合成 → 3D 提升 → 关节预测 | 无法实时，适合离线建库或预计算 |
| 内存占用 | 需要存储双状态 3D 点图 $(H \times W \times 3 \times 2)$ | $256 \times 256$ 输入约 $0.8\,\text{MB}/$状态，可接受 |
| 训练数据 | 需要 $(I_0, I_1, J_{\text{gt}})$ 三元组 | 数据收集成本高，可能限制泛化 |
| 合成质量敏感性 | 关节估计精度直接依赖 $\hat{I}_1$ 的真实性 | 合成失败会导致关节估计完全错误 |
| 部署约束 | 无需多视角/多状态输入，单 RGB 即可 | 适合真实机器人场景，但需 GPU 推理 |

**关键 trade-off**：
- 用合成质量换先验依赖：不需要外部标注，但合成网络必须足够强
- 用计算成本换输入简洁性：推理时需跑三个网络，但输入接口极简（单图像）

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- ✅ 从单张闭合状态 RGB 图像推断关节参数（类型/轴/原点/范围）
- ✅ 无需部件标注、多视角、或检索库
- ✅ 支持条件生成任意中间状态图像
- ✅ 处理训练分布内的常见articulated objects（门、抽屉、笔记本等）

### 不能做什么
- ❌ 无法处理训练未见过的物体类别（泛化能力待验证）
- ❌ 合成失败时关节估计会完全错误（无 fallback 机制）
- ❌ 无法处理多物体场景（假设单物体输入）
- ❌ 实时性不足（三阶段串行推理）
- ❌ 无法推断非刚性变形或复杂多关节耦合

### 6.1 隐含假设 (Hidden Assumptions)

| 假设 | 是否验证 | 风险 |
|------|----------|------|
| 合成网络能生成物理合理的打开状态 | 部分验证（视觉质量） | 合成伪影会导致关节估计偏差 |
| 双状态差异足够暴露所有关节线索 | 未系统验证 | 某些关节可能在打开状态仍被遮挡 |
| 集合预测能处理可变数量关节 | 标准做法 | 关节数量过多时可能漏检 |
| 3D 提升网络在单视图下足够准确 | 依赖先验深度模型 | 深度模糊会影响关节原点定位 |

**X-Ray 批判**：论文声称"无需先验"，但合成网络本身隐式编码了物体类别先验（训练数据分布）。对分布外物体的"零先验"声明需谨慎解读。
