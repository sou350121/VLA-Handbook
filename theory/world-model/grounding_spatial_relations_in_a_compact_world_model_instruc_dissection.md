## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

论文以 PrismWM 为基座模型，通过五个变体构建"模型阶梯"来系统性地诊断问题：

### 1.2 关键机制 (Key Mechanism)

**为什么目标条件动力学会泄漏？**

核心机制可以用一个直觉来概括：当指令直接命名了被评分的关系时（如"把红块放在蓝块**左边**"），预测器发现从指令中"抄答案"比从视觉中推理要容易得多。模型学会了将指令中的关系词（left/right/above/below）直接转录为锚点坐标，而不是真正理解场景中的空间关系。

**为什么显式锚点还不够？**

显式参考锚点的初衷是给关系一个"地方存放"——全局潜变量 z 是纠缠的，而锚点 p 是显式的、度量的。但锚点是否真正编码了关系，取决于模型是否被**强迫**从感知中推断它。如果目标 g 进入了预测器，模型可以绕过感知，直接从 g 中复制答案。

⚡ **Eureka Moment**：指令泄漏发生的条件是"被评分的量可以从指令中转录"（指令命名了答案），且这一现象本质上独立于非指令输入（动作、状态）的预测能力——即使动作信息完美，模型仍然会泄漏。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
Leakage = Acc(predicted_anchor | goal_given) - Acc(predicted_anchor | goal_withheld)
```

当 Leakage ≈ 0.63（0.90 - 0.27）时，"grounding" 是转录而非感知。

**目标**：学习一个世界模型，其预测的锚点能真实编码场景中的空间关系，而不是从指令中复制。

**核心方程**（JEPA 预测损失 + 锚点损失 + 目标损失）：

```
L_total = L_JEPA(z, z') + λ_reg·R(z) + λ_anchor·L_anchor(p, p') + λ_goal·L_goal(g)
```

其中：
- `L_JEPA`：下一步潜变量预测的均方误差（JEPA 核心目标）
- `R(z)`：JEPA 正则化项（防止塌缩）
- `L_anchor`：锚点原始损失（预测锚点与真实锚点的距离）
- `L_goal`：目标一致性损失（GoalDyn 变体中训练预测器匹配目标）

**变量说明**：

| 符号 | 含义 | 维度 |
|------|------|------|
| z | 全局 JEPA 潜变量 | 论文未明确给出 |
| p | 显式度量锚点（target + anchor 各一个 2D 坐标） | R^{2×2} |
| g | 语言目标嵌入 | 论文未明确给出 |
| a | 2D 动作（推的方向和力度） | R^2 |
| r | 空间关系 ∈ {left, right, above, below} | 4 类 |
| a (歧义度) | 重复 distractor 数量 ∈ {0, 1, 2, 3, 4} | 标量 |

> 符号与本文保持一致：z 为全局潜变量，p 为显式锚点，g 为目标嵌入，a 为动作（上下文区分歧义度）。

**直觉**：在 GoalDyn 中，`L_goal` 项给了预测器一条"捷径"——直接从 g 中推断 p' 的位置，绕过了对 z 和场景的推理。GoalFree 移除了这条捷径，迫使模型通过感知来定位锚点。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 tabletop 场景：4 个彩色形状（2 红圆 + 1 蓝方 + 1 绿三角），关系为"红圆在蓝方**左边**"。

**场景设定**：
- 目标（红圆）：位置 (2, 3)
- 锚点（蓝方）：位置 (5, 3)
- 真实关系：left（目标在锚点左侧）
- 指令："move the red circle to the left of the blue square"

**GoalDyn 的行为（有泄漏）**：

| 条件 | 预测锚点位置 | Readout 关系 | 正确？ |
|------|-------------|-------------|--------|
| 给真实目标 | 目标在锚点左侧 | left | ✅ 正确 |
| 隐藏目标（g=0） | 锚点位置无信息 | 随机 | ❌ 0.27 |
| 反事实目标（"above"） | 目标被预测到锚点上方 | above | ❌ 跟随假指令 |

关键数字：反事实条件下，94.5% 的样本中锚点跟随假指令，仅 2.3% 跟随真实场景。

**GoalFree 的行为（无泄漏）**：

| 条件 | 预测锚点位置 | Readout 关系 | 正确？ |
|------|-------------|-------------|--------|
| 给真实目标 | 目标在锚点左侧（从视觉推断） | left | ✅ 0.88 |
| 隐藏目标 | 目标在锚点左侧（从视觉推断） | left | ✅ 0.88 |
| 反事实目标 | 目标仍在锚点左侧（不受指令影响） | left | ✅ 正确 |

**控制循环中的影响**（8 步 MPC 规划）：

```
GoalDyn（泄漏）:  控制成功率 = 0.047（≈ 随机地板 0.055）
GoalFree（修复）: 控制成功率 = 0.29（恢复到 NoGoal 基线 0.30）
Oracle（真实动力学）: 控制成功率 = 0.71
```

泄漏如何破坏控制？预测器在 rollout 中产生错误的锚点位置 → 规划器基于错误的位置计算代价 → 选择的动作无法实现目标关系。

## 4. 工程视角 (Engineering View)

**架构改动成本**：极低。GoalFree 相比 GoalDyn 的唯一区别是从预测器输入中移除目标 g。不需要新增模块、不需要改变损失函数结构。

**推理延迟**：GoalFree 与 GoalDyn 推理延迟相同（少一个输入 embedding，但 Transformer 的注意力计算不变）。

**训练开销**：论文未给出具体训练时间，但所有模型都是"每个歧义度单独训练"（per-ambiguity training），计算量相同。

**内存/参数**：预测器参数量不变，只是输入维度减少（去掉 g 的 embedding 维度）。

**部署约束**：
- GoalFree 的 grounding 是"窄泛化"的——在训练歧义度上表现好，但跨歧义度测试时跌至随机水平（0.26-0.33）。这意味着部署时需要确保测试场景的歧义度与训练时匹配。
- 控制成功率（0.29）远低于 oracle（0.71），瓶颈在动力学保真度（单步预测器在多步 rollout 中漂移），而非表征。

**工程含义**：
- 如果你的世界模型使用语言条件预测器（如 FiLM 注入），且指令命名了被评估的关系，你的关系 readout 指标可能是假的。
- 修复方案可以在不改变现有架构的前提下应用——只需切断 goal→predictor 的连接。
- 但修复后控制性能不会"提升"，只是"恢复"到最简单的无目标基线。真正的控制增益需要解决动力学保真度问题。

### 能做什么

| 能力 | 条件 | 性能 |
|------|------|------|
| 真实关系 grounding | GoalFree + 监督读路径 + 低/中歧义度 | 0.83-0.88 |
| 跨环境泄漏检测 | BabyAI / Language-Table | 1.00 转录 / 0.00 无泄漏 |
| 恢复控制到无目标基线 | GoalFree | 0.29 ≈ NoGoal 0.30 |

### 不能做什么

| 失败模式 | 场景 | 原因 |
|----------|------|------|
| 高歧义度下 grounding 崩溃 | a=4（所有 distractor 重复） | 0.31（≈ 随机）；监督锚点 latch 到分布特定线索 |
| 跨歧义度泛化 | a=2 训练的模型测试 a=0 | 0.26-0.33（≈ 随机）；窄泛化 |
| 超越无目标基线 | 任何变体 | 修复的价值在感知，不在控制增益 |
| 接近 oracle 性能 | 所有变体 vs oracle 0.71 | 动力学保真度瓶颈（单步预测器多步漂移） |

### 6.1 隐含假设 (Hidden Assumptions)

1. **渲染分布稳定性假设**：泄漏检测必须在训练渲染分布上运行。作者发现新生成的场景会显著低估监督编码器的表现。这意味着实际部署时，如果渲染风格有域偏移，grounding 性能可能不可靠。

2. **锚点槽位约定假设**：几何 readout 假设锚点遵循"监督槽位约定"（slot 0 = 目标，slot 1 = 锚点）。无监督学习的锚点无法用此 readout 公平评估——这意味着显式监督锚点和隐式学习锚点之间没有直接的性能对比。

3. **单步预测充分性假设**：论文训练单步预测器，但控制在多步 rollout 中评估。作者承认这是动力学保真度瓶颈的根源，但未在多步预测上实验。

4. **2D 确定性运动学假设**：tabletop 使用确定性步进器运动学。真实机器人的物理（摩擦、滑动、不确定性）不在考虑范围内。
