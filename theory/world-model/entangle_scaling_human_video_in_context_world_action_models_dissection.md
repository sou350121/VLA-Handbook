## 1. 核心架构/方法总览 (Overview / Architecture)

Entangle 的一句话结构：**人类视频与机器人视频用同一个 3D VAE 编码，沿时间轴拼接成一条 token 流；动作 token 以"机器人视频段起点"为时间锚点做 RoPE；世界–动作 DiT 用 MoT 保持视频/动作两路独立参数，只让动作 query 看视频 key。**

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练 vs 推理差异 |
|------|------|------|-----------|------------------|
| 人类上下文编码 | 人类演示视频 V^ctx，K 帧 | 3D VAE latent，F_c 个时间帧 | 真机 13 帧 @ 5 Hz，跨度 2.4 s（§12.3） | 两者均为"干净"输入（σ_v = 0），不加噪 |
| 当前机器人观测 | 头部 + 左腕 + 右腕 RGB，I_t | latent + 加性相机视角嵌入 | 每次重规划取最新一帧组 | 仅第一个 robot-video latent 时间位被当前观测条件化，其余从噪声初始化（§12.3） |
| 未来视频预测 | 噪声 + 上下文 | 未来机器人视频 V = (I_{t+1}, …, I_{t+T_v}) | 与动作联合去噪 | 正文未给 T_v 的具体数值 |

### 1.2 关键机制 (Key Mechanism)

**（1）为什么必须"严格配对"，而不是任务级配对。** 若人类视频与机器人轨迹只按任务标签配对，或由"编辑首帧 + 文生视频"生成（论文把 Zero-WAM 归入这一类），两条轨迹共享高层目标却分叉于运动路径、接触时刻与执行速度。此时模型无法定位"哪段人类画面管哪个动作 chunk"，视频 prompt 退化为粗任务标签。严格配对要求三条同时成立：相机视角与场景布局一致、被操作物体与交互事件顺序一致、每个事件的时刻一致（§3.1）。

**（2）为什么用 video-to-video 而非首帧编辑。** Ent-Syn 的三段式管线是：关键帧手部编辑（gpt-image-2 + HaGRID 手部外观参考，把可见机械臂/夹爪换成人手与前臂，保留场景、物体、视角、接触关系）→ 以**完整源机器人片段**作运动参考、编辑帧作外观参考、原子动作描述作文本条件，用 Seedance 2.5 或 Wan 3.0 生成 → VLM 双重校验（视觉质量 + 与源轨迹的动作时序一致性）。关键在于喂整段源片段作运动参考，无需显式分割掩码、深度图或边缘控制，从而保住时序；这些接受后的 clip 仍沿用原始机器人观测与动作作为监督。

**（3）为什么需要任务内 InfoNCE。** 标准 flow-matching 损失逐条轨迹独立监督。当一个任务存在多条合法执行（不同访问顺序、不同避障路径）时，模型可以靠初始场景推断任务身份、再"语义补全"整件事，而不必跟着当前视频走。InfoNCE 在同一 batch 的同任务样本内做对比：拉近预测的一步干净动作与"当前视频配对的轨迹"，推远同任务的其它执行，使任务身份不再构成捷径。

**（4）为什么变长窗口。** 作者给出的权衡是：整段 episode 作条件会鼓励模型推断全局任务身份、按语义完成任务而非跟随上下文；只用短 clip 又限制时间上下文、损害泛化。折中做法是随机采样 13/25/37 帧（F_c ∈ {4,7,10}）并配同一动作片段，靠式(3)的锚定 RoPE 保证任意窗口长度下动作仍对齐机器人段。

**（5）为什么是"时间偏移"而非"重置"或"空间偏移"。** 三种 RoPE 布局的差别只在于哪一轴被重置/偏移：时间重置共享空间网格 (h,w) 但两段拿到相同 t（时间碰撞）；空间偏移让 (h,w) 不相交却破坏跨段空间对应；本文的时间偏移让 t 不相交、同时共享 (h,w)。表 1 的结果是 69.52% vs 64.76%（时间重置）vs 48.76%（空间偏移），作者将 20.76 分的差距归因于"匹配视角下共享 2D 坐标"这件事被保住了。

**（6）为什么推理时要 AH。** 开环执行整个 chunk 时，越靠后的步越可能失去对人类参照的 grounding，接触与轨迹误差在下一次观测前累积。AH 监控动作 query 对参照 token 的注意力质量与参照内部时间分布的熵：注意力质量低且熵高，说明 grounding 弱且弥散，于是在可靠前缀处截断。

⚡ **Eureka Moment**：让人类视频真正约束动作的，不是"把它塞进模型"，而是**先用时间对齐把每个动作 chunk 钉到一段具体画面上，再用任务内对比防止模型绕过这段画面去抄任务身份的近路**——对齐是监督的前提，对比是防作弊的保险。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L = L_v + λ_a·L_a + λ_NCE·L_InfoNCE
其中 L_InfoNCE 把一步干净动作估计 Â_i 拉向"与当前人类视频配对"的 A_i，推离同任务的其它 A_j
```

**目标**：建模 p_θ(V, A | I_t, V^ctx)，即"给定单个人类演示视频与当前机器人观测，联合预测未来视觉状态与可执行动作"，且在测试时 θ 冻结。

**联合分布与重规划**：

```
p_θ(V, A | I_t, V^ctx),  V = (I_{t+1}, ..., I_{t+T_v}),  A = (a_t, ..., a_{t+T_a-1})
测试时：θ 固定；执行预测动作 prefix，用更新后的观测 + 同一 V^ctx 闭环重规划
```

注意时间下标的差异：视觉从 t+1 开始（当前帧 I_t 是已观测的），动作从 a_t 开始（包含当前时刻）。这是"已观测历史"与"未来预测"的边界，见 §3 的验算。

**条件 flow matching**：

```
X_σ^m = (1 − σ_m)·X_0^m + σ_m·ε^m,   ε^m ~ N(0, I),  σ_m ∈ [0,1],  m ∈ {v, a}
u_θ^m ≈ ε^m − X_0^m
L_m = E[ || u_θ^m − (ε^m − X_0^m) ||²_{M_m} ]
L_WAM = L_v + λ_a·L_a
```

**动作时间 RoPE 锚定**：

```
π_A(k) = F_c + k / ρ
```

k 为动作步索引，ρ 为动作到 latent 的时间比，F_c 为人类上下文的 latent 帧数。把动作位置整体平移 F_c，使得上下文长度变化时动作 token 仍与机器人视频段对齐。

**任务内 InfoNCE**：

```
Â_i = X_i − σ_i·u_{θ,i}^a          # 一步干净动作估计，X_i 为第 i 个加噪动作输入
d(Â_i, A_j) = Â_i 与干净轨迹 A_j 的均方距离
G_i = batch 内与 i 同任务的样本集合（|G_i| ≥ 2）

L_InfoNCE = (1/|B|) · Σ_{i∈B} −log( exp[−d(Â_i, A_i)/τ_NCE]
                                    / Σ_{j∈G_i} exp[−d(Â_i, A_j)/τ_NCE] )

L = L_WAM + λ_NCE · L_InfoNCE
```

**AH 的注意力统计**（第 25 次去噪，0 起；18 个具有直接 V→A 连接的层 × 32 头）：

```
μ_i^{ℓb} = Σ_{r∈R} P_{ir}^{ℓb}                      # 动作 query i 在层 ℓ 头 b 上对参照 token 的总注意力
q_{ig}^{ℓb} = (Σ_{r∈R_g} P_{ir}^{ℓb}) / μ_i^{ℓb}    # 参照内部第 g 个 latent 时间组的相对分布
E_i^{ℓb} = −(Σ_{g=1..G} q_{ig}^{ℓb}·log q_{ig}^{ℓb}) / log G,   G = 4
(m_i, e_i) = (1/(18·32)) · Σ_{ℓ,b} (μ_i^{ℓb}, E_i^{ℓb})
候选条件: m_i < 0.10 且 e_i > 0.86，且同一预测内连续 3 个位置满足
h_k = clip(j, 6, 24)   # j 为第一个满足区间的零基起点；无满足区间则 h_k = 24
```

**上下文时钟**：

```
τ_{k+1} = τ_k + h_k / 10           # h_k 为 10 Hz 下的已下发动作步数
```

**变量说明**：

| 符号 | 含义 | 取值范围/备注 |
|------|------|---------------|
| K | 人类上下文原始帧数 | 推理 13；训练 13/25/37 |
| F_c | 上下文 latent 时间帧数 | {4, 7, 10}，对应上述三种窗口 |
| F_q | 机器人视频 latent 帧数 | 正文未给具体值 |
| T_a | 动作 chunk 长度 | 真机 24 步 |
| ρ | 动作到 latent 的时间比 | 正文未给具体数值 |
| λ_a | 动作损失权重 | 正文未给具体数值 |
| λ_NCE / τ_NCE | InfoNCE 权重 / 温度 | 0.05 / 0.1（表 7） |
| G | 参照内部 latent 时间组数 | 4（13 帧上下文） |
| h_k | 第 k 轮执行前缀长度 | [6, 24] 步 |

> 符号口径：论文中 τ 同时表示 InfoNCE 温度（式 4）与上下文起始时刻（式 5）。本文用 τ_NCE 指温度、τ_k 指上下文时钟，避免混淆。

**直觉**：flow matching 那条式子保证"能重建"，InfoNCE 那条式子保证"重建的是当前视频那一条"。前者是拟合，后者是辨识。作者在 §5.4 的观察也支持这一点：去掉 InfoNCE 后模型漂向"平均路径"，在有多条合法路线的任务上（Avoidance、Mouse）明显退化。

## 3. 带数字走一遍：玩具例子 (Worked Example)

以下三例中，(A) 完全使用论文正文已给出的设置，用于核对定义的内部一致性；(B)(C) 是**假设**数值，只为把公式算一遍，并在文中逐项验算，不代表论文的实验结果。

### (A) 上下文窗口的跨度（论文设置，算术核验）

真机上下文为 13 帧 @ 5 Hz，采样时刻 τ_k + {0, 0.2, …, 2.4} 秒。均匀间隔下，K 个采样帧的首末跨度是 (K−1)×Δt：

```
(13 − 1) × 0.2 s = 2.4 s   ✓ 与论文"spanning 2.4 s from first to last frame"一致
```

这 2.4 s 是**已观测历史**的跨度，不是未来预测区间。接着按式(5)推进：

- 执行 h_k = 10 个动作（10 Hz）→ τ 前进 1.0 s → 下一个窗口 [1.0, 3.4] s。论文正文给出了同一算例 ✓
- 执行 h_k = 6 → 前进 0.6 s → [0.6, 3.0] s
- 执行 h_k = 24 → 前进 2.4 s → [2.4, 4.8] s。论文正文亦给出此例 ✓

另有一处口径提示：真机每次预测 24 步 @ 10 Hz，论文记为 2.4 s。若按"采样点首末跨度"计，首个与末个动作点之间是 (24−1)×0.1 = 2.3 s；2.4 s 对应的是 24 个步长的时间总和。二者不矛盾，但在和"上下文 2.4 s 跨度"并排比较时要注意这是两种口径——**未来动作 chunk 的预测区间不能当作历史上下文或记忆窗口**。

### (B) InfoNCE 的一次计算（假设数值，已验算）

假设某锚点 i：d(Â_i, A_i) = 0.10，同任务两个负样本距离 0.30、0.40，τ_NCE = 0.1。

```
logits: exp(−0.10/0.1)=exp(−1)=0.36788
        exp(−0.30/0.1)=exp(−3)=0.04979
        exp(−0.40/0.1)=exp(−4)=0.01832
分母 = 0.36788 + 0.04979 + 0.01832 = 0.43599
p_pos = 0.36788 / 0.43599 = 0.8438
L = −ln(0.8438) = 0.1698 (nats)
```

若 Â_i 漂向第一个负样本（d_pos = 0.30，d_neg1 = 0.10，d_neg2 = 0.40）：

```
分母 = 0.04979 + 0.36788 + 0.01832 = 0.43599（同一组数换了位置）
p_pos = 0.04979 / 0.43599 = 0.1142
L = −ln(0.1142) = 2.1698 (nats)
```

抄袭同一任务的另一条执行，损失从 0.17 涨到 2.17，约 +2.0 nats。这正是作者想要的方向：任务身份本身不再能降低损失。注意该式用的是均方距离，若动作归一化后量纲较大，d/τ_NCE 会随之放大，τ_NCE = 0.1 是否合适取决于动作统计口径——论文给出的是 0.1，但未报告对该值的敏感性。

### (C) AH 的截断（假设数值，已验算）

假设某次预测中，零基位置 4、5、6 同时满足 m_i < 0.10 且 e_i > 0.86（连续 3 个位置），取 j = 4：

```
h_k = clip(4, 6, 24) = 6
```

于是实际执行 6 步而非 4 步——最小执行长度 6 覆盖了候选起点。论文明确写了这个行为："an interval starting before position 6 therefore still results in six executed actions"。若 j = 20，则 h_k = 20；若无候选区间，h_k = 24。若执行 6 步，则上下文时钟前进 0.6 s，下一窗口 [0.6, 3.0] s，与上一窗口 [0, 2.4] s 重叠 1.8 s——短执行保持完整上下文、并让相邻窗口重叠，这正是作者描述的效应。

## 4. 工程视角 (Engineering View)

**去噪成本是双倍的。** AH 与 no-AH 推理都用 50 次 Euler 更新；每次更新都要评估一个"有参照"分支和一个"无参照"分支（视频用式(11)引导，v_guided = v_no-ref + 5·(v_ref − v_no-ref)；动作流直接取有参照分支，CFG 尺度 1）。因此**一次模型调用 = 100 次去噪前向**。AH 的注意力统计读的是第 25 次更新（0 起）的条件前向，不额外增加前向次数。

**上下文时钟不按墙钟走。** 式(5)只按已下发的动作步数推进，推理、网络与等待延迟都不推进上下文时钟（§12.3 明确写了这一点）。好处是上下文不会因算力波动而漂移；代价是 AH 选短前缀时，单位动作时间内的观测获取与重规划次数上升——论文自己把这条列为 AH 的代价项。真机的 0.6–2.4 s 前缀时长**不含推理延迟，也不是墙钟意义上的重规划周期**。

**"记忆"到底是什么，要逐模型说清楚。**

- Entangle（本文）：每次调用只接收**最新**观测（头 + 双腕）+ **一个局部**人类视频窗口（真机 13 帧 @5 Hz；仿真 13 个连续原始帧）。它没有把自身过去的动作或过去的机器人视频作为滚动记忆送进网络；跨轮次的连续性只由上下文游标 τ_k 维持，而 τ_k 是按已下发动作步数推进的。未执行的动作后缀被直接丢弃，不进入下一轮条件。超出视频末尾时重复最后一帧，不循环播放。
- MotuBrain（初始化 backbone，引文[10]）：本文只说明从它初始化并在 Ent-Dataset 上继续训练，未描述其内部记忆机制，不作转述。
- RoboTTT（引文[67]，作者在 §2.3 提及）：按论文转述，它随机器人 visuomotor history 增长更新 fast weights；Entangle 明确不采用这条路线，部署时权重固定。

**仿真与真机的推进规则不同，不能互换叙述。** 仿真里上下文每轮前进 13 帧（固定），耗尽后重复最后一帧；真机则按 h_k/10 自适应推进。把"13 帧"或"24 步"当成所有实验共有的记忆窗口是错的：13 帧是上下文窗口长度，24 步是动作 chunk 的预测长度，6–24 步是执行前缀长度，三者不同层级。

**模型规模**：24 个 transformer 层、隐藏宽度 4,096、32 个注意力头、55 维统一动作表示；头部/左腕/右腕用加性视角嵌入。参数量、显存占用、端到端延迟：**正文未给出**。

**仿真侧的执行器差异**：客户端把 10 Hz 的源动作率插值到 50 Hz 仿真指令，初始执行 16 条命令、之后 32 条。这一层是评测封装，不属于模型本体。

### 5.3 真机设置（Astribot S1，§5.1、§8、§12.3）

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么（有定量或明确案例支撑）**

- 多步顺序与过程约束：六任务均含多步操作；Avoidance 要求走指定左侧开口，扣分表里"非规定路线"单项扣 30 分（表 4）。
- 由演示确定物体角色与放置顺序：Blocks 要求按左–右–中顺序堆叠（§8.2）。
- 工具重定用途：用杯子扫块入簸箕；Context-OOD 案例中用香蕉扫木块进纸箱（Fig. 6d）。
- 反直觉目标：按演示把笔从笔筒移进簸箕、把刷子放到笔筒上（§8.2）。
- 空桌面复现动作序列：笔与笔筒都不在时，仍保持传递顺序与左右手角色（Fig. 10）。

**不能做什么 / 明显薄弱处**

- 仿真绝对水平并非全面领先：表 1（RoboTwin）中 Entangle 在**打开微波炉（27.33%）**与**杯子放杯垫（74.33%）**两项低于 Zero-WAM（59.00%、84.87%）。作者的解释是任务匹配片段足以支撑短程单阶段动作，而帧级对齐对多步序列更关键——这解释了差距方向，但不改变这两项确实落后的读数。
- 细粒度动作并非全部成功：定性案例里带 InfoNCE 的 policy 腕部旋转更贴近演示，但**未能把布抛出**；不带 InfoNCE 的版本抛布成功却偏离圆形轨迹。另一个案例中，带 InfoNCE 的版本在收臂时布被夹爪勾住。
- 跨场景迁移只有定性证据：Context-OOD 的四类（布局改变、同类别替换、跨类别迁移、功能重定用途）都是案例展示，无量化表。
- 单本体：真机只在一个 Astribot S1 上评测，作者在 §6 明确把"限于单一本体"列为局限。

### 6.1 隐含假设 (Hidden Assumptions)

1. **V2V 生成的人类视频在时序上足以监督细粒度动作。** 这一条由 VLM 校验器把关（等间隔区间中点取帧、源帧与生成帧按同一相对时刻两行对照，检查动作身份、左右手角色、主阶段时序、轨迹、物体状态、无额外操作）。但正文未报告校验器的通过率、误判率或与人工判断的一致性——这是整条数据管线的单点假设。
2. **"VLM 判定时序一致"可以替代精确时间戳对齐。** 严格配对的定义是定性的三条；系统本身不产出逐帧时间对应关系。
3. **上下文时钟与真实执行进度同步。** 式(5)假设同步执行器会完整执行每个前缀后才请求下一次观测；论文明确说这不依赖编码器估计任务进度，也不学习上下文–机器人相位对齐。异步执行或中途打断会让这个假设失效。
4. **仿真与真机的"上下文推进"可分离处理。** 仿真固定每轮前进 13 帧并复用末帧，真机按 h_k/10 推进并复用末帧；两种规则都不构成对模型记忆机制的描述，但容易被误读为"模型的记忆窗口"。
5. **温度与损失权重不需要按动作量纲重调。** λ_NCE = 0.05、τ_NCE = 0.1 在 CT 与 RoboTwin SFT 两个阶段相同（表 7），但正文未给出敏感性分析。
6. **真实机器人评分与仿真成功率可比。** 前者是 0–100 扣分制、每任务 10 次试验；后者是二值成功率、每任务每种子 100 episode × 3 种子。跨设置比较需要额外换算假设。

## 8. 精读建议 (Reading Guide)

- **值得精读原文的人**：
  1. 正在做 video-conditioned VLA / in-context imitation，需要判断"上下文到底该怎么对齐"的研究者——§3.1 与 §4.3 是核心。
  2. 要把类似方法落到真机、需要评估上下文时钟与执行前缀设计的工程师——§12.3 的式(5)、式(6)–(10) 与 §9 的对照实验设置必须看。
  3. 关心 WAM 类模型评测口径的人——§11.2 的成功判据（含 OS/SS/MP/BB/EC/SB 的具体阈值）与 §12.2 的外部基线转引说明，是判断读数可比性的依据。

- **建议章节路径**：先读 §1 与 Fig. 3（建立"上下文–观测–未来–动作"四者的时间关系）→ 再读 §3 与 §4.3（对齐与对比这两件事如何配合）→ 然后读 §5.2/§5.4/§5.5（哪些结论有定量支撑）→ 最后读 §12.3（AH 的完整判据与上下文同步细节）。§2 的相关工作与 §2.3 的 test-time training 对比可以快读，除非你在做 fast-weight 路线。

- **不值得精读的理由**：如果你不做机器人学习、或只关心语言指令 VLA 的规模化预训练，读摘要与表 1、表 2 即可；本文的方法贡献集中在数据对齐与训练目标，对通用 VLA 架构的启示有限。另外，若你需要的是多本体、多场景的定量泛化证据，本文的真机部分（单本体、六任务、每任务 10 次试验）与 Context-OOD 的定性性质，可能不足以支撑你的判断。
