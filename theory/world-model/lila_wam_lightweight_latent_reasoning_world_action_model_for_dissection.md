💡 **X-Ray 开场**

现有世界-动作模型（WAM）要么在像素空间生成未来帧（计算昂贵），要么用多阶段管线构建潜在推理空间（训练复杂）。LiLa-WAM 的核心发现是：未来状态预测和动作生成可以在**同一个紧凑潜在流**中联合塑造——不需要像素解码器，不需要多阶段训练，仅用冻结的 DINOv3 视觉编码器 + 12 层 DiT，就能在单张 24GB GPU 上端到端训练。对 VLA 研究者的含义是：世界模型不一定要重。

📍 **研究全景时间线**

```
[2023] Imagine-then-Act (像素级) → [2024-25] 联合视频-动作 WAM (π0, Motus)
    → [2025] 两阶段 latent WAM (WoG, LaWAM) → [2026-08] LiLa-WAM ← 当前位置
        ↓ 局限: 仅单臂 / VTT 需离线预计算 / 无跨任务泛化测试
```

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 训练/推理差异 |
|------|------|------|---------------|
| **DINOv3 视觉编码器** 𝒱 | 观察图像 o_t (320×240) | 多层 patch features N_p × D | 冻结，不参与梯度更新 |
| **Query Adapter** 𝒜 | Learnable queries Q (N_q=64) + patch features | 压缩视觉潜在 Z_v (64×D) | 可训练，4 层交叉注意力 |
| **Foresight-Aware Action Expert** v_θ | [Z_a; Z_q; c_τ; Z_v] 统一 token 流 | 动作速度 v̂_s + 未来潜在 ẑ_{t+Δ} | 12 层 DiT，8 头，D=768 |
| **Q-Former 解码器** 𝒟 | 未来潜在 ẑ_{t+Δ} | 解码到 DINOv3 patch 特征空间 | **仅训练时**使用，推理时丢弃 |
| **VTT 生成** | 演示首尾帧全局特征 | 每任务 token c_τ (经 MLP 投影) | 离线预计算，推理时直接注入 |

**关键设计差异**：
- 与像素 WAM 相比：不生成像素帧，未来预测在特征空间做（cosine loss）
- 与两阶段 latent WAM 相比：单流端到端，无独立预训练模块
- 与 VLA 相比：无语言编码器，用 VTT 替代文本指令

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **单流联合训练**：动作速度 v̂_s 和未来潜在 ẑ_{t+Δ} 从同一 token 序列读出，梯度同时流入共享表示——未来预测成为塑造潜在空间的辅助目标，而非独立的生成任务。
2. **DINOv3 而非 VLM 骨干**：VLM 骨干大量参数用于语言建模，与精细操作的空间/几何线索关系弱。DINOv3 的密集预训练产生丰富的细粒度视觉特征，更适合控制。
3. **多层特征融合**：取 DINOv3 第 17 层 + 第 21 层拼接——早期层保留空间细节（对象位置、局部几何），后期层偏全局语义。组合后成功率从 48.0%（仅末层）提升到 70.0%。

⚡ **Eureka Moment**：未来状态预测不需要独立的生成模块——把它和动作生成塞进同一个 DiT 流，用共享梯度让潜在空间同时为两个目标服务，就能在保持轻量的同时获得 foresight 的收益。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L = L_fm + λ_ff · L_ff
  = E_x0,s [ ||v̂_s - v*||² ]  +  0.5 · cosine_loss(ẑ_{t+Δ}, z_{t+Δ}^{target})
```

**目标**：在紧凑潜在空间中同时学会"预测未来"和"生成动作"，两者共享表示。

**变量说明**：

| 符号 | 含义 | 维度 |
|------|------|------|
| v̂_s | 预测的 flow-matching 速度 | R^{H×d_a} |
| v* = x_1 - x_0 | 真实速度（ground truth action - 噪声） | R^{H×d_a} |
| ẑ_{t+Δ} | 预测的未来潜在表示 | R^{N_q×D} |
| z_{t+Δ}^{target} | DINOv3 从 o_{t+Δ} 提取的 patch 特征 | R^{N_p×D} |
| λ_ff | 未来损失权重 | 标量 = 0.5 |
| Δ | 前瞻步数 | = 32（等于 action chunk 长度） |
| H | action chunk 长度 | 32（执行前 16 步） |

**直觉**：flow matching 部分让模型学会从噪声到真实动作的连续变换路径；foresight 部分确保潜在空间编码了与控制相关的未来状态信息。两者通过共享 DiT 层的梯度耦合——预测未来"需要什么"的动作，动作生成就"知道"未来"会变成什么样"。

> 符号与论文保持一致。L_fm 使用条件流匹配（conditional flow matching），采样 s ~ logit-normal 分布。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：机器人需要将方块从 A 移到 B。

**输入**：
- o_t: 当前观察（方块在 A）
- q_t: 本体状态 [x, y, z, gripper_open, ...] (16 维)
- c_τ: VTT = mean(g_T^e - g_0^e) 从 50 个演示计算（编码"A→B"的视觉变化方向）

**训练时**：

```
步骤 1: 采样噪声 x_0 ~ N(0, I), 维度 [32, 7] (H=32, d_a=7)
步骤 2: 采样 flow time s = 0.6
步骤 3: 插值 x_s = (1-0.6)·x_0 + 0.6·x_1
        其中 x_1 = 真实动作序列 [a_1, a_2, ..., a_32]
步骤 4: 构建 token 流 [Z_a(x_s); Z_q(q_t); c_τ; Z_v(o_t)]
步骤 5: 通过 12 层 DiT → 输出 v̂_s 和 ẑ_{t+32}
步骤 6: 计算 L_fm = ||v̂_s - (x_1 - x_0)||² = 0.023
步骤 7: ẑ_{t+32} → 𝒟 → 解码特征 → L_ff = 1 - cosine = 0.15
步骤 8: L_total = 0.023 + 0.5 × 0.15 = 0.098
步骤 9: 反向传播更新所有可训练参数 (0.2B)
```

**推理时**（丢弃 𝒟）：

```
步骤 1: 选择任务 τ 的 VTT c_τ (离线预计算)
步骤 2: 采样 x_0 ~ N(0, I)
步骤 3: Euler 积分 10 步:
        s_0 = 0 → v̂_0 → x_1 = x_0 + 0.1·v̂_0
        s_1 = 0.1 → v̂_1 → x_2 = x_1 + 0.1·v̂_1
        ...
        s_9 = 0.9 → v̂_9 → x_{10} = 最终动作序列
步骤 4: 执行前 16 步动作，观测新状态，重复
```

## 4. 工程视角 (Engineering View)

| 指标 | 数值 | 含义 |
|------|------|------|
| 总参数量 | 0.5B | DINOv3-ViT-L/16 占 0.3B（冻结）+ Action Expert 0.2B（可训练） |
| 训练显存 | 14.7-21.3 GB | 取决于 N_q（64 queries 时约 18 GB），留有 24GB 余量 |
| 训练时间 | ~110 GPU 小时 | 单 RTX 5090，50 任务联合训练 |
| 推理延迟 | 85 ms/步 | RTX 4090，10 步 Euler 积分 |
| 控制频率 | 30 Hz (真机) | 绝对关节角度命令 |
| 相机分辨率 | 320×240 (仿真) / 256×256 (真机) | 远低于 OpenVLA 的 224×224 双视角 |
| Action chunk | 32 步（执行 16 步） | 覆盖 0.53 秒（30Hz） |

**工程含义**：
- **单 GPU 可训练**是最大卖点——对比 π0/Motus 需要多卡集群，LiLa-WAM 让小型实验室也能训练 WAM
- **推理 85ms** 意味着 ~12 Hz 的控制频率，对于桌面操作足够，但对高速动态任务偏慢
- **VTT 离线预计算**意味着部署时无需语言模型，但也意味着新任务需要重新采集演示并计算 VTT
- **冻结 DINOv3** 减少了可训练参数但限制了视觉表征的适应性——如果目标域与 DINOv3 预训练数据差异大，可能需要微调编码器

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- 50 任务联合训练（RoboTwin 2.0 clean 90.48%）——证明多任务能力
- 域随机化下保持竞争力（72.45%）——有一定的鲁棒性
- 真机迁移（82.0% 平均）——sim2real 可行
- 无语言指令操作——部署时不依赖文本

**不能做什么 / 局限**：
- **仅单臂操作**：所有实验在单臂机器人上完成，双臂/人形未验证
- **VTT 需要每任务演示**：新任务必须采集演示并计算 VTT，无法零样本接受新指令
- **LIBERO 多策略**：4 个 suite 各训练一个策略，非单模型通用
- **高分辨率受限**：320×240 分辨率可能限制精细操作的精度
- **无跨任务泛化测试**：未测试 VTT 在未见任务上的表现

### 6.1 隐含假设 (Hidden Assumptions)

1. **演示质量足够**：VTT 质量完全依赖演示——如果演示噪声大或覆盖不全，VTT 编码的任务方向可能偏差。论文未分析 VTT 对演示数量的敏感性。
2. **DINOv3 特征空间足够表达控制相关变化**：VTT 在 DINOv3 全局特征空间中计算差值——如果该空间对控制相关的细微变化不敏感（如手指微调），VTT 可能丢失信息。
3. **未来预测 horizon = action chunk 长度是最优的**：Δ=32 是经验设定，未做 horizon 长度消融。
4. **冻结编码器不会限制域适应**：在 RoboTwin 上效果好，但如果部署到不同机器人/相机，冻结的 DINOv3 可能成为瓶颈。
