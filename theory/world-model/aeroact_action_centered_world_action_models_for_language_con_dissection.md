## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 训练/推理差异 |
|------|------|------|---------------|
| 视觉编码器 (VAE) | $h$ 帧历史图像（$\Delta = 3$ 步间隔） | 时空潜在 token T_o | 冻结，Wan 2.1-1.3B 预训练 |
| 本体感知编码器 | 速度 v、加速度 a、body-z 向量（9维） | 状态 token T_s | MLP，hidden=128 |
| 动作编码器 | 24 步动作块 $a_{t:t+p-1}$ | 动作 token T_a | MLP，hidden=256 |
| 语言编码器 | 自然语言指令 l | 语言 token T_l | 冻结，Wan text encoder |
| 未来帧编码器 | K=8 帧未来图像 | 未来 token T_f | 冻结，同 VAE |
| 视频 DiT | [T_s; T_o; T_a; T_f] + T_l cross-attn | 动作噪声 $\varepsilon_a + $ 未来帧噪声 $\varepsilon_f$ | 可训练，blockwise causal mask |
| 自引导采样器 | 上一 chunk 后缀 + 当前观测 | 平滑衔接的 24 步轨迹块 | 推理时运行，不改架构 |

### 1.2 关键机制 (Key Mechanism)

1. **Blockwise Causal Mask**：状态和参考帧 token 不能 attend 到未来帧 token；动作 token 只能 attend 到状态、参考帧和自身 token；未来帧 token 可以 attend 所有 token。这保证了动作预测不会"偷看"未来帧，同时未来帧重建可以条件于生成的动作块。

2. **训练-推理不对称设计**：训练时联合优化 $L_{\text{act}} + \lambda_{\text{vis}} \cdot L_{\text{vis}}$（动作预测 + 未来帧预测）；推理时省略 $T_f$，只解码动作流。这减少了 37.8% 推理时间（$0.296\,\text{s} \to 0.184\,\text{s}$，4 步去噪），并避免了想象帧误差传播到控制。

3. **5 阶多项式轨迹块**：每个动作不是瞬时速度指令，而是一个 $T = 2\,\text{s}$ 的局部轨迹段，用 9 维参数（端点位移 $r,\theta,\psi$ + 端点速度 + 端点加速度）表示。多项式系数由起点/终点边界条件解析求解。

⚡ **Eureka Moment**：未来帧预测只作为训练时的密集监督信号——它教会模型"动作如何改变视觉"，但推理时完全不需要生成未来视频，策略直接输出可执行轨迹块。

### 1.3 信息流/架构图 (Flow / Diagram)

```
训练时:
  历史图像 o_{t-8Δ}...o_t ──→ VAE(冻结) ──→ T_o (参考token)
  本体状态 s_t ──────────────→ MLP ────────→ T_s (状态token)
  动作块 a_{t:t+23} ─────────→ MLP ────────→ T_a (动作token)
  未来图像 o_{t+Δ}...o_{t+8Δ}─→ VAE(冻结) ──→ T_f (未来token)
  语言指令 l ────────────────→ TextEnc(冻结)→ T_l (语言token)
  
  [T_s; T_o; T_a; T_f] ──→ Video DiT (blockwise causal mask) ──→ ε_a, ε_f
  T_l ─────────────────────────────────────────────────────────→ cross-attn
  
  L = L_act(||g^a(...) - ε_a||²) + λ_vis·L_vis(||g^f(...) - ε_f||²)

推理时:
  历史图像 + 本体状态 + 语言 ──→ 同上编码 ──→ [T_s; T_o; T_a]
  ──→ Video DiT (无T_f, 无mask限制) ──→ ε_a ──→ 动作块 a_{t:t+23}
  ──→ 自引导(与前chunk重叠区平滑) ──→ OM-MPC轨迹跟踪器 ──→ 电机指令
```

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L(Θ) = L_act + λ_vis · L_vis
L_act = E[||g_Θ^a(T_s, T_o, T_a, T_l) - ε_a||²]
L_vis = E[||g_Θ^f(T_s, T_o, T_a, T_f, T_l) - ε_f||²]
```

**目标**：联合训练动作预测和未来帧预测，用视频监督塑造动作表征。

**变量说明**：

| 符号 | 含义 |
|------|------|
| T_s, T_o, T_a, T_f, T_l | 状态/参考帧/动作/未来帧/语言 token |
| $\varepsilon_a, \varepsilon_f$ | 动作和未来帧的扩散/流匹配目标噪声 |
| $g_\Theta^a, g_\Theta^f$ | 从 DiT 提取的动作/视觉预测头 |
| $\lambda_{\text{vis}}$ | 视觉监督权重（论文未给出具体值，TODO） |
| $\Delta$ | 时间步间隔 = 3（每 3 个动作步编码 1 帧视频） |
| p | 动作块长度 = 24 步 |
| K | 未来帧数 $= \lfloor p / \Delta \rfloor = 8$ |

**直觉**：动作预测和未来帧预测共享同一个 Transformer  backbone。未来帧预测作为"后果监督"——如果模型预测的动作块不能正确重建未来视觉，说明动作本身不符合物理规律。推理时去掉未来帧分支，只保留动作解码。

> 符号与本文保持一致：所有公式中的向量/矩阵用粗体表示，下标表示时间索引。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设四旋翼在某一时刻的输入：

```
观测历史: h = 9 帧（覆盖 2.4 秒，Δ=3，帧率 30Hz → 动作频率 10Hz）
本体状态: s_t = [v_x=0.5, v_y=0.0, v_z=-0.2, a_x=0.1, a_y=0.0, a_z=-9.8, ...]  (9维)
语言指令: l = "fly to the yellow foam mat"
```

**推理过程**：

```
Step 1: 视觉编码 → 9 帧 → 9 × VAE_latent tokens (T_o)
Step 2: 本体编码 → s_t → T_s (1 token, dim=128)
Step 3: 语言编码 → l → T_l (cross-attn context)
Step 4: DiT 4 步去噪 → 输出 24 步动作块
        a_{t:t+23} = [a_0, a_1, ..., a_23]，每个 a_i 是 9 维轨迹参数
Step 5: 自引导（若 t_infer < t_interval）
        前 8 步（重叠区）= 上一 chunk 的后缀
        后 16 步 = 当前采样
Step 6: 轨迹块送入 OM-MPC → 电机指令 → 执行
```

**关键数字**：

```
推理耗时（RTX 5090）: 0.184s（无视频生成）vs 0.296s（含视频生成）
VRAM 占用: ~4,500 MB
真实部署延迟: t_infer ≈ 0.8s（含 ZeroMQ 通信往返）
动作块覆盖: 24 步 × 0.1s/步 = 2.4 秒轨迹
```

### 6.1 隐含假设 (Hidden Assumptions)

1. **状态估计完美**：真实实验中依赖运动捕捉系统提供精确状态，未讨论视觉里程计误差对策略的影响。
2. **通信延迟可控**：ZeroMQ 往返延迟约 0.8s，假设局域网延迟稳定；在 WiFi 干扰环境下可能恶化。
3. **单一任务阶段**：策略设计为单阶段目标到达，未验证多步骤指令（如"先去厨房，再去卧室拿杯子"）。
4. **仿真到真实的 sim-to-real gap 可被手持数据弥补**：手持采集设备近似飞行运动，但无法完全模拟四旋翼动力学（如气流扰动、振动）。
5. **$\lambda_{\text{vis}}$ 权重不需要任务级调参**：论文未报告 $\lambda_{\text{vis}}$ 的具体值和消融实验。
