💡 **X-Ray 开场**
世界-动作模型（WAM）面临一个根本困境：在控制速率下同步生成视频太慢（1.1-3.8 秒/块），而放弃测试时视觉想象则牺牲任务成功率。GlanceWAM 发现这个困境不是视觉想象的固有属性——它只是"想象与控制耦合在同一个时间尺度上"的人为产物。核心洞见：策略不需要逐帧的未来视频，它只需要一个"要去哪里"的空间目标。通过在单一视频 DiT 内将想象（3 秒慢时钟）与控制（0.8 秒快时钟）解耦，GlanceWAM 在 RoboCasa 厨房 24 任务上达到 72.2% 成功率（超越同步 Cosmos Policy 的 67.1%），同时推理速度快 24 倍（48ms/块）。

### 1.2 关键机制 (Key Mechanism)

GlanceWAM 的核心是在**单一视频 DiT（SkyReels-V2-DF, 1.3B 参数）**内统一视频世界建模和动作策略学习：

- **双时间尺度设计**：前瞻视界 Hf ≈ 3.0s（慢时钟，后台生成）与控制速率 Ha = 0.8s（快时钟，实时解码）解耦。一个前瞻帧服务约 4 个连续动作块（Hf/Ha ≈ 4）。
- **纯潜空间控制路径**：前瞻帧 `z^la` 从不解码为 RGB 像素——它始终保留在因果 VAE 的归一化潜空间内，直接作为后续动作前向传播的 conditioning tokens。消除 VAE 解码大幅降低计算开销。
- **非干扰 3 类注意力掩码**：通过 prefix-LM 块掩码隔离三类 token（观测/未来预测/前瞻），防止视频生成查询直接 attend 到干净前瞻帧而退化为复制捷径。

⚡ **Eureka Moment**：策略不需要密集帧级未来视频——它只需要一个"去哪里"的空间目标。单帧前瞻（3 秒后）+ 纯潜空间消费 = 同时实现实时性和高成功率。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L = L_video + L_action
L_video = E[||v_θ(z_t+Hf^(τ), τ | z_≤t, c) - (ε - z_t+Hf)||²]
L_action = E[||u_φ(a_t^(σ), σ | [h_obs; h_la], c, Δ) - (ε_a - a_t)||²]
```

**目标**：联合训练视频世界模型（前向动力学预测）和动作策略（逆动力学回归），两者共享同一个 DiT 骨干。

**变量说明**：

| 符号 | 含义 |
|------|------|
| `z_t+Hf^(τ)` | 在噪声水平 τ 下的未来目标潜表示 |
| `v_θ` | 视频骨干的速度预测网络（流匹配） |
| `ε, ε_a` | 视频/动作的噪声采样 |
| `a_t ∈ R^(Ha×Da)` | 动作块（16 步 × 动作维度） |
| `u_φ` | 动作头的流匹配网络 |
| `[h_obs; h_la]` | 从 DiT 层 {5,12,19,26} 拼接的多层观测+前瞻特征 |
| `Δ` | 前瞻偏移量（衰减从 Hf 到 0），通过正弦时间嵌入注入 |
| `σ ~ U(0,1)` | 动作流匹配时间步 |

**直觉**：视频损失教模型"预测未来长程场景演化"（Hf=3s），动作损失教模型"根据当前观测 + 前瞻目标 + 剩余偏移量 Δ 生成动作"。前瞻帧在训练时是 teacher-forced 的真实帧（u ~ U(0, Hf]），在推理时是模型自己生成的潜表示。

> 符号与论文保持一致。流匹配目标等价于学习从噪声到数据的速度场，而非传统扩散的噪声预测。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个厨房任务：把杯子从水槽移到架子上。

**时间线**（Hf = 3.0s, Ha = 0.8s, 控制频率 20Hz）：

```
t=0.0s:  生成前瞻帧 z^la (目标: 杯子在架子上)
         动作块 1: a[0:15] — 48ms, Δ=3.0s, 抓取杯子
         动作块 2: a[16:31] — 48ms, Δ=2.2s, 移动手臂
         动作块 3: a[32:47] — 48ms, Δ=1.4s, 继续移动
         动作块 4: a[48:63] — 48ms, Δ=0.6s, 放置杯子

t=3.2s:  刷新前瞻帧 z^la' (场景已更新)
         新动作块循环开始...
```

**数值验证**：
- 前瞻生成：ODE 10 步采样，约 800ms（后台，不阻塞）
- 单个动作块：48ms（单次前向传播）
- 4 个动作块总时间：4 × 48 = 192ms
- 前瞻开销摊销：800ms / (4 chunks × 0.8s) ≈ 17%（10步）或 ~2%（1步）
- 总延迟预算：48ms/chunk << 50ms（20Hz 控制周期），满足实时要求

**损失函数数值示例**（假设值）：
```
L_video ≈ 0.023  (速度预测 MSE, 未来帧生成质量)
L_action ≈ 0.017  (动作回归 MSE, 与真实动作的差距)
L_total = 0.023 + 0.017 = 0.040
```

## 4. 工程视角 (Engineering View)

| 工程维度 | GlanceWAM | 传统同步 WAM | 含义 |
|----------|-----------|-------------|------|
| 推理延迟/chunk | 48ms (A100) | 1100-3800ms | 24x 加速，满足实时控制 |
| 前瞻生成开销 | 800ms (后台, 异步) | 每个 chunk 都生成 | 从关键路径移除 |
| 前瞻开销占比 | ~2-17% | 100% 在关键路径 | 摊销后几乎可忽略 |
| 训练收敛 | 10k-15k steps | 60k-100k+ steps | 5-10x 更快收敛 |
| GPU 需求 | 4×H200 (训练) / 1×A100 (推理) | 类似 | 推理仅需单卡 |
| 模型大小 | 1.3B (SkyReels-V2-DF) | 类似 | 中等规模，可部署 |
| VAE 解码 | 推理时零次 | 每个 chunk 可能需解码 | 消除像素级开销 |
| 内存占用 | 前瞻帧缓存（单帧潜表示） | 无额外缓存 | 极小额外开销 |

**工程含义**：
- **控制频率边界**：48ms/chunk 对应 20.8Hz，刚好覆盖 20Hz 标准控制频率。若需更高频率（如 50Hz = 20ms/chunk），需要更轻量的动作头或模型蒸馏。
- **部署约束**：前瞻生成可放在专用 GPU 或后台线程，与动作推理完全解耦——适合边缘设备 + 云端推理的混合部署。
- **量化友好**：纯潜空间操作意味着不需要 VAE 编解码器的量化，只需量化 DiT 和动作头。

### 6.1 隐含假设 (Hidden Assumptions)

1. **单帧前瞻足够**：假设 3 秒后的单帧视觉目标足以引导 3 秒内的所有中间动作。对于需要精细中间状态反馈的任务（如插拔 USB），这可能不成立。
2. **场景在 3 秒内相对稳定**：假设环境在前瞻刷新周期内不会发生剧烈变化。动态环境可能使前瞻帧迅速失效。
3. **潜空间表征的迁移性**：假设 VAE 潜空间中的前瞻表征可以直接用于动作 conditioning，无需像素级解码。这在仿真中有效，但真实世界的 VAE 表征可能有域偏移。
4. **异步延迟可忽略**：假设后台生成前瞻帧的延迟（~800ms）相对于 3s 刷新周期足够小。在资源受限设备上可能不成立。
5. **50 个演示足够**：在低数据设置下表现优异，但作者未测试更多数据是否能进一步提升（可能存在数据效率天花板）。
