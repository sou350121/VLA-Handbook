💡 **X-Ray 开场**
这篇论文解决的是「世界-动作模型太慢、来不及闭环」的问题。它发现：receding-horizon 控制每次只执行预测段的前几个动作，那么被丢弃的「未来尾巴」其实是白算的——不如把去噪变成「续算」，让更远的未来 chunk 提前开始去噪。结论：同一套模型、同一批 demo，精度持平甚至更好，而每次要重规划时只需跑 2 步而不是 10 步。对 VLA 研究者意味着：**延迟这件事可以靠「时间上的重排」解决，而不必靠「删掉视觉想象」**（对比 Fast-WAM）。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练 vs 推理差异 |
|------|------|------|-----------|------------------|
| 视频专家 (Video Expert) | 当前观测 VAE latent + 带噪未来视频 latent | 未来视频流速度 (flow velocity) | 每个去噪步 | 训练/推理共用 Wan2.2-TI2V-5B 初始化权重 |
| 动作专家 (Action Expert) | 投影后的带噪动作 token | 动作流速度 | 每个去噪步 | 30 层、d_a=1024、~1B 参数，由视频专家权重插值初始化 |
| 掩码联合注意力 (Masked Joint Attention) | 两专家各层特征 | 耦合后的联合表征 | 每层 | 训练/推理用同一注意力掩码（Fig.2c） |
| 语言/本体编码器 | 指令 ℓ + 机器人状态 s_t | 条件嵌入 | 每周期一次 | 本体编码器参与训练，VAE/文本编码器冻结 |
| 滚动调度器 (Rolling Scheduler) | 窗口位置 j + 周期相位 τ | 各 chunk 噪声等级 σ_j | 每去噪步 | 初始化模式(0.2)/滚动模式(0.8)混合采样 |

### 1.2 关键机制 (Key Mechanism)

- **重规划周期的浪费**：标准 chunk 采样器每个重规划都从纯噪声起，对整条 horizon 做完整去噪，但控制只执行开头一小段，尾部被丢弃而非跨周期复用。
- **错位噪声窗口**：把预测窗切成 W 个对齐的视频-动作 chunk，越靠未来噪声越高（`σ_1 < σ_2 < ... < σ_W`）。每周期只让最近的 chunk 变干净以供执行，其余只做部分精修。
- **窗口滚动 = 续算**：执行完第一个 chunk 后，窗口前移，保留的 chunk 恰好落在新位置的起始噪声等级上（式 3 保证），再补一个纯噪声新 chunk。
- **跨 chunk 视觉上下文**：动作 token 可注意整个预测窗的视觉特征（包括超出自身执行区间的未来），从而「借」到更远的视觉想象，而动作 token 之间只允许同 chunk 内注意。

⚡ **Eureka Moment**：与其每个周期重算整条 horizon，不如让未来 chunk **提前开始去噪**——用一个错位的噪声表，把一次性的重计算变成跨周期的流水线。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
每个重规划周期：denoise steps = N / W  （而非 N）
```

默认 N=10, W=5 ⇒ 稳态每周期只跑 2 步。

**目标**：学一个联合分布，同时生成动作序列和未来视频 latent：

```
p_θ( a_{t:t+H-1}, v_{t+1:t+H} | c_t ),  c_t = (o_t, s_t, ℓ)
```

**滚动噪声调度**：chunk j 在相位 τ∈[0,1] 的噪声等级（τ 从 1 降到 0 表示去噪推进）：

```
σ_j^rolling(τ) = σ( (j-1+τ) / W ),   j = 1..W
```

其中 σ(·) 是单调递增的基础噪声表，`σ(1)=1`（纯高斯噪声），`σ(0)=0`（干净数据）。关键不变式：

```
σ_{j+1}^rolling(0) = σ_j^rolling(1)   （式 3：保留 chunk 天生落在新位置的起点）
```

**初始化模式**（回合开始时整窗从纯噪声起）：

```
σ_j^init(τ) = σ( min{1, τ + (j-1)/W } )
```

**Euler 采样更新**（对窗口内每个 chunk）：

```
X~_j ← X~_j + [ σ_j(τ+Δτ) - σ_j(τ) ] · f_{θ,j}( X~_{1:W}, σ; c_t )
```

**训练目标**（flow matching）：先加噪 `X~_j = (1-σ_j)·X_j + σ_j·ε_j`，再回归速度目标 `ε_j - X_j`：

```
ℓ_j^q = || [f_θ^q(X~_{1:W}, σ; c_t)]_j - (ε_j^q - X_j^q) ||_2^2

L = E[ (1/W) Σ_{j=1}^{W} b_j · w(σ_j) · (λ_v · ℓ_j^v + λ_a · ℓ_j^a) ]
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| H = W·K | 总预测 horizon（默认 W=5, K=16 ⇒ H=80） |
| W | 窗口内 chunk 数 |
| K | 每个 chunk 的动作数 |
| N | 每个 chunk 的总去噪步数（默认 10） |
| τ | 单周期去噪相位，1→0 |
| σ(·) | 基础噪声表，`σ(τ)=ρτ/[1+(ρ-1)τ]`，ρ=5 |
| b_j | 活动掩码，排除「初始化时被钉在纯噪声」的 chunk |
| w(σ_j) | 噪声等级权重 |
| λ_v, λ_a | 视频/动作损失权重，默认均为 1 |

**直觉**：因为保留的 chunk 天然满足「本周期结束噪声 = 下周期开始噪声」，所以滚动窗口不需要额外对齐操作——去噪自然跨周期接力。

## 3. 带数字走一遍：玩具例子 (Worked Example)

取默认配置 **W=5, K=16, N=10, ρ=5**，看窗口如何滚动。

**基础噪声表** `σ(τ) = 5τ/(1+4τ)`：

| τ | 0 | 0.2 | 0.5 | 1.0 |
|---|---|-----|-----|-----|
| σ(τ) | 0.00 | 0.56 | 0.83 | 1.00 |

**某稳态周期的滚动噪声等级**（`σ_j = σ((j-1+τ)/W)`）：

| chunk j | τ=1（周期开始） | τ=0（周期结束） |
|---------|------------------|------------------|
| 1 | σ(1/5)=0.56 | σ(0)=0.00 ✅ 可执行 |
| 2 | σ(2/5)=0.71 | σ(1/5)=0.56 |
| 3 | σ(3/5)=0.79 | σ(2/5)=0.71 |
| 4 | σ(4/5)=0.83 | σ(3/5)=0.79 |
| 5 | σ(5/5)=1.00 | σ(4/5)=0.83 |

校验式 3：chunk 2 在 τ=0 的 0.56 恰好等于 chunk 1 在 τ=1 的 0.56 —— 窗口前移后无需重设。

**步数账**：稳态每周期 2 步，`Δτ = -W/N = -0.5`，两步走完 τ: 1→0.5→0。一个 chunk 在窗口里待 W=5 个周期 × 2 步 = **10 步 = N**，走完整个去噪流程后被执行——与「每 chunk 总预算 N 步」自洽。

**初始化开销**：回合第一周期用 init 模式，`Δτ=-1/N=-0.1`，需 10 步才进入滚动模式；此后每周期稳定 2 步。

**延迟换算**：论文实测稳态 215ms/update（2 步）⇒ 约 4.6 Hz 重规划；而每 chunk 执行 16 个动作、真机 10Hz ⇒ 1.6s 执行窗，重规划 0.2s 完全容得下，可与执行重叠。

## 4. 工程视角 (Engineering View)

- **延迟**：单卡 A100、RoboTwin 2.0、384×320 分辨率下，默认配置 215ms/update；Joint-WAM 978ms（4.5×），Fast-WAM 548ms（2.5×）；VLA 基线 π0.5 296ms、GR00T N1.7 285ms。**关键点：Rolling-WAM 保留未来视频生成，单次 update 却比两个 VLA 基线更快，且维护的是 80 动作窗（基线仅 16）。所有数字未用 torch.compile / TensorRT / 自定义 CUDA kernel，是「素颜」成绩。**
- **窗口规模的收益递减**：每周期步数 `N/W = floor(16/W)`，当 W≥5 时降到 2 步，W=6–8 延迟曲线趋于平坦（≈322ms @ W=5 vs Joint-WAM 1529ms / Fast-WAM 832ms，对应 4.75× / 2.58×）。再增大窗口不再降延迟，只增显存。
- **内存/吞吐 trade-off**：窗口内存 ≈ W 倍单 chunk 的视频 latent + 动作 token；降延迟的前提是「GPU 并行度足以一次处理更宽的窗口」，否则并行收益被吃回。
- **部署约束**：稳态只需 2 步 ⇒ 每步计算量上升（要处理整窗）但步数骤减，适合「单步并行度高、序列步数受限」的推理栈；与「减少模型大小/视觉 token/去噪步数」等其他加速手段正交，可叠加。
- **抖动控制**：由于保留 chunk 每周期都被新观测重新条件化（cross-attention），跨 chunk 边界的执行更连续；论文称 Joint-WAM 更易出现「停顿」并中断任务。

| 基准 | Rolling-WAM | 最强基线 | 说明 |

**消融**（六项 RoboTwin Clean 任务 + 四 suite LIBERO）：

- 窗口大小：W=5 达峰 78.2%，W=3 为 77.3%，W=8 掉到 69.5%。
- 训练噪声混合：全滚动调度 = 78.2%(RoboTwin)/98.1%(LIBERO)；Random p=0.5 把 RoboTwin 抬到 78.5% 但把 LIBERO 压到 97.3%——无一能同时提升两基准，故保留纯滚动调度。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做**：
- 单策略跨多任务（LIBERO 四 suite、RoboTwin 50 任务、真机 3 任务）。
- 保留显式未来视频想象的同时把重规划延迟压到 215ms（快于 VLA 基线）。
- 跨 chunk 边界更连续的执行（作者定性观察）。

**不能做 / 会退化的场景**：
- **快场景变化**：保留的远期预测可能滞后于突发场景变化并误导动作，长窗口下尤甚（作者明确列为局限）。
- **超长窗口**：W=8 成功率降到 69.5%——更远的视觉预测受当前观测约束弱，对临近动作引导有限。
- **任务域有限**：只测了桌面/双臂操作与一型人形（Unitree G1）；未验证移动操作、多机型泛化。
- **真机样本小**：3 任务 × 20 trials、各 50 demo、单机型，统计力有限；作者称「competitive」而非「SOTA 泛化」。

### 6.1 隐含假设 (Hidden Assumptions)

- **并行度充足**：降延迟依赖一次能并行处理更宽窗口（W chunk）；若显存/并行受限，收益会被侵蚀。
- **场景演化慢于窗口推进**：默认「近期动作具体、远期计划暂定」的人类规划直觉在本任务域成立。
- **视频与动作共享噪声等级**：同 chunk 内两模态用同一 σ_j，未分别调度。
- **训练噪声分布匹配推理**：只有「全滚动调度」能同时兼顾两基准，暗示模型对训练-推理噪声错配较敏感。
- **保留 chunk 重新条件化足矣**：靠每周期的新观测 cross-attention 纠正漂移，而非显式再锚定。
