### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **闭环重访 (Closed-loop Revisited)**: 传统 benchmark 只评估单向生成，MIND 要求模型"原路返回"——向前生成后再逆向生成，检查是否回到一致状态。这直接测试世界模型的内部状态一致性。

2. **双视角设计 (First + Third Person)**: 现有 benchmark 几乎全是第一人称，无法评估角色 - 背景交互。MIND 的第三人称视频能暴露"角色穿模"等根本缺陷。

3. **动作空间泛化测试**: 同一场景下用 5 种不同的动作步长 (Δp) 和旋转角度 (Δr) 生成视频，测试模型能否 zero-shot 适应新动作空间。

4. **帧级动作对齐**: 每帧都有对应的动作标签 + 角色/相机位姿，支持细粒度评估而非仅视频级打分。

## 2. 数学核心 (Math Core)

### 2.1 动作空间定义

动作空间 𝒜 定义为 8 个离散动作：

```
𝒜 = {W, A, S, D, ↑, ↓, ←, →}
```

其中：
- W/A/S/D = 前/左/后/右移动
- ↑/↓/←/→ = 相机 pitch/yaw 旋转

### 2.2 平移运动更新

角色位置 pₜ = [xₜ, yₜ, zₜ] 按以下公式更新：

```
pₜ₊₁ = pₜ + Δp · vₐ
```

变量说明：
- `vₐ`: 动作对应的方向向量（如 v_W = [0, 0, 1] 表示向前）
- `Δp`: 移动步长（可配置，如 100/150/280 单位）

### 2.3 旋转运动更新

相机朝向 rₜ = [θₜ, φₜ] 按以下公式更新：

```
rₜ₊₁ = rₜ + Δr · uₐ
```

变量说明：
- `uₐ`: 旋转方向向量（如 u_↑ = [0, +1] 表示 pitch 向上）
- `Δr`: 旋转角度（可配置，如 0.4°/0.7°/1.4°）

### 2.4 记忆一致性损失 (Memory Consistency Loss)

当模型沿环路轨迹 𝒜_loop 回到已观察状态时，一致性误差定义为：

```
ℒ_mem = ||f̂ₜ - fₜ'||₂²
```

其中 fₜ' 是重访场景的真值帧。

### 2.5 长程上下文记忆指标 (Long Context Memory Metric)

```
ℒ_lcm = (1/k) · Σᵢ₌₁ᵏ ||f̂ₜ₊ᵢ - fₜ₊ᵢ||₂²
```

直觉：预测帧与真值帧的均方误差，越低表示长期记忆保持能力越强。

### 2.6 生成场景一致性指标 (Generated Scene Consistency Metric)

基于 10 条对称运动路径（前进后原路返回）：

```
ℒ_gsc = (1/k) · Σᵢ₌₁ᵏ ||f̂ₜ₊ᵢ^fwd - f̂ₜ₊ᵢ^rev||₂²
```

直觉：向前生成和逆向生成的帧应该完全匹配，衡量几何稳定性。

> 符号与本文/相关文档保持一致：ℒ 表示损失/误差，下标 lcm=long context memory, gsc=generated scene consistency, mem=memory

## 3. 带数字走一遍：玩具例子 (Worked Example)

**场景**: 测试长程记忆一致性

**设置**:
- 记忆段长度 T = 100 帧（模型先观察 100 帧）
- 预测长度 k = 50 帧（模型需生成未来 50 帧）
- 动作序列：向前移动 24 帧 → 向左转 90° → 向前 24 帧 → 向右转 90° → 向前 2 帧（理论上应回到起点附近）

**计算过程**:

1. 模型观察 ℳ = {f₁, f₂, ..., f₁₀₀}，建立内部场景表征
2. 接收动作 a₁₀₁ = "向前"，生成 f̂₁₀₁
3. 继续接收 a₁₀₂...a₁₅₀，逐帧生成 f̂₁₀₂...f̂₁₅₀
4. 假设第 150 帧理论上应接近第 50 帧的场景（环路闭合）

**评估**:

```
ℒ_lcm = (1/50) · Σᵢ₌₁⁵⁰ ||f̂₁₀₀₊ᵢ - f₁₀₀₊ᵢ||₂²
```

假设逐帧 MSE 如下（简化为 5 个采样点）：
- 帧 101: MSE = 0.08
- 帧 110: MSE = 0.11
- 帧 120: MSE = 0.15
- 帧 135: MSE = 0.22
- 帧 150: MSE = 0.31

```
ℒ_lcm ≈ (0.08 + 0.11 + 0.15 + 0.22 + 0.31) / 5 = 0.174
```

**解读**: MIND-World 的实测 ℒ_lcm 约 0.10-0.11，说明上述假设模型性能较差。误差随时间增长表明长期记忆衰减。

## 4. 工程视角 (Engineering View)

### 4.1 吞吐/延迟权衡

| 配置 | 上下文窗口 | 单帧延迟 | 显存占用 | 适用场景 |
| --- | --- | --- | --- | --- |
| Image-to-World | 0 帧（仅首帧） | ~50ms | ~8GB | 快速原型/无记忆需求 |
| Video-to-World | 25 帧 cache | ~80ms | ~12GB | 需要一致性的交互应用 |
| Video-to-World (长窗口) | 100+ 帧 | ~150ms | ~20GB+ | 长程任务/高精度需求 |

### 4.2 关键工程挑战

1. **动作注入机制**: MIND-World 将动作直接注入 timestep embedding，比 GameFactory 的多阶段训练更轻量，但实验显示动作控制精度仍有下降（RPE 随序列增长而累积）。

2. **KV Cache 管理**: 自回归推理时需要维护 context cache，cache 过大导致显存爆炸，过小导致记忆丢失。MIND-World 用 25 帧局部注意力窗口做折中。

3. **动作空间检测**: 实验发现，用记忆上下文推理时，如果测试动作空间与训练不一致，性能反而比无记忆更差。工程上需要前置动作空间检测模块。

4. **第三人称渲染**: 角色 - 背景交互是难点，MIND-World 会出现"角色穿墙"现象。需要额外的碰撞检测或深度约束。

### 4.3 部署约束

- **分辨率**: 训练/评估用 720p（原文表格），但数据集是 1080p——部署时需考虑上采样质量损失
- **帧率**: 24 FPS 是基准，实时交互可能需要 30/60 FPS，对推理速度要求更高
- **GPU**: 实验用 4×H100，单卡部署需量化或蒸馏

### 6.2 不能做什么（失败模式）

| 失败模式 | 触发条件 | 根本原因 |
| --- | --- | --- |
| 长程记忆漂移 | >100 帧预测 | 上下文窗口有限，早期信息丢失 |
| 动作空间泛化失败 | 测试Δp/Δr与训练不同 | 记忆上下文与动作空间不一致时干扰推理 |
| 第三人称角色穿模 | 角色靠近建筑/障碍物 | 缺乏显式碰撞检测或深度约束 |
| 环路不一致 | 原路返回测试 | 生成过程非确定性，累积误差 |
| 精细动作控制失败 | 小步长/小角度动作 | 动作注入机制分辨率不足 |

### 面试 Tip

> **问**: "如何评估世界模型的记忆一致性？"
>
> **答**: "用闭环重访测试——让模型沿一条路径生成，然后原路返回，比较返回时的生成帧与原始观察帧的 MSE（ℒ_gsc 指标）。如果世界模型有 consistent 的内部状态表示，往返应该生成一致的场景。MIND benchmark 用 10 条对称路径做这个测试，发现当前模型在>50 帧后一致性显著下降。"
