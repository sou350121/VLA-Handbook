### 1.2 关键机制 (Key Mechanism)

ImageWAM 的核心设计选择可以归结为三个关键洞察：

1. **指令到变化的对齐（Instruction-to-Change Alignment）**：图像编辑模型在预训练时就已经学会了"语言指令 → 视觉变化"的映射。这与机器人策略的需求天然吻合——给定当前观察和任务指令，模型需要理解"什么应该改变、在哪里改变"。

2. **更容易的代理任务（Easier Proxy）**：视频生成需要建模完整的时空轨迹（外观、背景、相机运动、时间平滑性），而图像编辑只需要建模当前帧到目标帧的视觉变换。后者与动作预测的相关性更高，且不容易被无关细节干扰。

3. **紧凑推理路径（Compact Inference）**：推理时不生成编辑后的图像，也不生成未来视频。只取图像编辑去噪过程中的一个固定时间步 $\tau^*$ 的 KV Cache，直接作为动作专家的上下文。

⚡ **Eureka Moment**：图像编辑模型的中间层 KV Cache 本身就编码了"当前观察在任务指令下应该如何变化"的信息——不需要解码成图像或视频，这个中间表示本身就是最好的世界-动作上下文。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
C_edit^τ = f_edit^τ(o_t, l)  →  a_t:t+H = v_θ(a_s, s | o_t, l, C_edit^τ)
```

用图像编辑去噪过程的中间层 KV Cache 作为世界-动作上下文，跳过视频生成，直接预测动作。

### 2.1 目标

给定当前观察 $o_t$ 和任务指令 $l$，预测动作序列 $a_{t:t+h}$。传统 WAM 先预测多帧未来视频再预测动作；ImageWAM 只提取编辑骨干的中间特征作为紧凑上下文。

### 2.2 核心方程

**编辑骨干 KV Cache 提取**（论文公式 5）：

```
C_edit^τ = {(K_l^τ, V_l^τ)}_{l=1}^L = f_edit^τ(o_t, l)
```

- $\tau$: 随机采样的去噪时间步（训练时）/ 固定时间步 $\tau^*$（推理时）
- L: Transformer 层数
- $K_l^\tau, V_l^\tau$: 第 $l$ 层的 key 和 value 缓存

**图像编辑损失**（论文公式 7，Flow Matching 形式）：

```
L_img = E[ ||u_φ(z_r, r | o_t, l) - (ε_z - z*_t+H+1)||² ]
```

- $z_r$: 插值隐变量 $= (1-r)\cdot z^* + r\cdot \varepsilon_z$
- $u_\varphi$: 速度预测器
- $\varepsilon_z \sim \mathcal{N}(0, I)$: 图像噪声
- $r \in (0,1)$: 图像流时间

**动作 Flow Matching 损失**（论文公式 9）：

```
L_act = E[ ||v_θ(a_s, s | o_t, l, C_edit^τ) - (ε_a - a*_t:t+H)||² ]
```

- $a_s$: 插值动作样本 = $(1-s) \cdot a^* + s \cdot \varepsilon_a$
- $v_\theta$: 动作速度预测器
- $\varepsilon_a \sim \mathcal{N}(0, I)$: 动作噪声
- $s \in (0,1)$: 动作流时间

**总损失**：

```
L = L_act + L_img
```

> 符号与本文保持一致：$o_t = $ 当前观察，$l = $ 任务指令，$H = $ 动作视界，$\tau = $ 图像编辑去噪时间步，$s = $ 动作流时间。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2D 场景：机器人需要把红色方块从位置 (0, 0) 移到 (2, 2)。

**当前状态**：
- 观察 $o_t$：一幅 $224 \times 224$ 图像，红色方块在左上角
- 指令 l："把红色方块移到右上角"
- 目标帧 oₜ₊ₕ₊₁：红色方块在右上角

**训练过程**：

1. 对目标帧编码：z* = VAE(oₜ₊ₕ₊₁)，假设 z* 维度为 28×28×4 = 3136
2. 采样噪声 $\varepsilon_z \sim \mathcal{N}(0, I)$，采样流时间 $r = 0.5$
3. 插值：$z_r = 0.5 \times z^* + 0.5 \times \varepsilon_z$
4. 编辑骨干前向：随机采样 $\tau = 300$（共 $1000$ 步去噪），提取 $L = 28$ 层的 KV Cache
5. 速度预测器预测：u_φ(z_r, 0.5 | oₜ, l)
6. 图像损失：L_img = ||预测速度 - (ε_z - z*)||² ≈ 假设 0.15

7. 动作专家：采样动作噪声 $\varepsilon_a$，采样 $s = 0.3$
8. 插值动作：$a_s = 0.7 \times a^* + 0.3 \times \varepsilon_a$（$a^*$ 是专家动作序列，如 $8$ 个 $7$ 维动作 = $56$ 维）
9. 动作损失：L_act = ||v_θ(a_s, 0.3 | oₜ, l, C_edit) - (ε_a - a*)||² ≈ 假设 0.08

10. 总损失 L = 0.15 + 0.08 = 0.23，反向传播更新编辑分支 + 动作专家

**推理过程**（关键简化）：

1. 固定 $\tau^* = 200$，单次前向提取 KV Cache（不再遍历整个去噪轨迹）
2. $C_{\text{edit}}^{\tau^*} = f_{\text{edit}}^{\tau^*}(o_t, l)$ — 不生成图像！
3. 动作专家从噪声 $a_0 \sim N(0, I)$ 开始，用 $C_{\text{edit}}^{\tau^*}$ 作为条件，多次去噪得到 $a_{t:t+h}$
4. 输出 8 个连续动作，执行后进入下一步

**计算量对比**（论文数据）：
- 视频 WAM：需要生成 8 帧未来视频 $\times 28\times28$ 空间 token $\times 4$ 通道 $\approx 25{,}088$ token，每帧多次去噪
- ImageWAM：仅需 1 次编辑骨干前向（提取 KV Cache）+ 动作专家的 flow matching 去噪
- 结果：FLOPs 降至 1/6，延迟降至 1/4

## 4. 工程视角 (Engineering View)

| 工程维度 | 视频 WAM | ImageWAM | 含义 |
|----------|----------|----------|------|

**工程含义**：ImageWAM 的核心工程价值在于把 WAM 的"reason-before-act"范式从"昂贵的视频想象"压缩为"一次编辑骨干前向 + KV Cache 复用"。这意味着：
- 在同样的硬件上，可以用更大的骨干模型（如 FLUX.2 9B）
- 在同样的模型大小下，可以达到更高的控制频率
- 边缘部署（如 Jetson 系列）的可行性显著提升

### 6.3 隐含假设 (Hidden Assumptions)

1. **图像编辑的"变化表示"与机器人动作的"变化需求"高度对齐**：论文假设图像编辑模型学到的"什么应该改变"与机器人策略需要的"如何改变"是同一个问题。这个假设在桌面操作任务上得到验证，但在更复杂的场景（如需要力控的插拔任务）中可能不成立。

2. **单帧编辑足以捕获动作所需的所有信息**：ImageWAM 只预测一个端点帧（$o_{t+h+1}$），不建模中间过程。对于需要精确中间状态的任务（如"把杯子倒水到半满"），这个假设可能过于简化。

3. **KV Cache 中的变换信息足以指导动作预测**：论文假设编辑骨干的中间层特征包含了足够的"如何改变"的信息，而不需要显式生成编辑后的图像。注意力可视化支持了这个假设，但仅在有限的任务上验证。

4. **冻结的 VLM 组件不会成为瓶颈**：论文冻结了 VLM 和 multimodal understanding 组件，只训练编辑分支和动作专家。如果冻结的组件无法充分理解新指令，可能限制整体性能。

  1. 研究世界动作模型（WAM）的研究者——本文提出了一个全新的 WAM 范式
  2. 探索图像编辑模型在机器人领域应用的研究者——本文是首个将图像编辑 KV Cache 用于动作预测的工作
  3. 需要降低 WAM 推理成本的工程师——4.1x 加速和 84.7% FLOPs 节省对部署有直接价值

- **建議章節路徑**：
  - 先读 §3.2（ImageWAM Architecture）——理解核心架构设计
  - 再看 §3.3（Action Prediction and Training）——理解两个 Flow Matching 损失的联合优化
  - 然后看 §4.1-4.2（实验结果）——评估在哪些任务上有效
  - 可跳过 §2（Related Works）——相关工作综述较标准

- **不值得精讀的理由**：
  - 如果你不做机器人策略学习（如只做纯视觉生成），这篇的方法论距离较远
  - 如果你已经熟悉 Fast-WAM 的 KV Cache 复用思路，ImageWAM 的核心创新主要是更换骨干网络，方法论增量不大
