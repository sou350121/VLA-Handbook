## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练/推理差异 |
|------|------|------|-----------|---------------|
| 视频 VAE (Wan2.2) | 原始帧 o_t | 潜在 token z_t ∈ R^{192×C} | 4× 下采样 (τ=4) | 冻结 |
| 视频流 Transformer | z_≤t, a_<t, 文本 c | 预测 z_{t+1:t+K} | 每 K 步自回归 | 推理时积分到 s=0.5 (部分去噪) |
| 动作流 Transformer | z_≤t+1, a_<t, 文本 c | 预测 a_{t:t+K-1} | 每 K 步自回归 | 推理时积分到 s=1.0 (完全去噪) |
| KV Cache | 历史 token | 复用 K/V 对 | 每步更新 | 推理专用，训练用 teacher forcing |
| FDM (前向动力学) | z_t, a_t | 预测 z_{t+1} | 异步分支 | 仅推理时使用，用于 grounding |

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **自回归而非分块双向**：物理世界是因果的——当前状态只依赖过去。双向注意力允许未来 token 影响过去预测，违反因果性，导致长视距不一致。

2. **视频 - 动作交错序列**：将视频 token 和动作 token  interleaved 成单一序列 `[z_t, a_{t,1}, ..., a_{t,τ}, z_{t+1}, ...]`，使两者能互相条件化，同时保持概念分离（视频流预测动力学，动作流解码逆动力学）。

3. **非对称 MoT 架构**：视频流用 Wan2.2-5B 初始化（d_v=3072），动作流宽度 d_a=768（4× 更小）。动作分布比视觉数据简单，无需同等参数量。

4. **Noisy History Augmentation**：训练时以 50% 概率对历史 z_≤t 添加噪声（s_aug ∈ [0.5, 1.0]），使动作解码器能从部分去噪的视频表示中提取信息，推理时视频积分步数减半（s=0→0.5 而非 s=0→1.0）。

⚡ **Eureka Moment**：这篇论文最核心的想法是——**世界模型和策略不需要是两个独立模块，它们可以是同一个自回归生成过程的两个输出流**。视频流"想象"未来视觉状态，动作流"解码"实现该状态所需的动作，两者共享 KV-cache 记忆和因果注意力掩码。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
视频动力学：z_{t+1:t+K} ~ p_θ(· | z_≤t, a_<t, c)
动作逆动力学：a_{t:t+K-1} ~ g_ψ(· | z_{t+1:t+K}, z_≤t, a_<t, c)
```

**目标**：学习两个条件流匹配（Conditional Flow Matching）过程——一个预测未来视觉状态的演变，另一个从预测的视觉转变中解码动作。

**公式详解**：

```
视频动力学损失：
L_dyn = E_{t,s,z_{t+1},ε}[ ||v_θ(z_{t+1}^{(s)}, s, z̃_≤t, a_<t | c) - ż_{t+1}^{(s)}||² ]

动作逆动力学损失：
L_inv = E_{t,s,a_t,ε}[ ||v_ψ(a_t^{(s)}, s, z̃_≤t+1, a_<t | c) - ȧ_t^{(s)}||² ]

总目标：L = L_dyn + λ·L_inv  (λ=1)
```

**变量说明**：

| 符号 | 含义 | 维度/范围 |
|------|------|-----------|
| z_t | t 时刻的视频潜在 token | R^{192×C}, C=3072 |
| a_t | t 时刻的动作向量 | R^{30} (双臂各 15 维) |
| s | 流匹配时间 | [0, 1] |
| z^{(s)} | 流轨迹上的插值 | (1-s)·ε + s·z_1 |
| z̃_≤t | 带噪声增强的历史 | 50% 概率添加噪声 |
| c | 文本指令嵌入 | T5 编码 |
| v_θ, v_ψ | 速度场预测网络 | 视频/动作流 Transformer |

**直觉**：流匹配学习一个向量场 v(x, s)，描述粒子如何从噪声 ε 流向数据 x_1。视频流学习"视觉状态如何随时间演变"，动作流学习"什么动作能产生期望的视觉转变"。两者共享历史上下文，但优化目标分离。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有一个简化的 2D 抓取任务：

**场景**：机械臂需要从位置 A 移动到位置 B 抓取物体。

**推理步骤**（K=4, τ=4）：

```
t=0: 观测 o_0 → 编码为 z_0 (192 tokens)
     KV Cache = {z_0}

t=0→1: 视频流预测 z_1:z_4
       - 从噪声 ε 开始，积分 s=0→0.5 (3 步 Euler)
       - 条件：KV Cache + 文本"抓取红色方块"
       - 输出：4 个未来帧的潜在表示

       动作流预测 a_0:3
       - 从噪声 ε 开始，积分 s=0→1.0 (10 步)
       - 条件：z_0:4 (预测的) + KV Cache
       - 输出：4 个动作向量 (每个 30 维)

执行 a_0，接收真实观测 o_1 → 编码为 z_1_real

t=1: FDM Grounding 步骤
     - 用 z_0 和 a_0 预测"应该看到什么"：z̃_1 = FDM(z_0, a_0)
     - 比较 z̃_1 和 z_1_real，若差异大则更新 KV Cache 用 z_1_real 替代
     - 这防止模型"继续幻觉"而忽略真实反馈

     KV Cache 更新：{z_0, a_0, z_1_real}
     重复预测 z_2:5 和 a_1:4
```

**关键数值**：

- 视频 token 数：192 tokens/帧 × 4 帧 = 768 tokens
- 动作 token 数：4 动作 × 1 (投影后) = 4 tokens
- 视频去噪步数：3 步 (s=0→0.5)
- 动作去噪步数：10 步 (s=0→1.0)
- KV Cache 复用：每步节省约 80% 的注意力计算

## 4. 工程视角 (Engineering View)

**吞吐/延迟/部署约束**：

| 指标 | 数值 | 含义 |
|------|------|------|
| 模型大小 | 5.3B 参数 | 视频流 5B + 动作流 350M |
| 推理 VRAM | ~24GB (单 GPU, offload 模式) | VAE 和 text encoder 可卸载到 CPU |
| 控制频率 | 12.5 Hz (视频 50Hz 下采样 4×) | 动作频率保持 50Hz |
| 延迟 (同步) | ~800ms/chunk | 不可接受用于实时控制 |
| 延迟 (异步) | ~400ms/chunk | 通过并行预测 + 执行实现 |
| Post-training 数据 | 50 条演示 | 3K steps @ lr=1e-5 |

**Trade-off 分析**：

1. **Chunk Size K**：K 越大，自回归步数越少（效率高），但每步计算量越大且闭环校正频率越低。论文用 K=4 作为折中。

2. **部分去噪**：视频积分到 s=0.5 而非 s=1.0，去噪步数减半，但动作预测质量几乎不受影响（因为动作解码器训练时见过带噪声的历史）。

3. **异步 vs 同步**：异步推理速度快 2×，但需要 FDM-grounding 步骤防止漂移。 naive 异步（无 FDM）成功率从 90.4% 降至 74.3%（Table 3）。

**部署建议**：

- 实时控制必须用异步流水线 + FDM grounding
- 资源受限时可 offload VAE 和 text encoder 到 CPU（显存从 24GB 降至 18GB）
- Post-training 可用高学习率 (1e-4) + 1K steps 快速适配，但性能略低于 3K steps 方案

### 6.1 隐含假设 (Hidden Assumptions)

**X-Ray 批判视角**：

1. **动作编码绝对位姿**：论文假设动作历史 a_<t 编码了机械臂的构型轨迹（因为动作包含末端执行器位姿）。这对绝对位姿控制的机器人成立，但对关节速度/力控的机器人可能不适用。

2. **视频 VAE 时间一致性**：Wan2.2 VAE 是因果的，但压缩过程中的信息损失可能影响长视距预测。论文未分析 VAE 瓶颈的影响。

3. **异步推理的 FDM 可靠性**：FDM-grounding 假设前向动力学预测比开放环幻觉更可靠。但在快速动态场景中，FDM 本身可能有延迟/误差。

4. **双臂 30 维动作表示**：统一动作接口假设所有机器人可映射到 30 维（双臂各 7EEF+7 关节 +1 夹爪）。对非双臂或冗余自由度机器人需额外处理。
