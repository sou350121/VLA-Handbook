### 1.2 关键机制 (Key Mechanism)

VIM 的核心设计围绕两个关键问题：

1. **如何生成互补视点？** 利用世界模型的生成先验——如果模型能从一个视点"想象"出另一个视点的图像，说明它已经学到了跨视点的空间对应关系。这种生成能力被转化为感知补全能力。

2. **如何让生成的视点对动作预测有用？** 不是简单地把生成图像拼接到输入中，而是将视觉 token 和动作 token 放在同一个自回归序列中：先生成互补视点的视觉 token，然后以这些 token 为条件预测动作 token。这样，想象视图成为感知到策略之间的"中间推理步骤"。

⚡ **Eureka Moment**：生成即理解——如果模型能从被遮挡的主视点生成合理的互补视点，这个生成过程本身就编码了跨视点空间推理，可以直接桥接遮挡感知与动作生成。

## 2. 数学核心 (Math Core)

### 2.1 标准 VLA 公式（基线）

标准 VLA 将操作建模为从观察到动作的条件分布：

```
p_θ(a_t | o_t, l)
```

其中 o_t 是主视点观察，l 是语言指令，a_t 是动作 chunk。这个公式隐含假设 o_t 包含足够的任务相关信息。

### 2.2 VIM 公式（本文）

VIM 引入互补视点作为中间变量，将联合分布分解为：

```
p_θ(o^c_t, a_t | o_t, l) = p_θ(o^c_t | o_t, l) · p_θ(a_t | o_t, o^c_t, l)
```

- 第一项：从被遮挡的主视点生成互补视点（视点想象）
- 第二项：以观察到的主视点和想象的互补视点为条件预测动作

### 2.3 训练目标

两阶段训练：

**Stage 1** — 视点想象预训练：
```
min_θ  L_view = CrossEntropy(视觉 token 生成)
```

**Stage 2** — 联合优化：
```
min_θ  L = L_action + λ · L_view
```

其中 L_action 是动作预测损失，L_view 是互补视点生成损失，λ = 0.5 用于平衡两组 token（视觉 token 通常远多于动作 token）的组间损失权重。

📌 **Napkin Formula**（一行抓住本质）：
```
想象看不见的 + 看到已见的 → 更好地行动
```

> 符号说明：o_t = 主视点观察（被遮挡）；o^c_t = 生成的互补视点；o_t^c = 真实互补视点（Ground Truth）；l = 语言指令；a_t = 动作 chunk；θ = 模型参数；λ = 阶段 2 损失权重系数（固定为 0.5）。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 LIBERO-Occ 任务：**"把红色方块放进蓝色碗里"**，但红色方块被一个绿色圆柱体部分遮挡。

**场景参数（假设值）：**
- 主视点：固定第三人称相机
- 遮挡严重度 S_occ = 0.62（62% 的方块面积被遮挡）
- 互补视点：腕部/夹爪相机（能看到方块顶部）

**标准 VLA 的困境：**
```
输入: o_t = [第三人称图像，方块仅 38% 可见]
      l = "把红色方块放进蓝色碗里"
输出: p_θ(a_t | o_t, l) → 抓取位置高度不确定
成功率: ~35%（Object suite 中位水平）
```

**VIM 的解决路径：**
```
Step 1 — 视点想象:
  输入: o_t (被遮挡的第三人称) + l
  生成: o^c_t = [腕部视角图像，方块顶部完全可见]
  直觉: 模型通过跨视点空间推理，"想象"出从上方看方块的样子

Step 2 — 动作预测:
  输入: o_t (原始) + o^c_t (想象) + l
  输出: p_θ(a_t | o_t, o^c_t, l) → 精确的抓取坐标
  成功率: ~78%（接近 VIM 在 Object suite 的实际表现 74.6%）
```

**损失计算示例（Stage 2）：**
```
L_view = -Σ_i log p_θ(视觉 token_i | o_t, l)    ≈ 2.3（token 级交叉熵）
L_action = -Σ_j log p_θ(动作 token_j | o_t, o^c_t, l) ≈ 1.8
L = 1.8 + 0.5 × 2.3 = 2.95
```

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/描述 | 含义 |
|----------|-----------|------|
| **训练硬件** | 8×H100 GPU | 高门槛；需要大规模并行训练 |
| **Batch Size** | 192 | 大 batch 对显存和通信有要求 |
| **学习率** | Stage 1: 8e-5; Stage 2: 4e-5 | 阶段 2 减半，符合联合优化惯例 |
| **Backbone** | Emu3-MoE（MoE 架构） | 混合专家模型，推理时激活部分参数 |
| **动作 Tokenizer** | FAST | 将连续动作离散化为 token，便于自回归建模 |
| **推理延迟增加** | 额外生成互补视点 token | 自回归模型需额外前向步数；具体数值论文未给出 |
| **部署硬件要求** | 单相机（与标准 VLA 相同） | 核心优势：无需额外相机或主动视点控制 |
| **GT 互补视点模式** | 若有真实互补相机，可直接替换生成视图 | 统一接口支持相机辅助和纯想象两种部署模式 |

**工程含义**：VIM 的核心 trade-off 是用训练阶段的额外计算（两阶段训练 + 多视点数据）换取部署阶段的硬件简洁性（单相机）。对于已有世界模型能力的团队（如使用 UniVLA），迁移成本较低；但对于从零开始的团队，8×H100 的训练成本是显著门槛。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 6.1 能做什么

| 场景 | 表现 | 原因 |
|------|------|------|
| 轻度遮挡 | 接近无遮挡性能 | 部分视觉线索仍可用，想象视图补充剩余信息 |
| 重度遮挡 | 显著优于基线 | 想象视图恢复关键空间证据，基线几乎完全失效 |
| 容器遮挡 | 成功率较高 | 放置操作对空间精度要求相对较低 |
| 被操作物体遮挡 | 中等 | 抓取需要精确定位，想象视图帮助但有限 |
| 双重遮挡 | 最具挑战性 | 物体和容器同时不可见，需同时推断两端 |
| LIBERO-10 长程任务 | 保持相对优势 | 想象视图在长序列中持续提供补充信息 |

### 6.2 不能做什么 / 失败模式

| 失败模式 | 场景 | 原因 |
|----------|------|------|
| 想象视图质量不足 | 高度非常规遮挡 | 世界模型未见过的遮挡配置可能导致错误想象 |
| 格式崩溃 | 移除 Stage 2 视图损失 | 输出 token 退化为非视觉文本/特殊 token，无法形成有效视觉网格 |
| 跨视图对应失败 | 移除 Stage 1 预训练 | 模型未学到可靠的跨视图空间对应，直接联合优化不够 |
| 仿真到现实差距 | 真机部署 | 所有实验在 LIBERO 仿真中完成，真实世界的传感器噪声、光照变化未覆盖 |
| 单一相机限制 | 极端遮挡 | 当主视点几乎看不到任何任务相关信息时，想象可能完全错误 |

### 6.3 隐含假设 (Hidden Assumptions)

1. **世界模型已学到跨视点空间对应** — VIM 依赖预训练世界模型（UniVLA）的生成先验。如果世界模型从未见过类似的视点配置组合，想象质量无法保证。论文未对世界模型的跨视点泛化能力做独立评估。

2. **遮挡物不改变任务语义** — LIBERO-Occ 的生成流程确保遮挡物与任务物体无语义重叠。但真实场景中，遮挡物可能是任务相关物体的一部分（如打开抽屉后抽屉本身成为遮挡），这种动态遮挡未覆盖。

3. **互补视点（腕部/夹爪）包含足够信息** — 论文固定使用腕部视图作为互补视点。对于某些任务（如需要全局场景理解的长程任务），腕部视图可能不够；对于另一些任务，可能需要多个互补视点。

4. **仿真环境足够真实** — 所有评估在 MuJoCo 仿真中进行。真实世界的传感器噪声、光照变化、物体形变等未建模。
