## 1. 核心架构/方法总览 (Overview / Architecture)

SWEET 是一个两阶段框架：**图像编辑规划器** + **目标条件动作预测器**。

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 训练方式 | 推理角色 |
|------|------|------|----------|----------|
| 图像编辑规划器 | 当前关键帧 k_m + 文本指令 l_m + 可选箭头 r_m | 下一关键帧 $k_{m+1}$ | FLUX-Kontext + LoRA (rank=32), 6K steps, AdamW lr=1e-4 | 开环生成稀疏关键帧序列 |
| 目标条件动作预测器 | 当前观测 $o_t$ + 目标关键帧 $k_{m+1}$ | 动作块 A_t:t+H-1 (H=16) | Diffusion Policy, DDPM loss, AdamW lr=1e-4, batch=32 | 闭环追踪每个子目标 |
| 混合训练模块 | 编辑关键帧 + 真实关键帧 (1:1) | 动作标签 (不变) | 同上，但 batch 内各 50% | 训练时桥接域 gap，推理时不额外开销 |

### 1.2 关键机制 (Key Mechanism)

**为什么用图像编辑而不是视频生成？**

论文首先做了一个受控对比：在相同机器人数据下，分别微调 Wan2.2（视频生成）和 FLUX-Kontext（图像编辑）。结果发现：

- **视觉保真度**: FLUX-Kontext 在 RoboMimic 上 MSE=0.01114 vs Wan2.2 的 0.01777（降低 37%）
- **结构一致性**: SSIM 0.9119 vs 0.8563（+6.4%）
- **感知相似度**: LPIPS 0.078 vs 0.130（-40%）
- **推理效率**: 10 秒 vs 400 秒（**快 40 倍**）

Wan2.2 的四个典型失败模式：
1. **不可行抓取**——夹爪没有形成物理上有效的接触
2. **物体形变**——被操作物体形状或身份发生变化
3. **机械臂形变**——机器人臂或夹爪结构扭曲
4. **物体瞬移**——物体在不连续帧之间出现位置跳跃

⚡ **Eureka Moment**：对于机器人操作任务，稀疏关键帧预测比密集视频生成更可靠、更高效——因为任务本质就是几个语义里程碑，不需要中间帧。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
K_hat = E_θ(o_0, C)     →    A_hat_t = π_φ(o_t, k_{m+1})
   稀疏视觉规划                   目标条件动作执行
```

**目标**: 将机器人操作轨迹分解为稀疏关键帧序列，先规划视觉子目标，再预测可执行动作。

**公式 1 — 图像编辑规划器**:
```
k_hat_{m+1} = E_θ(k_m, l_m, r_m)
```
- k_m: 当前关键帧（RGB 图像）
- l_m: 子任务文本描述（如"移动 toward 物体"）
- r_m: 可选箭头空间提示（粗粒度 gripper 运动方向）
- $E_\theta$: FLUX-Kontext + LoRA 微调的参数化编辑函数

**公式 2 — 目标条件动作预测器**:
```
A_hat_t = π_φ(o_t, k_hat_{m+1})
```
- o_t: 当前环境观测
- k_hat_{m+1}: 规划器生成的目标关键帧
- $\pi_\varphi$: Diffusion Policy，输出 $H=16$ 步动作块
- 训练损失: 标准 DDPM 去噪损失 L_act

**公式 3 — 混合训练目标**:
```
φ* = argmin_φ E[(1-b)·L_act(o_t, k_{m+1}, A^H_t) + b·L_act(o_t, k_tilde_{m+1}, A^H_t)]
```
- b ~ Bernoulli(0.5): 随机选择真实或编辑关键帧作为条件
- k_tilde_{m+1}: 规划器生成的编辑目标关键帧
- 动作标签 $A^H_t$ 保持不变（物理动作不随视觉域变化）

> 符号说明: 本文使用 $\theta$ 表示规划器参数，$\varphi$ 表示动作预测器参数，$H=16$ 为动作视界，$M$ 为关键帧数量，$K$ 为关键帧序列。

## 3. 带数字走一遍：玩具例子 (Worked Example)

以 RoboMimic 的 Lift 任务为例，假设轨迹被标注为 3 个关键帧：

```
关键帧序列:
  k_0: 初始状态 (夹爪打开，物体在桌上)
  k_1: 接触状态 (夹爪接近物体)
  k_2: 抓取状态 (夹爪闭合，抓住物体)
  k_3: 抬起状态 (物体被提起)

规划器推理 (开环):
  k_1 = E_θ(k_0, "移动 toward 物体", 箭头指向物体)
  k_2 = E_θ(k_1, "闭合夹爪", 无箭头)
  k_3 = E_θ(k_2, "抬起物体", 箭头向上)

假设规划器输出质量 (基于论文 Table 1 的合理假设值):
  MSE(k_1) ≈ 0.008, SSIM(k_1) ≈ 0.93
  MSE(k_2) ≈ 0.012, SSIM(k_2) ≈ 0.90
  MSE(k_3) ≈ 0.015, SSIM(k_3) ≈ 0.88

动作预测器执行 (闭环):
  步骤 1: o_0 + k_1 → A_0 (16 步) → 执行 → o_16
  步骤 2: o_16 + k_1 → A_1 (16 步) → 执行 → o_32  (如果 k_1 未达到)
  步骤 3: o_32 + k_2 → A_2 (16 步) → 执行 → o_48
  步骤 4: o_48 + k_3 → A_3 (16 步) → 执行 → o_64

论文结果 (Table 2, Lift 任务):
  Mix-trained 成功率: 92.0% (生成关键帧) / 92.0% (真实关键帧)
  动作预测 MSE: 0.0141 (生成) / 0.0145 (真实)
  → 混合训练使两种域的表现几乎一致！
```

## 4. 工程视角 (Engineering View)

| 维度 | 数值 | 工程含义 |
|------|------|----------|
| 规划器训练 | 6K steps, 单卡 H20, LoRA rank=32 | 轻量微调，无需全参数训练；FLUX-Kontext 基础模型冻结 |
| 规划器推理 | ~10 秒 / 3 关键帧 | 可接受的前端延迟；用户可在 10 秒内看到完整规划 |
| 动作预测器推理 | H=16 步/块，迭代去噪 | 每块需完整 diffusion 去噪循环（通常 50-100 步） |
| 视频生成基线 | ~400 秒 / 81 帧 | 40 倍差距——密集视频生成在实际部署中不可行 |
| 训练数据量 | DROID: 700 samples / RoboMimic: 600 samples | 数据量较小——这是当前 VLA 领域的典型规模 |
| 混合训练开销 | 推理时 0 额外开销 | 训练时生成编辑关键帧的额外计算是一次性的 |

**部署约束**:
- 当前为 one-shot 规划（生成一次关键帧序列后执行），不支持在线重规划
- 每个子目标闭环追踪——如果环境变化导致子目标偏离，预测器会基于新观测继续追踪同一目标
- 对于长程任务，需要扩展为 feedback-enabled replanning（论文明确列为未来工作）

### 标注方式

- **文本描述**: 人工标注子任务级语义变化
- **箭头空间提示**: 人工标注（2D gripper 运动方向 + 夹爪状态颜色编码）
- **VLM 替代测试**: Gemini-3 可以标注箭头但关键帧提取不可靠

### 评测指标
- **关键帧质量**: MSE ↓, PSNR ↑, SSIM ↑, LPIPS ↓
- **执行质量**: 任务成功率 (%) + 末端执行器位置 MSE
- **效率**: 推理时间（秒）

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **稀疏关键帧预测**: 在 seen/unseen 场景下均优于视频生成基线
- **端到端执行**: 从语言指令 → 关键帧规划 → 可执行动作的完整管线
- **域鲁棒性**: 混合训练使动作预测器对真实/编辑关键帧表现一致
- **空间引导**: 可选箭头提示提供粗粒度空间信息（可由 VLM 或用户生成）

### 不能做什么
- **密集视频生成**: 本文不生成中间帧——如果需要连续视频，此方法不适用
- **长程多步任务**: 当前评估限于短视距任务（3-4 个关键帧）
- **在线重规划**: one-shot 规划，执行中不根据新观测调整关键帧序列
- **零样本泛化**: 需要针对目标任务微调 FLUX-Kontext LoRA

### 6.1 隐含假设 (Hidden Assumptions)

1. **关键帧数量已知**: 推理时需要预先指定编辑步数（RoboMimic Lift=2步, Can/Square=3步, DROID=3步）。如果任务复杂度变化，这个超参需要手动调整。

2. **子任务文本描述可用**: 规划器需要每个关键帧转换的文本描述。论文假设这些可以由 VLM 生成或用户输入，但没有评估 VLM 生成文本的质量对规划的影响。

3. **动作标签跨域不变**: 混合训练假设真实和编辑关键帧共享相同的动作标签。这在物理上合理（动作是环境交互，不依赖视觉域），但忽略了编辑关键帧可能暗示不同的物理状态。

4. **短视距假设**: one-shot 规划在短任务中可行，但论文明确承认长程任务需要 feedback-enabled replanning。
