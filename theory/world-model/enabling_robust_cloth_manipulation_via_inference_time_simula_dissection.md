## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 训练/推理 | 角色 |
|------|------|------|-----------|------|
| 先验策略 (base policy) | 稀疏布料状态 | 末端动作序列 U_bar (H 步) | 离线：在 FLASH 内对脚本教师做 on-policy 模仿蒸馏；512/256/128 MLP，每件衣物一个 | 提供任务级先验，不直接执行 |
| Real-to-Sim 估计器 f_θ | 单张 RGB I_t | 顶点位置 s_hat = {p̂_i}，i=1..N | 纯合成数据训练；DINOv2 冻结 + 可学习 canonical tokens | 把真实现场提升为仿真兼容状态 |
| FLASH 仿真后端 | 状态 x_t=(q,q̇)、动作 a_t | 下一步状态 x_{t+1} | 无需训练（物理引擎） | 推理期前向模型 + 合成数据源 |
| 先验引导 MPPI | s_hat、U_bar、代价 c | 精修动作序列 U* | 在线，无训练 | 用并行物理 rollout 打分并重加权 |
| 执行器 | U*[0] | 新一轮观测 I_{t+1} | 硬件 | 滚动时域（receding-horizon）闭环 |

### 1.2 关键机制 (Key Mechanism)

- **为什么直接把仿真器当前向模型**：直接 rollout 免去了「任务/资产专用动力学训练」，也消除了学习式预测器带来的额外近似误差，可跨不同布料资产复用（论文 §1 明确对比了学习式动力学路线）。
- **为什么状态估计只预测位置**：单帧 RGB 本就不含速度信息，把速度置零既唯一自洽，又让 K 条候选 rollout 共享同一初态——代价差异只反映采样的动作本身（§3.2）。
- **为什么用先验引导而非无引导采样**：高维形变 + 非凸几何目标让无引导采样低效（论文引述此前工作常退化为开环原语）；把 U_bar 当提案中心，采样 U_bar + N(0,Σ)，大幅缩小探索空间。
- **为什么需要 sparse-mesh**：为在有限控制预算下保证足够多的并行 rollout 批量（K），牺牲一部分网格粒度换吞吐，同时保留操作相关的形变与接触。
- **工程细节**：MPPI rollout 期间关闭自碰撞，以换取采样效率（项目页 Highlights）。

⚡ **Eureka Moment**：**可形变物仿真器本身就该被当作推理期的 forward model**——你不用再为布料学一个动力学网络，只需解决「把真实布料对齐进仿真」这唯一一座桥（real-to-sim），剩下的交给物理引擎 + 采样优化。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
每步:  s_hat = f_θ(I_t);  U* = Σ_k w_k · (U_bar + ε_k);  执行 U*[0]
       其中 w_k ∝ exp(-S(FLASH(s_hat, U_bar+ε_k)) / λ)
```

**总目标**：给定单帧 RGB 与先验策略，在线求一段能完成折叠、又不过度越界的动作序列。

**(1) 状态估计（real-to-sim）**

```
s_hat_t = f_θ(I_t),   s_hat_t = { p̂_{t,i} },  p̂_{t,i} ∈ R^3,  i = 1..N
```

**(2) 视觉-顶点对齐（网络核心）**

```
V_t = P( Φ_DINO(I_t) )                    # 冻结 DINOv2 → 线性投影到维度 d
Z_t = SelfAttn([ C ; V_t ])_{1:N}         # N 个可学习 canonical token 与视觉 token 联合自注意力
p̂_{t,i} = D_θ(Z_{t,i})                    # 共享解码器输出每个材质顶点 3D 位置
```

**(3) 训练损失**

```
L_r2s = (1/N) · Σ_i  smoothL1( p̂_i , p*_i )
```

**(4) 仿真前向步**

```
x_{t+1} = F(x_t, a_t),   x_t = (q_t, q̇_t)
同步时:  q_t ← s_hat_t,  q̇_t ← 0
```

**(5) MPPI 重加权与精修**

```
U_t^(k) = U_bar_t + ε^(k),   ε^(k) ~ N(0, Σ),   k = 1..K
τ_t^(k) = F_{0:H}( s_hat_t, U_t^(k) )
w_k = exp(-S(τ_t^(k))/λ) / Σ_j exp(-S(τ_t^(j))/λ)
U_t* = Σ_k w_k · U_t^(k),   执行 a_t* = U_t*[0]
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| I_t | 第 t 步单张 RGB 观测 |
| f_θ | real-to-sim 估计器（θ=投影层 P + canonical tokens C + 注意力 + 解码器 D_θ）|
| N | 衣物网格材质顶点数（464 毛巾 ~ 1379 长袖）|
| C | N 个可学习 canonical token，编码每个材质点的身份与规范位置 |
| F | FLASH 仿真一步算子；F_{0:H} 为 H 步 rollout |
| U_bar_t | 先验策略在 horizon H 上产出的标称动作序列 |
| Σ | 局部探索尺度（采样协方差）|
| S(τ) | 任务代价（折叠目标 + 工作空间/穿桌/动作平滑等正则）|
| λ | MPPI 温度 |
| K | 每步并行 rollout 数（= 候选动作序列数）|

> 符号与本文一致：q 为顶点位置，q̇ 为顶点速度；所有公式均为纯文本/代码块表达，无 LaTeX。

**直觉**：先验策略给一个「大概率对」的动作中心，MPPI 在它周围撒 K 个扰动，用物理引擎快速「预演」每个扰动 0 到 H 步之后的布料形态，按代价好坏给指数权重平均——好动作被保留、坏动作被压掉，且每次只执行第一步。

## 3. 带数字走一遍：玩具例子 (Worked Example)

> 用论文的真实设置量级，但用假设数值演示 MPPI 一步（数字为演示用途，非论文实测）。

设某折中步骤 K = 4，先验给出 2 个关键通道的标称动作 U_bar = (抓点 x 位移, 抬起高度) = (0.10 m, 0.03 m)，λ = 0.05。采样 4 个扰动（单位 m）：

| k | ε 扰动 (Δx, Δz) | 候选动作 U^(k) | FLASH rollout 代价 S | 权重 w_k |
|---|------------------|----------------|----------------------|----------|
| 1 | (+0.02, 0.00) | (0.12, 0.03) | 0.30 | 0.50 |
| 2 | (-0.01, +0.02) | (0.09, 0.05) | 0.36 | 0.30 |
| 3 | (+0.03, -0.05) | (0.13, -0.02) | 0.60 | 0.10 |
| 4 | (-0.04, -0.03) | (0.06, 0.00) | 0.62 | 0.10 |

权重（w_k ∝ exp(-S/λ)）：

```
exp(-0.30/0.05)=0.00248 ; exp(-0.36/0.05)=0.00075
exp(-0.60/0.05)=6.1e-6  ; exp(-0.62/0.05)=4.1e-6
归一化 ≈ (0.77, 0.23, 0.002, 0.001) → 上面的示例权重
```

精修动作：

```
U* = 0.77·(0.12,0.03) + 0.23·(0.09,0.05) + 0.002·(0.13,-0.02) + 0.001·(0.06,0.00)
   ≈ (0.113, 0.035)
```

**可计算闭环**：机器人只执行 U*[0] 的 (Δx≈0.113, Δz≈0.035) 这一步，拿到新 RGB，重估状态，重新撒扰动。误差在接触里被逐步压回——这正是论文实测中「42.2 cm 抓取误差 → 22~31 步后 0.8 cm」的机制来源（论文 Appendix C.3，20 seeds 中 18/20 达标）。

## 4. 工程视角 (Engineering View)

| 指标 | 数值（论文实测，除非注明）| 工程含义 |
|------|--------------------------|----------|
| FLASH 单步时间 | 19.4 ms (K=64) → 137.3 ms (K=512) | 每步物理成本随并行环境数近似线性增长 |
| 单批 MPPI 时间 | 0.40 s (K=64) → 2.84 s (K=512) | **K 直接决定闭环控制率**；K=512 时每步近 3 秒，控制频率掉到亚 Hz |
| 估计器单帧延迟 | 7.4 ms (毛巾) / 12.4 ms (长袖) | 比 DPM 基线（318~513 ms）快 1~2 个数量级，感知不是瓶颈 |
| 同条件比 Isaac Sim | 单步 1.5~1.9× 更慢，但 SR 95~100% vs <60% | 「每步快」不等于「闭环能成」——保真度不够会拖垮规划 |
| 收敛步数 | 22~31 步（仿真 20 seeds）| 报告级实机折叠一次数十步 |
| 扰动恢复 | 6/9/12 cm 扰动后 4.0/4.1/6.0 步恢复 | 闭环纠错速度与扰动幅度近似正相关 |

**Trade-off 语言**：
- **吞吐 vs 多样性**：K 越大采样越充分，但 rollout 批量壁钟时间线性上升，控制率被单卡 GPU 预算锁死。论文明确指出「可形变动力学远比刚体难并行」，这是本路线最硬的部署约束。
- **保真 vs 速度**：Isaac Sim 单步更快但求解器在实时每步迭代预算内跟踪不到受控顶点 → MPPI 步数耗尽仍到不了目标（项目页 Clarification）。选后端不能只看步时。
- **粒度 vs 批量**：sparse-mesh 主动降网格粒度，就是为了在预算内塞下足够 K。
- **准静态约束**：速度置零 → 只适合「慢折」场景，动态甩布（如 FlingBot 式的动态展开）不适用。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做**：
- 单张 RGB、无真实标注的状态估计下，实现真实布料折叠的闭环纠错（单臂 9/10，双臂 8/10）。
- 折中过程被人为扰动后，闭环恢复（扰动 6/9/12 cm → 4.0/4.1/6.0 步回到扰动前水平）。
- 跨衣物资产和折叠变体迁移（长袖 8/10、短裤 7/10、反向对角 8/10），**无需额外动力学重训**。

**不能做 / 失败模式**：
- **不是通用策略**：基础策略仍是每件衣物在 FLASH 内蒸馏的 512/256/128 MLP，先验质量决定上限。
- **准静态限制**：速度被强制置零，动态操作不适用（论文 §6 明说）。
- **材质单一**：所有评测衣物都是厚度相近的编织织物，未验证跨材质类。
- **场景受限**：仅固定俯视相机下的桌面折叠。
- **组件强耦合**：实机替换任一模块（估计器/后端/控制器）都显著掉点——DPM 估计器 6/10 与 3/10；Isaac Sim 5/10 与 4/10；裸策略 3/10 与 1/10（Table 3）。说明这套系统「一起才好用」。

### 6.1 隐含假设 (Hidden Assumptions)

- **单帧 RGB 足以决定状态**：假设布料当前形变可由一张图无歧义恢复（严重自遮挡场景下是否成立未充分压测）。
- **速度置零无害**：仅在准静态且被评测的折叠动作下成立，作者自己标注为局限。
- **相机标定与渲染一致**：合成数据相机位姿「matched to calibrated real setup」，暗示标定误差会直接转化为 sim-real 落差。
- **quasi-static + 自碰撞关闭**：MPPI rollout 关自碰撞以提效，假设折叠中自碰撞不影响决策质量（真实折叠是否总成立存疑）。
- **每件衣物可重建 rest-shape 网格**：依赖 SAM 2 分割 + 深度反投影的质量，薄织物深度不佳时该前提会先崩塌。
