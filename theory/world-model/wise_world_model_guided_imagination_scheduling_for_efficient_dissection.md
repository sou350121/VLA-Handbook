## 1. 核心架构/方法总览 (Overview / Architecture)

WISE 是一个四模块协调的想象-评估-优化闭环：

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 训练方式 | 推理频率 |
|------|------|------|----------|----------|
| **想象调度器** (Scheduler) | 手腕+第三人称视觉观测 | 交互相关分数 s_t ∈ [0,1] | 弱监督（从机器人执行信号提取） | 每步都跑（轻量） |
| **世界模型** (World Model) | 当前观测+语言指令+候选动作 | H 帧未来多视角预测 | Rectified Flow 训练（冻结） | 仅在调度器触发时 |
| **奖励模型** (Reward Model) | 预测的多视角观测序列 | 进度/置信度/完成度三路信号 | 独立训练（DINOv2 + 3 heads） | 每次想象 rollout 后 |
| **策略优化** (Policy Refinement) | M 个候选动作的相对奖励 | 策略梯度更新方向 | Flow Matching + 参考正则 | 每个调度态一次 |

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？** 核心问题是"想象力分配"——世界模型推理成本高昂，且长 horizon 的闭环 rollout 会累积预测误差。WISE 的三个设计决策：

1. **何时想象**：调度器用 DINOv2 编码双视角视觉，轻量 head 输出交互相关分数，超过阈值 κ 才触发。这避免了在"VLA 已经能处理好的粗粒度运动阶段"浪费算力。
2. **想象多远**：有界多步 rollout（L 个 action chunk，每 chunk 预测 H 帧），限制累积误差范围。
3. **如何用想象**：想象只用于**反事实评估**（比较候选动作的相对优劣），不直接用于合成数据监督。更新信号锚定在真实交互上下文中的第一个 action chunk。

⚡ **Eureka Moment**：世界模型的价值不在于预测多准，而在于"在正确的状态、以正确的范围、转化为正确的学习信号"——想象调度比世界模型本身更关键。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
R_i = G_i - α·B_i + β·T_i    →    相对优势 A_i 标准化 → 符号梯度方向
```

**目标**：最大化任务成功率 E[y(τ, ℓ)]，但不用真实环境探索，而是用世界模型的反事实预测来评估候选动作。

**核心方程分解**：

**进度增益 G_i**（正向进展的累计）：
```
G_i = Σ_j c_{i,j} · [p_{i,j} - p_{i,j-1}]_0^δ
```
- c_{i,j}：置信度权重（抑制不确定预测的进度信号）
- [·]_0^δ = clip(x, 0, δ)：只计正向进步，上限 δ
- p_{i,j}：第 j 帧的进度分数

**后退惩罚 B_i**（退步的累计）：
```
B_i = Σ_j [p_{i,j-1} - p_{i,j}]_0^δ
```
- 惩罚轨迹回退，抑制"先好后坏"的候选

**完成度 T_i**：
```
T_i = max_j q_{i,j}
```
- 取整个轨迹中的最高完成度分数

**总奖励**：
```
R_i = G_i - α·B_i + β·T_i
```
- α, β 是超参，平衡进度、后退和完成度

**相对优势标准化**：
```
A_i = (R̄_i - μ_R̄) / max(σ_R̄, ε)
```
- R̄_i 是两次想象的平均奖励（论文对每个候选想象两次取平均）
- μ_R̄, σ_R̄ 是组内均值和标准差

**策略更新方向**：
```
g_WISE = (1/M) Σ_i sgn(A_i) · ∇_θ L_FM(θ; a_{t,i}, h_t) + λ_ref · ∇_θ L_ref
```
- 只取优势的**符号**（类似 GRPO 的 group-relative 思想）
- L_FM 是 Flow Matching 损失
- L_ref 是参考策略正则（防止偏离太远）
- **关键约束**：只有来自真实上下文的第一 chunk a_{t,i} 被用于策略更新；想象 rollout 仅用于评估

> 符号说明：θ 为策略参数；ψ 为世界模型参数（冻结）；φ_s / φ_r 分别为调度器/奖励模型的 DINOv2 编码器参数；η 为调度器 head 参数；ω 为奖励模型参数。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 Stack 任务场景，调度器在 t=15 步触发想象（s_15 = 0.78 > κ=0.5）。

**Step 1: 采样 4 个候选动作**
```
a_{t,1}: 夹爪闭合 → 物体被抓起
a_{t,2}: 夹爪半开 → 物体滑动
a_{t,3}: 夹爪全开 → 未接触物体
a_{t,4}: 夹爪闭合+微抬 → 物体被抓起并抬高
```

**Step 2: 世界模型对每个候选做 L=2 chunk 的闭环 rollout**
- 每个 chunk 预测 H=16 帧 → 总共 32 帧反事实轨迹

**Step 3: 奖励模型评估（假设数值）**

| 候选 | G_i (进度增益) | B_i (后退惩罚) | T_i (完成度) | R_i = G-αB+βT (α=0.5, β=0.3) |
|------|----------------|----------------|--------------|------------------------------|
| a_1  | 0.65           | 0.10           | 0.70         | 0.65 - 0.05 + 0.21 = 0.81    |
| a_2  | 0.30           | 0.25           | 0.35         | 0.30 - 0.125 + 0.105 = 0.28  |
| a_3  | 0.05           | 0.15           | 0.10         | 0.05 - 0.075 + 0.03 = 0.005  |
| a_4  | 0.72           | 0.08           | 0.85         | 0.72 - 0.04 + 0.255 = 0.935  |

**Step 4: 质量门检查**
```
ΔR = max(R̄) - min(R̄) = 0.935 - 0.005 = 0.93 ≥ 0.02 ✓
ρ_rank ≥ 0.5, σ_WM ≤ 0.2 → 假设两次想象排序一致 ✓
```
通过质量门，进入下一步。

**Step 5: 标准化优势**
```
μ_R̄ = (0.81+0.28+0.005+0.935)/4 = 0.5075
σ_R̄ ≈ 0.38

A_1 = (0.81 - 0.5075) / 0.38 = +0.79  → sgn = +1
A_2 = (0.28 - 0.5075) / 0.38 = -0.60  → sgn = -1
A_3 = (0.005 - 0.5075) / 0.38 = -1.32 → sgn = -1
A_4 = (0.935 - 0.5075) / 0.38 = +1.12 → sgn = +1
```

**Step 6: 策略更新**
```
g_WISE = (1/4) · [∇L_FM(a_1) - ∇L_FM(a_2) - ∇L_FM(a_3) + ∇L_FM(a_4)] + λ_ref·∇L_ref
θ ← θ - η · g_WISE
```
效果：a_1 和 a_4（成功抓起）的概率被增强，a_2 和 a_3（失败）的概率被抑制。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/特征 | 工程含义 |
|------|-----------|----------|
| 世界模型推理节省 | 80% 状态跳过，GPU 时间 11.45→2.61 小时 | 后训练成本从"不可接受"降到"可日常运行" |
| 想象 horizon | L chunks × H frames/chunk | 固定 horizon 是简化设计；长任务可能需要自适应 horizon |
| 调度器延迟 | DINOv2 + 轻量 head，每步运行 | 轻量级，不会成为推理瓶颈 |
| 候选数 M | 论文未明确给出（附录） | M 越大评估越准，但世界模型调用次数线性增长 |
| 奖励模型 | 3 个 head（进度/置信度/完成度） | 比单一标量奖励更稳定，但增加了训练复杂度 |
| 部署约束 | 世界模型冻结，仅策略在线更新 | 推理时无需世界模型，部署开销不变 |
| 闭环 rollout 误差 | L 个 chunk 累积 | 这是核心风险——世界模型误差随时间累积，bounding 是缓解手段 |

**关键 trade-off**：想象调度节省了 80% 计算，但代价是"可能错过非交互关键态中的有用学习信号"。论文假设交互态是策略改进的主要瓶颈——这在桌面操作任务中可能成立，但在需要精细时序协调的任务中（如装配、书写）可能不够。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **桌面操作任务的后训练**：在 5 个 MimicGen 任务上稳定提升 π0 和 π0.5
- **真实世界分布偏移鲁棒性**：泛化设置下提升更大（+26.3pp vs +17.5pp 标准设置）
- **计算效率**：80% 的 GPU 时间节省，使日常后训练可行
- **跨 VLA backbone 迁移**：对 π0 和 π0.5 都有效，不绑定特定架构

### 不能做什么 / 失败模式
- **长程时序协调任务**：固定想象 horizon 可能不足以覆盖需要多步前瞻的场景（如多步骤装配）
- **调度器域外泛化**：调度器在训练域上学习"什么是交互关键态"，到新任务域可能失效
- **世界模型误差累积**：即使有界 rollout，L 个 chunk 的闭环预测仍会累积误差，影响评估可靠性
- **仅操作任务**：论文未评估移动机器人、双臂协作、人形机器人等场景

### 6.1 隐含假设 (Hidden Assumptions)

1. **交互关键态是策略改进的瓶颈**：假设非交互态的 VLA 行为已经"足够好"，不需要额外优化。如果任务需要精细的时序控制（如拧螺丝的力度调节），这个假设可能不成立。
2. **弱监督调度信号可迁移**：从机器人执行信号提取的弱监督标签，假设在不同任务间有共性。但"交互"的定义因任务而异。
3. **世界模型在分布内足够准确**：调度器选出的交互关键态可能恰好是世界模型预测误差最大的区域（因为交互涉及接触，接触是 world model 的已知难点）。
4. **两次想象取平均足够可靠**：R̄_i = (R_i^(1) + R_i^(2)) / 2 假设两次想象的奖励相关性足够高。但世界模型的随机性（rectified flow 的采样路径）可能导致奖励波动。
