VLA 模型预训练后需要针对具体任务做后训练（post-training），传统方法要么依赖昂贵的专家演示（SFT），要么依赖高风险的真机探索（RL）。世界模型可以在虚拟环境中预测动作后果，但"更多想象"并不等于"更好策略"——延长 rollout 会累积预测误差，均匀调用则浪费算力。WISE 的核心发现是：想象的价值在任务执行的不同阶段差异巨大，粗运动阶段 VLA 已经够用，交互关键时刻才需要预测推理。通过调度器判断何时调用世界模型，WISE 在 5 个模拟任务和 4 个真实机器人任务上同时实现了性能提升和 80% 计算节省。

## 1. 核心架构/方法总览 (Overview / Architecture)

WISE 是一个四阶段闭环框架：**想象调度 → 有界反事实想象 → 轨迹评估 → 策略优化**，从预训练 VLA 策略出发，在交互过程中选择性调用世界模型来提供策略改进信号。

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 训练方式 | 推理阶段作用 |
|------|------|------|----------|-------------|
| **预训练 VLA** π_θ | 交互上下文 h_t = (O_t, s_t, ℓ) | 动作块 a_t | 大规模预训练（冻结） | 生成候选动作；被优化的目标 |
| **想象调度器** | 腕部 + 第三人称图像 (I_t^w, I_t^a) | 二元开关 m_t ∈ {0,1} | 弱监督（机器人执行信号） | 判断是否调用世界模型 |
| **世界模型** p_ψ | 当前观测 + 动作 | 未来多视角观测 | Rectified Flow 训练（冻结） | 生成候选动作的反事实未来 |
| **奖励模型** f_ω | 预测的多视角观测序列 | 进度/置信度/完成度 | 独立训练（冻结） | 评估想象轨迹的质量 |
| **策略优化器** | 候选动作 + 相对优势 A_i | 梯度更新方向 | Group-Relative Policy Optimization | 沿优势方向更新 VLA 参数 |

### 1.2 关键机制 (Key Mechanism)

**为什么需要调度？** 预训练 VLA 在粗运动阶段（如移动到目标附近）已经足够可靠，但在交互关键时刻（如抓取、插入、操作铰链）需要精确预测后果。均匀调用世界模型 = 在不需要预测的地方浪费算力 + 在需要预测的地方可能 horizon 不够长。

**为什么需要有界 rollout？** 世界模型的预测误差会随 rollout 步数累积。闭环比开环更真实（因为每一步都用预测观测生成下一步动作），但也更不稳定。WISE 限制 rollout 长度为 L 个动作块，每个块预测 H 帧，总帧数 L×H。

**为什么用相对评估而非绝对评分？** 绝对奖励信号容易受世界模型偏差影响（模型可能对某些轨迹系统性高估/低估）。通过比较同一组内 M 个候选的相对优劣，可以抵消系统性偏差，只保留排序信息。

⚡ **Eureka Moment**: 世界模型在 VLA 后训练中的瓶颈不是"预测精度不够"，而是"调用方式不对"——选择性地在交互关键态调用有界想象，比均匀调用全部想象更高效、更可靠。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
g_WISE = (1/M) · Σ_i sgn(A_i) · ∇_θ L_FM(θ; a_{t,i}, h_t) + λ_ref · ∇_θ L_ref
其中 A_i = (R_i - μ_R) / max(σ_R, ε),  R_i = G_i - α·B_i + β·T_i
```

**目标**：最大化任务期望成功率，但用世界模型的反事实想象替代真实环境交互来提供优化信号。

**核心方程分解**：

```
进度得分:  G_i = Σ_j c_{i,j} · [p_{i,j} - p_{i,j-1}]_0^δ
回退惩罚:  B_i = Σ_j [p_{i,j-1} - p_{i,j}]_0^δ
完成信号:  T_i = max_j q_{i,j}
综合奖励:  R_i = G_i - α·B_i + β·T_i
```

**变量说明**：

| 符号 | 含义 | 来源 |
|------|------|------|
| p_{i,j} | 候选 i 在第 j 帧的进度分数 | 奖励模型预测头 h_p |
| c_{i,j} | 进度置信度 | 奖励模型预测头 h_c |
| q_{i,j} | 完成度分数 | 奖励模型预测头 h_q |
| δ | 进度变化截断阈值 | 超参数，防止极端值 |
| α, β | 回退惩罚/完成信号权重 | 超参数 |
| [x]_0^δ | 截断函数 min(max(x,0),δ) | 数学操作 |
| κ | 调度阈值 | 超参数，控制想象力分配 |
| L_FM | Flow Matching 损失 | VLA 的基础训练损失 |

> 符号与本文保持一致：O_t 为多视角观测，s_t 为机器人本体感知状态，ℓ 为语言指令，a_t 为动作块，π_θ 为 VLA 策略，p_ψ 为世界模型，f_ω 为奖励模型。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设在某个交互关键态，调度器触发（m_t=1），采样 M=4 个候选动作。世界模型对每个候选做 L=2 块 rollout（每块 H=16 帧，共 32 帧）。

**Step 1: 奖励模型评估**

| 候选 | 进度 G_i | 回退 B_i | 完成 T_i | R_i = G - 0.5·B + 0.3·T |
|------|----------|----------|----------|-------------------------|
| a_1  | 0.45     | 0.08     | 0.90     | 0.45 - 0.04 + 0.27 = 0.68 |
| a_2  | 0.38     | 0.12     | 0.75     | 0.38 - 0.06 + 0.225 = 0.545 |
| a_3  | 0.25     | 0.15     | 0.60     | 0.25 - 0.075 + 0.18 = 0.355 |
| a_4  | 0.30     | 0.10     | 0.50     | 0.30 - 0.05 + 0.15 = 0.40 |

**Step 2: 质量门检查**

```
ΔR = max(R) - min(R) = 0.68 - 0.355 = 0.325 ≥ 0.02  ✓
ρ_rank ≥ 0.5 (两轮想象排序一致)  ✓
σ_WM ≤ 0.2 (奖励波动小)  ✓
```

组被接受。

**Step 3: 相对优势计算**

```
μ_R = (0.68 + 0.545 + 0.355 + 0.40) / 4 = 0.495
σ_R = std([0.68, 0.545, 0.355, 0.40]) ≈ 0.129

A_1 = (0.68 - 0.495) / 0.129 = +1.43  (正优势 → 强化)
A_2 = (0.545 - 0.495) / 0.129 = +0.39  (正优势 → 强化)
A_3 = (0.355 - 0.495) / 0.129 = -1.09  (负优势 → 抑制)
A_4 = (0.40 - 0.495) / 0.129 = -0.74  (负优势 → 抑制)
```

**Step 4: 策略更新**

```
g_WISE = (1/4) · [sgn(+1.43)·∇L(a_1) + sgn(+0.39)·∇L(a_2)
                  + sgn(-1.09)·∇L(a_3) + sgn(-0.74)·∇L(a_4)]
       = (1/4) · [+∇L(a_1) + ∇L(a_2) - ∇L(a_3) - ∇L(a_4)]

更新方向: θ ← θ - η · g_WISE
```

直觉：a_1 和 a_2 被强化（沿着它们的梯度方向更新），a_3 和 a_4 被抑制（远离它们）。只有符号被使用（sgn），所以优势的大小不影响更新幅度，只影响方向选择。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/特征 | 工程含义 |
|------|-----------|----------|
| 世界模型调用量 | 减少 ~80%（138→28 个选中态） | 从 11.45 GPU-hr 降至 2.61 GPU-hr，训练成本大幅降低 |
| 想象 horizon | L 个动作块 × H 帧/块（固定） | 固定 horizon 是简化设计，长任务可能需要自适应 horizon |
| 候选数量 M | 未明确给出（论文附录） | M 越大排序越可靠，但 WM 调用量线性增长 |
| 奖励模型 | 3 个头（进度/置信度/完成度） | 独立训练，可替换为其他 reward model 架构 |
| 调度器 | DINOv2 + 轻量头 | 推理极快，几乎不增加额外延迟 |
| 策略更新 | 仅监督第一个动作块 | 想象 rollout 不直接提供监督信号，只用于评估 |
| 闭环 vs 开环 | 闭环比开环更真实但不稳定 | 误差累积是主要风险，有界 rollout 缓解但不消除 |
| 双次想象 | 每个候选想象 2 次取平均 R̄_i | 提高奖励估计稳定性，但 WM 调用翻倍 |

**部署约束**：WISE 是后训练框架，推理阶段不需要世界模型。训练时需要：预训练 VLA（冻结或微调）、世界模型（冻结）、奖励模型（冻结）、调度器（冻结或微调）。四个组件可独立部署到不同 GPU。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

- **接触密集任务提升显著**：Threading（+7.3pp π0）、Mug Cleanup（+12.0pp π0）——世界模型在需要精确预测接触后果的场景中最有价值
- **泛化能力提升更大**：真实世界泛化设置下，π0+WISE 比 π0 平均高 26.3pp（标准设置只高 17.5pp）——世界模型引导的后训练特别有助于分布外鲁棒性
- **计算效率显著**：80% 的 WM 调用减少，GPU 时间从 11.45h 降至 2.61h（Table 3）
- **跨 backbone 迁移**：π0 和 π0.5 都能从 WISE 受益，说明框架不依赖特定 VLA 架构

### 不能做什么 / 已知局限

- **单一机器人平台**：真实实验仅在 Galaxea R1 Lite 上验证，未测试移动机器人、双臂或人形平台
- **固定想象 horizon**：论文 §5 明确承认当前使用固定 horizon，长程任务可能需要自适应 horizon
- **弱监督调度器**：调度器依赖机器人执行信号作为弱监督，训练数据质量直接影响调度精度
- **世界模型误差累积**：尽管有界 rollout 缓解了误差累积，但闭环 rollout 中预测误差仍是系统性风险
- **仅桌面操作**：所有任务都是桌面级机械臂操作，未涉及导航、移动操作等更大空间尺度的任务

### 6.1 隐含假设 (Hidden Assumptions)

1. **交互关键时刻可被视觉信号可靠识别**：调度器仅用视觉输入判断是否需要想象。如果关键交互状态需要本体感知或力觉信息才能识别，调度器可能漏判。
2. **世界模型在分布内预测足够准确**：调度器选出的状态如果超出世界模型训练分布，预测质量会下降，导致错误评估。
3. **相对排序比绝对评分更可靠**：Group-Relative 方法假设同一组内候选的误差是相关的（系统性偏差可抵消）。但如果候选动作差异很大（一个在分布内、一个在分布外），这个假设可能不成立。
4. **双次想象取平均足够稳定**：R̄_i = (R_i^(1) + R_i^(2))/2 假设两次想象的差异主要来自随机性而非系统性偏差。如果世界模型本身有系统性不确定性，双次平均可能不够。

**面试 Tip**：如果被问到"WISE 和其他世界模型引导方法的区别"，回答：「现有方法把世界模型当作均匀调用的组件（要么全用、要么全不用），WISE 首次把"何时调用世界模型"本身作为一个调度问题来优化，核心 insight 是想象的价值在任务执行的不同阶段差异巨大。」
