### 1.2 关键机制 (Key Mechanism)

**设计 1：SANS 数据集（Success And Near-Success）**
- 现有机器人数据集几乎全是成功轨迹，世界模型没见过"差点成功"的失败模式
- SANS 专门混合成功 + 近成功轨迹（末端执行器微小偏差导致的失败），迫使模型学习成功/失败的精细边界
- 规模：ManiSkill 预训练 35k 视频-动作对（23 个任务）；LIBERO 和真实世界每任务 ~50 成功 + ~50 失败

**设计 2：状态感知奖励预测头（State-Aware Reward Head）**
- 在 Cosmos-Predict 2 的 DiT 去噪潜变量后加一个轻量 MLP
- 联合优化：L = L_flow + λ·Σ‖r̂_t − r_t‖²
- 奖励头不是独立的——它与视频生成共享潜空间，联合训练让生成器更好地区分成功/失败轨迹

⚡ **Eureka Moment**：把奖励预测头直接长在视频世界模型的扩散潜空间上，而不是外挂一个独立模块——奖励和视觉生成共享表征，互相增强。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L = L_flow(x_0,...,x_{h+T-1} | a_1,...,a_T) + λ·Σ_t ‖φ(z_t) − r_t‖²
```

**目标**：在视频生成的同时，让扩散模型的内部潜变量 z_t 编码"当前状态是否成功"的信息，从而无需外部奖励模块。

**变量说明**：

| 符号 | 含义 |
|------|------|
| $x_0,\dots,x_{h-1}$ | h 帧初始观察帧 |
| a_1,...,a_T | T 步机器人末端执行器动作（6-DoF 位姿 + 夹爪开闭） |
| $x_h,\dots,x_{h+T-1}$ | 预测的未来 T 帧 |
| z_t | DiT 第 t 步去噪后的潜变量 |
| $\varphi(\cdot)$ | 奖励预测头（轻量 MLP） |
| $\hat{r}_t = \varphi(z_t)$ | 预测的标量奖励 |
| r_t | ground truth 二值奖励（成功=1, 失败=0） |
| $\lambda$ | 权重系数，按 EDM 框架的采样噪声水平动态调制 |

> 符号与本文保持一致：奖励头直接作用于最终去噪步的潜变量 $z_t$，而非中间步。$\lambda$ 的噪声水平调制确保早期高方差去噪步不会主导奖励梯度。

**直觉**：传统方法把奖励当成"事后判分"（用独立模型或 VLM 看生成的视频再打分），本文让奖励成为"内在感知"——世界模型在生成视频的同时就知道"这步走对了没有"。联合训练时，奖励梯度会反向塑造潜空间，让成功和失败的表征自然分开，反过来又提升了视频生成的动作跟随精度。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的夹取任务，chunk size = 4 步：

**Step 0 — 初始观察**：相机看到杯子在桌上，机械臂在起始位。

**Step 1 — 策略输出动作 a_1**：[x+5mm, y+0mm, z-10mm, 夹爪开]

世界模型预测：
- 视觉：下一帧显示机械臂向下移动了 10mm
- 奖励：r̂_1 = 0.15（远未接近目标）

**Step 2 — 动作 a_2**：[x+3mm, y+2mm, z-5mm, 夹爪开]

世界模型预测：
- 视觉：机械臂更接近杯子，但偏左 2mm
- 奖励：r̂_2 = 0.42（在接近，但位置偏差仍在）

**Step 3 — 动作 a_3**：[x+1mm, y-1mm, z-2mm, 夹爪闭]

世界模型预测：
- 视觉：夹爪合上，但杯子未被夹住（偏了 1mm）
- 奖励：r̂_3 = 0.68（near-success——非常接近）

**Step 4 — 动作 a_4**：[x+0mm, y+0mm, z+5mm, 夹爪闭]

世界模型预测：
- 视觉：机械臂抬起，杯子仍在桌上
- 奖励：r̂_4 = 0.72（最终失败，因为夹爪没闭合时杯子未到位）

**GRPO 优势计算**（假设同组 4 个 rollout）：

| Rollout | 最终奖励 | 平均奖励 | 优势 (A = r − mean) |
|---------|----------|----------|---------------------|
| R1 (成功) | 1.0 | 0.85 | +0.25 |
| R2 (成功) | 1.0 | 0.82 | +0.22 |
| R3 (near-success) | 0.72 | 0.49 | -0.11 |
| R4 (失败) | 0.35 | 0.28 | -0.32 |

GRPO 用这些优势更新策略：R1/R2 的动作序列被强化，R3/R4 被抑制。关键点是 R3 的 near-success 奖励 0.72 比 R4 的 0.35 高很多——世界模型精确区分了"差一点"和"完全失败"，这让策略能学到更细粒度的改进方向。

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/设计 | 含义 |
|----------|-----------|------|
| 基础模型 | Cosmos-Predict 2（NVIDIA） | 大规模 embodiment 视频预训练，需 GPU 推理 |
| 动作维度 | 6-DoF 位姿 + 1 维夹爪 = 7D | 标准单臂末端执行器控制空间 |
| Chunk size | 24（统一设置） | 每次策略输出 24 步动作，与世界模型 T 对齐 |
| 视频生成方式 | 自回归 chunk 拼接 | 长 horizon 任务需多轮拼接，误差累积严重 |
| 奖励头参数量 | 轻量 MLP（论文未明确给出） | 相对于 DiT 主干可忽略，但训练时与主干 jointly update |
| 数据需求 | ManiSkill 35k 对预训练；新任务 50+50 微调 | 迁移到新场景只需约 100 条轨迹，成本可控 |
| 迭代轮次 | 实验验证 2 轮迭代 | 每轮 = 世界模型微调 + VLA RL + 新数据采集 |
| 真实交互成本 | 每轮仅少量 rollout 采集 | 相比纯真实 RL 降低 1-2 个数量级 |

**工程含义**：
- 世界模型替代物理模拟器后，RL rollout 完全在 GPU 上完成，消除了机器人物理交互的时间和安全成本
- 但自回归视频生成的误差累积限制了 horizon 长度——LIBERO-100（>300 帧）被明确列为 future work
- 奖励头与生成器共享潜空间，意味着部署时只需加载一个模型（而非"世界模型 + 独立奖励模型"的两段式），减少推理开销

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **真实机器人策略优化无需大量物理交互**：初始采集约 100 条轨迹 + 2 轮迭代（每轮少量新采集），即可将真实任务成功率从 13.3% 提升到 36.7%
- **区分成功与近成功**：奖励对齐率平均 87.25%，能可靠区分"差一点"和"完全失败"
- **跨场景迁移**：ManiSkill 预训练模型只需 50+50 条新任务轨迹即可迁移到 LIBERO 和真实场景

### 不能做什么
- **长程任务（>300 帧）**：自回归视频生成的质量漂移严重，LIBERO-100 明确列为 future work
- **多机器人协作**：实验仅限单 Franka 臂 + 单第三视角相机
- **动态环境**：假设环境静态，未测试物体被外部扰动或光照变化的情况

### 6.1 隐含假设 (Hidden Assumptions)

| 假设 | 说明 | 风险 |
|------|------|------|
| 二值奖励足够 | 论文使用 success/failure 二值奖励，未探索稠密奖励 | 对于需要中间引导的复杂任务（如多步装配），二值奖励可能信息不足 |
| 世界模型奖励与真实奖励一致 | 奖励对齐率 ~87%，意味着 ~13% 的预测与 ground truth 不符 | RL 策略可能基于错误奖励信号优化，导致"模拟器内成功、真实世界失败" |
| 相机视角固定 | 实验使用固定第三视角 RealSense D435 | 未验证手持相机或眼在手上的设置 |
| Cosmos-Predict 2 可用 | 依赖 NVIDIA 闭源视频生成模型 | 可复现性受限，社区无法完全独立复现 |
