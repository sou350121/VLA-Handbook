### 1.2 关键机制 (Key Mechanism)

**为什么需要三面评估？**
- **物理可行性 E_phy**: LLM 缺乏物理常识，会生成运动学不可达的任务（如双臂工作区不重叠却要求协作）。E_phy 检查运动学可行性、任务分解逻辑、物理定律遵循、同步控制约束。
- **新颖性 E_nov**: 防止生成退化为简单 pick-place 重复。从 4 维度评估：物体复杂度（可变形/流体）、交互精度（手内操作/工具使用）、时序深度（长程任务/部分可观测）、环境非结构化程度（动态目标/扰动）。
- **约束遵循 E_con**: 确保生成任务不幻觉——物体必须来自采样集 O_t，技能必须来自 S_t，场景类型必须匹配。

**为什么用 LFU 采样？**
人工设计与 LLM 生成都存在严重长尾分布：少数常见物体/技能占据 80%+ 任务。LFU (Least Frequently Used) 主动选择使用计数最低的场景/物体/技能，强制探索欠表示区域。

**为什么需要人类反馈记忆？**
开放-loop 生成无法利用真实执行中的失败信息（如"抽屉把手因遮挡需左手操作"）。HITL 反馈经 LLM 汇总为启发式知识，存入记忆 M，后续通过 RAG 检索注入优化器，实现持续进化。

## 2. 数学核心 (Math Core)

### 2.1 任务空间形式化

**目标**: 定义可生成的任务空间，使多样性采样与约束检查可计算。

```
T = ⟨r, e, c, O, S⟩

其中:
  r ∈ R  : 机器人类型 (单臂/双臂/移动操作)
  e ∈ E  : 场景类别 (家庭/办公室/工业/医疗等 8 类)
  c      : 任务描述上下文 (自然语言)
  O ⊆ 𝒪  : 使用物体集合 (来自 1137 物体库)
  S ⊆ 𝒮  : 使用技能集合 (来自 118 技能库)
```

### 2.2 生成过程公式

**目标**: 将端到端生成拆解为可独立优化的子模块。

```
T = Φ_refine( Φ_gen( Φ_sample(E, 𝒪, 𝒮 | H), R ) | M )

模块分解:
  Φ_sample  : 多样性采样，输出约束元组 (e_t, O_t, S_t)
  Φ_gen     : 任务提案生成，输出 T_raw
  Φ_refine  : 记忆增强优化，输出 T_ref
```

### 2.3 LFU 采样公式

**目标**: 量化"多样性"，使采样策略可优化。

```
场景选择: e_t = argmin_{e ∈ E} u(e)

物体采样:
  1. 语义过滤: 𝒪_{e_t} = { o ∈ 𝒪 | sim(o, e_t) > τ }
  2. LFU 候选集: O_t = TopK_LFU(𝒪_{e_t}, u, k)
  
技能采样: 同理 S_t = TopK_LFU(𝒮_{e_t}, u, k)

更新规则: 任务验证通过后 u(e_t)++, u(o)++, u(s)++ ∀o∈O_t, s∈S_t
```

### 2.4 符号说明

| 符号 | 含义 | 本文定义 |
|------|------|----------|
| T | 任务实例 | ⟨r, e, c, O, S⟩ 五元组 |
| R | 机器人类型空间 | {单臂，双臂，移动操作} |
| E | 场景类别空间 | 8 类 (家庭/办公室/工业/医疗/厨房/零售/教育/实验室) |
| 𝒪 | 全局物体库 | 1137 个物理实体 |
| 𝒮 | 全局技能库 | 118 个操作原语 |
| H | 历史统计 | {u(e), u(o), u(s)} 使用计数器 |
| M | 长期记忆 | {(K, V)} 语义嵌入 - 启发式知识对 |
| u(·) | 使用计数 | 成功生成后递增 |

### 2.5 直觉解释

- **任务空间 T**: 把"任务"从模糊的自然语言描述转化为结构化五元组，使多样性可量化、约束可检查。
- **生成链式分解**: Φ_sample → Φ_gen → Φ_refine 的级联设计，使每个模块可独立优化（采样管分布、生成管语义、优化管物理）。
- **LFU 核心**: 用计数器 u(·) 显式追踪长尾，argmin 选择保证欠表示区域优先探索——这是对"多样性"的可计算定义。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有一个简化场景：
- E = {厨房，工业} (2 类场景)
- 𝒪 = {苹果，螺丝刀，微波炉，传送带} (4 物体)
- 𝒮 = {pick, place, rotate, clean} (4 技能)
- 初始 u(e) = u(o) = u(s) = 0

**第 1 轮生成**:

```
1. Φ_sample:
   e_1 = argmin u(e) = "厨房" (u=0，平局时选第一个)
   𝒪_厨房 = {苹果，微波炉} (语义过滤)
   O_1 = TopK_LFU({苹果，微波炉}, u, k=2) = {苹果，微波炉}
   S_1 = {pick, place} (假设语义过滤后)

2. Φ_gen:
   输入：e_1="厨房", O_1={苹果，微波炉}, S_1={pick, place}, R="单臂"
   输出 T_raw:
   {
     "task_description": "从桌上拿起苹果放到微波炉旁边",
     "objects": ["苹果", "微波炉"],
     "skills": ["pick", "place"]
   }

3. 三面评估:
   E_phy: 通过 (单臂 pick-place 运动学可行)
   E_nov: 批判 "过于简单，仅为基本 pick-place"
   E_con: 通过 (物体/技能均在采样集内)

4. Φ_refine:
   根据 E_nov 批判，优化为:
   {
     "task_description": "先用湿布清洁苹果表面，然后放入微波炉，关闭炉门",
     "objects": ["苹果", "微波炉", "湿布"],
     "skills": ["pick", "place", "clean"]
   }
   
   → 但 E_con 发现"湿布"不在 O_1 中，驳回
   
   二次优化:
   {
     "task_description": "拿起苹果，用纸巾擦拭后放到微波炉顶层架子上",
     "objects": ["苹果", "微波炉", "纸巾"],
     "skills": ["pick", "place", "clean"]
   }
   
   → 仍不通过 (纸巾不在 O_1)
   
   最终版本:
   {
     "task_description": "拿起苹果，在微波炉门前展示 3 秒后放到微波炉顶部",
     "objects": ["苹果", "微波炉"],
     "skills": ["pick", "place"]
   }

5. 验证通过，更新 H:
   u(厨房)=1, u(苹果)=1, u(微波炉)=1, u(pick)=1, u(place)=1
```

**第 2 轮生成**:

```
1. Φ_sample:
   e_2 = argmin u(e) = "工业" (u=0 < u(厨房)=1)
   𝒪_工业 = {螺丝刀，传送带}
   O_2 = {螺丝刀，传送带}
   S_2 = {rotate, pick} (假设)

2. 生成 T_raw: "用螺丝刀旋转传送带上的螺丝"
   → E_phy 批判："传送带无螺丝，物体关系不成立"
   → Φ_refine 修正为："用螺丝刀旋转固定在工作台上的螺丝"
   → E_con 批判："工作台"不在 O_2 中
   → 最终："拿起螺丝刀，在传送带末端模拟旋转动作"
   
3. 更新 H: u(工业)=1, u(螺丝刀)=1, u(传送带)=1, u(rotate)=1
```

**关键观察**:
- LFU 强制第 2 轮选择"工业"场景，避免全部任务集中在"厨房"
- E_con 阻止幻觉物体（湿布、工作台）
- E_nov 推动增加任务复杂度（展示 3 秒）

## 4. 工程视角 (Engineering View)

### 4.1 吞吐与延迟

| 阶段 | 单次调用延迟 | 每任务调用次数 | 总延迟贡献 |
|------|-------------|---------------|-----------|
| Φ_sample | <10ms (查表 + 排序) | 1 | ~10ms |
| Φ_gen | 2-5s (LLM/VLM) | 1 | 2-5s |
| E_phy/E_nov/E_con | 1-3s × 3 | 1 | 3-9s |
| Φ_refine | 2-5s | 1-2 (可能迭代) | 2-10s |
| **总计** | | | **7-24s / 任务** |

**工程含义**: 生成 1200 任务约需 2.3-8 小时（串行）。可并行化：Φ_gen 与评估器可批量调用，预计可提速 5-10 倍。

### 4.2 内存与存储

```
物体库 𝒪: 1137 物体 × ~50 字节/名称 ≈ 57 KB
技能库 𝒮: 118 技能 × ~30 字节/名称 ≈ 4 KB
历史统计 H: (1137+118+8) × 4 字节 ≈ 5 KB
长期记忆 M: 假设 1000 条反馈 × (64 维嵌入 + 200 字节文本) ≈ 256 KB
单任务 JSON: ~500 字节
18k 轨迹数据集: 18000 × 500 ≈ 9 MB
```

**工程含义**: 内存占用极小 (<1MB)，可嵌入边缘设备。主要瓶颈是 LLM API 调用成本与延迟。

### 4.3 量化误差与抖动

- **LFU 计数器溢出**: u(·) 用 32-bit int，最大 2^31-1 ≈ 20 亿次。18k 任务远未达上限。
- **语义相似度阈值 τ**: 论文未明确 τ 值，需调参。τ 过高导致 𝒪_{e_t} 为空，τ 过低导致语义不连贯（如"在厨房折叠传送带"）。
- **评估器一致性**: 3 个评估器可能给出冲突批判（E_nov 要求复杂化，E_phy 判定不可行）。Φ_refine 需优先级仲裁——论文未说明仲裁策略，待验证。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 6.1 能做什么

## 7. 与相关工作对比 (Comparison)

### 7.1 同系列/基线对比

| 方法 | 关注点 | 架构 | 训练方式 | 适用场景 |

**关键差异**:
- RoboGen/GenSim 聚焦仿真，RoboGene 直接面向真实机器人数据收集
- 现有方法为 open-loop，RoboGene 为 closed-loop (HITL 反馈→记忆→优化)
- 现有方法无显式多样性优化，RoboGene 用 LFU 量化并优化分布

### 7.2 面试 Tip

**问**: "RoboGene 相比直接用 GPT-4o 生成任务，核心优势是什么？"

**答**: "三个关键词：**闭环、量化、记忆**。闭环是指用人类执行反馈持续优化，而非一次性生成；量化是指用 LFU 计数器显式追踪并优化长尾分布，而非依赖 LLM 隐式多样性；记忆是指将失败模式转化为可检索的启发式知识，使系统随时间进化。实验证明这三点使物体覆盖率从 0.31 提升至 0.63，策略泛化能力提升 3.6 倍。"
