### 1.2 关键机制 (Key Mechanism)

**三流 Mixture-of-Transformers (MoT)**：
- **Text Stream**：独立文本流作为条件分支，不参与输出但通过注意力影响视频和动作流。这比将文本 token 直接拼接到视频/动作序列中更能保持语义理解的独立性。
- **Video Stream**：基于 Vidu VAE 编码的潜在空间，用 flow matching 预测视频速度场。
- **Action Stream**：用相对末端执行器坐标（位置 + 6D 旋转 + 夹爪状态 = 10D），同样用 flow matching。

**H-Bridge 注意力设计**：
- 底层 25%：视频和动作 token 独立处理（保持模态特异性表征）
- 中层 50%：全量 V-A 联合注意力（语义对齐与策略 grounding）
- 顶层 25%：再次解耦（避免注入过多模态无关信息）

**统一多视图表示**：
- 每个视图独立经 Vidu VAE 编码，在 token 级拼接
- 利用 3D RoPE，仅在空间维度引入视图相关偏移，时间维度不变
- 支持任意数量相机视图，无需修改骨干架构

⚡ **Eureka Moment**：视频生成模型 = 世界模型。因为视频生成模型已经在海量网络视频上学到了物理动力学，将它们与动作预测统一到一个扩散框架中，VLA 就能从"模仿行为"进化为"推理世界"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L = λ_v · MSE(v_out, v_target) + λ_a · MSE(a_out, a_target)
```

**目标**：在统一扩散框架中同时学习视频速度场预测和动作速度场预测，让两个模态在共享注意力中互相增强。

**变量说明**：

| 符号 | 含义 |
|------|------|
| L | 总损失（Stage 2 联合优化） |
| λ_v, λ_a | 视频和动作损失的权重系数 |
| v_out, v_target | 视频流预测的速度场与真实速度场 |
| a_out, a_target | 动作流预测的速度场与真实速度场 |
| timeshift_v = 6 | 视频采样的 SNR 偏移（更偏向噪声区域） |
| timeshift_a = 1 | 动作采样的 SNR 偏移（更均匀分布） |

**直觉**：视频流被训练在更噪声的条件下预测——这迫使模型学会在视觉信息不完整时仍能推理出正确的动作。动作流则在较清晰的条件下学习，确保动作精度。两者通过注意力交互，视频流为动作提供物理世界先验，动作流为视频注入控制相关信号。

**条件帧噪声增强**（LingBot-VA 风格）：
```
z̃_0 = s_aug · z_0 + (1 - s_aug) · ε
其中 s_aug ~ U[0.3, 0.7], ε ~ N(0, I)
以 p=0.5 概率应用
```

**相对末端执行器表示**（跨具身统一）：
```
e_rel_i = e_abs_i ⊖ s
       = (p_i - p_s, R_s^{-1} · R_i, g_i)
```
其中 ⊖ 表示分量级位姿差：位置直接相减，旋转与参考逆旋转合成，夹爪状态不变。

> 符号与本文保持一致：o 为观测，ℓ 为语言指令，z 为 VAE 潜在，a 为动作，s 为条件帧末端执行器状态。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2D 机械臂抓取任务：

**场景**：机械臂末端在位置 s = (0.1, 0.2, 0.3)，目标物体在 (0.5, 0.4, 0.3)。

**Step 1 — 动作表示**：
- 绝对目标动作 e_abs = (0.5, 0.4, 0.3, R_target, g=1)
- 相对动作 e_rel = (0.5-0.1, 0.4-0.2, 0.3-0.3, ...) = (0.4, 0.2, 0.0, ...)
- 这样不同起始位置的机械臂可以用同一组权重学习"向目标移动 0.4m 前、0.2m 右"的通用策略

**Step 2 — 扩散去噪**：
- 初始：z_a^(0) = 纯高斯噪声，维度 10 × K（K 为动作 chunk 长度）
- 第 1 步去噪：a_out_1 = ActionStream(z_a^(0), z_v^(0), text)
- MSE 损失：L_a = ||a_out_1 - a_target||² = 0.05（假设）
- 更新：z_a^(1) = z_a^(0) - η · a_out_1

**Step 3 — 视频-动作交互**：
- 中层注意力层中，动作 token 查询 attends to 视频 token 的 key/value
- 视频流告诉动作流："前方有障碍物"→ 动作流调整轨迹绕行
- 这种交互仅在中间 50% 层发生，首尾层保持模态独立

**Step 4 — 推理加速（V2A 风格）**：
- 前 10 步：联合去噪视频和动作
- 后 20 步：视频 latent 冻结，只更新动作
- 节省：视频流的 DiT 前向计算被跳过 20/30 = 67%

## 4. 工程视角 (Engineering View)

**推理延迟优化栈**（论文 Table 2 数据）：

| 优化技术 | 去噪步数 | 每步延迟 | 总延迟 | 频率 | 累计加速 |
|----------|---------|---------|--------|------|---------|
| Baseline | 50 | 95.0 ms | 4.90 s | 0.20 Hz | 1.00× |
| + 噪声采样 | 30 | 95.0 ms | 2.90 s | 0.34 Hz | 1.69× |
| + torch.compile | 30 | 32.7 ms | 0.98 s | 1.02 Hz | 5.00× |
| + FP8 量化 | 30 | 29.3 ms | 0.88 s | 1.14 Hz | 5.57× |
| + DiT Cache | 30 | — | 0.20 s | 5.00 Hz | 24.5× |
| + V2A 风格 | 30 (动作) | — | 0.09 s | **11.11 Hz** | **54.4×** |

**关键工程含义**：
- **11 Hz 推理频率**超过人类反应速度（约 3-5 Hz），意味着可以部署到需要快速响应的操作任务
- **FP8 量化**在 GEMM 密集型 DiT 上几乎无损——因为量化在 torch.compile 之前应用，编译图直接追踪量化算子
- **DiT Cache**利用去噪步之间的时间冗余：当连续两步速度预测余弦相似度 > γ 时，跳过后续 DiT 评估
- **V2A 非对称注意力**是最大加速来源（24.5× → 54.4×），因为它完全消除了后半段采样中视频流的计算

**实时执行策略**：
- 推理循环与执行循环解耦：控制器以目标频率执行当前 chunk，模型异步生成下一个 chunk
- Chunk 边界融合（RTC 启发）：用指数衰减权重平滑过渡
```
g(ρ_i) = ρ_i · (e^{ρ_i} - 1) / (e - 1)
w_i = 1 (0 ≤ i < d), 1-g(ρ_i) (d ≤ i < L), 0 (i ≥ L)
ã_new_i = w_i · a_remain_i + (1-w_i) · a_new_i
```
- 维护延迟队列 Q，用 max(Q) 作为保守估计确定冻结前缀长度

**内存与部署约束**：
- 需要 FP8 支持的 GPU（如 H100/Ada）才能发挥量化优势
- Vidu VAE 编码器需要额外显存（论文未明确模型参数量）
- 三流架构的显存占用高于单流 VLA（三个独立 Transformer 流）

**评测设置**：
- **仿真**：RoboTwin 2.0，50 个任务，多任务训练
  - 干净场景：每任务 50 演示 = 2,500 轨迹
  - 随机化场景：每任务 500 演示 = 25,000 轨迹
  - 视频下采样至 5 Hz，动作下采样至 10 Hz
- **世界模型**：WorldArena 基准，16 项指标覆盖 6 个感知子维度

- RoboTwin 2.0 干净场景：95.8%（比 LingBot-VA 高 2.9%，比 Motus 高 7.1%）

- 50 个任务中 24 个干净/25 个随机化达到 100% 成功率
- 42/44 个任务超过 90% 成功率
- 任务多样性扩展比数据量扩展更有效（任务扩展曲线更陡峭）

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- 五种推理模式切换（VLA/WM/VGM/IDM/联合预测）——同一模型
- 任意数量相机视图输入（通过 3D RoPE 视图偏移）
- 跨具身迁移（相对 EEF 表示 + 异构数据预训练）
- 11 Hz 实时推理（54× 加速栈）
- 长 horizon 任务（AR chunk-level rollout）
- 鲁棒处理视觉条件噪声（LingBot-VA 风格增强）

**不能做什么 / 失败模式**：
- **Hanging Mug 任务**：干净 55% / 随机化 43%——这是所有模型共同的难点，涉及精细的悬挂操作
- **Turn Switch 任务**：82%/84%——虽然优于 π0.5 的 62%/54%，但仍低于平均水平
- 实验仅在仿真（RoboTwin 2.0）和有限真实场景验证，泛化到全新机器人平台的风险未知
- 依赖闭源 Vidu 视频生成基座，限制了独立复现
- 未见对单臂机器人、移动机器人、人形机器人的评估

### 6.1 隐含假设 (Hidden Assumptions)

- **Vidu VAE 的泛化性假设**：论文假设 Vidu 在通用视频上训练的 VAE 编码能直接适用于机器人操作视频，但未验证当操作视频与训练视频分布差异大时的表现
- **相对 EEF 表示的普适性**：相对坐标假设所有具身的运动学可以用同一套相对表示捕获，但不同机器人的关节限制、工作空间差异可能被忽略
- **V2A 非对称注意力的无损性**：论文声称 V2A 风格推理"本质上无损"（子百分比波动），但这仅在 RoboTwin 2.0 上验证，可能在更复杂任务中引入偏差
- **DiT Cache 的阈值 γ 通用性**：缓存策略的阈值可能需要针对不同任务/机器人调整，论文未讨论自适应机制
