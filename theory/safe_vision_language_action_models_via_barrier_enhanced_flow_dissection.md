### 1.2 关键机制 (Key Mechanism)

本文的核心机制分三步：

1. **Action Chunk 安全定义**：将传统单状态安全扩展为整个 action chunk 的安全。一个大小为 H 的 action chunk z = [q₁, q₂, …, q_H] 是安全的，当且仅当 chunk 中所有动作 q_i 都满足 h(q_i) ≥ 0。

2. **Log-Sum-Exponential 聚合屏障**：用 min 操作符组合 H 个屏障函数会导致不可微问题。本文用平滑近似：
   ```
   h(z_check) = -(1/κ) · ln(Σ_{i=t}^{t+H} exp(-κ · h(q_i)))
   ```
   其中 κ > 0 是平滑参数。小 κ → 更平滑但更保守；大 κ → 更接近 min 算子。

3. **CBF-QP 嵌入 FM 去噪**：在 FM 的 ODE 中注入修正项 δs，通过最小化 ‖δ‖² 使修正尽可能小，同时满足 CBF 约束。

⚡ **Eureka Moment**：不在 VLA 输出后做安全过滤，而是把安全约束变成 FM 去噪 ODE 的一个内嵌修正项——安全成为生成过程的内在属性，而非外挂补丁。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
δ_s = ReLU(-α·h(z) - ∇_z h · v_θ(τ,z)) / ‖∇_z h‖² · ∇_z h
```

**目标**：在 FM 去噪过程中，找到最小的修正 δ_s，使得修正后的向量场满足 CBF 安全约束。

**核心方程分解**：

1. **FM 去噪 ODE（原始）**：
   ```
   dψ(τ,z)/dτ = v(τ, ψ(τ,z));  ψ(0,z) = z
   ```
   τ ∈ [0,1] 是去噪时间，z(τ=0) 是噪声采样，z(τ=1.0) 是去噪后的 action chunk。

2. **Action Chunk 聚合屏障函数**：
   ```
   h(z_check) = -(1/κ) · ln(Σ_{i=t}^{t+H} exp(-κ · h(q_i)))
   ```
   下界保证：min_i h(q_i) - (ln H)/κ ≤ h(z_check) ≤ min_i h(q_i)

3. **CBF-QP 优化问题**：
   ```
   min_δ  (1/2)·‖δ‖²
   s.t.   ∂h/∂z · (v_check_θ(τ,z) + δ) ≥ -α·h(z)
   ```

4. **闭式解（KKT 条件）**：
   ```
   δ_s = ReLU(-α·h(z) - ∇_z h · v_θ(τ,z)) / ‖∇_z h‖² · ∇_z h
   ```

5. **分布偏移有界性（Corollary 1）**：
   ```
   ε_bar² ≤ ε² + ∫_0^1 E[‖δ_s(z,τ)‖²] dτ
   W_2(π_hat_1, π_1) ≤ ε_bar · exp(∫_0^1 L_bar dτ)
   ```

> 符号说明：
> - τ: FM 去噪时间，[0,1] 区间
> - z: action chunk ∈ R^{H×n}，H 是 chunk 长度，n 是关节维度
> - v_θ(τ,z): 学习的 FM 向量场
> - h(q): 控制屏障函数，h(q) ≥ 0 表示状态 q 安全
> - α: CBF 指数衰减率参数
> - κ: LSE 聚合平滑参数
> - δ_s: CBF 修正项
> - ε: FM 向量场 L2 逼近误差上界
> - L: 向量场 Lipschitz 常数

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 2 关节机械臂（n=2），action chunk 大小 H=3，即一次生成 3 个时间步的关节目标位置。

**场景**：机械臂在桌面前方操作，安全约束是末端执行器不能穿过桌面（z 坐标 ≥ 0）。

**Barrier Function 设计**：
```
h(q) = q_z  （末端执行器的 z 坐标）
```

**假设当前 FM 生成的 action chunk**：
```
q₁ = [0.3, 0.1]   → h(q₁) = 0.1 > 0 ✓ 安全
q₂ = [0.2, -0.05] → h(q₂) = -0.05 < 0 ✗ 不安全（穿过了桌面）
q₃ = [0.1, 0.08]  → h(q₃) = 0.08 > 0 ✓ 安全
```

**LSE 聚合屏障**（取 κ=10）：
```
h(z_check) = -(1/10) · ln(exp(-10·0.1) + exp(-10·(-0.05)) + exp(-10·0.08))
           = -(1/10) · ln(exp(-1) + exp(0.5) + exp(-0.8))
           = -(1/10) · ln(0.368 + 1.649 + 0.449)
           = -(1/10) · ln(2.466)
           = -0.090
```
h(z_check) < 0 → 整个 chunk 被判定为不安全。

**CBF-QP 修正**（假设 α=5，∇_z h = [0, 0, 0, 0, 0, 1]，即只有 q₃ 的 z 分量影响屏障）：
```
v_θ(τ,z) 在 z 方向的分量 = -0.2（FM 想让 q₃ 向下移动）

δ_s = ReLU(-5·(-0.090) - 1·(-0.2)) / 1² · 1
    = ReLU(0.45 + 0.2)
    = 0.65
```

修正后的向量场在 z 方向的分量变为 -0.2 + 0.65 = 0.45，即向上推动，避免穿过桌面。

**修正后的 q₃**：
```
q₃_safe = [0.1, 0.08 + 0.65·Δτ]  （Δτ 是 FM 步长，假设 0.1）
        = [0.1, 0.145]  → h(q₃) = 0.145 > 0 ✓
```

## 4. 工程视角 (Engineering View)

| 工程维度 | 分析 |
|----------|------|
| 推理延迟 | 每个 FM 去噪步增加一次闭式修正计算（梯度 + 标量运算），无 QP 求解器开销。相比后处理 CBF（每控制周期一次 QP），总开销 = FM 步数 × 修正开销。若 FM 用 4 步去噪，则每 chunk 增加 4 次小计算 |
| 吞吐 | 闭式解可完全向量化，适合 GPU 并行。chunk 内 H 个动作的屏障梯度可批量计算 |
| 内存 | 无额外内存开销。只需存储 barrier function h(q) 及其梯度 ∇h |
| 部署约束 | 需要知道机器人运动学（计算 h(q)）；不需要动力学模型（dynamics-free CBF） |
| 模块化 | 完全模块化——不修改 VLA 权重，仅在推理时注入。可插拔到任何使用 FM 的 VLA |
| 调参 | κ 控制安全保守程度，α 控制安全恢复速率。两者均可在线调整 |
| 与现有 VLA 集成 | 需修改 FM 推理 loop：在每一步去噪后计算 δ_s 并注入。对 OpenVLA/π0 等使用 FM 的模型可直接套用 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **Barrier Function 可设计性**：假设对于每个安全场景，都能找到一个合适的 h(q)。这在结构化环境中可行，但在开放世界中极具挑战性。

2. **紧凑配置空间**：Corollary 1 的证明假设机器人运行在"紧凑配置空间且远离运动学奇异点"。在奇异点附近，‖∇_z h‖ 可能趋近于 0，导致 δ_s 发散。

3. **CBF 可行性**：QP 的可行性依赖于安全集非空。在某些极端场景下（如被障碍物包围），可能不存在满足所有约束的 δ。

4. **无模型 CBF 的保守性**：dynamics-free CBF 通常比基于模型的 CBF 更保守——这是已知 trade-off，但论文未量化保守程度。

5. **LSE 聚合的保守性下界**：定理 2 显示 LSE 近似比真实 min 低 (ln H)/κ。对于 H=16 的 chunk，κ=10 时保守性偏差约 0.28。这意味着实际安全裕度比理论值小。
