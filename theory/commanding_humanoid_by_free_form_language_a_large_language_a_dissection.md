### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **统一词汇的必要性**：人形机器人数据稀缺（遥操作成本高），但人类动作 - 文本数据丰富。通过跨 embodiment 的 VQ-VAE，让人类和机器人动作共享同一离散空间，借用人类数据规模。

2. **词汇导向蒸馏**：直接从语言生成连续轨迹难以保证物理可行性。先训练一个能完美跟踪连续轨迹的 teacher，再蒸馏成 token 条件的 student——把物理约束"编译"进词汇执行层。

3. **两阶段微调**：SFT 学语义映射（文本→token），RLFT 注入物理先验（token 序列在仿真中 rollout 的反馈）。闭环训练确保生成的 token 序列既能被理解又能被执行。

⚡ **Eureka Moment**：**同一 token 在人和机器人身上代表相同的动作原语**——这不是简单的 retargeting，而是通过跨模态重建损失强制对齐，使得 LLM 可以在统一空间推理，无需关心 embodiment 差异。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L = L_intra + α·L_commit + β·L_cross
```

**目标**：学习统一 tokenizer，使同一 token 在人和机器人身上解码出语义等价的运动原语。

**公式展开**：

```
L_intra = ||m_h - D_h(E_h(m_h))||² + ||m_r - D_r(E_r(m_r))||²
L_cross = ||m_r - D_r(E_h(m_h))||² + ||m_h - D_h(E_r(m_r))||²
L_commit = ||E(m) - sg[z]||²  (codebook commitment loss)
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| m_h, m_r | 人类/机器人运动序列 |
| E_h, E_r | 人/机器人编码器 |
| D_h, D_r | 人/机器人解码器 |
| z | 量化后的 latent token |
| α, β | 平衡系数（commitment / cross 损失权重） |
| sg[·] | stop-gradient 操作 |

**直觉**：
- L_intra 保证各自模态内的重建质量
- L_cross 强制跨模态对齐——人类动作编码的 token，用机器人解码器解码出来应该是等价的机器人动作
- L_commit 保证编码器输出靠近 codebook 向量

> 符号与本文/相关文档保持一致：E=Encoder, D=Decoder, L=Loss, m=motion, h=human, r=robot

## 4. 工程视角 (Engineering View)

| 工程指标 | 数值/约束 | 含义 |
|----------|-----------|------|
| 词汇大小 | 隐式分块：有效词汇 ~10⁴-10⁵ | 比单 codebook VQ-VAE 更紧凑 |
| 控制频率 | 100-500Hz (Student Controller) | 需实时响应，低延迟 |
| LLA 推理 | 事件触发（每条指令一次） | 非高频，可接受秒级延迟 |
| 仿真 rollout | RL 阶段每 step 需物理仿真 | 计算密集，需 GPU 加速 |
| Sim2Real | Unitree G1 / Booster T1 已验证 | 但需系统辨识 + 域随机化 |
| 内存占用 | VQ-VAE codebook + LLA 权重 | 嵌入式部署需量化/剪枝 |

**Trade-off**：
- 词汇越大 → 表达力越强，但 LLA 训练越难收敛
- RL 奖励权重越高 → 物理可行性越好，但语言泛化可能受限
- 仿真保真度越高 → Sim2Real 越容易，但训练越慢

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- 自由形式语言指令 → 人形机器人全身动作（首次实现）
- 复杂、抽象指令理解（"自信快乐地走"、"僵尸来了"）
- 跨 embodiment 知识迁移（人类数据 → 机器人控制）
- 物理可行的动作生成（RL 注入物理先验）

**不能做什么**：
- 词汇覆盖范围外的新颖动作（VQ-VAE 的固有限制）
- 需要精确力控制的接触丰富任务（如抓取易碎物体）
- 长时序复杂任务规划（如"先走到桌子旁，拿起杯子，喝水"——可能需要 hierarchical 扩展）
- 极端扰动下的恢复（论文提到增强鲁棒性，但未量化极限）

### 6.1 隐含假设 (Hidden Assumptions)

1. **人类 - 机器人动作可对齐**：假设存在双射映射，使得同一 token 在两种 embodiment 上语义等价。但对于某些动作（如人类手指精细操作），机器人可能无法精确复现。

2. **仿真 - 真实差距可跨越**：RL 在仿真中训练，但部署到真实机器人。论文在 G1/T1 上验证，但未说明域随机化策略或系统辨识细节。

3. **词汇覆盖足够**：假设训练数据覆盖的动作原语足够组合出测试时的指令。对于开放词汇指令，可能存在 OOV (out-of-vocabulary) 问题。

4. **语言 - 动作对齐是静态的**：LLA 学习的是固定映射，但实际交互中用户可能用不同方式描述同一动作。
