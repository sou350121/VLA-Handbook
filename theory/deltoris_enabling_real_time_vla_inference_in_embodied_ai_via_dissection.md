### 1.2 关键机制 (Key Mechanism)

Deltoris 由三层技术组成，逐层解决 Diffusion VLA 推理的瓶颈：

**第一层：时序感知比特级稀疏（Temporal-Aware Bit-Level Sparsity）**
- 核心观察：连续控制步的输入高度相似（>98.5% 像素不变，平均像素差值 1.3）
- 方法：不计算 `W·x_t`，而是计算 `W·Δx_t` 并加到缓存的前一步输出 `y_{t-1}`
- 效果：比特级稀疏度从权重的 ~50% 提升到激活差分的 >90%，最多消除 92.9% 的位操作

**第二层：推测推理（Speculative Inference）**
- 问题：比特稀疏引入额外 off-chip 数据流量（非线性操作后需重建完整激活值）
- 方案：轻量 VLA 先生成 k 步推测轨迹 → 大型 VLA 批量验证
- 效果：模型权重只需加载一次，摊薄 k 个验证步的内存流量

**第三层：定制加速器架构**
- 1D 脉动比特串行 PE 阵列
- 输出驻留（output-stationary）数据流，跨 PE 共享激活值
- 消除比特串行加速器中常见的 PE 负载不平衡问题

⚡ **Eureka Moment**：机器人控制循环中连续帧之间的时间冗余（>98% 像素不变）比扩散去噪步之间的相似性更高、更持久——"只算变化的比特"比"减少去噪步数"是更长期的优化方向。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
y_t = y_{t-1} + W · Δx_t    where Δx_t = x_t - x_{t-1}
```

**目标**：用差分更新替代完整前向传播，利用 Δx_t 的高比特稀疏性跳过零位运算。

**逐层展开**：

Step 1 — 差分激活：
```
Δx_t = x_t - x_{t-1}          （连续控制步的激活差）
```

Step 2 — 比特级稀疏投影：
```
W · Δx_t = (-1)^s_t × Σ_{b=0}^{B-1} W × v_{t,b} × 2^b
```
其中 s_t 是符号位，v_{t,b} ∈ {0,1} 是 Δx_t 第 b 位的零指示器——只有 v_{t,b}=1 的位才参与累加。

Step 3 — 输出重建：
```
y_t = y_{t-1} + W · Δx_t      （复用前一步缓存输出）
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| x_t | 当前控制步的输入激活 |
| x_{t-1} | 前一步的输入激活 |
| Δx_t | 差分激活（高度稀疏） |
| W | 模型权重（固定不变） |
| y_t | 当前输出激活 |
| y_{t-1} | 前一步输出（缓存复用） |
| s_t | 差分激活的符号位 |
| v_{t,b} | 第 b 位的零指示器 |
| B | 比特宽度 |

**直觉**：传统方法每步做 `W·x_t`（全部位都要算），Deltoris 只做 `W·Δx_t`（只有变化位算）。当 90%+ 的位为零时，计算量直接降到原来的不到 10%。

> 符号与本文保持一致。扩散去噪步公式沿用原文：
> ```
> x'_{t-1} = α_t · (x'_t - β_t · z'_t) + σ_t · n'_t
> z'_t = F(x'_t, t)
> ```
> 其中 α_t, β_t 为预定义超参，σ_t·n'_t 为随机重噪声项。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的线性投影层，权重 W 和激活 x 均为 4-bit 整数：

```
W  = [1011, 0101, 1100]   (3 个权重)
x_{t-1} = [0100, 0011, 0110]  (前一步激活)
x_t     = [0101, 0011, 0110]  (当前步激活，仅第 1 个元素变了 1)
```

**传统方法**（完整计算）：
```
y_t = W · x_t
需要 3 × 4 = 12 次位级乘加运算
```

**Deltoris 方法**：
```
Δx_t = x_t - x_{t-1} = [0001, 0000, 0000]  (仅 1 个非零元素)

比特展开 Δx_t[0] = 0001:
  符号 s = 0 (正数)
  位模式: v_0=1, v_1=0, v_2=0, v_3=0
  只有 b=0 位是 "1"，需要计算

W · Δx_t = (-1)^0 × (W × 1 × 2^0) = W × 1 = [1011, 0101, 1100]

y_t = y_{t-1} + W · Δx_t
```

**计算量对比**：
- 传统：12 次位操作
- Deltoris：3 次位操作（只有 W 的 3 个元素各加一次，因为 Δx 只有一个非零位）
- **加速比：4×**（此例中），实际论文中因稀疏度 >90%，加速比可达 10×+

**扩散去噪中的累积效应**：
- 每个控制步有 T=50 次去噪迭代
- 每次迭代都复用前一步的缓存输出
- 假设每步节省 90% 计算，50 步累计节省约 50 × 0.9 = 45 步等效计算
- 加上推测解码将 k=3 步的权重加载摊薄为 1 次，进一步减少 off-chip 流量

**关键 trade-off**：

1. **计算 vs 内存**：比特稀疏大幅减少计算量，但将工作负载从计算受限推向内存受限。朴素实现增加 80% off-chip 流量。推测解码通过批量验证摊薄权重加载来解决。

2. **帧间相似性 vs 步间相似性**：作者论证帧间（控制步之间）相似性比步间（去噪步之间）相似性更高且更持久——因为即使扩散模型蒸馏减少去噪步数，高控制频率需求不会变。

3. **推测窗口大小**：窗口 k 越大，权重加载摊薄效果越好；但 k 过大时小模型预测误差累积，大模型验证拒绝率上升。论文设定验证阈值 θ_th = 0.01。

4. **硬件依赖**：算法部分（差分计算+比特稀疏）可独立用于软件优化；但完整加速比需要定制 1D 脉动比特串行 PE 阵列。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **桌面操作任务**：在 PushT 等桌面操作基准上实现实时推理
- **高控制频率场景**：50-200 Hz 的闭环控制，满足安全平滑运动需求
- **多 Diffusion VLA 模型**：算法与具体模型架构解耦，适用于 PAD、Diffusion Policy、UVA 等

### 不能做什么
- **AR-based VLA**：方法专为 Diffusion-based 模型设计，不适用于 OpenVLA 等 AR 模型
- **快速变化的场景**：如果机器人运动极快导致帧间差异大，比特稀疏度下降，加速效果减弱
- **无硬件部署**：完整加速比依赖定制加速器 ASIC/FPGA，纯软件实现无法达到 34.2×

### 6.1 隐含假设 (Hidden Assumptions)

1. **帧间相似性持续存在**：假设未来机器人控制频率继续提高，帧间相似度不会降低。这在大多数操作场景中合理，但在高速动态场景（如跑酷、抓取飞行物体）中可能不成立。

2. **小模型推测质量足够**：推测解码假设轻量模型能生成合理的候选轨迹。如果小模型偏差过大，验证拒绝率会很高，失去摊薄效果。

3. **自注意力可忽略**：自注意力仅占 5.9% 执行时间，因此对其不做差分优化影响有限。但在视觉 token 数量大的模型中（如高分辨率输入），自注意力占比可能上升。

4. **符号幅度表示优于补码**：作者选择符号幅度表示差分激活以减少活跃位数，但未与补码做系统对比。
