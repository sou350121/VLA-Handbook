### 1.2 关键机制 (Key Mechanism)

**为什么线性探针能读出任务进度？**

1. **VLA 的残差流承载时序信息**：Transformer 的残差连接 zⁱ⁺¹ = zⁱ + fⁱ(zⁱ) 使得每一层都累积了关于"当前状态距离完成还有多远"的信息。
2. **大规模机器人预训练建立了进度表征**：实验表明，即使未微调的 base π₀.₅ 也能解码进度（R² 接近微调版），说明预训练阶段机器人数据中的轨迹结构已经编码了这个信号。
3. **任务进度是标量、单调、任务条件**：与"物体高度"等物理状态不同，进度是任务特定的标量，天然适合作为运行时监控信号。

⚡ **Eureka Moment**：VLA 内部已经编码了"任务还剩多少"——你不需要额外训练一个监控模型，只需要一根线性探针去读它。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
τ(x_t) = 1 - t/T,  其中 t = 轨迹中当前步索引, T = 总步数
φ(zⁱ) = wᵀzⁱ + b ≈ τ(x_t)
```

**目标**：从 VLA 中间层嵌入 zⁱ 中线性回归出任务进度 τ ∈ [0,1]。

**探针定义**：
```
φ(zⁱ) = wᵀ · zⁱ + b
```
其中 zⁱ ∈ R^(d×n) 是第 i 层的嵌入（d = 嵌入维度, n = token 数），在 token 维度上均值池化后得到 R^d 向量。

**探针风险（损失）**：
```
R(φ; D) = (1/K) · Σ_k L(φ(zⁱ_k); ζ_k)
```
- L 为 L1 损失（连续标量回归）
- ζ_k 是第 k 个样本的真实进度标签

**变量说明**：

| 符号 | 含义 |
|------|------|
| zⁱ | 第 i 层残差流嵌入（token 均值池化后） |
| w, b | 线性探针的权重向量和偏置 |
| τ(x_t) | 任务进度 = 1 - t/T，归一化剩余时间 |
| φ | 线性探针函数 |
| R(φ; D) | 探针在数据集 D 上的风险（L1 损失） |
| ζ | 目标特征（此处 τ = 任务进度） |

**直觉**：任务进度是一个单调递减的标量信号。VLA 在执行任务时，每一步的输入都隐含了"当前处于轨迹的哪个位置"。由于 Transformer 的残差结构，这个时序信息被编码在嵌入空间中，线性探针只需找到正确的投影方向 w 就能读出它。

> 符号与本文保持一致：zⁱ 表示第 i 层嵌入，φ 表示探针，τ 表示任务进度，𝒯 表示反事实变换。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个抓取任务总共有 T = 50 步。当前处于第 t = 15 步。

**步骤 1：计算真实进度**
```
τ = 1 - 15/50 = 0.70
```
表示任务还剩 70%。

**步骤 2：提取嵌入**
VLA 处理第 15 步的观测 (I₁₅, q₁₅, ℓ)，经过 SigLIP → Gemma Layer 0，得到嵌入 z⁰ ∈ R^d。

**步骤 3：探针预测**
```
τ̂ = wᵀ · z⁰ + b
```
假设训练好的探针给出 τ̂ = 0.68。

**步骤 4：OOD 检测**
假设从 ID rollout 估计出期望完成时间 E[T|ℓ] = 50 步。计算残差：
```
V_τ(t=15) = τ̂ - (1 - t/E[T|ℓ])
          = 0.68 - (1 - 15/50)
          = 0.68 - 0.70
          = -0.02
```
|V_τ| = 0.02，假设阈值 δ = 0.15，未触发 OOD。

**OOD 场景**：假设机器人在 t = 20 时遇到障碍（如物体被移走），无法继续推进。
```
真实进度应为: τ_expected = 1 - 20/50 = 0.60
但探针读出:    τ̂ = 0.72  (仍认为进度在 72%，因为视觉没变)
V_τ(20) = 0.72 - 0.60 = 0.12
```
如果继续卡住，t = 25 时：
```
τ_expected = 1 - 25/50 = 0.50
τ̂ ≈ 0.72  (停滞)
V_τ(25) = 0.72 - 0.50 = 0.22 > δ = 0.15 → 触发 OOD！
```

**关键洞察**：OOD 检测不依赖任何异常样本标签，纯粹依靠"预测进度 vs 期望进度"的偏差。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/特性 | 工程含义 |
|------|-----------|----------|
| 探针参数量 | ~d（d = 嵌入维度，约 2048-4096） | 极轻量，可在线训练 |
| 训练数据需求 | 400 episodes (100/task × 4 tasks) | 少量 ID rollout 即可 |
| 推理开销 | 一次矩阵向量乘法 wᵀz + b | < 0.1ms，可忽略 |
| 部署位置 | Gemma Layer 0（弱解码）或 Layer 10（强解码） | 在动作头之前截取嵌入 |
| 决策频率 | 每个 replan 周期 | 与 VLA replan 频率对齐（通常 5-10Hz） |
| OOD 阈值 δ | 从 ID rollout 校准 | 需为每个任务/指令估计 E[T\|ℓ] |
| 跨任务泛化 | 单探针泛化到未见任务（AUROC 0.833） | 不需要为每个任务重训探针 |

**部署约束**：
- 需要预先知道或估计 E[T|ℓ]（期望完成时间），可通过少量 ID rollout 统计
- 探针冻结后部署，无需在线训练
- 仅支持单臂桌面操作的仿真环境验证，真机部署需重新校准

## 5. 数据与评测 (Data & Eval)

**目标模型**：π₀.₅，在 VLABench 上微调（10 个操作任务，每任务 500 条轨迹）

**探针训练数据**：
- 400 episodes（每任务 100 条），10 个任务共 4000 条
- 评估：每任务 50 条 held-out episodes

**OOD 数据生成**（§4.5）：
- 6 个任务 × 50 ID trajectories = 300 ID 轨迹
- 4 种扰动模式：高斯噪声、颜色偏移、模糊、遮挡
- 3 个注入点：轨迹的 25%/50%/75% 处
- 每任务每模式每注入点 50 条 OOD 轨迹

**评测指标**：
- 弱可解码性：ID 数据集上的 L1 损失 / R²
- 强可解码性：反事实变换后的探针泛化能力
- 可控性：注入后动作分布与真实反事实动作分布的 divergence
- OOD 检测：per-replan AUROC 和 per-episode AUROC

**关键实验结果**：

| 实验 | 关键发现 | 数据来源 |
|------|----------|----------|
| Q1 弱解码 | Layer 0 最佳，R² = 0.95（ naive probe） | Fig 2, §4.2 |
| Q2 跨阶段 | 预训练阶段即建立，微调不显著提升 | Fig 3, §4.2 |
| Q1 强解码 | naive probe 忽略语言输入，R² 不变 | Fig 4 left, §4.3 |

| 跨架构迁移 | ✅ base π₀.₅ 和微调版 π₀.₅ 表现接近 | 信号来自预训练 |

### 不能做什么

| 场景 | 失败 | 原因 |
|------|------|------|
| 策略操控（Steering） | ❌ 注入进度不改变动作输出 | 进度是"可读不可控"信号 |
| 强解码（naive probe） | ❌ 忽略语言输入，对 noun-swap 无响应 | Layer 0 探针纯视觉依赖 |
| 跨架构保证 | ⚠️ 仅 π₀.x 验证，OpenVLA 等未测试 | 架构差异可能影响信号位置 |
| 真机部署 | ⚠️ 仅仿真验证 | 仿真到真实的 gap 未评估 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **进度 = 归一化时间**：论文用 τ = 1 - t/T 定义进度，这假设成功演示中的时间步数与语义完成度一致。如果不同轨迹长度差异大（如策略效率不同），这个定义会混淆"时间流逝"和"任务完成"。
2. **E[T|ℓ] 可估计**：OOD 检测需要预先知道期望完成时间。论文假设这可以从少量 ID rollout 中统计，但如果部署环境中策略行为与 ID 差异大，估计可能不准。
3. **反事实标签为代理**：强解码实验中，counterfactual prompt 的进度标签设为 τ=1.0（零进度），这是近似——真实的反事实任务进度无法直接测量。
4. **单层探针足够**：论文主要使用单层线性探针。更复杂的非线性关系或多层联合解码可能捕获更多信息，但未探索。
5. **单一注入方向**：可控性实验仅在 Layer 0 以固定幅度（τ_boost=0.2）注入。更强的干预或多层联合编辑可能产生不同结果。
