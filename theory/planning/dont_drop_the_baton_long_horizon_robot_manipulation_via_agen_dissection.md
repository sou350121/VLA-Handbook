### 1.2 关键机制 (Key Mechanism)

BATON 解决两个根本性问题：

**问题 ❶ — 探索成本爆炸**
- 全任务探索：K 个子任务各需 T 次尝试 → O(T^K) 次尝试（指数级）
- BATON 方案：每个子任务独立探索 → O(T·K) 次尝试（线性级）
- 类比：接力队不跑一万次全程，而是反复练每一棒交接

**问题 ❷ — 过渡未建模**
- VLA 基元只有退出条件（何时停止），没有进入条件（何时开始）
- 前一个子任务的"残留状态"可能让下一个子任务从训练分布外开始
- BATON 方案：三种过渡契约让边界成为"可检查的接口"

⚡ **Eureka Moment**：将"过渡"本身（而非子任务）作为学习和存储的一等公民——边界上的检查条件比子任务内部的动作更重要，因为"技能死于边界之间"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
Cost(BATON) = O(T · K)    vs    Cost(全任务探索) = O(T^K)
```

其中 T = 单个子任务首次成功所需尝试次数，K = 子任务数量。

**目标**：最小化长视界任务的总探索成本，同时最大化子任务间过渡的可靠性。

**核心方程**（任务分解形式）：
```
T_task = u_1 ⊳ σ_{1,2} ⊳ u_2 ⊳ σ_{2,3} ⊳ ... ⊳ σ_{K-1,K} ⊳ u_K
```

- u_k = 第 k 个子任务（短视界接触丰富技能，~100 步）
- σ_{k,k+1} = 子任务 k 到 k+1 的交接边界（包含三种过渡契约）
- ⊳ = 顺序组合算子

**变量说明**：

| 符号 | 含义 | 备注 |
|------|------|------|
| T_task | 长视界任务 | "摆桌子"等千步级指令 |
| u_k | 子任务 | 开抽屉、拿罐子、放入抽屉等 |
| σ_{k,k+1} | 交接边界 | 三个过渡：调用/交接/前瞻 |
| T | 单子任务探索成本 | 首次成功平均尝试次数 |
| K | 子任务数量 | 千步任务通常 5-15 个子任务 |

**直觉**：BATON 将探索成本从指数 O(T^K) 降为线性 O(T·K)，同时将模糊的"全任务失败"转化为精确的"子任务/边界级失败归因"。关键在于——过渡 σ 不是子任务的副产品，而是显式建模、检查和存储的一等对象。

> 符号与本文保持一致。论文未给出显式损失函数（因为零参数更新），以上为任务分解与成本分析的形式化表达。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 5 子任务的长视界任务（如"从橱柜拿杯子放到桌上"）：

**场景参数**：
- K = 5 个子任务：开橱柜 → 拿杯子 → 关橱柜 → 走到桌边 → 放杯子
- 每个子任务独立探索需 T = 3 次尝试首次成功
- 每个子任务成功率 ~90%（短视界独立）

**全任务探索（Baseline）**：
```
期望尝试次数 = T^K = 3^5 = 243 次全任务尝试
每次尝试 = ~1000 步 × 每步 LLM token = 天文数字
失败归因 = 不知道哪一棒掉了
```

**BATON 子任务探索**：
```
子任务级探索 = T × K = 3 × 5 = 15 次短尝试
组合验证 = 4 次两两组合 + 3 次三组合 + ... ≈ 10 次
总成本 ≈ 25 次短尝试（vs 243 次全任务尝试）
失败归因 = 精确到子任务 u_2 或边界 σ_{2,3}
```

**过渡契约具体化**（以"开橱柜 → 拿杯子"为例）：

1. **调用过渡**（Invocation）：验证器检查腕部相机 → 确认橱柜门已开足够宽 → 才调用 VLA_ACT 伸入拿杯子
2. **交接过渡**（Handoff）：记录"橱柜门开启角度 ≥ 45°" → 拿杯子子任务开始前验证此条件 → 若不满足则修复（再推一下门）
3. **前瞻过渡**（Lookahead）：调度器知道"拿杯子"后需要"关橱柜" → 选择"握住杯柄朝外"的策略而非"握住杯底"，因为后者会挡住关门的动作

**关键数字**：论文在 RoboMemArena 基准上，BATON 相比 SoTA（RoboMem 方法）：
- 任务成功率提升 **+11.6 个百分点**（论文 Abstract）
- 累积成功率提升 **+14.9 个百分点**（论文 Abstract）
- 对比：π_0.5 在孤立子任务上表现良好，但千步任务仅完成 ~10%（论文 §1）

## 4. 工程视角 (Engineering View)

| 工程维度 | 分析 |
|----------|------|
| **延迟** | 每次子任务探索需 LLM 推理 + VLA 推理 + 环境交互；调用过渡增加一层验证器推理（~数百 ms 额外延迟） |
| **吞吐** | 子任务可并行探索（不同子任务独立），但组合验证需串行 |
| **步数** | 子任务级 ~100 步/次尝试；全任务 ~1000 步/次尝试。BATON 总交互步数大幅减少 |
| **Token 成本** | 未详细披露。探索阶段每个失败尝试都产生 LLM token；记忆中的语言描述也需 token 存储和检索 |
| **内存** | 三种记忆（技能/过渡/失败）以语言形式存储，规模随任务数线性增长 |
| **部署约束** | 需要：(1) LLM Agent 框架 (2) 冻结 VLA 模型 (3) 腕部相机 (4) 解析运动基元（IK 求解） |
| **量化误差** | VLA 冻结故无训练误差；但 LLM 决策的随机性可能影响探索一致性 |
| **零训练优势** | 无需收集长视界演示数据；新任务只需测试时探索一次 |

**工程含义**：BATON 将 VLA 从"需要长视界训练的模型"转变为"可调用的接触黑盒"。工程团队只需维护一个冻结 VLA + Agent 框架 + 记忆系统，即可适配任意长视界任务——代价是 LLM 推理的 token 成本和探索阶段的时间。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

| 能力 | 说明 |
|------|------|
| 千步级多阶段任务 | 通过子任务分解 + 层次组合实现 |
| 零参数更新适配新任务 | 测试时探索即可，无需训练 |
| 失败精确归因 | 失败定位到具体子任务或边界 |
| 记忆复用 | 已学过的子任务和过渡可跨任务复用 |
| 保留 rival strategies | 同一子任务可存储多种执行策略，由调度器根据后续需求选择 |

### 不能做什么 / 局限

| 局限 | 原因 |
|------|------|
| 仅仿真验证 | 实验仅在 RoboMemArena 上，未报告真实机器人结果 |
| 依赖 LLM 能力 | 分解质量、探索效率、记忆语言化都依赖 LLM 推理能力 |
| 探索阶段成本高 | 虽然 O(T·K) 远优于 O(T^K)，但仍需多次环境交互 |
| 分解质量敏感 | 如果 Decomposer 分解不当（子任务边界不可检查），系统失效 |
| 腕部相机依赖 | 调用过渡需要腕部相机做场景就绪验证 |
| 未覆盖动态环境 | 假设环境在任务执行期间静态，不处理动态干扰 |

### 6.1 隐含假设 (Hidden Assumptions)

| 假设 | 风险 |
|------|------|
| 任务可被合理分解为独立子任务 | 某些长视界任务的子任务高度耦合，难以找到可检查的边界 |
| LLM 能写出可靠的语言化过渡契约 | LLM 生成的条件可能不完整或不准确 |
| 冻结 VLA 在预 staging 后的状态分布内工作 | 如果解析基元的定位误差过大，VLA 仍会 OOD 失败 |
| 腕部相机能可靠验证场景就绪 | 视觉验证器本身的准确率未报告 |
| 仿真到现实的 gap 可被忽略 | 仿真的物理接触与真实机器人差异显著 |
