## 1. 核心架构/方法总览 (Overview / Architecture)

RoboStream 将 VLM 规划循环从"每步孤立推断"改造为"带持久记忆的因果推理"。整个框架分为三个层级：

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | VoxPoser / SoFar（基线） | RoboStream |
|------|--------------------------|------------|
| **空间感知** | 每步从 RGB-D 重建几何约束 | STF-Tokens 跨步持久化 3D 几何+视觉 |
| **因果记忆** | 无；每步视为独立决策 | CSTG 滑动窗口记录动作→状态转移 |
| **遮挡处理** | 物体消失即遗忘 | CSTG 维护物体恒常性，因果推断隐藏状态 |
| **训练需求** | 零微调 | 零微调（相同） |
| **规划输入** | 当前帧图像 + 语言指令 | CSTG + 标注图像 + 目标规格 |
| **输出形式** | 直接 6-DoF 位姿 | 语义指令 → 确定性几何实例化 |
| **误差传播** | 累积→级联失败 | 因果验证 + 前置条件检查→阻断 |
| **VLM 角色** | 端到端规划+执行 | 仅语义推理；坐标由确定性几何解析 |

### 1.2 关键机制 (Key Mechanism)

**问题诊断**：论文精准指出了两个紧密耦合的表征缺陷：

1. **Ungrounded Spatial Perception（未锚定的空间感知）**：现有系统通过图像中心感知隐式推断空间关系，没有几何锚定和跨步身份绑定。每步从原始像素重建几何，小误差累积成空间幻觉。

2. **Untracked Causal History（未追踪的因果历史）**：动作不可逆地改变环境，但现有方法不保留动作→状态转移的记录。被移动的物体"去了哪里"、被遮挡的物体"还在不在"，规划器一无所知。

**解决方案**：

- **STF-Tokens（时空融合标记）**：将每个物体的视觉外观（masked image → VLM encoder → 16×16 patch tokens）与 3D 几何（质心 + 高斯形状参数）融合为单一标记序列，序列化到 VLM 的语言嵌入空间中。VLM 不再看原始像素，而是看结构化的物体实例引用。

- **CSTG（因果时空图）**：维护一个滑动窗口（长度 K）的时空标记历史，节点=物体（带身份持久化），边=物体间欧氏距离+方向偏移，日志=语义事件（位移/碰撞/遮挡/子任务完成）。

⚡ **Eureka Moment**：不需要训练 VLM 学会记忆——只需要把视觉证据和 3D 几何编码成 VLM 能直接 attention 的结构化标记，VLM 本身就具备跨标记推理的能力。训练-free 的本质是"用表征设计替代参数学习"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
τ_i^t = ⟨v_i^t, c_i^t, s_i^t, t⟩
     = ⟨VisualEncoder(mask_i ⊙ I_t), median(P_i), GaussianParams(P_i), t⟩
```

**目标**：将每个物体的多模态信息（视觉外观 + 3D几何 + 时间戳）编码为单一标记序列，使 VLM 能在同一嵌入空间中联合 attention 视觉和空间信号。

**公式分解**：

| 符号 | 含义 | 来源 |
|------|------|------|
| v_i^t | 物体 i 在时刻 t 的视觉证据 | SAM3 掩码 → masked image → VLM visual encoder → 16×16 patches → 语言空间聚合 |
| c_i^t | 物体 i 的 3D 质心 | 点云 P_i 的中位数，R^3 |
| s_i^t | 物体 i 的形状表征向量 | 每轴 (μ_a, σ_a, a_min, a_max)，a ∈ {x,y,z}，共 12 维 |
| t | 时间戳 | 当前规划步索引 |
| τ_i^t | 完整的 STF-Token | 四元组，序列化到 VLM 语言嵌入空间 |

**直觉**：STF-Token 的本质是把"物体"从像素集合变成 VLM 可以像处理单词一样处理的结构化单元。视觉证据 v 让 VLM 认出"这是什么"，质心 c 告诉它"在哪里"，形状 s 描述"有多大、什么形状"，时间戳 t 标记"什么时候观测到的"。四者融合后，VLM 的 attention 机制自然就能跨物体、跨时间步做推理——不需要任何额外训练。

**图更新**：
```
G_t^{CST} = Ψ_graph(T_t^{STF}, G_{t-1}^{CST})
          = (G_t = (V_t, E_t), H_t^K)
```
- 节点 V_t：每个 STF-Token 对应一个物体节点，维护 K 步滑动窗口历史
- 边 E_t：d_ij = ||c_i - c_j||_2（欧氏距离），Δc_ij = c_j - c_i（方向偏移）
- 日志 H_t^K：语义事件记录（位移/碰撞/遮挡/子任务完成），含时间戳、位置、因果源

**动作生成与实例化**：
```
â_t = Π_θ(I_goal, P_t | G_t^{CST})    // VLM 语义推理
a_t = Φ_inst(â_t, G_t^{CST})           // 确定性几何解析
```
关键设计：语义推理（VLM 负责）和坐标提取（确定性解析负责）解耦，避免 VLM 直接输出不精确的数值坐标。

> 符号与本文/相关文档保持一致。Φ_enc、Ψ_graph、Π_θ、Φ_inst 分别对应编码、图更新、推理、实例化四个算子。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个三步积木搭建任务：
- 初始状态：红色方块在 (0,0,0)，蓝色方块在 (2,0,0)，绿色方块在 (1,1,0)
- 目标：将绿色方块叠到红色方块上

**Step 1：放置绿色到红色上**

```
① 感知: VLM 识别 3 个物体 → SAM3 生成 3 个掩码
② STF-Token 构建:
   τ_red   = ⟨v_red,   [0,0,0],   {μ=(0,0,0),σ=(0.1,0.1,0.1)}, t=1⟩
   τ_blue  = ⟨v_blue,  [2,0,0],   {μ=(2,0,0),σ=(0.1,0.1,0.1)}, t=1⟩
   τ_green = ⟨v_green, [1,1,0],   {μ=(1,1,0),σ=(0.1,0.1,0.1)}, t=1⟩

③ CSTG 构建:
   V_1 = {red, blue, green}
   E_1 = {d(red,blue)=2.0, d(red,green)=1.41, d(blue,green)=1.41}
   H_1^K = {}  (初始为空)

④ VLM 推理: "目标是将绿色放到红色上 → 当前绿色在(1,1,0)，
   需要移动到红色(0,0,0)上方约(0,0,0.1)处"
   â_1 = "pick green, place at red_top"

⑤ 实例化: Φ_inst 从 CSTG 中 τ_green 提取 c_green=[1,1,0] 作为抓取点，
   从 τ_red 提取 c_red=[0,0,0] 计算放置点 = [0,0,0.1]
   a_1 = (grasp_pos=[1,1,0], place_pos=[0,0,0.1], grasp=True)

⑥ 执行后状态更新:
   τ_green 更新为 t=2, c=[0,0,0.1]
   CSTG 日志: H_2^K = {event="place_green_on_red", time=1, source="VLM"}
```

**Step 2：假设手遮挡了蓝色方块**

```
① 感知: RGB-D 中蓝色方块被机械臂遮挡 → SAM3 无法检测到蓝色

② 关键差异（RoboStream vs 基线）:
   - VoxPoser/SoFar: 蓝色方块"消失"，规划器不知道它在哪
   - RoboStream: CSTG 中 τ_blue 的滑动窗口保留 t=1 的历史记录
     H_2^K 中记录 "blue_last_seen at [2,0,0], t=1"
     VLM 推理时知道蓝色方块仍在 (2,0,0)，不会被碰撞

③ VLM 推理（带因果记忆）: "蓝色在(2,0,0)，绿色要放到红色上，
   路径不经过蓝色 → 安全"
```

**Step 3：恢复任务（遮挡后还原）**

```
假设任务变为：先用杯子遮住蓝色方块，然后执行 distractor 步骤，
最后恢复蓝色方块到原位。

CSTG 日志追踪:
  t=1: blue at [2,0,0]
  t=2: event="cover_blue_with_cup", blue_last_pose=[2,0,0]
  t=3: distractor steps (移动其他物体)
  t=4: "restore blue" → VLM 从 CSTG 查询 blue 的 last_known_pose=[2,0,0]
       → 成功恢复

基线方法: 蓝色在 t=2 被遮住后完全丢失，t=4 无法恢复 → 任务失败
```

这个例子展示了 STF-Tokens + CSTG 的核心价值：**即使视觉证据暂时消失，结构化记忆仍然维持物体的身份和位置**。

## 4. 工程视角 (Engineering View)

| 维度 | 评估 |
|------|------|
| **每步延迟** | 每步需要：VLM 物体识别 + SAM3 分割 + VLM 视觉编码 + VLM 因果推理 + 几何实例化。至少 2 次 VLM 调用（识别+推理），加上 SAM3 推理。估计每步 2-5 秒（取决于 VLM 规模） |
| **吞吐** | 不适合高频控制（>10Hz）。适合高层规划（0.2-0.5Hz），底层由传统控制器执行 |
| **内存** | CSTG 滑动窗口大小 K 是关键超参。K 越大记忆越长，但 VLM context window 有限。每物体 STF-Token ≈ 16×16=256 patches + 几何序列化 ≈ 300-500 tokens/物体。10 个物体 × 500 tokens = 5000 tokens/context |
| **量化误差** | STF-Token 的几何参数 (μ,σ,a_min,a_max) 序列化到文本嵌入空间，精度受 tokenizer 粒度影响。对于毫米级操作可能不够精细 |
| **部署约束** | 需要 RGB-D 相机（RealSense D435i）、SAM3（开源分割模型）、VLM（Qwen3-VL 系列）。硬件门槛：GPU 推理 + 机械臂 + 深度相机 |
| **VLM 规模敏感性** | 遮挡恢复：8B=33.3%，32B=未报告，235B=88.9%。能力随模型规模单调增长，小模型可能不足以利用结构化记忆 |
| **训练-free 优势** | 无需收集机器人数据、无需 RL/BC 训练、跨场景零迁移。代价是推理计算成本高 |

**工程含义**：RoboStream 不是一个实时控制器，而是一个"认知层"——它负责长视界任务规划和因果推理，底层需要传统的运动规划和控制器来执行具体的 6-DoF 轨迹。这种分层架构与 HiRobot、RoboMatrix 等 hierarchical 方法一致，但 RoboStream 的独特贡献在于用 CSTG 提供了跨步的因果一致性保证。

| 因果状态追踪 | 记录动作→环境改变的因果链 | Block Disassembly 66.7% |
| 遮挡下物体恒常性 | 物体被完全遮挡后仍能推理其位置 | Hide & Restore 88.9% (235B) |
| 零微调跨场景迁移 | 无需场景特定训练 | 所有基准均 zero-shot |
| 规模可扩展性 | 能力随 VLM 规模单调增长 | 8B→235B 持续提升 |

### 失败模式

| 失败场景 | 原因 | 严重程度 |
|----------|------|----------|
| 小模型遮挡恢复差 | 8B 模型不足以利用结构化记忆进行因果推理 | 高（33.3%） |
| 复杂接触力学 | 仅跟踪几何位置，不建模接触力/摩擦力 | 中 |
| 动态干扰 | 未明确处理外部扰动（如人碰倒积木） | 中 |
| 非刚性物体 | STF-Token 假设刚体（高斯形状参数），不适用于软体/可变形的物体 | 高 |
| 大规模场景 | 物体数量多时 context window 可能不够 | 中 |
| 每步 VLM 调用延迟 | 不适合需要快速反应的场景 | 高（应用限制） |

### 6.1 隐含假设 (Hidden Assumptions)

1. **RGB-D 始终可用且准确**：论文假设深度图始终可靠。但在强反光表面、透明物体、或远距离场景下，深度传感器会失效。论文未讨论深度失效时的降级策略。

2. **SAM3 分割始终准确**：物体身份持久化依赖 SAM3 每步正确分割同一物体。如果 SAM3 将同一物体在不同步中分割为不同掩码（或反之），STF-Token 的身份绑定会出错。论文未报告 SAM3 的分割一致性。

3. **刚体假设**：形状参数使用高斯分布（μ,σ）描述，隐含假设物体近似刚体且形状稳定。对于可变形物体（布料、绳索、软体），高斯参数无法捕捉形状变化。

4. **VLM 因果推理能力**：框架假设 VLM 能够利用 CSTG 中的结构化信息进行因果推理。但 8B 模型在遮挡恢复中仅 33.3% 成功率暗示：小模型可能"看不懂"结构化记忆。这是否意味着框架实际上需要足够大的 VLM？如果是，"training-free" 的适用范围就受限。

5. **静态环境**：未讨论环境中存在其他动态 agent 或人类干扰时的行为。CSTG 的事件检测可能无法区分"计划内位移"和"外部干扰"。

## 7. 与相关工作对比 (Comparison)

| 方法 | 关注点 | 架构 | 训练方式 | 持久记忆 | 因果推理 | 适用场景 |
|------|--------|------|----------|----------|----------|----------|
| **VoxPoser** (2023) | 3D 价值图零-shot 规划 | VLM → 3D value maps → 采样 | 零微调 | ❌ 每步重建 | ❌ | 短视界操作 |
| **SoFar** (2025) | 语言→6-DoF 位姿映射 | VLM → 6-DoF poses | 零微调 | ❌ 每步重建 | ❌ | 短视界精确放置 |
| **CoPa** (2024) | 几何关键点约束 | VLM → keypoints → constraints | 零微调 | ❌ 每步重建 | ❌ | 关键点约束操作 |
| **Inner Monologue** (2023) | 自校正循环 | VLM 多轮自我对话 | 零微调 | ❌ 无跨步记忆 | 部分（反应式） | 短视界自校正 |
| **HiRobot** (2025) | 分层指令分解 | VLM → 原子命令序列 | 零微调 | ❌ 无状态追踪 | ❌ | 长视界但无因果 |
| **CoT-VLA** (2025) | 潜在视觉子目标推理 | 训练 VLM 做 CoT | 需要训练 | ❌ 无持久记忆 | 部分 | 短视界推理增强 |
| **RoboStream** (2026) | 时空记忆注入 | STF-Tokens + CSTG + VLM | **零微调** | ✅ 滑动窗口 | ✅ 因果图 | **长视界+遮挡** |

面试 Tip：当被问到"RoboStream 和 VoxPoser 的核心区别是什么"时，回答："VoxPoser 每步从像素重建几何约束，RoboStream 用 STF-Tokens 跨步持久化几何——前者是'每次重新看世界'，后者是'记住世界如何变化'。这使 RoboStream 在长视界和遮挡任务中有数量级的优势。"

## 8. 精讀建議 (Reading Guide)

**值得精讀原文的人**：
- 做多模态具身 Agent 长视界规划的研究者——STF-Tokens 的表征设计思路可直接迁移
- 要评估 VLM 持久化记忆可行性的工程师——training-free 方案降低了部署门槛
- 研究遮挡恢复/物体恒常性的学者——Task C 的 Hide & Restore 设计是好的基准

**建議章節路徑**：
- 先读 §3.3（STF-Tokens 构建）→ 理解视觉+几何融合的核心机制
- 再看 §3.4（CSTG）→ 理解因果图如何维护跨步一致性
- 可跳 §2（相关工作）→ 如果你已熟悉 VoxPoser/SoFar/CoPa

**不值得精讀的理由**：
- 如果你不做机器人操作/长视界规划，这篇的方法论距离你的场景较远
- 如果你已熟悉 SoFar 的每步重建范式且只关心短视界任务，读摘要即可
- 如果你关注的是端到端训练 VLA（如 OpenVLA、DexVLA），这篇的 training-free 路线与你不同
