### 1.2 关键机制 (Key Mechanism)

FailSafe 管道由三个核心步骤组成：

**Step 1: 失败注入（Failure Generation）**
- 三种失败模式：平移扰动（$\pm 0.1\,\text{m}$）、旋转扰动（$\pm 1\,\text{rad}$）、no-op（机械臂卡住不动）  
- 在 ManiSkill 地面真值轨迹的任意阶段随机注入扰动
- 通过 YAML 配置文件定义失败模式、噪声范围、注入阶段

**Step 2: 恢复动作收集（Recovery Action Collection）**
- 关键创新：不是文本解释，而是**用运动规划器从失败姿态规划到目标姿态的 7-DoF 末端执行器动作**
- 这保证了恢复动作的物理可行性和精确性
- 运动规划器自动计算从当前失败位姿到目标位姿的有效轨迹

**Step 3: 系统化验证（Systematic Verification）**
- 每个"失败-恢复"配对必须通过验证才入库
- 验证方式：在仿真中执行恢复动作，确认任务能成功完成
- 未通过验证的数据对被丢弃

> ⚡ **Eureka Moment**: 用运动规划器（而非 LLM 文本生成）来产生恢复动作——运动规划器给出的 7-DoF 末端执行器动作是精确、可执行、物理可行的，这比"夹爪应该向左移"这种模糊文本指令有用得多。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
Recovery(a_rec | s_fail, task) = MotionPlanner(s_fail, s_goal)
```

**直觉**：恢复动作不是由语言模型"想"出来的，而是由运动规划器从失败位姿 s_fail 到目标位姿 s_goal 精确计算出来的 7-DoF 末端执行器动作。FailSafe-VLM 的学习目标是模仿这个规划器的输出。

**目标**：训练一个 VLM（FailSafe-VLM），使其在给定当前观察图像和任务指令时，能：
1. 判断当前是否处于失败状态
2. 如果失败，输出可执行的 7-DoF 恢复动作

**变量说明**：

| 符号 | 含义 |
|------|------|
| s_fail | 失败时的机器人末端执行器位姿（7-DoF: x,y,z,roll,pitch,yaw,grip） |
| s_goal | 目标位姿（由任务定义） |
| a_rec | 恢复动作（7-DoF 末端执行器 delta 动作） |
| MotionPlanner | 仿真器内置的运动规划器（如 MoveIt），输出从起点到目标的有效轨迹 |
| I_obs | 当前多视角观察图像 |
| L_task | 任务语言指令 |

**训练目标**：

```
L = L_VLM(I_obs, L_task; θ) + λ·L_action(a_rec, a_gt)
```

其中 L_VLM 是 VLM 的视觉-语言损失（失败推理文本），L_action 是恢复动作的回归/分类损失，a_gt 是运动规划器生成的地面真值恢复动作。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个抓取-放置任务：机械臂需要将红色方块从 A 点移动到 B 点。

**正常轨迹**（地面真值）：
```
t=0:  移动到 A 上方          → 位姿 (0.3, 0.1, 0.25, 0, 0, 0, open)
t=1:  下降到抓取位置          → 位姿 (0.3, 0.1, 0.05, 0, 0, 0, open)
t=2:  闭合夹爪               → 位姿 (0.3, 0.1, 0.05, 0, 0, 0, close)
t=3:  提升到安全高度          → 位姿 (0.3, 0.1, 0.25, 0, 0, 0, close)
t=4:  移动到 B 上方          → 位姿 (0.6, 0.4, 0.25, 0, 0, 0, close)
t=5:  下降并释放             → 位姿 (0.6, 0.4, 0.05, 0, 0, 0, open)
```

**注入失败**（在 t=2 注入旋转扰动）：
```
t=2': 闭合夹爪时发生旋转扰动 (+0.5 rad yaw)
     → 实际位姿: (0.3, 0.1, 0.05, 0, 0, 0.5, close)
     → 结果: 夹爪未对准方块中心，抓取失败，方块未被拾取
```

**FailSafe-VLM 检测**：
```
输入: I_obs(t=2') + L_task = "pick and place red block from A to B"
输出: "FAILURE DETECTED: gripper misaligned with object, yaw offset detected"
```

**运动规划器生成恢复动作**：
```
起点: s_fail = (0.3, 0.1, 0.05, 0, 0, 0.5)
终点: s_goal = (0.3, 0.1, 0.05, 0, 0, 0)  ← 回到正确的抓取位姿
输出: a_rec = (0, 0, 0, 0, 0, -0.5, close)  ← 修正 yaw 偏移
```

**验证**：在仿真中执行 $a_{\text{rec}}$，确认夹爪成功对准方块并抓取 → 验证通过 → 入库。  

**推理阶段**：VLA 在 $t=2$ 实际执行时出现同样的旋转偏移 → FailSafe-VLM 检测到失败 → 注入 $a_{\text{rec}}$ → 修正后 VLA 继续执行 $t=3\sim t=5$ → 任务成功。  

## 4. 工程视角 (Engineering View)

| 维度 | 数值/描述 | 工程含义 |
|------|-----------|----------|
| 基础模型 | LLaVA-OneVision-7B | 7B 参数规模，单 GPU 可部署（~14GB 显存） |
| 恢复动作维度 | 7-DoF (x,y,z,roll,pitch,yaw,grip) | 覆盖末端执行器全部自由度，适用于大多数机械臂 |
| 扰动范围 | 平移 $\pm 0.1\,\text{m}$，旋转 $\pm 1\,\text{rad}$   | 覆盖了常见的执行偏差量级 |
| 推理开销 | "small overhead"（论文未给具体数值） | TODO: 待补充 FailSafe-VLM 推理延迟数据 |
| 数据生成速度 | 依赖 ManiSkill 运动规划器 | 每个失败-恢复配对需运行运动规划 + 验证，数据生成较慢但质量高 |
| 部署模式 | 外部辅助模块（非端到端集成） | VLA 和 FailSafe-VLM 独立推理，增加了系统复杂度和通信延迟 |

**关键 trade-off**：
- **优势**：FailSafe-VLM 作为外部模块，不修改原始 VLA 模型，可以"即插即用"地增强任何 VLA
- **代价**：外部模块意味着额外的推理步骤（观察 → FailSafe-VLM 判断 → 可能注入恢复动作 → VLA 执行），增加了端到端延迟  
- **仿真依赖**：恢复动作由 ManiSkill 运动规划器生成，仿真→现实迁移时运动规划器可能不可用，需要替代方案

| 无运动规划支持的仿真器/真实世界 | ❌ 数据生成受限 | 需要运动规划器生成恢复动作 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **运动规划器始终可用且可靠**：FailSafe 依赖 ManiSkill 的运动规划器来生成恢复动作。在真实世界中，运动规划器可能不可用或不可靠（如动态环境、未知障碍物）。
2. **单次失败可独立恢复**：假设每次失败可以通过单一恢复动作解决，未评估多步连续失败或级联失败场景。
3. **扰动范围覆盖真实失败**：训练时使用的扰动范围（$\pm 0.1\,\text{m} / \pm 1\,\text{rad}$）是否覆盖真实世界中的失败程度，未经验证。
4. **FailSafe-VLM 的推理延迟可接受**：作为外部监控模块，每次 VLA 执行都需要 FailSafe-VLM 判断是否失败，增加了推理开销。论文声称"small overhead"但未给具体数字。
5. **仿真到现实的迁移性**：在 ManiSkill 中训练的 FailSafe-VLM 能否在真实机器人上有效工作，完全未验证。
