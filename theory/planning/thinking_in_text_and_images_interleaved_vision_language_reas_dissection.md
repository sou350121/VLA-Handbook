💡 **X-Ray 开场**

长程机器人操作（如"把咖啡杯放到桌上，然后拿起笔"）要求策略同时满足两个条件：因果顺序正确（先放杯子再拿笔）和几何落地（杯子放哪、笔怎么抓）。现有 VLA 策略要么把规划藏在隐状态里（不可解释、容易因果漂移），要么只用纯文本链式推理（缺空间约束）或纯视觉预测（缺语义引导）。IVLR 的核心发现是：让模型在任务开始时生成一个交错文本子目标和视觉关键帧的"故事板"（trace），然后把这个故事板缓存起来作为闭环执行的长期上下文——两种模态缺一不可，合在一起比任一单模态高出约 30 个百分点。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 运行频率 | 训练方式 |
|------|------|------|----------|----------|
| 轨迹生成器 (Trace Generator) | 初始观测 $o_0$ + 指令 $\mathcal{I}$ | IVLR-Trace $z = [(c^{(1)},k^{(1)})\dots(c^{(N)},k^{(N)})]$ | 每 episode 1 次（t=0） | 文本：自回归 CE；视觉：Flow Matching |
| 文本子目标解码器 | 多模态上下文 | 文本 token 序列 $c^{(i)}$ | 每个 stage 1 次 | 标准 next-token CE |
| 视觉关键帧生成器 | 多模态上下文 + 噪声 | RGB 关键帧 $k^{(i)}$ | 每个 stage 1 次 | Flow Matching (ODE 求解) |
| 动作解码器 (Action Decoder) | 当前观测 $o_t$ + 指令 $\mathcal{I}$ + 缓存轨迹 $z$ | 连续动作 $a_t$ | 10 Hz（执行阶段） | L1 action loss |

### 1.2 关键机制 (Key Mechanism)

- **显式中间表示**：IVLR-Trace 是一个完整的"故事板"——每个 stage 包含一个文本子目标（因果角色）和一个视觉关键帧（空间锚点）。不是单步预测，也不是纯文本链。
- **生成一次，缓存使用**：轨迹在 t=0 生成后作为上下文缓存。执行阶段每个时间步，动作解码器同时看到当前观测、原始指令和缓存轨迹——闭环而非开环回放。
- **隐式阶段对齐**：没有手写的 stage pointer。动作 token 通过 attention 自动选择与当前观测兼容的轨迹内容。
- **伪轨迹监督**：标准机器人数据集没有交错轨迹标注。作者用 UVD（Universal Visual Decomposer）分段演示轨迹，用 VLM（Qwen3-VL）为每段生成结构化 caption，构造伪监督信号。

⚡ **Eureka Moment**：长程 VLA 的最优中间表示不是纯文本也不是纯视觉，而是"文本子目标 + 视觉关键帧"的交错序列——两种模态互补而非可替代。消融实验证明：text-only 62.0%、vision-only 68.4%、full interleaved 92.4%。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
P(z, a₁:T | o₀, ℐ) = P(z | o₀, ℐ) · ∏ₜ P(aₜ | oₜ, ℐ, z)
```

先分解为"轨迹生成"和"轨迹条件动作预测"两个因子——推理和执行的解耦。

### 目标 $\to$ 公式 $\to$ 变量 $\to$ 直觉

**总损失函数**：

```
L_total = L_text + λ·L_flow + γ·L_action
```

| 分量 | 公式 | 说明 |
|------|------|------|
| L_text | CE(next-token on captions) | 文本子目标的自回归交叉熵 |
| L_flow | E[‖v_θ(τ, x_τ, C) − (x₁−x₀)‖²] | Flow Matching 损失：学习向量场将噪声变换为目标视觉潜变量 |
| L_action | ‖âₜ − aₜ‖₁ | L1 动作损失，$\hat{a}_t = \text{MLP}(h_{\text{[ACT]}}) + \mu_{\text{act}}$ |

**变量说明**：
- $z = [(c^{(1)},k^{(1)}), \dots, (c^{(N)},k^{(N)})]$：IVLR-Trace，$N$ 个 stage 的交错序列
- $c^{(i)}$：第 $i$ 个 stage 的文本子目标（caption）
- $k^{(i)}$：第 $i$ 个 stage 的视觉关键帧（RGB image）
- $o_0$：初始观测；$o_t$：$t$ 时刻观测；$\mathcal{I}$：任务指令
- $v_\theta$：flow-matching 向量场网络；$x_0 \sim \mathcal{N}(0,I)$，$x_1 = E(k^{(i)})$ 为编码后的视觉潜变量
- h_[ACT]：可学习 [ACT] token 的隐状态
- $\mu_{\text{act}}$：数据集动作统计量（归一化用）

> 符号与论文保持一致。$\lambda$ 和 $\gamma$ 为超参数（论文未给出具体值，TODO: 待补充）。

**直觉**：L_text 确保文本子目标因果正确，L_flow 确保视觉关键帧几何准确，L_action 确保动作可执行。三者联合训练让同一个 1.5B Transformer 同时学会"想"（生成轨迹）和"做"（预测动作）。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设任务指令 ℐ = "把咖啡杯放到桌上，然后拿起笔"。

**Step 1: 轨迹生成 (t=0)**

模型接收初始观测 $o_0$（桌上有咖啡杯和笔）和指令 $\mathcal{I}$，生成 2-stage 轨迹：

```
z = [
  (c⁽¹⁾="Pick up the coffee mug and place it on the table left side",
   k⁽¹⁾=RGB frame showing mug placed on table left),
  (c⁽²⁾="Pick up the pen from the table center",
   k⁽²⁾=RGB frame showing gripper grasping pen)
]
```

生成过程：
- 先自回归解码 $c^{(1)}$（文本 token by token）
- 再用 Flow Matching 从噪声采样生成 $k^{(1)}$（ODE 求解器，TODO: 步数待补充）
- 交替进行 $c^{(2)}$ 和 $k^{(2)}$

耗时：~10 秒（单 H20 GPU）

**Step 2: 闭环执行 (t=1,2,...,T)**

假设执行到 t=5 时：
- $o_5$：观测到咖啡杯已在桌上左侧 ✓（与 $k^{(1)}$ 匹配）
- 动作解码器通过 attention 自动聚焦到轨迹的第二部分 $(c^{(2)},k^{(2)})$
- 输出 $a_5 = $ 向笔移动（连续动作）

假设有一个 2cm 执行扰动（咖啡杯实际偏右 2cm）：
- $o_5'$ 与 $k^{(1)}$ 有偏差，但闭环观测 conditioning 让策略能恢复
- 实验数据：有扰动时 LIBERO-Long 成功率 88.2% vs 无扰动 92.4%（仅降 4.2%）

**可计算的闭环验证**：
- 无轨迹基线：37.7%（因果漂移——先拿笔忘了放杯子）
- text-only：62.0%（知道顺序但不知道放哪）
- vision-only：68.4%（知道目标状态但不知道因果顺序）
- full interleaved：92.4%（两者互补）

## 4. 工程视角 (Engineering View)

| 指标 | 数值 | 含义 |
|------|------|------|
| 模型参数量 | 1.5B | Show-o2 初始化，相对轻量 |
| 轨迹生成延迟 | ~10s/episode | 前置 thinking cost，不适合动态场景 |
| 执行频率 | 10 Hz | 缓存轨迹后动作解码很快 |
| 训练算力 | $16 \times H200$, $4\text{h}$ (LIBERO) / $6\text{h}$ (SimplerEnv) | 40K/60K steps |
| 动作空间 | 连续 (7-DoF) | L1 loss + 动作归一化 |
| 推理阶段 | 10s (一次性) + 10Hz 闭环 | 适合静态长程，不适合实时交互 |

**工程含义**：
- **10 秒前置延迟是硬约束**：在有人类共存的动态环境中不可接受。作者建议的解决方案是"异步 plan-while-acting"——先生成第一阶段快速执行，后续阶段在运行中继续生成。
- **缓存轨迹 = 静态计划**：一旦场景变化（物体被移动、新物体出现），缓存轨迹可能过时。需要在线重规划机制。
- **单一模型做两件事**：Show-o2 1.5B 同时承担轨迹生成和动作解码，避免了多模型 handoff 的复杂性，但也意味着架构设计的 trade-off。

## 5. 数据与评测 (Data & Eval)

**训练数据构造**：
- 基础数据集：标准机器人演示轨迹（未包含交错轨迹标注）
- 伪轨迹构造管线：
  1. UVD（Universal Visual Decomposer）自动分段演示轨迹
  2. 每段末帧作为视觉关键帧 $k^{(i)}$
  3. Qwen3-VL 为每段生成结构化 caption $c^{(i)}$
  4. 随机人工检查作为 sanity check

**评测基准**：

| 基准 | 测试维度 | IVLR 结果 | 最佳基线 | 差距 |
|------|----------|-----------|----------|------|
| LIBERO-Spatial | 空间泛化 | 99.6% | 99.4% (VLA-0) | +0.2% |
| LIBERO-Object | 物体变化 | 98.0% | $98.6\%$ ($\pi_0$-FAST) | -0.6% |
| LIBERO-Goal | 目标变化 | 97.0% | 96.4% (VLA-0) | +0.6% |
| LIBERO-Long | 长程序列 | 92.4% | 87.6% (VLA-0) | +4.8% |
| LIBERO-Average | 综合 | **95.5%** | 93.0% (VLA-0) | +2.5% |
| SimplerEnv-WidowX | 视觉分布偏移 | 59.4% | 42.7% (SpatialVLA) | +16.7% |

**关键观察**：增益主要集中在 LIBERO-Long（+4.8%），这正是 IVLR-Trace 设计的核心场景。在 Spatial 和 Goal 等短程任务上，增益较小甚至略有落后（Object -0.6%），说明该方法的价值在长程而非短程。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **长程因果排序**：在多阶段任务中维持正确的执行顺序（LIBERO-Long 92.4% vs 无轨迹 37.7%）
- **视觉分布偏移鲁棒性**：SimplerEnv 中光照/背景/视角变化下 59.4%（+16.7% over SpatialVLA）
- **局部执行扰动恢复**：2cm 末端扰动后仍保持 88.2%（仅降 4.2%）
- **局部轨迹损坏容忍**：30% 文本 mask 降至 92.2%，30% 视觉 mask 降至 90.0%

### 不能做什么
- **严重遮挡**：初始观测中目标不可见时无法生成有效轨迹
- **大尺度物理随机性**：物体滑动等超出 2cm 扰动的情况
- **规划后场景变化**：缓存轨迹老化后无自动重规划
- **未观测目标**：t=0 时不在视野中的物体无法被纳入轨迹

### 6.1 隐含假设 (Hidden Assumptions)

1. **静态全观测假设**：论文假设任务相关的工作空间在 t=0 时完全可见且执行过程中不发生变化。这在仿真中成立，但在真实场景中（人类干预、物体移动）可能不成立。
2. **伪轨迹质量足够**：UVD 分段 + VLM caption 构造的伪监督信号被当作训练目标，但其质量直接影响模型上限。论文未量化伪轨迹与"真实"轨迹之间的差距。
3. **隐式阶段对齐有效**：没有显式 stage pointer，依赖 attention 自动对齐。论文承认"不声称这种对齐是完美可解释的"，仅通过扰动实验间接验证。
4. **仿真到真实的 gap 可控**：所有实验在仿真中完成，SimplerEnv 仅作为视觉分布偏移的 proxy。真实机器人部署仍需验证。
