## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | LipVQ-VAE (基线) | HiST-AT (本文) | 差异说明 |
|------|------------------|----------------|----------|
| 量化层级 | 单层平面聚类 | 两层分层聚类 | 子动作簇→动作簇 |
| Codebook 数量 | K 个原型 | αK 个子簇 + K 个簇 | 本文用 (64,16) 最优 |
| 重建目标 | 仅动作 X | 动作 X + 时间戳 T | 时空联合监督 |
| 平滑约束 | Lipschitz 正则 | Lipschitz 正则 (两级) | 编码器 + 中间层都加 |
| RoboCasa 成功率 | 53% | 59% | +6% 绝对提升 |

### 1.2 关键机制 (Key Mechanism)

**分层矢量量化**：第一级将动作映射到细粒度子簇（αK 个），第二级将子簇映射到粗粒度动作簇（K 个）。这种设计灵感来自 HVQ[32] 在时序动作分割中的成功。

**时空重建**：空间解码器重建原始动作，时间解码器预测时间戳。两者联合训练迫使表示同时编码"做什么"和"何时做"。

**Lipschitz 平滑**：每层权重 W 被归一化并乘以 softplus(c_ℓ)，确保隐空间表示的连续性。

⚡ **Eureka Moment**：动作序列天然具有层次结构（如"抓取"由"接近→闭合→提起"组成），平面聚类无法捕捉这种结构，而分层 VQ 可以显式建模子动作到动作的组合关系。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L = λ_vq(L_vq_Z + L_vq_A) + λ_spat·MSE(X, X^) + λ_temp·MSE(T, T^) + λ_reg·L_reg
```

**目标分解**：

| 符号 | 含义 | 公式 |
|------|------|------|
| L_vq_Z | 子簇层 VQ 损失 | L_commit_Z + L_codebook_Z |
| L_vq_A | 簇层 VQ 损失 | L_commit_A + L_codebook_A |
| L_spat | 空间重建损失 | MSE(X, X^) |
| L_temp | 时间重建损失 | MSE(T, T^) |
| L_reg | Lipschitz 正则 | 每层权重约束 |

**关键公式细节**：

```
第一级 VQ: q_k^Z = z_j*,  j* = argmin_j ||v'_k - z_j||_2

第二级 VQ: q_k^A = a_i*,  i* = argmin_i ||q^Z'_k - a_i||_2

Lipschitz 约束：W_i^(ℓ) = W_i^(ℓ) / Σ_j|W_i,j^(ℓ)| · softplus(c_ℓ)
其中 softplus(c_ℓ) = ln(1 + e^c_ℓ)
```

> 符号与本文/相关文档保持一致：B=batch size, S=sequence length, K=codebook 大小，α=子簇比例 (实验中 αK=64, K=16 最优)

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简单场景：机器人执行"抓取杯子"任务，动作序列长度 S=10，动作维度 D_feature=7（x,y,z,roll,pitch,yaw,gripper）。

**编码阶段**：
```
输入：X ∈ ℝ^(10×7)  # 10 个时间步，每步 7 维动作
编码器输出：V ∈ ℝ^(10×64)  # D_hidden=64
Lipschitz 正则后：V' ∈ ℝ^(10×32)  # D_latent=32
```

**第一级量化（子簇层）**：
```
Z 有 64 个子簇原型 {z_1, ..., z_64}
对每个 v'_k，找到最近的 z_j*
例如：v'_1 → z_5, v'_2 → z_5, v'_3 → z_12, ...
输出：Q^Z ∈ ℝ^(10×32)
```

**第二级量化（簇层）**：
```
A 有 16 个动作原型 {a_1, ..., a_16}
对每个 q^Z'_k，找到最近的 a_i*
例如：z_5, z_5, z_12 → a_2  # "接近物体"子动作
      z_20, z_21 → a_7      # "闭合夹爪"子动作
      z_30, z_35 → a_11     # "提起物体"子动作
```

**重建阶段**：
```
空间解码器：Q^A → X^ ∈ ℝ^(10×7)
时间解码器：Q^Z' → T^ ∈ ℝ^10

损失计算：
L_spat = MSE(X, X^) = 0.023  # 动作重建误差
L_temp = MSE(T, T^) = 0.015  # 时间戳预测误差
```

**直觉理解**：10 个原始动作被压缩为两层离散表示——底层 64 个子簇捕捉细粒度运动模式，顶层 16 个簇对应语义动作单元。解码时能从离散表示恢复连续动作，同时保持时序平滑。

## 4. 工程视角 (Engineering View)

| 指标 | 数值/说明 |
|------|-----------|
| 训练硬件 | 单卡 NVIDIA A100 |
| RoboCasa 训练步数 | 500K iterations |
| ManiSkill 训练步数 | 30K iterations |
| Codebook 配置 | (αK, K) = (64, 16) 最优 |
| λ_temp 最优值 | 0.02（过大损害动作表示学习） |
| 推理延迟 | 未明确报告，但 VQ 操作为查表，应接近 LipVQ-VAE |

**部署约束**：
- 需预先训练 codebook（随机初始化，联合训练）
- 推理时需存储两个 codebook（64+16=80 个原型向量）
- Lipschitz 正则增加少量计算开销（每层权重归一化）

**Trade-off 分析**：
- 增加子簇数量（αK）→ 捕捉更细粒度动作，但 (64,32) 比 (64,16) 无提升，说明存在冗余
- λ_temp 过大（>0.2）→ 时间戳预测主导训练，动作表示质量下降
- 分层 vs 单层：+6% 成功率，代价是增加一级 VQ 操作和 codebook 存储

### 6.1 隐含假设 (Hidden Assumptions)

- 动作序列天然具有层次结构（子动作→动作）—— 对桌面操作任务成立，但对连续轨迹任务（如画画）可能不适用
- 时间戳重建有助于动作表示——假设动作的时序信息对策略学习至关重要
- Codebook 大小可迁移——实验中 (64,16) 在 ManiSkill 最优，但未验证在其他 domain 是否通用
