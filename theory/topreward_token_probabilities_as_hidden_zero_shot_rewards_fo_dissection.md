💡 **X-Ray 开场**
现有方法想让 VLM 输出进度分数（"完成了 70%"），但开源 VLM 在数字生成上极不可靠。TOPReward 的核心洞察是：别让它生成数字——直接问它"任务完成了吗？"，然后读取模型内部说 "True" 的概率。这个概率随时间单调增长，天然就是密集奖励信号。对 VLA 研究者意味着：RL 精调的奖励瓶颈可能被一个零训练的方案绕过了。

### 1.2 关键机制 (Key Mechanism)

**为什么 GVL 在开源模型上崩盘？** GVL 让 VLM 对打乱帧输出数值进度分（"第 1 帧 10%，第 2 帧 35%..."）。问题在于：(1) 开源 VLM 的指令跟随能力弱，格式经常出错；(2) LLM 对数值 token 的表示天生偏差大——"70" 和 "71" 的概率分布可能天差地别。

**TOPReward 的解法**：把数值回归问题降维成二分类问题。不问"完成了百分之几"，只问"完成了吗？True or False"。然后不生成文本，直接提取 "True" 这个 token 的概率。

⚡ **Eureka Moment**：开源 VLM 的"视觉-语言理解"能力已经足够判断任务是否完成，瓶颈不在理解而在输出表征——把问题从"生成数字"降维到"输出布尔概率"，零样本奖励信号就自然浮现了。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
r_t = log p_θ("True" | c(τ[1:t], u))
```

**目标**：从预训练 VLM 中提取一个标量奖励信号 r_t，使得 r_t 随任务进度单调递增，且对指令内容敏感（不同指令产生不同奖励）。

**公式拆解**：

| 符号 | 含义 |
|------|------|
| θ | 预训练 VLM 权重（冻结，不更新） |
| τ[1:t] | 视频前缀，从第 1 帧到第 t 帧 |
| u | 构造的 prompt（包含指令 instruction） |
| c(τ[1:t], u) | 视频条件化的文本上下文 |
| a | 答案 token，选择 "True" |
| p_θ(a \| c) | VLM 在上下文 c 下生成 token a 的条件概率 |
| r_t | 奖励值，范围 (-∞, 0]，越接近 0 表示越确定完成 |

**直觉**：VLM 在训练时已经看过海量视频-文本对，它内部对"这个视频是否匹配这个指令"有一个隐式信念。TOPReward 不做任何额外学习——只是把这个信念翻译成一个数值。随着视频前缀增长，视觉证据累积，p("True") 从接近 0 增长到接近 1，log 概率从 -∞ 增长到 0，自然形成进度曲线。

**归一化**（仅用于可视化/评估，非因果）：
```
s[t_k] = (r[t_k] - min_j(r[t_j])) / (max_j(r[t_j]) - min_j(r[t_j]) + ε)
```

**增量权重**（用于 offline RL）：
```
Δ[t_k] = min{exp(β · (r[t_k] - r[t_{k-1}])), δ_max}
```
其中 β=0.2 控制权重锐度，δ_max=2.0 防止权重爆炸。

> 符号与原文保持一致。原文使用 Qwen3-VL-8B/32B、Molmo2-8B 作为开源 backbone，Gemini-2.5-Pro 作为闭源 baseline。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 5 步的机器人任务"把红色积木放到蓝色区域"，我们用 Qwen3-VL-8B 提取每步的 token 概率：

| 步骤 t | 视觉内容 | p("True") | r_t = log p | Δ_t (β=0.2) |
|--------|---------|-----------|-------------|-------------|
| 1 | 机械臂静止，积木在原位 | 0.05 | -2.996 | — (初始) |
| 2 | 机械臂伸向红色积木 | 0.12 | -2.120 | 1.017 |
| 3 | 机械臂抓住积木抬起 | 0.35 | -1.050 | 1.214 |
| 4 | 积木移动到蓝色区域上方 | 0.72 | -0.329 | 1.446 |
| 5 | 积木放入蓝色区域，任务完成 | 0.95 | -0.051 | 1.556 |

**可计算的闭环**：
- 步骤 1→2：概率从 5% 升到 12%，奖励从 -3.0 升到 -2.1，增量权重 1.017（略大于 1，轻微 up-weight）
- 步骤 3→4：关键跃迁，概率从 35% 跳到 72%，奖励变化 0.72，权重 1.446（显著 up-weight 这一步）
- 步骤 4→5：接近完成，概率 72%→95%，增量权重 1.556（最大权重给最后一步）

如果对比一个失败轨迹（积木掉地上）：
| 步骤 t | 视觉内容 | p("True") | r_t |
|--------|---------|-----------|-----|
| 5 (失败) | 积木掉在地上，未放入蓝色区域 | 0.08 | -2.526 |

成功轨迹最终 r_5 = -0.051，失败轨迹 r_5 = -2.526，差距超过 2.4 个 log-prob 单位。这直接支撑了 §4.3 的成功检测实验（ROC-AUC 0.965）。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/特性 | 工程含义 |
|------|----------|---------|
| **每次评估的 forward 次数** | K 次（K 个均匀采样前缀，论文中 K 未明确给出，典型值 10-20） | 比 GVL 的 batch 打分更细粒度，但计算量也更大 |
| **模型大小** | 8B-32B 参数（Qwen3-VL / Molmo2） | 需要单卡 A100/H100 加载；8B 可在单卡 40GB 上运行 |
| **推理延迟** | 未明确报告 | 估计每前缀 50-200ms（8B 模型，含视频编码） |
| **chat template 敏感性** | 高（ablation 显示 chat template 显著降低性能） | 部署时必须用 direct prompt scoring，不能用生成式 chat 格式 |
| **token 选择敏感性** | 中（"True" 优于 "Yes"，ablation 见附录 B） | 需对每个 backbone 验证最优答案 token |
| **归一化非因果** | min-max 需要全轨迹 | 在线 RL 只能用原始 log-prob；归一化仅用于离线评估 |
| **内存占用** | 视频编码缓存 + 单次 forward | 每前缀独立 forward，无 KV cache 复用（可优化） |

**部署建议**：如果用 TOPReward 做 online RL 的 reward signal，原始 log-prob 是因果的（只依赖前缀），可以直接用。但要注意：(1) 每步都要跑一次 VLM forward，计算开销不小；(2) 可以先做 offline 权重 BC 验证信号质量，再决定是否上 online。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **跨 embodiment 泛化**：在 4 种不同机器人平台上无需微调即有效（ManiRewardBench 实验）
- **指令敏感**：正确指令 vs 错误指令的奖励差异显著（-1.68 vs -5.04，LeRobot 150 episodes）
- **成功检测**：无需训练，直接用终端轨迹的 TOPReward 分数做二分类
- **Offline RL 信号**：增量权重 Δ_t 可直接用于 reward-weighted behavior cloning

### 不能做什么 / 失败模式
- **细粒度空间任务**：需要精密对齐或小物体操作的任务，VLM 视觉分辨能力不足时奖励噪声大（§5 Limitations 明确承认）
- **Chat template 不兼容的 API**：Gemini API 强制 chat 格式，导致 TOPReward 在 Gemini 上表现弱于 GVL（Table 1）
- **非单调干扰**：虽然大部分轨迹单调递增，但个别帧可能因视觉歧义导致奖励波动
- **仅评估了桌面操作**：实验全部是机械臂 manipulation，未验证移动机器人、双臂协调或人形平台

### 6.1 隐含假设 (Hidden Assumptions)

1. **VLM 的"True/False"token 语义与机器人任务完成度对齐**——论文假设预训练 VLM 对"这个视频完成了指令"的判断能力来自通用视觉-语言训练，但并未验证 VLM 是否真的理解"完成"的机器人语义（可能只是学到了表面视觉模式匹配）
2. **log p("True") 的绝对值可跨任务比较**——归一化解决了单轨迹内比较，但跨轨迹比较依赖 raw score。不同任务的 baseline p("True") 可能不同（简单任务初始概率更高），论文未做系统分析
3. **Boolean token 是最优选择**——论文选 "True" 是因为附录 B 显示它区分度最大，但未系统搜索其他 token 组合（如 "Yes/No"、"Completed/Not completed"），不同 tokenizer 可能有不同表现
4. **前缀采样均匀即可**——论文用 K 个均匀间隔前缀，但对于长尾任务（大部分时间无变化，最后一步突变），均匀采样可能错过关键转折

**面试 Tip**：如果被问到"TOPReward 和 GVL 的本质区别是什么"，回答："GVL 把进度估计当成数值生成任务，TOPReward 把它降维成二分类概率提取。前者依赖 VLM 的指令跟随和数值表示能力（开源模型弱项），后者只依赖 VLM 的视觉-语言对齐能力（预训练已具备）。这是问题表征的选择，不是模型能力的差距。"
