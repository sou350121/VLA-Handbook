💡 **X-Ray 开场**
这篇论文解决的核心问题是：VLA 强化学习需要稠密奖励信号，但训练奖励模型成本高、泛化差。作者发现，与其让 VLM 生成数值化的进度百分比（开源模型做不好这件事），不如直接问它"任务完成了吗？"然后提取它内部说"True"的概率。这个概率天然就是一个连续、因果、指令敏感的奖励信号。对 VLA 研究者意味着：你可以直接用现成的开源 VLM（Qwen3-VL、Molmo2）做 reward-weighted BC，无需任何奖励模型训练。

### 1.2 关键机制 (Key Mechanism)

**为什么 GVL 在开源模型上崩了？** 作者的核心洞察是：开源 VLM 并非缺乏视频理解能力，而是败在两个表层能力上——(1) 不稳定的指令跟随，(2) 数值 token 的固有偏差。让 LLM 精确输出 "73%" 这样的数字，比让它理解视频难多了。

**TOPReward 的解法**：把进度估计从"生成一个数字"降级为"回答是或否"。布尔 token（True/False）的概率分布远比数值 token 稳定。模型对"这个视频是否展示了任务完成"的内部信念，本身就编码了丰富的进度信息。

⚡ **Eureka Moment**：开源 VLM 的奖励建模能力一直就在那里——只是你一直在看它生成的文本，而不是它内部的概率分布。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
r_t = log p_θ("True" | c(τ[1:t], u))
```
用一句话：奖励就是 VLM 认为"任务已完成"这个命题为真的对数概率。

**目标**：从预训练 VLM 中提取因果的、指令敏感的、稠密的时间进度信号，用于 VLA 的 RL 微调或 offline BC。

**公式分解**：

| 符号 | 含义 |
|------|------|
| p_θ | 预训练 VLM 的下一个 token 分布，权重 θ 固定 |
| τ[1:t] | 视频轨迹前缀，帧 I_1 到 I_t |
| u | 包含指令的 prompt 模板 |
| a | 答案 token，固定为 "True" |
| c(τ[1:t], u) | 视频条件化的文本上下文 |
| r_t | 因果奖励信号，范围 (-∞, 0] |

**归一化（用于轨迹内可视化，非因果）**：
```
s_tk = (r_tk - min_j r_tj) / (max_j r_tj - min_j r_tj + ε)
```

**RWBC 权重（用于 offline 学习）**：
```
Δ_tk = min{ exp(β · (r_tk - r_tk-1)), δ_max }
```
其中 β=0.2 控制权重锐度，δ_max=2.0 防止权重爆炸。

> 符号与原文保持一致。所有公式基于因果前缀评分，归一化仅用于评估可视化。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 10 帧的"把积木放入盒子"任务，我们每 2 帧采样一次前缀：

| 前缀长度 | 视觉内容 | p("True") | r_t = log p | 直觉 |
|----------|---------|-----------|-------------|------|
| t=2 | 机器人伸手接近积木 | 0.05 | -3.00 | 几乎不可能完成 |
| t=4 | 手指抓住积木 | 0.12 | -2.12 | 刚开始 |
| t=6 | 积木离开桌面 | 0.35 | -1.05 | 进行中 |
| t=8 | 积木移到盒子上方 | 0.62 | -0.48 | 快完成了 |
| t=10 | 积木在盒子里，手收回 | 0.85 | -0.16 | 几乎确定完成 |

成功轨迹的 r_t 从 -3.00 单调递增到 -0.16。失败轨迹（积木掉地上）可能停在 -1.80 附近。两条轨迹的终端 r_t 差约 1.64，对应成功/失败的平均 raw reward 差距（论文报告：正确指令 -1.68 vs 错误指令 -5.04，差 3.36）。

归一化后（s_t）：
```
s_2 = (-3.00 - (-3.00)) / (-0.16 - (-3.00)) = 0.00
s_10 = (-0.16 - (-3.00)) / (-0.16 - (-3.00)) = 1.00
```
得到一条从 0 到 1 的平滑进度曲线。

RWBC 权重计算（β=0.2, δ_max=2.0）：
```
Δ_t6 = min{exp(0.2 × (-1.05 - (-2.12)))}, 2.0} = min{exp(0.214), 2.0} = 1.24
Δ_t10 = min{exp(0.2 × (-0.16 - (-0.48)))}, 2.0} = min{exp(0.064), 2.0} = 1.07
```
进度快的步骤获得更高权重，BC 训练时更关注这些"关键帧"。

## 4. 工程视角 (Engineering View)

| 工程维度 | 分析 |
|----------|------|
| 推理开销 | 每个前缀需 1 次 VLM 前向传播；K 个前缀 = K 次前向。以 K=15 帧、Qwen3-VL-8B 计，单次推理约 100-300ms（A100），单轨迹约 1.5-4.5s |
| 吞吐 | 可批量处理多轨迹；单卡 A100 约可处理 5-10 轨迹/秒 |
| 内存 | 与 VLM 参数量线性相关；8B 模型约 16GB FP16，32B 约 64GB |
| 量化 | 未评估 INT8/FP8 量化对 token 概率校准的影响——潜在优化方向 |
| 部署约束 | 需要 VLM 提供 logits 访问；API-only 模型（如 Gemini）受 chat template 限制性能下降 |
| 因果性 | 原始 r_t 是因果的（仅依赖前缀）；归一化 s_t 是非因果的（需要 episode 全局 min/max） |
| 提示词敏感 | Chat template 会显著降低性能（附录 E.2 消融）；直接 prompt scoring 优于生成式模板 |

**工程含义**：TOPReward 的核心 trade-off 是用推理次数换训练成本。传统方法训练一次奖励模型后推理成本低，但适配新任务需重新收集数据+训练。TOPReward 零训练但每次评估需 K 次 VLM 前向。对于 offline BC 场景（一次性评分所有 demo），这是完全可接受的；对于 online RL 实时奖励，可能需要缓存或近似。

## 5. 数据与评测 (Data & Eval)

**ManiRewardBench（本文新建基准）**：
- 130 个独特真实操作任务
- 4 种机器人平台：Franka Emika、Single-Arm YAM、Bimanual YAM、SO-100/101
- 子任务边界标注（阶段感知进度评估）
- 23 任务失败 split（成功检测评估）
- 497 成功评估 episode（113 任务）

**Open X-Embodiment（过滤子集）**：
- 从 LeRobot 集合中筛选 33 个高质量数据集
- 每个数据集 20 个 episode

**评测指标**：
- VOC（Value-Order Correlation）：Spearman 秩相关，衡量预测进度与时间顺序的对齐度
- Kendall tau-b：另一种秩相关度量
- Pearson correlation：线性相关
- MAE：归一化进度误差
- ROC-AUC：成功检测的二分类性能

**关键数字**（来自论文 Table 1-3）：
- OXE VOC：Qwen3-VL-8B TOPReward 优于 GVL；Molmo2-8B 上 GVL ≈ 0 而 TOPReward 正数
- ManiRewardBench：Qwen3-VL-8B TOPReward 在 aggregate progress metrics 上最强
- 成功检测：Qwen3-VL-32B 达到 0.965 ROC-AUC，Qwen3-VL-8B 达到 0.939，均超过 Robometer-4B 的 0.935
- 指令敏感性：对角质量 TOPReward 0.420 vs Robometer-4B 0.149（随机基线 0.05）

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **跨平台零样本进度估计**：同一 prompt 在 Franka、YAM、SO-100 上均有效，无需平台特定微调
- **成功/失败二分类**：用终端 r_t 即可区分成功和失败轨迹（AUC > 0.93）
- **多步骤任务理解**：进度曲线能捕捉子任务完成的平台期和主动操作阶段的加速
- **奖励加权 BC**：在 6 个真实 SO-100 任务上，TOP-RWBC 全部优于标准 BC，部分任务从 7/10 提升到 10/10
- **指令消歧**：正确指令 vs 错误指令的 raw reward 差达 3.36，证明信号确实依赖语言指令

### 不能做什么
- **细粒度空间操作**：需要精确对齐或小物体操作的任务，VLM 视觉分辨能力不足时奖励噪声大
- **Online RL 实时反馈**：每步需 K 次 VLM 前向，延迟较高；更适合 offline 场景
- **闭源模型上超越 GVL**：Gemini-2.5-Pro 上 GVL (0.572) > TOPReward (0.430)，归因于 chat template 强制格式

### 6.1 隐含假设 (Hidden Assumptions)

| 假设 | 论文验证情况 | 风险等级 |
|------|-------------|----------|
| "True" token 概率在所有 VLM tokenizer 中都是最优选择 | 仅在 Qwen3-VL 和 Molmo2 上做了 token 比较（附录 B） | 中——其他 tokenizer 可能有更优 token |
| 视频帧均匀采样足够捕捉进度 | 使用 K 个均匀间隔前缀，未探索自适应采样 | 中——快速动作阶段可能需要更密集采样 |
| 预训练 VLM 的视觉理解足以覆盖机器人操作域 | 实验仅在桌面操作任务上验证 | 高——移动操作、双臂协作、人形机器人未测试 |
| min-max 归一化不会引入评估偏差 | 归一化是非因果的，仅用于可视化 | 低——但 VOC 计算依赖归一化值，可能影响跨轨迹比较 |
| chat template 不影响 token 概率提取 | 有消融实验（附录 E.2）显示有影响 | 低——但 Gemini API 强制 chat template，无法绕过 |
