# TOPReward：用 Token 概率作零样本奖励 (Token Probabilities as Hidden Zero-Shot Rewards for Robotics)

> **核心定位**: 绕过 VLM 的文本生成，直接抽取内部 token 概率作为机器人任务的零样本进度奖励信号，无需训练奖励模型即可在 130 个真实操作任务上达到或超越训练型奖励基线。

💡 **X-Ray 开场**
VLA 模型做 RL 微调时最大的瓶颈是什么？不是策略网络不够强，而是没有 dense reward 信号。传统做法要么手工设计奖励（不可扩展），要么训练奖励模型（需要大量标注数据）。TOPReward 发现了一个反直觉的事实：你不需要训练任何东西——只需要问 VLM 一个布尔问题"这个任务完成了吗？"，然后看它内部回答 "True" 的概率。这个概率随时间上升的轨迹，本身就是一条高质量的进度曲线。对 VLA 研究者意味着：RLHF 管线中的奖励模型可以省掉了。

## 1. 核心架构/方法总览

### 1.1 系统对比概览

| 维度 | GVL (生成式) | RoboReward/RoboDopamine (训练式) | TOPReward (概率式) |
|------|-------------|--------------------------------|-------------------|
| 核心机制 | VLM 生成数值分数 | 训练专用奖励网络 | 抽取 VLM 内部 token 概率 |
| 训练需求 | 无 | 需要大规模标注数据 | 无 |
| 数据需求 | 无需标注 | 3400+ 小时操作数据 | 无需 |
| 泛化性 | 闭源模型好，开源崩溃 | 跨平台/视角泛化有限 | 跨 4 平台 130 任务有效 |
| 计算开销 | 每帧 1 次前向 | 推理阶段 1 次前向 | 每前缀 K 次前向 |
| 输出形式 | 离散数值 | 连续分数 | 连续 log-prob |
| 指令敏感性 | 弱 | 弱 (0.149 对角质量) | 强 (0.420 对角质量) |

### 1.2 关键机制

**核心洞察**：开源 VLM 在 GVL 上表现差，不是因为缺乏视觉理解能力，而是因为：
1. **数值 token 偏差**：LLM 对数值 token 的校准极差（已知问题）
2. **指令遵循不稳定**：要求模型按固定格式输出百分比，开源模型经常格式错误

**解决方案**：不要求 VLM 生成数字，而是给它一个布尔判断问题，然后直接读取内部概率。

⚡ **Eureka Moment**：VLM 已经知道任务是否完成了——你不需要它说出来，你只需要看它说 "True" 时有多确信。

### 1.3 信息流/架构图

```
┌──────────────────────────────────────────────────────┐
│  输入: 视频前缀 τ_{1:t} + 语言指令 instruction       │
│         ↓                                            │
│  ┌──────────────────────────────────────────┐        │
│  │  Prompt 构造                              │        │
│  │  "<|video|> 上面视频展示了完成以下任务的   │        │
│  │   机器人操作轨迹: {INSTRUCTION}。          │        │
│  │   判断上述陈述是否为 True。答案是: {a}"    │        │
│  └──────────────────────────────────────────┘        │
│         ↓                                            │
│  ┌──────────────────────────────────────────┐        │
│  │  VLM 前向 (冻结权重)                      │        │
│  │  → 获取 answer token "True" 的概率        │        │
│  │  p_θ("True" \| c(τ_{1:t}, u))            │        │
│  └──────────────────────────────────────────┘        │
│         ↓                                            │
│  ┌──────────────────────────────────────────┐        │
│  │  r_t = log p_θ("True" \| c(τ_{1:t}, u)) │        │
│  │  → 连续奖励信号, 范围 (-∞, 0]             │        │
│  └──────────────────────────────────────────┘        │
│         ↓                                            │
│  下游应用: 进度曲线 / 成功检测 / 加权行为克隆          │
└──────────────────────────────────────────────────────┘
```

## 2. 数学核心

📌 **Napkin Formula**（一行抓住本质）：
```
r_t = log p_θ("True" | 视频前缀 + 指令)
```

**目标**：为每个视频前缀 τ_{1:t} 产出一个标量进度分数 s_t，反映"指令已被完成的证据累积量"。

**核心方程**：

```
给定 VLM p_θ，构造 prompt u：
  "<|video|> ... {INSTRUCTION} ... True or not? Answer: {a}"

其中 a = "True"（经实验验证，boolean token 的 success-failure 分离度最大）

奖励定义:
  r_t = log p_θ(a | c(τ_{1:t}, u))

性质:
  - r_t ∈ (-∞, 0]，成功轨迹上单调递增
  - 因果性：仅依赖前缀 τ_{1:t}，不依赖未来帧
  - 零训练：直接使用预训练权重
```

**归一化**（用于轨迹内可视化，非因果）：
```
s_{t_k} = (r_{t_k} - min_j r_{t_j}) / (max_j r_{t_j} - min_j r_{t_j} + ε)
```

**下游加权**（用于 offline BC）：
```
Δ_{t_k} = min{exp(β · (r_{t_k} - r_{t_{k-1}})), δ_max}
其中 β 控制权重锐度, δ_max 限制最大权重保证训练稳定
```

> 符号说明：θ = VLM 预训练权重；τ_{1:t} = 视频前缀（帧序列）；u = prompt 模板；a = answer token ("True")；c(·) = 视频条件化文本上下文；β = 逆温度系数（论文用 0.2）；δ_max = 权重上限（论文用 2.0）；ε = 数值稳定性常数。

## 3. 带数字走一遍：玩具例子

假设一个 5 步操作任务 "把红色积木放进蓝色盒子"，我们用 K=5 个均匀前缀评估：

```
前缀    视觉内容                    p("True")    r_t = log p    s_t (归一化)
t=1     手靠近积木                   0.15       -1.90          0.00
t=2     手抓住积木                   0.28       -1.27          0.28
t=3     积木移到盒子上方              0.52       -0.65          0.58
t=4     积木放入盒子                  0.81       -0.21          0.85
t=5     手收回，任务完成              0.95       -0.05          1.00
```

加权信号（用于 offline BC，β=0.2, δ_max=2.0）：
```
Δ_t1 = min{exp(0.2 × (-1.90 - (-1.90))), 2.0} = 1.00  (基线)
Δ_t2 = min{exp(0.2 × (-1.27 - (-1.90))), 2.0} = 1.13  (进展)
Δ_t3 = min{exp(0.2 × (-0.65 - (-1.27))), 2.0} = 1.14  (进展)
Δ_t4 = min{exp(0.2 × (-0.21 - (-0.65))), 2.0} = 1.09  (进展放缓)
Δ_t5 = min{exp(0.2 × (-0.05 - (-0.21))), 2.0} = 1.03  (收尾)
```

**工程含义**：进度快的步骤获得更高权重，BC 训练时自然聚焦于"信息量最大"的轨迹片段。失败轨迹（p("True") 始终低）的所有权重接近 1.0，不会被过度惩罚——只是不被特别强调。

## 4. 工程视角

| 工程维度 | 分析 |
|----------|------|
| 推理延迟 | 每轨迹 K 次 VLM 前向（论文用 K=15），以 Qwen3-VL-8B 为例，单次前向约 100-200ms → 每轨迹 1.5-3s |
| 吞吐 | 可并行化：不同前缀独立评估，GPU batch 处理可线性加速 |
| 内存 | 仅需加载 VLM 权重（8B/32B），无需额外奖励模型参数 |
| 量化误差 | 未讨论量化影响；logit-level 操作对 INT8 量化可能敏感——TODO: 待验证 |
| 部署约束 | 需要 VLM 提供 raw logits 访问；闭源 API（如 GPT-4）通常不提供，Gemini 2.5 Pro 提供但 chat template 限制性能 |
| Chat Template 敏感性 | 论文 §E.2 消融实验显示 chat template 会显著降低性能——直接用 prompt scoring 而非 chat 格式 |
| Answer Token 选择 | "True" 的 success-failure 分离度最大；探索过完整指令多 token 变体但效果较差（Appendix A） |

**工程含义总结**：TOPReward 把奖励信号的计算从"训练一个专用网络"简化为"调用现有 VLM 的 logits"，大幅降低了部署门槛。主要瓶颈是 VLM 前向次数（每轨迹 K 次），但这是 embarrassingly parallel 的。

| 指标 | 含义 | 范围 |
|------|------|------|

### 关键结果

- **OXE 上**：Qwen3-VL-8B 的 TOPReward VOC 显著超越同 backbone 的 GVL；与训练型 Robometer-4B 相当
- **ManiRewardBench 上**：Qwen3-VL-8B 达到最强综合进度指标；Molmo2-8B 上 GVL 接近零而 TOPReward 恢复有效信号

- **真实世界 BC 改进**：6 个 SO-100 任务上，TOP-RWBC 全面超越标准 BC，困难任务上 10/10 vs 7/10

## 6. 能力与失败模式

### 能做什么
- **零样本进度估计**：无需任何任务特定数据，直接在新任务上工作
- **跨平台泛化**：在 4 种不同机器人平台上均有效（Franka、SO-100/101、YAM 单臂/双臂）
- **指令敏感**：对角质量 0.420（vs 随机基线 0.05），能区分正确指令和错误指令
- **成功检测**：无需训练，ROC-AUC 超过训练型奖励模型
- **策略改进**：作为 offline BC 的样本权重，在真实机器人上稳定提升成功率

### 不能做什么
- **细粒度空间推理**：需要精确对齐或小物体操作的任务，VLM 视觉分辨不足时奖励噪声大（§5 Limitations）
- **在线实时推理**：每前缀需要完整 VLM 前向，延迟不适合高频控制循环（更适合离线评估或低频 reward shaping）
- **闭源模型最优**：Gemini 上 TOPReward (0.430) 反而不如 GVL (0.572)，因为 API 强制 chat template 损害了性能

### 6.1 隐含假设 (Hidden Assumptions)

1. **VLM 已"见过"类似操作**：零样本的前提是预训练数据中包含了足够的机器人操作视觉模式。对于极端新颖的操作范式（如非标准夹具、非典型物体），token 概率可能不可靠
2. **布尔判断足够表达进度**：假设 "任务是否完成" 的二元问题能捕捉多步骤任务的渐进性。对于高度并行的多目标任务（同时做 A 和 B），单一布尔信号可能信息不足
3. **Answer token 选择通用**：论文选择 "True" 因为实验中发现它分离度最大，但未系统验证其他语言/其他 tokenizer 下的等价 token
4. **视频编码是充分条件**：假设 VLM 的视频编码器能捕捉所有与进度相关的视觉信息——忽略了深度/触觉等模态可能在某些任务中的必要性
