## 1. 核心架构/方法总览 (Overview / Architecture)

WISE 是一个四组件协作框架：**想象调度器 → 有界反事实想象 → 轨迹评估 → 策略优化**，形成闭环。

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 训练方式 | 推理时是否激活 |
|------|------|------|----------|----------------|
| **调度器 (Scheduler)** | 双视角观察 (手腕+第三人称) | 交互相关性分数 s_t ∈ [0,1] | 弱监督（基于机器人执行信号） | 是，每次决策都运行 |
| **世界模型 (WM)** | 当前观察 + 语言指令 + 候选动作 | H 帧未来多视角预测 | Rectified Flow (冻结) | 仅当 s_t > κ 时激活 |
| **奖励模型 (RM)** | 预测的多视角观察序列 | 进度/置信度/完成度三信号 | 独立训练 (DINOv2 + 分类头) | 仅当 WM 激活时运行 |
| **VLA 策略 (π_θ)** | 真实交互上下文 (观察+状态+指令) | 动作块 a_t | 梯度更新 (目标组件) | 始终运行 |

**训练 vs 推理差异**：
- 训练时：四个组件协同工作，WM 和 RM 冻结，只更新 π_θ
- 推理时：仅 VLA 策略运行，调度器/WM/RM 全部卸载

### 1.2 关键机制 (Key Mechanism)

**调度器：何时想象？**

- 使用共享的 DINOv2 编码器 E_φs 编码双视角观察
- 轻量级头 g_η 输出交互相关性分数 s_t = σ(g_η([E_φs(I_t^w); E_φs(I_t^a)]))
- 阈值判断：m_t = 𝕀[s_t > κ]，仅当 m_t = 1 时触发想象
- 训练数据来自机器人执行信号的弱监督（视觉代理，标记哪些状态是交互关键的）

**有界反事实想象：想象多远？**

- 采样 M 个候选动作块 a_{t,i} ~ π_θ(·|h_t)
- 每个候选进行 L 步封闭循环 rollout（每步 H 帧），总长 L×H 帧
- 世界模型基于 Open-Sora 适配，支持多视角（手腕+第三人称）预测
- **关键设计**：想象用于反事实评估，不直接用于合成数据监督

**轨迹评估：哪个候选更好？**

奖励模型从预测观察中提取三个信号：

```
进度: p_{i,j} = σ(h_p(e_{i,j}))     — 任务推进了多少
置信度: c_{i,j} = σ(h_c(e_{i,j}))   — 预测有多可靠
完成度: q_{i,j} = tanh(h_q(e_{i,j})) — 是否到达终态
```

综合评分：

```
R_i = G_i - α·B_i + β·T_i
G_i = Σ_j c_{i,j} · [p_{i,j} - p_{i,j-1}]_0^δ    (加权正向进度)
B_i = Σ_j [p_{i,j-1} - p_{i,j}]_0^δ               (后退惩罚)
T_i = max_j q_{i,j}                                (最大完成度)
```

**策略优化：如何更新？**

- 每个候选想象两次取平均 R̄_i
- 质量门控：ΔR ≥ 0.02, ρ_rank ≥ 0.5, σ_WM ≤ 0.2（确保评估可靠）
- 标准化优势：A_i = (R̄_i - μ_R̄) / max(σ_R̄, ε)
- 梯度方向：g_WISE = (1/M) Σ_i sgn(A_i) · ∇_θ L_FM(θ; a_{t,i}, h_t) + λ_ref · ∇_θ L_ref
- **关键**：仅对真实上下文的第一个动作块做监督，想象 rollout 仅用于评估

⚡ **Eureka Moment**：想象不是越多越好——它是一种需要被调度的计算资源。在交互关键状态做短程反事实评估，比全程长程想象更高效、更可靠。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
g_WISE = (1/M) Σ_i sgn(A_i) · ∇_θ L_FM(θ; a_{t,i}, h_t)
其中 A_i 标准化了 R_i = G_i - α·B_i + β·T_i
```

**目标**：最大化任务成功率，但避免在真实世界中做昂贵的探索。

**核心方程分解**：

```
最大化: E_{ℓ, τ~π_θ}[y(τ, ℓ)]     — 任务成功率的期望
约束:  仅用世界模型想象评估候选      — 不依赖真实交互探索
更新:  符号优势梯度                — sgn(A_i) 只保留方向，不依赖幅度
```

**变量说明**：

| 符号 | 含义 | 值域/说明 |
|------|------|-----------|
| h_t | 真实交互上下文 | (O_t, s_t, ℓ) |
| a_{t,i} | 第 i 个候选动作块 | 从 π_θ 采样 |
| p_{i,j} | 进度信号 | [0,1]，任务推进程度 |
| c_{i,j} | 置信度信号 | [0,1]，预测可靠性 |
| q_{i,j} | 完成度信号 | [-1,1]，终态接近度 |
| G_i | 加权正向进度 | 越大越好 |
| B_i | 后退惩罚 | 越小越好 |
| T_i | 最大完成度 | 越大越好 |
| R_i | 综合评分 | 越高表示候选越好 |
| A_i | 标准化优势 | 正=好，负=差 |

> 符号与本文保持一致。世界模型训练使用 Rectified Flow 目标：
> ```
> L_WM = E[||v_ψ([z̃_obs; z_{fut,λ}], λ, ℓ, a)_fut - (z_fut - ε)||^2]
> z_{fut,λ} = (1-λ)ε + λ·z_fut, λ~U(0,1), ε~N(0,I)
> ```

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 Stack 任务的交互关键状态，调度器触发想象：

**设定**：M=4 个候选动作，L=3 步 rollout（每步 H=8 帧，总 24 帧）

| 候选 | G_i (进度) | B_i (后退) | T_i (完成) | R_i = G - 0.5·B + 0.3·T |
|------|------------|------------|------------|--------------------------|
| a_1 | 0.85 | 0.12 | 0.90 | 0.85 - 0.06 + 0.27 = **1.06** |
| a_2 | 0.60 | 0.20 | 0.50 | 0.60 - 0.10 + 0.15 = **0.65** |
| a_3 | 0.45 | 0.35 | 0.30 | 0.45 - 0.175 + 0.09 = **0.365** |
| a_4 | 0.70 | 0.15 | 0.60 | 0.70 - 0.075 + 0.18 = **0.805** |

**质量门控检查**：
- ΔR = 1.06 - 0.365 = 0.695 ≥ 0.02 ✅
- 假设 ρ_rank = 0.72 ≥ 0.5 ✅（两次想象排名一致）
- 假设 σ_WM = 0.12 ≤ 0.2 ✅（奖励波动小）

→ 通过门控，进行标准化：

```
μ_R̄ = (1.06 + 0.65 + 0.365 + 0.805) / 4 = 0.72
σ_R̄ ≈ 0.27

A_1 = (1.06 - 0.72) / 0.27 = +1.26  → sgn = +1 (更新方向: +∇L_FM)
A_2 = (0.65 - 0.72) / 0.27 = -0.26  → sgn = -1 (更新方向: -∇L_FM)
A_3 = (0.365 - 0.72) / 0.27 = -1.31 → sgn = -1
A_4 = (0.805 - 0.72) / 0.27 = +0.31 → sgn = +1
```

**梯度合成**：

```
g_WISE = (1/4) · [+∇L_FM(a_1) - ∇L_FM(a_2) - ∇L_FM(a_3) + ∇L_FM(a_4)]
```

好的候选（a_1, a_4）推动策略向它们靠拢，差的候选（a_2, a_3）推开策略。**只用符号，不用幅度**——这避免了奖励尺度不稳定带来的梯度爆炸。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/设计 | 工程含义 |
|------|-----------|----------|
| **计算节省** | GPU 时间 11.45h → 2.61h（↓77%） | 后训练成本从"不可承受"到"可日常运行" |
| **状态选择率** | 138 → 28 states（↓80%） | 调度器有效过滤了非交互状态 |
| **想象步数 L** | 3 chunks（每 chunk 8 帧 = 24 帧） | 短程限制预测误差累积 |
| **候选数 M** | 论文未明确，典型 4-8 | 越多评估越准，但 WM 推理线性增长 |
| **WM 推理调用** | 每选中状态 L 次 | 是主要计算瓶颈 |
| **策略更新频率** | 仅当 m_t=1 且通过门控 | 更新稀疏但信号质量高 |
| **部署开销** | 推理时仅 π_θ | 调度器/WM/RM 全部可卸载，零额外延迟 |

**关键 trade-off**：
- 调度器阈值 κ 越低 → 更多想象 → 更高性能但更慢
- 想象步数 L 越大 → 评估更全局但误差累积更多
- 候选数 M 越大 → 优势估计更准但 WM 推理成本线性增长

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- 显著提升 π_0 和 π_0.5 在仿真和真实世界的操作成功率
- 在分布偏移下（光照/几何/干扰物变化）表现更强鲁棒性
- 大幅降低世界模型计算成本（80% 节省）
- 跨不同 VLA 基线迁移（π_0 → π_0.5 都有效）

**不能做什么 / 局限**：
- **仅桌面操作**：实验限于 MimicGen 仿真 + Galaxea R1 Lite 单臂桌面机器人，未验证移动/双臂/人形平台
- **短程任务**：5 个仿真任务都是相对短程操作，未测试需要数十步以上的长程规划
- **调度器依赖训练信号**：调度器需要基于机器人执行信号的弱监督训练，新任务需要额外标注
- **世界模型质量瓶颈**：如果 WM 预测不准，评估信号就不可靠——WISE 无法超越 WM 的能力上限
- **单一步长阈值**：当前使用固定想象步数 L 和固定调度阈值 κ，未自适应

### 6.1 隐含假设 (Hidden Assumptions)

1. **交互状态可预测**：调度器假设仅凭视觉观察就能可靠判断哪些状态需要想象。但如果关键交互信号隐藏在状态空间（如力触觉），纯视觉调度器可能漏判。
2. **世界模型在分布内**：WM 基于 Open-Sora 适配，假设其在目标任务的分布内预测足够准确。但后训练过程中策略分布会偏移，可能导致 WM 在分布外区域给出误导性评估。
3. **奖励信号可泛化**：奖励模型在仿真训练，直接用于真实世界评估。仿真到真实的视觉域差距可能影响评分可靠性。
4. **M 个候选覆盖最优**：假设从 π_θ 采样的 M 个候选中包含足够好的动作。如果策略已经严重偏离最优，采样可能无法覆盖好的候选。
