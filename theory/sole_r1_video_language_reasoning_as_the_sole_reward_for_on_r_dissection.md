💡 **X-Ray 开场**
当前 VLM（如 GPT-5、Gemini-3-Pro）用作 RL 奖励时，会因为部分可观测性和分布偏移导致策略"欺骗"奖励模型——机器人学会让 VLM 看起来觉得成功但实际没完成任务。SOLE-R1 的核心发现是：让 VLM 显式做链式推理（CoT）+ 连续进度预测，而不是直接输出成功/失败判断，可以大幅降低奖励被利用的概率，从而真正实现"从零开始、仅靠 VLM 推理引导"的在线强化学习。对 VLA 研究者意味着：奖励工程（reward engineering）可能不再是刚需，VLM 推理本身就可以成为通用的学习信号。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

SOLE-R1 系统由三个核心组件构成，下表对比各模块的职责与输入输出：

| 模块 | 输入 | 输出 | 训练方式 | 关键超参 |
|------|------|------|----------|----------|
| **视频编码 + 语言推理** | 自然语言目标 g + 首帧 o₀ + 最近 K 帧 oₜ₋ₖ₊₁:ₜ + 上一步进度 pₜ₋₁ | CoT 推理 mₜ（自由文本）+ 进度值 pₜ ∈ [-100, 100] | SFT + RLVR（两阶段） | K ∈ [1, 8]（训练时变化），pₜ₋₁ dropout |
| **奖励转换函数** | 进度值 pₜ | 奖励 rₜ = ψ·clip(pₜ, -c, c) | 无训练（确定性函数） | ψ 缩放系数, c 裁剪范围 |
| **在线 RL 策略（DrQv2）** | 两路 RGB（腕部 + 外部）+ 本体感知 | 末端执行器 delta 运动 + 夹爪开/关 | PPO/SAC（SERL 实现） | 从随机策略初始化 |

**训练与推理差异**：
- **训练阶段**：SFT 学习 CoT 推理质量 → RLVR 精细调节进度预测准确性
- **推理阶段**：每 timestep 输出 CoT + 进度 → 转换为奖励 → 驱动 DrQv2 策略更新
- **关键设计**：推理频率可以低于控制频率，中间 timestep 的奖励通过线性插值填补

### 1.2 关键机制 (Key Mechanism)

SOLE-R1 的设计围绕三个核心洞察：

1. **CoT 推理是防奖励利用的关键**：让模型先"想"再"打分"，迫使它关注帧间变化、判断是否推进目标、并预测下一步子目标。消融实验显示：去掉 CoT 通道后，进度信号变平/变噪，学习显著退化。

2. **多帧上下文窗口 > 单帧 caption**：输入包含首帧 o₀（提供初始状态锚点）+ 最近 K 帧（捕捉运动/接触/状态转换），而非单帧。训练时 K 值变化（包括稀疏使用 K=0）迫使模型既做局部推理也做全局推理。

3. **混合训练：SFT 学推理 + RLVR 学精度**：SFT 阶段学习高质量时空 CoT，但标量进度值只占响应 token 的一小部分，信号弱。RLVR 阶段用 GRPO 直接优化进度预测准确性，弥补 SFT 的不足。

⚡ **Eureka Moment**：让 VLM 先做链式推理再输出进度值（而非直接输出奖励），CoT 过程本身就是对"感知捷径"的约束——模型必须解释"为什么"，才能"打分"，这天然降低了奖励被视觉欺骗的概率。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
rₜ = ψ · clip( p_θ(t | g, o₀, oₜ₋ₖ₊₁:ₜ, pₜ₋₁), -c, c )
```

**目标**：用 VLM 参数 θ 从视频流中预测每一步的任务进度 pₜ，将其转换为 RL 奖励 rₜ，驱动策略从随机初始化学会新任务。

**公式分解**：

```
输入：xₜ = [g, o₀; oₜ₋ₖ₊₁:ₜ, pₜ₋₁]
输出：yₜ = [<think> mₜ </think>, <answer> pₜ </answer>]
奖励：rₜ = ψ · clip(pₜ, -c, c)
```

| 符号 | 含义 | 范围/说明 |
|------|------|-----------|
| g | 自然语言任务目标 | 如 "pick up the red block" |
| o₀ | 首帧（初始状态锚点） | RGB 图像 |
| oₜ₋ₖ₊₁:ₜ | 最近 K 帧（运动上下文） | K ∈ [1, 8]（训练时变化） |
| pₜ₋₁ | 上一步进度预测 | [-100, 100] |
| mₜ | CoT 推理（自由文本） | 描述变化 + 判断推进/后退 + 下一步子目标 |
| pₜ | 进度预测 | [-100, 100]，100 = 完全成功 |
| ψ | 奖励缩放系数 | 超参 |
| c | 奖励裁剪范围 | 防止极端值 |

**直觉**：pₜ 本质上是"任务完成了百分之多少"的连续估计。ψ 和 clip 将其映射到 RL 算法友好的奖励范围。关键创新不是公式本身，而是 pₜ 的来源——它不是 VLM 的零样本输出，而是经过 1.2M 条 CoT 轨迹 + 4M 推理 traces 专门训练出来的。

> 符号与本文保持一致：g=目标, o=观测帧, p=进度, m=CoT推理, ψ=缩放, c=裁剪

### 训练损失

**阶段 1 — SFT（监督微调）**：

```
L_SFT(φ) = -E[(i,q,r,a)~D] [ Σₜ log p_φ(yₜ | i, q, y_<ₜ) ]
```

最大化结构化输出 y=[推理 r; 答案 a] 的似然。

**阶段 2 — RLVR（可验证奖励强化学习）**：

```
J_GRPO(φ) = E[q, {oᵢ}] [ (1/G) Σᵢ min(ρᵢ(φ)·Aᵢ, clip(ρᵢ(φ), 1-ε, 1+ε)·Aᵢ) ] - β·D_KL(p_φ || p_ref)
```

其中可验证奖励 r(o) = r_format(o) + r_acc(o)：

```
r_acc(o) = α · exp(-|p̂ₜ - pₜ| / τ)
r(o) ∈ [0, 2]（format 0.5 + accuracy 1.5）
```

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的"抓取红色方块"任务，用假设数值演示 SOLE-R1 的推理和奖励转换过程：

| 时间步 | 输入帧 | CoT 推理 mₜ（假设输出） | 进度 pₜ | clip(pₜ, -30, 30) | 奖励 rₜ (ψ=1) |
|--------|--------|------------------------|---------|--------------------|---------------|
| t=0 | 初始状态 | "机器人和方块都在初始位置，还没有任何移动" | -10 | -10 | -10 |
| t=1 | 机械臂开始移动 | "机械臂向方块方向移动了，这是一个好的进展" | 15 | 15 | 15 |
| t=2 | 机械臂接近方块 | "机械臂更接近方块了，但还没有接触" | 25 | 25 | 25 |
| t=3 | 夹爪张开准备抓取 | "夹爪张开了，准备抓取，进度继续推进" | 40 | 30 (clip!) | 30 |
| t=4 | 机械臂错过方块 | "机械臂错过了方块，向反方向移动了，进度回退" | -20 | -20 | -20 |
| t=5 | 重新调整 | "机械臂重新调整方向，向方块移动" | 5 | 5 | 5 |
| t=6 | 成功抓取 | "夹爪合拢，抓住了方块！任务完成" | 95 | 30 (clip!) | 30 |

**关键观察**：
- clip(c=30) 防止极端进度值（如 pₜ=95）产生过大的奖励跳跃，稳定训练
- 负奖励（t=4）明确惩罚"后退"行为，引导探索方向
- 线性插值：如果推理频率是控制频率的 1/4，t=1~t=3 之间的 reward 通过线性插值填充

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|-----------|----------|
| 模型大小 | Qwen3-VL-8B（微调后） | 8B 参数，单卡 A100 可推理，但训练需多卡 |
| 推理频率 | 可低于控制频率 | 控制频率假设 20Hz，推理可 5Hz，中间插值 → 降低 4× 推理成本 |
| 训练数据 | 10M 图像帧 + 4M CoT traces | 数据合成是核心工作量，需 41K 视频源 |
| 两阶段训练 | SFT（1 epoch）+ RLVR | SFT 收敛快，RLVR 是精度精细调节 |
| 零样本在线 RL | 从随机策略开始 | 无需演示数据、无需任务特定调参 → 部署成本极低 |
| 泛化能力 | 跨 4 个仿真器 + 真机 | 未见过的机器人形态（Sawyer, WidowX, Fetch）也能工作 |

**部署约束**：
- **延迟瓶颈**：8B VLM 每步推理约 100-500ms（取决于硬件），限制了控制频率上限
- **内存**：需要维护 K 帧的缓存窗口 + 上一步进度 pₜ₋₁
- **量化误差**：8B 模型可做 INT8 量化，但 CoT 生成质量可能下降——未验证

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能力

| 能力 | 证据 | 限制 |
|------|------|------|

| 抗奖励利用 | 失败多为"信号受限"而非"奖励 hacking" | 仍有 3 类错误模式（见下） |

### 失败模式

论文识别出三类 recurring error modes（论文 Table 1 / Appendix C）：

1. **短暂事件遗漏**：快速接触/抓取事件在帧间发生，VLM 可能错过
2. **不完整视角的歧义**：部分可观测时，无法判断物体真实状态
3. **外观捷径**：目标邻近/对齐但实际未完成，模型给出中等进度分数

### 6.1 隐含假设 (Hidden Assumptions)

| 隐含假设 | 说明 | 风险 |
|----------|------|------|
| 视频帧率足够捕捉关键事件 | 推理依赖帧间变化 | 低帧率场景下 CoT 质量可能下降 |
| 任务可用连续进度描述 | pₜ ∈ [-100, 100] 假设任务有"完成度"概念 | 离散/布尔任务（如"按下按钮"）可能不适合 |
| 仿真合成的非专家轨迹 ≈ 真实探索分布 | 仿真中注入随机偏差生成训练数据 | 真实 RL 探索分布可能不同，导致分布偏移 |
| 自然语言目标足够精确 | 依赖 g 提供任务规范 | 模糊目标（如"整理桌子"）可能产生歧义推理 |
| 8B 模型容量足够 | 选择 Qwen3-VL-8B 而非更大模型 | 更复杂任务可能需要更大容量——未做模型规模消融 |
