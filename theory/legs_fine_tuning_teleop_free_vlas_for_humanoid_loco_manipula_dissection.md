## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 频率/时序 | 训练 vs 推理 |
|------|------|------|-----------|-------------|
| **3DGS 背景重建** | 1-2 分钟手持场景视频 | 3D 高斯场（静态） | 一次性（每场景） | 数据准备阶段 |

| **MuJoCo 物理后端** | 18-D 高层指令（SE(3)×2 + 基座 4-D） | 关节状态、碰撞检测 | 500 Hz | 训练数据生成 |
| **SONIC 全身控制器** | 18-D 高层指令 | 关节级执行指令 | 同 MuJoCo | 训练 & 推理（同一二进制） |
| **程序化运动生成器** | 场景级参数（目标位姿、物体 ID、手臂选择） | Walk → Pick → Place 轨迹 | 每 episode | 训练数据生成 |
| **VLA 微调** | LEGS 生成的图像-指令-动作三元组 | 策略网络权重 | 一次性训练 | 部署推理 |

### 1.2 关键机制 (Key Mechanism)

**核心设计哲学：两个解耦。**

1. **物理与渲染解耦**：MuJoCo 在网格几何上解析动力学（500 Hz），渲染前端独立生成图像观测。两者通过 18-D 指令流桥接。
2. **静态背景与动态前景解耦**：3DGS 背景是固定的（从手持视频重建），网格前景在物理中运动，通过深度测试逐帧合成。

**为什么这样设计？**
- 3DGS 最小化渲染误差（相对于真实照片），消除了 mesh 渲染的视觉 sim-to-real gap
- 运动记录为独立指令流，不依赖渲染输入 → 同一运动数据集可在新背景和网格下重新渲染
- 两阶段色彩校准将两个不同色彩空间（3DGS 的扫描设备 ISP + SAM3D 的反照率）映射到部署相机色彩空间

⚡ **Eureka Moment**：把运动生成和外观渲染彻底解耦 — 运动在物理中记录为 18-D 指令流，外观通过重新渲染同一运动生成，因此适配新场景的成本从「1.5 小时人工遥操作」降为「0.1 小时 GPU 渲染」。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
c_d ≈ M · [R(c_m) ⊕ c_b]
```

**目标**：将两个不同色彩空间的渲染结果（SAM3D 网格色 c_m 和 3DGS 背景色 c_b）映射到部署相机色彩空间（c_d），使得仿真图像与真实相机图像在视觉编码器层面不可区分。

**公式分解**：

| 符号 | 含义 |
|------|------|
| c_m | mesh 顶点颜色（SAM3D 回归的反照率） |
| c_b | 3DGS 背景像素（扫描设备的 ISP 色彩空间） |
| c_d | 部署相机像素（目标色彩空间） |
| R(·) | 逐网格对角缩放矩阵（线性 RGB），使每个网格的渲染均值匹配手持扫描 |
| ⊕ | 深度测试合成操作 |
| M ∈ R^(3×3) | 全局色彩校正矩阵，由 24 色 ColorChecker 双相机照片最小二乘拟合 |

**直觉**：R 修正 SAM3D 的错误反照率（SAM3D 把黑色盒子渲染成灰白色 → R 恢复为黑色），M 将 3DGS 背景（桌子和地板）偏移至部署相机色彩。两步合起来把合成图像拉到真实图像附近。

> 符号与本文保持一致。详细推导见论文 Appendix C。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设 Task 1（纯操作，无移动）的一个 episode：

**初始条件**：橘子在 (0.3, 0.0, 0.75) m，盘子在 (0.5, 0.1, 0.75) m，机器人静止。

**程序化运动生成**：
1. **Pick 原语**：目标腕部 SE(3) → 橘子上方 5cm → 闭合夹爪 → 抬起 10cm

**MuJoCo 物理求解**（500 Hz）：
- 每个控制步：18-D 指令 → SONIC 控制器 → 关节力矩
- 29-DoF 身体 + 7-DoF 手 × 2 = 43-DoF 系统
- 假设一个 Pick 阶段耗时 2 秒 → 1000 个物理步

**渲染**：
- 每帧：3DGS 背景渲染（固定）+ 网格前景光栅化 + 深度测试合成
- 色彩校准：c_d = M · [R(c_m) ⊕ c_b]
- 30 Hz RGB → 60 帧图像

**最终数据集条目**（以 50 episodes 为例）：
- 50 episodes × ~60 frames/episode = ~3,000 帧
- 每帧：(图像, 18-D 指令, 语言标签 "place the orange on the plate")

**对比遥操作**：
- 遥操作 50 episodes ≈ 1.5 人工小时（操作员通过 VR 控制）
- LEGS 50 episodes ≈ 0.5 GPU 小时（无人值守）
- 新场景适配：遥操作需重新采集 >1.5h，LEGS 重新渲染仅需 ~0.1h

## 4. 工程视角 (Engineering View)

| 维度 | LEGS | 遥操作 | 工程含义 |
|------|------|--------|----------|
| 初始数据采集成本 | 0.5 GPU-hr (RTX 4090) | 1.5 operator-hr | LEGS 将人力绑定转为计算绑定，可并行化 |
| 新场景适配成本 | 0.1 GPU-hr | >1.5 operator-hr | 15× 成本降低，核心优势 |
| 场景准备 | 1-2 min 手持视频 + 物体照片 | 无需准备 | 3DGS 重建是前置开销，但远低于遥操作 |
| 物理求解频率 | 500 Hz (MuJoCo) | N/A | 高频率确保动力学精度 |
| 渲染频率 | 30 Hz (RGB) | 30 Hz (RealSense D435) | 匹配真实相机帧率 |
| 控制器部署 | 同一 SONIC 二进制 | 同一 SONIC 二进制 | 零代码变更部署 |
| 光照鲁棒性 | 敏感（需固定 auto-exposure/white-balance） | 自适应 | 关键局限：策略对训练时光照分布外变化敏感 |
| 并行扩展 | 可跨 GPU 并行重新渲染 | 不可并行 | 大规模场景覆盖时 LEGS 优势更大 |

**部署约束**：
- 关闭自动曝光和自动白平衡是必要前提 — 这限制了策略对光照变化的鲁棒性
- 3DGS 对高反射/透明表面重建质量差 — 这类场景需要额外处理
- 背景假设为静态 — 动态场景（移动的人）需要动态 3DGS，本文未实现

### 不能做什么

| 跨平台泛化 | 其他人形机器人 | 仅评估 Unitree G1；未测试其他硬件 |
| 大类别物体迁移 | 远超训练尺寸/几何的物体 | 外观随机化仅测试了相似大小的可抓握物体 |
| 运动效率优化 | 动力学效率 | 程序化生成器生成可行运动但不优化效率（不同于轨迹优化/MPC） |

### 6.1 隐含假设 (Hidden Assumptions)

1. **固定光照假设**：色彩校准假设部署环境光照与 3DGS 扫描时一致。论文在 Limitations 中承认了这一点，但未量化"多大程度的光照变化会导致策略失效"。
2. **静态背景假设**：3DGS 背景是静态的。在真实家庭/工厂环境中，背景中的人/物移动是常态。
3. **控制器可迁移假设**：SONIC 控制器在仿真和真实机器人上运行同一二进制。这假设了 SONIC 本身已经足够鲁棒，LEGS 只解决视觉层面的 sim-to-real gap，而非动力学层面的 gap。
4. **SAM3D 网格质量假设**：SAM3D 从单张照片重建物体网格。如果 SAM3D 重建质量差（如复杂几何、半透明物体），整个 pipeline 会受影响。
5. **程序化运动充分性假设**：程序化生成的 Walk/Pick/Place 原语覆盖了 VLA 需要学习的所有行为模式。但未与人类遥操作数据的多样性做定量比较。

**面试 Tip**：当被问到"Sim-to-Real 的核心挑战是什么"时，可以这样回答：「传统方法有两个 gap — 视觉 gap（mesh 渲染 vs 真实图像）和动力学 gap（仿真物理 vs 真实物理）。LEGS 通过 3DGS 解决了视觉 gap，通过 SONIC 控制器（已在真实机器人上训练）解决了动力学 gap，然后用程序化运动替代遥操作生成数据。关键 insight 是运动和外观解耦，使得数据适配新场景的成本从人力绑定转为计算绑定。」
