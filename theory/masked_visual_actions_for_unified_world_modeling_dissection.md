### 1.2 关键机制 (Key Mechanism)

核心思想极其简洁：**把动作从"数字"变成"像素"**。

- 传统方法：动作 = 低维向量（如7-DoF末端位姿）→ 需要通过全连接层映射到视觉特征空间 → 与预训练视频模型的视觉先验不对齐
- 本文方法：动作 = 视频中机器人所在区域的掩码轨迹 → 直接用视频模型的自编码器编码 → 与输出视频在相同特征空间拼接 → 天然对齐

这种设计带来了三个关键优势：
1. **像素对齐**：条件信号与输出在相同空间，不需要额外的模态映射
2. **具身无关**：只要能在像素空间画出"某个实体"的轨迹，模型就能理解——不关心是Franka、二足还是大猩猩
3. **前向/逆向统一**：掩码覆盖机器人 = 前向（预测场景）；掩码覆盖物体 = 逆向（反推机器人）

⚡ **Eureka Moment**：前向动力学和逆向动力学不是两个独立问题——它们只是同一个视频补全任务的两种不同掩码查询方式。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
p_θ(V | M⊙V, I₀)  →  通过改变掩码M，同一θ实现前向和逆向
```

**目标**：让预训练视频模型学习条件分布 `p(V | M⊙V, I₀)`，其中掩码 `M` 决定哪些像素区域被揭示、哪些需要预测。

**核心方程**：

```
p(V) = p(e₁, e₂, ..., eₙ)          # 联合分布：场景中所有实体的轨迹
p({eᵢ}ᵢ∉ₛ | {eⱼ}ⱼ∈ₛ, I₀)         # 条件分布：给定实体子集S，预测其余
M(S) = ⋃ᵢ∈ₛ eᵢ                     # 掩码 = 被揭示实体的像素区域并集
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| `V ∈ R^{T×H×W×3}` | 视频序列（T帧，H×W分辨率，3通道） |
| `eᵢ` | 场景中第i个实体的时空轨迹（像素区域） |
| `S ⊆ {1,...,n}` | 被揭示的实体子集（条件集） |
| `M ∈ {0,1}^{T×H×W}` | 二值掩码，1=揭示，0=待预测 |
| `I₀` | 初始场景参考帧 |
| `A` | 主动实体索引（机器人等施动者） |
| `P` | 被动实体索引（被操作物体等） |

**直觉**：模型本质上在做"视频填空"。填空的内容取决于你填了什么——填机器人运动轨迹，模型补全场景变化（前向）；填物体运动轨迹，模型补全机器人运动（逆向）。训练时随机采样不同的掩码模式，推理时通过选择掩码模式来选择任务。

> 符号与本文保持一致：主动实体（active）指具有自主运动能力的实体（机器人/人），被动实体（passive）指因交互而运动的实体（物体）。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：3个实体——机器人手臂(e₁)、杯子(e₂)、桌面(e₃)。

**训练阶段**：

```
场景: V = [e₁, e₂, e₃] 的时空轨迹
掩码采样: 随机选择 S = {e₁}（揭示机器人）
输入给模型: M⊙V = 只有机器人轨迹可见，杯子和桌面区域为灰色
学习目标: p(e₂, e₃ | e₁, I₀) = 给定机器人运动，预测杯子如何被移动
```

**推理阶段 — 前向模式**：

```
输入: 参考帧 I₀ + 掩码视频（机器人URDF渲染轨迹）
掩码: M = 机器人区域 = 1，其余 = 0
输出: V̂ = 完整视频，其中杯子被机器人推动、可能掉落
```

用具体假设数值演示：
- 机器人末端在t=0时位于(x=0.3, y=0.5)，t=10时移动到(x=0.5, y=0.5)
- 杯子初始位于(x=0.45, y=0.5)
- 模型预测：t=5时机器人接触杯子，t=8时杯子被推动到(x=0.55, y=0.5)
- 与真实执行对比：实际杯子移动到(x=0.53, y=0.51)，误差约2cm

**推理阶段 — 逆向模式（零样本）**：

```
输入: 参考帧 I₀ + 掩码视频（期望的杯子运动轨迹）
掩码: M = 杯子区域 = 1，其余 = 0
输出: V̂ = 完整视频，其中机器人运动被补全
```

注意：模型训练时从未见过"掩码覆盖物体"的样本——它只见过掩码覆盖机器人的数据。但掩码机制的对称性让模型自然学会了逆向推理。

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/设计选择 | 含义 |
|----------|--------------|------|

| Batch size | 4 | 较小，受限于14B模型+视频序列的显存 |
| 条件注入 | 特征拼接（concatenation） | 简单高效，但需要条件与输出同分辨率 |
| 推理延迟 | 未明确给出，估计每样本数秒 | 14B扩散模型+视频生成，不适合实时控制 |
| 掩码构造 | 分割法（SAM）+ 渲染法（URDF） | 分割法通用但测试时难提供；渲染法精确但需相机标定 |

**工程含义**：
- 该模型定位是**离线规划/评估工具**，而非实时控制策略。推理延迟使其适合模型预测控制（MPC）中的rollout评估，而非闭环控制。
- LoRA rank=256 是一个较高的秩——说明视频条件注入需要较大的适配容量。
- 15小时数据就能实现跨具身泛化，说明预训练视频模型的视觉先验远比机器人数据本身更重要。

### 6.1 隐含假设 (Hidden Assumptions)

1. **掩码可获取性假设**：推理时需要提供实体的掩码轨迹。对于前向模式，需要渲染或分割机器人；对于逆向模式，需要预先知道物体的期望运动轨迹——这本身就是一个规划问题。
2. **实体可分离性假设**：方法假设场景可以被分解为独立的实体轨迹。对于高度耦合的交互（如柔性物体变形、流体），这种分解可能不够精确。
3. **预训练先验覆盖假设**：跨具身泛化能力完全依赖预训练视频模型中是否包含类似形态的视觉先验。对于极端新颖的形态（如软体机器人），泛化可能退化。
4. **零样本逆向的局限性**：模型仅在主动实体掩码上训练，逆向能力是涌现的。这意味着逆向生成的质量可能不如专门训练的逆向模型稳定。
