💡 **X-Ray 开场**
视频模型在大规模数据上学会了物理世界的运动、接触和变形先验，但它们通常是"被动观察者"——你给一张初始帧，它生成后续视频，但你无法控制机器人做什么。这篇论文的核心发现是：如果把机器人的运动以"掩码轨迹"的形式部分揭示给视频模型，模型就会自动变成一个前向动力学模拟器；反过来，如果你揭示的是目标物体的运动轨迹，同一个模型就会合成出机器人应该如何运动才能实现这个目标。一个模型，两种模式，无需分别训练。

### 1.2 关键机制 (Key Mechanism)

论文的核心观察是：视频模型隐式地学习了场景中所有实体的联合分布 p(e₁, e₂, ..., eₙ)。传统方法通过低维动作向量或稀疏骨骼来条件化这个分布，但这些信号与模型预训练时的视觉经验不对齐。

**掩码视觉动作**的做法是：

1. **将场景视为实体集合**：每个实体（机器人臂、被操作物体、背景）在视频中占据一个时空区域。
2. **用二值掩码控制条件化**：M ∈ {0,1}^{T×H×W}，M=1 的区域是"揭示"的（模型看到的），M=0 的区域是"预测"的（模型需要生成的）。
3. **通过切换揭示哪个实体来切换模式**：
   - 揭示机器人 → 模型预测场景中其他实体的运动 → **前向动力学**
   - 揭示目标物体 → 模型预测机器人应该如何运动 → **逆向行为合成**

⚡ **Eureka Moment**：前向和逆向建模不是两个不同的任务——它们是同一个联合分布上不同条件查询的产物。关键在于用空间掩码（而非低维向量）作为条件化接口，使这个切换成为可能。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
p({eᵢ}ᵢ∉ₛ | {eⱼ}ⱼ∈ₛ, I₀)  —  同一个模型，不同 S 集合 = 不同任务
```

**目标**：让视频模型在给定初始帧 I₀ 和部分揭示实体 {eⱼ}ⱼ∈ₛ 的条件下，预测剩余实体 {eᵢ}ᵢ∉ₛ 的时空轨迹。

**核心方程**：
```
训练目标:  min_θ  E[M∼p(M)]  [ -log p_θ(V | M⊙V, I₀) ]

其中:
  M(𝒮) = ⋃_{i∈𝒮} eᵢ          // 条件化集合 S 中所有实体的像素区域并集
  M⊙V = 掩码后的视频           // M=1 处保留原像素, M=0 处设为灰色
  I₀    = 初始参考帧
  𝒜    = 主动实体索引 (机器人)
  𝒫    = 被动实体索引 (物体)
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| V ∈ ℝ^{T×H×W×3} | 视频序列（T 帧，H×W 分辨率，3 通道 RGB） |
| eᵢ | 第 i 个实体及其时空像素区域 |
| 𝒮 ⊆ {1,...,n} | 条件化实体集合（被揭示的） |
| M ∈ {0,1}^{T×H×W} | 二值时空掩码 |
| 𝒜 | 主动实体集合（机器人） |
| 𝒫 | 被动实体集合（被操作物体） |
| I₀ | 初始参考帧 |

**直觉**：训练时随机采样掩码 M（即随机选择揭示哪些实体），让模型学习条件分布。推理时，选择揭示机器人（S=A）就做前向预测，选择揭示物体（S=P）就做逆向合成。模型本身没有"主动/被动"的概念——它只是在做视频补全。

> 符号与本文 §3 保持一致。模型训练时仅使用了揭示主动实体（机器人）的掩码样本，但在推理时零样本泛化到了揭示被动实体（物体）的逆向查询。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：

- **场景**：2 个实体 — 机器人臂 (e₁) 和方块 (e₂)
- **视频**：T=16 帧，H×W=256×256
- **初始帧 I₀**：机器人在方块左侧，未接触

**前向模式**（S = {e₁}，揭示机器人运动）：
```
输入:  M 揭示 e₁ 在 16 帧中的轨迹（灰色背景填充其余区域）
模型:  p(e₂ | e₁, I₀)
输出:  预测方块被推动后的 16 帧视频

假设数值:
  掩码覆盖率: M=1 占 16×256×256 的 ~8%（机器人臂区域）
  待预测区域: ~92% 的时空像素
  模型通过自注意力机制学习 e₁ 与 e₂ 的交互模式
```

**逆向模式**（S = {e₂}，揭示目标物体运动）：
```
输入:  M 揭示 e₂ 的期望轨迹（如"方块从 A 移动到 B"）
模型:  p(e₁ | e₂, I₀)
输出:  合成机器人臂运动，使方块达到目标位置

假设数值:
  掩码覆盖率: M=1 占 ~5%（方块区域）
  待预测区域: ~95%（主要是机器人运动）
  模型从联合分布中"反推"出与 e₂ 运动一致的 e₁ 轨迹
```

**关键洞察**：同一个 14B 参数模型，同一套权重，仅仅因为输入掩码 M 不同，就执行了两个完全不同的任务。不需要单独训练逆向模型头。

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/描述 | 含义 |
|----------|----------|------|
| 基础模型 | Wan-Fun-Control 2.2 14B | 大模型 = 强先验，但推理慢 |
| 微调方式 | LoRA rank=256 | 仅更新少量参数，保留预训练先验 |
| 训练硬件 | 8×NVIDIA H200 GPU | 高端配置，成本不低 |
| 训练时长 | ~10,000 步，4 天 | 数据量小（15h），但模型大 |
| 批次大小 | 4（每 GPU） | 受限于 14B 模型的显存 |
| 条件化机制 | 视频 latent 拼接 | 简单有效，因条件信号与输出空间对齐 |
| 缺失区域填充 | 均匀灰色 | 避免信息泄漏，给模型清晰的"待预测"信号 |
| 推理速度 | 受限于基础视频模型 | 扩散模型推理通常需多步去噪，不适合高频控制 |

**工程含义**：
- 该方法不适合直接作为高频闭环控制器（如 10Hz+ 的控制循环）。它更适合：(1) 离线规划评估（Best-of-N 采样），(2) 策略性能预评估（在仿真中判断策略成功率），(3) 逆向行为合成（低频的意图→动作映射）。
- LoRA rank=256 是一个较高的秩——说明 14B 模型需要足够的适配容量来学习掩码条件化。
- 分割法 + 渲染法互补：分割法泛化性强但可能泄漏遮挡信息；渲染法精确但需要相机标定。

### 6.1 隐含假设 (Hidden Assumptions)

1. **实体可分割性假设**：掩码构建依赖 SAM 或 URDF 渲染能准确分割出目标实体。对于无标定数据的真实场景，渲染法不可用；SAM 分割可能不精确。
2. **前/被动实体可分离假设**：虽然论文说"主动/被动是使用方法而非模型属性"，但实际训练中只使用了揭示主动实体的掩码。逆向泛化是 emergent 能力，其可靠性尚未在分布外场景充分验证。
3. **视频模型先验充分性假设**：方法的有效性高度依赖基础视频模型的物理先验质量。如果基础模型对某种交互（如流体、软体）没有学好，掩码方法也无法弥补。
4. **单摄像头假设**：所有实验使用单目 RGB。多视角扩展需要额外工作。

## 7. 与相关工作对比 (Comparison)

| 方法 | 动作表征 | 前向 | 逆向 | 跨形态 | 训练方式 |
|------|---------|------|------|--------|---------|
| **本文 (MVA)** | 像素掩码轨迹 | ✅ | ✅ (零样本) | ✅ | LoRA (15h) |
| Ctrl-World | 低维 EEF 状态 | ✅ | ❌ | ❌ | 全量微调 |
| BridgeV2W | URDF 渲染掩码 | ✅ | ❌ | 部分 | 全量微调 |
| Action Images | 多视图高斯热力图 | ✅ | ❌ | 部分 | 全量微调 |
| UVA | 模态通道掩码 | ✅ | ✅ | ❌ | 全量微调 |
| AIM | 空间价值图 | ✅ | ✅ | ❌ | 全量微调 |
| VAP | 骨架可视化 | ✅ | ❌ | ❌ | 全量微调 |

**关键差异**：
- 与 UVA/AIM 等"统一模型"相比，本文的掩码是**空间级**的（同一像素画布），而非**模态级**的（动作向量通道 vs 视频通道）。这使得跨形态泛化成为可能。
- 与 BridgeV2W/Shadow 等掩码方法相比，本文的掩码是**条件化接口**（输入），而非**预测目标**（输出）或**数据编辑工具**（训练时合成）。

💡 **面试 Tip**：当被问到"你的方法和 Ctrl-World 的本质区别是什么"时，回答："Ctrl-World 用低维动作向量条件化，这绑定了特定机器人形态；我们用像素空间掩码，动作就是场景中的一个实体区域——切换揭示哪个实体，同一个模型就能在前向预测和逆向合成之间切换，且对未见过的机器人形态零样本泛化。"
