VLA 模型能理解指令并输出动作，但在混乱环境中经常撞到不该碰的物体。现有安全方案（如 RL 训练）需要重新训练模型，成本高且缺乏硬保证。本文提出 AEGIS——在 VLA 输出后加一个"安全守卫"：先用 VLM 识别最危险的障碍物，再用 CBF-QP 微调动作确保不碰撞。**核心发现：安全不是 VLA 的软目标，而是可以数学证明的硬约束，且几乎不增加推理延迟。**

### 1.2 关键机制 (Key Mechanism)

AEGIS 的 SC（Safety Constraint）层由两个模块串联：

1. **视觉语言安全评估模块**：VLM（GLM-4.5V）读取 RGB 图像 + 自然语言指令，推理出"当前最可能碰撞的障碍物"（如"红色牛奶盒"）→ GroundingDINO 定位 2D BBox → 双视角深度相机融合 → 3D 点云 → 聚类提取主障碍物。

2. **动作驱动安全控制模块**：将障碍物点云拟合为最小体积包围椭球（MVEE）→ 机械臂末端也用椭球建模 → 计算两椭球间最短有符号距离 h(x) → 作为 CBF 约束 → QP 求解器最小化偏离 VLA 原始动作的幅度。

⚡ **Eureka Moment**：用 VLM 的语义推理能力解决"哪个物体是障碍"，用 CBF 的数学保证解决"怎么不碰到它"——两个经典工具的组合恰好填补了 VLA 安全性的模态鸿沟。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
u_safe = argmin_u ‖u - u_vla‖²    s.t.    ḣ(x) ≥ -α·h(x)
```

**目标**：在满足安全约束的前提下，让执行动作尽可能接近 VLA 的原始意图。

**变量说明**：

| 符号 | 含义 | 来源 |
|------|------|------|
| u_vla | VLA 输出的原始动作 [v, ω, g] | 预训练模型 |
| u_safe | 安全修正后的动作 | QP 求解结果 |
| h(x) | 末端执行器椭球与障碍物椭球间的最小有符号距离 | 式(9) 推导 |
| C = {x \| h(x) ≥ 0} | 安全状态集合（超水平集） | 式(1) |
| α(·) | K∞ 类函数，控制收敛速率 | 本文设 α(h) = 10h |
| x | 增广状态 [p_ep, R_ef, p_s] | 含虚拟辅助状态 |

**直觉**：h(x) > 0 表示两个椭球不相交（安全）；h(x) = 0 表示刚好接触；h(x) < 0 表示碰撞。QP 求解器确保 h(x) 永远不会变成负数——只要初始状态安全，则全程安全。

**CBF 距离公式**（式 9，核心推导）：

```
h(x) = [-‖Q̄_ob · Q̄_ef⁻¹ · p_s‖ + (p_ob - p_ef)ᵀ · Q̄_ef⁻¹ · p_s - 1] / ‖Q̄_ef⁻¹ · p_s‖
```

其中 Q̄ = R · Q · Rᵀ 是旋转后的形状矩阵，p_s 是单位球面上的虚拟辅助状态，通过最大化 h(x) 来减少保守性。

> 符号与本文保持一致：Q_ef = diag(0.06, 0.12, 0.11) m（末端椭球尺寸），α(h) = 10h，控制系数 k = 10。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：

- 末端执行器椭球：Q_ef = diag(1, 1, 1)（单位球，中心在 p_ef = [0, 0, 0]）
- 障碍物椭球：Q_ob = diag(1, 1, 1)（单位球，中心在 p_ob = [3, 0, 0]）
- VLA 原始动作：u_vla = [2, 0, 0]（向障碍物方向移动 2 单位）

**Step 1 — 计算当前距离 h(x)**：
两球中心距离 = 3，半径各为 1 → 表面间距 = 3 - 1 - 1 = 1 > 0，当前安全。

**Step 2 — 执行原始动作后**：
p_ef_new = [2, 0, 0] → 新间距 = 3 - 2 - 1 - 1 = -1 < 0 → 碰撞！

**Step 3 — QP 求解**：
约束 ḣ ≥ -α·h → h 必须保持 ≥ 0。

QP 求解器找到最小偏离：u_safe ≈ [1, 0, 0]（只移动 1 单位，刚好不碰）。

```
‖u_safe - u_vla‖² = ‖[1,0,0] - [2,0,0]‖² = 1  （最小偏离）
h(x_new) = 0  （刚好安全边界）
```

**Step 4 — 下一步**：VLM 重新评估场景 → 若障碍物仍在，QP 继续约束 → 机器人绕行或等待。

## 4. 工程视角 (Engineering View)

| 工程指标 | 数值 | 含义 |
|----------|------|------|
| SC 层延迟 | 0.356ms/步 | RTX 4090 上实测 |
| VLA 推理延迟 | ~19ms/步 | 同硬件 |
| SC 占比 | 1.86% | 几乎可忽略 |
| 控制频率 | 20 Hz | Robosuite OSC_POSE 接口 |
| 底层控制器频率 | 1 kHz | 真实机器人实验 |
| VLA 推理频率 | 15 Hz | 真实机器人 |
| 最大 episode | 300-550 步 | 取决于任务套件 |
| QP 约束数 | 1 个线性约束 | 凸 QP，求解极快 |

**工程含义**：
- SC 层是"轻量级介入"——仅在检测到安全风险时修改动作，其余时间直通 VLA 输出。
- 单约束 QP 保证了实时性：0.356ms << 20Hz 周期（50ms），不会成为瓶颈。
- 依赖外部 VLM（GLM-4.5V）和 GroundingDINO——这两个模块的延迟未计入 0.356ms 中，实际端到端延迟取决于 VLM 推理速度。
- 真实部署需要双深度相机（agent-view + back-view），增加了硬件复杂度。

| 快速动态障碍物 | CBF 基于瞬时几何，不预测运动 | 假设障碍物静态 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **单障碍物主导假设**：系统每次只处理一个障碍物。当多个障碍物同时构成威胁时（如狭窄通道），理论保证退化。论文在 §V-C 承认这一点但未给出多障碍物扩展方案。

2. **椭球充分性假设**：定理 1 的证明依赖"椭球严格包围真实物体"。对于细长/非凸物体（如扫把、衣架），MVEE 可能过度膨胀，导致机器人过度保守甚至无法通过。

3. **VLM 准确性假设**：整个安全链的起点是 VLM 正确识别障碍物。如果 VLM 将目标物体误判为障碍物（如"拿起红色杯子"中把红色杯子识别为障碍），系统会阻止合法动作。论文未量化 VLM 识别错误率。

4. **静态障碍物假设**：CBF 约束基于当前帧几何，不建模障碍物运动。移动障碍物（如人来人往的厨房）场景未涉及。

5. **仿真-现实鸿沟**：仿真中点云是完美的；真实 ZED 相机有噪声、遮挡、标定误差。真实实验仅 2 个任务 × 2 等级 = 4 个场景，泛化性待验证。
