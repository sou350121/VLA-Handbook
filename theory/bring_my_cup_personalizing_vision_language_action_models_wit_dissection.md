## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.2 关键机制 (Key Mechanism)

VAP 的核心设计围绕两个互补信号：

1. **Grounding（定位）**: 用 ~5 张参考图构建非参数视觉记忆。通过开放词汇检测器定位场景中所有同类物体，再用视觉编码器计算嵌入相似度，通过投票机制选出最匹配的候选框，最后用分割器细化为像素级掩码。

2. **Visual Prompting（提示）**: 将掩码区域叠加半透明彩色高亮（如红色），同时将指令中的个性化引用（"my cup"）重写为匹配高亮颜色的通用短语（"the red cup"）。视觉高亮提供像素级锚点，指令重写提供语言 token 告诉 VLA 该关注哪个锚点。

**为什么需要两者配对？** 消融实验（论文 Appendix E.1）证明：仅有视觉高亮或仅有指令重写时，VLA 会退化为类别级先验，在相似物品中几乎随机选择。两者缺一不可，构成一个绑定机制。

**为什么用外部提示而非学习 token 嵌入？** 作者发现学习式 token 嵌入在静态图像中能识别目标，但在闭环执行过程中注意力会漂移，恰好 VLA 最需要实例信号时信号消散了。外部掩码干预通过每帧重新锚定实例信号避免了这个问题。

⚡ **Eureka Moment**: 个性化不需要改模型权重——把目标用视觉高亮"涂"在输入图上，同时把指令改写成匹配高亮的颜色词，冻结 VLA 就能操作用户特定物品。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
M_t = g(I_t, R_o, H_{t-1})    →    (x̃_t, ℓ̃) = p(x_t, ℓ, M_t)    →    a_t = π_VLA(x̃_t, ℓ̃)
```

**目标**: 在不更新 π_VLA 参数的前提下，仅通过输入变换 (x, ℓ) → (x̃, ℓ̃) 引导模型操作正确实例。

**变量说明**:

| 符号 | 含义 |
|------|------|
| π_VLA(a \| x, ℓ) | 冻结的 VLA 策略，输入观测 x=(I, s) 和指令 ℓ，输出动作 a |
| R_o = {I_o^(k)} | 用户提供的 K≈5 张参考图像 |
| M_t | t 时刻的像素级掩码，标记目标物体所在区域 |
| H_{t-1} | 追踪器历史状态 |
| x̃_t, ℓ̃ | 提示后的观测和指令 |
| b* | 投票选出的目标边界框 |

**投票匹配公式**（核心实例选择机制）：

```
b* = argmax_{b_i ∈ B_t} Σ_{k=1}^K 1[i = argmax_j cos(e_j, z_k)]
```

直觉：每张参考图 z_k 为自己最匹配的候选框投一票，得票最多的框被选中。平票时取平均余弦相似度最高者。这比单纯取平均相似度更鲁棒——它要求跨参考视图的一致性。

> 符号与本文保持一致：I 为多视角 RGB 图像，s 为本体感知状态，f(·) 为冻结视觉编码器。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设桌面上有 3 个杯子：A（用户的，蓝色花纹）、B（白色）、C（红色）。指令："pick up my cup"。参考图 R_o = {5 张蓝色花纹杯子的照片}。

**Step 1 — 检测**: 开放词汇检测器找到 3 个杯子 B_t = {b_A, b_B, b_C}。

**Step 2 — 嵌入与相似度**: 假设视觉编码器产生的余弦相似度矩阵（行=候选，列=参考图）：

```
        z_1  z_2  z_3  z_4  z_5
b_A     0.82 0.79 0.85 0.81 0.83  ← 蓝色花纹杯
b_B     0.31 0.28 0.33 0.30 0.29  ← 白杯
b_C     0.42 0.38 0.45 0.40 0.41  ← 红杯
```

**Step 3 — 投票**: 每张参考图投票给相似度最高的候选：
- z_1 → b_A (0.82 最高)
- z_2 → b_A (0.79 最高)
- z_3 → b_A (0.85 最高)
- z_4 → b_A (0.81 最高)
- z_5 → b_A (0.83 最高)

投票结果: b_A = 5 票, b_B = 0 票, b_C = 0 票 → **b* = b_A** ✅

**Step 4 — 提示**: 掩码 M_0 覆盖杯子 A → 叠加红色半透明高亮 → 指令重写 "pick up my cup" → "pick up the red cup"。

**Step 5 — VLA 推理**: π_VLA 看到红色高亮的杯子 A + "pick up the red cup" → 输出抓取杯子 A 的动作。

**对比无 VAP 的情况**: 原始指令 "pick up my cup" 被 VLA 理解为 "pick up a cup" → 可能抓到 B 或 C（类别级随机）。

## 4. 工程视角 (Engineering View)

| 维度 | 分析 |
|------|------|
| **计算开销** | t=0 时运行检测器+编码器+分割器（一次性）；t>0 仅运行追踪器（轻量）。整体额外开销远低于 VLA 推理本身 |
| **延迟** | 检测器+分割器约 100-300ms（取决于模型）；追踪器约 30-50ms/帧。对 10Hz 控制频率影响可忽略 |
| **内存** | 参考嵌入 Z_o 仅 K×d 向量（K≈5, d≈512-768），几乎无存储压力 |
| **部署约束** | 需要预部署开放词汇检测器（如 GroundingDINO）、分割器（如 SAM）、追踪器（如 OSTrack）。这些是独立模块，可分别优化 |
| **量化误差** | 所有外部模块均为冻结推理，可独立量化；VLA 本身不受影响 |
| **鲁棒性 trade-off** | 检测器漏检 → 降级为无提示模式（安全但不个性化）；追踪器丢失目标 → 同样降级。不会崩溃，但性能下降 |
| **多用户扩展** | 项目页展示了多用户场景（"my cat figurine AND my brother's owl figurine"），只需维护多个对象的参考记忆库 M |

**工程含义**: VAP 的本质是一个"输入预处理器"——它在 VLA 的摄像头输入和指令输入之间插入了一个轻量级适配层。这类似于在传感器和执行器之间加了一个翻译器，不改变核心控制器，只改变它看到的世界。

### 6.1 隐含假设 (Hidden Assumptions)

1. **开放词汇检测器能召回目标类别**: 如果检测器在 "cup" 上失败（N_v = 0），整个 VAP 降级。论文假设检测器召回率足够高，但未量化这一假设的脆弱程度。

2. **视觉编码器能区分同类不同实例**: 依赖 f(·) 对细粒度差异（花纹、纹理、微小几何差异）的敏感性。如果编码器过于类别抽象化，投票机制会退化为随机选择。

3. **参考图与场景图的域差距可忽略**: 参考图通常是物体中心裁剪图，场景图是杂乱桌面。论文通过裁剪减少背景偏差，但域差距对嵌入相似度的影响未量化。

4. **指令重写模板覆盖所有个性化表达**: 当前使用 "my X" → "the tint-color X" 的模板替换。对于 "my brother's cup" 或 "the mug with the chip" 等更复杂表达，模板可能不适用。

5. **桌面操作假设**: 所有实验在桌面场景进行。扩展到移动机器人或更复杂环境时，检测器/追踪器的稳定性可能显著下降。
