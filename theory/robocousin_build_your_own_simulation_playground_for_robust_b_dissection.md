## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

RoboCousin 由三个核心模块组成，覆盖从图像到轨迹的完整数据生成管线：

| 模块 | 输入 | 输出 | 关键技术 | 功能定位 |
|------|------|------|----------|----------|
| **Digitalize Anything** | RGB 图像 / 房间 prompt | 仿真资产（URDF + 碰撞网格 + 物理属性 + 接触点） | SAM 3D 3D 重建、VLM 物理属性推断、CoT 摩擦系数估计 | 把"看到的物体"变成"能交互的仿真资产" |
| **Generate Digital Cousins** | 桌面 RGB 图像 / 场景 JSON | 数字表亲场景（变化的物体/背景/布局/指令） | 分割+深度估计+重描述、支撑图构建、类别级实例随机化 | 在保持任务语义的前提下扩展场景多样性 |
| **Robots Should Move** | 场景 JSON + 机器人 URDF | 导航路径 (x, y, θ) 序列 | A* 网格规划、碰撞膨胀、两阶段对接 | 把固定桌面任务扩展为"导航+操作"连续轨迹 |

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

现有仿真数据生成的根本瓶颈不是"轨迹生成速度"，而是"仿真世界本身的扩展性"。增加轨迹数量只能在已有资产范围内提升覆盖率，但无法增加新物体或新环境。RoboCousin 的洞察是：**可扩展的机器人数据生成应该让仿真世界本身可扩展，而不仅仅是在已有世界中加速轨迹生成。**

三个模块分别解决三个耦合挑战：

1. **资产必须是交互就绪的**（不仅是视觉逼真）：3D 生成模型提供几何，但机器人学习还需要精确尺度、碰撞网格、物理属性和操作标注。Digitalize Anything 模块用 VLM 推断物理属性（质量、摩擦系数），用自动化接触点推断生成抓取候选。

2. **多样性必须保留任务语义**：传统域随机化可能产生与目标场景功能结构弱相关的扰动。数字表亲在变化物体实例和背景的同时，保留任务相关的支撑关系和空间语义。

3. **移动操作扩展**：大多数合成轨迹从固定桌面位姿开始。RoboCousin 用场景布局做导航规划，将同一桌面任务与不同房间布局、起始位姿、路径组合，增加时空多样性。

⚡ **Eureka Moment**：从"封闭资产库内生成更多轨迹"到"让仿真世界本身可扩展"——数据生成的瓶颈不在轨迹产量，而在资产和场景的扩展成本。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
P_policy = π_θ(obs, lang)  其中 obs ~ Cousins(I_real, Ω_asset, Ω_bg)
```

直觉：策略 π_θ 的观测分布来自对真实场景 I_real 的数字表亲变换——在资产库 Ω_asset 和背景库 Ω_bg 中采样语义一致的变体，而非从固定数字孪生中采样。

**目标**：最大化策略在真实世界测试场景上的成功率，训练时从数字表亲分布中采样数据。

**公式分解**：

```
数据生成：D = ∪_k Cousins(scene_k, Ω_asset, Ω_bg)
策略训练：θ* = argmax_θ E_(s,a)~D [R(s,a)]
评估：success_rate = P(π_θ 在 real_test 上成功)
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| Cousins(·) | 数字表亲生成函数：保持语义关系、变化物体/背景实例 |
| Ω_asset | 资产库（3000+ 实例，300+ 类别） |
| Ω_bg | 背景环境库（50 个场景，6 种家庭场景类型） |
| π_θ | 策略网络（本文使用 π_0.5 基座微调） |
| scene_k | 第 k 个真实桌面场景的语义布局 |

> 符号与本文保持一致。论文未给出显式的损失函数公式（基于 π_0.5 基座），训练细节为 batch_size=32, 30000 steps。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们要为"把水瓶放到杯子里"这个双臂任务生成训练数据：

**步骤 1 — 资产数字化**
- 输入：一张水瓶的 RGB 照片
- SAM 3 分割 → SAM 3D 重建为 3D mesh → VLM 推断：category="bottle", mass=0.3kg, friction=3（中等摩擦，塑料）
- 接触点推断：检测到近似旋转对称 → Mixed Strategy → 生成 8 个侧面抓取 + 2 个垂直抓取候选
- 过滤后保留 6 个有效抓取候选

**步骤 2 — 桌面表亲**
- 输入：一张真实桌面照片（水瓶 + 杯子 + 鼠标）
- 分割+深度估计 → 匹配资产库：bottle→001_bottle, cup→021_cup, mouse→047_mouse
- 构建支撑图：bottle on table, cup on table, mouse on table
- 表亲变体 1：bottle→071_can, cup→021_cup（背景不变）
- 表亲变体 2：bottle→001_bottle, cup→075_bread, 背景从 kitchen→office

**步骤 3 — 轨迹生成**
- 每个表亲场景下，RoboTwin 2.0 用 Aloha-AgileX 模型收集双臂专家轨迹
- 假设每个场景收集 50 条轨迹，3 个表亲变体 × 50 = 150 条
- 扩展到 50 个任务 × 平均 3 个表亲 × 50 条 = 7,500 条
- 论文实际生成：50 任务 × 平均 ~400 条/任务 = 1,000,000+ 条

**步骤 4 — 策略训练与评估**
- 从 π_0.5 checkpoint 微调，batch_size=32, 30000 steps
- sim-to-real 部署到 ARX AC-One 真实机器人（双臂间距 0.5m）

### 6.1 隐含假设 (Hidden Assumptions)

1. **3D 重建质量足够支撑物理交互**：假设 SAM 3D 重建的 mesh 在碰撞检测和物理模拟中足够准确，但未系统评估重建误差对 sim-to-real 的影响幅度。

2. **VLM 推断的物理属性足够可靠**：假设 VLM 从多视角渲染推断的质量、摩擦系数等参数与实际物理行为一致，但未报告 VLM 推断精度与人工标注的一致性。

3. **数字表亲的语义保持足够好**：假设匹配资产库中的替代物体在功能上与原始物体等价，但对于形状差异大的物体（如圆柱形水瓶 vs 不规则面包），支撑关系可能不准确。

4. **A* 导航在仿真中可行 = 在真实中可行**：导航路径在仿真中确定性 replay，但未评估仿真-真实导航误差累积。
