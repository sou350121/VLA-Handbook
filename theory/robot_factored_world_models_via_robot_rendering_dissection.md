## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 训练/推理 | 职责 |
|------|------|------|-----------|------|
| **动作实现算子 Φ_R** | 原始动作 a_{1:F} + 初始状态 q_0 | 名义轨迹 q_{1:F} | 推理可用 | 用机器人自身控制器和运动学将指令解算为无交互场景下的预期运动 |
| **机器人渲染器 Π_R** | 名义轨迹 q_{1:F} + 相机轨迹 C_{1:F} | 机器人网格 RGB M^{rgb}_{1:F} + 末端深度 D^{eef}_{1:F} | 预处理 | 通过 URDF 将轨迹渲染为相机对齐的机器人几何 |
| **静态场景渲染器 Π_S** | 初始场景 S_0 + 相机轨迹 C_{1:F} | 静态 RGB B^{rgb}_{1:F} + 场景深度 D^{scene}_{1:F} | 预处理 | 提供场景外观、深度和视角信息 |
| **VAE 编码器 ℰ** | 4 路条件流 | 编码向量 c | 训练/推理 | 将各条件流编码为视频 VAE 隐空间表示 |
| **流匹配扩散模型 v_θ** | 噪声隐变量 z_σ + 条件 c + 文本 T | 目标速度 u | 训练/推理 | 预测交互引起的场景变化（残差动力学） |

### 1.2 关键机制 (Key Mechanism)

**核心问题分解**：传统方法把世界模型要学的东西混在一起——既要学"关节指令→机器人运动"的映射（这是机器人特定的），又要学"机器人运动→场景变化"的映射（这是共享的）。本文把前者剥离为固定预处理，只把后者留给学习模型。

**三个动作信号的区分**：

| 信号 | 定义 | 部署可用性 | 是否泄漏交互 | 适合条件化？ |
|------|------|-----------|-------------|-------------|
| Raw Action | 控制器/遥操作器发出的原始指令 | ✅ 可用 | ❌ 不泄漏 | ❌ 绑定特定机器人 |
| **Nominal Trajectory** | 动作经控制器和运动学解算后的预期运动 | ✅ 可用 | ❌ 不泄漏 | ✅ 本文选择 |
| Realized State | 实际执行后记录的机器人状态 | ❌ 推理不可用 | ✅ 已包含接触/顺应/延迟 | ❌ 信息泄漏 |

⚡ **Eureka Moment**：世界模型不应该学习"动作如何变成机器人运动"——这是机器人控制器已经解决的问题。世界模型应该只学习"可见的机器人运动如何引起场景变化"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
min_θ  E[||u - v_θ(z_σ, σ | c, T)||^2]
其中 c = [ℰ(B^{rgb}), ℰ(M^{rgb}), ℰ(D^{scene}), ℰ(D^{eef})]
```

**目标**：用流匹配（flow matching）训练一个残差视频扩散模型，使其在给定静态场景上下文和渲染机器人几何的条件下，预测交互引起的场景变化。

**公式分解**：

```
(1) 动作实现:    q_{1:F} = Φ_R(a_{1:F}; q_0)
(2) 机器人渲染:  (M^{rgb}_{1:F}, D^{eef}_{1:F}) = Π_R(q_{1:F}; C_{1:F})
(3) 场景渲染:    (B^{rgb}_{1:F}, D^{scene}_{1:F}) = Π_S(S_0; C_{1:F})
(4) 条件编码:    c = [ℰ(B^{rgb}), ℰ(M^{rgb}), ℰ(D^{scene}), ℰ(D^{eef})]
(5) 流匹配损失:  L = E[||u - v_θ(z_σ, σ | c, T)||^2]
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| a_{1:F} | 原始动作序列（F 帧） |
| q_{1:F} | 名义轨迹（控制器解算后，无场景交互） |
| Φ_R | 动作实现算子（机器人特定） |
| Π_R | 机器人渲染算子（URDF → 相机对齐几何） |
| Π_S | 静态场景渲染算子 |
| C_{1:F} | 相机轨迹 |
| M^{rgb} | 机器人网格 RGB 视频 |
| D^{eef} | 末端执行器深度 |
| B^{rgb} | 静态场景 RGB |
| D^{scene} | 场景深度 |
| ℰ | 预训练视频 VAE 编码器 |
| v_θ | 流匹配网络（预测速度场） |
| T | 文本提示（仅含场景上下文，不含动作描述） |

> 符号与本文保持一致。流匹配目标 u = ε - z_0 是标准设定，详见参考 [48, 49]。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2D 场景：

**设定**：
- 机器人从初始关节角 q_0 = [0, 0, 0] 开始
- 收到动作指令 a = [0.1, -0.05, 0.02]（关节空间指令）
- 预测帧数 F = 3

**Step 1: 动作实现**
```
Φ_R(a; q_0) → q_{1:3} = [
  [0.08, -0.04, 0.02],   // 第1帧（控制器跟踪有延迟）
  [0.15, -0.08, 0.04],   // 第2帧
  [0.21, -0.10, 0.05]    // 第3帧
]
```
注意：名义轨迹 ≠ 原始动作（控制器延迟/运动学约束造成的 action-realization gap）。

**Step 2: 渲染**
```
Π_R(q_{1:3}; C) → M^{rgb}_{1:3} (480×832 RGB), D^{eef}_{1:3} (480×832 depth)
Π_S(S_0; C)     → B^{rgb}_{1:3} (重复初始帧), D^{scene}_{1:3}
```

**Step 3: 编码与扩散**
```
c = [ℰ(B^{rgb}), ℰ(M^{rgb}), ℰ(D^{scene}), ℰ(D^{eef})]
// 4 路条件，每路经 VAE 编码后拼接

// 推理时：
z_T ~ N(0, I)  // 从纯噪声开始
逐步去噪 z_T → z_0  // 用 v_θ 预测速度场
解码 z_0 → V_{1:3}  // 得到 3 帧预测视频
```

**直觉**：如果末端深度 D^{eef} 显示机器人在物体前方 5cm（非接触），模型应预测物体不动；如果 D^{eef} 显示末端与物体深度差 ≈ 0（接触），模型应预测物体被推动。这就是深度对的作用——区分"图像上重叠"和"真实接触"。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 说明 |
|------|----------|------|
| 推理分辨率 | 480×832 | 与 Wan 2.1 14B 训练分辨率一致 |
| 预测帧数 | 81 帧 @ 16fps | 约 5 秒预测 horizon |
| 骨干模型 | Wan 2.1 14B / SVD 1.5B | 两种规模均有实验 |
| 条件流数量 | 4 路（静态RGB + 机器人RGB + 场景深度 + 末端深度） | 均通过 VAE 编码后拼接 |
| 渲染开销 | 预处理阶段 | URDF 渲染在推理前完成，不增加模型推理延迟 |
| 部署前提 | 已知 URDF + 手眼标定 | 新机器人需重新标定，但无需重新训练模型 |
| 动态相机 | 需要完整 3D 场景表示 | 仿真中可用，真实场景需 feedforward 3D 重建 |

**工程含义**：
- **模块边界清晰**：动作实现（Φ_R）和渲染（Π_R）是固定预处理，不纳入训练图，降低了模型复杂度
- **跨部署一致性**：同一模型可在不同机器人上运行，只需更换 URDF 和标定参数
- **内存瓶颈**：4 路条件流 × 81 帧 × VAE 编码 → 条件张量较大，14B 模型需要多 GPU 或高显存环境
- **量化误差**：深度信号的精度直接影响接触判断，低比特量化可能削弱深度条件化的效果

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **动作跟随**：改变渲染的名义轨迹，模型预测的 scene response 随之改变（§4.4 图 5）
- **零样本跨机器人泛化**：xArm 6 + Inspire F1 组合从未在训练中见过，仍能生成合理的场景响应（§4.4 图 6）
- **双臂场景**：单个机械臂训练的模型可处理双臂场景（项目页展示）
- **人类演示→机器人视频**：DexYCB 人类手部动作 retarget 到机器人后，可生成机器人交互视频（§4.5）

### 不能做什么 / 局限
- **需要 URDF 和标定**：每个新机器人需要已知的 URDF 文件和相机-机器人手眼标定（§5 局限性）
- **动态相机需要完整 3D 场景**：真实世界中静态场景表示只能部分观测，feedforward 3D 重建有外观差距（§5）
- **失败模式覆盖不足**：DROID 数据以成功轨迹为主，模型少见抓取失败、打滑、误接触等场景（§5）
- **深度渲染仅限末端**：只渲染末端执行器深度，如果交互发生在机械臂其他部位（如碰撞），深度信号无法提供几何线索

### 6.1 隐含假设 (Hidden Assumptions)

1. **URDF 几何足够代表真实外观**：渲染的网格 RGB 假设与真实相机视图在外观上足够接近。如果渲染-真实 gap 大（如材质反射、纹理细节），VAE 编码可能无法桥接。
2. **名义轨迹可精确获取**：假设在推理时可以通过无场景的 shadow rollout 获得名义轨迹。在真实部署中，这需要提前运行一次仿真，增加了推理延迟。
3. **末端深度可获取**：假设已知末端执行器的精确深度。如果从传感器估计，噪声会直接影响接触判断。
4. **静态场景在预测期间不变**：除了机器人交互引起的变化，场景本身是静态的。对于有其他人/动物/移动物体的场景，这个假设不成立。
