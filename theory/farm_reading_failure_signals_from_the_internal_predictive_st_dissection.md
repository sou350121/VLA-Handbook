💡 **X-Ray 开场**

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模組 | 輸入 | 輸出 | 是否訓練 | 頻率/時序 |
|------|------|------|----------|-----------|
| V-JEPA2 encoder | 观测历史 | world-state tokens | ❄️ 冻结 | 每 replanning step |
| VLA-JEPA predictor (12 层) | tokens + 任务条件化 latent-action tokens | action-conditioned 预测状态 | ❄️ 冻结 | 每 replanning step |
| WM-state 抽取 | 第 12 层输出（归一化前、去 action tokens） | H ∈ R^{768×1024} | 无参数 | 每 replanning step |
| FARM readout | H | z^F ∈ R^{32} → step 分数 s_t | ✅ 仅此 33,985 参数 | 每 replanning step |
| 因果风险聚合 | s_t 序列 | q_t = max(τ≤t) s_τ | 无参数 | 递归，O(1) 存储 |

关键点：**梯度在 WM state 处被 `sg[·]`（stop-gradient）切断**，所以读出头永远不会反向影响预测骨干——这让实验变成一个「表征探针（probing）」而非「联合训练」。

### 1.2 关键机制 (Key Mechanism)

- **为什么抽「归一化前」的第 12 层输出**：作者去掉预测器最后一步的 output projection 与 LayerNorm，拿到尚未被任务输出逻辑「压扁」的原始预测状态；同时剔除 action-conditioning tokens，只留 world-state tokens（768 个，宽度 1024）。
- **为什么读出头要「窄」**：#1.1 的读出头故意把 768×1024 压到 32 维，再 attention-pool 成 32 维向量。目的是**限制容量**——如果读出头能重建一个全新的动力学模型，就无法证明「信息本来就在冻结状态里」了。32 维瓶颈是方法论上的证据约束，不是省参数。
- **attention pooling 只在单步内**：attention 不跨 rollout 时间，保证每个 step 的分数只依赖当前步的 token 组合；跨时间的聚合交给 max 风险（§III-E），从而天然满足因果性。
- **任务均衡采样**：层级均匀采样（任务 → 轨迹 → 步），使长 rollout 不会因步数多而主导损失，且每个任务总权重相等。

⚡ **Eureka Moment**：**失败信号不需要被「引入」，它已经躺在冻结世界模型的预测状态里——你只需要一个足够小、无法作弊的读出头把它解码出来。** 换句话说，「监控」这件事可以从「训练一个模块」降级为「读一个现成表征」。

### 1.3 信息流/架构图 (Flow / Diagram)

```
观测历史 x_{≤t} ──► [V-JEPA2 Encoder ❄️] ──► world-state tokens
                                              │
任务条件 + latent-action tokens ──────────────┤
                                              ▼
                            [VLA-JEPA Predictor ×12 ❄️]
                                              │  (取第12层, 归一化前)
                                              ▼
                        切掉 action tokens ──► H^{WM} ∈ R^{768×1024}
                                              │  sg[·] 切断梯度
                                              ▼
   ┌──────────── FARM Readout (θ, 33,985 params) ────────────┐
   │  u_j = GELU(LN(W_p h_j + b_p))      # 共享投影 → 32维      │
   │  α_j = softmax_j(aᵀ u_j); r = Σ α_j u_j   # attention pool │
   │  z^F = GELU(W_f r + b_f)            # 32维瓶颈            │
   │  s_t = σ(w_oᵀ z^F + b_o)            # step 失败分数       │
   └──────────────────────────────────────────────────────────┘
                                              │
                                              ▼
                        q_t = max(q_{t-1}, s_t)   # 因果轨迹风险
```

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
s_t = σ( w_oᵀ · GELU( W_f · Σ_j α_j · GELU(LN(W_p h_j^{WM} + b_p)) + b_f ) + b_o )
风险：q_t = max_{τ≤t} s_τ      （只聚合已观测到的分数 → 因果）
```

**目标**：把冻结状态 H^{WM} 映射成逐步失败分数，再聚合成轨迹风险。
**定义**：

```
H^{WM}_{i,t} = sg[ F_φ(x_{i,≤t}) ]        # φ 冻结，从不用失败标签更新
s_{i,t}      = G_θ(H^{WM}_{i,t}) ∈ [0,1]  # θ 是唯一可训练参数
ℒ_FARM(θ)    = 𝔼_{k,i,t}[ ℓ_BCE(s_{i,t}, y_i) ]   # 任务均衡 BCE
ℓ_BCE(s,y)   = -y·log s - (1-y)·log(1-s)
```

**变量说明**：

| 符号 | 含义 | 取值/维度 |
|------|------|-----------|
| φ | 预训练 WM-state 抽取器（V-JEPA2 + VLA-JEPA） | 全冻结 |
| H^{WM} | 归一化前的预测状态 | 768 × 1024 |
| z^F | 失败感知表征 | 32 |
| W_p, a, W_f, w_o | 读出头参数 | 32,800 / 32 / 1,056 / 33 |
| y_i | 轨迹结局（1=失败，0=成功） | 每条轨迹一个标签，广播到所有有效 step |
| q_t | 因果轨迹风险 | 标量，递归 max |

**直觉**：注意力池化让读出头「按执行状态挑重点 token」——同一个读出头在不同时刻可以关注不同的预测 token；而 32 维瓶颈 + stop-gradient 共同保证：如果解码成功，那一定是状态里本来就有，而不是读出头现学出来的。

> 符号与本文保持一致：H^{WM} 即论文的 WM state；q_t 即 causal trajectory risk。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一条「把杯子放进抽屉」的失败轨迹，共 T=100 个 replanning step：

1. 每步取 H^{WM}（768×1024）→ 投影成 768 个 32 维向量 → attention 池化 → z^F(32) → s_t。
2. 前 70 步一切正常：s_t 在 0.05~0.15 之间抖动（论文 Fig.4 显示早期分低）。
3. 第 85 步杯子滑落：s_85 = 0.82；第 90 步彻底失败：s_90 = 0.94。
4. 因果风险递归更新：
   ```
   q_{84} = 0.14
   q_{85} = max(0.14, 0.82) = 0.82
   q_{90} = max(0.82, 0.94) = 0.94   （单调不减）
   ```
5. 部署端可设阈值 τ=0.7：q_t > τ → 请求人工接管/触发恢复。

**部分历史实验（论文 Fig.5）** 证明上面这个「边走边判」的思路成立：只观测 25% 的 horizon，池化 AUROC/AUPRC 已达 75.07/80.75；观测到 75% 时达 81.63/85.53，距离全历史仅差 1.78/1.27 点——**无需为前缀单独重训**。

## 4. 工程视角 (Engineering View)

| 指标 | 数值 | 工程含义 |
|------|------|----------|
| 读出头延迟 | 0.2256 ms 均值，0.2393 ms P99 | 世界模型 state 一旦就绪，额外开销可忽略 |
| 读出头吞吐 | 4,432.8 steps/s（RTX 5090） | 远超典型控制频率（10–100 Hz） |
| 读出头参数量 | 33,985 | 可整机置于 CPU 或共享 GPU 上，无显存压力 |
| 风险状态存储 | 1 个标量 q_t | 适合长时并行 rollout |
| 测量边界 | 不含 WM 推理/特征提取/传输/控制 | **真实端到端延迟取决于骨干，而非本例** |

**工程含义提炼**：
- 监控频率不应成为瓶颈——瓶颈在世界模型推理本身。FARM 让「加监控」几乎免费（前提是 state 已算出）。
- 递归 max 聚合意味着可以**在线、逐 step** 决策，不需要等 rollout 结束，适合 real-time 接管门控。
- 需注意 P99 与均值接近（0.2393 vs 0.2256 ms），抖动小，对周期性控制友好。
- 部署约束：必须能访问世界模型**内部 state**（README 明确写「backbone 特征提取在包边界之外」），这对闭源策略/仅提供 API 的 VLA 是个硬门槛。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- 多任务模拟下稳定判别成功/失败，且超过所有 15 个匹配基线（Seen 场景）。
- 跨策略/跨平台零样本迁移：四个真实设置中 FARM-Expanded 均优于 FARM-Core。
- 只更新 33,985 参数即可「读出头适配」吸收目标域残差偏移，骨干完全不动。
- 从部分因果历史中提前判别（25% 历史即达 75.07 AUROC）。

**不能做什么 / 已知失败模式**：
- **零样本迁移并非一致**：strict-Unseen 上，STAC-Single（任务无关的动作一致性分数）排名第一，FARM 只是高于 SAFE-MLP/LSTM——任务语义迁移仍是最难的。
- **必须能访问内部 state**：只有闭源 API 的策略无法使用。
- **依赖标签**：训练/适配都需要带成功/失败标签的轨迹。
- **读出头绑定特定世界模型**：本文只验证了 VLA-JEPA 的预测状态，未证明对其他 world model 同样成立（待外部复现）。
- **实验域仍以桌面操作/抓取为主**，未见移动/双臂/人形验证，不要外推泛化性。
- **未闭环到控制**：论文只做「监控评分」，如何把 q_t 接到干预/恢复策略是 future work。

### 6.1 隐含假设 (Hidden Assumptions)

- **假设「失败信息在表征里的可解码性」≈「部署可用性」**：高 AUROC 不等于下游接管策略能提升任务成功率；论文未做闭环实验。
- **假设轨迹级标签可广播到所有 step**：每条轨迹只有一个 y_i，若一条轨迹「早期失败、后期偶然成功」，标注会噪声化。作者用 max 聚合来缓解，但未量化这类「混合结局」轨迹占比。
- **假设感知观察（视觉）足以定义失败**：失败判别完全基于视觉世界模型状态，未引入力/触觉——对接触密集任务（插入、抓取）可能是盲区。
- **假设冻结骨干的 state 接口稳定**：跨机器人迁移时相机、采样率、历史长度都变了（SO-101 用 10 Hz 八帧双相机、Franka 用 task-specific horizon），但作者未系统分析这些协议差异对读数的影响。
- **统计口径**：主要结果跨种子 {5,9,11} 平均，但主表未见置信区间/显著性检验，个体差异需谨慎解读。
