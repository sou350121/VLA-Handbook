💡 **X-Ray 开场**
现有世界动作模型（WAM）面临一个根本性困境：高效方法只关注最近几帧的滑动窗口，在非马尔可夫任务中"失忆"；而保留全历史 KV 缓存的方法又随着轨迹长度线性膨胀，延迟和显存不可承受。MemoryWAM 受人类认知心理学启发——人脑不是简单记录所有经历，而是用短期记忆处理当下、用锚点帧记住事件边界、用摘要痕迹压缩长期历史——将这一机制工程化为三种记忆组件的混合注意力，在 RMBench 9 个长视界双臂操控任务上达到 83.0% 平均成功率（比全历史方法高 4.8%），同时推理开销降低 15 倍。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 维度 | π0.5 / FastWAM (滑动窗口) | LingBot-VA (全历史) | MemoryWAM (混合记忆) |
|------|---------------------------|---------------------|----------------------|
| 记忆策略 | 固定大小近期窗口 | 全历史 KV 缓存 | 滑动窗口 + 锚帧 + gist token |
| 推理复杂度 | O(1)（常数窗口） | O(N)（线性增长） | O(N/d)，d=15 |
| GPU 显存增长 | 常数 | 线性 | O(N/d) |
| 非马尔可夫能力 | 弱（超出窗口即失忆） | 强（完整历史） | 强（压缩历史） |
| 推理延迟 | 低 | 高（长轨迹时不可接受） | 中等偏低 |
| RMBench 平均成功率 | 10.4% | 78.2% | **83.0%** |
| 推理时视频生成 | 不需要 | 不需要 | 不需要 |
| 模型参数量 | ~5B (视频 DiT) | ~6B | ~6B (视频 DiT 5B + 动作 DiT 1B) |

### 1.2 关键机制 (Key Mechanism)

MemoryWAM 采用 **MoT (Mixture-of-Transformers)** 双分支架构：

- **视频 DiT（Φv）**：基于预训练 Wan2.2-TI2V-5B，维护视频侧 KV 缓存，负责视觉动力学表征
- **动作 DiT（Φa）**：独立 1B 参数模型（通过插值视频 DiT 权重初始化），以视频缓存为条件生成动作块

**训练时**：视频预测（扩散去噪）提供密集的动力学监督信号。
**推理时**：跳过昂贵的视频生成，仅用视频 DiT 前向一次更新 KV 缓存，动作 DiT 直接预测动作。

⚡ **Eureka Moment**：长期历史不需要保留完整的视觉 token——每帧只需 8 个可学习的 gist token（压缩率 15×），就能在动作 DiT 的注意力中检索到足够的长期上下文，同时把 KV 缓存大小从 O(N×L) 压到 O(N×M)，其中 M=8 ≪ L=120。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
C_≤t^v = C_short^v ∪ C_anchor^v ∪ C_gist^v
|C_gist^v| = O(N·M) = O(N·L/d)  where d = L/M = 15
```

**目标**：在保持长期上下文可检索的前提下，将 KV 缓存大小和注意力计算复杂度从 O(N·L) 降至 O(N·L/d)。

**变量说明**：

| 符号 | 含义 | 值 |
|------|------|-----|
| N | 轨迹长度（历史帧数） | 可变 |
| L | 每帧视觉 token 数 | 120 |
| M | 每帧 gist token 数 | 8 |
| d | 压缩率 L/M | 15 |
| N_recent | 滑动窗口大小 | 4 |
| N_init | 初始锚帧数 | 2 |

**直觉**：人类记忆不会记住每个细节——我们记住最近发生的事（短期）、事件开始时的场景（锚点）、以及一段经历的"摘要"（gist）。MemoryWAM 把这个机制精确工程化：近期帧保留完整 token（高保真控制），初始帧保留完整 token（任务 grounding），其余历史只保留 8 个 gist token（压缩摘要）。动作 DiT 的查询向量同时 attend 到这三类记忆，实现"既要细节又要全局"。

> 符号与本文保持一致：C^v 表示视频侧 KV 缓存，下标 short/anchor/gist 对应三类记忆组件。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 100 步的长视界操控任务（如 RMBench 的 Press Button），每步产生 1 帧观测：

**全历史方法（LingBot-VA）**：
- 缓存 token 数 = 100 × 120 = 12,000 tokens
- 注意力计算量 ≈ O(12,000²) = 1.44×10⁸ 次 pairwise 计算
- 随轨迹增长到 1600 帧时：1600 × 120 = 192,000 tokens → 3.69×10¹⁰ 次计算

**MemoryWAM 混合记忆**：
- 近期帧：4 × 120 = 480 tokens（完整）
- 锚帧：2 × 120 = 240 tokens（完整）
- Gist 记忆：(100 - 6) × 8 = 752 tokens（压缩）
- 总缓存 = 480 + 240 + 752 = **1,472 tokens**
- 注意力计算量 ≈ O(1,472²) = 2.17×10⁶ 次 pairwise 计算
- **压缩比**：12,000 / 1,472 ≈ **8.15×**（短轨迹）
- 1600 帧时：总缓存 ≈ 480 + 240 + 15,872 = **16,592 tokens**，vs 全历史 192,000 → **11.6× 压缩**

**关键观察**：随着轨迹变长，压缩比趋近 d=15（因为近期帧和锚帧的常数开销被稀释）。

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/约束 | 含义 |
|----------|-----------|------|
| 模型总参数 | ~6B | 视频 DiT 5B + 动作 DiT 1B |
| 视频 DiT 深度 | 30 blocks, hidden 3072 | 与 Wan2.2-TI2V-5B 一致 |
| 动作 DiT 深度 | 30 blocks, hidden 1024 | 通过插值视频 DiT 权重初始化 |
| 动作 horizon | h=16 steps | 帧 stride=4 × 时序 VAE stride=4 |
| 训练 GPU | 8×GPU, per-GPU batch=1 | 总 batch=8 |
| 推理视频生成 | 不需要 | 训练时有视频监督，推理时仅用缓存特征 |
| 推理延迟（1600帧） | 低于 RNN/TTT 基线 | 论文图4显示，即使1600帧仍比RNN和TTT更高效 |
| 输入 mosaic | 384×320 | 头部 256×320 + 双腕各 128×160 拼接 |
| 机器人状态维度 | 14-dim（双臂关节向量） | 投影到 text token 维度后拼接到动作 expert 的 text context |

**工程含义**：
- 训练时需要 8 GPU 集群，但推理时单 GPU 可行（无需视频去噪）
- 动作 horizon 为 16 步意味着每帧 latent 对应一个 16 步动作块，控制频率约 5Hz（假设 80Hz 关节控制）
- 混合记忆将长轨迹推理延迟从"不可接受"（LingBot-VA 在 Shell Game 中因高延迟错过杯子交换）降到"可用"水平

## 5. 数据与评测 (Data & Eval)

### 数据集
- **RMBench**：长视界、记忆依赖型双臂操控仿真基准
- 9 个任务，覆盖不同 Task Memory Complexity 等级
- 每个任务 50 个专家演示（50 demonstrations/task）

### 评测设置
- 每个任务 100 次 rollout，报告成功率
- 对比 3 类基线：直接观测→动作（π0.5）、滑动窗口 WAM（FastWAM）、全历史 WAM（LingBot-VA）

### 核心结果（RMBench Table 1）

| 任务 | π0.5 | FastWAM | LingBot-VA | MemoryWAM |
|------|------|---------|------------|-----------|
| Observe and Pick Up | 9% | 0% | 13% | **27%** |
| Rearrange Blocks | 13% | 0% | 100% | **100%** |
| Put Back Block | 11% | 0% | 100% | **100%** |
| Swap Blocks | 24% | 0% | 99% | **100%** |
| Swap T | 15% | 7% | 88% | **94%** |
| Battery Try | 16% | 20% | 41% | **41%** |
| Blocks Ranking Try | 6% | 26% | 100% | **100%** |
| Cover Blocks | 0% | 0% | 79% | **98%** |
| Press Button | 0% | 0% | 84% | **87%** |
| **Average** | **10.4%** | **5.9%** | **78.2%** | **83.0%** |

**关键发现**：
- MemoryWAM 在每个任务上都优于 LingBot-VA，平均高 4.8 个百分点
- 在 Cover Blocks 上差距最大：79% → 98%（+19%），说明压缩记忆比全历史 KV 缓存更利于检索任务相关信息
- 作者分析：保留全部历史 token 不总是最优——密集历史可能引入冗余信息，增加检索任务相关信号的难度

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能力
- ✅ 非马尔可夫操控：能记住窗口外的关键信息（如被遮挡的目标位置）
- ✅ 长视界任务：在 1600 帧轨迹上仍保持低延迟
- ✅ 实时性：推理延迟足够低，能在 Shell Game 中捕捉杯子交换（LingBot-VA 因延迟错过）
- ✅ 仿真到现实：在 ARX 双臂机器人上验证了两个真实任务

### 失败模式
- ❌ **语义理解有限**：继承视频扩散模型的局限，缺乏显式的语义推理能力（论文 §5 自认）
- ❌ **训练成本高**：需要 8 GPU + 预训练 Wan2.2 权重，门槛较高
- ❌ **单一机器人平台验证**：真实实验仅在 ARX 双臂机器人上完成，泛化到其他平台（移动/人形）未验证
- ❌ **50 演示/task 的数据需求**：虽然比一些方法少，但对零样本场景仍不够
- ❌ **任务特定超参**：N_recent=4, N_init=2, M=8 是人工设定的，不同任务可能需要不同配置

### 6.1 隐含假设 (Hidden Assumptions)

1. **事件边界可识别**：假设任务初始帧天然就是最有信息量的锚点。但在连续多阶段任务中，中间阶段转换可能同样重要
2. **gist token 足以编码长期依赖**：8 个 token 压缩 120 个视觉 token（15×），对于简单任务足够，但复杂场景可能需要更多容量
3. **预训练视频 DiT 的动力学表征足够通用**：Wan2.2 在通用视频上预训练，其动力学表征是否最优适配机器人操控数据，未做消融
4. **训练时注意力 mask = 推理时 KV 缓存**：训练时精确模拟推理时的可见性，这个假设在理论上合理，但实际中 autoregressive 误差累积可能有差异

**面试 Tip**：当被问到"为什么不用 RNN/TTT 做长期记忆"时，可以回答：RNN 和 TTT 确实能做到 O(1) 复杂度，但论文实验（§4.2 图4c）显示它们在 Press Button 任务上成功率低于混合记忆——过度压缩的状态表示丢失了任务相关的细节信息。混合记忆的优势在于：它不是用一个固定大小的状态向量压缩所有历史，而是有选择地保留关键帧的完整 token + 其余帧的轻量摘要，在信息保留和效率之间找到了更好的平衡点。
