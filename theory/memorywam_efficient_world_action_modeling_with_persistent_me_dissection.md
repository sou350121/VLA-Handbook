💡 **X-Ray 开场**
机器人操作需要记住"之前发生了什么"——但传统方法要么只看最近几帧（遗忘关键历史），要么缓存所有历史帧（推理越来越慢）。MemoryWAM 受人类记忆启发：短期记忆保持最近 4 帧高清，事件边界保留初始 2 帧锚点，长期历史压缩为每帧仅 8 个 gist token（压缩比 15×）。结果：在 RMBench 9 个记忆依赖任务上平均比 LingBot-VA 高 4.8%，且推理延迟显著更低。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 训练时 | 推理时 | 内存占用 |
|------|------|------|--------|--------|----------|
| 3D Causal VAE | 384×320 拼接图像 | z_t (48-channel latent) | 编码 | 编码 | 固定 |
| Video DiT (Φ_v) | z_t + 任务指令 l + C_<t | C_t^v (KV cache) | 视频预测损失 | 仅前向更新 cache | 混合记忆 |
| Action DiT (Φ_a) | 噪声 action tokens + C_≤t^v | a_{t:t+h-1} (16步) | 动作预测损失 | 去噪生成 | 复用 video cache |
| Gist Tokens | 每帧 L=120 visual tokens | M=8 gist tokens | 学习压缩 | 持久缓存 | O(N/d) |

**关键设计决策**：
- Video DiT 和 Action DiT 采用 MoT（Mixture-of-Transformers）架构，两个独立但深度对称的 DiT（各 30 层）
- 训练时视频预测提供密集动力学监督，推理时**不需要视频生成**——这是与早期 WAM 的本质区别
- Action DiT 通过插值 Video DiT 权重初始化（沿 hidden dim 插值），加速收敛

### 1.2 关键机制 (Key Mechanism)

MemoryWAM 的核心创新在于**混合记忆**——它不是一种记忆，而是三种记忆的组合：

1. **短期记忆（Sliding Window）**：最近 N_recent=4 帧的完整 video latent。负责快速变化的交互线索（物体运动、接触状态、手-物构型）。
2. **事件边界记忆（Anchor Frames）**：任务初始 N_init=2 帧的完整 video latent。负责锚定任务指令和初始场景状态（后续可能被遮挡或移出视野）。
3. **长期记忆（Gist Tokens）**：每帧仅 M=8 个可学习 token，压缩 L=120 个 visual token。负责长期历史摘要。后续帧不直接 attend 到原始帧，而是 attend 到其 gist token。

⚡ **Eureka Moment**：人类记忆不是单一存储——短期记忆管当下，事件边界记忆管关键时刻，摘要记忆管长期历史。MemoryWAM 将这一认知原理工程化：用 15× 压缩的 gist token 替代全历史 KV cache，同时保留关键帧的完整信息，在效率和记忆质量之间找到了比 RNN/TTT/全注意力更好的 Pareto 前沿。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
C_≤t^v = C_short^v ∪ C_anchor^v ∪ C_gist^v
复杂度: O(N) → O(N/d), 其中 d = L/M = 120/8 = 15
```

**目标**：在保持策略性能不降的前提下，将序列长度依赖的推理复杂度从 O(N) 压缩到 O(N/d)。

**核心方程**：

```
C_t^v = Φ_v(z_t, l; C_<t)          # Video DiT 更新 KV cache
a_{t:t+h-1} = Φ_a(x_τ^a, l; C_≤t^v)  # Action DiT 条件于混合记忆生成动作
C_≤t^v = C_short^v ∪ C_anchor^v ∪ C_gist^v  # 混合记忆组合
|C_gist^v| = O(N·M) = O(N·L/d)     # Gist 记忆大小，d=L/M=15
```

**变量说明**：

| 符号 | 含义 | 数值 |
|------|------|------|
| z_t | 第 t 帧的 video latent | 48-channel |
| L | 每帧 visual token 数 | 120 |
| M | 每帧 gist token 数 | 8 |
| d | 压缩比 = L/M | 15 |
| N_recent | 短期滑动窗口大小 | 4 |
| N_init | 锚帧数量 | 2 |
| h | 动作 horizon | 16 步 |
| τ | 扩散去噪时间步 | 1000 steps (训练) |

**直觉**：与其缓存所有历史帧的 120 个 token（每帧），MemoryWAM 只保留最近 4 帧和初始 2 帧的完整信息，其余所有历史帧各压缩为 8 个 gist token。随着轨迹增长，完整帧数恒定（6 帧），gist token 数线性增长但斜率降低 15 倍。

> 符号与本文/相关文档保持一致：C 表示 KV cache，上标 v 表示 video 侧，下标 short/anchor/gist 表示三种记忆类型。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 50 帧的长视界操作任务（约 3 轮交互，每轮 ~16 步）：

**Full Attention（LingBot-VA 方式）**：
```
总 token 数 = 50 帧 × 120 token/帧 = 6,000 tokens
KV cache 存储 = 6,000 × hidden_dim × num_layers ≈ 6,000 × 3072 × 30 ≈ 553M 参数当量
注意力计算 = O(6,000²) = 36M 次 pairwise 操作
```

**MemoryWAM 混合记忆**：
```
短期记忆 = 4 帧 × 120 token = 480 tokens（完整）
锚帧记忆 = 2 帧 × 120 token = 240 tokens（完整）
长期记忆 = (50-6) 帧 × 8 gist token = 352 tokens（压缩）
总 token 数 = 480 + 240 + 352 = 1,072 tokens
KV cache 存储 ≈ 1,072 × 3072 × 30 ≈ 99M 参数当量
注意力计算 = O(1,072²) = 1.15M 次 pairwise 操作

压缩比 = 6,000 / 1,072 ≈ 5.6× 总 token 减少
注意力计算减少 = 36M / 1.15M ≈ 31×
```

**关键洞察**：虽然长期记忆部分压缩了 15 倍，但总压缩比是 5.6 倍——因为近期帧和锚帧的完整信息仍占一部分。但这已经足够让注意力计算从 36M 降到 1.15M，解释了为什么实验中看到显著的延迟下降。

## 4. 工程视角 (Engineering View)

| 维度 | Full Attention (LingBot-VA) | MemoryWAM | 工程含义 |
|------|---------------------------|-----------|----------|
| 推理延迟增长 | 线性 O(N) | 次线性 O(N/d) | 长任务下 MemoryWAM 不会越来越慢 |
| GPU 内存增长 | 线性 O(N) | 次线性 O(N/d) | 可部署在固定显存的边缘设备 |
| 视频生成 | 训练时仅 | 训练时仅 | 推理时无需扩散去噪视频，比 DreamZero 快 |
| 模型大小 | ~6B | ~6B | Video DiT 5B + Action DiT 1B |
| 控制频率 | 取决于推理延迟 | 更低延迟 → 更高控制频率 | Shell Game 中 LingBot-VA 因延迟错过杯子交换 |
| 训练 batch | 8 GPU × 1/gpu | 8 GPU × 1/gpu | 受 DiT 显存限制，batch 较小 |

**部署约束**：
- 需要预训练 Wan2.2-TI2V-5B video DiT（开源可用）
- 推理时至少需要能容纳 6B 参数的显存（FP16 ≈ 12GB）
- 三相机拼接输入（256×320 头部 + 2×128×160 手腕）需要特定的相机布局
- 动作空间 14 维（双臂），迁移到单臂需要调整

**Trade-off 分析**：
- Gist token 从 8 增加到 16：可能提升复杂任务性能，但压缩比从 15× 降到 7.5×
- 滑动窗口从 4 增加到 8：更好的短期上下文，但短期记忆翻倍
- 锚帧从 2 增加到 4：更多事件边界信息，但增加了固定开销

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **非马尔可夫决策**：Press Button 任务需要记住之前按了几次，MemoryWAM 达到 87%（与全注意力持平）
- **长期遮挡恢复**：初始场景信息保存在锚帧中，即使后续被遮挡仍可检索
- **实时操作**：低延迟使 Shell Game 中能及时响应杯子交换（LingBot-VA 因延迟失败）
- **多相机融合**：三相机拼接编码有效利用 Wan2.2 的视频先验

### 不能做什么
- **复杂语义推理**：论文明确承认继承了视频扩散模型在语义理解上的局限
- **超出训练分布的泛化**：实验仅在桌面双臂操作验证，未测试移动/人形平台
- **超长轨迹的精细记忆**：gist token 仅 8 个/帧，对于需要记住大量细节的任务可能信息瓶颈

### 6.1 隐含假设 (Hidden Assumptions)

1. **事件边界 = 任务初始帧**：假设任务开始时 2 帧包含了所有关键边界信息。但对于多阶段任务（如先取 A 再取 B），中间阶段的边界可能同样重要。
2. **gist token 压缩足够**：120→8 的压缩比在 RMBench 上有效，但对于需要记住物体精确位置/颜色/形状的任务，8 个 token 可能不够。
3. **相机布局固定**：三相机拼接方式（头部 256×320 + 双腕各 128×160）硬编码到系统中，迁移到新硬件需要重新设计。
4. **50 个演示足够**：RMBench 每个任务仅 50 个演示训练，这在小样本设定下有效，但在更复杂任务中可能需要更多数据。
5. **Wan2.2 视频先验可迁移**：依赖 Wan2.2-TI2V-5B 的视频生成先验，但该模型训练于自然视频而非机器人视频，存在 domain gap。
