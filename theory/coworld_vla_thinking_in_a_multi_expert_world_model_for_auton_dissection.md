## 1. 核心架构/方法总览 (Overview / Architecture)

CoWorld-VLA 采用三阶段训练管线：

```
Stage 1: 视频生成器预训练 (Wan2.2-5B)
         └─ 动作条件化世界模型，学习未来场景演化
              ↓
Stage 2: 多专家表征学习 (Qwen3-VL-2B)
         └─ 4种专家token对齐：JEPA语义 / VGGT几何 / Wan动态 / 轨迹回归
              ↓
Stage 3: 扩散融合规划器 (HMEF)
         └─ 专家token → 轨迹条件 → 联合去噪 → 连续自车轨迹
```

### 1.2 关键机制 (Key Mechanism)

**为什么拆成 4 种专家 token？**

作者的核心观察：自动驾驶推理需要四类互补知识——
1. **语义交互**（其他交通参与者的意图）→ JEPA 蒸馏
2. **几何结构**（道路布局、空间约束）→ VGGT 对齐
3. **动态演化**（未来场景时序变化）→ Wan 视频模型条件
4. **行为目标**（自车轨迹先验）→ 轨迹回归监督

单一世界表征无法同时捕获这四类信息（论文 §1 引用多篇文献支撑此论点）。多专家 token 的设计让每种知识有专门的"表达通道"，在 VLM 隐空间中并行推理。

**为什么用扩散规划器而不是直接回归？**

扩散模型在轨迹生成上的优势已被 DiffusionDrive 等工作验证（多模态分布建模能力）。HMEF 的创新在于：将 4 种专家 token 作为条件嵌入到联合去噪过程中（两流架构：干净场景流 + 噪声动作流），而非事后融合。

⚡ **Eureka Moment**：世界模型不应只是训练时的辅助监督信号——它的表征应该直接作为推理时轨迹生成的条件，通过多专家 token 在 VLM 隐空间中形成"Latent Chain-of-Thought"。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的十字路口场景：

**输入**：
- o_t: 前视图像（H=256, W=256）
- c_t: 导航指令"右转" + 历史 5 帧位姿 + 当前速度 5 m/s + 加速度 0
- 规划 horizon T = 8 步（4 秒，2 Hz）

**Stage 2 推理**（VLM 前向传播）：
```
H_ctx = VLM(o_t, c_t)                          → 场景上下文
H_sem = VLM(o_t, c_t, t_sem)                   → 语义token: "右侧有车接近"
H_geo = VLM(o_t, c_t, t_geo)                   → 几何token: "右转车道边界"
H_dyn = VLM(o_t, c_t, t_dyn)                   → 动态token: "右侧车辆继续接近"
H_traj = VLM(o_t, c_t, t_traj)                 → 轨迹token: "右转轨迹先验"
```

**快速轨迹回归**（Stage 2 内置，Eq. 12）：
```
Â = Φ_traj(H_traj[-1])  →  8×3 轨迹点
MSE loss 约 0.15（粗略方向正确，但车道保持偏差大）
```

**Stage 3 HMEF 扩散规划**（10 步去噪）：
```
初始化: A_τ ~ N(0, I)  (8×3 高斯噪声)

Step 1-10: 两流架构联合去噪
  场景流: C (Perceiver压缩后的场景token) — 保持干净
  动作流: R_e (每个专家的噪声token + 时间嵌入 + ego状态)
  每层: cross-attention(C, R_e) → stream-specific FFN

Step 10 输出:
  Â_sem (语义专家轨迹)   → PDMS 贡献: 安全/避撞
  Â_geo (几何专家轨迹)   → PDMS 贡献: 车道保持
  Â_dyn (动态专家轨迹)   → PDMS 贡献: 时序合理性
  Â_traj (轨迹专家轨迹)  → PDMS 贡献: 前向进展

融合: Ā = softmax(w) · [Â_sem, Â_geo, Â_dyn, Â_traj]
```

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能力
- **复杂场景规划**：在 NAVSIM 挑战性动态场景中，PDMS 89.8 超越所有对比方法（包括多传感器方法）
- **未来场景生成**：FVD 32.7 最优，Stage 2 的 Latent CoT 比 Stage 1 的文本条件更好地保持转向行为和车道级演化
- **消融稳健性**：每增加一个专家 token 都有稳定 PDMS 提升（Table 3），证明互补性而非冗余

### 失败模式
- **单帧输入**：作者明确列为 limitation。缺少多帧时序输入意味着对快速动态场景的理解依赖 VLM 内部表征，可能不够鲁棒
- **计算开销**：三阶段训练 + 大模型（5B+2B+扩散规划器），论文明确提到 "substantial computational overhead"
- **领域局限**：实验仅在自动驾驶场景（NAVSIM/NuPlan），未验证具身操作场景
- **开环评估**：NAVSIM 是非反应式开环协议，闭环真实驾驶中的表现可能不同

### 6.1 隐含假设 (Hidden Assumptions)

1. **专家 token 独立性假设**：论文假设 4 种专家 token 提供互补信息（消融实验部分验证），但未验证 token 之间是否存在信息泄漏或冗余。如果 JEPA 和 Wan 分支学到了相似的语义信息，多专家的优势会被高估。

2. **冻结编码器充分性假设**：JEPA 和 VGGT 编码器在 Stage 2 中保持冻结，仅对齐 VLM 隐状态。这假设预训练表征足以覆盖自动驾驶场景——但 JEPA 预训练数据与驾驶数据的分布偏移未被量化。

3. **扩散规划器条件充分性假设**：HMEF 假设专家 token 包含足够的规划信息。消融中仅用 HMEF（无专家）的配置未报告，无法确认专家 token 相比随机条件的增益。

4. **单帧充分性假设**：所有对比方法中，部分使用多帧输入（如 PWM、WoTE）。CoWorld-VLA 在单帧设置下最优，但未与多帧设置对比——单帧是否真的足够？

  如果你不做自动驾驶、不关心世界模型与规划的统一、或已熟悉 ReCogDrive/LaST-VLA 等隐式推理方法且对多专家设计不感兴趣，读摘要和 §1 即可。本文的核心贡献（多专家 Latent CoT）对具身 VLA 的启发是间接的——需要自行迁移到机器人场景。
