### 1.2 关键机制 (Key Mechanism)

**为什么用四个专家 token 而不是一个统一表示？**

自动驾驶决策需要四种不同性质的世界知识：
- **语义交互**（其他车辆要干什么？）→ JEPA 蒸馏，捕捉高层意图
- **几何结构**（道路在哪？可行驶区域边界？）→ VGGT 3D 特征，提供空间约束
- **动态演化**（场景未来怎么变？）→ Wan 视频模型监督，预测时序动力学
- **自车轨迹**（我要去哪？）→ 轨迹回归，连接世界推理与行为目标

单一世界表示（如 Uni-World VLA 的 RGB-only 表示）无法同时编码这四类信息——几何细节会被语义抽象抹平，动态预测会被静态结构稀释。

⚡ **Eureka Moment**: 世界建模不必是"一个模型预测一切"——可以把世界知识拆成四个互补的专家 token，各自用不同来源监督（JEPA/VGGT/Wan/轨迹标注），然后在 VLM 隐空间中统一对齐，最后由扩散规划器在去噪时显式融合。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
p(A | o, c, Z) = DiffusionFusion( H_sem, H_geo, H_dyn, H_traj | o, c )
其中 Z = {z_sem, z_geo, z_dyn, z_traj} 是四个专家 token 构成的 Latent CoT
```

**目标**: 将传统 VLA 的 p(A | o, c) 扩展为 p(A | o, c, Z)，让世界知识 Z 成为轨迹生成的显式条件，而非隐式编码在单一网络中。

**核心方程组**（按训练阶段）：

```
// Stage 1: 世界模型 Flow Matching (仅对未来段加噪)
L_flow = E[ ||F_θ(z~_σ, c, σ)_f - (ε - z_f)||_2^2 ]
其中 z~_(f,σ) = (1-σ)·z_f + σ·ε,  历史段 z_h 保持无噪

// Stage 2: 多专家对齐损失
L_sem = λ_l1 · SmoothL1(Z^_sem, Z_sem) + λ_cos · (1 - cos(Z^_sem, Z_sem))
L_geo = MSE(Z^_geo, Z_geo)
L_dyn = L_flow(o^_fut, o_fut; o_t, H_dyn)     // H_dyn 替代文本条件
L_traj = MSE(A^, A)                            // 轨迹直接回归

L_total = w_dyn·L_dyn + w_sem·L_sem + w_geo·L_geo + w_traj·L_traj
权重: w_dyn=1.0, w_sem=0.1, w_geo=0.1, w_traj=1.0

// Stage 3: 扩散融合规划
L_diff = (1/N_e) · Σ_e ||Â_e - A_norm||_2^2    // 每个专家独立去噪
Ā = Σ_e α_e · Â_e                              // softmax 融合
L_act = L_diff + λ_fusion · ||Ā - A_norm||_2^2  // 融合+独立双监督
```

**变量说明**:

| 符号 | 含义 |
|------|------|
| o_t | 当前帧 (3×H×W) |
| c_t | 条件信息 {导航指令, 历史位姿, 速度, 加速度} |
| Z_sem, Z_geo | 从未来观测提取的 JEPA/VGGT 池化特征（监督目标） |
| Z^_sem, Z^_geo | VLM 适配后的专家表示（与监督目标对齐） |
| H_dyn | VLM 输出的动态演化隐状态 |
| A ∈ R^{T×3} | T 步轨迹，每步 (x, y, ψ) |
| α | 可学习的专家融合权重 (softmax) |
| τ | 扩散噪声水平 (logit-normal 采样) |

> 符号与本文保持一致：H_* 表示 VLM 隐状态，Z_* 表示外部专家特征，A 表示轨迹。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的十字路口场景：

**输入**: 自车以 5 m/s 直行，前方 30m 有车辆准备左转，导航指令"直行通过"。

**Stage 2 专家表示**（假设维度 D=2048）:

```
H_sem: 编码"前方车辆左转意图" → 高激活维度集中在交互语义区域
H_geo: 编码"十字路口几何 + 车道线" → 高激活维度集中在空间约束区域
H_dyn: 编码"3秒后场景演化" → 自车位置前移 + 对方车辆左移
H_traj: 编码"直行通过目标" → 轨迹终点在路口正前方 50m
```

**Stage 3 扩散去噪**（10 步）:

```
Step 0: A_0 ~ N(0, I)  [纯高斯噪声, T=80 步轨迹]
Step 3: 场景 token C 开始约束轨迹不偏离车道 (H_geo 作用)
Step 5: H_sem 开始影响——轨迹在路口前轻微减速 (预测对方左转)
Step 7: H_dyn 确保轨迹与预测的未来场景一致
Step 10: 最终融合
  α = softmax([0.25, 0.30, 0.20, 0.25]) ≈ [0.24, 0.28, 0.22, 0.26]
  Ā = 0.24·Â_sem + 0.28·Â_geo + 0.22·Â_dyn + 0.26·Â_traj
  反归一化 → 可执行轨迹
```

**关键观察**: 融合权重 α 是可学习的，在训练过程中自动学会给几何约束（H_geo）更高权重——因为车道保持是安全底线。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|-----------|----------|
| 总参数量 | Wan2.2-5B + Qwen3-VL-2B + HMEF (~0.1B) | 约 7.1B 参数，需多 GPU 部署 |
| 冻结模型 | Wan2.2-5B, Qwen3-VL-2B, V-JEPA, VGGT | 推理时 4 个模型需加载，显存约 28GB+ |
| 视频生成步数 | 20 步采样 | Stage 2 中如需未来视频预测时的开销 |
| 轨迹规划步数 | 10 步扩散去噪 | 核心推理延迟来源，需优化 |
| 输入帧数 | 单帧 (1 frame) | 显著低于多数基线 (N frames)，降低吞吐压力 |
| 传感器 | 单目摄像头 | 成本最低配置，但依赖视觉质量 |
| 训练策略 | 三阶段串行 | 无法端到端联合训练，各阶段误差累积 |
| 推理频率 | 2 Hz (NAVSIM 设定) | 10 步扩散去噪需 <500ms 才能满足 |

**部署约束**: 四个冻结模型的显存占用是最大瓶颈。Qwen3-VL-2B 约 4GB，Wan2.2-5B 约 10GB，V-JEPA + VGGT 约 8-10GB，加上 HMEF 和 KV cache，单卡部署至少需要 A100-80GB。

**关键 trade-off**: 单帧输入 vs 多帧时序。CoWorld-VLA 用单帧 + 世界模型预测替代多帧输入，降低了推理时的帧率要求和内存带宽，但代价是 Stage 1/2 的训练复杂度显著增加。

### 6.1 隐含假设 (Hidden Assumptions)

1. **四个专家 token 的互补性在推理时成立**: 训练时用未来观测提取 JEPA/VGGT 特征作为监督，但推理时这些特征是从当前帧生成的——训练-推理分布偏移未量化评估。

2. **扩散规划器的 10 步去噪足够**: 论文未报告不同采样步数下的性能曲线，10 步可能是工程妥协而非最优选择。

3. **单帧输入足够**: 虽然结果好，但单帧丢失了时序信息（仅靠历史位姿/速度/加速度补偿），在快速变化场景中可能不足。

4. **Wan2.2-5B 的视频生成能力可迁移**: Stage 1 在 NuPlan 上预训练视频生成器，但 Wan 模型主要在通用视频上训练，驾驶场景的泛化能力依赖预训练数据覆盖度。

5. **融合权重 α 的稳定性**: softmax 融合权重在训练集上学习，但在分布外场景中的权重分配行为未分析——可能出现某个专家权重过高/过低的情况。
