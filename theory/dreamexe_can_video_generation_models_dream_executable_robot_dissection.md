### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

核心洞察是：现有的视频生成评测全部基于"看起来怎么样"——视觉质量、时间一致性、人类审美评分。但这些指标无法区分"机器人优雅地穿过桌子"和"机器人物理正确地抓取物体"。Dream.exe 将评判标准从主观感知转移到客观物理——如果视频中的运动在物理仿真器中无法执行，那么无论它看起来多好看，其物理知识都是不完整的。

**视频→轨迹提取的5步管线**是整篇论文的工程核心：

1. **区域掩码初始化**：在第一帧上识别末端执行器和操作对象的空间区域（仿真场景用实例分割，通用场景用 Grounding DINO + SAM2）
2. **2D点跟踪**：用 CoTracker 在全部帧中跟踪掩码内的查询点，得到每帧像素坐标和可见性标志
3. **深度估计与3D提升**：用 DVD 模型（带LoRA机器人视频适配）估计视频深度，结合初始场景深度校准到度量尺度，再结合相机内外参将2D点提升到世界坐标系3D点
4. **末端执行器轨迹提取**：从提升后的点集估计每帧视觉中心，通过初始状态校准将其转换为控制器参考点轨迹，用 Kabsch 对齐估计末端执行器姿态
5. **夹爪感知动作组装**：根据末端执行器与操作对象的相对运动推断夹爪开合时机，结合校准后的运动轨迹生成可执行动作流

⚡ **Eureka Moment**：视频生成模型不需要经过机器人数据训练——互联网规模的一般视频数据已经编码了足够的物理知识，使其生成的操作视频可以在物理仿真器中成功执行。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
Executability(model) = TaskSuccess_in_Simulator(
    Extract_Trajectory( Generate_Video(model, scene_img, task_desc) )
)
```

**目标**：量化视频生成模型对物理规律的内化程度，用仿真器中的任务成功率作为 grounding signal，替代传统的视觉质量评分。

**变量说明**：

| 符号 | 含义 |
|------|------|
| `model` | 被评估的视频生成模型（8个候选之一） |
| `scene_img` | 初始场景图像（来自 RoboCasa365，固定初始状态） |
| `task_desc` | 自然语言任务描述（标准指令或VLM增强的描述性指令） |
| `Generate_Video` | 模型的条件视频生成过程（image-to-video） |
| `Extract_Trajectory` | 5步视频→轨迹提取管线 |
| `TaskSuccess_in_Simulator` | 在 MuJoCo/robosuite 中执行后的任务成功判定 |

**直觉**：如果模型真的理解了物理规律，`Generate_Video` 输出的视频隐含的运动轨迹应该能在物理仿真器中产生任务成功。这比任何视觉评分都更直接地测试了"世界模型"假说。

**轨迹评估指标**（论文 §4.2）：
```
HSD = 对称 Hausdorff 距离（最坏情况形状偏差）
DYN = Wasserstein-1 距离（速度分布差异）
NDTW = DTW对齐代价 / 对齐路径长度（时间错位惩罚）
```
三个原始距离均除以每任务的归一化因子，映射到 [0,1] 相似度分数。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 Level 1 任务："将红色杯子放到砧板上"。

**步骤1：视频生成**
- 输入：厨房台面场景图 + "Place the red cup on the cutting board"
- Wan 2.7 生成 4秒操作视频（约96帧，24fps）

**步骤2：轨迹提取**
- CoTracker 跟踪末端执行器上的10个查询点 → 96帧 × 10个2D坐标
- DVD 深度估计 → 每个2D点提升到3D → 96帧 × 10个3D点
- 视觉中心校准 → 控制器TCP轨迹：96个 (x, y, z, roll, pitch, yaw)
- 夹爪时机推断：第15帧检测到末端执行器接近杯子 → 夹爪闭合；第78帧接近砧板 → 夹爪打开

**步骤3：仿真执行**
- MuJoCo 中 Franka Panda 执行96步动作
- 每10步一个检查点，偏差超过阈值则校正
- 结果：E-SR = 0.85（85%检查点到达），Pos95 = 2.1cm，Rot95 = 5.4°
- 任务判定：杯子中心距砧板中心 3.2cm < 5cm阈值 → SR-B = 1（成功）

**对比**：同一任务，Hailuo 2.3 生成的视频视觉评分更高（VLM评分 4.2 vs 3.8），但执行结果 E-SR = 0.42（42%检查点到达），Pos95 = 53cm——夹爪在错误位置闭合，杯子被推离目标。这直接验证了论文的核心发现：视觉质量 ≠ 可执行性。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/特征 | 工程含义 |
|------|-----------|----------|
| 任务规模 | 101个手动策展任务 | 比典型基准大10-100倍，但仅覆盖 RoboCasa365 的28% |
| 模型数量 | 8个（5闭源+2开源+1专用） | 覆盖当前视频生成生态的主流选择 |
| 视频→轨迹管线 | 5步级联（分割→跟踪→深度→校准→组装） | 每步引入误差，级联累积可能导致最终轨迹偏差 |
| 深度估计 | DVD模型 + LoRA适配 | 需要初始场景深度校准到度量尺度；对生成视频中不存在的深度线索敏感 |
| 仿真执行 | MuJoCo + robosuite + Franka Panda | 闭环校正防止误差累积，但掩盖了部分轨迹质量问题 |
| 相机依赖 | 需要已知相机内外参 | 限制了在未知相机设置下的泛化能力 |
| 单臂限制 | Franka Panda 7-DOF | 不覆盖双臂、移动操作、人形机器人 |
| 仿真局限 | 全部在 MuJoCo 中 | sim-to-real gap 未测试；物理引擎的接触建模可能与真实世界有差异 |

**关键 trade-off**：闭环校正提高了执行鲁棒性（防止开环误差累积导致完全失败），但也降低了评测的区分度——一个质量较差的轨迹可能通过多次校正"勉强成功"，掩盖了原始视频隐含运动的质量问题。

## 5. 数据与评测 (Data & Eval)

**数据来源**：RoboCasa365（Nasiriany et al., 2026），一个包含365个日常操作任务的大规模仿真框架。

**数据筛选**：从365个任务中手动筛选出101个适合视频生成评测的任务，筛选标准包括：
- 相机视角适合（不遮挡末端执行器）
- 物体身份明确（无歧义）
- 轨迹清晰（运动路径可辨识）
- 不需要基座导航（当前提取管线不支持）

**难度分层**：

| 级别 | 任务数 | 描述 | 例子 |
|------|--------|------|------|
| Level 1 | ~40 | 单物体原子操作 | 拾取放置、关节操作、按钮按压、旋钮旋转 |
| Level 2 | ~35 | 多物体交互 | 放入容器、堆叠、容器间转移 |
| Level 3 | ~26 | 多阶段复合任务 | 先开抽屉再取物、先转灶台旋钮再移动烹饪容器 |

**评测协议**：
- 两种指令变体：标准指令（原始数据集标注）和增强指令（Gemini 3 Pro 重述为更描述性风格）
- 每个模型对两种指令变体分别生成视频，端到端评估
- 正文报告为两种指令的平均值

**评估维度**（三轨制）：
1. **视觉评估**：VLM（Gemini 3 Pro + Qwen3-VL-Plus）在机器人稳定性、物理合理性、任务遵循三个维度评分
2. **轨迹评估**：HSD / DYN / NDTW 三个指标对比提取轨迹与ground truth
3. **执行评估**：E-SR（检查点到达率）、SR-B（二元成功率）、SR-P（连续进度分数0-1）、子目标分数

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 6.1 能做什么

| 能力 | 证据 | 限制条件 |
|------|------|----------|
| 编码基础物理知识 | 多个模型在 Level 1 达到可测量执行成功率 | 仅限仿真环境 |
| 生成几何一致的末端执行器运动 | Wan 2.7 在 EEF 轨迹相似度上领先 | 需要已知相机参数 |
| 泛化到多样化任务和视角 | 通用模型在跨任务/跨视角上优于专用模型 | 仅测试了101个固定场景 |
| 多物体空间关系理解 | CosmosPolicy-BenchCam 在物体轨迹相似度上领先 | Level 2 成功率仍显著低于 Level 1 |

### 6.2 不能做什么

| 失败模式 | 原因 | 严重程度 |
|----------|------|----------|
| Level 3 多阶段任务成功率低 | 无法在长任务跨度上维持物理一致性 | 高——限制了实际可用性 |
| 视觉质量与可执行性脱节 | 模型优化目标是视觉逼真度而非物理正确性 | 高——现有评测体系存在盲区 |
| 夹爪开合时机错误 | 从相对运动推断夹爪状态，对深度估计误差敏感 | 中——直接影响抓取成功率 |
| 复杂视角下深度估计失败 | DVD 模型在非常规视角下预测不准确 | 中——限制了泛化 |
| 未见过的物体/场景 | 全部测试在固定101个场景上 | 高——未测试分布外泛化 |

### 6.3 隐含假设 (Hidden Assumptions)

1. **仿真成功率 ≈ 物理知识内化**：论文假设如果生成的视频在仿真器中能成功执行，说明模型"内化了物理规律"。但可能存在另一种解释：模型只是学习了互联网视频中常见的运动模式，这些模式碰巧与仿真器中的可行轨迹相似——这不代表真正的物理理解，而是统计相关性。

2. **已知相机参数是合理的**：提取管线依赖场景的已知相机内外参。在真实世界中，相机参数可能未知或动态变化，这会使3D提升步骤失效。

3. **单视角足够**：除 Cosmos Policy 外所有模型只接收单视角输入。但真实机器人操作通常需要多视角信息来理解3D空间关系。

4. **仿真到真实的迁移**：全部评估在 MuJoCo 中进行。仿真器中的接触力学、摩擦模型、传感器噪声与真实世界存在差异——仿真成功不保证真实成功。

5. **VLM评分的可靠性**：视觉评估使用 Gemini 3 Pro 和 Qwen3-VL-Plus 作为评分者。黑盒 VLM 的评分一致性和校准程度未被充分验证。
