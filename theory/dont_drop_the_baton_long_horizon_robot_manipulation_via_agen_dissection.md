### 1.2 关键机制 (Key Mechanism)

BATON 解决两个根本问题：

**问题 ❶ — 探索成本指数爆炸**
- 整条 K 阶段任务联合探索需要约 T^K 次尝试（T 为单阶段首次成功所需尝试数）
- BATON 将子任务作为探索单元，成本降至 O(T·K)，且每次失败可精确定位

**问题 ❷ — 过渡无表示**
- VLA 原语只有退出条件，没有进入条件
- 子任务 A 的成功执行可能留下子任务 B 无法使用的状态
- BATON 引入三层过渡：调用过渡（子任务内）、交接过渡（前→后）、前瞻过渡（后→前）

⚡ **Eureka Moment**：「过渡」本身才是长视界操作的真正学习对象——把它从执行副产品提升为一等记忆实体，边探索边写合同，此后所有经过同一条边的任务自动继承。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
探索成本:  O(整链) = T^K  →  O(子任务) = T·K
记忆结构:  M = {Nodes: (粗轨迹, 失败记录)} ∪ {Edges: (σ_act, σ_ho, σ_la)}
```

**目标**：在零参数更新的前提下，让冻结 VLA 能可靠执行 K 阶段长视界任务。

**核心方程**：

```
任务分解:  T = u₁ ⊳ σ₁,₂ ⊳ u₂ ⊳ σ₂,₃ ⊳ ... ⊳ σ_{K-1,K} ⊳ u_K
子任务分解: u_k = a_k ⊳ σ_act_k ⊳ v_k
            a_k = 非接触段 (LLM Agent 解析原语)
            σ_act_k = 调用过渡 (手腕相机就绪条件)
            v_k = 接触段 (冻结 VLA_ACT)
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| T | 长视界任务（千步级） |
| u_k | 第 k 个子任务（百步级接触技能） |
| σ_{k,k+1} | 子任务 k 到 k+1 的交接边界 |
| a_k | 非接触段：LLM Agent 用解析原语完成（移动、定位、预接触姿态） |
| σ_act_k | 调用过渡：手腕相机 verifier 确认就绪后才触发 VLA |
| v_k | 接触段：冻结 VLA 执行接触丰富操作 |
| σ_ho | 交接过渡：恢复被前驱扰动的后继入口状态 |
| σ_la | 前瞻过渡：后继需求约束当前子任务的执行策略 |
| T | 单阶段首次成功平均尝试次数 |
| K | 子任务数量 |

**直觉**：把「什么时候调用 VLA」「交接时手腕应该是什么姿态」「当前策略是否兼容后继」从隐式的试错结果变成显式的语言条件，写在记忆的边上（edge），而非节点（node）上。

> 符号与本文保持一致：⊳ 表示时序组合，σ 表示过渡条件。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 3 阶段任务：打开抽屉 → 拿起罐头 → 放进抽屉。

**传统整链探索（Harness VLA 风格）**：
- 单阶段首次成功平均 T = 5 次尝试
- 整链探索成本 = T^K = 5³ = **125 次完整任务尝试**
- 每次尝试约 1800 步 → 总计 ~225,000 步
- 失败时不知道是哪个阶段出的问题

**BATON 子任务探索**：
- 阶段 1（开抽屉）：5 次短视界探索 = 5 × 100 步 = 500 步
- 阶段 2（拿罐头）：5 次短视界探索 = 5 × 100 步 = 500 步
- 阶段 3（放罐头）：5 次短视界探索 = 5 × 100 步 = 500 步
- 分层组合：验证 [1,2] → 2 次尝试；验证 [1,2,3] → 3 次尝试
- 总计 ≈ 5×3 + 5 = **20 次短探索 + 5 次组合** ≈ ~2,500 步

**成本对比**：225,000 vs 2,500 → **90 倍节省**

**过渡示例**：
- 阶段 1 结束后，机械爪水平旋转了 90°（开抽屉的残留）
- 阶段 2 需要机械爪垂直朝下抓罐头
- Handoff 过渡 σ_ho：verifier 检测到「爪子非垂直」→ 用解析原语重新定向 → 确认「爪子垂直、张开、位于罐头上空」→ 允许阶段 2 开始
- 如果阶段 3 要求「把罐头放进微波炉」，Lookahead 过渡 σ_la 会约束阶段 2 必须用「侧面抓」（顶部抓会导致罐头+爪子高度超过微波炉内部高度）

## 4. 工程视角 (Engineering View)

| 工程维度 | BATON 特征 | 含义 |
|----------|-----------|------|
| 推理延迟 | LLM Agent 每过渡一次需调用 | 每次 σ_act / σ_ho / σ_la 检查都是一次 LLM 视觉推理调用，可能增加 1-3s/次 |
| 探索开销 | O(T·K) 短视界 vs O(T^K) 整链 | 大幅降低 token 消耗，但 LLM 调用次数随子任务数线性增长 |
| 内存增长 | 每子任务可能积累多个 rival 策略 | 记忆大小随任务多样性增长，但 edges 按过渡类型复用 |
| 部署约束 | 需要手腕相机 + 解析原语库 | 纯端侧部署需预装 IK 求解器和视觉检测模块 |
| 零训练 | 不更新任何参数 | 可随时切换 VLA 后端（VLA/WAM/任何接触策略），接口不变 |
| 可审计性 | 所有学习成果以语言写入记忆 | 可读取、审计、复用，区别于权重黑盒 |
| 容错性 | 失败定位到子任务或边界 | 可针对性修复，不需重跑整条任务 |

**工程含义**：BATON 把 VLA 从「整条链的执行者」降级为「接触段的工具调用」，LLM Agent 成为「项目经理」。这种分工在工程上意味着：VLA 的 OOD 脆弱性被限制在短窗口内（预接触姿态已就位），而组合复杂度被语言记忆吸收。代价是 LLM 推理开销——每个过渡都需要视觉推理，在实时控制回路中可能成为瓶颈。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

| 能力 | 场景 | 原因 |
|------|------|------|
| 可靠执行千步级任务 | 多阶段家务操作 | 子任务级探索 + 过渡合同确保每段可控 |
| 跨任务迁移 | 新任务复用已有子任务/边界 | 记忆按过渡类型索引，非按任务 |
| 零样本过渡检查 | 新边界首次遇到时 | 语言条件零样本验证，不需训练 |
| 多策略选择 | 同一子任务在不同后继下选不同策略 | Scheduler 根据剩余计划检索 rival |
| 失败诊断 | 定位失败到具体子任务或边界 | 分层探索 + 分层组合 |

### 不能做什么 / 失败模式

| 失败模式 | 场景 | 原因 |
|----------|------|------|
| 新过渡类型 | 遇到记忆中从未见过的边界类型 | 需返回 Explorer 重新探索，增加开销 |
| LLM 视觉推理失败 | Verifier 误判就绪条件 | 手腕相机图像质量差或条件描述模糊 |
| 解析原语不足 | 需要 IK 无法求解的姿态 | 非接触段依赖预定义的解析原语库 |
| 过度分解 | 子任务拆得太细 | K 增大 → 探索成本 O(T·K) 和过渡检查开销都增加 |
| 记忆膨胀 | 大量任务积累大量 rival 策略 | 检索效率可能下降（论文未讨论） |

### 6.1 隐含假设 (Hidden Assumptions)

1. **子任务分解是可行的**：假设 LLM 能正确将长任务分解为有意义的子任务。如果分解点选在不合适的地方（比如把「抓」和「放」拆成两个子任务但中间没有可检查的边界），整个方法会退化。

2. **手腕相机足以判断就绪条件**：假设手腕视角的视觉信息足够 Verifier 做出准确判断。如果关键状态信息在手腕相机视野之外（如物体全局位置），Verifier 可能误判。

3. **解析原语覆盖非接触段**：假设所有非接触操作都能用 IK 解析原语完成。对于复杂地形或非标准夹具，可能需要更多原语。

4. **过渡条件可用语言描述**：假设所有重要的过渡条件都能用自然语言精确描述。某些微妙的接触状态（如「刚好卡入」的触觉感受）可能难以用视觉语言条件表达。

5. **仿真到实物的迁移**：所有实验在仿真中进行。实物中的传感器噪声、执行器延迟、物体形变等可能破坏仿真中成立的过渡条件。
