### 1.2 关键机制 (Key Mechanism)

**核心设计哲学：分离"该共享的"和"该独立的"**

UCAG-P 将 VLA 策略拆成两个独立模块：

1. **共享相机中心运动头（Shared Camera-Centric Motion Head）**：预测 p0/p1 锚点在相机坐标系中的 3D 轨迹。这个头在所有数据源之间共享——无论是单臂机器人、双臂机器人、人形机器人还是人类手部视频，监督信号都是同一个东西：相机看到的锚点运动。

2. **几何条件翻译器（Geometry-Conditioned Translator）**：将共享的几何运动预测翻译为目标机器人的可执行指令。翻译器接收：预测的相机中心运动 chunk + 当前机器人状态 + 相机到基座的变换矩阵 + 当前状态的 Jacobian + 编码形态结构的 geometry tokens。

**⚡ Eureka Moment**：异构数据之间最稳定的共同结构不在低级控制器中，而在相机可观测的操作几何中——手腕和抓取中心的运动轨迹。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
π_θ(o_t, l) = ĝ_t:t+H     (共享几何预测)
û_t:t+H^(k) = φ_ψ(ĝ, s_t^(k), T_cam→base, J_t, z_geo^(k))   (形态翻译)
L = L_geo + λ_cmd · L_cmd   (联合目标)
```

**目标**：学习一个共享的相机中心动作空间 G，使得异构数据（机器人轨迹 + 人类视频）可以在同一个动作空间中被联合优化，同时保留将共享预测映射到各形态可执行指令的能力。

**核心方程**：

```
L_geo = Σ_h=1^H Σ_d m_h,d^g · |ĝ_t+h,d - g_t+h,d| / max(1, Σ_h,d m_h,d^g)

L_cmd = Σ_h=1^H Σ_d m_h,d^u · |û_t+h,d^(k) - u_t+h,d^(k)| / max(1, Σ_h,d m_h,d^u)

L = L_geo + λ_cmd · L_cmd
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| g_t+h ∈ R^30 | 相机中心动作 chunk 单步：每 manipulator 10 维 (Δp0, Δp1, Δψ, γ_gripper, 0) × 2 + 相机运动 |
| p0 | 手腕/末端执行器锚点，相机坐标系 3D 坐标 |
| p1 | 夹爪中心（机器人）/ 抓取中心（人手），相机坐标系 3D 坐标 |
| m_h,d^g | 几何目标可用性掩码（人类数据无 p1 时对应维度为 0） |
| u_t:t+H^(k) | 形态 k 的可执行指令 chunk，稀疏 80 维布局 |
| m_h,d^u | 指令维度掩码（ inactive 形态的 slot 不参与 loss） |
| T_cam→base^(k) | 相机到机器人基座的变换矩阵 |
| J_t^(k) | 当前状态的局部 Jacobian |
| z_geo^(k) | 编码形态结构的 geometry tokens |
| λ_cmd | 平衡几何监督与指令监督的权重 |

> 符号与本文保持一致：所有位移量相对于 chunk 首帧的锚点坐标测量；相机运动项 ξ_cam 仅在移动相机数据集中激活，固定相机设为零。

**直觉**：L_geo 确保模型学会"相机中看到的操作运动"——这是所有形态的交集；L_cmd 确保翻译器能把这个共享运动变成具体机器人能执行的指令。掩码机制让每种数据只贡献它有的标签（人类视频只贡献 L_geo，机器人数据两者都贡献）。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：单臂机器人在固定相机前抓取一个杯子。

**Step 1 — 数据预处理**

- 相机观测到末端执行器在 t=0 时位于 p0,0^cam = [0.1, -0.05, 0.5]^T 米
- 抓取中心 p1,0^cam = [0.12, -0.04, 0.48]^T 米
- 目标位置：t=30 时 p0,30^cam = [0.15, 0.02, 0.45]^T 米

**Step 2 — 运动头预测**

模型预测一个 H=30 的 chunk。简化为线性插值：

```
Δp0,h^cam ≈ [0.0017, 0.0023, -0.0017] × h  （每步位移，米）
Δp1,h^cam ≈ [0.0013, 0.0020, -0.0010] × h
```

单步 g_h = [Δp0, Δp1, Δψ, γ_gripper, 0] ∈ R^10

**Step 3 — 翻译器映射**

给定当前状态 s_t（关节角 θ = [0.5, -0.3, 0.8, ...]^T）和 Jacobian J_t：

```
Δθ ≈ J_t^+ · T_cam→base · Δp0^cam
```

其中 J_t^+ 是 Jacobian 伪逆。假设 Δp0^cam = [0.0017, 0.0023, -0.0017]^T：

```
T_cam→base · Δp0^cam = [0.0015, 0.0025, -0.0018]^T  （基座坐标系）
J_t^+ · [0.0015, 0.0025, -0.0018]^T = [0.002, -0.001, 0.003, ...]^T  （关节增量）
```

翻译器输出 û_t:t+H 的稀疏 80 维向量中，前 7 个 slot 填入关节增量，其余为 0（被 mask）。

**Step 4 — 损失计算**

假设预测 ĝ 与真实 g 的平均绝对误差为 0.002 米：

```
L_geo = 0.002 （所有维度可用，掩码全 1）
L_cmd = 0.005 （关节指令误差）
L = 0.002 + 1.0 × 0.005 = 0.007
```

**人类数据场景**：同一任务的人类手部视频，p0 来自手腕关键点，p1 来自拇指-食指中点。无机器人指令 → L_cmd 的掩码全 0 → L = L_geo = 0.002。模型只学几何，不学指令。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能力

- **跨形态零微调执行**：单个 checkpoint 同时支持单臂（LIBERO）、双臂（RoboTwin）、人形（RoboCasa GR-1），无需任何 benchmark 特定的 fine-tuning
- **人手视频直接训练**：人类手部视频不经重定向/视频生成即可作为独立形态参与联合训练，利用 2,340h 人手数据增强泛化
- **分布外鲁棒性**：LIBERO-Plus 上对机器人位姿（92.8%）、光照（98.9%）、背景（98.0%）扰动特别鲁棒
- **真实机器人适配**：在 Piper 真实机器人上三个任务均优于 π₀.5，面包抓取从 20%→60%（人→机迁移场景）

### 失败模式

- **跨形态零迁移弱**：RoboTwin 中直接将 ALOHA 替换为 ARX 机器人，零迁移仅 35% 成功率（论文 §9.1），远低于源形态性能
- **接触密集任务弱**：RoboCasa GR-1 中关节操作（如旋钮、把手）表现较差，这是所有 VLA 模型的共同挑战
- **相机/深度误差级联**：相机标定误差、深度估计偏差、手部关键点定位错误会直接传播到 p0/p1 几何目标，进而影响下游控制器（论文 §11 和 project page Limitations）
- **仿真主导偏差**：训练数据 59% 来自仿真（InternData-MultiRobot 占 57%），真实数据仅 4.2%，sim2real gap 仍是主要限制

### 6.1 隐含假设 (Hidden Assumptions)

1. **p0/p1 可稳定检测**：假设所有数据源都能可靠提取手腕/末端和抓取中心的 3D 位置。人类数据的 p1 定义为"拇指尖和食指尖的中点"，这个启发式定义在复杂抓取（如三指捏、掌抓）下可能不准确。
2. **相机标定可用**：翻译器依赖 T_cam→base 和 J_t，这些需要精确的相机外参和机器人运动学模型。在未知相机配置或未标定机器人上无法直接部署。
3. **几何运动充分性**：假设"相机可观测的锚点运动"足以表征所有操作任务。但对于需要触觉反馈的操作（如插拔、滑动接触），仅靠视觉几何可能不够。
4. **Jacobian 局部线性近似有效**：翻译器使用局部 Jacobian 将几何位移映射为关节增量，这在大幅度运动或奇异位形附近可能失效。

| Being-H | 人形专用 VLA | ❌ | N/A | 单形态 specialist |
| **UCAG-P** | **解耦几何预测与形态翻译** | **✅** | **不需要** | **共享几何 + 翻译器** |

**面试 Tip**：当被问到"UCAG-P 和 Qwen-RobotManip 的区别"时，回答："Qwen-RobotManip 统一了相机中心的末端执行器动作空间，但这个空间仍然绑定在机器人末端执行器上——人类手部没有'末端执行器'的概念。UCAG-P 的关键创新是用 p0/p1 锚点（手腕 + 抓取中心）替代了末端执行器，这是一个更抽象的几何概念，人手和机器人都可以映射到这个空间，因此人手视频可以直接参与训练而不需要任何重定向。"

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 做多形态统一 VLA 策略的研究者——本文的解耦架构是一个值得借鉴的设计范式
  2. 需要利用人手/人类视频数据训练机器人策略的团队——本文提供了直接利用人手数据的完整方案
  3. 关注动作表示抽象的工程师——p0/p1 锚点设计对任何跨形态操作任务都有启发

- **建議章節路徑**：先读 §4.2（相机中心动作空间，理解 p0/p1 的核心设计）→ 再看 §4.3（架构，理解运动头 + 翻译器的解耦）→ 再看 §5.2（实验结果，验证 claim）→ 可跳过 §3.2（数据预处理细节，工程实现相关）和 §8（训练超参）
