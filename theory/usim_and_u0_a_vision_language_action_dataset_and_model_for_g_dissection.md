## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 训练方式 | 推理频率 | 关键超参 |
|------|------|------|----------|----------|----------|
| **VLM Encoder** | 双目 RGB + 语言指令 L | 2048-d 特征 ϕ_t | 冻结（GR00T N1.5 预训练权重） | 每 1.6s 触发 | — |

| **动作 MLP** | 历史动作 A_t + 位置编码 | 2048-d 特征 | 可训练 | 每步 10Hz | H=16（action chunk） |
| **DiT Action Module** | VLM 特征 + 传感器特征 + 动作特征 + 噪声 | 速度场 v_τ（16 步动作） | Flow-matching 训练 | K=4 步 Euler 积分 | batch=256, 50K steps |
| **CAP Module** | VLM 特征 ϕ_t | 6-DoF 目标位姿 T（机器人坐标系） | MSE 辅助损失 | 每步 10Hz | α=1.0（损失权重） |

**统一动作空间**：推进器 PWM 归一化信号 + 4-DoF 机械臂关节角度拼接。这是水下机器人特有的设计——陆地机器人通常不需要同时控制推进器和机械臂。

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计：**

1. **从 GR00T N1.5 初始化**：GR00T 本身已具备多模态融合 + DiT 动作生成的能力，选择它而非从零训练，降低了水下域适配的数据需求。
2. **CAP 模块作为"空间感知锚"**：水下环境视觉特征稀疏、目标距离远。通过强制模型预测目标 6-DoF 位姿（导航时为下一个路点，抓取时为目标物体），模型必须学习几何约束，而非仅靠端到端黑盒映射。
3. **Flow-matching 而非 DDPM**：Flow-matching 推理只需 K=4 步（vs DDPM 通常 50-100 步），对 10Hz 控制频率至关重要。
4. **仿真数据 + 随机探索**：真实水下数据采集成本极高（熟练操作员需大量练习）。用 Stonefish 仿真 + 手专家策略 + 随机噪声注入，自动生成覆盖次优状态和恢复行为的轨迹。

⚡ **Eureka Moment**：用显式目标位姿估计（CAP 模块）作为辅助任务，强制 VLA 模型学习水下空间的几何约束——不是让模型"猜"动作，而是先让它"看到"目标在哪里。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L = L_action + α·L_CAP
  = E_τ[‖V_θ(ϕ_t, A_t^τ, S_t) - v_τ‖²] + α·E[‖T - T_gt‖²]
```

**先给目标**：训练一个同时输出动作序列和目标位姿的统一策略，最小化动作预测误差和位姿估计误差的加权和。

**公式拆解**：

```
// Flow-matching 动作损失
A_t^τ = τ·A_t + (1-τ)·ε          // 插值噪声
v_τ = A_t - ε                     // 速度场目标
L_action = E_τ[‖V_θ(ϕ_t, A_t^τ, S_t) - v_τ‖²]

// CAP 位姿估计损失（机器人坐标系）
T_gt = (R_r^T·R_g,  R_r^T·(t_g - t_r))   // 世界坐标→机器人坐标
L_CAP = E[‖T - T_gt‖²]

// 总损失
L = L_action + α·L_CAP,  α = 1.0
```

**变量说明**：

| 符号 | 含义 | 维度/范围 |
|------|------|-----------|
| ϕ_t | VLM 提取的视觉-语言特征 | 2048-d |
| A_t^τ | τ 时刻的噪声动作 | 推力+关节向量 |
| v_τ | 速度场（GT 动作 - 噪声） | 同 A_t |
| V_θ | DiT 动作模块 | 3B 参数 |
| T | CAP 预测的目标位姿 | 6-DoF (R∈SO(3), t∈R³) |
| T_gt | 机器人坐标系下的目标位姿 GT | 6-DoF |
| τ | flow-matching 时间步 | [0,1] 均匀采样 |
| ε | 高斯噪声 | N(0,I) |
| H | action chunk 长度 | 16 |
| K | Euler 积分步数 | 4 |

> 符号与本文保持一致。动作损失使用 flow-matching 目标（而非传统 DDPM 的噪声预测），推理时通过 4 步 forward Euler 积分从噪声逐步去噪到动作。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个水下抓取场景：BlueROV2 需要抓取前方 2 米处的管道阀门。

**推理过程逐步走一遍**：

```
Step 0 — 输入
  V_t: 双目图像（阀门在画面右上方，距相机约 2m）
  L: "grasp the valve"
  S_t: IMU [0.1, -0.05, 9.8] m/s², DVL [0.3, 0.1, -0.05] m/s, depth=15.2m

Step 1 — VLM 编码
  ϕ_t = VLM(V_t, L) → 2048-d 向量
  （内部注意力机制将"valve"与图像右上方区域对齐）

Step 2 — CAP 位姿估计
  F = Conv(ϕ_t, MASK) → 特征图
  Att = Conv(F) → 通道注意力权重
  T = MLP(Pool(F·Att)) → [R_pred, t_pred]
  假设输出: t_pred = [1.8, 0.3, -0.5] m（阀门在机器人右前方 1.8m，略偏上）

Step 3 — DiT 动作生成（4 步 Euler 积分）
  τ₀ = 1.0: A₀ = ε ~ N(0,I)  // 纯噪声
  τ₁ = 0.75: A₁ = A₀ + 0.25·V_θ(ϕ_t, A₀, S_t)
           → 推进器开始输出向前推力 ~0.6（归一化），机械臂开始伸展
  τ₂ = 0.50: A₂ = A₁ + 0.25·V_θ(ϕ_t, A₁, S_t)
           → 推力调整到 0.55，机械臂关节角向阀门方向旋转
  τ₃ = 0.25: A₃ = A₂ + 0.25·V_θ(ϕ_t, A₂, S_t)
           → 推力微调，夹爪接近目标
  τ₄ = 0.00: A₄ = A₃ + 0.25·V_θ(ϕ_t, A₃, S_t)
           → 最终动作：推力 [0.52, 0.48, 0.51, 0.49]，关节 [45°, 30°, -15°, 10°]

Step 4 — 执行
  输出 H=16 步动作序列（1.6s 的控制指令），机器人执行后进入下一轮推理
```

**关键数字**：
- 推理延迟：DiT 前向 4 次 + CAP 1 次 ≈ 几十 ms（RTX 3090）
- 控制频率：10Hz，每 1.6s 触发一次完整推理（输出 16 步 chunk）
- 动作误差：U0 整体 APE = 0.0359（GT 动作与预测动作的 MSE）

## 4. 工程视角 (Engineering View)

| 维度 | 数值 | 含义 |
|------|------|------|
| 模型大小 | ~3B 参数 | 初始化自 GR00T N1.5，可部署在单卡 RTX 3090 |
| 推理设备 | 4×RTX 3090 | 论文评测配置（Intel Xeon Silver 4214R） |
| 训练设备 | 8×H20 | 50K steps, batch=256（H20 为国产 AI 芯片，算力约 A100 的 50-70%） |
| 推理频率 | 10Hz 控制 / 1.6s 触发推理 | 每次推理输出 16 步 action chunk |
| DiT 步数 | K=4 | Flow-matching 相比 DDPM 的显著优势（DDPM 通常 50-100 步） |
| 数据规模 | 905K 帧 / 25 小时 | 仿真自动生成，无需人工标注 |
| 训练时间 | 未明确给出 | 50K steps × batch 256 on 8×H20，预估 1-2 天 |

**工程含义**：
- **控制边界清晰**：VLM 冻结 + DiT 可训练，推理时 VLM 只需每 1.6s 运行一次（而非每 100ms），大幅降低计算负载。
- **部署约束**：3B 参数在 RTX 3090（24GB VRAM）上 FP16 推理约需 6-8GB VRAM，留有足够余量给仿真环境。但若要部署到水下机器人边缘计算平台（如 Jetson Orin），需要量化或蒸馏。
- **Sim2Real 鸿沟**：所有训练数据来自 Stonefish 仿真。真实水下环境的浊度、光线衰减、水流扰动在仿真中难以完全复现——这是最大的工程风险。

### 6.1 隐含假设 (Hidden Assumptions)

1. **仿真流体动力学足够真实**：Stonefish 的水下物理模型能否复现真实水流的湍流、涡旋、浮力变化？未验证。
2. **手专家策略覆盖足够广**：虽然注入了随机噪声，但专家策略本身的设计偏差可能限制数据多样性。
3. **GT 位姿在机器人坐标系中可学习**：CAP 模块假设 VLM 特征足以推断 6-DoF 位姿。但在极端浊度或遮挡情况下，视觉特征可能不足以支撑精确位姿估计。
4. **训练/测试分布一致**：77/23 划分在相同环境条件下收集——这意味着评测反映的是插值能力，而非外推能力。
5. **语言指令已对齐**：假设 VLM 的语言理解能力可直接迁移到水下场景，未单独验证水下专用指令的理解准确度。

- **不值得精讀的理由**：如果你不做水下机器人、不关心跨域迁移、已有充足的真实水下数据——那么这篇的方法论（仿真数据+辅助位姿估计）对你的直接价值有限。读摘要和 §IV 的表格即可。
