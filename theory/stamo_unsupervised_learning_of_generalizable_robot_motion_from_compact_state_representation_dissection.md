## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 频率/时序 | 训练/推理 |
|------|------|------|-----------|-----------|
| DINOv2 特征提取器 | 原始图像 (H×W×3) | 256×1024 特征图 | 每帧 | 冻结 |
| Transformer Compressor | 256×1024 特征 | 2×1024 状态 token | 每帧 | 可训练 |
| DiT 解码器 | 状态 token + 噪声 | 重建图像 | 训练时 | 可训练 |
| 隐空间插值 | s_start, s_goal | 中间状态序列 | 规划时 | 无需训练 |
| 动作解码器 | 状态差 Δs | 机器人动作 | 执行时 | 可训练 |

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **紧凑性优先**：256-token 特征图对长视野规划和实时执行过于冗余；单 CLS token 又太粗糙。2-token 是经验上的 sweet spot。
2. **DiT 先验**：用预训练 Diffusion Transformer 作为解码器，因为"能准确重建像素"隐含了对机器人姿态、物体交互等关键状态信息的理解。
3. **运动涌现**：隐空间中线性插值 s(t) = (1-α)·s_start + α·s_goal 生成的中间状态，经 DiT 解码后对应平滑、动力学一致的运动轨迹。

⚡ **Eureka Moment**：如果状态表示足够好，运动就是状态的变化——不需要专门学"动作"，只需要学"状态"，然后做减法。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
运动 = 状态差 = s_goal - s_start  (在 2-token 隐空间中)
```

**完整形式**：

状态编码：
```
s = ℰ(x₀)  其中 ℰ = Compressor ∘ DINOv2
```

Diffusion Autoencoder 损失（Flow Matching）：
```
L_DAE = E_{z₀,t}[ ||𝒟(z_t, ℰ(x₀), t) - u(z_t)||² ]
```
其中 z_t = (1-σ_t)·z₀ + σ_t·ε 是噪声与潜变量的线性插值，u(z_t) 是目标速度场。

隐空间插值：
```
s(α) = (1 - α) · s_start + α · s_goal  其中 α ∈ [0, 1]
```

动作解码：
```
a = π_φ(Δs) = π_φ(s_goal - s_start)
```

**变量说明**：
| 符号 | 含义 | 维度 |
|------|------|------|
| x₀ | 输入图像 | H×W×3 |
| s | 状态表示 | 2×1024 |
| z_t | 扩散过程潜变量 | 与 VAE 潜空间同维 |
| α | 插值系数 | 标量 |
| a | 机器人动作 | 取决于动作空间 |

**直觉**：DiT 解码器在训练中学会了"从状态重建图像"，这意味着它理解了状态与视觉的映射。当我们在隐空间中移动时，解码器生成的图像序列自然对应平滑的视觉变化——即运动。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有一个"抓取杯子"任务：

**步骤 1：编码起始状态**
- 输入：机器人手在杯子上方的图像 x_start
- 输出：s_start = [t₁, t₂] 其中 t₁, t₂ ∈ R^1024
- 例如：t₁ = [0.23, -0.45, ..., 0.12], t₂ = [-0.11, 0.67, ..., -0.33]

**步骤 2：编码目标状态**
- 输入：机器人手抓住杯子的图像 x_goal
- 输出：s_goal = [t'₁, t'₂]
- 例如：t'₁ = [0.31, -0.38, ..., 0.19], t'₂ = [-0.05, 0.72, ..., -0.28]

**步骤 3：计算状态差**
```
Δs = s_goal - s_start = [t'₁-t₁, t'₂-t₂]
```
这个 Δs 隐式编码了"手向下移动、闭合夹爪"的运动信息。

**步骤 4：插值生成中间状态**
取 α = 0.5：
```
s(0.5) = 0.5 · s_start + 0.5 · s_goal
```
解码 s(0.5) 得到"手在中间位置"的图像。

**步骤 5：动作解码**
动作解码器 π_φ 将 Δs 映射为具体动作：
```
a = [Δx=0.02, Δy=-0.15, Δz=-0.08, gripper_close=0.8]
```

**关键观察**：整个过程没有显式建模时间或速度，运动完全由状态几何决定。

## 4. 工程视角 (Engineering View)

| 工程指标 | StaMo | 传统视频基线 | 含义 |
|----------|-------|--------------|------|
| 输入模态 | 单帧 RGB | 视频片段 (8-16 帧) | StaMo 数据需求更低 |
| 状态维度 | 2×1024 = 2048 | 256×1024 = 262144 | 压缩 128 倍 |
| 推理延迟 | ~5ms (encoder) + ~10ms (interpolate) | ~50ms (时序模型) | 5-10 倍加速 |
| 显存占用 | ~200MB (冻结 DINOv2 + 小 compressor) | ~2GB (3D CNN/Transformer) | 10 倍节省 |
| 训练数据 | 静态图像 (可来自互联网) | 机器人视频 (稀缺) | 数据可扩展性更好 |

**部署约束**：
- 需要 fine-tune Diffusion Autoencoder（约需 10k-100k 机器人图像）
- DiT 解码器可冻结（用预训练 Stable Diffusion 3）
- 动作解码器 π_φ 需下游任务 fine-tune

**Trade-off**：
- 2-token 可能在极端复杂场景（多物体遮挡、精细操作）中丢失细节
- 可动态调整 token 数（论文测试了 2/4/8-token，2-token 性价比最高）

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- ✅ 紧凑状态表示用于世界模型预测
- ✅ 从静态图像生成平滑运动轨迹
- ✅ 无缝集成现有 VLA 架构（作为中间表示层）
- ✅ Sim-to-real 迁移（隐空间具有域不变性）
- ✅ 多数据源 scaling（真实/仿真/人类视频）

**不能做什么**：
- ❌ 高动态场景（快速运动导致单帧信息不足）
- ❌ 需要精确力控的接触丰富操作（缺乏触觉/力觉输入）
- ❌ 长时序依赖任务（>100 步，累积误差显著）

### 6.1 隐含假设 (Hidden Assumptions)

1. **状态马尔可夫性**：假设单帧图像包含足够的状态信息——对遮挡、高速运动场景可能不成立。
2. **隐空间线性**：假设隐空间中线性插值对应真实运动——对非刚体、可变形物体可能失效。
3. **DiT 先验充分**：假设预训练 DiT 理解机器人场景——对域外物体（训练未见类别）重建质量下降。
4. **动作可解码**：假设状态差可映射为动作——需要额外训练动作解码器，不是完全 zero-shot。
