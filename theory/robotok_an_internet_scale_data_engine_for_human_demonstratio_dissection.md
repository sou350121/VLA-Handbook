### 1.2 关键机制 (Key Mechanism)

RoboTok 的核心设计围绕三个关键洞察：

1. **动作相似性 ≠ 外观相似性**：视觉相似的场景可能包含完全不同的操作行为，而视觉差异大的视频可能执行相同的操作。因此检索必须基于运动而非外观。

2. **躯干中心化是关键**：将手部轨迹从相机坐标系变换到以人体躯干为中心的坐标系，使得不同视角、不同场景、不同遮挡情况下的操作行为可以比较。更重要的是，躯干帧仅从手腕轨迹估计——不需要人体本身在画面中可见。

3. **DTW 监督嵌入**：动态时间规整（DTW）提供了一个运动对齐的伪标签，但计算 O(N²) 不可扩展。用 DTW 监督训练一个轻量嵌入，将昂贵的轨迹比较转移到训练阶段，推理时只需一次前向传播 + 向量搜索。

⚡ **Eureka Moment**：不需要看到人的身体——仅从手腕的运动轨迹就能估计出躯干中心参考系，这使得从任意互联网视频中提取可比较的操作行为成为可能。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L = L_set + λ·L_rank,  其中 L_set 学习"哪些轨迹相似"，L_rank 学习"相似程度排序"
Γ(x) ∈ S^(d-1),  s(i,j) > s(i,k) ⇒ ⟨Γ(x_i), Γ(x_j)⟩ > ⟨Γ(x_i), Γ(x_k)⟩
```

**目标**：学习一个嵌入映射 Γ，使得嵌入空间中的内积排序保留 DTW 定义的轨迹相似度排序。

**DTW 相似度（伪标签）**：

```
s(i,j) = -DTW(x_i, x_j) / [0.5·(L_i + L_j)]

其中 DTW(x_i, x_j) = min_π Σ_(t,u)∈π ‖x_i^t - x_j^u‖₂
```

- x_i, x_j: 两条 21 关节手部轨迹，长度分别为 L_i 和 L_j
- π: DTW 对齐路径，最小化累积位姿距离
- 分母是长度归一化因子
- 负号使相似度为正值（DTW 成本越小，相似度越高）

**嵌入训练目标**：

```
L = L_set + λ·L_rank

L_set: 鼓励 oracle Top-K 邻居得分高于边界负样本
L_rank: 鼓励采样正样本的相对排序匹配 DTW 排序
```

**批次构造**（关键设计）：

```
对每个锚点 a:
  R(a) = Top-K DTW 邻居 (K=20)
  正样本: p₁, p₂ ∈ R(a)
  边界负样本: n = 第 (K+1) 近邻
  组: G(a) = {a, p₁, p₂, n}
  批次: 49 组 → b=196 条轨迹
```

> 符号与本文保持一致：x 表示 21 关节手部位姿轨迹，Γ 表示嵌入编码器，S^(d-1) 表示 d 维单位超球面，DTW 表示动态时间规整距离。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有 3 条手部轨迹（简化为 2 关节 × 3 帧），演示 RoboTok 的完整流程：

**步骤 1：躯干中心化**

```
原始轨迹 A（相机坐标系，2 关节 × 3 帧）:
  t=0: 手腕(0.5, 0.3, 0.2), 指尖(0.6, 0.4, 0.3)
  t=1: 手腕(0.6, 0.3, 0.2), 指尖(0.7, 0.4, 0.3)
  t=2: 手腕(0.7, 0.2, 0.2), 指尖(0.8, 0.3, 0.3)

躯干估计（仅从手腕轨迹）:
  预测躯干中心 = (0.0, 0.0, 0.0)

躯干中心化后:
  t=0: (0.5, 0.3, 0.2), (0.6, 0.4, 0.3)
  t=1: (0.6, 0.3, 0.2), (0.7, 0.4, 0.3)
  t=2: (0.7, 0.2, 0.2), (0.8, 0.3, 0.3)
  （此例中躯干在原点，坐标不变；实际场景中躯干中心化消除视角偏移）
```

**步骤 2：DTW 相似度计算**

```
DTW(A, B) = 0.15m（A 和 B 动作相似，都是"向左切割"）
DTW(A, C) = 0.82m（A 和 C 动作不同，C 是"向上举起"）

s(A, B) = -0.15 / 0.5·(3+3) = -0.05 → 高相似度
s(A, C) = -0.82 / 0.5·(3+3) = -0.27 → 低相似度
```

**步骤 3：批次构造与训练**

```
锚点 A 的 Top-K=20 邻居中包含 B → B 是正样本
C 不在 Top-20 中 → 若 C 是第 21 近邻，则是边界负样本

批次 G(A) = {A, B, C, n}

训练后嵌入:
  Γ(A) = [0.8, 0.2, 0.1, ...]  (d=256 维)
  Γ(B) = [0.7, 0.3, 0.1, ...]  (与 A 内积高)
  Γ(C) = [0.1, 0.8, 0.2, ...]  (与 A 内积低)

  ⟨Γ(A), Γ(B)⟩ = 0.70 > ⟨Γ(A), Γ(C)⟩ = 0.18 ✓
```

**步骤 4：推理检索**

```
新查询 Q: "用刀切菜"
  Γ(Q) = [0.75, 0.25, 0.1, ...]
  余弦搜索 Top-3:
    1. A (cos=0.92) → "向左切菜"
    2. B (cos=0.88) → "向右切菜"
    3. D (cos=0.65) → "切水果"
```

## 4. 工程视角 (Engineering View)

| 维度 | 数值/设计 | 工程含义 |
|------|-----------|----------|
| 训练语料规模 | N=100,000  clips (Action100M) | 互联网规模，可无限扩展 |
| 视频帧率 | 5 fps（手部关键点提取） | 低帧率降低计算成本，手部运动足够捕获 |
| 嵌入维度 | d（论文未明确，轻量交叉注意力） | 紧凑表示，支持大规模向量索引 |
| 批次大小 | b=196 (49 组 × 4) | 中等批次，边界负样本策略提高训练效率 |
| Top-K 邻居 | K=20 | 检索窗口大小，平衡精度与召回 |
| DTW 计算 | 仅训练阶段（离线） | 推理时 O(1) 前向 + 向量搜索，不依赖 DTW |
| 新增视频索引 | 单次前向传播 | 实时可扩展，无需重新训练 |
| 相机假设 | 静态相机 | 限制：移动相机视频需先稳定或排除 |
| 手部可见性 | 至少一只手可见 | 限制：遮挡严重或手部不明显的视频被过滤 |
| 下游策略输入 | 本体感受 + 指尖力（3 帧滚动窗口） | 不依赖视觉输入，检索的演示通过奖励信号间接引导 |

**部署约束**：
- 离线阶段需要 WiLoR + MoGe-2 + HaWoR 三个模型，计算成本集中在预处理
- 在线检索阶段仅需轻量编码器 + 向量索引，延迟极低
- 躯干帧估计模型仅需要手腕轨迹，不依赖人体检测，降低了部署复杂度

### 6.1 隐含假设 (Hidden Assumptions)

1. **静态相机假设**：论文过滤掉了非静态相机视频，但互联网上大量演示视频是手持拍摄的。这个假设大幅缩小了可索引的视频范围。
2. **躯干帧静态假设**：躯干中心被建模为静态参考系，但实际操作中人的躯干会移动（弯腰、转身）。静态假设在大幅度身体运动中可能失效。
3. **手部轨迹充分性假设**：仅用 21 关节手部轨迹编码操作行为，忽略了物体形状、力反馈、接触信息。对于依赖触觉或力控制的操作（如拧瓶盖的力度），仅轨迹可能不充分。
4. **仿真到真实可迁移假设**：下游策略评估仅在 VTDexManip 仿真中进行，奖励塑造的参数（β, w, γ）在真实环境中可能需要重新调整。
5. **形态匹配假设**：方法假设机器人手部与人类手部形态相似（anthropomorphic），对于平行夹爪或其他非人手形态的末端执行器，检索的人类演示可能不适用。
