### 1.2 关键机制 (Key Mechanism)

StageWAM 的核心设计哲学是**两尺度未来解耦**：

1. **短期物理未来 (V_short)**: 描述接下来 H_v 帧的局部场景演化（物体怎么动、接触怎么发生），由 WAM 的视频专家生成
2. **阶段语义未来 (Y_stage)**: 描述任务应该推进到什么目标状态（物体应该对齐到什么位置、机器人应该与什么交互），由 Stage-JEPA 预测

⚡ **Eureka Moment**: 用 JEPA 的联合嵌入预测（而非像素生成）来表示下一阶段目标——因为像素级预测容易关注外观而非任务完成度，而隐空间表征保留了任务相关的语义和物理结构。

**Stage-pair 自动构建**（无需人工标注阶段标签）：
- 每 8 帧采样一个候选中心，用冻结 V-JEPA2 编码 64 帧 clip
- 计算局部窗口内表征变化量 q_j（clip-level + token-level 取 max）
- 时序 NMS（半径 r=3，最多 K=5 个关键帧）
- 关键帧 + 首尾帧 = 阶段边界，每个当前帧 t 配对下一个边界 b_{i+1}

**门控注入接口**：将 Stage-JEPA 输出的阶段表征通过 MLP 映射到视频 token 维度，用可学习的有界标量门 α = 0.2·σ(β) 做残差注入：
```
X_tilde = X_video + α · MLP(Pool(Z_stage))
```

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
p(V_short, A | o, s, l, Y_stage)  where  Y_stage = f_θ(o, l)
```

先给目标：WAM 不再仅以 (o, s, l) 为条件，而是额外以预测的阶段语义目标 Y_stage 为条件。Y_stage 由独立的 Stage-JEPA 模型从当前观测和指令预测。

**Stage I — 阶段预测损失**：
```
L_stage = (1/B) · Σ_i [1 - (z_hat_i)^T · z_i]
```
- z_hat_i: 预测的下一阶段归一化表征
- z_i: 目标阶段归一化表征（来自冻结 V-JEPA2 编码器）
- 余弦相似度最大化，直接对齐隐空间表征

**Stage II — 门控注入 + WAM 损失**：
```
h_t = P_ψ(Pool(Z_hat_target))
α = 0.2 · σ(β)                    // β 可训练标量
X_tilde = X_video + α · h_t

L = L_video + L_action + λ_g·α² + λ_ρ·(ρ - ρ_0)²
其中 ρ = ||α·h_t|| / ||X_video||
```

变量说明：

| 符号 | 含义 | 值/来源 |
|------|------|---------|
| β | 可训练门参数 | 零维标量，初始使 α ≈ 0.02 |
| α | 有界门控标量 | α ∈ [0, 0.2] |
| ρ | 注入特征相对幅度 | 目标 ρ_0 = 0.08 |
| λ_g | 门大小正则权重 | 10^{-4} |
| λ_ρ | 幅度比正则权重 | 10^{-3} |
| ρ_0 | 目标相对幅度比 | 手动设定 0.08 |

直觉：α 门控确保阶段表征以残差方式注入（不破坏 WAM 原有的视频生成能力），ρ 正则约束注入幅度不偏离目标比例——本质上是"阶段引导是辅助信号，不是主导信号"。

> 符号与本文保持一致：o_t=视觉观测, s_t=机器人状态, a_t=动作, l=语言指令, V_short=短期视频未来, A_t=动作块, Y_stage=阶段语义未来

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个"把杯子放到指定位置"的任务，分为 3 个阶段：
- Stage 0: 初始状态（杯子在桌上）
- Stage 1: 抓取完成（机械臂握住杯子）
- Stage 2: 放置完成（杯子在目标位置）

**Stage-pair 构建过程**：
```
Episode 共 200 帧，每 8 帧采样 → M = 25 个候选中心
V-JEPA2 编码后计算表征变化 q_j：
  q_3  = 0.12 (帧 24 附近，杯子静止 → 变化小)
  q_7  = 0.85 (帧 56 附近，手接近杯子 → 变化大)  ✓ 关键帧
  q_12 = 0.78 (帧 96 附近，杯子离开桌面 → 变化大)  ✓ 关键帧
  q_18 = 0.15 (帧 144 附近，杯子已放置 → 变化小)

NMS 后保留 K=2 关键帧 → 边界 B = [0, 56, 96, 199]
阶段: [0,56) → [56,96) → [96,199)
```

**Stage I 训练**（以 t=30 为例，当前在 Stage 0）：
```
S_t (帧 -17~+46, 中心 t=30) → E → z_t (dim=1024)
S_tgt (帧 28~91, 中心 b_1=56) → E → z_tgt (dim=1024)
Predictor(z_t, l="put cup") → z_hat_tgt

假设: cos(z_hat_tgt, z_tgt) = 0.73
L_stage = 1 - 0.73 = 0.27  → 反向传播更新 Predictor
```

**Stage II 推理**（t=30, 在 Stage 0 中）：
```
z_hat_tgt (来自冻结 JEPA)
→ Pool → MLP → h_t (dim=d_v, 假设 d_v=1024)
→ α = 0.2·σ(β) ≈ 0.05 (训练后)
→ X_tilde = X_video + 0.05 · h_t

WAM 以 X_tilde 为条件:
→ 预测 8 帧未来视频 + 16 步动作
→ 执行前 8 步动作 → 观察新状态 → 循环
```

**效果**：因为有阶段目标引导，WAM 的短期预测会更倾向于"向抓取方向运动"而非"原地探索"，减少了无效动作步数。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/设计 | 工程含义 |
|------|----------|---------|
| 硬件 | 8×A800 80GB | 需要多卡集群，不适合边缘部署 |
| Stage I 训练 | 1000 steps, LR=1e-5, BS=256 | 快速训练，V-JEPA2 冻结节省算力 |
| Stage II 训练 | 4 epochs, LR=1e-6, BS=256 | 精细调优，BF16 混合精度 |
| 输入分辨率 | 384×320 | 中等分辨率，兼顾精度与速度 |
| 视频窗口 | 8 帧输入 → 8 帧预测 | 短窗口，适合高频控制 |
| 动作块 | 16 步 action chunk | 与 Motus 一致 |
| JEPA 输入 | 64 帧 clip | V-JEPA2 固定要求，推理需维护缓存 |
| 门控 α | 有界 [0, 0.2] | 防止阶段表征覆盖视频流 |
| 推理延迟 | JEPA 前向 + WAM 前向 | 约 2× 单 WAM 延迟（JEPA 冻结可优化） |
| 闭环节奏 | 执行 chunk → 观察 → 重规划 | 收束 horizon 控制 |

**部署约束**：
- 推理开始时需要填充 64 帧缓存（前 64 帧重复第一帧），这意味着前 64 帧的预测质量较低
- Stage-JEPA 冻结后可做量化/蒸馏优化
- 门控注入接口通用——可迁移到其他有视觉条件流的 WAM

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **多阶段长程任务**：阶段感知使模型在需要多步骤序列的任务上表现更好（如"打开抽屉→取出物品→放置"）
- **环境泛化**：在 randomized 配置下仍有竞争力，说明阶段表征有一定鲁棒性
- **步数优化**：减少 5.97% 执行步数，说明阶段引导确实减少了无效探索

### 不能做什么
- **真实机器人部署未验证**：所有实验在 RoboTwin 2.0 仿真中进行，sim-to-real gap 未知
- **超长期任务**：最多 K=5 个阶段关键帧，对于超过 5 个子阶段的任务可能不够
- **跨平台迁移**：仅在双臂仿真环境测试，未验证单臂/人形/移动操作平台

### 6.1 隐含假设 (Hidden Assumptions)

1. **V-JEPA2 表征足够区分阶段**：假设冻结的 V-JEPA2 编码器的表征变化能可靠检测任务阶段边界——但 V-JEPA2 是在通用视频上预训练的，不一定对机器人操作的细微状态变化敏感
2. **阶段边界可自动检测**：基于表征变化的启发式方法（min-max 归一化 + NMS）假设每个任务的阶段变化幅度在同一量级——但不同任务的阶段差异可能相差很大
3. **门控注入不破坏 WAM**：假设 α 门控能平衡阶段引导和原有视频生成——但 ρ_0=0.08 是手动设定的，不同任务可能需要不同的注入强度
4. **两阶段训练足够**：假设顺序训练（先 JEPA 后 WAM）能达到全局最优——但可能存在 JEPA 预测和 WAM 生成的分布偏移
