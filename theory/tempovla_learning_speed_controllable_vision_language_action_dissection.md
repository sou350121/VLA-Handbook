💡 **X-Ray 开场**
现有 VLA 从训练数据中"继承"了一个固定的执行速度——快慢完全由演示数据决定，部署后无法调整。但真实操作需要交替进行：低风险阶段应该快，高风险接触阶段应该慢。TempoVLA 的核心发现是：预测动作的幅度本身就决定了机器人移动速度，因此只需给 VLA 加一个标量速度输入 + 在线重定时数据增强，就能让同一个策略在 0.5× 到 2× 之间自由调速，而且变速训练还意外地提升了默认速度下的成功率。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 维度 | 传统 VLA | TempoVLA |
|------|----------|----------|
| 训练数据 | 单一速度演示 | VSTA 在线重定时到多速度（0.5×–2×） |
| 策略输入 | (observation, instruction) | (observation, instruction, speed_scalar s) |
| 速度控制 | 无（继承自演示） | 显式标量输入，s > 1 加速，s < 1 减速 |
| 架构改动 | — | 可选：text prefix（零改动）/ RMSNorm 调制 / soft prompt |
| 低层控制器 | 不变 | 不变（完全正交） |
| 部署灵活性 | 固定速度 | 同一策略按需调速，可搭配 VLM 动态调度 |

### 1.2 关键机制 (Key Mechanism)

TempoVLA 由两个耦合组件构成：

**数据侧：VSTA（Variable-Speed Trajectory Augmentation）**
- 将演示轨迹按运动一致性分段（still / translate / rotate / translate-and-rotate）
- 在每个段内，将 q 个源帧的动作累积为总运动 Δ，再均分为 p 个输出帧
- s = q/p：q > p 加速，q < p 减速
- 累积-分割操作保证总运动量守恒（Δ 不变，仅改变内部形状）
- 在线随机 chunk-start sampling：每次采样时随机偏移 r，确保所有帧都能成为 chunk 起点

**模型侧：速度 Conditioning**
- 三种注入方式效果几乎相同（SR 差异 < 0.3%）
- Text prefix 最优：零架构改动，直接在 instruction 前加 "Perform the task at ⟨s⟩x speed."

⚡ **Eureka Moment**：动作幅度本身就编码了执行速度——放大动作 = 加速，缩小动作 = 减速；关键在于让模型学会"同一个观察在不同速度指令下输出不同幅度的动作"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
π_θ(o_t, s) ≈ s · π_baseline(o_t)   （直觉：速度 s 线性缩放动作幅度）
```

**目标**：训练一个速度条件策略，使其在给定速度指令 s 下输出的动作幅度按比例缩放：
```
θ* = argmin_θ E[(o_t, A_t)~D̃, s] [ L(π_θ(o_t, s), VSTA(A_t, s)) ]
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| s | 速度标量，s > 1 加速，s < 1 减速，s = 1 默认 |
| o_t = (v_t, ℓ_t, ρ_t) | 观察：视觉 + 语言指令 + 本体感受 |
| A_t = (a_t, ..., a_{t+H-1}) | 动作 chunk，horizon H |
| D̃ | VSTA 在线增强的多速度数据集 |
| L | 模仿损失（回归或 flow-matching） |
| VSTA(A_t, s) | 重定时后的目标动作（累积-分割后） |

**直觉**：VSTA 保证了"重定时后的动作总和等于原始总运动"，因此模型学习到的映射本质上是"在速度 s 下，每个时间步应该输出总运动的 1/p 份额"。速度 conditioning 通过 text prefix / RMSNorm 调制 / soft prompt 三种方式实现，实验表明三者效果几乎等价——说明只要数据重定时做得好，速度控制本身是一个"简单"的映射问题。

> 符号与本文保持一致：VLA 策略记为 π_θ，速度指令为标量 s，动作空间为 ℝ^7（平移 3 + 旋转 3 + 夹爪 1）。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的直线移动演示，4 帧动作（仅平移 x 维度）：
```
原始: a = [0.1, 0.1, 0.1, 0.1]  （总位移 = 0.4）
```

**加速到 2×（s = 2 = q/p = 4/2）**：
```
累积: Δ = 0.1 + 0.1 + 0.1 + 0.1 = 0.4
分割: a' = [0.2, 0.2]  （2 帧完成同样的 0.4 位移）
```

**减速到 0.5×（s = 0.5 = q/p = 2/4）**：
```
对每 2 帧累积: Δ_1 = 0.1+0.1 = 0.2, Δ_2 = 0.1+0.1 = 0.2
分割: a' = [0.1, 0.1, 0.1, 0.1]  （4 帧输出，每帧减半）
实际: [0.05, 0.05, 0.05, 0.05, 0.05, 0.05, 0.05, 0.05]
```

**训练时**：每次采样同一演示时，随机偏移 r ∈ {0, ..., q-1}。例如 q=4, r=2：
```
帧 0-1: 原速通过（verbatim）
帧 2-5: 累积-分割为 2 帧
```
这样经过多轮训练，每一帧都有机会成为 chunk 起点，不会被永久丢弃。

**推理时**：给定 s = 1.5，模型看到 instruction "Perform the task at 1.5x speed. Pick up the cup."，输出的动作 chunk 幅度约为 baseline 的 1.5 倍，rollout 步数从 152 降到 129（LIBERO 实测数据）。

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/分析 | 含义 |
|----------|-----------|------|
| 训练成本 | 30k iterations, batch 512, 32×H20 | 与标准 VLA 微调相当；VSTA 在线计算开销极小 |
| 推理延迟 | 零增加（text prefix 方案） | 不改变模型架构，每步推理时间不变 |
| 实际速度比 | Model Ratio ≈ Data Ratio（中速区） | 1.25× 指令 → 1.19× 实际；1.5× 指令 → 1.37× 实际 |
| 高速区偏差 | 2× 指令 → 1.56× 实际 | 差距来自：纠错步 + 控制器跟踪误差 |
| 内存开销 | 零（text prefix）/ 极小（MLP 调制） | 不增加参数量 |
| 部署约束 | 要求 action 空间可线性叠加 | 直角坐标平移 OK；四元数/欧拉角需先转 so(3) |
| 低层控制器 | 完全不变 | 与现有控制栈正交，可叠加 motion planner |

**工程含义**：TempoVLA 的最大工程价值在于"零侵入"——text prefix 方案不需要修改任何模型代码，只需在 instruction 字符串前拼接速度描述。对于已有 VLA 部署，升级成本接近于零。

**部署建议**：默认部署速度应设为 1.25× 而非 1×。LIBERO 和 Franka 实验一致显示 1.25×–1.5× 的成功率高于 1×，原因是演示数据中存在"节奏冗余"（teleoperation 中的犹豫帧），VSTA 的合并操作压缩了这些冗余，使策略执行更果断。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做
- **双向调速**：0.5×–2× 范围内连续可调（训练覆盖范围内）
- **零架构改动部署**：text prefix 方案即插即用
- **数据增强效应**：变速训练提升 1× 成功率（LIBERO +0.2–0.7%，Franka +8%）
- **VLM 动态调度**：与 GPT-4o 配合实现阶段感知调速（Franka 上 96% SR）

### 不能做
- **超范围外推差**：2× 速度在 LIBERO 上 SR 降至 88.4%（vs baseline 96.7%），Model Ratio 仅 1.56×
- **非可加 action 空间需预处理**：四元数/旋转矩阵/欧拉角不能直接累积-分割
- **不解决推理延迟**：每步推理时间不变，只是每步动作幅度更大
- **不改变路径**：VSTA 保持运动语义不变，只改变时间分布；如果原始演示路径有缺陷，TempoVLA 不会修正

### 6.1 隐含假设 (Hidden Assumptions)

1. **演示质量足够**：VSTA 假设原始演示的总运动轨迹是正确的，只需要重定时。如果演示本身路径错误，VSTA 会忠实复现错误路径。
2. **运动段内轴角恒定**：VSTA 对旋转的累积-分割假设段内旋转轴近似不变，大幅方向变化会被分段边界截断。这限制了极端旋转操作的加速能力。
3. **低层控制器能跟踪大动作**：2× 速度下 Model Ratio 显著低于 Data Ratio（1.56× vs 1.90×），部分原因是低层控制器无法精确跟踪大步幅动作——但作者未系统分析控制器带宽限制。
4. **GPT-4o 调度可靠性**：动态调度实验依赖 GPT-4o 的视觉推理能力，未测试开源 VLM 的效果。调度保守（多数决策在 1×–1.25×），可能受 prompt 偏差影响。
