### 1.2 關鍵機制 (Key Mechanism)

**資料端：VSTA（Variable-Speed Trajectory Augmentation）**
- **運動一致分段**：將示範切割成內部運動一致的段（still/translate/rotate/translate-and-rotate），夾爪開關作為硬邊界
- **Chunk 級速度變換**：對每個 chunk，累積總運動 Δ = Σᵢ aᵢ，然後線性插值重新分配到 p 個輸出步驟
- **線上 chunk 起點採樣**：每次訓練時隨機偏移 r ~ U{0,...,q-1}，確保所有原始幀最終都能成為 chunk 起點

**模型端：三種速度注入方案**
- **文字前綴（預設）**：在指令前加 "Perform the task at ⟨s⟩x speed."，零架構修改
- **速度調變 RMSNorm**：MLP 將 s 嵌入後加到 flow-matching 時間步嵌入，驅動 adaRMSNorm
- **Soft Prompt**：為每個訓練速度錨點維護可學習 prompt tokens，推理時選最近錨點

⚡ **Eureka Moment**：預測動作的幅度本身就決定了機器人移動速度——速度控制不需要修改底層控制器，只需讓 VLA 學會按比例縮放其預測動作幅度。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：
```
π_θ(o_t, s) ≈ s · π_base(o_t)    [直覺：速度條件縮放動作幅度]
```

**目標**：訓練單一政策 π_θ(o_t, s)，使其預測動作幅度隨指令速度 s 線性縮放。

**訓練目標**：
```
θ* = argmin_θ E[(o_t, A_t)~D̃] [ L(π_θ(o_t, s), A_t(s)) ]
```

其中：
- D̃ = VSTA(D, s) 是可變速增強資料集
- s ∈ {0.5, 0.75, 1, 1.25, 1.5, 1.75, 2} 是目標速度倍率
- L 是模仿學習目標（回歸或 flow-matching）
- A_t(s) 是速度 s 下的目標動作 chunk

**VSTA 核心運算**：
```
s = q/p  (q, p 互質)
Δ = Σ_{i=1}^{q} a_i          [累積 chunk 總運動]
a'_j = (j/p) · Δ  -  ((j-1)/p) · Δ  [線性插值重分配]
     = Δ/p  (等幅分配)
```

**速度調變 RMSNorm**（方案二）：
```
adaRMSNorm(x; σ_ts + φ_mod(s)) = γ(σ_ts + φ_mod(s)) ⊙ (x / ‖x‖_RMS)
```

其中 φ_mod(s) ∈ R^{d_mod} 是兩層 MLP 對速度 s 的嵌入。

> 符號說明：o_t = (v_t, ℓ_t, ρ_t) 為觀察（視覺、語言指令、本體感知）；A_t 為動作 chunk；s 為速度倍率；H 為預測視窗；π_θ 為 VLA 政策。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

假設一個 2D 平移示範，原始 4 個動作步驟：
```
a_1 = (0.01, 0.02)    a_2 = (0.01, 0.02)    a_3 = (0.01, 0.02)    a_4 = (0.01, 0.02)
```

**加速到 2×（s = 2 = 2/1，q=2, p=1）**：
```
Chunk: [a_1, a_2] → Δ = (0.02, 0.04) → 重分配到 1 步: a'_1 = (0.02, 0.04)
Chunk: [a_3, a_4] → Δ = (0.02, 0.04) → 重分配到 1 步: a'_2 = (0.02, 0.04)
結果：4 步 → 2 步，總運動不變，速度翻倍
```

**減速到 0.5×（s = 0.5 = 1/2，q=1, p=2）**：
```
Chunk: [a_1] → Δ = (0.01, 0.02) → 重分配到 2 步: a'_1 = (0.005, 0.01), a'_2 = (0.005, 0.01)
... 對每個原始動作重複
結果：4 步 → 8 步，總運動不變，速度减半
```

**訓練時速度條件注入**：
```
輸入指令: "pick up the red block" + 速度 s=1.5
文字前綴: "Perform the task at 1.5x speed. pick up the red block"
VLA 輸出: 動作幅度約為 1× 時的 1.5 倍（實際由模型學習，非硬性縮放）
```

| **部署約束** | 底層控制器完全不改動，可直接套用到現有 VLA 部署 |

**工程含義**：
- VSTA 是線上資料增強，不增加儲存成本——每次訓練時即時重採樣
- 文字前綴方案零架構修改，意味著可以套用到任何現有的 VLA（包括閉源模型）
- 動態調度時 VLM 每 2 個 chunk 查詢一次，額外延遲可忽略（VLM 推理與 VLA 並行）

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

### 能力
- **雙向速度控制**：同一政策可加速（s>1）和減速（s<1），不需額外訓練
- **資料增強效應**：可變速訓練本身提升 1× 成功率（LIBERO +0.2~0.7%，Franka +8%）
- **動態調度**：與 VLM 配對可自動根據風險調整速度
- **輕量部署**：不修改底層控制器，文字前綴方案零架構修改

### 失敗模式
- **極端速度退化**：2× 加速時 LIBERO SR 降至 89.4%（vs 97.4% 最佳），Model Ratio 僅 1.58×（目標 2×）
- **減速精度限制**：0.5× 時 Object 套件 SR 降至 94.4%（vs 98.2% 最佳）
- **僅單一機器人平台驗證**：實驗僅在 Franka 7-DoF 臂上完成，未覆蓋移動機器人/人形/雙臂
- **動作表示限制**：VSTA 要求動作空間對加法封閉（Cartesian 平移、關節速度、so(3) 軸角），四元數/旋轉矩陣/Euler 角需先轉換
- **夾爪狀態處理**：夾爪開關作為硬邊界不參與插值，可能導致不連續

### 6.1 隱含假設 (Hidden Assumptions)

1. **動作幅度 ≈ 速度**：核心假設是預測動作幅度直接映射到執行速度。這在低層控制器線性跟隨時成立，但對有飽和/限幅的控制器可能不成立。
2. **運動方向在 segment 內近似恆定**：VSTA 的 so(3) 軸角假設在 segment 內軸不變，大角度旋轉時可能引入誤差。
3. **示範資料質量**：VSTA 依賴原始示範的運動語義完整性——如果原始示範本身有抖動或錯誤，重採樣會放大這些問題。
4. **VLM 調度可靠性**：動態調度依賴 GPT-4o 的風險判斷，未評估 VLM 錯誤決策的後果。
