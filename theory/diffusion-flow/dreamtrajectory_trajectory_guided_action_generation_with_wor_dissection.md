💡 **X-Ray 开场**

移动操作 VLA 面临两个根本问题：(1) 直接把视觉观测映射到全身动作块，在巨大的动作空间里"盲搜"，基座和手臂配合不精确；(2) 开环执行预测的动作块，不检查动作是否真的能实现预期的末端运动，导致控制误差和非预期接触不断累积。DreamTrajectory 的解法是：让 VLA 同时输出一条末端轨迹（"要去哪"）和动作块（"怎么动"），用轨迹引导动作生成；然后在执行前用一个轻量世界模型模拟每个候选动作的实际效果，选出最符合计划的那个。在 MS-HAB 基准上，成功率从 32.3% → 47.5% → 54.8%；在真机上从 63.3% → 81.7% → 90.0%。

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **轨迹作为中间表示的物理意义**：末端执行器的 3D 轨迹天然编码了"基座移动 + 手臂伸展"的联合效果。因为轨迹锚定在 replanning 时刻的基座坐标系上，该坐标系在整个预测 horizon 内固定——所以轨迹中隐含了未来基座运动的意图。这比让 VLA 直接在高维关节空间里隐式学习协调要高效得多。

2. **双流联合生成 vs 串行生成**：不是先生成轨迹再条件化动作，而是同时去噪。共享流时间 σ 确保两个流的去噪过程同步演化——轨迹在早期提供粗略方向，在晚期精化细节，动作流在整个过程中持续接收轨迹的条件信号。

3. **Group-Causal Attention 的方向性**：轨迹 token 只能看到多模态前缀和之前的轨迹 token；动作 token 可以看到完整的轨迹流和之前的动作 token。这建立了单向依赖——轨迹引导动作，但动作信息不会泄露回轨迹生成。这防止了"动作去噪过程中的噪声污染轨迹规划"。

4. **世界模型在轨迹空间而非像素空间操作**：这是关键工程决策。预测 16 步 7D 位姿（112 维）远比预测 16 帧图像便宜。GRU 只需 49M 参数就能捕捉接触、碰撞、控制器误差等非解析动力学效应。

⚡ **Eureka Moment**：用一条末端 3D 轨迹作为"意图层"和"执行层"之间的桥梁——轨迹告诉你"要去哪"，动作块告诉你"怎么动"，世界模型验证"这个动作真能到那儿吗"。三层一致性检查把移动操作的协调问题从隐式学习变成了显式约束。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
a_tilde = argmax_a∈C [ λ · Sim(τ_hat, W_φ(o,s,a)) + (1-λ) · η · Smooth(a) ]
```

**先给目标**：在测试时从 N=30 个候选动作中选出最优执行动作，评判标准是"该动作实际产生的轨迹与 VLA 计划轨迹的一致性"加上"动作本身的平滑度"。

**公式分解**：

```
// 1. VLA 联合生成目标 (流匹配)
L_VLA = E[ λτ · ||vτ - uτ||² + λa · ||va - ua||² ]

其中:
  τ^σ  = σ·ετ + (1-σ)·τ    (轨迹插值)
  a^σ  = σ·εa + (1-σ)·a     (动作插值)
  uτ   = ετ - τ             (轨迹目标速度)
  ua   = εa - a             (动作目标速度)
  σ    ~ Uniform(0,1)       (共享流时间)

// 2. 轨迹表示 (7D 位姿)
τ_t+h = [p_t+h^(Bt), q_t+h^(Bt)] ∈ R^7
  p ∈ R^3: 末端位置 (在块局部坐标系 Bt 中)
  q ∈ R^4: 四元数表示的末端朝向

// 3. 世界模型预测
τ̃(a) = W_φ(o_t, s_t, a_t:t+H-1) ∈ R^(H×7)

// 4. 候选采样 (AR(1) 高斯过程)
C = {a_hat} ∪ {a_hat + εi | i=1,...,N-1}
  εi 维度独立, 边际标准差 σ=0.05, 滞后相关 ρ=0.9

// 5. 打分选择
a_tilde = argmax [ λ·S_traj(a) + (1-λ)·η·S_smooth(a) ]
  λ = 0.5, η = 1e-3
```

**变量说明**：

| 符号 | 含义 | 维度 |
|------|------|------|
| τ | 末端执行器轨迹 (H 步 7D 位姿) | R^(H×7) |
| a | 全身动作块 | R^(H×d_a) |
| σ | 流匹配时间步 | scalar ∈ [0,1] |
| vτ, va | 预测的轨迹/动作速度场 | 同 τ, a |
| uτ, ua | 目标速度 (噪声-数据) | 同 τ, a |
| W_φ | 轨迹世界模型 (GRU) | — |
| S_traj | 计划-预测轨迹一致性分数 | scalar |
| S_smooth | 动作平滑度惩罚 | scalar |
| H | 预测 horizon | 16 |
| N | 候选数量 | 30 |

> 符号与本文保持一致：τ 表示末端轨迹，a 表示动作块，Bt 表示锚定在 replanning 时刻的块局部坐标系。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：移动机械臂需要将桌上的苹果放入碗中。

**初始状态**：
- 基座距离桌子 1.2m，手臂完全收缩
- 末端当前位置：p_0 = [0.5, 0.0, 0.3] m（相对基座）
- 目标：移动苹果到碗的位置 p_goal = [0.8, 0.3, 0.25] m

**Step 1 — VLA 联合生成**：

VLA 从噪声出发，经过流匹配去噪（σ=1→0），输出：

```
计划轨迹 τ_hat (H=4 简化版):
  τ_0 = [0.50, 0.00, 0.30, q_0]  (当前位置)
  τ_1 = [0.58, 0.05, 0.30, q_1]  (基座开始前移)
  τ_2 = [0.70, 0.15, 0.28, q_2]  (基座靠近+手臂伸展)
  τ_3 = [0.80, 0.30, 0.25, q_3]  (到达碗上方)

初始动作 a_hat (H=4):
  a_hat = [v_base=0.15, θ_arm1=0.2, θ_arm2=-0.1, ...]
```

**Step 2 — 候选采样**：

以 a_hat 为中心，用 AR(1) 过程采样 N-1=29 个扰动候选：

```
候选 #1: a_hat + ε_1,  ε_1 ~ N(0, 0.05²), ρ=0.9
候选 #2: a_hat + ε_2,  ...
...
候选 #29: a_hat + ε_29
```

**Step 3 — 世界模型并行预测**：

GRU 世界模型对 30 个候选并行推理（batch dimension），每个输出预测的末端轨迹：

```
W_φ(o, s, a_hat)   → τ̃_0 = [0.50, 0.00, 0.30, ..., 0.75, 0.25, 0.26]
W_φ(o, s, a_hat+ε_1) → τ̃_1 = [0.50, ..., 0.72, 0.22, 0.24]
W_φ(o, s, a_hat+ε_5) → τ̃_5 = [0.50, ..., 0.80, 0.30, 0.25] ← 最接近 τ_hat!
```

**Step 4 — 打分选择**：

```
Score(a_hat)   = 0.5 × S_traj(τ_hat, τ̃_0) + 0.5 × 1e-3 × S_smooth(a_hat)
               = 0.5 × 0.82 + 0.5 × 1e-3 × 0.95 = 0.4105

Score(a_hat+ε_5) = 0.5 × 0.95 + 0.5 × 1e-3 × 0.92 = 0.4751 ← 最高!

→ 执行 a_hat + ε_5
```

**直觉**：初始动作 a_hat 的计划末端是 [0.75, 0.25, 0.26]，但世界模型预测它实际只会到 [0.75, 0.25, 0.26]——差了 5cm。候选 #5 的世界模型预测末端是 [0.80, 0.30, 0.25]，完美匹配计划轨迹，所以被选中。这就是"计划-执行对齐"的核心：不是选动作最大的，而是选"实际效果最符合预期"的。

**关键 trade-off**：

- **候选数 N vs 延迟**：N=30 是经验值。增大 N 可提高找到最优候选的概率，但世界模型推理时间线性增长。在 RTX 4090 上 30 个候选并行仅增加 11.75ms，说明 batch 并行效率很高。
- **轨迹空间 vs 像素空间**：世界模型在 7D 位姿空间（112 维）操作而非像素空间（如 256×256×3 = 196,608 维），参数量从可能的数百 M 降到 49M。这是工程上最关键的决策——没有这个降维，测试时搜索不可行。
- **GRU vs Transformer/Diffusion**：论文对比了 4 种世界模型架构（§4.4）。GRU 在 xyz ADE (0.028m) 和角 ADE (6.2°) 上最优，Diffusion 在 geodesic ADE 上匹配但位置和角误差更大。GRU 的序列建模能力对 H=16 的短期预测已经足够，且推理更快。
- **不 Retraining**：世界模型作为插件挂载，不需要重新训练 VLA。这意味着可以逐步部署：先上线轨迹引导 VLA，再按需挂载世界模型。

### 6.1 隐含假设 (Hidden Assumptions)

1. **块局部坐标系锚定假设**：轨迹在整个 horizon 内锚定在 replanning 时刻的基座姿态。这假设基座在 horizon 内不会发生剧烈的不可预测位移。如果地面湿滑或基座打滑，轨迹坐标系的"固定性"假设失效。

2. **世界模型的马尔可夫假设**：W_φ 只依赖当前观测 o_t、状态 s_t 和候选动作 a_t:t+H-1，不依赖历史。对于接触历史敏感的任務（如摩擦累积效应），这可能不够。

3. **候选采样的充分性**：AR(1) 高斯过程采样假设最优动作在初始动作的局部邻域内。如果初始动作偏差很大（如 VLA 对任务理解错误），采样可能覆盖不到正确的动作区域。

4. **打分函数的线性组合**：λ·S_traj + (1-λ)·η·S_smooth 假设轨迹一致性和平滑度可以线性权衡。但在某些场景下（如紧急避障），可能需要非线性优先级。

## 7. 与相关工作对比 (Comparison)

| 方法 | 未来表示 | 在动作生成中的角色 | 移动操作 | 计划-执行对齐 |
|------|---------|-------------------|---------|-------------|
| DTP (2025) | 2D 像素轨迹 | 独立引导策略学习 | × | × |
| MoManipVLA (2025) | 3D 位姿轨迹 | 外部输入给基座-手臂优化器 | ✓ | × |
| DINO-WM (2024) | Latent 特征 | Rollout 用于规划 | × | × |
| V-JEPA-AC (2025) | Latent 视频 | 预测用于规划 | × | × |
| **DreamTrajectory** | **3D 位姿轨迹** | **联合生成 + 测试时精炼** | **✓** | **✓** |

**关键差异**：

- **vs MoManipVLA**：MoManipVLA 用外部 3D 轨迹作为基座-手臂优化器的输入，是串行两阶段流程。DreamTrajectory 在单一 action expert 中联合生成轨迹和动作，通过 group-causal attention 实现端到端训练，避免了串行误差累积。
- **vs DTP**：DTP 用 2D 像素轨迹引导策略学习，但轨迹和动作是分离的训练过程。DreamTrajectory 在 3D 位姿空间操作，且轨迹和动作联合生成。
- **vs 世界模型方法 (DINO-WM, V-JEPA-AC)**：这些方法在 latent/像素空间预测未来，参数量大且难以直接与动作对齐。DreamTrajectory 在紧凑的 7D 位姿空间预测，使测试时搜索可行。

💡 **面试 Tip**：当被问到"DreamTrajectory 和 MoManipVLA 的区别"时，回答："MoManipVLA 是串行两阶段——先规划轨迹再优化动作，误差会累积；DreamTrajectory 在单一 Transformer 中联合生成，用 group-causal attention 让轨迹显式引导动作去噪，端到端可微。此外 DT 多了测试时世界模型对齐层，这是 MoManipVLA 没有的。"

## 8. 精讀建議 (Reading Guide)

**值得精讀原文的人**：
- 做多移动操作/全身控制 VLA 的研究者——轨迹引导+世界模型对齐是当前移动操作 VLA 最完整的方案之一
- 要评估在现有 π0 系列 VLA 上挂载测试时精炼模块可行性的工程师——49M 参数的世界模型 + 11.75ms 延迟是务实的工程选择
- 对流匹配 (flow matching) 多流联合去噪感兴趣的研究者——group-causal attention mask 的设计可直接复用到其他多输出场景

**建議章節路徑**：
- 先读 §3.2（轨迹引导动作生成）→ 理解双流流匹配和 group-causal attention
- 再看 §3.3（测试时精炼）→ 理解世界模型如何打分选候选
- 可跳过 §2（相关工作）——除非你需要写 related work
- 建议补充阅读 supplementary materials（论文多次提到详细公式在附录）

**不值得精讀的理由**：
- 如果你不做移动操作（只关心固定基座桌面操作），核心创新（基座-手臂协调引导）与你无关
- 如果你已经熟悉 π0 流匹配框架，§3.2 的流匹配部分没有太多新内容——新的是双流联合和 group-causal mask
