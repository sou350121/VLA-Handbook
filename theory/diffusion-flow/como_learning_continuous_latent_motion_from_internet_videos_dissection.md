## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练/推理差异 |
|------|------|------|-----------|---------------|
| IDM (逆动力学编码器) | 当前帧 Ot, 未来帧 Ot+n | 连续运动表示 Zt,t+n | 每帧对一次 | 训练时用 Td+Tcl，推理时仅前向 |
| FDM (正动力学解码器) | Zt,t+n, Ot | 重建未来帧 Ôt+n | 与 IDM 同步 | 仅训练时用，推理不需要 |
| 统一策略头 (动作) | 视觉 + 语言特征 | 机器人动作 at | 每控制步 | 扩散：1000 步训练/5 步推理；自回归：分块预测 |
| 统一策略头 (运动) | 视觉 + 语言特征 | 潜在运动 zt | 每控制步 | 与动作头共享 backbone，独立 MLP 输出 |

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **早期时序差分 (Td)**：传统 IDM 直接编码未来帧 Ft+n，模型会"偷懒"把静态背景也编码进去（因为解码器重建更容易）。CoMo 在编码器输入前就做 Ft+n - Ft 差分，显式增强运动信号同时增加捷径学习难度。

2. **时序对比学习 (Tcl)**：仅用 Td 会导致表示稀疏且含无关信息。Tcl 用 InfoNCE 损失让模型区分"正向时序"和"反向时序"——正样本对是 $(Z_{t,t+n+\delta}, Z_{t,t+n})$，负样本对是时序反转的 $(Z_{t,t+n+\delta}, Z_{t+n,t})$。这迫使表示捕捉"如何运动"而非"物体在哪"。

3. **协同效应**：单独 Td $\to$ 稀疏但有噪声；单独 Tcl $\to$ 可能只学物体身份忽略运动模式；两者结合 $\to$ 聚焦前景 + 结构化运动 cues。

⚡ **Eureka Moment**：连续表示本身不是创新，创新在于**在不使用向量量化的前提下，用 Td+Tcl 双机制解决了连续表示的捷径学习问题**——这让连续分布的潜在运动能与连续分布的机器人动作无缝联合训练。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L_total = L_tcl + λ₁·L_recon + λ₂·L_perceptual
```

其中 L_tcl 是时序对比损失，L_recon 是未来帧重建损失，L_perceptual 是感知损失。

### 2.1 时序对比学习 (Tcl) 公式

```
S₁ = S(Zt,t+n+δ, Zt,t+n)           # 正样本对相似度
S₂ = S(Zt,t+n+δ, Zt+n,t)           # 负样本对 1（时序反转）
S₃ = S(Zt,t+n, Zt+n,t)             # 负样本对 2（时序反转）

L_tcl = -log(e^S₁ / (e^S₁ + e^S₂ + e^S₃))
```

变量说明：
- `Zt,t+n`：从当前帧 Ot 到未来帧 Ot+n 的运动表示
- `δ`：小时间偏移，范围 [-n/5, n/5]
- `S(·,·)`：余弦相似度
- `Zt+n,t`：时序反转的表示（从未来到当前）

直觉：正样本对是"稍微更远的未来 vs 当前未来"，负样本对是"未来 vs 过去"。模型必须学会区分运动方向而非仅识别物体。

### 2.2 早期时序差分 (Td) 操作

```
Ft = ViT(Ot)                       # 当前帧特征
Ft+n = ViT(Ot+n)                   # 未来帧特征
Dt = Ft+n - Ft                     # 时序差分（元素级减法）
输入编码器 = [Ft, Dt]              # 拼接，而非直接用 Ft+n
```

> 符号与本文/相关文档保持一致：Z 表示运动表示，F 表示 ViT 特征，D 表示时序差分，O 表示观测帧

### 2.3 S-PCFC 评估指标

```
S-PCFC(t) = z(ot-n, ot)ᵀ · z(ot+n, ot) / (‖z(ot-n, ot)‖₂ · ‖z(ot+n, ot)‖₂)
```

直觉：在运动主导的数据集上，"过去$\to$当前"和"未来$\to$当前"的运动表示应该相似（都是描述当前时刻的运动状态）。若 S-PCFC 过高（接近 $1.0$），说明表示中含有大量与运动无关的静态背景噪声。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有一个 2D 抓取场景：
- 当前帧 Ot：机械手在物体左侧
- 未来帧 Ot+n：机械手已抓取物体

**传统离散方法（如 LAPA）**：
1. 编码器提取 Ft 和 Ft+n
2. 通过 VQ-VAE 量化到 codebook（如 8 个码）
3. 输出离散码序列：[3, 5, 2, ...]
4. 问题：精细的抓取力度变化被量化丢失

**CoMo 连续方法**：
1. ViT 提取 Ft 和 Ft+n（768 维 token 特征）
2. Td 操作：Dt = Ft+n - Ft（差分后背景静态区域接近 0）
3. 输入 [Ft, Dt] 到 Motion Q-former
4. 输出连续向量 Zt,t+n（如 128 维）
5. Tcl 约束：确保 $Z_{t,t+n}$ 与 $Z_{t,t+n+\delta}$ 相似，与 $Z_{t+n,t}$ 不相似
6. 最终 Zt,t+n 可用于：
   - 训练 MLP 回归真实动作（MSE 评估）
   - 与机器人动作数据联合训练扩散策略

**数值示例**（来自论文 Table 1）：
- 离散方法 (Dis.)：LIBERO 成功率 75.9%，MSE 未知，S-PCFC 最低（但信息损失大）
- CoMo (Con.+Td+Tcl)：LIBERO 成功率 80.1%，MSE 最低，S-PCFC 低（连续方法中）
- 朴素连续 (Con.)：S-PCFC $\approx 0.93$（接近 $1.0$，说明大量背景噪声）

## 4. 工程视角 (Engineering View)

| 工程维度 | CoMo 设计选择 | 含义/Trade-off |
|----------|---------------|----------------|
| **表示维度** | $128\to512$ 可扩展 | 仅 Td 时维度增加会导致 S-PCFC 上升（噪声增加）；加 Tcl 后维度增加 MSE 持续下降 |
| **推理延迟** | IDM 仅训练时用 | 推理时策略直接用预提取的 zt，无额外开销 |
| **训练稳定性** | Td+Tcl 协同 | 单独 Td 或 Tcl 都不如组合稳定（论文 Table 1/2 显示组合最优） |
| **数据效率** | 120k 视频预训练 | SAM-V/EgoVid/Droid 各 4 万，覆盖 in-the-wild/第一人称/机器人场景 |
| **策略架构兼容** | 扩散 + 自回归均支持 | 扩散：1000 步训练/5 步 DPM-Solver++ 推理；自回归：动作分块 5/运动分块 2 |
| **控制频率** | 20Hz（真实世界） | 从原生 100Hz 降频以平衡训练效率和运动连续性 |
| **动作空间** | 相对 SE(3) + 夹爪 | 真实世界：3D 位置 + 四元数姿态 + 夹爪状态 = 7 维 |

**部署约束**：
- IDM 推理仅需一次离线提取（视频数据），策略推理无额外开销
- 扩散策略推理需 5 步采样（相比 1000 步训练大幅加速）
- 自回归策略需维护 KV cache，延迟随序列长度增长

### 5.3 评估指标

| 指标 | 用途 | 计算方式 | 理想值 |
|------|------|----------|--------|
| **成功率 (S.R.)** | 最终策略性能 | 任务完成次数 / 总试验次数 | 越高越好 |
| **MSE** | 运动表示的动作信息编码能力 | MLP 从 zt 回归 at 的均方误差 | 越低越好 |
| **S-PCFC** | 动作无关背景噪声诊断 | 过去$\to$当前与未来$\to$当前表示的余弦相似度 | 连续方法中越低越好 |

> 关键发现：单独降低 MSE 或 S-PCFC 都不保证策略性能提升，两者都较低时策略成功率最高（Finding 5）

### 6.1 隐含假设 (Hidden Assumptions)

1. **视频帧率与控制频率匹配**：假设视频帧间变化与机器人控制步长语义对齐（实际可能需时间对齐预处理）
2. **前景运动主导**：假设视频中存在可学习的前景运动模式（若视频全是静态场景则方法失效）
3. **单一相机视角**：假设单目视频足够提取运动表示（多视角可能提供更鲁棒的表示）
4. **动作连续性**：假设机器人动作是连续的（离散动作空间如抓取/释放状态可能需额外建模）
