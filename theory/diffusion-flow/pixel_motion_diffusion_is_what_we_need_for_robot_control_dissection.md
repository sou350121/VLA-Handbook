### 1.2 关键机制 (Key Mechanism)

**为什么用像素运动而不是视频帧预测？**
- 视频帧预测需要生成完整 RGB 图像，计算开销大且包含大量与动作无关的背景信息
- 像素运动场（optical flow 类似表示）只编码"哪里往哪里移动"，更紧凑且直接对应动作意图
- 人类可以直观理解像素运动：箭头指向 = 物体移动方向

**为什么两级扩散而不是一级端到端？**
- 解耦高层意图（运动）和低层执行（动作），便于调试和可视化
- Motion Director 可以独立预训练在视频数据上，Action Expert 专注机器人控制
- 但两级仍可端到端联合微调，保持端到端优化的优势

⚡ **Eureka Moment**：像素运动是"刚好足够抽象"的中间表示——比原始像素更紧凑，比关节角度更通用，且天然适合扩散模型建模。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
p(action | obs, text) = ∫ p(action | flow, obs, text, state) · p(flow | obs, text) dflow
```

**公式解读**：
- 左边：传统端到端方法直接建模的条件概率
- 右边：DAWN 的两级分解——先预测像素运动 flow，再基于 flow 预测动作
- 积分符号表示 flow 是隐变量，两级扩散分别近似两个条件分布

**扩散过程形式化**：

Motion Director 的逆向过程：
```
flow_{t-1} = √α_t · flow_t + (1 - α_t) · ε_θ(flow_t, t, img, text)
```

Action Expert 的逆向过程：
```
action_{t-1} = √α_t · action_t + (1 - α_t) · ε_φ(action_t, t, flow, img, text, state)
```

**变量说明**：
| 符号 | 含义 | 维度示例 |
|------|------|----------|
| flow | 像素运动场 | $(T, H, W, 2)$ — $T$ 步未来，$H \times W$ 像素，2 通道 $(dx, dy)$ |
| action | 机器人动作 | (H, D) — H 步未来，D 维关节空间 |
| $\varepsilon_\theta$, $\varepsilon_\phi$ | 两个扩散模型的噪声预测网络 | U-Net / Transformer |
| $\alpha_t$ | 扩散调度系数 | 标量，随 timestep t 递减 |

> 符号与本文/相关文档保持一致：flow 指像素运动（类似光流但预测未来），action 指机器人关节动作或末端执行器位姿。

**直觉**：把动作生成拆成两步——先想清楚"场景里什么东西该往哪里动"（Motion Director），再决定"我的机械臂该怎么动才能实现这个运动"（Action Expert）。第一步是任务层面的理解，第二步是执行层面的映射。

## 3. 带数字走一遍：玩具例子 (Worked Example)

**场景**：机械臂需要"拿起桌上的蓝色积木"

**步骤 1：Motion Director 预测**
- 输入：当前 RGB 图像（$640 \times 480$）+ 文本指令 "pick the blue block"
- 输出：未来 8 帧的像素运动场（$8 \times 640 \times 480 \times 2$）
- 可视化：图像中蓝色积木区域的像素被预测为"向上移动"，机械臂夹爪区域被预测为"向下然后闭合"

**假设数值**（简化 2D 示例）：
```
t=0 时刻，蓝色积木中心像素坐标 (320, 240)
Motion Director 预测：
  flow[0:8, 320, 240, :] = [(0, -2), (0, -4), (0, -6), ..., (0, -16)]
  # y 坐标递减 = 向上移动（图像坐标系）
```

**步骤 2：Action Expert 消费运动预测**
- 输入：上述 flow + 原图 + 文本 + 当前关节角度 [q1, q2, q3, q4, q5, q6]
- 输出：未来 16 步的关节动作（$16 \times 6$）
- 推理：Action Expert 学到"当积木区域像素向上移动时，夹爪应该先下降再闭合再上升"

**步骤 3：执行与闭环**
- 执行前 2 步动作（其余丢弃，MPC 式滚动时域）
- 观察新帧，重复步骤 1-2

**关键闭环**：如果 Motion Director 预测错误（如积木实际没动），下一帧的 flow 预测会修正，Action Expert 随之调整动作——这是端到端可训练的优势。

## 4. 工程视角 (Engineering View)

**计算开销**：
- Motion Director：单次扩散推理约 50ms（25 步 DDIM，RTX 4090）
- Action Expert：单次扩散推理约 30ms（15 步 DDIM）
- 总延迟：~80ms / 12.5Hz —— 对桌面操作足够，对高速动态任务可能不足

**优化策略**：
- 论文使用潜在扩散（latent diffusion）而非像素空间扩散，减少 $4 \times$ 计算量
- 可蒸馏为单步策略（如 consistency model）进一步提升速度

**内存占用**：
- 模型参数：Motion Director ~200M，Action Expert ~150M
- 推理时显存：~4GB（batch=1，包括中间特征）

**部署约束**：
- 需要 GPU 推理（论文未测试边缘设备）
- 真实世界迁移只需少量微调（论文用 100 条真实演示在 30 分钟内完成适配）

**工程含义**：像素运动表示的 trade-off——增加了一个中间模块的计算开销，但换来了可调试性和跨任务泛化能力。对于研究场景值得；对于产品部署需评估速度要求。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- 语言条件的桌面操作任务（抓取、放置、推拉、开合容器）
- 长序列多任务（CALVIN 平均 4.1 个连续任务）
- 跨场景泛化（CALVIN ABC-D 域偏移测试）
- 真实世界迁移（少量微调后成功执行未见过的物体）

**不能做什么**：
- 高速动态任务（如接抛球）—— 80ms 延迟过高
- 需要深度/力觉反馈的任务（如精密装配、柔顺控制）—— 纯视觉输入
- 长时程规划任务（如"整理整个桌面"）—— 只支持短序列（8 帧运动 + 16 步动作）

### 6.1 隐含假设 (Hidden Assumptions)

**X-Ray 批判视角**：
1. **视觉主导假设**：假设像素运动足以编码任务意图——对透明物体、镜面反射、低纹理场景可能失效
2. **刚性物体假设**：像素运动场对可变形物体（如布料、线缆）表达力不足
3. **单视角假设**：假设单目 RGB 足够——对遮挡严重场景，多视角或深度信息可能必要
4. **语言简洁假设**：指令是简短命令式（"pick blue block"），对复杂组合指令（"先拿蓝色再拿红色但不要碰绿色"）未测试
