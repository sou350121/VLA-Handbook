## 1. 核心架构/方法总览 (Overview / Architecture)

WorldDP 是一个双层 MPC 框架：高层用对象中心世界模型规划子目标序列，低层用目标条件扩散策略执行这些子目标。

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 训练方式 | 推理角色 |
|------|------|------|----------|----------|
| DINOv2 Encoder | RGB 图像 224×224 | Patch features (P, d) | 冻结预训练 | 特征提取 |
| Object-Centric Encoder (OCE) | Patch features + N slots | Object slots s ∈ R^(N×d) | SAM2 引导 + L2 + Tversky | 状态编码 |
| CDiT Dynamics Model | Object slots + 动作序列 | 预测下一状态 | 教师强制 MSE | 世界模型过渡函数 |
| Contact Predictor | Object slot s_k | (N-2) 维接触概率 | MLP 训练 | MPC 成本函数 |
| Particle Filter Planner | 初始状态 + 目标图像 | 最优子目标序列 | 在线优化 | 高层规划 |
| Diffusion Policy | 当前状态 + 子目标 | 40 步动作序列 | 模仿学习 | 低层执行 |

### 1.2 关键机制 (Key Mechanism)

**为什么用对象中心而不是 patch-level？**
- Patch-level（如 DINOv2 的 14×14=196 个 patch）在切割时丢失小对象（如 10×10 像素的方块）的细粒度信息
- 对象中心表征将环境分解为 N 个独立实体（机器人、背景、各物体），每个实体有独立向量
- 这使得 MPC 可以针对单个物体做优化——"只移动红色方块"而不是"改变整张图"

**为什么用粒子滤波而不是 CEM？**
- CEM（Cross-Entropy Method）假设动作空间是单峰高斯分布
- 机器人任务本质是多峰的：到达同一目标可以有多种完全不同的运动轨迹
- 粒子滤波维护 Q 个独立假设（粒子），保留多模态解空间

⚡ **Eureka Moment**: 世界模型不应该直接输出动作——它应该把多阶段任务分解为扩散策略可以逐个追踪的子目标序列。世界模型做"要到哪里"的推理，扩散策略做"怎么到那里"的执行。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
C(s_hat_T, s_g) = (1/((N-2)*d)) * ||o_g - o_hat_T||^2  +  λ_plan * CE(c, c_ref)
```

**目标**: 在粒子滤波优化中找到一组动作序列，使得世界模型预测的最终状态与目标状态在对象空间中最接近，同时接触信号与期望一致。

**公式分解**:

第一项 — 对象距离成本：
```
C_dist = (1 / ((N-2) * d)) * ||o_g - o_hat_T^(q)||_2^2
```
- o_g: 目标状态中 N-2 个物体对象的嵌入向量（排除机器人和背景）
- o_hat_T^(q): 第 q 个粒子经 T 步自回归 rollout 后的预测对象嵌入
- 归一化因子 (N-2)*d 确保不同 N 和 d 设置下成本可比

第二项 — 接触预测成本：
```
C_ce(c^(q), c_ref) = CrossEntropy(contact_predictor(s_1^(q)...s_T^(q)), c_ref)
```
- c^(q) ∈ R^(N-2): 完整 rollout 轨迹的接触概率向量
- c_ref: one-hot 参考向量（目标物体接触=1，其余=0）
- 鼓励规划器生成"先接触目标物体"的子目标

**变量说明**:

| 符号 | 含义 | 维度 |
|------|------|------|
| N | 对象槽数量（含机器人+背景） | 标量 |
| d | 每个槽的特征维度 | 标量 |
| T | 世界模型规划步数 | 标量 |
| Q | 粒子数量 | 标量 |
| λ_plan | 接触成本权重 | 超参 |
| s_k | 时刻 k 的对象中心状态 | R^(N×d) |
| o_k | 排除机器人/背景的对象嵌入 | R^((N-2)×d) |
| a_k | 末端执行器动作 (x,y,z,yaw,gripper) | R^5 |

> 符号与本文保持一致：s 表示完整对象状态，o 表示纯物体子集，c 表示接触概率。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：2 个物体（红色方块 + 蓝色方块）+ 机器人 + 背景，N=4，d=768（DINOv2 特征维度）。

**初始状态**: 红方在 (1,1)，蓝方在 (3,3)
**目标状态**: 红方在 (4,4)，蓝方在 (2,2)

**Step 1 — 粒子初始化**:
- 生成 Q=50 个粒子，每个粒子是 T=5 步的动作序列
- 动作空间: 每步 (dx, dy, dz, dyaw, dgripper) ∈ R^5
- 种子从末端执行器到关键点的空间轨迹采样

**Step 2 — 单粒子 Rollout 示例**（粒子 q=7）:
```
s_0 = [robot_emb, bg_emb, red_emb@(1,1), blue_emb@(3,3)]

a_0 = (0.5, 0.3, 0, 0, 0)  → s_1 = CDiT(s_0, a_0) = [robot_emb', bg_emb', red_emb'@(1.5,1.3), blue_emb@(3,3)]
a_1 = (0.4, 0.2, 0, 0, -0.1) → s_2 = CDiT(s_1, a_1) = [robot_emb'', bg_emb'', red_emb''@(1.9,1.5), blue_emb@(3,3)]
...
s_5 = CDiT(s_4, a_4) = [robot_emb^(5), bg_emb^(5), red_emb@(3.2,3.8), blue_emb@(3.3,3.1)]
```

**Step 3 — 成本计算**:
```
o_g = [red_target@(4,4), blue_target@(2,2)]
o_hat_5^(q=7) = [red_pred@(3.2,3.8), blue_pred@(3.3,3.1)]

C_dist = (1/(2*768)) * ||o_g - o_hat_5||^2
       ≈ (1/1536) * (||[4,4]-[3.2,3.8]||^2 + ||[2,2]-[3.3,3.1]||^2)
       ≈ (1/1536) * (1.28 + 2.69) ≈ 0.0026

Contact: 假设粒子 7 的接触轨迹 c = [0.3, 0.1]（红方接触概率低，蓝方更低）
c_ref = [1, 0]（目标是先接触红方）
C_ce = CE([0.3, 0.1], [1, 0]) ≈ 1.2 (高惩罚)

Total Cost = 0.0026 + 1.0 * 1.2 ≈ 1.2026
```

**Step 4 — 选择**:
- 50 个粒子中，成本最低的 M=5 个作为下一轮均值
- 经过 L=10 轮迭代，最优粒子的子目标序列被提取
- 假设最优子目标: [ŝ_1^o: 接近红方, ŝ_2^o: 抓住红方, ŝ_3^o: 放置红方到(4,4), ...]

**Step 5 — 扩散策略执行**:
- DP(curr_obs=初始帧, subgoal=ŝ_1^o) → 40 步动作 → 执行 → 新观测
- DP(curr_obs=新帧, subgoal=ŝ_2^o) → 40 步动作 → 执行
- ...直到所有子目标完成

## 4. 工程视角 (Engineering View)

| 维度 | 数值/设计 | 工程含义 |
|------|-----------|----------|
| 图像分辨率 | 224×224 | 较低分辨率，适合实时推理但丢失小对象细节 |
| DINOv2 | 冻结，ViT-B/14 | 196 个 patch，特征维度 d=768 |
| 对象槽数 N | 取决于场景复杂度 | 越多槽 → 更多计算但更细粒度；论文未明确给出 N 值 |
| CDiT 深度 | 12 层，4 头注意力 | 中等规模，推理延迟可控 |
| 动作嵌入维度 | 32 | 高度压缩的动作表征 |
| 训练数据 | 200 万帧/环境 | 大量无标注 play 数据，无需 reward |
| 训练批次 | 128，5 epochs | 约 77,500 总步数（15,500/epoch × 5） |
| 硬件 | 单 H100 | 训练成本可控 |
| DP 动作序列长度 | 40 步 | 短 horizon 匹配子目标间距；DP100 反而略差 |
| 推理延迟 | 世界模型规划 (PF: Q×L 次 rollout) + DP 执行 | 规划是主要瓶颈；PF 比 CEM 更慢但质量更高 |
| 部署约束 | 需要 SAM2 预标注 | 新环境部署需额外标注步骤，非端到端 |

**关键 trade-off**:
- 对象中心表征提高了规划精度，但引入了 SAM2 标注依赖——如果 SAM2 分割质量差（如透明物体、重叠物体），OCE 表征会退化
- 粒子滤波比 CEM 更慢（维护 Q 个粒子 vs 单高斯），但在多峰动作空间中的解质量更高
- 40 步 DP horizon 恰好匹配子目标间距；更长 horizon（100 步）反而因为子目标太近而引入冗余

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**:
- 多阶段顺序操作：先按按钮→再开抽屉→再取物（Scene-Single-Composite 上 20% 成功率，基线接近 0%）
- 多物体重排：三个方块依次放置（Cube-Triple 3-Cubes 指标上超过基线 2 倍）
- 从目标图像推断任务：无需显式任务指令，仅靠 I_0 和 I_g 即可推断要操作哪个物体
- 从无标注 play 数据学习：不需要 reward、不需要 goal 标签

**不能做什么 / 失败模式**:
- 单阶段任务上不如专用方法：Cube-Single 上 72% vs DP100 的 98%——层次化设计对简单任务反而引入额外开销
- 依赖仿真环境：所有实验在 OGBench 仿真中完成，未部署真实机器人
- SAM2 标注依赖：新环境需要运行 SAM2 生成分割掩码，增加了部署链路
- 小对象可能欠表征：虽然 SAM2 引导缓解了这个问题，但极小物体（<15% patch 覆盖率）仍可能丢失

### 6.1 隐含假设 (Hidden Assumptions)

1. **SAM2 分割质量足够好**: 论文假设 SAM2 能可靠地将场景分割为机器人/背景/各物体。但在真实世界中，透明物体（玻璃杯）、半透明物体、重叠严重物体可能导致 SAM2 分割失败，进而影响 OCE 表征质量。作者未验证 SAM2 分割错误对最终性能的敏感度。

2. **对象数量 N 已知或可预设**: Slot 数量 N 是超参，需要预先设定。论文未讨论如何自动估计场景中的对象数量——如果 N 设小了，多个物体共享一个 slot；N 设大了，空 slot 可能引入噪声。

3. **静态外部相机**: 实验假设相机位置固定。如果相机移动（如眼在手上的相机），DINOv2 特征和 OCE 表征的稳定性需要重新验证。

4. **动作空间为末端执行器 delta**: 动作是 (x,y,z,yaw,gripper) 的增量命令。这个假设在大多数桌面操作场景中成立，但不适用于基座移动或双臂协同场景。

5. **子目标可独立执行**: 框架假设子目标序列可以被 DP 独立追踪。但如果子目标之间间距过小（世界模型规划步长 T 太小），DP 可能来不及完成一个子目标就被迫切换到下一个。
