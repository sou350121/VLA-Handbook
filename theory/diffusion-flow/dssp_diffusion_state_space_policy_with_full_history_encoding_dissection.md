💡 **X-Ray 开场**

扩散策略（Diffusion Policy）在机器人操作上表现强劲，但大多数方法只依赖当前观测或短期窗口来预测动作。在长程多阶段任务中，两个视觉上几乎相同的时刻可能对应完全不同的任务进度——比如"瓶子是否已被放入篮子"——只看当前帧的策略会混淆这些状态，导致重复动作或撤销已完成的操作。DSSP 的核心发现是：用 Mamba（一种线性复杂度的状态空间模型）把完整观测历史压缩成一个紧凑的上下文 token，再把这个上下文与近期观测组合成层级条件，注入到同样由 Mamba 实现的扩散去噪器中——结果不仅成功率大幅提升（长程任务 +21.4%，真机平均 +133%），而且模型更小、推理更快。

## 1. 核心架构/方法总览 (Overview / Architecture)

DSSP 将策略分解为三个核心组件：**因果历史编码器**（压缩全历史）、**动力学感知辅助学习**（确保上下文保留未来预测信息）、**层级条件扩散去噪器**（用 Mamba 生成动作）。

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 训练方式 | 推理行为 |
|------|------|------|----------|----------|
| 观测编码器 E_obs | 多模态观测 o_t（RGB +  proprio / 点云） | 状态表示 z_t | 与策略联合训练 | 每步编码当前观测 |
| 因果历史编码器 G (Mamba) | 状态序列 z_{1:t} | 上下文表示 c_t = z̃_t（最后一个 token） | 联合训练 + 动力学辅助损失 L_dyn | 流式更新，维护隐藏状态缓存 |
| 动力学预测器 g_φ | (c_t, a_t) | 下一状态预测 ẑ_{t+1} | 监督学习，cos 相似度损失 | 推理时不使用（仅训练） |
| 扩散去噪器 f_θ (Mamba) | 噪声动作 x_τ + 层级条件 C_t + timestep τ | 预测干净动作 x̂_0 | 扩散重建损失 L_diff | 多步去噪生成动作序列 |

**关键设计差异 vs DP3**：DP3 只用当前点云观测做条件；DSSP 用 [c_t, z_{t-N+1}, ..., z_t] 作为层级前缀条件，同时去噪骨干从 Transformer 换成 Mamba。

### 1.2 关键机制 (Key Mechanism)

- **因果 SSM 历史编码**：Mamba 的选择性状态更新机制让编码器能自适应地保留关键事件（物体状态变化、接触改变、子目标完成）而过滤冗余观测。线性时间复杂度意味着历史越长，相对优势越大。
- **动力学感知辅助目标**：压缩历史不自动等于保留有用信息。通过要求上下文 c_t 能预测"执行动作 a_t 后的下一状态"，迫使编码器保留对未来决策有预测力的历史线索。
- **层级前缀条件**：长程上下文 c_t 解决任务阶段歧义 + 近期状态 z_t 提供精细控制线索，两者拼接后作为前缀注入去噪器，避免长程信息在扩散过程中被稀释。
- **Timestep 解耦注入**：timestep 信息只通过 AdaLN 注入动作 token，不污染前缀条件——保持历史表征在整个去噪过程中稳定。

⚡ **Eureka Moment**：用同一个 Mamba 架构同时做历史编码器和扩散去噪骨干，架构统一不仅减少参数量，更让流式历史更新和扩散采样的计算模式天然匹配——这是"一个骨干干两件事"的设计哲学。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L(θ,ψ,φ) = L_diff(θ,ψ) + λ · L_dyn(ψ,φ)
L_diff = E[‖f_θ(x_τ, τ, [c_t, z_{t-N+1:t]}) − x_0‖²]
L_dyn  = E[1 − cos(g_φ(c_t, a_t), sg(z_{t+1}))]
```

**目标**：联合优化扩散去噪器（生成准确动作）和历史编码器（保留预测性上下文），两者通过共享的编码器参数 ψ 耦合。

**变量说明**：

| 符号 | 含义 |
|------|------|
| x_0 | 干净动作轨迹 a_{t:t+H_a-1} |
| x_τ | 第 τ 步加噪后的动作 |
| c_t | 历史编码器输出的上下文表示（单个 token） |
| z_t | 观测编码器输出的状态表示 |
| f_θ | Mamba 扩散去噪器 |
| g_φ | 轻量级动力学预测器 |
| sg(·) | stop-gradient（目标不反向传播） |
| λ | 辅助损失权重（论文中未给出具体值 → TODO） |

**直觉**：L_diff 保证动作生成质量，L_dyn 保证上下文 c_t 不是"被动记忆"而是"主动预测"——只有能预测下一状态的历史压缩才是有用的压缩。两者联合优化让编码器知道"该保留什么"。

> 符号与本文保持一致：POMDP 定义 M = (S, A, T, Ω, O)，策略 π_θ(a_t | h_t)，专家轨迹 D_E = {ζ_1, ..., ζ_N}。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 3 阶段任务：**拿 A → 放入容器 → 拿 B**。

**时刻 t=5**（刚完成"拿 A 放入容器"）：

- 当前观测 o_5：机械臂在容器上方，容器中有 A，工作台上还有 B
- 近期观测 o_3, o_4：类似场景（臂在容器附近）

如果策略只看 o_5（DP3 模式）：它看到"臂在容器上方"，可能重复"放下"动作——但 A 已经在容器里了。

DSSP 的处理流程：

```
步骤 1: 观测编码
  z_5 = E_obs(o_5) = [视觉特征: 臂在容器上, 本体: 手已松开]

步骤 2: 历史编码 (Mamba 流式更新)
  c_5 = G(z_1, z_2, ..., z_5)
  → Mamba 的选择性机制在 t=3 时记录了"抓取A"事件
  → 在 t=4 时记录了"移动到容器"事件
  → c_5 编码了"已完成阶段1"的信息

步骤 3: 层级条件构建
  C_5 = [c_5, z_3, z_4, z_5]  (N=3 近期窗口)

步骤 4: 扩散去噪
  x_0 = f_θ(x_τ, τ, C_5)
  → c_5 告诉去噪器"阶段1已完成，该去拿B了"
  → z_5 提供精细的"手臂当前位置"控制信息
  → 输出动作: 移动到工作台拿 B ✓

对比：无历史编码时
  条件 = [z_3, z_4, z_5]（无 c_5）
  → 三个近期观测都显示"臂在容器附近"
  → 策略混淆：可能重复放下动作 ✗
```

**动力学辅助目标的作用**：在训练时，g_φ(c_5, a_5) 被要求预测 z_6（下一步状态）。如果 c_5 不编码"阶段1已完成"这个信息，预测就会出错（因为不知道下一步该去拿 B），L_dyn 会惩罚这种压缩方式。

## 4. 工程视角 (Engineering View)

| 指标 | DSSP (Mamba 全历史) | Transformer 全历史 | 优势 |
|------|---------------------|-------------------|------|
| p95 编码延迟 | 1.97 ms | 3.61 ms | 快 45.4% |
| 峰值 GPU 内存 | 238.5 MB | 586.2 MB | 低 59.3% |
| 历史长度扩展性 | 近似常数（流式缓存） | 二次增长（注意力） | 线性 vs 二次 |

**关键工程含义**：

1. **控制频率友好**：1.97ms 的编码延迟意味着理论上可支持 ~500Hz 的历史更新频率（实际受扩散去噪多步采样限制）。
2. **内存可扩展**：峰值内存不随历史长度二次增长——这对部署在边缘设备（如 Jetson）上的机器人至关重要。
3. **流式推理**：推理时只需维护一个紧凑的隐藏状态缓存，不需要存储全部历史观测——内存占用与历史长度解耦。
4. **架构统一**：历史编码器和去噪骨干都是 Mamba，减少模型种类、简化部署管线。
5. **训练成本**：需要联合优化三个模块（编码器、预测器、去噪器），但辅助预测器 g_φ 是轻量级的，推理时不需要。

**Trade-off**：层级前缀条件增加了输入序列长度（c_t + N 个近期 token + 动作序列），但 Mamba 的线性复杂度使得这个开销可控。

### 6.1 隐含假设 (Hidden Assumptions)

1. **历史中的关键事件可被 SSM 的选择性机制捕获**：论文假设 Mamba 的 input-dependent selective update 能自动学会"什么该记住、什么该遗忘"，但没有可视化或量化分析 SSM 隐藏状态到底编码了什么信息。
2. **动力学预测与动作生成目标一致**：L_dyn 鼓励 c_t 保留能预测下一状态的信息，但"可预测下一状态"的信息不一定都是"对动作生成有用"的信息——可能存在信息冗余或目标冲突。论文用 λ 加权但没给出调参细节。
3. **点云观测足够表征任务状态**：DSSP 使用点云作为主要观测（与 DP3 一致），但没有对比 RGB-only 或 RGB+点云 的性能差异。
4. **50 demonstrations 足以学习长程策略**：长程任务通常需要更多演示来覆盖所有可能的历史路径，50 demo 可能不足以覆盖长程任务的分布。
