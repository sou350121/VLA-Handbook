💡 **X-Ray 開場**
長視角機器人操作很少「瞬間崩潰」——它是一個漸進螺旋：一步抓錯 → 狀態偏移 → 下一步更糟 → 越過不可逆臨界點。AEGIS 的核心發現是：這個螺旋在早期就能被預測，而且預測信號就藏在弱策略自己的神經激活裡。對 VLA 研究者來說，這意味著「安全」不一定需要重新訓練模型——可以作為一個即插即用的運行時層疊加在現有系統上。

### 1.2 關鍵機制 (Key Mechanism)

AEGIS 由四個模塊組成，形成一個從「感知風險」到「執行升級」的完整鏈路：

1. **激活探針（Activation Probe）**：在弱策略的 layer-15 action expert 輸出投影處掛 forward hook，對 H=10 的動作塊做 mean-pool，得到 720 維特徵 h_t，送入 2 層 MLP 輸出失敗概率 s_t。
2. **共形觸發閾值（Conformal Trigger）**：用 split-conformal 校準，在「不會失敗」的軌跡早期窗口數據上，確定每步閾值 δ_t，控制偽觸發率 α=0.10。
3. **早期傷害門（Early-Harm Gate）**：抑制 t < t_min = max(0.20T, 2) 的升級，防止策略剛啟動就盲目切換。
4. **預算上限（Budget Cap）**：每 episode 最多 K_max = ceil(0.05T) 次觸發，按信號強度排序。

⚡ **Eureka Moment**：弱策略自己的神經激活就是一個足夠好的早期預警信號——不需要額外的世界模型、不需要 MC dropout、不需要 token logit entropy，只需要在 action expert 的內部表示上訓練一個 2 層 MLP。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：
```
esc_t = 1[s_t ≥ δ_t] · 1[t ≥ t_min] · 1[Σ_{u≤t} esc_u ≤ K_max]
```

**目標**：在每一步 t 做出一個二元升級決策 esc_t，使得：
- 在失敗發生前及時切換到強策略
- 不浪費強策略的計算資源
- 不干擾原本會成功的軌跡

**公式分解**：

| 項 | 含義 | 作用 |
|----|------|------|
| 1[s_t ≥ δ_t] | 共形觸發 | 風險分數超過校準閾值才觸發 |
| 1[t ≥ t_min] | 早期傷害門 | t_min = max(0.20T, 2)，防止啟動階段誤觸發 |
| 1[Σ esc_u ≤ K_max] | 預算上限 | K_max = ceil(0.05T)，防止單一 episode 過度升級 |

**探針分數**：
```
h_t = mean-pool_{j=1}^{H} a^{(ℓ=15)}_{t,j}    ∈ R^720
s_t^probe = g_θ(h_t)                           ∈ (0,1)
```

其中 g_θ 是 [720→256→1] 的 2 層 MLP，用二元交叉熵訓練，標籤是軌跡最終成敗（fail=1）。

**共形閾值**：
```
δ_t = Quantile_{1-α}({s_u^cal : u ∈ calibration set})
其中 α = 0.10（目標偽觸發率）
```

> 符號說明：T = 軌跡總步數；H = 動作塊長度（=10）；ℓ = 探針掛載層（=15）；d = 特徵維度（=720）；K_max = 每 episode 最大觸發次數。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

假設一個 LIBERO-Spatial 任務，軌跡長度 T = 100 步，動作塊 H = 10。

| 步 t | h_t (720d) | s_t^probe | δ_t (α=0.10) | t ≥ t_min? | 觸發計數 | esc_t | 動作 |
|------|-----------|-----------|-------------|-----------|---------|-------|------|
| 1 | [0.12, ...] | 0.15 | 0.72 | ❌ (t<20) | 0 | 0 | π_w |
| 10 | [0.18, ...] | 0.22 | 0.70 | ❌ (t<20) | 0 | 0 | π_w |
| 20 | [0.35, ...] | 0.55 | 0.68 | ✅ | 0 | 0 | π_w |
| 30 | [0.52, ...] | 0.73 | 0.65 | ✅ | 0 | **1** | **切換→π_s** |
| 31-59 | — | — | — | ✅ | 1 | 1 | π_s (保持3 chunks) |
| 60 | [0.28, ...] | 0.40 | 0.62 | ✅ | 1 | 0 | 回退→π_w |

**解讀**：
- t=30 時，探針分數 s_t=0.73 超過閾值 δ_t=0.65，且 t ≥ t_min=20，觸發計數未達上限 → esc_t=1
- 在下一個 chunk 邊界（t=30）切換到 π_s
- π_s 至少保持 k=3 個 chunks（30 步），之後若信號下降則回退到 π_w
- 整個過程強策略只在「需要的時候」工作，而非全程運行

## 4. 工程視角 (Engineering View)

| 維度 | 數值/ trade-off | 工程含義 |
|------|----------------|---------|
| 探針推理開銷 | 2 層 MLP [720→256→1]，極低 | 可忽略，每步增加 <1ms |
| 強策略 duty cycle | 38%（確認實驗 n=700） | 相比 always-strong 節省 ~62% 計算 |
| 強策略計算倍率 | ~4.6× 弱策略 | 若 always-strong，計算成本增加 4.6 倍 |
| 動作塊長度 | H=10（控制頻率 ~10Hz） | 切換延遲最多 1 個 chunk（~100ms） |
| 保持時間 | k=3 chunks = 30 步 | 防止頻繁切換抖動 |
| 探針訓練數據 | 離線 rollouts，70/15/15 分裂 | 不需在線收集，部署前一次性完成 |
| 探針泛化 | 未測試跨任務/跨機器人 | 每個新場景可能需要重新校準 |
| 內存佔用 | 需同時載入 π_w 和 π_s | 雙模型駐留內存，對邊緣設備不友好 |

**部署約束**：
- 需要同時加載兩個 VLA 模型（450M + 4.14B），邊緣設備（如 Jetson）可能內存不足
- 切換延遲受動作塊長度限制，最小 ~100ms（H=10, 10Hz 控制）
- 探針校準需要每個新場景的離線 rollouts 數據

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

### 能做什么
- **漸進式失敗恢復**：對「一步錯、步步錯」的長視角操作有效，在不可逆臨界點前攔截
- **計算效率**：以 38% 的強策略佔用率達到 ~2× 盲目升級的恢復效果
- **即插即用**：不修改 π_w 和 π_s 的權重，只訓練一個小探針頭
- **因果驗證**：通過預算匹配對照實驗證明收益來自「時機選擇」而非「額外計算」

### 不能做什么
- **單一策略內部恢復**：如果沒有更強策略可用，AEGIS 無法工作（這是 HELM/Pre-VLA 的領域）
- **跨任務泛化**：探針在特定任務/機器人上訓練，未測試跨場景遷移
- **極端 OOD 場景**：探針在早期窗口（≤30%T）訓練，對訓練分佈外的失敗模式可能無效
- **即時響應**：切換延遲受動作塊長度限制，最小 ~100ms，不適合高動態場景

### 6.1 隱含假設 (Hidden Assumptions)

1. **強策略在弱策略失敗的場景中確實更可靠**——這是整個方法的前提，但論文沒有分析強策略在哪些類型的失敗上也無能為力
2. **弱策略的激活攜帶足夠的失敗預警信息**——在 SmolVLA 上成立（AUROC 0.764），但對其他架構（如純 diffusion policy）是否成立未知
3. **失敗是漸進的而非突發的**——如果失敗由單一外部干擾（如人碰倒物體）導致，早期窗口可能沒有預警信號
4. **兩個策略的動作空間和坐標系一致**——切換需要在同一控制框架下，否則需要額外的動作映射
5. **離線訓練的探針能泛化到在線部署**——探針用離線 rollouts 訓練，但在線分佈可能因環境微小變化而偏移
