### 1.2 關鍵機制 (Key Mechanism)

**為什麼這樣設計？**

1. **合成中介推理（Synthesis-mediated Reasoning）**：單張閉合圖像存在嚴重歧義（同一外觀可能對應多種關節解釋）。通過合成一個"最大化打開"的狀態，暴露原本被遮擋的運動線索，將欠約束的單圖回歸轉化為有雙狀態證據的差異估計。

2. **3D 提升（3D Lifting）**：2D 圖像空間的差異不足以可靠估計 3D 關節軸向。使用預訓練的 VGGT（Visual Geometry Grounded Transformer）將圖像對提升為密集 3D 點圖，從而在世界坐標系中推理關節幾何。

3. **集合預測（Set Prediction）**：不預設關節數量，用 K=16 個查詢槽位同時預測所有關節，通過匈牙利匹配與真值對齊，未匹配槽位優化為"固定"類別。

⚡ **Eureka Moment**：這篇論文最核心的想法是——**與其用先驗（mask/檢索/部件數）來約束單圖回歸，不如自主合成一個打開狀態來創造運動證據**。這打破了"需要知道哪個部件會動才能合成運動"的循環依賴。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：

```
核心直覺：Joint Estimation = f(Disparity(Synthesis(I₀, t=1), I₀))
```

**Stage I 合成目標**：
```
Î₁ = 𝒟(𝒮(ℰ(I₀), t=1, ∅))
```
- ℰ: DINOv2 圖像編碼器（凍結）
- 𝒮: 狀態適應模塊（可學習，用 AdaLN 注入 t）
- 𝒟: VAE 解碼器
- ∅: 空關節條件（Stage I 不指定哪個部件運動）

**Stage II 關節參數化**（每個關節 Ĵₖ 為 9 維）：
```
Ĵₖ = (τₖ, oₖ, aₖ, ϑₖ)
τₖ ∈ {0,1,2,...,6}     → 關節類型（fixed/revolute/prismatic 等）
oₖ ∈ ℝ³                 → 樞紐原點
aₖ ∈ ℝ³                 → 軸向方向（單位向量）
ϑₖ = (mₖ^min, mₖ^max) ∈ ℝ²  → 運動範圍
```

**Stage II 損失函數**：
```
ℒ_II = ℒ_cls + λ_reg · (1/N) · Σₙ ℒ_joint(Jₙ, Ĵ_σ(n))

ℒ_cls = (1/K) · Σₖ CE(τₖ, τ̂ₖ)                    # 類型分類
ℒ_joint = ‖oₙ - ô‖² + (1 - cos(aₙ, â)) + ‖ϑₙ - ϑ̂‖²  # 回歸
```

> 符號與本文/相關文檔保持一致：τ=類型, o=origin, a=axis, ϑ=motion range

**直覺解釋**：
- 分類損失確保關節類型正確（區分轉動/滑動/固定）
- 原點用 L2 距離（位置誤差）
- 軸向用餘弦距離（方向誤差，不敏感於長度）
- 運動範圍用 L2（歸一化到 [0,2] 以平衡 revolute 和 prismatic 的量綱）

## 3. 帶數字走一遍：玩具例子 (Worked Example)

假設輸入一張**合上的筆記本**圖像 I₀：

**Step 1 - Stage I 合成**：
- 編碼：tok = ℰ(I₀) → 768 維 token 序列
- 狀態注入：t=1（最大化打開）通過 AdaLN 調製 token
- 解碼：Î₁ = 解碼出筆記本打開 180° 的圖像

**Step 2 - 3D 提升**：
- VGGT 輸出：P₀, P₁ ∈ ℝ^(224×224×3) 點圖
- 計算位移：ΔP(u) = P₁(u) - P₀(u)
- 過濾：保留位移大小在中間 65% 的點（去除 15% 最小噪聲 + 20% 最大異常）
- 假設篩選後得到 12,000 個 motion seeds

**Step 3 - 關節估計**：
- K=16 個查詢槽位初始化為 motion seeds 的 3D 位置
- Transformer 輸出 16 個關節假設
- 匈牙利匹配：假設真值有 2 個關節（屏幕鉸鏈 + 底座）
  - Ĵ₁ 匹配 J₁（revolute, 屏幕鉸鏈）
  - Ĵ₂ 匹配 J₂（fixed, 底座）
  - Ĵ₃...Ĵ₁₆ 優化為 fixed（未使用槽位）
- 置信度閾值過濾：保留 conf > 0.5 的關節 → 最終輸出 2 個關節

**Step 4 - 驗證**：
- 預測：τ̂₁=revolute, ô₁=(0, 0.5, 0), â₁=(1, 0, 0), ϑ̂₁=(0°, 180°)
- 真值：τ₁=revolute, o₁=(0, 0.48, 0), a₁=(0.98, 0.02, 0), ϑ₁=(0°, 175°)
- 誤差：類型✓, 原點 0.02m, 軸向 2°, 範圍 5° → 成功（所有誤差低於閾值）

## 4. 工程視角 (Engineering View)

| 指標 | 數值 | 工程含義 |
|------|------|----------|
| 推理延遲 | 0.45s/張 (單 GPU) | Stage I 280ms + Stage II 170ms，適合交互式應用 |
| 顯存佔用 | 未明確報告（H200 140GB×8 訓練） | 推測推理時 <8GB（DINOv2-L + VGGT + 小型 Transformer） |
| 輸入分辨率 | 224×224 | 標準 ViT 輸入，可接受 |
| 關節上限 | K=16 | 覆蓋 PartNet-Mobility 最複雜物體（~12 關節） |
| 置信度閾值 | 0.5（推斷） | 平衡召回與精確率 |

**Trade-off 分析**：
- **合成質量 vs 關節精度**：Ablation 顯示用 GT 打開狀態（Oracle）僅比合成高 1.3% SR，說明合成誤差傳播可控
- **3D 提升 vs 2D 編碼**：移除 3D 提升後 SR 從 68.4% 降至 50.0%，證明 3D 幾何約束對關節軸向估計至關重要
- **直接合成 vs 序列生成**：序列生成延遲 1.45s（3.2×）且 PSNR 下降 0.5，直接合成更優

**部署約束**：
- 依賴 VGGT 預訓練模型（需額外加載）
- 假設物體有明確的閉合/打開端點狀態（對連續旋轉/無端點物體失效）
- 3D 提升在物體背對攝像頭時可能失效（無運動可見）

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

### 能做什么：
- **單圖關節估計**：從單張閉合狀態 RGB 圖像估計完整關節參數集（類型 + 原點 + 軸向 + 範圍）
- **部件級可控合成**：基於估計關節，生成任意運動狀態 t'∈[0,1] 的部件級可視化
- **無先驗推理**：不需要部件 mask、檢索庫、多視圖、語言提示

### 不能做什么：
- **極端遮擋**：當關節線索完全不可見（如物體背對攝像頭）時，3D 提升失效
- **無端點狀態物體**：對連續旋轉關節（如風扇）或無明確閉合/打開狀態的物體，合成假設失效
- **動態場景**：僅處理靜態圖像，不處理視頻中的連續關節運動

### 6.1 隐含假设 (Hidden Assumptions)

| 假設 | 是否驗證 | 風險 |
|------|----------|------|
| 物體有明確閉合狀態 (t=0) | 未驗證 | 對部分打開的輸入圖像可能失效 |
| 存在canonical 最大化打開狀態 (t=1) | 未驗證 | 多穩態物體（如多檔位鉸鏈）可能不適用 |
| 合成誤差對關節估計影響小 | Ablation 驗證（Oracle 僅 +1.3%） | 低風險 |
| VGGT 3D 提升足夠準確 | 未系統評估 | 真實場景深度歧義時可能失效 |

**X-Ray 批判**：論文的"無先驗"聲稱部分依賴 VGGT 的隱式 3D 先驗（在大量數據上預訓練）。嚴格來說，這不是"無先驗"，而是"無任務特定先驗"。
