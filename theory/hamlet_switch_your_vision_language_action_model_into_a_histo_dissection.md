### 1.2 关键机制 (Key Mechanism)

**Moment Tokens（时刻标记）**:
- 在每个 timestep t，向 VLM 输入追加 n_m 个可学习标记（默认 4 个）
- 通过 VLM 编码器后，提取这些标记的输出表示 m'_t，作为该时刻的"压缩摘要"
- 关键设计：用时间对比学习（Time-Contrastive Learning, TCL）初始化，使标记能区分不同时刻的独特特征，抑制静态背景

**Memory Module（记忆模块）**:
- 轻量级 Transformer（默认 2 层），对过去 T 个时刻的 moment token 表示进行因果自注意力聚合
- 输出历史增强特征 ~m'_t，与原始 VLM 表示 h_t 拼接后送入动作专家

⚡ **Eureka Moment**: HAMLET 的核心洞见是——**历史信息的价值不在于"更多帧"，而在于"更聪明的压缩"**。与其把原始帧堆进 VLM（计算爆炸），不如用可学习标记提取每帧的任务相关特征，再用轻量记忆网络选择性聚合。这使得历史感知的开销从 35% 延迟 +3.6× 显存降至 2% 延迟 +2× 显存。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula（一行抓住本质）**:

```
历史感知动作预测 = 动作专家(VLM(当前帧) ⊕ 记忆模块(moment_tokens(历史帧)))
```

更形式化地：

**目标**: 在动作预测中融入历史信息，同时最小化计算开销。

**核心方程**:

```
[1] 标准 VLA:     h_t = F_θ(o_t, c)
                  a_{t:t+k-1} = A_ψ(h_t, s_t)

[2] HAMLET:       [h_t; m'_t] = F_θ([o_t, c; m_t])
                  ~m'_t = last_n_rows(M_φ([m'_{t-k(T-1)}; ...; m'_t]))
                  a_{t:t+k-1} = A_ψ([h_t; ~m'_t], s_t)

[3] TCL 初始化:   L_TCL = -Σ_t log[exp(sim(z_t, z_t⁺)/τ) / (exp(sim(z_t, z_t⁺)/τ) + exp(sim(z_t, z_t⁻)/τ))]
```

**变量说明**:

| 符号 | 含义 | 维度/默认值 |
|------|------|-------------|
| o_t | timestep t 的视觉观察（多视角图像） | [n_views, H, W, 3] |
| c | 任务指令（文本） | 可变长度 |
| m_t | moment tokens（可学习） | [4, d] (d=VLM 隐藏维度) |
| h_t | VLM 隐藏表示 | [L, d] (L=序列长度) |
| m'_t | moment token 输出表示 | [4, d] |
| M_φ | 记忆模块（Transformer） | 2 层，因果注意力 |
| T | 历史长度 | 4（默认） |
| k | 动作块长度 | 由 VLA 决定（GR00T 为 8） |
| z_t | m'_t 的投影表示（用于 TCL） | [d_proj] |
| z_t⁺ | 正样本（同一帧的增强视图） | [d_proj] |
| z_t⁻ | 负样本（同一轨迹中 t'≠t 的帧） | [d_proj] |
| τ | 对比学习温度 | 0.07 |

**直觉解释**:
- 方程 [1] 是标准 VLA 的单帧假设
- 方程 [2] 是 HAMLET 的核心：用 m_t 压缩当前帧信息，用 M_φ 聚合历史 moment tokens
- 方程 [3] 是 TCL 损失：鼓励同一时刻的表示相似（正样本），不同时刻的表示区分（负样本）

> 符号与本文/相关文档保持一致：h 表示 hidden，m 表示 moment，~表示历史增强版本。

## 3. 带数字走一遍：玩具例子 (Worked Example)

考虑一个简单的"Pick-and-Place Twice"任务：机器人需要把立方体从 A 点移到 B 点，再移回 A 点。

**场景**: 在 timestep t，机器人摄像头看到立方体在 B 点， gripper 是空的。

**问题**: 下一步应该做什么？
- 如果立方体还没被移动过 → 应该去 A 点抓取
- 如果立方体已经从 A 移到 B（第一次完成）→ 应该抓取 B 点的立方体移回 A

**单帧 VLA 的困境**: 仅从当前帧无法区分这两种情况（立方体都在 B 点，gripper 都空）。

**HAMLET 的处理流程**（假设历史长度 T=4，moment token 数=4）:

```
步骤 1: 提取当前时刻的 moment tokens
  输入：[o_t (当前帧), c (指令), m_t (4 个可学习标记)]
  VLM 输出：m'_t ∈ R^{4×d} (d=768，假设)
  → m'_t 编码了"立方体在 B 点，gripper 空"的语义

步骤 2: 查询记忆模块
  记忆库：M' = [m'_{t-8}; m'_{t-4}; m'_t] (k=8，T=4，实际 3 个有效时刻)
  
  假设过去的 moment tokens 编码了：
    m'_{t-8}: "gripper 在 A 点，立方体在 A 点"
    m'_{t-4}: "gripper 抓着立方体，从 A 移向 B"
  
  记忆模块的自注意力权重（简化）：
    Attention(m'_t, m'_{t-8}) = 0.6  ← 高权重（立方体位置变化是关键）
    Attention(m'_t, m'_{t-4}) = 0.3
    Attention(m'_t, m'_t)       = 0.1
  
  输出：~m'_t = 0.6·m'_{t-8} + 0.3·m'_{t-4} + 0.1·m'_t
        ≈ "立方体已从 A 移到 B，第一次完成"

步骤 3: 动作预测
  输入动作专家：[h_t; ~m'_t]
  输出：a_t = "移动到 B 点，抓取立方体"
```

**数值推导**（假设的合理值）:

```
假设 d=768，m'_t 的某个关键维度（编码"立方体位置"）的值为：
  m'_{t-8}[pos] = [0.9, 0.1]  ← A 点 (one-hot 近似)
  m'_{t-4}[pos] = [0.5, 0.5]  ← 移动中
  m'_t[pos]     = [0.1, 0.9]  ← B 点

记忆模块输出：
  ~m'_t[pos] = 0.6×[0.9,0.1] + 0.3×[0.5,0.5] + 0.1×[0.1,0.9]
             = [0.54+0.15+0.01, 0.06+0.15+0.09]
             = [0.70, 0.30]

动作专家解读：
  [0.70, 0.30] 表示"立方体主要在 A 点（历史）但现在在 B 点"
  → 推断出"已完成第一次移动"
  → 生成动作：抓取 B 点立方体
```

**对比：如果没有历史感知**:
- 单帧 VLA 只看到 [0.1, 0.9]（立方体在 B 点）
- 无法区分是"初始状态"还是"第一次完成后"
- 可能错误地尝试去 A 点抓取（任务失败）

## 4. 工程视角 (Engineering View)

### 4.1 计算开销分析

| 指标 | GR00T N1.5 基线 | Multi-frame (4 帧) | HAMLET (4 帧历史) |
|------|----------------|-------------------|------------------|
| **推理延迟** | 80.5ms | 108.5ms (+35%) | 82.4ms (+2%) |
| **峰值显存** | 289MB | 1051MB (+264%) | 566MB (+96%) |
| **额外参数** | - | 0 | +140M (moment tokens + 记忆模块) |
| **训练时间** | ~14h | ~14h | ~16h (+2h TCL) |

**工程含义**:
- **延迟**: HAMLET 的 2% 开销在实际部署中几乎不可感知（80ms→82ms），而 multi-frame 的 35% 开销会显著降低控制频率（从 12.4Hz 降至 9.2Hz）
- **显存**: HAMLET 的 2× 显存增长主要来自记忆模块的 KV cache，但仍远低于 multi-frame 的 3.6×（后者需要存储多帧的完整 VLM 激活）
- **训练**: TCL 初始化是可选的（论文显示无 TCL 也有 63.1% vs 65.4%），可根据资源选择跳过

### 4.2 超参数敏感度

| 超参数 | 默认值 | 可调范围 | 敏感度 |
|--------|--------|----------|--------|
| Moment token 数 | 4 | 1-8 | 中（4→8 提升 1%，8→16 下降） |
| 记忆模块层数 | 2 | 1-4 | 低（2 层已足够） |
| 历史长度 T | 4 | 2-8 | 中（T=8 时延迟 +7%） |
| TCL 温度 τ | 0.07 | 0.05-0.1 | 低 |

**部署建议**:
- 资源受限场景：moment tokens=4，历史长度=2，跳过 TCL 初始化
- 性能优先场景：moment tokens=8，历史长度=4，启用 TCL
- 超长程任务（>10 步）：需验证历史长度=8 的效果（论文未测试）

### 4.3 与现有 VLA 的集成成本

- VLM 冻结，仅训练记忆模块 + 动作专家

2. **假设：moment tokens 能充分压缩历史信息**

## 7. 与相关工作对比 (Comparison)

### 7.1 与基线方法对比

| 方法 | 历史编码方式 | 训练成本 | 推理开销 | 适用场景 |
|------|-------------|----------|----------|----------|
| **GR00T N1.5** | 无历史 | 低 | 最低 | 单帧足够任务 |
| **Multi-frame** | 原始帧拼接 | 低 | 高（+35% 延迟） | 短历史、资源充足 |
| **MemoryVLA** (并发) | 从头训练记忆架构 | 高 | 未知 | 新模型设计 |
| **HAMLET (本文)** | Moment tokens + 记忆模块 | 中（+2h TCL） | 低（+2% 延迟） | 现有 VLA 升级 |

### 7.2 与记忆架构对比（Table 5c）

| 记忆架构 | RoboCasa 平均成功率 |
|----------|-------------------|
| 无记忆 | 62.6% |
| Moment Concat（简单拼接） | 62.7% ← 几乎无提升 |
| RNN | 64.5% |
| LSTM | 65.0% |
| GRU | 64.3% |
| **Transformer (HAMLET)** | **65.4%** ← 最佳 |

**关键洞察**: 简单的拼接无效（62.6%→62.7%），需要选择性注意力机制。

### 7.3 面试 Tip

**问**: "如何让现有 VLA 获得历史感知能力，同时最小化计算开销？"

**答**: "HAMLET 的方案是用可学习的 moment tokens 压缩每帧信息，再用轻量 Transformer 记忆模块聚合历史。关键是不直接处理原始帧（开销大），而是处理压缩后的标记（开销小）。在 GR00T 上实测：历史长度=4 时，延迟仅 +2%，显存 +96%，但长程任务性能提升 47%。"
