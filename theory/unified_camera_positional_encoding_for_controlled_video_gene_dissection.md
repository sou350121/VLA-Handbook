## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 频率/时序 | 训练/推理差异 |
|------|------|------|-----------|---------------|
| Relative Ray Encoding | 像素坐标 (u,v) + 相机参数 (xFoV, ξ, R, t) | 每像素射线变换矩阵 T_rw ∈ R^{4×4} | 每帧每像素 | 训练时采样多种镜头，推理时支持任意镜头 |
| Absolute Orientation Encoding | 世界空间射线方向 d_t | Lat-Up 特征图 (纬度角 + 上向量) | 每帧 | 训练时提供绝对朝向监督，推理时可指定 pitch/roll |
| Spatial Attention Adapter | 原始 token + UCPE 混合编码 | 相机感知 token | 每层 DiT | 零初始化权重保证预训练先验不被破坏 |
| UCPE 混合算子 | D_t^Ray ⊕ D_t^RoPE | 块对角算子 D_t^UCPE | 每 token | 与 RoPE 融合促进射线空间 + 图像空间双重推理 |

### 1.2 关键机制 (Key Mechanism)

**为什么从相机级编码改为射线级编码？**

- 现有方法（Plücker、PRoPE、GTA）假设同一相机内所有像素共享同一个线性投影函数
- 真实镜头（鱼眼、折反射）有空间变化的投影非线性，相机级编码无法捕捉这种变化
- 射线级编码让每个 token 有自己的几何变换，注意力机制在"射线空间"而非"相机框架"内操作

**为什么需要绝对朝向编码？**

- 现有 T2V 方法将相机位姿定义为相对于第一帧，导致全局旋转框架模糊
- pitch 和 roll 两个自由度无法唯一确定，无法指定/复现初始视角的绝对朝向
- Lat-Up 图通过外观线索（天空 - 地面分离、物体对齐）提供重力对齐的"上"方向

⚡ **Eureka Moment**：UCPE 的核心洞见是**将位置编码从"相对相机"重新表述为"相对射线"**——每个 token 对应自己的观测射线，在射线空间内进行注意力计算，从而天然兼容任意镜头投影模型。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
UCPE = RelativeRayEncoding(每像素射线变换 T_rw) + AbsoluteOrientationEncoding(Lat-Up 图)
```

**相对射线编码的数学形式**：

对于每个图像 token t，定义其观测射线为：
```
r_t = (o_t, d_t),  o_t ∈ R³,  d_t ∈ S²
```

其中 o_t 是射线原点（中心相机为 0），d_t 是射线方向。构建局部射线坐标系：
```
z_t = d_t  (射线方向作为局部 z 轴)
x_t = y_cam × z_t  (相机向下方向与射线方向的叉积)
y_t = z_t × x_t
```

形成射线到世界的变换矩阵：
```
T_wr_t = [R_wr_t  t_wr_t]
         [0^T      1    ]
```

其中 R_wr_t = [x_t, y_t, z_t] 是标准正交基，t_wr_t = o_t 是平移。

**Lat-Up 编码计算**：

纬度角（射线相对于水平面的仰角）：
```
Lat_t = arctan2(-d_t,y, sqrt(d_t,x² + d_t,z²))
```

上向量（将射线绕局部轴旋转小角度δ后投影回图像平面的位移）：
```
Up_t = [Δu_t, Δv_t] / ||[Δu_t, Δv_t]||
```

> 符号说明：d_t,x/y/z 是世界空间射线方向的三个分量；y_cam 是相机坐标系中的向下方向；arctan2 是四象限反正切函数。

> 符号与本文/相关文档保持一致：T_wr 表示射线到世界的变换，T_rw 是其逆；UCM 指 Unified Camera Model；xFoV 是水平视场角；ξ是 UCM 畸变参数。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有一个 480×832 分辨率的视频帧，使用鱼眼镜头（xFoV=160°，ξ=1.8）。

**步骤 1：计算单像素的射线方向**

对于像素 (u=416, v=240)（图像中心）：
- 归一化坐标：x = (416-416)/f_x = 0, y = (240-240)/f_y = 0
- UCM 反投影：ρ = sqrt(0²+0²) = 0
- 射线方向：d_cam = [0, 0, 1-1.8×0] / sqrt(0+0+(1-0)²) = [0, 0, 1]

**步骤 2：应用相机位姿**

假设相机位姿 R = I（无旋转），t = [0, 0, 0]（原点）：
- 世界空间射线：d = R·d_cam = [0, 0, 1], o = t = [0, 0, 0]

**步骤 3：构建局部射线坐标系**

- z_t = d_t = [0, 0, 1]
- 假设相机向下方向 y_cam = [0, -1, 0]（y 轴向下）
- x_t = y_cam × z_t = [0, -1, 0] × [0, 0, 1] = [-1, 0, 0]
- y_t = z_t × x_t = [0, 0, 1] × [-1, 0, 0] = [0, -1, 0]
- R_wr_t = [[-1, 0, 0], [0, -1, 0], [0, 0, 1]]

**步骤 4：计算 Lat-Up 特征**

- Lat_t = arctan2(-0, sqrt(0+1)) = 0°（水平射线）
- Up_t 通过旋转δ角后投影计算，假设得到 [0, 1]（指向图像上方）

**步骤 5：注入注意力**

对于 1/8 压缩比的适配器：
- 原始 token 维度：2048
- 投影后维度：2048/8 = 256
- D_Ray_t 是 128×128 矩阵（I_{128} ⊗ T_rw_t）
- D_RoPE_t 是 128×128 矩阵（标准 RoPE）
- D_UCPE_t = blkdiag(D_Ray_t, D_RoPE_t) 是 256×256 矩阵

注意力计算：
```
O = D_UCPE ⊙ Attn((D_UCPE)^T ⊙ Q, (D_UCPE)^{-1} ⊙ K, (D_UCPE)^{-1} ⊙ V)
```

输出通过零初始化线性层映射回 2048 维，与原始注意力输出相加。

**部署约束**：
- 需要 Wan 或类似 Diffusion Transformer 作为基座
- 空间适配器插入每个 DiT 块的并行分支，不改变原始架构
- 推理时需提供相机参数（位姿、xFoV、ξ、pitch/roll），可通过 SLAM 或手动指定获取

**Trade-off 分析**：
- 1/8 压缩比是性能/效率最佳平衡点（Table 1 消融实验）
- 1/12 压缩比参数更少 (23.8M) 但镜头控制精度下降 (FoV 误差 8.96° vs 8.22°)
- 并行适配器设计优于 Pre-Attn/Post-Attn 插入（旋转误差 4.12° vs 4.03°/4.68°）

### 6.3 隐含假设 (Hidden Assumptions)

**X-Ray 批判视角**：

1. **中心相机假设**：推导中假设所有射线共享同一原点（o_t = 0），非中心相机（如折反射系统）需扩展
2. **重力对齐世界框架**：Lat-Up 编码依赖"上"方向定义，失重环境或倾斜场景可能失效
3. **SLAM 位姿准确性**：训练数据位姿来自 ViPE/GeoCalib 估计，存在误差累积（论文承认"jitters due to inaccurate ViPE pose estimation"）
4. **UCM 覆盖范围**：统一相机模型能近似广角/鱼眼，但极端畸变（如全景拼接）可能超出建模能力
5. **文本 - 相机解耦**：假设文本 prompt 与相机控制独立，复杂场景（如"环绕物体拍摄"）需联合建模
