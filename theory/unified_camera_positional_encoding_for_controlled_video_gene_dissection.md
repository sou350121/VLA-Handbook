### 1.2 关键机制 (Key Mechanism)

**为什么需要射线级编码？**

现有相对相机编码（如 PRoPE、GTA）假设同一视图内所有 token 共享单一线性投影函数。这在 pinhole 相机下成立，但鱼眼/全景镜头存在空间变化的投影畸变——图像边缘的射线弯曲程度与中心不同。相机级编码忽略这种 intra-camera 变化，导致泛化失败。

**UCPE 的解决方案：**

1. 为每个 token t 构建局部射线坐标系，以射线方向 d_t 为 z 轴
2. 用相机向下向量 y^cam 确定 x/y 轴（正交基）
3. 形成射线到世界的变换矩阵 T^wr_t，其逆 T^rw_t 作为 attention 的几何算子

⚡ **Eureka Moment**：将编码粒度从"相机"细化到"射线"——每个像素有自己的几何坐标系，attention 在射线空间而非相机空间操作，天然兼容任意镜头畸变。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
每 token 射线编码：r_t = (o_t, d_t), 其中 d_t = R · d_t^cam(U CM; xFoV, ξ)
```

**目标**：将任意相机模型（pinhole/鱼眼/全景）统一表示为射线映射，使 Transformer attention 在射线空间操作。

**公式推导**：

1. **射线定义**（世界坐标系）：
   ```
   r_t = (o_t, d_t),  o_t ∈ ℝ³,  d_t ∈ 𝕊²
   ```
   其中 o_t 是射线原点（中心相机下 o_t = t），d_t 是单位方向向量。

2. **UCM 射线映射**（Unified Camera Model）：
   ```
   d_t^cam = Φ_UCM(u, v; xFoV, ξ, H, W)
   ```
   UCM 用单一参数 ξ 控制畸变：ξ=0 退化为 pinhole，ξ>1 模拟鱼眼。

3. **局部射线坐标系**：
   ```
   z_t = d_t
   x_t = y_i(t)^cam × z_t
   y_t = z_t × x_t
   R_t^wr = [x_t, y_t, z_t]  (3×3 正交基)
   T_t^wr = [R_t^wr  o_t; 0^T  1]  (4×4 变换矩阵)
   ```

4. **Attention 注入**：
   ```
   D_t^UCPE = blkdiag(D_t^Ray, D_t^RoPE)
   O = D^UCPE ⊙ Attn((D^UCPE)^T ⊙ Q, (D^UCPE)^(-1) ⊙ K, (D^UCPE)^(-1) ⊙ V)
   ```

**变量说明**：

| 符号 | 含义 | 来源 |
|------|------|------|
| (u,v) | 像素坐标 | 输入 |
| xFoV | 水平视场角 | 相机内参 |
| ξ | UCM 畸变参数 | 相机内参 |
| R, t | 相机外参（旋转 + 平移） | 相机位姿 |
| d_t^cam | 相机坐标系射线方向 | UCM 反投影 |
| d_t | 世界坐标系射线方向 | d_t = R·d_t^cam |
| T_t^rw | 世界→射线变换 | 公式 (7) |
| D^UCPE | 混合编码算子 | 公式 (10) |

> 符号与本文/相关文档保持一致：射线编码沿用 NeRF/CameraCtrl 惯例，UCM 参数参考 Mei & Rives 2007。

**直觉解释**：

传统方法编码"相机在哪里"，UCPE 编码"每个像素看到什么方向"。后者将几何推理下沉到像素级，attention 机制可以直接学习射线间的空间关系，而非通过相机参数间接推断。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设生成一个 480×832 分辨率的视频帧，使用鱼眼镜头（xFoV=150°, ξ=1.5）。

**步骤 1：计算单像素射线**

取图像中心像素 (u=416, v=240)：
```
归一化坐标：x = (416-416)/f_x = 0,  y = (240-240)/f_y = 0
UCM 反投影：d^cam = [0, 0, 1-ξ·0] / norm = [0, 0, 1]
```

取边缘像素 (u=800, v=240)：
```
归一化坐标：x = (800-416)/f_x ≈ 0.92
UCM 反投影：d^cam = [0.92, 0, 1-1.5·0.92] / norm ≈ [0.71, 0, -0.29]
```
→ 边缘射线明显弯曲（z 分量为负），体现鱼眼畸变。

**步骤 2：构建局部坐标系**

假设相机向下向量 y^cam = [0, -1, 0]（标准约定），相机位姿 R=I, t=[0,0,0]：

中心像素：
```
z_t = [0, 0, 1]
x_t = [0, -1, 0] × [0, 0, 1] = [-1, 0, 0]
y_t = [0, 0, 1] × [-1, 0, 0] = [0, -1, 0]
R_t^wr = [[-1, 0, 0], [0, -1, 0], [0, 0, 1]]
```

边缘像素：
```
z_t = [0.71, 0, -0.29]
x_t = [0, -1, 0] × [0.71, 0, -0.29] = [0.29, 0, 0.71]
y_t = [0.71, 0, -0.29] × [0.29, 0, 0.71] = [-0.50, -0.59, -0.21]
R_t^wr = [[0.29, -0.50, 0.71], [0, -0.59, 0], [0.71, -0.21, -0.29]]
```
→ 不同像素有不同的局部坐标系，编码射线间相对关系。

**步骤 3：Attention 操作**

Query 向量 Q_t 乘以 (D_t^UCPE)^T，Key 向量 K_t 乘以 (D_t^UCPE)^(-1)：
```
Q'_t1 · K'_t2 = (D_t1^T Q_t1) · (D_t2^(-1) K_t2)
              = Q_t1^T · D_t1 · D_t2^(-1) · K_t2
```
其中 D_t1 · D_t2^(-1) 编码两像素射线的相对几何变换。

## 4. 工程视角 (Engineering View)

**计算开销**：

| 操作 | 复杂度 | 实际耗时 (832×480, 81 帧) |
|------|--------|--------------------------|
| UCM 射线映射 | O(HW) | ~50ms (GPU 并行) |
| 局部坐标系构建 | O(HW) | ~30ms |
| Attention 注入 | O(HW·d) | 增加 12% 推理时间 |
| 总 overhead | - | <15% vs 无相机控制 |

**内存占用**：

- UCPE 参数：35.5M（1/8-dim 配置），占基座 Wan 7.3B 的 0.5%
- 射线编码缓存：每帧 832×480×16 字节 ≈ 6MB（可实时计算，无需缓存）
- 训练显存：8×A800 80GB，batch=1，gradient accumulation=4

**部署约束**：

1. **相机标定**：推理时需已知 xFoV 和 ξ。无标定场景可用 GeoCalib 单目标定（误差~2°）
2. **重力对齐**：Absolute Orientation 要求训练数据重力一致。真实数据需 IMU 或地平线检测
3. **帧率限制**：81 帧@16fps = 5 秒视频。更长视频需滑动窗口或层级生成

**工程权衡**：

- **压缩比选择**：论文测试 1/2/4/8/12-dim，1/8 最佳（35.5M 参数，FVD=495）
- **注入位置**：并行 adapter > Pre-Attn > Post-Attn（并行保持预训练先验）
- **编码选择**：Relative Ray + RoPE 混合优于纯射线编码（兼顾图像空间推理）

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：

1. **镜头类型控制**：在 pinhole/广角/鱼眼间切换，生成对应畸变效果（论文 Fig.4）
2. **绝对方向指定**：精确控制初始帧的 pitch/roll（如"仰视 30°+ 右倾 15°"）
3. **轨迹跟踪**：沿给定 6-DoF 轨迹生成视频，TransErr=15.21（vs Wan CameraCtrl 39.16）
4. **零样本泛化**：在 RealEstate10K（仅 pinhole）上无需微调即超越专用基线

**不能做什么**：

1. **动态内参**：假设帧间 xFoV/ξ 恒定。变焦镜头需逐帧指定参数（论文未测试）
2. **非中心相机**：推导假设中心相机（所有射线共原点）。双筒/折反相机需扩展公式
3. **极端运动**：快速平移（>5m/s）下 ViPE 位姿估计抖动，影响训练信号质量
4. **长视频一致性**：81 帧以上需滑动窗口，累积误差未评估

### 6.1 隐含假设 (Hidden Assumptions)

1. **重力对齐**：Absolute Orientation 依赖训练数据共享世界"上"向量。无 IMU 的网络视频需预对齐
2. **静态场景**：PanShot 从 360° 视频合成，假设场景静态。动态物体遮挡未建模
3. **UCM 充分性**：用 UCM 近似所有镜头。某些鱼眼（如立体鱼眼）需更复杂模型
4. **文本描述质量**：训练用 vLLM 生成 caption。真实 prompt 分布偏移可能影响可控性
