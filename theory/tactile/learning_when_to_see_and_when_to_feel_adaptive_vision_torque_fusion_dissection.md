### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **接触门控**：自由运动阶段的关节力矩包含惯性效应和传感器噪声，没有可学习模式。通过阈值检测接触状态（任一关节外力矩超过预设值），用可学习参数 f* 替换非接触阶段的力矩特征。

2. **双专家 U-Net**：单一 U-Net 容易模态坍塌（过度依赖视觉）。训练两个模态专用 U-Net，在噪声预测层面融合而非特征层面。

3. **CFG 风格自适应融合**：受 Classifier-Free Guidance 启发，用尺度预测器动态输出 w_torque，接触时放大力量专家贡献，自由运动时纯视觉驱动。

⚡ **Eureka Moment**：**力矩信号不是越多越好——在自由运动阶段它是噪声，在接触阶段它是信号。关键不是融合，而是知道何时融合。**

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
ε_final = ε_vision + φ·σ(w_scale)·(ε_torque - ε_vision)
```

**目标**：在接触丰富操作中动态融合视觉和力矩模态，自由运动时纯视觉驱动，接触时自适应混合。

**公式拆解**：

| 符号 | 含义 | 取值范围 |
|------|------|----------|
| ε_final | 最终噪声预测（用于去噪） | R^d |
| ε_vision | 视觉专用 U-Net 的噪声预测 | R^d |
| ε_torque | 力矩专用 U-Net 的噪声预测 | R^d |
| φ | 接触状态门控 | {0, 1} |
| w_scale | 尺度预测器输出 | R |
| σ(·) | softplus 函数 | (0, ∞) |
| w_torque = φ·σ(w_scale) | 力矩引导权重 | [0, ∞) |

**接触门控公式**：

```
f_torque-gated = φ·f_torque + (1-φ)·f*
```

其中 f* 是可学习参数，代表自由运动阶段的"默认"力矩特征。

**直觉**：当φ=0（无接触）时，w_torque=0，输出纯视觉预测；当φ=1（接触）时，w_torque>0，力矩专家开始贡献。尺度预测器学习何时需要更多力矩信息。

> 符号与本文/相关文档保持一致：ε表示扩散模型的噪声预测，φ表示门控变量，f*表示可学习默认特征。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设机器人执行"拧开电饭煲盖子"任务，我们跟踪一次推理过程：

**场景 A：自由运动阶段（接近锅盖）**

- 关节力矩测量：[0.2, -0.1, 0.3, 0.1, -0.2, 0.15, 0.1] Nm（小幅波动，惯性噪声）
- 接触检测：所有力矩 < 阈值 0.5 Nm → φ = 0
- 尺度预测器输出：w_scale = 1.5 → σ(1.5) ≈ 4.5
- 力矩权重：w_torque = 0 × 4.5 = 0
- 最终噪声：ε_final = ε_vision + 0 × (ε_torque - ε_vision) = ε_vision

**结果**：纯视觉驱动，避免力矩噪声干扰。

**场景 B：接触阶段（开始拧盖子）**

- 关节力矩测量：[2.1, 1.8, 3.2, 2.5, 1.9, 2.0, 2.3] Nm（明显阻力）
- 接触检测：最大力矩 3.2 > 阈值 0.5 → φ = 1
- 尺度预测器输出：w_scale = 2.0 → σ(2.0) ≈ 7.4
- 力矩权重：w_torque = 1 × 7.4 = 7.4
- 视觉专家预测：ε_vision = [0.1, -0.2, 0.3, ...]
- 力矩专家预测：ε_torque = [0.5, 0.1, -0.1, ...]（基于力矩历史推断阻力方向）
- 最终噪声：ε_final = ε_vision + 7.4 × (ε_torque - ε_vision)
  - = [0.1, -0.2, 0.3, ...] + 7.4 × [0.4, 0.3, -0.4, ...]
  - ≈ [3.1, 2.0, -2.7, ...]（力矩专家主导）

**结果**：力矩信号主导动作生成，精确感知阻力并调整拧转力度。

## 4. 工程视角 (Engineering View)

**吞吐/延迟**：
- 推理频率：10 Hz（与数据采集频率一致）
- 扩散步数：100 步去噪（标准 Diffusion Policy 设置）
- 单次推理延迟：未明确报告，但双 U-Net 架构相比单 U-Net 增加约 2 倍计算量
- 实时性：10 Hz 对于操作任务足够（人类操作约 5-10 Hz）

**内存**：
- 两个 U-Net 参数量：未报告，但 ResNet-18 + U-Net 架构通常在 10-50M 参数范围
- 力矩历史缓冲：7×10 = 70 个浮点数（可忽略）
- 总内存占用：估计 <500 MB（可部署在 Jetson 等边缘设备）

**部署约束**：
- 需要关节力矩传感器（Franka Research 3 自带，无需额外硬件）
- 力矩阈值需要针对具体机器人标定（论文未报告具体阈值）
- 10 步力矩历史对应 1 秒窗口（10 Hz 采样），需要根据任务时域调整

**工程权衡**：
- **双 U-Net vs 单 U-Net**：计算量翻倍，但避免模态坍塌
- **接触门控阈值**：过高会漏检接触，过低会误检噪声——需要任务相关标定
- **力矩历史长度**：10 步是经验值，更长历史可能捕捉更丰富的动力学但增加延迟

**量化误差**：
- 力矩传感器噪声：未报告具体噪声水平，但提到"惯性效应"是主要干扰源
- 解决方案：接触门控过滤非接触阶段，而非滤波（避免相位延迟）

### 6.1 隐含假设 (Hidden Assumptions)

**X-Ray 批判视角**：

1. **力矩阈值可标定**：假设存在一个普适的力矩阈值区分接触/非接触，但实际中不同任务、不同速度下的惯性力矩差异很大。

2. **关节力矩≈外力矩**：Franka 提供的"外部力矩"是经过动力学补偿的，但补偿精度依赖准确的机器人模型（负载、摩擦等）。

3. **接触是二元的**：φ∈{0, 1} 假设接触是开关状态，但实际中存在"轻微接触"、"滑动接触"等中间状态。

4. **视觉始终可靠**：自由运动阶段纯视觉驱动的假设前提是视觉不失效，但在强光照变化、运动模糊等场景下可能失败。

5. **任务时域匹配 10 步窗口**：假设 1 秒力矩历史足够捕捉接触动力学，但对快速冲击或慢速蠕变任务可能不足。
