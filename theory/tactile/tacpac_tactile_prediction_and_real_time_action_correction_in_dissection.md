💡 **X-Ray 开场**
世界-动作模型（WAM）能预测未来观测来指导动作生成，但视觉预测丢失了接触密集操作中最关键的局部触觉线索。直觉上「把触觉也加入预测」就行——但论文发现这只恢复了约三分之一的收益。核心原因是时序错配：预测在动作执行前完成，触觉反馈在执行中到达。TacPAC 的解法是把预测的触觉和动作表征缓存为 KV，让触觉专家在 chunk 执行过程中逐帧读取新触觉图像、修正未执行部分。

## 1. 核心架构/方法总览

### 1.1 系统对比概览

| 组件 | 输入 | 输出 | 训练阶段 | 推理频率 |
|------|------|------|----------|----------|
| Video Expert | 当前视觉+触觉帧 + 指令嵌入 | 未来视觉+触觉 latent 速度场 | Stage 1 | 每 chunk 1 次（含 denoising 多步） |
| Action Expert | 当前帧 + 未来 latent + proprioception | 动作 chunk â 速度场 | Stage 1 | 每 chunk 1 次（含 denoising 多步） |
| Tactile Expert | 当前触觉图像 I_m + 更新版 â + 执行偏移 m + 缓存 C | 逐步 delta 动作 Δa | Stage 2（冻结 Stage 1） | 每触觉帧 1 次（~32.9 Hz） |
| KV Cache C | denoised video latent + â（τ=0 额外 pass） | 每层 tactile + action 的 K/V | 每 chunk 构建 1 次 | 每 correction 只读 |

**训练/推理差异**：Stage 1 联合训练 video + action expert（MoT 架构）；Stage 2 冻结二者，仅训练 tactile expert。推理时 base model 每个 chunk 只跑一次 denoising，tactile expert 在 chunk 执行期间异步运行。

### 1.2 关键机制

**为什么这样设计**：

1. **预测不够**：触觉变化时间稀疏（接触阶段仅占 4.9% 的帧但贡献 18.6% 的触觉变化），未来视图目标无法让动作生成对关键接触转换敏感。
2. **时序错配**：预测在动作执行前完成，一旦 chunk 计划好就无法根据实际接触修订。
3. **缓存 KV 的核心价值**：chunk 在计划时 attended 到预测的触觉 token——这些 KV 编码了「模型期望感受到什么」。把 KV 缓存后，触觉专家不仅能读到「实际感受到什么」，还能读到「期望感受到什么」，从而判断偏差方向。

⚡ **Eureka Moment**：修正不是看触觉传感器「现在读到了什么」，而是看「实际触觉 vs 计划预期触觉」的偏差——同一个触觉读数，如果接触是预期的，就不需要修正；如果接触出乎意料，就需要修正。

## 2. 数学核心

### 📌 Napkin Formula

```
Δa = f(I_m, â, m, C)    where C = KV_cache(denoised_z, â at τ=0)
L_tac = 1/(H-m) · Σ_{i≥m} || â_i + Δa_i - a_i ||²
```

**目标**：让触觉专家输出的 delta 动作加上原始计划，逼近 ground-truth 动作。

**变量说明**：

| 符号 | 含义 |
|------|------|
| I_m | 执行到第 m 步时的触觉图像 |
| â | base model 计划的动作 chunk（H 步） |
| m | 执行偏移（已执行步数） |
| C | 缓存的每层 tactile + action KV（τ=0 干净状态） |
| Δa | 触觉专家输出的逐步修正量 |
| a_i | ground-truth 第 i 步动作 |
| H | chunk horizon |
| d | 修正延迟（以 action step 计，实际≈0） |

**直觉**：损失函数监督 Δa 成为「计划与真实之间的残差」，条件是在执行偏移 m 处观察到的触觉证据。通过在 horizon 上密集采样 m，专家学会在每个执行阶段给出正确的修正方向。

> 符号与本文保持一致。flow matching 的基础公式 x_τ = (1-τ)x + τ·ε 与 u = ε - x 为标准条件流匹配，此处不展开。

## 3. 带数字走一遍：玩具例子

假设一个 charger-plug 插入任务，chunk horizon H=10 步。

**Step 1: Base model 计划**
- 输入：当前帧 + 指令 "insert charger plug"
- 输出：â = [0.1, 0.1, 0.1, 0.05, 0.0, -0.05, -0.1, -0.1, -0.1, -0.05]（单位：mm 位移）
- 预测触觉：期望在 step 3-4 之间感受到轻微侧向力

**Step 2: 执行 + 触觉反馈**
- 实际执行 step 0-2：â[0:3] = [0.1, 0.1, 0.1]
- step 3 触觉传感器读数 I_3：侧向力比预期大 2 倍（插偏了）

**Step 3: Tactile Expert 修正**
- 输入：I_3 + â（前 3 步替换为实际值）+ m=3 + C
- 输出：Δa = [?, ?, ?, 0.05, 0.08, 0.06, 0.03, 0.0, 0.0, 0.0]（? 表示已执行步不修正）
- 修正后：a_corrected[3:] = [0.10, 0.08, -0.02, -0.07, -0.10, -0.10, -0.05]
- 效果：向右多移 0.08mm 补偿偏差，后续步逐步回归正常轨迹

**训练视角**：
- ground-truth 动作 a[3:] = [0.15, 0.18, 0.04, -0.02, -0.10, -0.10, -0.05]
- L_tac = 1/7 · Σ ||â[i] + Δa[i] - a[i]||²
- 梯度推动专家学会：当触觉侧向力 > 预期时，输出正的横向修正

## 4. 工程视角

| 指标 | 数值 | 含义 |
|------|------|------|
| 修正延迟 | 30.4 ms | 单次 correction forward pass 耗时 |
| 修正频率 | 32.9 Hz | 触觉帧到达率下的实际修正速率 |
| 相对加速 | 20.7× | 比重新生成整个 chunk 快 20.7 倍 |
| 延迟步数 d | ≈0 | 修正返回时几乎不损失可修正步数 |
| 缓存构建 | 1 次/chunk | τ=0 额外 forward pass，不重复 |
| Base model 推理 | 1 次/chunk | denoising 多步（flow matching 通常 4-8 步） |

**工程含义**：
- **控制频率匹配**：32.9 Hz 修正频率与典型机器人控制频率（20-100 Hz）兼容，可作为闭环控制的上层修正模块。
- **模块边界清晰**：base model 和 tactile expert 完全解耦——Stage 2 冻结 Stage 1，可独立部署和升级。
- **部署约束**：需要触觉传感器以 ≥30 Hz 提供图像；InTac S1 满足要求，但低成本触觉传感器可能成为瓶颈。
- **内存占用**：缓存 C 存储每层 tactile + action KV，层数与 base model 深度成正比。视觉 KV 不存储，节省约 1/3 缓存空间。
- **修正不累积误差**：每次 delta 加到原始 â 而非前一次修正结果上，避免 spurious correction 传播。

### 6.1 隐含假设 (Hidden Assumptions)

1. **触觉传感器足够快**：假设触觉帧率 ≥ 30 Hz 且延迟可忽略。低成本触觉传感器（如 10 Hz）可能使 d 显著增大，修正窗口缩小。
2. **缓存大小可控**：每层 KV 缓存随 base model 深度线性增长。对更大 WAM（如 28+ 层），缓存内存可能成为瓶颈。
3. **训练数据覆盖执行偏移**：训练时从 Unif{0, ..., H-1} 采样 m，假设真实执行中各偏移出现概率均匀。实际中早期偏移（接触刚建立）可能更关键但采样权重相同。
4. **触觉表示通用性**：raw + frame-residual + stress 三种表示在 Flexiv+InTac 上有效，但不同触觉传感器（如 GelSight, Digit）的像素物理含义不同，预处理需重新适配。
5. **delta 加性修正足够**：假设 â + Δa 的加法修正足以覆盖所有接触偏差。对于大偏差场景（如完全抓错物体），可能需要更激进的重规划。
