## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 传统特征拼接 | 本文策略共识 |
|------|-------------|-------------|
| 融合层级 | 特征层（encoder 输出拼接） | 策略层（diffusion score 组合） |
| 模态处理 | 共享网络，所有模态通过同一套权重 | 独立专家，每个模态有自己的 diffusion 模型 |
| 权重机制 | 隐式（由网络学习，不可解释） | 显式共识权重 wi（路由器输出，可解释） |
| 新增模态 | 需重新训练整个网络 | 只需训练新专家，组合权重可复用 |
| 稀疏信号保护 | 无（统计主导模态压制稀疏信号） | 有（独立专家保证触觉等信号不被淹没） |
| 参数量 | 基准 262.9M | 263.6M（+0.3%） |

### 1.2 关键机制 (Key Mechanism)

**核心设计选择**：

1. **模态内分解 (Intra-Modality Factorization)**：每个模态 i 进一步分解为 Ki 个子专家（实验中 Ki=2），捕捉互补行为模式
   - 视觉专家：geometry vs fine detail
   - 触觉专家：contact onset vs sustained force

2. **模态间组合 (Inter-Modality Composition)**：路由器网络 Rψ 接收各模态 embedding，输出共识权重 {wi}，满足 Σwi = 1

3. **扩散分数组合**：在 diffusion 去噪的每一步 k，组合分数为：
   ```
   ε_comp(a^k, s_t, k) = Σ_i wi(s_t) · ε_i,comp(a^k, m_i,t, k)
   ```

⚡ **Eureka Moment**：这篇论文最核心的洞见是——**融合应该发生在策略输出层（action distribution），而不是特征表示层**。这样每个模态的专家可以独立学习其统计特性，稀疏信号不会因为"出现频率低"而被训练过程忽略。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
p(a|s_t) ∝ ∏_i [p_i(a|m_i,t)]^{w_i}
```

**目标**：学习一个多模态策略 $\pi(a|s_t)$，其中状态 $s_t$ 包含 $N$ 个异构感官模态 $\{m_{1,t}, \dots, m_{N,t}\}$，每个模态在不同任务阶段的重要性动态变化。

**核心公式**（能量基组合）：

```
p(a|s_t) ∝ exp(-Σ_i wi · Σ_j E_θ_i,j(a, m_i,t))
```

**扩散实现**（分数组合）：

```
ε_comp(a^k, s_t, k) = Σ_i=1^N wi(s_t) · ε_i,comp(a^k, m_i,t, k)
ε_i,comp = (1/Ki) · Σ_j=1^Ki ε_θ_i,j(a^k, m_i,t, k)
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| a | 动作候选 |
| $a^k$ | diffusion timestep k 的噪声动作 |
| s_t | t 时刻状态，包含 N 个模态 |
| m_i,t | 模态 i 在 t 时刻的原始观测 |
| e_i,t | 模态 i 的 latent embedding（含机器人状态） |
| p_i,j | 模态 i 的第 j 个子策略 |
| $E_{\theta_{i,j}}$ | 子策略定义的能量函数 |
| $\varepsilon_{\theta_{i,j}}$ | diffusion 分数（score function） |
| wi | 路由器输出的共识权重，Σwi = 1 |
| Ki | 模态 i 的子专家数量（实验中 Ki=2） |

> 符号与本文/相关文档保持一致：下标 i 表示模态索引，j 表示模态内子专家索引，上标 k 表示 diffusion timestep。

**直觉解释**：
- 传统特征拼接：把所有模态塞进一个网络，让网络自己学怎么融合 → 统计主导模态（视觉）压制稀疏模态（触觉）
- 本文方法：每个模态独立学一个专家，路由器根据当前状态决定听谁的 → 触觉在接触阶段自动获得高权重

## 3. 带数字走一遍：玩具例子 (Worked Example)

**场景**：遮挡物体抓取任务（occluded marker picking）

**任务阶段分解**：

| 阶段 | 时间占比 | 主导模态 | 路由器权重 (w_rgb, w_tac) |
|------|---------|---------|-------------------------|
| 阶段 1：接近容器 | 0-60% | 视觉 | (0.85, 0.15) |
| 阶段 2：进入容器 | 60-80% | 视觉 + 触觉过渡 | (0.55, 0.45) |
| 阶段 3：容器内抓取 | 80-100% | 触觉 | (0.20, 0.80) |

**Diffusion 去噪步骤示例**（假设 K=10 步去噪）：

假设在阶段 3（容器内抓取），路由器输出 w_rgb=0.2, w_tac=0.8

```
步骤 k=5:
  ε_rgb,comp(a^5, ...) = [预测的视觉分数向量，维度=action_dim]
  ε_tac,comp(a^5, ...) = [预测的触觉分数向量，维度=action_dim]
  
  ε_comp = 0.2 × ε_rgb,comp + 0.8 × ε_tac,comp
  
  a^4 = a^5 + step_size × ε_comp + noise
```

**关键观察**：即使视觉专家在某些维度上给出强信号（如"继续前进"），触觉专家的高权重（0.8）可以覆盖这些信号，转而执行"停止并抓取"的动作。这就是为什么在遮挡情况下，本文方法成功率 65% vs 特征拼接基线仅 5%。

## 4. 工程视角 (Engineering View)

### 4.1 计算与延迟 Trade-off

| 指标 | 特征拼接基线 | 本文方法 |
|------|-------------|---------|
| 参数量 | 262.9M | 263.6M (+0.7M, +0.3%) |
| 推理延迟 | 单模型前向传播 | 多专家并行 + 路由器（~1.2x 延迟） |
| 训练复杂度 | 单模型端到端 | 各模态独立训练 + 路由器联合微调 |
| 内存占用 | 基准 | + 各专家模型（可分批加载） |

### 4.2 部署约束

- **推理时**：需要同时加载所有模态专家模型（或实现动态加载机制）
- **训练时**：可以先独立训练各专家，再联合训练路由器（支持增量学习）
- **传感器故障**：当某模态传感器失效时，可以将其权重 wi 手动设为 0，系统降级运行而非完全失效

### 4.3 实现建议

1. **路由器训练**：建议用对比学习或辅助任务预训练，避免初期权重震荡
2. **专家数量 Ki**：论文用 Ki=2，但可根据模态复杂度调整（如触觉可用 Ki=3 区分接触 onset/sustained/release）
3. **权重平滑**：在路由器输出后加 temporal smoothing，避免权重高频抖动导致动作不稳定

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 6.1 能做什么

| 能力 | 场景 | 原因 |
|------|------|------|
| 遮挡操作 | 视觉被遮挡时依靠触觉完成抓取 | 触觉专家独立训练，权重可动态提升 |
| 精细插入 | 毫米级对齐任务 | 触觉专家提供接触力反馈 |
| 传感器故障容错 | 某传感器失效时降级运行 | 可将失效模态权重设为 0 |
| 增量添加传感器 | 新增模态无需重新训练 | 只需训练新专家，路由器可微调适配 |

### 6.2 不能做什么 / 失败模式

| 失败场景 | 原因 | 论文证据 |
|---------|------|---------|
| 极端传感器腐蚀 | 所有模态同时失效或噪声过大 | 项目网站 Limitations 节承认 |
| 需要跨模态推理的任务 | 如"根据触觉纹理推断视觉外观" | 架构设计为独立专家，无跨模态生成能力 |
| 高速动态任务 | 多专家并行推理延迟较高 | 未评估高频控制场景 |

### 6.3 隐含假设 (Hidden Assumptions)

- **假设 1**：各模态在时间上对齐（同步采样）——论文未讨论异步模态处理
- **假设 2**：模态数量固定（路由器输入维度固定）——新增模态需修改路由器架构
- **假设 3**：各专家训练数据分布相似——未讨论域偏移下的组合效果
- **假设 4**：路由器权重在推理时固定——不支持在线适应新任务分布
