### 1.2 关键机制 (Key Mechanism)

**(a) 阶段化程序，而不是单一代价函数。** 一个 stage 定义为 S = (R, T, w, τ)：running cost 项集合、terminal cost 项集合、权重、完成阈值。程序 P = (S₁, …, S_M)。这样"先接近、再对准、再闭合、再抬升"可以被写成 M 段，而不是让一个静态权重去平衡互相冲突的目标。

**(b) cost library 收缩搜索空间。** 论文给了 12 个参数化残差项：point_point_distance、relative_position、axis_parallel、axis_angle、signed_axis_gap、rotation_progress、point_on_line、in_region、tool_mediation、object_held、not_held、gripper_command。VLM 不能凭空发明新代价，只能组合与调参。消融显示这一步很关键：无 library 且无 self-review 时首轮 8/40（20%），有 library 无 self-review 时 20/40（50%）（论文 Table III，实测）。

**(c) terminal cost 带死区 → 阈值同时充当"阶段完成条件"。** 同一个 τ 既让 terminal 代价在残差小于 τ 时归零，又被独立的 stage verifier 用来判断是否推进。这是"目标"和"控制流"共用一个数值的设计。

**(d) 两级修正：先自审，再吃 rollout 反馈。** 自审只看程序本身——后续 stage 能否从前一 stage 的末状态出发、目标是否冲突、抓取/接触要求是否不可行。执行反馈则给 VLM 6 条实测状态记录、到达过哪些 stage、每个 stage 完成条件的最后读数。

⚡ **Eureka Moment**：把"任务目标"从神经网络的隐表示里拿出来，做成一份语言模型可读、可改、可被 MPC 直接执行的**结构化中间产物**——于是"改行为"退化成"改一段 JSON"，不需要重新训练任何东西。

**(e) 一个反向约束：C_physics 常驻。** 除 VLM 指定的项之外，每阶段都加惩罚：控制变化、关节速度、过大接触力、以及**未被 VLM 指定为可动的物体的位姿变化**。最后一项值得单独记：它防止"为了完成任务顺手把旁边东西推开"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
程序 P = (S_1..S_M),  S_m = (R_m, T_m, w_m, τ_m)
控制 U* = argmin_U  J^m_P(U, X)   s.t.  x_{i+1} = f_sim(x_i, u_i)
```

先给目标，再给公式，再给变量说明，最后给直觉。

**目标**：在给定当前 stage m 与程序 P 的条件下，找一条控制序列，使复合代价最小；代价 = VLM 选的 running 项（沿轨迹积分）+ terminal 项（只看末状态）+ 固定物理惩罚。

```
U* = argmin_{U ∈ 𝒰}  J^m_P(U, X)
s.t.  x_{i+1} = f_sim(x_i, u_i)   ∀ x_i ∈ X
X = (x_0, …, x_H),  U = (u_0, …, u_{H-1})
```

> 符号与本文/相关文档保持一致：H 为规划视野步数，B 为每次实际执行并重规划的控制数，N 为 MPPI 采样条数。

**MPPI 加权**（公式 2）：

```
ω_k = exp( -(J^m_P(U^(k), X^(k)) - ρ) / λ ) / Σ_k exp( -(J^m_P(U^(k), X^(k)) - ρ) / λ )
ρ   = min_k J^m_P(U^(k), X^(k))
U*  = Σ_k ω_k · U^(k)
```

**两级残差→代价映射**（公式 3、4）：

```
running:   c_i^R(x,u) = sqrt( 1 + (r_i(x,u)/s_i)^2 ) - 1
terminal:  c_i^T(x,u,τ_i) = ( [r_i(x,u) - τ_i]_+ / s_i )^2
```

**总目标**（公式 5）：

```
J^m_P(X,U) = (1/H) · Σ_{c_i^R ∈ R_m} w_i · Σ_t c_i^R(x_t, u_t)
           + Σ_{c_j^T ∈ T_m} w_j · c_j^T(x_H, u_{H-1}, τ_j)
           + C_physics(X,U)
```

| 符号 | 含义 | 备注 |
|------|------|------|
| r_i | 第 i 个库项的残差（米、弧度或 0/1 指示量） | 各库项定义见论文 Table I |
| s_i | 尺度，与 r_i 同单位，使 r_i/s_i 无量纲 | 论文要求 s_i > 0 |
| τ_i | 第 i 个 terminal 项的完成阈值 | 残差 ≤ τ 时该 terminal 项零代价 |
| w_i | 项权重 | VLM 在程序中给出 |
| [z]_+ | max(0, z) | 死区算子 |
| C_physics | 控制变化、关节速度、接触力、未指定可动物体位姿变化 | 每阶段常驻，非 VLM 生成 |
| λ | MPPI 温度 | 每阶段开始时置 1，MPC 更新间自适应（论文未给自适应公式） |

**直觉**：c_i^R 在 r/s 小时近似 r²/(2s²)（二次型，梯度平滑），在 r/s 大时近似 r/s（线性，不会梯度爆炸）；这是"远离目标时也要有可用的下降方向"的经典做法。c_i^T 用平方加死区，意味着"进入 τ 之后完全不管"，于是 τ 不只是数值容差，而是一个**可执行的行为边界**。

**条件性分析（我的判断）**：把 completion 判据放在 terminal cost 里，等价于让"终止"成为代价设计的一部分而非独立的模式切换逻辑。好处是 VLM 只需要改一个数；代价是 τ 设得过松会让 verifier 过早推进，而 verifier 与真正的任务成功判据是两套东西（论文 §IV-A 明确说任务成功用固定 task-specific criteria，独立于生成的阈值）。

## 3. 带数字走一遍：玩具例子 (Worked Example)

> ⚠️ 以下数值均为**假设**，只为把公式走通并验算，不对应论文任何具体 trial。

**场景假设**：某 carry stage 只有两个 terminal 条件——相对位置项 A 与轴对齐项 B，权重 w_A = w_B = 1。

```
条件 A：relative_position,  r_A = 0.030 m,  τ_A = 0.010 m,  s_A = 0.005 m
条件 B：axis_parallel,      r_B = 0.05 rad, τ_B = 0.10 rad, s_B = 0.05 rad
```

验算 terminal 代价：

```
c_A^T = ( [0.030 - 0.010]_+ / 0.005 )^2 = (0.020/0.005)^2 = 4^2 = 16
c_B^T = ( [0.05 - 0.10]_+ / 0.05 )^2    = 0^2 = 0
J_terminal = 1×16 + 1×0 = 16
```

若位置误差降到 r_A = 0.012 m：

```
c_A^T = (0.002/0.005)^2 = 0.4^2 = 0.16
```

即残差从 20 mm 降到 2 mm（降 10 倍），代价从 16 降到 0.16（降 100 倍）——平方映射把"最后一毫米"的权重放得极大。这解释了为什么阈值设 10 mm 时，controller 会在接近阈值前就开始"用力"，也解释了 τ 设偏的风险。

再验算 running 代价的两种区制：

```
r/s = 0.1 → sqrt(1+0.01) - 1 = 1.0049876 - 1 = 0.0049876
           二次近似 (r/s)^2/2 = 0.005      → 相对误差约 0.25%
r/s = 3.0 → sqrt(1+9) - 1 = 3.1622777 - 1 = 2.1622777
           此时若按二次近似会得 4.5，明显偏离 → 已进入线性区
```

**MPPI 加权验算**（3 条样本，假设）：

```
J = [2.0, 3.0, 5.0],  λ = 1,  ρ = 2.0
未归一化权重 ∝ exp(-(J-ρ)/λ) = [1, 0.367879, 0.049787]
和 = 1.417666
归一化 ω = [0.705375, 0.259489, 0.035136]   （和恰为 1）
设标量控制 U = [0.2, 0.1, -0.4]
U* = 0.705375×0.2 + 0.259489×0.1 + 0.035136×(-0.4)
   = 0.141075 + 0.025949 - 0.014054 = 0.152970
```

若把温度降到 λ = 0.1：

```
未归一化 ∝ [exp(0), exp(-10), exp(-30)] = [1, 4.54e-5, 9.36e-14]
ω ≈ [1.0000, 0.0000454, ~0]  →  U* ≈ 0.2000
```

结论：λ 是"探索 vs 贪心"的旋钮，论文把每个 stage 的初值统一设为 1，靠更新间自适应调整——所以同一 stage 内不同 MPC 更新步的实际 λ 可能不同，这一点会影响复现（我的条件性分析：论文未公开自适应规则，属于复现时必须自行补全的超参）。

## 4. 工程视角 (Engineering View)

**时域账本要对齐，别把三个时间概念混成一个。** 论文参数可以直接推出：

```
单次 MPC 更新覆盖：H × 2 ms = 600 × 2 ms = 1200 ms = 1.2 s   ← 未来预测跨度
每次实际执行并重规划：B × 2 ms = 40 × 2 ms = 80 ms           ← 控制块长度
有效重规划频率：1 / 0.08 s = 12.5 Hz
单次执行上限：250 × 80 ms = 20000 ms = 20 s                  ← 与论文"20 s commanded motion"吻合
每次 MPC 更新的物理步数：N × H = 1000 × 600 = 600,000 步
上限内累计物理步：250 × 600,000 = 1.5 × 10^8 步
```

验算说明：250 次更新 × 40 步 × 2 ms = 20 s，与论文给的上限一致，说明"250 次更新"和"20 s"不是两个独立约束而是同一个约束的两种写法。

**预测视野不是记忆窗口。** 1.2 s 是 f_sim 往前推的未来跨度；它不是历史上下文，也不是模型的记忆长度。同理，反馈时喂给 VLM 的 6 条记录，是在**已执行的历史**上均匀子采样（含首末），若设采样间隔为 Δt，则首末跨度是 (6-1)×Δt = 5Δt。这个 5Δt 是"本次反馈覆盖的历史观测跨度"，随每次执行时长变化，不是固定常数，更不该被写成"OaP 的记忆窗口"。论文没有定义跨 trial 的记忆机制——每个 trial 的程序从上一轮程序继承，但状态记录不跨 trial 累积。

**两个仿真器 = 两笔算力账。** MuJoCo-warp 承担 GPU 并行采样（1000 条 rollout 同时跑），CPU MuJoCo 承担"更准但更慢"的反馈 rollout。这意味着反馈轮次的时间成本主要落在 CPU MuJoCo 串行部分，而 MPC 在线部分靠 GPU 吞吐。论文没给具体延迟数字，所以部署时的实时性仍属未验证项（我的条件性分析：12.5 Hz 重规划频率是否能在真机闭环中稳定维持，取决于未公开的 wall-clock 数据）。

**程序即配置，改行为不改权重。** 工程含义是：调参入口从"重新训练/微调"变成"编辑 JSON 里的 stage 与阈值"。代价是这条链路对 schema 很敏感——论文要求 program 字段含有序 stages 列表，每 stage 有 name、running/terminal cost terms、movable_objects，每个 term 给 type 与 Table I 的参数。schema 一错，MPC 拿到的是无效目标而非"差一点的目标"。

## 5. 数据与评测 (Data & Eval)

**预训练。** 本文不做任何策略预训练，也不更新 VLM 权重。GPT-5.6-sol 以 high reasoning effort 直接推理；Qwen3-VL 只用于估物理参数。这一点必须与端到端 VLA 的训练范式分开看：OaP 的"学习"全部发生在**推理期的程序迭代**里。

**仿真评测设置。** 4 个桌面任务：pick-and-place（橡皮放到白盒顶面并释放）、cup reorientation（抓杯并朝 robot-base +X 倾斜至少 20°，保持抓握）、direct push（直接接触推白盒沿 +X 至少 60 mm）、push with tool（用橡皮推白盒至少 60 mm，保持夹持）。成功判据是固定的 task-specific criteria，与 VLM 生成的阈值无关；仿真用 simulator ground-truth 状态。

**实验次数与"成功率"的语义（关键）。** 论文 Table II 的说明是：每任务每条件 10 次 trial；**earlier successes carry forward**；每轮反馈最多允许一次额外执行。所以表里的"成功率"= 累积成功 trial 数 / 40，含义是"在 k 轮反馈预算内至少成功一次的 trial 比例"，**不是**第 k 轮的单轮成功率。分母是 trial 数（40），而实际执行次数会超过 40。

| 反馈轮次 | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 无 self-review | 20/40 (50%) | 31/40 (77.5%) | 36/40 (90%) | 37/40 (92.5%) | 38/40 (95%) | 38/40 (95%) |
| 有 self-review | 26/40 (65%) | 34/40 (85%) | 36/40 (90%) | 37/40 (92.5%) | 38/40 (95%) | 39/40 (97.5%) |

来源：论文 Table II，实测。可读出的两点：self-review 的收益集中在第 0 轮（20/40 → 26/40），第 2–4 轮两组同为 36/40、37/40、38/40，到第 5 轮才又分开（38 vs 39）；因此"自审的价值随反馈轮次递减"是作者的假设性解释，而"第 2 轮起两者完全同步"并不成立。

**基线对比（仿真，Table III，实测）。**

| 方法 | Pick-and-place | Cup Reorient. | Direct Push | Push with Tool | 总体 |
|---|---|---|---|---|---|
| L2R | 2/10 | 3/10 | 4/10 | 2/10 | 11/40 (27.5%) |
| ReKep | 9/10 | 6/10 | 0/10 | 2/10 | 17/40 (42.5%) |
| CoRAL (adapted) | 7/10 | 6/10 | 10/10 | 8/10 | 31/40 (77.5%) |
| OpenVLA-OFT | 0/10 | 0/10 | 0/10 | 0/10 | 0/40 (0%) |
| π₀.₅ | 10/10 | 0/10 | 0/10 | 0/10 | 10/40 (25%) |
| OaP（2 轮反馈） | 10/10 | 7/10 | 10/10 | 9/10 | 36/40 (90%) |

**VLA 基线必须带条件读。** 论文 §IV-C 明确：VLA 基线保留 released LIBERO evaluation setup 的机器人、相机与控制器配置（Franka Emika Panda、PandaGripper、operational-space pose controller，第三人称 + 腕部相机），只把任务目标与物体换成自己的场景，**不做任务特定微调**。所以这不是跨具身迁移，而是"released checkpoint 零样本迁移到自定义任务场景与物体"。OpenVLA-OFT 的 0/40 与 π₀.₅ 只在 pick-and-place 拿分，不能读作"VLA 方法本身的上限"。CoRAL 一行标为 adapted：论文说原作者未完全开源代码，本文按发表方法尽量复现，并用同一个 GPT-5.6-sol。

**真机设置（与仿真分开看）。** 每任务挑 5 个**在仿真中成功**的程序，每个程序在 2 种物理场景配置下各执行 1 次，共 40 次执行；程序固定，只扰动物体相对精修场景的位置。

| 任务 | 小扰动 | 大扰动 | 合计 |
|---|---|---|---|
| Pick-and-place | 4/5 | 4/5 | 8/10 (80%) |
| Cup Reorientation | 4/5 | 3/5 | 7/10 (70%) |
| Direct Push | 4/5 | 4/5 | 8/10 (80%) |
| Push with Tool | 5/5 | 4/5 | 9/10 (90%) |
| 总计 | 17/20 | 15/20 | 32/40 (80%) |

来源：论文 Table IV，实测。所以真机测的是"仿真成功程序在物体位置扰动下的迁移"，不是在线精修闭环；论文把在线 real-to-sim 与"用真机执行反馈改程序"明确列为 future work。失败归因（作者主张）：多数失败来自抓取质量差，怀疑 VLM 估的摩擦系数偏离实物，3D 打印杯子最明显（仿真预测稳定抓取、真机滑落）；另外仿真把物体当刚体，而实物在接触下会变形，夹持力固定时不同刚度的响应不同。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么（有实测支撑）。** ①零任务特定训练下完成 4 个桌面接触任务，仿真 2 轮反馈内 36/40；②把"多阶段接触任务"表达成可编辑程序，并能通过 rollout 统计定位到具体是哪一段的哪个代价项出错——论文给的 pick-and-place 例子很典型：第一轮反馈后 VLM 在最后阶段保留了 object_held running cost，结果橡皮被"按住"无法放置；第二轮删掉该项并加一个 settling stage，执行成功。这是**程序级可解释性**的实证：失败能定位到一行代价。

**不能做什么（论文自述 + 我的条件性分析）。**

| 失败模式 | 具体表现 | 来源 |
|---|---|---|
| 单向线性程序，无回退 | stage verifier 一旦推进就不能退回上一 stage；若完成条件之后失效，controller 不会显式恢复 | 论文 §V-A 自述 |
| 库表达能力封顶 | 固定 12 项 cost library 决定 VLM 能表达的目标集合 | 论文 §V-A 自述 |
| 依赖重建与接触动力学 | 遮挡、抓取滑移下真机执行退化 | 论文 §V-A 自述 |
| 摩擦/刚度失配 | 仿真稳定抓取、真机滑落；3D 打印杯最明显 | 论文 §IV-D，实测归因 |
| 反馈信息有损 | 每轮只给 6 条均匀子采样记录；若失败发生在两条记录之间，VLM 看不到 | 我的分析 |
| 阈值与真值判据解耦 | verifier 用生成的 τ 推进，成功率用独立判据算；τ 偏松会让"程序认为完成"与"任务实际完成"错位 | 我的分析（论文 §IV-A 确认两套判据并存） |

### 6.1 隐含假设 (Hidden Assumptions)

1. **digital twin 的接触动力学"够用"。** 论文用两个 MuJoCo 变体，但承认 CPU 版"稍更准确"；没有给出接触参数的系统辨识，只把 explicit system identification 列为 future work。于是"仿真里成功"被当作"值得上真机"的代理指标——真机 32/40 说明这个代理有约 20% 的漏损。
2. **物体是刚体、密度与摩擦可从一个 VLM 看外观估出来。** 论文自己在失败分析里推翻了这个假设的一半（变形、摩擦失配）。
3. **一个固定的 cost library 足以覆盖桌面接触任务的目标空间。** 消融显示 library 确实带来大幅提升（20% → 50%），但这只证明"有库比没库好"，没证明"这 12 项够用于其他任务族"。
4. **6 条状态记录足以让 VLM 定位失败原因。** 论文没做 n 的消融（n=6 是设定值，不是调出来的），所以这个信息带宽是否够用属未验证。
5. **stage 之间的状态衔接可由 VLM 在文本层面推断。** 自审就是干这个的；论文的现象（自审在第 0 轮收益最大、后续递减）与该假设一致，但不构成证明。

## 7. 与相关工作对比 (Comparison)

| 方法 | 接口形态 | 谁提供物理 | 是否训练 | 本文实测（仿真总体） |
|---|---|---|---|---|
| L2R | 通用残差项 + 参数/权重 | MuJoCo MPC | 否 | 11/40 (27.5%) |
| ReKep | 关系关键点约束 | 局部前向模型（假设抓取点随末端刚性移动） | 否 | 17/40 (42.5%) |
| CoRAL (adapted) | 多阶段代价 + 物理参数，执行中在线修 | MPC + 参数更新 | 否 | 31/40 (77.5%) |
| OpenVLA-OFT | 直接出动作 | 无显式物理模型 | 预训练 checkpoint，零样本 | 0/40 (0%) |
| π₀.₅ | 直接出动作 | 无显式物理模型 | 预训练 checkpoint，零样本 | 10/40 (25%) |
| **OaP** | **可编辑多阶段 objective program（JSON）** | **MuJoCo-warp 显式仿真接触** | **否（仅推理期迭代程序）** | **36/40 (90%，2 轮反馈)** |

差异点集中在三处：①与 ReKep 相比，OaP 的 forward model 是显式接触仿真，不是刚性附着假设；②与 CoRAL 相比，OaP 的更新发生在**部署前的仿真反馈**里，不在执行中以约 1 Hz 频繁调 LLM；③与 VLA 基线相比，OaP 完全不做动作层面的学习，把泛化压力放在"程序能否被语言模型改对"上。

**面试 Tip**：被问到"这篇和 VLA 什么关系"时，一句话答——"它是 VLA 的并行路线，不是替代：VLA 学的是 π(a|o,ℓ)，OaP 学的是'让语言模型写一个 J(u) 的程序'，前者把物理隐式化，后者把语义显式化；本文的实验里 VLA 基线是零样本迁移到自定义场景，所以那组 0/40、10/40 不能当能力上限引用。"

## 8. 精读建议 (Reading Guide)

- **值得精读原文的人**：
  ①做"基础模型 + 优化控制"混合路线的研究者——重点看 §III-A 的 stage 形式化与 §III-D 的残差→代价映射，这是可复用的设计模式；
  ②要评估"不采数据能不能上新任务"的工程师——重点看 §IV-A 的参数账与 §IV-D 的真机协议，判断 20 s / 250 次更新 / 25 N 这组约束是否匹配你的硬件；
  ③做接触丰富操作、被端到端策略的长尾失败困扰的人——重点看 §V-A 的局限清单，那是这条路线真实的天花板。
- **建议章节路径**：先读 §III-A + §III-D（建立"程序=阶段+库项+阈值"的心智模型）→ 再看 §III-E（反馈到底喂了什么，n=6 是什么）→ 然后 §IV-B/§IV-C 的表格，注意 carry-forward 语义 → 最后 §V-A。§II 相关工作可快读，本文与各基线的差异在那三段里已经说得比较直白。
- **不值得精读的理由**：如果你不做机器人操作、或已熟悉 VLM+MPC 这类"生成目标而非生成动作"的范式，读 Abstract 加 Table II/III/IV 即可；本文的数学是标准 MPPI 加标准残差代价，创新点在接口设计而非公式。若你关心的是动作 chunk、跨具身迁移、触觉闭环，本文没有对应实验。
