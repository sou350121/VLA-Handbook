💡 **X-Ray 开场**
UMI（Universal Manipulation Interface）类手持数据采集系统让机器人学习不再依赖昂贵的机器人闭环采集，但现有系统只采集 RGB 和轨迹——它们"看得见"动作，却"感觉不到"力。OmniUMI 的核心发现是：当你在一个紧凑手持接口中同时采集触觉、内部夹持力和外部交互力，并通过双边夹爪让操作者"感受"到这些力时，采集到的演示数据在接触丰富任务上显著更平滑、更符合人类直觉，下游策略性能也更高。对 VLA 研究者的意义：这提供了一条从"视觉主导"走向"物理感知主导"的数据采集范式转换路径。

### 1.2 关键机制 (Key Mechanism)

**三层架构设计哲学：**

1. **数据采集层 — 物理具身多模态**
   - 不是"加一个传感器"，而是重新设计整个接口让 6 种模态共存
   - 仿生指尖设计：保护触觉传感器同时不牺牲操作能力
   - 电机快换夹爪：数据采集和部署复用同一夹爪，减少 embodiment mismatch

2. **演示层 — 人类对齐交互**
   - 双边夹爪反馈：操作者能"感觉"到内部夹持力，而非仅靠视觉估计
   - 手持形态天然保留对外部交互 wrench 和触觉的感知
   - 关键洞察：不是"测量物理变量"，而是"围绕人类自然感知组织数据采集"

3. **学习部署层 — 多模态策略 + 阻抗控制**
   - 扩展 Diffusion Policy 接受视觉+触觉+力观测
   - 策略输出翻译为虚拟目标，通过阻抗控制执行
   - 无需显式切换运动/力控制模式

⚡ **Eureka Moment**：「不是加传感器，而是让人类感知力」——双边夹爪反馈让操作者在演示时能自然感知和调节夹持力，采集到的数据比纯视觉遥操作更平滑、力波动更小。这解决了"机器能测量但人类调不了"的根本矛盾。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
π_θ(a_t | o_t) = DP_θ( [RGB_t, Depth_t, Tactile_t, F_grasp_t, W_ext_t, Gripper_t] )
     │
     ├── 训练: a_t* = argmin_a Σ_k ||a - β_k||²,  β_k ~ q_φ(a | o_t, noise_k)
     │
     └── 部署: τ = K_p(p_des - p) + K_d(v_des - v) + K_f(f_des - f)
                ↑阻抗控制统一调节运动与接触，无需显式切换
```

**目标**：学习一个联合视觉、触觉和力观测的多模态策略，使策略在接触丰富任务中输出物理一致的动作。

**变量说明**：

| 符号 | 含义 |
|------|------|
| o_t | t 时刻多模态观测向量 |
| RGB_t, Depth_t | 视觉观测 |
| Tactile_t | 触觉传感器读数（指尖压力分布） |
| F_grasp_t | 内部夹持力（沿夹爪轴向） |
| W_ext_t | 外部交互 wrench（3D 力 + 3D 力矩） |
| Gripper_t | 夹爪开合状态 |
| a_t | 策略输出的 6-DOF 动作 + 夹爪指令 |
| β_k | Diffusion 去噪第 k 步的采样动作 |
| τ | 阻抗控制器输出的电机力矩 |
| K_p, K_d, K_f | 阻抗控制的刚度/阻尼/力增益 |

> 符号与本文保持一致：策略部分沿用 Diffusion Policy 标准符号；部署部分采用经典阻抗控制公式。

**直觉**：策略不是"看然后动"，而是"看+感觉+受力然后动"。部署时阻抗控制把策略输出的"想要什么"翻译为"怎么安全地实现"——不需要在"运动模式"和"力模式"之间切换，一个控制器统一处理。

## 3. 带数字走一遍：玩具例子 (Worked Example)

以 **Task 1: 擦白板** 为例，走一遍从采集到部署的闭环：

**采集阶段**：
- 操作者手持 OmniUMI 接口在白板上画圈擦拭
- 传感器实时记录：
  - RGB: 640×480，白色板面 + 红色标记
  - Depth: 端到板面距离 ~5cm
  - Tactile: 指尖压力分布（接触区域 ~2cm²，压力 ~15kPa）
  - F_grasp: 内部夹持力 ~8N（保持稳定握持）
  - W_ext: 外部交互力 — 法向力 ~3N（保持接触），切向力 ~1.5N（滑动摩擦）
  - 轨迹: 角速度 ~0.5 rad/s

**关键对比**（论文项目页数据）：
- 纯视觉遥操作：操作者依赖视觉估计接触力，在接触瞬间出现力过冲，力波动标准差 ~2.1N
- OmniUMI 双边反馈：操作者能"感觉"到法向力，力波动标准差 ~0.8N，下降 62%

**训练阶段**：
- 收集 ~200 个 episode（每 episode ~30 秒）
- 多模态 Diffusion Policy 训练 1000 步
- 输入序列长度 H=16（过去 16 帧观测）
- 输出序列长度 T=4（预测未来 4 步动作）

**部署阶段**：
- 策略输出虚拟目标位置 p_des 和期望力 f_des
- 阻抗控制器：τ = K_p·(p_des - p) + K_d·(v_des - v) + K_f·(f_des - f)
- 实际执行：法向力维持在 2.5-3.5N 范围内，擦除成功率显著提升

**可计算的闭环**：力波动降低 → 数据质量提升 → 策略学习的力调节更精确 → 部署时力控制更稳定。这是一个从采集到部署的完整正反馈。

## 4. 工程视角 (Engineering View)

| 维度 | 设计选择 | Trade-off | 工程含义 |
|------|----------|-----------|----------|
| 传感器集成 | 6 种模态共用一个 Hub | 布线复杂 vs 同步性好 | 减少异步误差，但硬件调试成本高 |
| 夹爪设计 | 电机快换夹爪复用 | 通用性降低 vs 一致性提升 | Collection-deployment 的 embodiment mismatch 大幅降低 |
| 触觉传感 | 仿生指尖保护 | 灵敏度可能降低 vs 耐用性提升 | 适合长期数据采集，不适合高精度触觉研究 |
| 力反馈 | 双边 Master-Slave 夹爪 | 额外电机成本 vs 数据质量提升 | 力波动降低 62%，对接触任务至关重要 |
| 策略部署 | 阻抗控制统一执行 | 需要调 K_p/K_d/K_f vs 无需模式切换 | 简化了控制栈，避免了切换瞬态 |
| 通信 | 单连接 Hub 统一协议 | 带宽瓶颈风险 vs 简化集成 | 6 种模态同步采集，需确保带宽充足 |

**部署约束**：
- 需要同一款电机快换夹爪在采集和部署两端复用
- 阻抗控制参数（K_p, K_d, K_f）需要针对每个任务手动调节
- 触觉传感器需要定期校准（指尖磨损影响读数）

**可扩展性**：
- 理论上可添加更多模态（如 EMG、关节力矩），但 Hub 带宽和同步复杂度会线性增长
- 手持形态限制了传感器数量和重量

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

| 场景 | 原因 |
|------|------|
| 擦拭/拧螺丝等接触丰富操作 | 外部 wrench 感知使策略能调节接触力 |
| 易碎物体抓取 | 内部夹持力感知防止过握力损坏物体 |
| 精密装配（孔轴配合等） | 触觉+wrench 联合提供接触状态细粒度感知 |
| 可变形物体操作 | 力反馈使策略能感知形变并调整策略 |

### 不能做什么

| 场景 | 原因 |
|------|------|
| 自由空间快速运动 | 力传感在此类任务中冗余，反而增加噪声 |
| 双臂协调操作 | 单手持接口无法采集双臂交互数据 |
| 移动机器人操作 | 手持接口设计面向桌面操作，未覆盖移动平台 |
| 大规模跨任务泛化 | 仅 3 个任务验证，策略泛化能力未评估 |
| 高速动态操作 | 阻抗控制适合准静态接触，不适合高速冲击 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **同一夹爪可复用**：假设数据采集和部署使用同一款快换夹爪。如果部署端机器人使用不同夹爪（如不同指宽、不同触觉布局），多模态观测的一致性会显著下降。
2. **力反馈提升数据质量**：假设操作者能利用力反馈采集更高质量的演示。但如果操作者不熟练或力反馈延迟大，可能反而引入更多噪声。
3. **阻抗控制足够通用**：假设阻抗控制能统一处理所有接触任务的运动+力调节。但对于需要显式模式切换的任务（如先自由运动再接触），阻抗控制的单一控制器可能不够灵活。
4. **六模态同步可行**：假设 6 种传感器能通过 Hub 实现精确时间同步。实际中不同传感器的采样率和延迟可能不同，同步误差会影响策略学习。
5. **桌面操作假设**：所有实验在桌面环境下进行，未验证移动平台或全身机器人上的表现。
