💡 **X-Ray 开场**
传统 chunk-based VLA 在动作执行前一次性预测整个动作块（如 50 步），但触觉信息在执行期间变化极快（40 步内余弦距离从 0 变化到 0.55），导致后半段动作基于过时的触觉条件。TacForcing 的核心思路是：把动作块拆成多个子块，先完成靠近执行的子块并下发执行，同时保留后续子块的中间状态，等新触觉数据到来后继续生成——相当于让 VLA "边做边摸边改"。

### 1.2 关键机制 (Key Mechanism)

**问题本质**: 传统 Flow Matching 动作专家对整个动作块共享同一个 flow time，所有动作位置同步去噪生成。触觉观察 T_t 在生成开始时编码一次，后续动作 a_{t+1}, ..., a_{t+H-1} 全部基于这个固定的触觉条件。但触觉状态在执行期间变化剧烈——论文在"捏滴管"任务中测量发现，40 步执行窗口内视觉表征余弦距离仅变化 ~0.005，而触觉表征变化高达 ~0.55。

**解决方案三步**:

1. **分块流调度 (Block-wise Flow Scheduling)**: 将动作块（H=50）分成 K=10 个子块，每块 B=5 个动作。每个子块有独立的 flow time λ_k，靠近执行的子块先完成去噪。
2. **执行中触觉刷新 (Execution-Time Tactile Updates)**: 子块 A_t^(k) 完成后立即执行，执行后采集新触觉 T_t^(k) 并编码为 Z_t^(k)，用于后续子块的生成。
3. **执行感知触觉注意力 EATA**: 新触觉 Z_t^(k) 只允许 attention 到下一个即将执行的子块 A_t^(k+1)，不允许直接 attention 到更后面的子块。通过 additive attention mask 实现。

⚡ **Eureka Moment**: 不是"加入触觉反馈"——而是"控制触觉反馈能 attention 到哪些动作位置"。EATA 的注意力掩码是整篇论文最核心的设计，它解决了"新触觉对远期动作可能已过时"的问题。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L_train = E[ (1/|U(p)|) · Σ_{i∈U(p)} ‖v_θ(a~_t, τ(p), C_t, Z_t^(k*-1); M^(k*)) - (a_{t+i-1} - ε_i)‖² ]
```

**目标**: 训练一个流式速度场 v_θ，使其在任意生成进度 p 下，对未完成动作位置 U(p) 预测正确的速度，条件包括：任务上下文 C_t、当前可用触觉 Z_t^(k*-1)、以及 EATA 掩码 M^(k*)。

**公式拆解**:

| 符号 | 含义 |
|------|------|
| p ~ U([0,1)) | 归一化生成进度，训练时随机采样 |
| k*(p) = ⌊K·p⌋+1 | 当前进度对应的子块索引 |
| λ_k(p) = min(K·p/k, 1) | 子块 k 的 flow time |
| a~_t^(k) = (1-λ_k)·ε^(k) + λ_k·A_t^(k) | 子块 k 的插值状态 |
| U(p) | 未完成动作位置集合 (λ < 1) |
| Z_t^(k*-1) | 当前进度可用的最新触觉编码 |
| M^(k*) | EATA 注意力掩码 |

**直觉**:
- 传统 FM 对整个 chunk 用同一个 τ，所有位置同步去噪
- TacForcing 给每个子块独立 λ_k，近端子块先完成（λ→1），远端子块还在早期（λ≈0）
- 训练时随机采样进度 p，模拟推理过程中任意中间状态
- 损失只计算未完成动作 U(p)，匹配推理时"只更新未完成位置"的行为
- EATA 掩码确保触觉 Z 只影响下一个子块，不污染远期动作

> 符号与本文保持一致：K=子块数, B=子块大小, H=KB=总动作跨度, N=KS=总采样步数

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设 H=10（简化为 10 个动作位置），K=2（2 个子块），B=5（每块 5 个动作），N=4（4 个采样步），S=2（每子块 2 步完成）。

**采样步 n=0**（初始）:
```
子块1 [a0-a4]: λ_1(0) = 0/2 = 0.0 → 全是高斯噪声 ε
子块2 [a5-a9]: λ_2(0) = 0/4 = 0.0 → 全是高斯噪声 ε
触觉: Z_t^(0)（初始触觉）
```

**采样步 n=1**:
```
子块1 [a0-a4]: λ_1(1) = 1/2 = 0.5 → 半去噪
子块2 [a5-a9]: λ_2(1) = 1/4 = 0.25 → 轻微去噪
EATA: Z_t^(0) → 只 attention 到子块1
```

**采样步 n=2**（子块1完成）:
```
子块1 [a0-a4]: λ_1(2) = 2/2 = 1.0 → ✅ 完成，执行 a0-a4
子块2 [a5-a9]: λ_2(2) = 2/4 = 0.5 → 半去噪
→ 采集新触觉 T_t^(1) → 编码为 Z_t^(1)
→ 子块1固定不变，子块2现在接收 Z_t^(1)
```

**采样步 n=3**:
```
子块1 [a0-a4]: 已固定
子块2 [a5-a9]: λ_2(3) = 3/4 = 0.75 → 继续去噪
EATA: Z_t^(1) → 只 attention 到子块2（当前唯一未完成块）
```

**采样步 n=4**（子块2完成）:
```
子块2 [a5-a9]: λ_2(4) = 4/4 = 1.0 → ✅ 完成，执行 a5-a9
→ 采集新触觉 T_t^(2)（但无更多子块，结束）
```

**关键数字验证**: 子块1在 n=2 时完成（占 2/4=50% 的采样预算），子块2在 n=4 完成。触觉在 n=2 时刷新一次，子块2的后半段去噪（n=3,4）使用的是执行了子块1后的新触觉。

## 4. 工程视角 (Engineering View)

| 工程维度 | 分析 |
|----------|------|
| 推理延迟 | 流式生成增加采样步间同步开销，但子块完成即可执行，整体端到端延迟可能降低（边生成边执行） |
| 吞吐 | 单 chunk 内子块串行生成，无法并行；但相比"生成完再执行"的 pipeline，实际 wall-clock 可能更优 |
| 内存 | 需保留所有未完成子块的中间状态（KV cache + 隐状态），内存占用与 K 成正比 |
| 量化误差 | Flow Matching 对量化相对友好（连续速度场），但 EATA 掩码引入的稀疏 attention 可能增加量化难度 |
| 部署约束 | 需要触觉传感器在每个子块执行后可用（论文 B=5，控制频率假设 ~30Hz → 子块间隔 ~167ms） |
| 超参敏感性 | B（子块大小）是关键：B 小 → 触觉刷新频繁但推理开销大；B 大 → 触觉可能再次过时。论文固定 B=5 未做消融 |

**工程含义**: TacForcing 的核心 trade-off 是"触觉刷新频率 vs 推理开销"。传统方法（RDP）用独立高频控制器解决此问题，但需要双模型训练。TacForcing 用单模型 + 流式调度实现类似效果，代价是推理时需要在每个子块完成后重新调用模型。对于算力受限的边缘部署，这是一个值得权衡的设计选择。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **精密装配**: 零件插入、孔位对准等需要力反馈的任务（仿真中 Insert Hole 表现优异）
- **液体操作**: Transfer Liquid 任务中大幅领先所有基线（50% vs ≤19%）
- **接触状态快速变化的任务**: 触觉表征在动作跨度内变化 >0.5 的场景
- **无需高频控制器**: 单模型架构降低部署复杂度

### 不能做什么 / 局限
- **纯视觉任务无优势**: 如果任务不依赖触觉接触，流式生成的额外开销可能不值得
- **未见过的接触模式**: 训练数据中的接触模式有限，泛化到新型接触（如粘性表面、可变摩擦）未验证
- **多臂协作未测试**: 论文方法本身不限制臂数，但实验全部是单臂

### 6.1 隐含假设 (Hidden Assumptions)

| 假设 | 说明 | 风险 |
|------|------|------|
| 触觉传感器延迟可忽略 | 假设每个子块执行后能立即采集并编码触觉 | 实际传感器延迟可能使"最新"触觉在推理时已不是最新 |
| B=5 是通用最优 | 论文固定 B=5 未做消融 | 不同任务可能需要不同子块大小 |
| 触觉编码器泛化性 | 使用 FTP-1 预训练触觉编码器 | 编码器在训练域外的触觉模式上可能失效 |
| 单臂假设 | 实验均为单臂操作 | 双臂协作时触觉反馈的时间对齐更复杂 |
| 接触状态 Markov 性 | 当前触觉只条件到下一子块 | 某些任务可能需要更长程的触觉记忆 |
