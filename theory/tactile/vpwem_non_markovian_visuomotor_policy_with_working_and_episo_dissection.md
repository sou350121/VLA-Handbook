## 1. 核心架构/方法总览 (Overview / Architecture)

VPWEM 的核心思想是解耦短期和长期记忆的建模：短期用滑动窗口（经典做法），长期用一个独立的 Transformer 压缩器递归压缩历史观察。两者联合条件化扩散策略的动作生成。

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 更新频率 | 训练方式 |
|------|------|------|----------|----------|
| 多模态编码器 | RGBD 图像 + 本体状态 | 联合特征向量 o_t ∈ R^D | 每步 | 端到端联合训练 |
| 工作记忆 (WM) | 最近 L 帧嵌入 | w_t = concat(o_{t-L+1:t}) | FIFO 滑动，每步更新 | 无参数 |
| 情景记忆压缩器 | 窗口外观察 + 历史摘要缓存 | e_τ ∈ R^{M×D} | 每步（观察出窗口时） | 端到端联合训练 |
| 扩散策略 | w_t + e_τ + 噪声 a_K | 动作块 a_0 | 每决策步（K 次去噪） | BC 损失联合训练 |

**关键设计选择**:
- 工作记忆窗口 L = 2（短窗口，控制计算量）
- 情景记忆嵌入数 M = 2（固定大小，不随历史增长）
- 压缩器层数 N = 2（轻量 Transformer encoder）
- 缓存最大容量 S = 8（FIFO 管理）

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **固定大小情景记忆**: 无论 episode 多长，情景记忆始终是 M=2 个嵌入。这打破了 O(L²) 自注意力复杂度的束缚。
2. **递归压缩**: 每步当观察出窗口时，压缩器用 self-attention 查询历史摘要 + cross-attention 查询历史观察，递归更新记忆。类似人脑海马体将短期记忆转化为长期存储。
3. **detach 截断梯度**: 存入缓存的观察嵌入和摘要嵌入都 detach 梯度，防止反向传播穿透时间轴——历史信息的传播完全通过摘要嵌入，大幅降低显存占用。
4. **端到端联合优化**: 压缩器和扩散策略用同一个 BC 损失联合训练，压缩器自动学会保留任务相关信息、丢弃无关噪声。

⚡ **Eureka Moment**: 不扩大上下文窗口，而是用一个可学习的压缩器将无限历史压缩为固定大小的记忆嵌入——计算复杂度与历史长度解耦，同时保留任务相关的长程信息。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L = E[||ε - ε_θ(a_k, w_t, e_τ, k)||²]
    其中 e_τ = Compressor(C_f, C_q, o_τ)  递归压缩历史观察
```

**目标**: 训练一个扩散策略，使其在给定工作记忆 w_t（短期）和情景记忆 e_τ（长期）的条件下，从噪声中恢复出正确的动作。

**核心方程**:

```
前向加噪:  a_k = √ᾱ_k · a_0 + √(1-ᾱ_k) · ε,  ε ~ N(0,I)
反向去噪:  a_{k-1} = (1/√α_k) · [a_k - ((1-α_k)/√(1-ᾱ_k)) · ε_θ(a_k, w_t, e_τ, k)] + σ_k · z
训练损失:  L = E[||ε - ε_θ(a_k, w_t, e_τ, k)||²]
```

**情景记忆压缩器**（递归更新）:

```
初始化:    q_{1,τ} = q (可学习参数, M×D)
Self-attn: x_{1,n} = q_{n,τ} + Attn(q_{n,τ}Q_s, C̄_q K_s, C̄_q V_s)
Cross-attn: x_{2,n} = x_{1,n} + Attn(x_{1,n}Q_c, C̄_f K_c, C̄_f V_c)
MLP:       q_{n+1,τ} = x_{2,n} + MLP(x_{2,n})
输出:      e_τ = MLP(q_{N,τ})
```

**变量说明**:

| 符号 | 含义 | 维度 |
|------|------|------|
| a_k | 第 k 步去噪时的动作 | R^{H×A} |
| w_t | 工作记忆（最近 L 帧嵌入拼接） | R^{L×D} |
| e_τ | 情景记忆（压缩器输出） | R^{M×D} |
| q_{n,τ} | 第 n 层压缩器的查询嵌入 | R^{M×D} |
| C̄_f | 观察缓存拼接 | R^{S×D} |
| C̄_q | 摘要缓存拼接 | R^{S×M×D} |
| ε_θ | 去噪网络（Transformer decoder） | — |
| ᾱ_k, α_k, σ_k | 噪声调度器参数 | 标量 |

> 符号与本文保持一致。扩散策略部分沿用标准 DDPM 记号。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 Shell Game 任务：机器人看到球被放在 3 个杯子中的一个下，然后杯子被移动/遮盖，机器人需要记住球的位置并选择正确的杯子。

**设定**:
- 观察维度 D = 64（简化）
- 工作记忆窗口 L = 2
- 情景记忆嵌入数 M = 2
- 缓存大小 S = 4
- 压缩器层数 N = 2

**时间线推演**:

```
t=0: 看到球在杯子A下
  o_0 = [0.1, -0.3, ..., 0.5] (64维)
  工作记忆: w_0 = [o_0]
  情景记忆: 无（还没出窗口）

t=1: 杯子开始移动
  o_1 = [0.2, -0.1, ..., 0.4]
  工作记忆: w_1 = [o_0, o_1]
  情景记忆: 无

t=2: 新观察进入，o_0 出窗口
  o_2 = [0.0, 0.1, ..., 0.3]
  工作记忆: w_2 = [o_1, o_2] (o_0 被 FIFO 淘汰)
  o_0 出窗口 → 加位置编码 f_0 = o_0 + PE(0)
  观察缓存: C_f = [f_0]
  压缩器:
    q_1 = q_learnable = [[0.5, 0.2], [-0.3, 0.4]] (2×2, 简化)
    Self-attn: q_1 查询 C̄_q (空) → x_1 = q_1
    Cross-attn: x_1 查询 C̄_f = [f_0] → x_2 (捕捉到"球在A"的信息)
    q_2 = x_2 + MLP(x_2)
    e_0 = MLP(q_2) = [[0.8, 0.1], [-0.2, 0.6]] ← 情景记忆编码了"球在A"
  
  动作生成: ε_θ(a_K, w_2=[o_1,o_2], e_0, k) → 去噪 → a_0

t=50: 杯子已移动多次，球被遮盖
  工作记忆 w_50 = [o_49, o_50] (只看到杯子和遮盖物，看不到球)
  情景记忆 e_τ = 压缩器递归更新后的结果
    → 经过多次 self-attn (与历史摘要交互) + cross-attn (与历史观察交互)
    → e_τ 仍然编码了"球最初在A"的关键信息
  动作生成: ε_θ(a_K, w_50, e_τ, k) → a_0 = "选择杯子A" ✅

对比 DP (无情景记忆):
  w_50 = [o_49, o_50] → 只能看到当前帧 → 无法推断球的位置 → 随机选择 ❌
```

**关键洞察**: 工作记忆只保留最近 2 帧（看不到球），但情景记忆通过递归压缩保留了 t=0 时的关键信息。压缩器学会了在 t=0 时将"球在A"编码进 e_τ，并在后续 50 步中通过 self-attention 不断巩固这个记忆。

## 4. 工程视角 (Engineering View)

| 指标 | DP (context=4) | DP (context=64) | DP-VPWEM (L2S2) |
|------|----------------|-----------------|-----------------|
| 模型大小 | 50.67M | 50.73M | 52.98M |
| GPU 显存 | 656 MB | 1792 MB | 734 MB |
| 训练时间 | 0.02 s/step | 0.18 s/step | 0.09 s/step |
| 推理时间 | 0.17 s | 0.72 s | 0.22 s |

**工程含义**:

1. **显存恒定**: DP 上下文从 4 扩展到 64 时，显存增长 2.7 倍（656→1792 MB）；VPWEM 仅 734 MB，接近短上下文 DP。这意味着可以在同一 GPU 上跑更大的 batch size。
2. **推理延迟可控**: VPWEM 推理时间 0.22s，比 DP(context=64) 的 0.72s 快 3 倍。对于 10Hz 控制频率（100ms 预算），VPWEM 可行；长上下文 DP 不可行。
3. **额外参数极小**: VPWEM 仅增加约 2.3M 参数（50.67M → 52.98M），主要来自压缩器的 2 层 Transformer。
4. **训练开销**: VPWEM 训练时间 0.09s/step，是长上下文 DP(64) 的一半。但比短上下文 DP 慢 4.5 倍——这是为长程记忆支付的代价。
5. **部署约束**: 压缩器的缓存大小 S=8 是硬编码的超参。部署时需要维护两个 FIFO 队列（观察缓存 + 摘要缓存），内存占用 O(S·D)，非常轻量。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**:
- 需要跨长时间步记住关键信息的任务（如 ShellGame 中球被遮盖后仍记得位置）
- 长程移动操作任务（如 MoMaRT 中从洗碗机取盘子放到桌上）
- 部分可观察任务（当前帧不足以推断完整状态，需要历史信息）

**不能做什么**:
- Markovian 任务上没有收益（Robomimic Square/Transport 与基线持平）——压缩器没有带来额外价值
- 极度依赖精确时序的任务（压缩器是固定大小嵌入，可能丢失精确时间信息）
- 需要记住大量离散事实的任务（M=2 个嵌入的信息容量有限）

### 6.1 隐含假设 (Hidden Assumptions)

1. **历史信息可通过固定大小嵌入充分压缩**: 假设任何任务相关的历史都可以被压缩为 M=2 个嵌入。但对于需要记住大量独立事实的任务（如"依次访问 10 个位置"），这可能不够。
2. **压缩器和策略可以端到端联合训练**: 理论上优雅，但实际中压缩器和策略的梯度可能存在冲突——压缩器想保留更多信息，策略想忽略噪声。论文通过 detach 缓解了这个问题，但最优平衡点可能因任务而异。
3. **缓存大小 S=8 足够**: 缓存管理使用 FIFO，假设最近 8 个出窗口的观察足以代表整个历史。对于超长 episode（>1000 步），早期信息可能完全丢失。
4. **单帧编码器已足够强**: VPWEM 假设单帧编码器能提取足够的特征，压缩器只需做时序整合。如果单帧特征本身不足（如遮挡严重），压缩器也无法弥补。

## 7. 与相关工作对比 (Comparison)

| 方法 | 记忆机制 | 复杂度 | 训练方式 | 适用场景 |
|------|----------|--------|----------|----------|
| DP | 无（固定窗口） | O(L²) | BC | Markovian 任务 |
| RNN/LSTM | 隐状态传递 | O(L) | BC | 短程依赖 |
| MaIL (Mamba) | SSM 隐状态 | O(L) | BC | 短上下文长程 |
| DP-PTP | 辅助 past-token 预测 | O(L²) | BC + 辅助 | 缓解 copycat |
| CronusVLA | 多帧 VLA 后训练 | O(L²) | 后训练 | 多帧 VLA |
| MemoryVLA | 检索-融合记忆 | O(L²) | 微调 | VLA + 检索 |
| BPP/MemER | VLM 关键帧选择 | O(L) + VLM 调用 | 两阶段 | VLM 辅助 |
| **VPWEM** | **双记忆压缩** | **O(1) (每步)** | **端到端 BC** | **非马尔可夫 IL** |

**面试 Tip**: 当被问到"VPWEM 和 RNN/SSM 记忆的区别是什么？"——回答："RNN/SSM 通过固定维度的隐状态逐步传递历史信息，存在信息瓶颈；VPWEM 用显式的注意力缓存机制，通过 self-attention 和 cross-attention 有选择地保留和检索历史信息，信息容量更灵活，且计算复杂度与历史长度解耦。"
