### 1.2 关键机制 (Key Mechanism)

FELT 的核心设计围绕一个关键洞察展开：

**为什么用双分支解码器？** 左右手指是独立的物理表面，经历不同的接触模式（如擦拭时一侧受力、插入时两侧不对称）。单分支解码器会混淆两侧信号，导致力平衡预测错误。

**为什么用 frozen DINOv2？** 利用预训练视觉编码器的多尺度特征（低层纹理 + 高层语义），避免触觉生成器从头学习视觉表征。

**为什么分接触检测 + 压力回归两步？** 触觉图像极度稀疏（大部分区域无接触）。用 Focal + Dice Loss 处理类别不平衡检测接触区域，再用 Value-Weighted Huber Loss 强调高压区域——分别优化比端到端 MSE 效果好得多。

⚡ **Eureka Moment**：视觉上下文中的夹爪-物体-接触区域几何关系，足以预测触觉压力分布——不需要额外的触觉传感器，只需要 fisheye 相机拍到接触区域。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L(φ) = E[ L_contact(c_hat, c) + L_intensity(p_hat, p) ]
     = E[ Focal+Dice(c_hat, c) + VW-Huber(p_hat, p) ]
```

**目标**：从 RGB 图像 I^vis 学习映射 G_φ，生成与真实触觉图像 I^tac 物理一致的触觉信号。

**公式分解**：

```
G_φ: I^vis_t → ~I^tac_t ∈ R^{12×32×2}
```

- 输出每 finger 12×32 网格，每个 cell 两个通道：接触概率 + 压力强度
- 总损失 = 接触损失 + 强度损失

**变量说明**：

| 符号 | 含义 | 维度 |
|------|------|------|
| I^vis_t | t 时刻 RGB 图像 | R^{H×W×3} |
| ~I^tac_t | 生成的触觉图像 | R^{12×32×2} |
| c_hat_t | 预测接触 logit | R^{12×32×2} |
| p_hat_t | 预测压力强度 | R^{12×32×2} |
| c_t, p_t | 真实接触/压力（从 I^tac 提取） | R^{12×32×2} |
| L_contact | Focal Loss + Dice Loss | scalar |
| L_intensity | Value-Weighted Huber Loss | scalar |

> 符号与本文保持一致：上标 vis/tac 区分视觉/触觉模态，下标 t 表示时间步，hat 表示预测值。

**直觉**：触觉生成不是图像到图像的像素重建问题——它是"接触在哪里"（稀疏分类）+ "接触有多强"（回归）的组合问题。分开优化比统一 MSE 更适配触觉数据的稀疏性和非均匀分布。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2×2 触觉网格（论文实际是 12×32），用假设的合理数值演示训练过程。

**场景**：夹爪左侧手指接触物体，右侧无接触。

**Ground Truth**：
```
c (contact):    p (pressure):
[[1, 0],        [[0.8, 0.0],
 [1, 0]]         [0.6, 0.0]]
```

**FELT 预测**（假设训练中间状态）：
```
c_hat:          p_hat:
[[0.7, 0.2],    [[0.5, 0.1],
 [0.6, 0.3]]    [0.4, 0.2]]
```

**接触损失计算**：
```
Focal Loss(c_hat, c) ≈ 0.35  (处理正负样本 1:3 不平衡)
Dice Loss(c_hat, c) ≈ 0.20   (IoU 约 0.67)
L_contact = 0.35 + 0.20 = 0.55
```

**强度损失计算**（Value-Weighted Huber）：
```
Huber(0.5, 0.8) = 0.045  (大误差，二次区)
Huber(0.4, 0.6) = 0.020
加权后（高压 cell 权重更高）:
L_intensity = 0.7×0.045 + 0.3×0.020 = 0.0375
```

**总损失**：
```
L(φ) = 0.55 + 0.0375 = 0.5875
```

**关键观察**：接触损失的量级远大于强度损失——这符合设计意图，因为"接触在哪里"比"接触多强"更关键。如果接触区域预测错误，压力值再准也没用。

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/约束 | 含义 |
|----------|-----------|------|
| 生成器延迟 | ~20ms (RTX 4090) | 支持 10Hz 闭环控制（策略本身 10Hz） |
| 触觉网格 | 12×32×2 | 每 finger 768 个 cell，非常轻量 |
| 视觉编码器 | DINOv2 ViT (frozen) | 推理时不更新，节省计算 |
| 可训练参数 | 仅 query decoder + conv head | 参数量远小于从头训练 |
| 训练数据 | 2.6M RGB-tactile 对 (80/20 split) | 需要配对数据，但不需要任务特定数据 |
| 策略训练数据 | 60 demos/task (~520K frames, 4 tasks) | 低数据 regime，与生成器训练数据独立 |
| 部署模式 | 三种：离线增强/在线生成/隐特征 | 隐特征模式完全不需要触觉硬件 |

**工程含义**：
- FELT 将触觉传感器从"策略部署的必需品"降级为"仅训练生成器时需要"，大幅降低部署成本
- 20ms 生成延迟 vs 策略本身的推理时间，需要评估总延迟是否满足控制频率要求
- 隐特征模式（12×32×256 = 98,304 维/帧）比触觉图像（12×32×2 = 768 维/帧）高两个数量级，但策略可以直接消费这些特征，无需解码

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

| 能力 | 证据 | 条件 |
|------|------|------|
| 生成物理一致的触觉图像 | LPIPS 0.191，Energy Ratio 1.123（表 1） | 需要 fisheye 相机拍到夹爪+接触区域 |
| 提升下游策略成功率 | 4 个任务全部超越 Vision Only（表 2） | 生成器需在相似传感器数据上训练 |
| 隐特征模式完全免触觉硬件 | Triangle Peg Insertion 90%（vs 真实触觉 70%）（表 2） | 低数据 regime 下有效（60 demos/task） |
| 支持非对称接触模式 | 双分支 + 面板交换消融验证（表 1） | 需要左右 finger 分别建模 |

### 不能做什么

| 失败模式 | 原因 | 证据 |
|----------|------|------|
| 跨传感器泛化 | 训练于 FlexiTac 12×32 网格，未验证其他传感器 | 论文仅用单一传感器 |
| 夹爪不在视野内时生成 | 依赖视觉上下文中的夹爪-物体几何关系 | 假设 fisheye 相机拍到接触区域（§3） |
| 高精度压力校准 | Panel Asymmetry Error 0.738（不如 MAE 的 0.431）（表 1） | 左右力平衡仍有误差 |
| 高频动态接触 | 策略部署 10Hz，可能错过快速接触变化 | 未报告 >10Hz 的接触动态评估 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **Fisheye 相机始终可见夹爪和接触区域**——如果相机视角偏移或物体完全遮挡夹爪，生成质量会急剧下降。论文 §3 明确假设了这一点，但未系统验证视角鲁棒性。

2. **训练传感器与部署传感器物理拓扑一致**——12×32 FlexiTac 网格是固定的。更换传感器型号（如 16×16 或不同排列）需要重新训练生成器。

3. **低数据 regime 下隐特征优于真实触觉**——论文观察到这一现象（§6.2），但承认"这是一个假设，需要进一步评估"。在高数据 regime（>500 demos）下，真实触觉可能仍然占优。

4. **RGB-tactile 时间同步精度足够**——论文提及"所有传感器流在策略训练前时间对齐"（§5.1），但未报告同步误差范围。如果同步误差 >50ms（半个控制周期），生成的触觉信号可能与实际动作错位。
