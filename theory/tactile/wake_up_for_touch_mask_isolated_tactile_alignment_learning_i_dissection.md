### 1.2 关键机制 (Key Mechanism)

Splash 的核心机制分为两步：

1. **定位休眠子空间**：使用视觉相对重要性评分（借鉴 Wanda 剪枝方法），在小型校准集（128 个 CC3M 样本）上计算每个权重的贡献度 `S[i,j] = |W[i,j]| · ||x[i]||₂`。按稀疏度阈值 s=60% 将参数分为"关键"（冻结）和"休眠"（可训练）两个子空间。

2. **掩码隔离训练**：训练时，关键参数完全冻结作为视觉知识的"锚点"，仅更新休眠子空间参数 + 触觉前端。梯度通过二值掩码 M 进行门控：`θ ← θ - η·(M ⊙ ∇θL)`。

⚡ **Eureka Moment**：预训练 MLLM 中存在大量对 VL 任务贡献极小的"休眠"参数——这些参数不是冗余的噪声，而是可以被"唤醒"用于新模态适配的天然容量。与其像 LoRA 那样在原有参数空间上叠加增量（扰动整个流形），不如直接隔离出一块"安全区"专门给新模态用。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L = -Σ_n log P(y_n | y_{<n}, X_RGB, X_Tactile, X_Text)
s.t. ∇θ[i,j] = 0 当 M[i,j] = 0 (关键参数冻结)
```

**目标**：在保持关键 VL 参数不变的前提下，最大化触觉描述生成的似然。

**完整训练目标**：
```
L = -Σ_{n=1}^{N} log P(y_n | Y_{<n}, X_R, X_C, X_T)
```

**参数更新规则**：
```
θ* ← θ - η · (M ⊙ ∇_θ L)    // 掩码门控的 LLM 更新
ψ  ← ψ - η · ∇_ψ L            // 触觉前端全量更新
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| X_R | RGB 自然图像 |
| X_C | 触觉接触图像 |
| X_T | 文本 prompt |
| Y | 生成的触觉描述 token 序列 |
| $\theta$ | LLM 参数 |
| $\psi$ | 触觉前端参数 |
| M | 二值掩码 (M[i,j] = 1 表示休眠/可训练) |
| s | 稀疏度比例 (默认 60%) |
| $\eta$ | 学习率 (2e-5, cosine decay) |

**直觉**：掩码 $M$ 像一个"安全阀"——它确保只有那些对原始 VL 任务贡献最小的参数被修改，关键参数被严格保护。这与 LoRA 的 $\theta + \Delta\theta$ 加法模式不同，Splash 是"替换"模式：休眠参数直接被重新分配给触觉任务，不增加任何参数量。

> 符号与原文保持一致：$F_\varphi$ 为视觉前端，$F_\psi$ 为触觉前端，$\mathrm{LLM}_\theta$ 为语言模型骨干。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2 层 MLP，每层 4 个参数：

```
Layer 1: W = [0.8, -0.1, 0.05, -0.02]   (权重幅度递减)
         x = [1.0, 0.5, 0.3, 0.1]       (激活值)
```

**Step 1 — 计算重要性分数** `S[i] = |W[i]| · ||x[i]||`：
```
S = [0.8×1.0, 0.1×0.5, 0.05×0.3, 0.02×0.1]
  = [0.80, 0.05, 0.015, 0.002]
```

**Step 2 — 按 s=60% 设定阈值**：
60% 的参数（即 $2.4 \to 2$ 个）应被标记为休眠。排序后 $S = [0.80, 0.05, 0.015, 0.002]$，取第 60 百分位阈值 $\tau \approx 0.05$。

**Step 3 — 生成掩码** `M[i] = 1(S[i] < τ)`：
```
M = [0, 0, 1, 1]
```
→ $W[0]=0.8$ 和 $W[1]=-0.1$ 是关键参数（冻结），$W[2]=0.05$ 和 $W[3]=-0.02$ 是休眠参数（可训练）。

**Step 4 — 触觉训练时的梯度更新**：
假设梯度 $\nabla L = [0.1, 0.2, 0.3, 0.4]$，$\eta=0.01$：
```
θ_update = η · (M ⊙ ∇L) = 0.01 · [0, 0, 0.3, 0.4] = [0, 0, 0.003, 0.004]
θ_new    = [0.8, -0.1, 0.05+0.003, -0.02+0.004] = [0.8, -0.1, 0.053, -0.016]
```
关键参数 W[0] 和 W[1] 完全不变——视觉知识的安全锚点。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

- **触觉属性推理**：从 RGB + 触觉图像生成自然语言触觉描述（如"粗糙、柔软、有弹性"）
- **跨数据集泛化**：在 TacQuad（手持交互数据，分布偏移）上保持 4.86 分，显著优于 TVL-LoRA 的 4.22
- **保留 VL 能力**：MMMUval 从 53.1 提升到 55.3，MathVista 从 62.3 提升到 65.3——触觉适配未损害通用 VL 推理
- **边缘部署**：3B 模型 + 零额外推理开销，适合资源受限的机器人平台

### 不能做什么

- **动态交互场景**：掩码是离线静态生成的，无法适应交互过程中参数重要性的动态变化
- **跨传感器迁移**：目前仅在 DIGIT 传感器上验证，跨传感器泛化待探索
- **长期视触推理**：论文承认静态掩码可能无法捕捉长时间视触推理中的时变参数利用率

### 6.1 隐含假设 (Hidden Assumptions)

1. **自然稀疏性假设**：预训练 MLLM 中确实存在大量"休眠"参数——这个假设在实验中得到了验证（60% 稀疏度下表现最佳），但对于不同架构/规模的模型，休眠比例可能不同
2. **VL 重要性 $\approx$ 全局重要性**：使用 VL 校准数据计算的重要性分数假设"对 VL 不重要的参数对触觉也不重要"——这可能不成立，某些参数可能对 VL 和触觉都重要
3. **静态掩码充分性**：假设离线计算的掩码足以覆盖整个训练过程的参数需求——作者自己也承认这是一个局限
4. **触觉前端初始化非关键**：消融实验（Table 5）显示即使使用 TVL 的触觉编码器初始化，Splash 仍然优于 TVL，表明增益主要来自掩码策略而非前端初始化——但这仅在 DIGIT 传感器上验证
