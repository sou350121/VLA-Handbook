### 1.2 关键机制 (Key Mechanism)

**问题 1 — 触觉表示丢失手指空间结构**：现有方法通常将触觉信号展平为通用 token 或压缩为时间力序列，丢失了"哪个手指、哪个接触区域"的空间拓扑。ReTouch 的 Tactile-Patch Encoder 将每根手指的 120 个 taxel 按功能接触区域划分为 5 个 patch（指尖、指中、指根、左侧、右侧），保留手指身份和局部接触结构。每帧只向策略暴露 5 个触觉 token（每指一个），极度紧凑。

**问题 2 — 触觉预测在执行过程中过时**：现有预测式方法在动作块开始时生成触觉预测，然后在高频更新中只修正动作、不重新估计预测。ReTouch 的关键创新是将未来触觉隐状态视为**执行时状态**——每次高频调用时，FAE 用最新触觉反馈精炼 Z^+_t，同时重新生成剩余动作块 A^_t。

⚡ **Eureka Moment**：触觉预测不应该是一次性前向输出，而应该作为递归维护的控制状态——每次收到新触觉反馈时同时更新"预测了什么"和"该做什么"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
(Z^_t^+, A^_t) = FAE(c_k, s_k, T_t, Q~_t^fore)
其中 Q~_t^fore = M_t · stop-gradient(Z^_{t-1}^+) + (1 - M_t) · Q^fore
```

**目标**：在动作块执行过程中，用最新触觉反馈递归更新未来触觉隐状态和剩余动作，使预测始终与实际接触状态对齐。

**核心方程分解**：

```
Q~_t^fore = M_t ⊙ sg(Z^_{t-1}^+) + (1 - M_t) ⊙ Q^fore
```

| 符号 | 含义 |
|------|------|
| Q~_t^fore | 当前时刻的触觉前瞻查询（用于 FAE 输入） |
| M_t | 掩码，选择已执行部分对应的隐状态前缀 |
| sg(·) | stop-gradient，防止梯度回传到携带的隐状态 |
| Z^_{t-1}^+ | 上一时刻精炼的未来触觉隐状态 |
| Q^fore | 可学习的初始触觉前瞻查询 |
| Z^_t^+ | 精炼后的未来触觉隐状态 |
| A^_t | 更新后的动作块 |

```
(Z^_t^+, A^_t) = FAE_θ(c_k, s_k, T_t, Q~_t^fore)
```

| 符号 | 含义 |
|------|------|
| c_k | VLM 缓存的语义上下文（9Hz 低频更新） |
| s_k | 动作块起始的机器人状态 |
| T_t | 时刻 t 的触觉上下文（当前+历史触觉观测） |
| FAE_θ | Foresight Action Expert（参数 θ） |

**训练损失**：
```
L_policy = L_act^hid + L_act^fore + λ_align · L_align + L_update
```

| 项 | 含义 |
|----|------|
| L_act^hid | HAE 的动作流匹配损失（仅训练） |
| L_act^fore | FAE 的动作流匹配损失 |
| L_align | 余弦距离对齐 FAE 预测与 HAE 目标隐状态 |
| L_update | 随机中间偏移处的更新监督（对齐训练与推理） |

**直觉**：HAE 像"阅卷老师"——看到标准答案后给出最优隐状态目标；FAE 像"考生"——只能看到当前观测，学习预测未来。对齐损失让考生学会老师的方式思考。部署时老师消失，考生独立工作，但每次收到新反馈时都会"重新思考"。

> 符号与本文保持一致：上标 ^ 表示预测/估计值，上标 + 表示未来时段，下标 t 表示高频调用时刻，下标 k 表示低频 VLM 更新时刻。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2D 场景：用灵巧手捏住一个圆柱体并旋转。

**初始状态**（t=0，动作块开始）：
- 5 指接触力：[拇指 2.1N, 食指 1.8N, 中指 1.5N, 无名指 0.3N, 小指 0.1N]
- 拇指和食指在 tip patch 接触，中指在 center patch 轻触
- FAE 首次调用：M_0 = 0，查询完全来自 Q^fore
- 预测未来触觉：拇指力递增（捏紧），食指力稳定

**执行 4 步后**（t=1，检测到打滑）：
- 新触觉：拇指力从 2.1N 降到 1.2N（打滑），食指力从 1.8N 升到 2.3N（补偿）
- FAE 第 2 次调用：M_1 选择前 4 步对应的隐状态前缀
- Q~_1^fore = M_1 · sg(Z^_0^+) + (1 - M_1) · Q^fore
- 用新触觉反馈精炼 Z^_1^+：拇指接触区域从 tip 转移到 base（手指滑入）
- 重新生成动作：增加拇指法向力 + 调整食指角度

**对比 one-shot 变体**：
- one-shot 也重新生成动作，但 Z^+ 保持 t=0 的预测不变
- 结果：one-shot 的触觉预测仍认为"拇指 tip 强接触"，但实际已滑到 base
- ReTouch 的预测更新为"拇指 base 接触增强"，动作修正更准确

**量化效果**（来自论文 Fig.5，100 条测试轨迹平均）：
- 接触后阶段：ReTouch 将隐状态余弦相似度提升 0.908%
- 接触后阶段：ReTouch 将剩余动作 MSE 降低 2.139%
- 误差减少随更新次数递增——更新越频繁，对齐越好

## 4. 工程视角 (Engineering View)

| 维度 | 数值/设计 | 工程含义 |
|------|-----------|----------|
| VLM 频率 | 9 Hz | 低频语义推理，缓存上下文避免重复推理 |
| FAE 频率 | 36 Hz | 4× 于 VLM，高频触觉闭环控制 |
| 动作块长度 | 16 步 | 每个 chunk 内 FAE 调用约 4 次（36Hz / 9Hz ≈ 4） |
| 触觉历史窗口 | 9 帧 | 约 250ms 历史，捕捉接触动态趋势 |
| 训练步数 | 80k（策略）+ 20k（TPE 预训练） | 两阶段训练，TPE 先冻结 5k 步再端到端 |
| 随机偏移 | {4, 8, 12} | 训练时随机选 chunk 中间位置开始更新，对齐推理 |
| 每指 taxel 数 | 120 个 3D 力 | 5 指 × 120 × 3 = 1800 维原始触觉输入 |
| 压缩后 token | 5 个/帧 | 从 1800 维压缩到 5 个 token，极大降低策略输入维度 |

**关键 trade-off**：
- **频率比 4:1（FAE:VLM）**——足够高频以捕捉接触动态，又不需要每步都跑 VLM。但如果接触变化更快（如快速打滑），可能需要更高频率。
- **16 步 action chunk**——足够长以完成子任务，但过长会导致预测过时更严重。消融显示去掉 chunk 内精炼损失 23.6%，说明 chunk 长度与预测过时的权衡很关键。
- **5 个触觉 token/帧**——极度紧凑，但依赖于 Tactile-Patch Encoder 的质量。如果手指结构或传感器布局不同，需要重新设计 patch 划分。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- 持续接触任务（Sponge Wipe +25.0%，Liquid Transfer +19.0%）——在线精炼的优势最明显
- 接触几何变化（高度变化、物体位移）——触觉反馈弥补视觉-接触映射偏差
- 光照变化——触觉提供视觉之外的独立接触信息源（+20.0%）
- 抓取后外部扰动（拉拽 +30.0%，ReTouch 85.0% vs 最强基线 55.0%）——在线精炼的核心价值

**不能做什么 / 局限**：
- Cabinet Retrieval 任务（62.5% vs ViTacFormer 67.5%）——纯视觉遮挡场景下，ViTacFormer 的交叉注意力触觉融合可能更适合，ReTouch 的在线精炼优势未显现
- 泛化到其他灵巧手平台——实验仅在 XHand-UR7e 上验证，patch 划分（5 功能区）依赖特定传感器布局
- 超出 900 条演示的数据分布——所有方法在同一数据集上训练，未见更大规模数据下的表现

### 6.1 隐含假设 (Hidden Assumptions)

1. **触觉传感器延迟可忽略**：36Hz 高频调用假设触觉数据到达延迟远小于 28ms（1/36s）。实际传感器可能有额外延迟，影响闭环性能。
2. **触觉 patch 划分是通用的**：5 功能区（tip/center/base/left/right）假设适用于大多数灵巧手接触场景。不同手指构型或传感器密度可能需要不同划分。
3. **HAE 的"阅卷老师"角色不会过拟合**：HAE 使用真实未来触觉生成目标，理论上可能学到部署时 FAE 无法复制的表示。虽然用了 stop-gradient 和对齐损失，但 HAE-FAE 差距仍是潜在风险。
4. **7 任务共享单一策略可行**：所有 7 个任务训练单一策略（80k 步），未展示任务数量增加时的可扩展性。

💡 **面试 Tip**：如果被问到"ReTouch 和 UniTacVLA/TouchWorld 的核心区别是什么"——回答：它们把触觉预测当作一次性生成的参考信号（planning-rate），高频反馈只修正动作；ReTouch 把触觉预测当作递归维护的控制状态（control-rate），每次高频调用同时更新预测和动作。这是"开环预测"和"闭环状态估计"的本质区别。
