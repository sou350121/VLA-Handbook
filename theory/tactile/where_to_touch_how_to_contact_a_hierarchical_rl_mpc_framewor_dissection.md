## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 职责 | 输入 | 输出 | 训练方式 | 运行频率 |
|------|------|------|------|----------|----------|
| **高层 RL 策略** | 几何推理：决定在哪接触、物体子目标 | 三组件物体坐标系观察 (点云+目标流+碰撞距离) | Contact Intention (接触位置 + 子目标位姿/权重) | PPO 仿真训练，抽象末端执行器 | ~10 Hz (每 T 步决策一次) |
| **Contact Intention 接口** | 解耦层：将几何意图传递给底层 | 高层 RL 输出 | 接触位置 $\bar{c} \in G$ + 子目标 $\bar{q}_{\text{obj}} \in SE(3)$ | 无训练（数据结构） | 跟随高层频率 |
| **底层 ComFree-MPC** | 接触动力学推理：生成具体机器人动作 | Contact Intention + 当前系统状态 | 机器人关节动作序列 (H 步预测) | 无训练（模型优化） | ~100 Hz (实时滚动优化) |
| **抽象末端执行器** (仅训练期) | 加速 RL 训练：简化为质点-弹簧-阻尼器 | 物体状态 | 接触力 | 不参与（仿真建模） | — |

**训练 vs 推理差异**：
- 训练期：RL 在抽象末端执行器仿真中训练（加速），MPC 不参与训练
- 推理期：RL 策略零样本迁移到真实机器人，搭配具体机器人的 ComFree-MPC

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **几何与动力学解耦**：传统端到端策略必须同时学习几何理解和接触物理，搜索空间巨大。分解后，RL 只需学"该碰物体哪个面"，MPC 负责"怎么碰出期望运动"。
2. **物体坐标系观察**：所有观察量（几何点云、目标流、碰撞距离）都在物体坐标系下表示，策略不需要"重新发现物体位姿相关的变换"——天然具备位姿不变性。
3. **Contact Intention 作为抽象动作空间**：RL 不直接输出关节力矩或末端位姿，而是输出语义更高层的"接触意图"。这使得同一策略可适配不同机器人（只需更换底层 MPC）。
4. **多速率耦合**：高层 RL 每 T 步决策一次，底层 MPC 在 T 步内以 100Hz 滚动优化——匹配了几何决策的慢变性和接触控制的快速性。

⚡ **Eureka Moment**：接触操作的核心难点不是"如何执行接触"，而是"在哪里接触"——把几何推理从接触动力学中剥离出来，RL 的数据效率问题迎刃而解。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
I_k = π(o_k) = (c̄_k, q̄_obj_k)    ← RL 输出接触意图
u_{0:H-1} = argmin Σ L(p_ee, c̄_k) + V(q_H, q̄_obj_k)  ← MPC 执行
```

**目标**：在接触丰富的操作中，找到一个分层策略，使得高层决定"在哪碰、碰成什么样"，底层负责"怎么碰"。

**公式分解**：

```
Contact Intention 定义:
  I = (c̄¹, c̄², ..., c̄ⁿ, q̄_obj) ∈ Gⁿ × SE(3)

  其中:
    c̄ⁱ ∈ G  — 物体表面 G 上的第 i 个接触位置
    q̄_obj ∈ SE(3) — 接触后的物体子目标位姿
    n = 1 (单 stick 末端执行器)

MPC 优化目标 (每控制步 t):
  min_{u_{0:H-1}}  Σ_{t=0}^{H-1} [ w_c · ||p_ee,t - T_obj^w · c̄_k||² ]
                   + V(q_H_obj, q̄_obj_k)

  其中:
    w_c — 接触位置跟踪权重
    p_ee,t — t 时刻末端执行器位置
    T_obj^w — 物体坐标系到世界坐标系的变换
    V(q_H, q̄_obj) — 终端代价，鼓励物体到达子目标
    ComFree(x_t, u_t) — 无互补约束的接触动力学模型

子目标参数化 (Option 1):
  V(q_obj, q̄_obj) = w_pos · e_pos(p_obj, p̄_target)
                   + w_ori · e_ori(r_obj, r̄_target)

  其中:
    w_pos, w_ori ∈ {0,1} — RL 离散选择
    e_pos — 位置误差
    e_ori — 姿态误差
```

> 符号与本文保持一致：𝒢 为物体表面点集，SE(3) 为三维特殊欧氏群，ComFree 为 complementarity-free contact model (Yang et al.)。

## 3. 带数字走一遍：玩具例子 (Worked Example)

**场景**：将一个 L 形物体从初始位姿推到目标位置（平面 2D 简化版）。

**初始状态**：
- 物体中心位置：p_obj = (0, 0)，姿态 θ = 0°
- 目标位置：p_target = (0.5, 0.3)，目标姿态 θ_target = 45°
- 物体表面关键点集 $P = \{p_0, \dots, p_{N-1}\}$，$N = 20$ 个点

**第 1 步 — RL 决策**：
- 观察 $o_0 = (P, \Delta P_0, D_0)$
  - P: 20 个物体表面点（物体坐标系下固定）
  - $\Delta P_0$: 每个点从当前位置到目标位置的位移向量
  - D_0: 每个点到障碍物的距离（假设无障碍，全部 > 0.1m）
- RL 策略输出 Contact Intention：
  - c̄_0 = p_7（选择 L 形短臂外侧的点 — 几何直觉：推短臂可以产生旋转）
  - (w_pos, w_ori) = (1, 1)（同时优化位置和姿态）

**第 1 步 — MPC 执行**（T = 30 个控制步）：
- MPC  horizon H = 15，频率 100Hz
- 优化：min Σ_{t=0}^{14} [w_c · ||p_ee,t - T_obj^w · c̄_0||²] + V(q_15, q̄_obj)
- 求解得到 $u_{0:14}$，执行 $u_0$
- 30 个控制步内，末端执行器移动到 c̄_0 并开始推物体
- 物体移动：p_obj → (0.05, 0.02)，θ → 3°

**第 2 步 — RL 重新决策**：
- 新观察 o_1，物体已移动
- RL 输出新的 c̄_1 = p_3（切换到 L 形长臂 — 因为需要更多平移、更少旋转）
- (w_pos, w_ori) = (1, 0)（现在主要优化位置）
- MPC 继续执行 30 步...

**循环约 10 次 RL 决策步**后，物体到达目标位姿附近，任务完成。

**关键数字**：
- 每个 RL 步 $\approx 30$ 个 MPC 控制步
- 总控制步 $\approx 300$ 步
- 端到端 RL 需要 600K 决策步才能收敛到 83%，本文方法 15K 决策步达到 100%

## 4. 工程视角 (Engineering View)

| 维度 | 数值/设计 | 含义 |
|------|-----------|------|
| 高层决策频率 | ~10 Hz (每 T 步) | 匹配几何推理的慢变性，降低 RL 调用开销 |
| 底层控制频率 | ~100 Hz (ComFree-MPC) | 接触动力学需要高频响应以处理滑动/ sticking 切换 |
| MPC 预测步数 H | 10-15 步（任务相关） | 较短视距，依赖高层策略提供全局引导 |
| RL 训练数据量 | 40K-100K 步（不同任务） | 比端到端 RL 少 10-40 倍 |
| 抽象末端执行器 | 质点-弹簧-阻尼器 | 训练时跳过复杂机器人动力学，加速采样 |
| Sim-to-Real | 零样本迁移 | 高层策略不依赖具体机器人模型，只需更换 MPC |
| 硬件平台 | Franka Emika 7-DOF + stick 末端 | 论文实验使用，但框架理论上适配任意机械臂 |

**工程含义**：
- **模块边界清晰**：RL 策略与机器人解耦，更换硬件只需重写 MPC 层（已知动力学模型），RL 策略可复用。
- **部署约束**：ComFree-MPC 需要准确的物体质量/摩擦参数。论文通过 domain randomization 在训练期覆盖了参数不确定性，但极端参数偏移（如物体质量变化 >3 倍）可能影响性能。
- **延迟预算**：100Hz MPC 需要实时求解器。ComFree 模型去除了互补约束，使每次求解在毫秒级完成，但硬件算力不足时可能需要降频。

### 6.1 隐含假设 (Hidden Assumptions)

1. **物体几何可准确获取**：假设物体表面关键点集 P 可以通过 CAD 模型或精确感知获得。在真实场景中，遮挡或感知噪声会直接影响接触位置选择的可靠性。
2. **接触动力学模型足够准确**：ComFree 模型需要质量、摩擦、惯性等参数。论文通过 domain randomization 缓解，但极端情况（如未知物体）下模型误差可能累积。
3. **单步接触足够**：每个 RL 步对应一个固定接触点。对于需要连续切换接触模式的任务（如灵巧的手指滚动物体），10Hz 的决策频率可能不够。
4. **环境静态**：实验假设环境是静态的（桌子、台阶不动）。动态环境中的操作未涉及。
5. **n=1 的简化**：论文声明框架可扩展到 n>1（多接触点），但所有实验仅使用 n=1。多接触点的协调是一个开放问题。

- vs PushAnything/HiDex：这些方法是在线优化/搜索，无需训练但计算开销大。本文的方法训练后推理高效（只需一次 RL 前向 + MPC 求解）。
- vs 端到端 VLA/RL：本文不追求端到端通用性，而是在接触操作子域内做到极致效率和可靠性。

> **面试 Tip**：如果被问到"为什么不用端到端 VLA 做接触操作？"——可以回答："端到端策略将几何推理和接触动力学耦合在一个神经网络中，导致样本效率低且 Sim-to-Real 困难。分层架构（如本文的 RL-MPC）通过接口设计将两者解耦，RL 学几何、MPC 管物理，各展所长。VLA 更适合语义层面的任务规划，而底层接触控制需要物理模型的精确性。"
