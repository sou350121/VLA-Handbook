## 1. 核心架构/方法总览 (Overview / Architecture)

TransDex 分为两个阶段：**预训练阶段**（点云重建）和 **策略阶段**（视触觉融合 + 差异化动作预测）。两阶段共享同一个编码器，预训练赋予其对残缺点云的鲁棒理解力。

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 训练方式 | 关键设计 |

### 1.2 关键机制 (Key Mechanism)

**为什么分两条注意力通路？**

TransDex 的核心设计决策是：**机械臂需要空间理解，灵巧手需要力感知**。

- **自注意力通路 F_s^(M)**：融合全局点云 + 交互点云 + 触觉位置，不含力信息。这让它擅长理解"物体在哪、手在哪、环境结构如何"——正是机械臂轨迹规划需要的。
- **交叉注意力通路 F_c^(M)**：以力特征为 Query，以自注意力输出为 K/V。力信息主动"查询"空间特征，让网络学会"在什么接触状态下该施加什么力"——这正是灵巧手精细操作需要的。

⚡ **Eureka Moment**：不要用同一个融合特征控制所有关节——机械臂要空间感（自注意力），灵巧手要力感知（交叉注意力），分化设计比统一融合更有效。

**为什么用点云重建做预训练而非特征对齐？**

现有视触觉预训练多聚焦于"对齐视觉和触觉的特征空间"或"单模态内重建"。TransDex 选择了一个更直接的目标：**从被手遮挡 + 加噪声的交互点云中恢复完整物体形状**。这模拟了真实场景——手挡在物体前面、深度相机看到残缺数据——让编码器在预训练阶段就学会"脑补"被遮挡的部分。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L_total = L_cls(query) + λ·L_contrast([cls])    [预训练]
L_total = λ₁·MSE(â_a, a_a) + λ₂·MSE(ε, ε_θ)     [策略]
```

**预训练目标**：让网络从遮挡+噪声的交互点云中判断每个3D空间查询点是否属于目标物体。

```
min_θ E[ L_cls( p, y(Q_p, P_object^t) ) ] + λ·E[ L_contrast(F_[cls]) ]
```

- p = 查询点二分类置信度（N 个查询点）
- y = 真实标签（正/负）
- L_cls = 二元分类损失
- L_contrast = 对比损失，让不同样本的 [cls] 特征可区分
- λ = 对比损失权重

**策略训练目标**：机械臂用 MSE 回归位姿，灵巧手用 DDPM 去噪损失。

```
L_a = MSE( â_a, a_a )                           [机械臂: pred_T×6 位姿]
L_h = MSE( ε^k, ε_θ(ᾱ_k·a_h^0 + β̄_k·ε^k, k, F_c^(M)) )  [灵巧手: DDPM去噪]
L_t = λ₁·L_a + λ₂·L_h                           [总损失]
```

- â_a = 机械臂预测位姿 (pred_T 步 × 6维: x,y,z,rx,ry,rz)
- a_a = 真实机械臂位姿
- ε^k = DDPM 第 k 步的真实噪声
- ε_θ = 去噪网络预测的噪声
- F_c^(M) = 交叉注意力通路的融合特征（含力调制）
- ᾱ_k, β̄_k = 噪声调度参数

> 符号说明：与论文保持一致。pred_T 为动作预测步长，obs_T 为历史观察窗口，M 为注意力轮次，K 为 DDPM 去噪步数。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个倒水任务场景，用假设的合理数值走一遍推理流程：

**输入观测**（单帧）：
- 全局点云 P_g: 2048 点 × 6 维 (xyz + RGB)
- 交互点云 P_ho: 1024 点 × 3 维（其中触觉点约 200 个，视觉点约 824 个）
- 触觉力阵列 I_f: 4 个传感器 × (12×6 + 10×6) taxels × 3 维力 = 2136 个力值
- 本体状态 s: 23 维关节角

**预训练阶段**（离线）：
- 原始交互点云 1024 点，经 FPS 选 64 个中心点，KNN 分组为 64 patches
- 随机 Mask 40%（26 patches），剩余 38 patches 输入编码器
- 在 3D 空间生成 4096 个查询点，其中 1500 个为正（靠近物体表面），2596 个为负
- 编码器输出 [cls] 特征 + 38 个 patch tokens，Decoder 对 4096 个查询点做二分类
- 假设分类准确率 92%，对比损失让 [cls] 特征在不同物体间可分

**策略推理**（在线）：
- F_g: 全局点云 → MLP 编码 → 512 维
- F_[cls]': 交互点云 → 预训练编码器 → [cls] 512 维 → MLP 适配 → 512 维
- F_pos_t: 200 个触觉点位置 → 位置编码 → 256 维
- F_t: 力阵列 → CNN → 256 维

**自注意力通路**（M=3 轮）：
- F_s^(0) = [F_g, F_[cls]', F_pos_t] = 1280 维拼接
- 3 轮自注意力后 → F_s^(3) = 512 维
- 机械臂头 MLP → â_a = 8 步 × 6 维 = 48 维（未来 8 步末端位姿轨迹）

**交叉注意力通路**（M=3 轮）：
- F_c^(0) = [F_t] = 256 维
- 每轮: F_t 作为 Query "查询" F_s^(m) 作为 K/V
- 3 轮后 → F_c^(3) = 512 维
- DDPM 头: 从随机噪声 a_h^K (16 维) 开始，经 K=10 步去噪 → a_h^0 (16 维关节动作)

**关键直觉**：机械臂输出的是确定性轨迹（MLP 直接回归），灵巧手输出的是分布采样（DDPM 去噪）。这是因为机械臂运动相对连续可预测，而灵巧手操作需要处理多模态动作分布（同一个杯子可以用不同手指组合抓起）。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/设计 | 工程含义 |
|------|-----------|----------|
| 观察窗口 obs_T | 多帧历史（论文未明确具体值） | 需要缓存最近 obs_T 帧的传感器数据 |
| 动作预测步 pred_T | 未明确（典型 4-8 步） | 开环执行 pred_T 步后重新观测 |
| 机械臂动作维度 | 6 (末端位姿) | 标准 6-DOF 输出，可直接送逆运动学 |
| 灵巧手动作维度 | 16 | 匹配 16-DOF 手的关节空间 |
| DDPM 去噪步 K | 未明确（典型 10-50） | 推理延迟与 K 线性相关；10 步快但质量略降 |
| 注意力轮次 M | 未明确（典型 2-4） | 每轮增加一次 self-attn + cross-attn |
| 触觉传感器 | PaXini 阵列 (12×6 指尖 + 10×6 指腹) × 4 指 | 每 taxel 3 维力 (Fx, Fy, Fz) |
| 深度相机 | 2× RealSense D435 (腕部 + 工作台) | 需要手眼标定 + ICP 微调对齐 |
| 预训练数据 | PyBullet 仿真 (ClearPose 物体) | sim2real 依赖 ICP 配准桥接域 gap |

**部署约束**：
- 需要 23 维关节角实时读取 + 4 个触觉传感器阵列 + 2 个深度相机
- 推理延迟主要来源：DDPM 去噪（K 步迭代）+ Transformer 编码器
- 触觉力阵列转为图像格式后用 CNN 处理，可利用 GPU 加速

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **透明物体灵巧操作**: 倒水、摇烧瓶、转杯子——这些任务对纯视觉策略几乎不可能
- **泛化到未见物体**: 论文提到在 unseen objects 上测试，表现良好
- **鲁棒性**: 对复杂背景和光照变化有一定鲁棒性
- **sim2real 迁移**: 预训练在仿真完成，策略在真实机器人上有效

### 不能做什么（局限）
- **仅限单一机器人平台**: 实验仅在 UST 自研 7-DOF 臂 + 16-DOF 手上验证，未在其他构型上测试
- **仅限透明物体操作**: 未评估对非透明物体的性能（理论上应该也行，但无数据）
- **依赖触觉硬件**: 需要 PaXini 触觉阵列，不是所有机器人平台都配备
- **预训练质量依赖仿真逼真度**: PyBullet 中的点云特性可能与真实深度相机有差距

### 6.1 隐含假设 (Hidden Assumptions)

1. **仿真点云 ≈ 真实点云的噪声分布**: 预训练在 PyBullet 中加噪声模拟真实深度相机，但真实折射/反射效应可能比简单高斯噪声复杂得多。ICP 微调可以部分弥补，但这是未经验证的假设。

2. **触觉传感器全覆盖指尖和指腹**: 实验配置中每个手指都有触觉传感器。如果实际部署中传感器数量/位置不同，F_pos_t 和 F_t 的维度会变化，需要重新训练。

3. **专家演示数据质量足够**: 策略训练依赖遥操作采集的专家数据。如果演示质量不高（抖动、不流畅），策略上限会被限制。论文未报告演示数据量或质量指标。

4. **机械臂和灵巧手可以解耦控制**: 设计假设 F_s^(M) 控制机械臂、F_c^(M) 控制灵巧手是充分的。但实际上臂手协同任务中两者有强耦合（例如倒水时手腕角度影响手指握力），解耦可能损失性能。

**面试 Tip**: 如果被问到"TransDex 相比 3DTacDex-P 的改进在哪"，可以这样回答："3DTacDex-P 的瓶颈在于触觉表示虽好但点云太稀疏，透明物体场景下深度相机给的点云本身就残缺。TransDex 用预训练让编码器学会从残缺点云'脑补'物体形状，然后用双通路注意力分别服务机械臂（空间理解）和灵巧手（力感知），平均成功率从 47% 跳到 83%。核心创新不是某个组件，而是'预训练恢复感知 + 分化控制'的组合拳。"
