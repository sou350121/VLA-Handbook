### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？** 核心逻辑链：

1. **观察**：机器人轨迹在时域高度平滑 → 频域能量极度集中在低频
2. **量化**：RoboTwin2.0 的 20,000 条轨迹中，前 2 个 DCT 模态占 98.5% 能量（k=1 单模态占 93.2%）
3. **理论**：频域误差上界证明，当能量集中在 m 维低频子空间时，T 步 DDIM 的相对误差上界为 `(m / (n·Tr(Σ))) · (σ²/α²) + η/n`，其中 η 是高频能量占比
4. **代入**：m=1, n=32, η=0.07 → T=2 时相对误差上界 ≈ 0.25%
5. **结论**：两步采样已足够，后续迭代是边际递减；解码器无需图像生成级别的容量

⚡ **Eureka Moment**：机器人动作不是图像——它的频域能量 98.5% 挤在前 2 个低频模态里，所以扩散策略的"重解码器 + 多步采样"范式是一个根本性的设计错配。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
ê_T ≲ [m / (n·Tr(Σ))] · (σ²_{T⁻¹} / α²_{T⁻¹}) + η/n
      ↑低频误差项              ↑高频残差项
      当 m=1, n=32, η=0.07 → T=2 时 ê_2 ≲ 0.25%
```

**目标**：量化 T 步 DDIM 采样的相对误差上界，证明对低频主导数据，极少步数即可饱和。

**公式分解**：

| 符号 | 含义 | 典型值 |
|------|------|--------|
| m | 低频子空间维度（主要能量模态数） | 1-2 |
| n | 轨迹帧数 | 32 |
| η | 高频能量占比 | 0.07 (7%) |
| Σ | 频域协方差矩阵 | 经验估计 |
| α_t, σ_t | 噪声调度系数（cosine schedule） | T=2 时确定 |
| ê_T | T 步采样的相对 MSE | ≤ 0.25% at T=2 |

**直觉**：
- 第一项（低频误差）：随采样步数减少而下降——DDIM 从 t=1/T 开始，T 越大，起始点越靠近 t=0，噪声越小
- 第二项（高频残差）：与采样步数无关——高频能量本身只有 7%，这部分误差是"地板"，再多采样也降不下来
- 关键洞察：高频残差可以被机器人底层控制器过滤，所以闭环执行性能几乎不受影响

> 符号与论文保持一致：x₀ 为干净轨迹，x_t 为加噪轨迹，α_t/σ_t 为 DDPM 噪声调度，DCT 为正交变换 U。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：

- 轨迹长度 n = 32 帧
- DCT 变换后，能量分布：k=1 模态占 93.2%，k=2 占 5.3%，其余 30 个模态合计占 1.5%
- 因此 m = 1（第一个模态主导），η = 0.07（高频占 7%）

**T=2 步 DDIM 的误差上界计算**：

```
ê_2 ≲ [1 / (32 × Tr(Σ))] × (σ₀.₅² / α₀.₅²) + 0.07/32

代入 cosine schedule 在 t=0.5 处的值：
σ₀.₅² / α₀.₅² ≈ 3.3

→ ê_2 ≲ 0.0023 × 3.3 + 0.0022
       ≲ 0.0076 + 0.0022
       ≲ 0.0098 ≈ 0.98%
```

论文给出更紧的界 ≈ 0.25%（使用了经验协方差矩阵而非最坏情况）。

**对比 T=10 步**：

```
ê_10 ≲ 0.0023 × (σ₀.₁² / α₀.₁²) + 0.0022
     ≲ 0.0023 × 0.11 + 0.0022
     ≲ 0.00025 + 0.0022
     ≲ 0.00245 ≈ 0.25%
```

差距仅约 0.7%，但采样步数差了 5 倍。这解释了为什么实验中 2 步和 10 步的成功率差异在噪声范围内。

**高频误差的闭环过滤**：
假设 2 步采样后剩余 MSE = 0.01（主要在高频），机器人底层 PID 控制器对 >5Hz 的信号衰减 90%，则实际执行误差 ≈ 0.001，几乎不可察觉。

## 4. 工程视角 (Engineering View)

| 指标 | DP3 | Flow Policy | MP1 | Hyper-DP3 |
|------|-----|-------------|-----|-----------|
| 参数量 | 255.8M | 255.8M | 255.8M | **2.52M** |
| 采样步数 | 10 | 1 | 1 | **2** |
| 推理延迟 (ms) | 51.4 | 7.04 | 7.02 | **4.50** |
| 是否需要蒸馏 | 否 | 是 (Flow Matching) | 是 (MeanFlow) | **否** |
| 训练复杂度 | 中 | 高（额外训练目标） | 高 | **低** |
| 内存占用 (FP16) | ~512 MB | ~512 MB | ~512 MB | **~5 MB** |

**工程含义**：

1. **部署友好**：2.52M 参数 ≈ 5 MB（FP16），可装入任何边缘设备（Jetson Nano 等）的 L2 cache
2. **无需蒸馏**：Flow Policy 和 MP1 虽然 1 步推理，但需要额外的 Flow Matching / MeanFlow 训练，HDP3 直接用标准 DDPM 训练 + 2 步 DDIM 推理
3. **控制频率**：4.50 ms 推理延迟 → 理论控制频率 222 Hz，远超典型机器人控制环（50-100 Hz）
4. **Trade-off**：DiM 的 Temporal MLP + Channel MLP 交替结构牺牲了自注意力机制的长程依赖建模能力，但对 32 帧的短时轨迹足够

### 6.1 隐含假设 (Hidden Assumptions)

1. **轨迹始终低频主导**：论文假设所有机器人操作任务的轨迹能量都集中在低频，但这可能只在"专家演示"中成立——噪声数据或次优演示可能包含更多高频成分
2. **底层控制器能过滤高频误差**：理论分析依赖"高频残差被低层控制器抑制"这一假设，但如果控制器带宽不足或任务对高频精度敏感（如精细装配），这一假设可能不成立
3. **x₀-prediction 优于 ε-prediction**：论文采用 x₀-prediction 参数化但未做对比实验；在 2 步采样的极端设定下，参数化选择可能影响更大
4. **DiM 容量足够**：6 层 × 128 维的 MLP-Mixer 在 2 步采样下表现良好，但这是"刚好够用"还是"有冗余"？论文未做容量缩放实验
