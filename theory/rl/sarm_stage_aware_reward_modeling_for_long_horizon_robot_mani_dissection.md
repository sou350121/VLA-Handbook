💡 **X-Ray 开场**
长视界机器人操作（如叠 T-shirt）的最大痛点不是"模型不够大"，而是"数据质量不可测"——不同示范者完成同一子任务的时间不同，用帧索引标注进度会引入严重噪声。SARM 的核心发现是：用自然语言子任务标注推导语义一致的进度标签，训练一个阶段感知奖励模型，再用它来加权行为克隆，可以显著提升长视界操作的成功率。对 VLA 研究者的含义是：奖励建模可以成为 VLA 后训练阶段的数据质量过滤器。

### 1.2 关键机制 (Key Mechanism)

**问题核心**：长视界任务的示范轨迹长度差异巨大。以叠 T-shirt 为例，"铺平"阶段有人用 30 帧完成，有人用 80 帧——如果用帧索引做进度标签，同一个"已铺平"状态在不同轨迹中可能获得 0.2 到 0.8 的进度值，噪声极大。

**SARM 的解决方案**：
1. **子任务标注协议**：将任务分解为语义子任务（如 T-shirt 折叠的铺平→抓角→对折→整理），标注每个子任务的起止帧
2. **数据集级先验比例**：计算每个子任务在所有轨迹中的平均时间占比 ᾱ_k
3. **帧级进度推导**：在子任务内部线性插值，确保同一语义状态获得一致的进度值

⚡ **Eureka Moment**：用自然语言子任务标注的语义边界替代帧索引的时序边界，让进度标签与"任务做到了哪一步"对齐，而非与"过了多少帧"对齐。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
ŷ_t = P_{k-1} + ᾱ_k · τ_t    (进度 = 子任务累积先验 + 子任务内插值)
```

**目标**：为任意帧 t 分配一个语义一致的进度值 ŷ_t ∈ [0,1]，使其反映"任务完成了多少"而非"过了多少帧"。

**公式分解**：

```
步骤 1: 子任务先验比例
  ᾱ_k = (1/M) · Σ_i (L_{i,k} / T_i)    对 M 条轨迹求平均

步骤 2: 帧级进度目标
  y_t = P_{k-1} + ᾱ_k · τ_t
  其中 τ_t = (t - s_k) / (e_k - s_k) ∈ [0,1]
        P_k = Σ_{j=1}^{k} ᾱ_j (累积先验)

步骤 3: 模型预测
  Ŝ_t = argmax_i Π_{t,i}              (阶段分类)
  ŷ_t = P̂_{k-1} + ᾱ_k · τ̂_t         (进度回归)

步骤 4: RA-BC 加权
  r̂_i = φ(o_i^{t+Δ}) - φ(o_i^t)      (进度增量)
  w̃_i = clip((r̂_i - (μ-2σ)) / (4σ+ε), 0, 1)  (线性映射)
  w_i = 1{r̂_i > κ} + 1{0 ≤ r̂_i ≤ κ} · w̃_i    (先验覆盖)

步骤 5: 加权损失
  L_RA-BC(θ) = Σ_i w_i · ℓ(π_θ(o_i), a_i) / (Σ_i w_i + ε)
```

**变量说明**：

| 符号 | 含义 | 范围 |
|------|------|------|
| ᾱ_k | 子任务 k 的平均时间占比 | [0,1], Σᾱ_k = 1 |
| τ_t | 子任务内归一化时间 | [0,1] |
| P_k | 累积先验（子任务 k 结束时的进度） | [0,1] |
| Ŝ_t | 预测的离散阶段 | {1,...,K} |
| ŷ_t | 预测的连续进度 | [0,1] |
| r̂_i | 进度增量（anchor 到 next window） | [-1,1] |
| μ, σ | 进度增量的运行均值/标准差 | 在线更新 (Welford) |
| κ | 先验阈值 | >0 (论文未给出具体值) |
| Δ | action chunk 长度 | 取决于策略 |

> 符号与本文保持一致。μ 在训练中 clamp 为非负：μ ← max(μ, 0)，避免早期训练时以负进度为中心。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化版 T-shirt 折叠任务，分为 3 个子任务：

```
子任务: [铺平]        [抓角对折]      [整理]
ᾱ_k:   0.40          0.35           0.25
P_k:   0.00→0.40     0.40→0.75      0.75→1.00
```

**场景**：一条轨迹总长 T = 200 帧。当前帧 t = 90，落在"抓角对折"子任务内，该子任务范围 [s_2=80, e_2=150]。

```
步骤 1: 计算子任务内归一化时间
  τ_t = (90 - 80) / (150 - 80) = 10/70 ≈ 0.143

步骤 2: 计算帧级进度目标
  y_t = P_1 + ᾱ_2 · τ_t = 0.40 + 0.35 × 0.143 ≈ 0.45

  → 该帧的进度标签是 0.45（任务完成了 45%）
```

**对比帧索引标注的噪声**：如果用帧索引，同一条轨迹中"已铺平"状态（约第 80 帧）的进度 = 80/200 = 0.40。但另一条轨迹中铺平用了 120 帧，同样"已铺平"状态的进度 = 120/250 = 0.48。**相同语义状态，标签差了 20%**。SARM 通过子任务边界对齐，消除了这种噪声。

**RA-BC 加权示例**：假设策略执行一个 action chunk 后，奖励模型预测：

```
anchor window 结束时的进度: φ(o^t) = 0.45
next window 结束时的进度:   φ(o^{t+Δ}) = 0.52
进度增量: r̂ = 0.52 - 0.45 = 0.07
```

假设运行统计 μ = 0.05, σ = 0.03, κ = 0.05：

```
r̂ = 0.07 > κ = 0.05 → w = 1.0 (明确的高质样本，直接给满权重)

如果 r̂ = 0.03 (在 [0, κ] 区间):
  w̃ = clip((0.03 - (0.05-0.06)) / (0.12+ε), 0, 1) = clip(0.04/0.12, 0, 1) ≈ 0.33
  w = 0.33 (中等质量，部分加权)

如果 r̂ = -0.02 (退步):
  w = 0 (明确低质，丢弃)
```

## 4. 工程视角 (Engineering View)

| 维度 | 数值/设计 | 工程含义 |
|------|-----------|----------|
| 视觉编码器 | Frozen CLIP | 无需端到端训练视觉部分，推理开销低 |
| 输入序列长度 | N 帧（论文未明确，ReWiND 用 ~16 帧） | 短窗口推理，延迟可控 |
| 输入模态 | 3 视角 RGB + 关节状态 | 需要多摄像头同步 + 机器人关节读取 |
| 位置编码 | 仅首帧位置偏置 | 防止绝对时间泄漏，模型只能学相对时序 |
| Rewind 增强 | 必需（消融实验证明） | 训练时需注入失败片段，否则模型在真实 rollout 中过于乐观 |
| 亮度鲁棒性 | ±0.3 扰动下性能稳定 | 适合真实环境光照变化 |
| RA-BC 开销 | 推理阶段零额外开销 | 奖励模型仅用于训练期加权，部署时只有策略网络 |
| 架构无关性 | RA-BC 是 drop-in replacement | 可套在任何 BC 策略上（Pi0、ACT 等） |

**部署约束**：
- 训练期需要三视角视频 + 关节状态，推理期策略只需要单帧观测
- 奖励模型本身不部署，仅用于训练期数据筛选
- 子任务标注是前置成本：T-shirt 折叠需要设计标注协议 + 人工标注 500-700 条轨迹

> 注意：D_sparse 和 D_dense 是**不同的示范轨迹**，不是同轨迹不同标注。

### 评测任务

1. **T-shirt 折叠**：长视界、多阶段、接触丰富、形变物体
2. **卸盘子**：较短视界、多阶段、高变化（盘子数量/朝向/机架位置）

### 评测协议

**示范数据进度估计**：单步 MSE 损失（模型预测 vs 人工标注进度）

**策略 Rollout 进度估计**：收集 36 条真实策略轨迹（12 成功/12 部分成功/12 失败），用分类协议评估奖励模型能否正确分类：

```
SE (成功):  最终进度 > 0.8 且 后 1/3 轨迹平均进度 > 0.6
PSE (部分): 全程平均进度 ≥ ξ (ξ 为非成功轨迹的中位数)
FE (失败):  其他
```

分类分数 ρ = (正确数 - 错误数) / 36

| LIV | — | — |

| GVL | 过高（过于悲观） | 低 |
| VICtoR | 过高（过于悲观） | 低 |

| ReWiND | 较强基线 | 最强基线 |

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

| 能力 | 证据 | 条件 |
|------|------|------|
| 准确估计长视界任务进度 | Table 2, Demo MSE 显著低于基线 | 需要子任务标注数据 |
| 识别成功/部分成功/失败 rollout | Rollout ρ 显著高于基线 | 需要 rewind 增强训练 |
| 泛化到 OOD rollout | 能处理 misgrasp、回退、恢复尝试 | 训练数据需覆盖失败模式 |
| 鲁棒光照变化 | SARM(VB) 消融实验 | ±0.3 亮度扰动范围内 |
| 提升下游策略性能 | RA-BC 在 T-shirt 上 83%/67% | 需要奖励模型质量足够高 |

### 不能做什么

| 失败模式 | 原因 |
|----------|------|
| 无标注数据时无法工作 | 依赖子任务标注推导进度标签 |
| 单方案模型泛化差 | 仅用 D_dense 训练的模型在未见场景中表现差（数据量小、多样性不足） |
| 无 rewind 增强时过度乐观 | 训练数据无失败案例 → 模型无法识别回退/失败 |
| 语义相似子任务阶段混淆 | 阶段估计器可能将语义相近的子任务混淆（论文未深入分析） |

### 6.1 隐含假设 (Hidden Assumptions)

1. **子任务边界可清晰定义**：论文假设每个长视界任务都能被分解为语义明确的子任务序列。但对于某些连续操作（如擦拭桌面），子任务边界可能模糊。
2. **示范者遵循相同子任务顺序**：标注协议要求示范者按固定子任务序列执行。如果不同示范者以不同顺序完成子任务，先验比例 ᾱ_k 会失真。
3. **CLIP 特征足以表征操作状态**：Frozen CLIP 在自然图像上预训练，对机器人操作场景中的细粒度状态差异（如手指位置、布料褶皱）可能不够敏感。
4. **进度单调性近似成立**：虽然 SARM 不强制单调性（不同于 REDS），但进度标签的线性插值隐含了"子任务内进度均匀推进"的假设。

## 7. 与相关工作对比 (Comparison)

| 方法 | 关注点 | 架构 | 训练方式 | 适用场景 |
|------|--------|------|----------|----------|
| **IRL (Ng et al.)** | 从示范推断奖励 | 反向优化 | 需要专家示范 | 短视界、状态可观测 |
| **LIV** | 预训练 VLM 奖励 | EpicKitchens 预训练 | 零样本/少样本 | 通用厨房任务 |
| **VLC** | 排序 VLM 奖励 | 序列排序微调 | 单调性鼓励 | 短视界 |
| **GVL** | 打乱帧 VLM 奖励 | 预训练 VLM prompt | 零样本 | 短视界 |
| **VICtoR** | 视觉-文本相似度 | VLM 嵌入相似度 | 零样本 | 指令跟随 |
| **REDS** | 阶段感知奖励 | 半稀疏阶梯奖励 + 单调正则 | 阶段分割标注 | 长视界，但速度变化时泛化差 |
| **ReWiND** | 重绕帧增强 | Transformer + rewind 帧 | 帧索引进度标签 | 长视界，但标签噪声大 |
| **DrS** | 阶段感知判别器 | 每阶段独立判别器 | 全模拟器状态 | 仿真环境，难扩展 |
| **SARM (本文)** | 阶段感知 + 子任务标注 | 双头 (阶段+子任务) + CLIP | 子任务标注推导进度 | 长视界、形变物体、真实世界 |

**面试 Tip**：当被问到"SARM 和 REDS 的区别"时，回答："REDS 用图像-子任务嵌入相似度推断阶段，学习半稀疏阶梯奖励；SARM 用专用阶段估计网络 + 子任务标注推导连续进度，两者在阶段推断机制和进度建模粒度上都有本质差异。"
