💡 **X-Ray 开场**
这篇论文解决的是 RL 训练机器人策略时的核心痛点：奖励信号太稀疏。传统方法只在 episode 结束时给一个 binary 成功/失败标签，中间步骤完全没有反馈。DenseReward 的突破在于：它不依赖人工标注失败数据，而是在仿真中通过"靶向扰动"自动生成六种物理真实的失败轨迹（碰撞、未抓住、掉落、恢复等），然后用这些数据训练一个视觉-语言奖励模型，让它对每个时间步给出 0-1 之间的进度评分。对 VLA 研究者意味着：RL 微调的奖励瓶颈有了一个可扩展的解决方案。

### 1.2 关键机制

DenseReward 的设计围绕三个核心组件：

1. **五阶段任务分解**：将机械臂操作分解为 Reach → Grasp → Lift → Move → Place 五个标准阶段，每个阶段有明确的物理边界检测（如 gripper 接触物体、物体离桌、进入目标半径），无需人工标注。

2. **靶向扰动失败合成**：在每个阶段施加特定扰动（禁用碰撞检测、偏移抓取位姿、注入旋转扰动、高斯噪声等），生成六种失败模式：Success、Collision、Miss、Fall、Smooth（抖动）、Recover（碰撞后恢复）。

3. **帧级奖励预测**：基于 Qwen3-VL-4B-Instruct 微调，输入语言指令 + 当前帧 + 2 帧历史，输出 [0,1] 标量奖励，保留三位小数以捕捉细粒度进度差异。

⚡ **Eureka Moment**：不在真实世界费力收集失败数据，而是在仿真中用"靶向扰动"自动生成物理真实的失败轨迹——这解决了密集奖励训练最大的数据瓶颈。

## 2. 数学核心

### 📌 Napkin Formula

```
r_t = α · r_t^sim + β · r_t^model    (PPO 集成)
r_t = -1 + r_t^model                  (DSRL 真实世界集成)
```

**先给目标**：让 RL 算法在每个时间步都能收到关于任务进度的细粒度反馈，而不是等到 episode 结束才得到一个 binary 标签。

**再给公式**：

```
奖励融合 (PPO, LIBERO):
  r_t = α · r_t^sim + β · r_t^model
  其中 α = 1.0, β = C / T_max
  C = action chunk 长度 (5), T_max = 最大 episode 长度
  r_t^sim ∈ {0, 1} (模拟器成功信号)
  r_t^model ∈ [0, 1] (DenseReward 预测)

奖励融合 (DSRL, 真实世界):
  r_t = -1 + r_t^model        (中间步骤，有步惩罚)
  r_T = r_T^model             (最终步，若成功则无步惩罚)
```

**变量说明**：

| 符号 | 含义 | 范围 |
|------|------|------|
| r_t | 融合后的每步奖励 | 实数 |
| $r_t^{\text{sim}}$ | 模拟器原始奖励 (binary) | {0, 1} |
| $r_t^{\text{model}}$ | DenseReward 预测的密集奖励 | [0, 1] |
| $\alpha$ | 模拟器奖励权重 | 1.0 |
| $\beta$ | 模型奖励权重 | C/T_max (缩放以匹配累积尺度) |
| C | action chunk 长度 | 5 |
| T_max | 最大 episode 长度 | 任务相关 |

**直觉**：$\beta = C/T_{\max}$ 的设计确保密集奖励的累积量与 episode 级成功信号在同一量级——不会让密集信号淹没稀疏信号，也不会弱到没有引导作用。

> 符号与论文 §4.3/4.4 保持一致。DenseReward 模型本身的训练损失为 MAE（平均绝对误差），论文未公开具体网络结构细节。

## 3. 带数字走一遍：玩具例子

假设一个"把杯子放入篮子"的任务，T_max = 50 步，C = 5（每 5 步一个 action chunk）。

**场景**：机器人在第 15 步时发生了碰撞，但重规划后继续执行，最终在第 45 步成功完成。

**DenseReward 预测的 $r_t^{\text{model}}$ 轨迹**（假设值，反映论文描述的模式）：

```
步数  阶段      r_model  说明
──────────────────────────────────────────
 1-3   Reach    0.05-0.15  接近目标，进度低
 4-6   Grasp    0.20-0.35  开始抓取
 7-9   Lift     0.40-0.55  抓住并抬起
10-12  Move     0.60-0.70  搬运中
13-15  Move     0.65→0.30  碰撞！奖励骤降 (Mountain-shaped)
16-18  Recover  0.35→0.55  重规划恢复，奖励回升
19-21  Move     0.60→0.70  继续搬运
22-24  Place    0.75→0.85  接近目标
25-27  Place    0.90→0.95  放置中
28-30  Done     1.00       成功完成
```

**PPO 融合奖励**（$\alpha=1.0$, $\beta=5/50=0.1$, 假设 $r_{\text{sim}}=0$ 直到完成）：

```
步数  r_model  r_sim  r_t = 1.0·r_sim + 0.1·r_model
─────────────────────────────────────────────────────
 1-3    0.10     0        0.01        ← 微弱正向信号
 7-9    0.50     0        0.05        ← 进度增加 → 奖励增加
13-15   0.30     0        0.03        ← 碰撞后奖励下降
16-18   0.50     0        0.05        ← 恢复 → 奖励回升
28-30   1.00     1        1.10        ← 成功 + 最大密集奖励
```

**对比纯稀疏奖励**：如果没有 DenseReward，前 29 步的奖励全部为 0，只有第 30 步得到 $r=1$。PPO 的 credit assignment 几乎无法工作——它不知道哪步做对了、哪步做错了。有了 DenseReward，每一步都有梯度信号，尤其是碰撞→恢复的奖励变化直接告诉策略"碰撞是坏的，但恢复是好的"。

## 4. 工程视角

| 工程维度 | 数值/约束 | 含义 |
|----------|-----------|------|
| 模型大小 | Qwen3-VL-4B | 4B 参数，单卡可部署（~8GB VRAM FP16） |

| 推理延迟 | 未报告（需实测） | 参考 Qwen3-VL-4B 推理速度，预计单帧 <50ms (A100) |
| 训练数据 | 27k episodes | 仿真生成，零人工标注成本；覆盖 60+ 物体 |
| 数据集来源 | DROID + Isaac Sim + RoboSuite + LIBERO | 跨源混合提升泛化性 |
| MPC 候选动作 | 28 个 (27 方向 + 开/关夹爪) | 每步需 28 次 reward 推理，延迟敏感 |
| PPO chunk 长度 | C=5 | DenseReward 每 5 步评分一次，非每步 |
| DSRL 真实世界 rollout | 10-20 条轨迹 | 20k 步 (stack cups) / 10k 步 (put ball)，样本效率高 |

**工程含义**：
- DenseReward 作为独立模块，不改变 VLA 策略网络结构，可即插即用
- 奖励融合公式极轻量（一次加法和乘法），不增加推理开销
- MPC 场景下 28 次/步的 reward 推理是主要瓶颈，可考虑批量推理或缓存
- 仿真到真实的 gap 是最大工程风险：失败合成基于 Isaac Sim 物理引擎，真实世界的摩擦/弹性/传感器噪声可能产生未见过的失败模式

### 6.1 隐含假设 (Hidden Assumptions)

1. **仿真失败 ≈ 真实失败**：论文假设通过 Isaac Sim 中的靶向扰动生成的失败轨迹，能够覆盖真实世界中机器人执行时遇到的失败模式。但仿真物理引擎（尤其是接触力学、摩擦模型、传感器噪声）与真实世界存在系统性差异，某些真实失败模式可能无法在仿真中复现。

2. **五阶段分解具有普适性**：Reach→Grasp→Lift→Move→Place 的分解假设所有操作任务都可以映射到这个框架。但对于非抓取操作（如推、倒、拧）或多对象交互任务，这个分解可能不够表达。

3. **视觉输入稳定性**：DenseReward 依赖当前帧 + 历史帧作为输入，假设摄像头视角在操作过程中相对稳定。如果相机抖动或视角大幅变化，奖励预测可能退化。

4. **奖励尺度可迁移**：PPO 集成中使用 $\beta = C/T_{\max}$ 缩放密集奖励，假设这个缩放因子在不同任务长度下都能保持奖励信号的合理量级。但对于 $T_{\max}$ 差异很大的任务，可能需要任务特定的调参。
