## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 传统 VLA (SFT/训练时 RL) | TT-VLA (本文) |
|------|------------------------|---------------|
| 训练阶段 | SFT 或 RL 在固定数据集上 | 同左（保留预训练先验） |
| 部署阶段 | 固定策略，无自适应 | 在线策略更新，每 8 步微调一次 |
| 奖励信号 | 无（推理）或稀疏终端奖励 | 密集进度差奖励 rt = pt - pt-1 |
| 优化目标 | 无（推理） | 无值函数 PPO: $L(\theta) = \mathbb{E}_t[L_t^{\text{CLIP}}(\theta)]$ |
| 值函数 | 训练时学习 | 不学习（测试时样本不足） |
| 优势估计 | 无 | 单步优势 $\hat{A}_t = r_t$（$\gamma=0$, $\lambda=0$） |
| 更新频率 | N/A | 每 8 环境步更新一次策略 |
| 额外组件 | 无 | 进度估计器 $\Phi$ (用 VLAC 模型) |

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **密集进度奖励**：传统 RL 用终端稀疏奖励（成功/失败），但测试时只有一个 episode，等不到结束就要调整。进度差 rt = pt - pt-1 提供每步反馈。

2. **无值函数 PPO**：训练时 PPO 学习值函数 V(s) 来估计长期回报，但测试时：① 样本极少（单 episode）不足以学习可靠的 V；② 延迟约束严格，没时间训练 critic。直接去掉值函数，用即时奖励当优势。

3. **$\gamma=0$, $\lambda=0$ 的优势坍缩**：标准 GAE 用折扣因子$\gamma$和 trace 参数$\lambda$来平滑长期回报。但论文证明（Proposition 1），当奖励是进度差时，任何$\gamma>0$ 都会引入系统性负偏差。所以设$\gamma=\lambda=0$，优势就是当前步奖励：$\hat{A}_t = r_t$。

⚡ **Eureka Moment**：测试时自适应的核心矛盾是"样本极少但需要快速适应"——TT-VLA 的解法是放弃长期规划（不学值函数、不折扣），专注于每步是否让任务进度前进，用即时反馈驱动策略调整。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
核心更新：θ' = θ + α · ∇_θ E_t[min(r_t(θ)·r_t, clip(r_t(θ), 1-ε, 1+ε)·r_t)]
其中 r_t = p_t - p_{t-1}  (进度差奖励), r_t(θ) = π_θ(a_t|s_t) / π_θ_old(a_t|s_t)
```

**目标**：在测试时单 episode 内，用进度差奖励在线微调 VLA 策略，同时保持预训练先验不崩溃。

**公式**（价值自由 PPO 目标）：

```
L(θ) = E_t[L_t^CLIP(θ)]

L_t^CLIP(θ) = min(r_t(θ) · r_t, clip(r_t(θ), 1-ε, 1+ε) · r_t)

r_t(θ) = π_θ(a_t | s_t) / π_θ_old(a_t | s_t)  (策略比率)

r_t = p_t - p_{t-1}  (进度差奖励)
```

**变量说明**：

| 符号 | 含义 | 来源 |
|------|------|------|
| $\theta$ | VLA 策略参数 | 预训练 + LoRA 微调 |
| $\pi_\theta$ | 策略网络 | OpenVLA/Nora 等 backbone |
| $r_t(\theta)$ | 新旧策略概率比 | PPO 标准定义 |
| r_t | 时步 t 的奖励 | 本文定义：进度差 |
| p_t | 任务进度估计 | VLAC 模型输出 [0,1] |
| $\varepsilon$ | clip 范围 | 0.2（论文设置） |
| $\gamma$, $\lambda$ | GAE 折扣/trace | 本文设为 0 |

**直觉**：标准 PPO 的目标是最大化折扣回报，但测试时没法学好值函数。TT-VLA 说：别管长期了，每步让进度前进就是好动作。进度差 r_t 直接当优势信号，策略更新只关心"这个动作是否比旧策略更能推动任务"。

> 符号与本文/相关文档保持一致：进度 $p$ 用小写 $p$，奖励 $r$ 用小写 $r$，策略$\pi$用希腊字母$\pi$。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个"把香蕉放到盘子里"的任务，episode 共 160 步。

**初始状态**（t=0）：
- 进度估计：p_0 = 0.05（机器人还没动）
- 策略：$\pi_\theta$（预训练 OpenVLA）

**第 1 步**（t=1）：
- 机器人执行动作 a_0（向香蕉移动）
- 新进度：p_1 = 0.12（靠近了香蕉）
- 奖励：r_1 = p_1 - p_0 = 0.12 - 0.05 = 0.07（正奖励，进度前进）
- 策略比率：假设 $\pi_\theta(a_0|s_0) = 0.8$, $\pi_\theta^{\text{old}}(a_0|s_0) = 0.75$ → $r_1(\theta) = 0.8/0.75 = 1.067$
- PPO 损失：$L_1 = \min(1.067 \times 0.07,\ \text{clip}(1.067,\ 0.8,\ 1.2) \times 0.07) = \min(0.0747,\ 1.067 \times 0.07) = 0.0747$
- 梯度更新：$\theta' = \theta + \alpha \cdot \nabla L_1$（$\alpha$是学习率）

**第 5 步**（t=5，发生异常）：
- 机器人抓香蕉时滑了一下，偏离目标
- 进度估计：$p_5 = 0.35$, $p_4 = 0.42$ → $r_5 = 0.35 - 0.42 = -0.07$（负奖励，进度倒退）
- 策略比率：假设 $\pi_\theta(a_4|s_4) = 0.3$, $\pi_\theta^{\text{old}}(a_4|s_4) = 0.6$ → $r_5(\theta) = 0.3/0.6 = 0.5$
- PPO 损失：$L_5 = \min(0.5 \times (-0.07),\ \text{clip}(0.5,\ 0.8,\ 1.2) \times (-0.07)) = \min(-0.035,\ 0.8 \times (-0.07)) = -0.056$
- 梯度更新：这个动作被惩罚，策略会学习避免类似行为

**关键观察**：
- 正奖励时（进度前进），策略被鼓励重复该行为
- 负奖励时（进度倒退），策略被抑制
- 每 8 步累积一次更新（论文 Table 2 发现这个频率最佳）
- 整个 episode 结束后，策略已经针对这个具体任务场景做了自适应

## 4. 工程视角 (Engineering View)

**计算开销**：
- 进度估计器 Φ：用 VLAC 模型（预训练多模态 critic），每次推理约 50-100ms（取决于模型大小）
- PPO 更新：LoRA 微调，rank {16, 32}，每次更新约 200-500ms（单 GPU）
- 更新频率：每 8 步更新一次 → 160 步 episode 共 20 次更新，总额外延迟约 4-10 秒

**内存占用**：
- LoRA 适配器：rank 32 时约 10-20MB（远小于全参数微调）
- 优化器状态：AdamW，约 $2\times$参数量的内存
- 总体：在 7B VLA 上，额外内存 < 1GB

**部署约束**：
- 需要实时进度估计：VLAC 模型需与 VLA 并行运行
- 延迟敏感场景（如高速装配）可能不适合——每 8 步的更新延迟可能影响控制频率
- 适合中低速任务（如桌面操作、长 horizon 任务）

**Trade-off**：
- 更新频率太高（每 $1$ 步）$\to$ 训练不稳定，论文 Table 2 显示成功率下降
- 更新频率太低（每 $16$ 步）$\to$ 学习信号延迟，自适应不及时
- 最佳点：每 8 步（论文在 Nora 和 OpenVLA 上都验证过）

**量化误差**：
- 进度估计 $p_t \in [0,1]$ 是连续值，VLAC 的回归误差会传递到奖励
- 论文未详细分析进度估计误差对最终性能的影响——这是潜在风险点

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- ✅ 在未见过的物体位置、光照条件、指令表述下自适应调整策略
- ✅ 在单 episode 内纠正执行错误（如抓取滑脱后重新调整）
- ✅ 兼容多种 VLA 架构（离散 token -based 模型）
- ✅ 与训练时 RL 正交，可叠加使用（OpenVLA-RL + TT-VLA 仍有提升）

**不能做什么**：
- ❌ 无法处理任务目标变化的情况（如从"放香蕉"变成"切香蕉"）——进度估计器 $\Phi$ 是针对固定任务训练的
- ❌ 对扩散式 VLA 不直接适用（论文 §S1.1 解释：扩散 head 没有 tractable 的 log-likelihood，无法用 policy gradient）
- ❌ 高延迟敏感场景不适合（每 8 步更新的延迟可能影响控制稳定性）
- ❌ 进度估计器域外泛化有限——如果测试场景与 VLAC 训练域差异太大，进度估计可能失效

### 6.1 隐含假设 (Hidden Assumptions)

**X-Ray 批判视角**：

1. **进度可估计假设**：论文假设存在一个可靠的进度估计器 $\Phi$，能从前缀观察 $o_{0:t+1}$ 和指令 $l$ 预测当前进度 $p_t \in [0,1]$。但：
   - VLAC 是在什么数据上训练的？论文引用 Zhai et al. (2025)，但未说明是否覆盖测试任务域
   - 如果进度估计系统性偏差（如高估早期进度），奖励信号会误导策略更新

2. **单调进步假设**：奖励 $r_t = p_t - p_{t-1}$ 隐含假设"好动作会让进度单调增加"。但某些任务需要暂时后退（如先松开物体再重新抓取），这类动作会被错误惩罚。

3. **单任务假设**：整个 framework 假设测试时任务指令 l 是固定的。如果任务中途变化（如人机交互中指令更新），进度估计和奖励都会失效。

4. **LoRA 可塑性假设**：论文用 LoRA 微调（rank 16/32），假设小参数更新足以适应新场景。但对于域 shift 极大的情况（如从桌面操作到移动操作），LoRA 可能不够。

## 7. 与相关工作对比 (Comparison)

| 方法 | 训练时/测试时 | 奖励来源 | 值函数 | 适用模型 | 计算开销 |
|------|--------------|----------|--------|----------|----------|
| SFT (标准 VLA) | 训练时 | 行为克隆（无奖励） | N/A | 所有 VLA | 低 |
| RL4VLA (Liu et al. 2025a) | 训练时 | 稀疏终端奖励 | 学习 | 离散 VLA | 中 |
| EVOLVE-VLA (Bai et al. 2025b) | 测试时 | 任务进度奖励 | 不学习 | 离散 VLA | 高（GRPO 采样） |
| TTRL (Hu et al. 2025) | 测试时 | 共识伪标签 | 不学习 | LLM/VLM | 中 |
| **TT-VLA (本文)** | **测试时** | **任务进度差奖励** | **不学习** | **离散 VLA** | **中（无 GRPO 采样）** |

**关键区别**：
- vs EVOLVE-VLA：两者都用进度奖励，但 EVOLVE-VLA 用 GRPO（需采样多个候选动作，计算开销大），TT-VLA 用简化 PPO（单次前向 + 反向，适合实时部署）
- vs TTRL：TTRL 用多数投票构建伪标签，适合语言任务但不适配动作空间；TT-VLA 直接用环境进度信号
- vs 训练时 RL：训练时 RL 需要大量环境交互和数据收集，TT-VLA 在部署时零数据收集，用单 episode 自适应

**面试 Tip**：被问到"如何让 VLA 在部署时自适应未见场景"时，可以答："训练时 RL 解决不了分布偏移问题，因为训练环境和测试环境不同。TT-VLA 的思路是用任务进度作为密集奖励信号，在测试时单 episode 内在线微调策略——关键是去掉值函数学习（样本太少学不好），直接用进度差当优势信号。"
