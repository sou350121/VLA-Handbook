### 1.2 关键机制 (Key Mechanism)

**核心张力**: VLA 的预训练多模态通路需要同时支持两种任务：
- **语言侧处理**: 保留丰富的语义和 grounding 结构，用于指令理解和生成
- **动作生成**: 抽象出行为相关的因子，形成稳定鲁棒的控制信号

这两种需求在表征组织上存在结构性冲突。动作监督梯度直接流经继承通路时，会把表征"拉向"动作兼容方向，但同时会**破坏**语言侧能力。

⚡ **Eureka Moment**: 动作接口不是被动读取继承表征的管道——它是控制动作监督如何重塑继承表征的**阀门**。通过可学习查询吸收部分动作更新，可以减少对上游表征的破坏性重写。

**Action QFormer 的 K 层迭代流程**:
1. **指令条件化**: 可学习查询 Q^{k-1} 与指令表征 H_t^S 拼接，经过 Self-Attention，查询部分吸收指令上下文
2. **视觉证据选择**: 指令条件化的查询 Q~^k 对图像表征 H_t^I 做 Cross-Attention，选择性提取与当前指令相关的视觉信息
3. **组合输出**: K 层迭代后，最终查询状态携带"指令条件的视觉信息"，Pool 后与指令侧表征组合，形成最终动作面向表征 z_t

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
∂L_action/∂θ_path = (∂L/∂z_t) · (∂z_t/∂Φ_t) · (∂Φ_t/∂(H^I,H^S)) · (∂(H^I,H^S)/∂θ_path)
                                        ↑
                    Action QFormer 在此处插入查询路径，
                    使 ∂Φ_t/∂(H^I,H^S) 的范数减小
```

**目标**: 让动作监督在形成动作兼容表征的同时，最小化对预训练多模态表征的破坏。

**核心方程**:

```
动作损失:
L_action = E_{τ,ε} [ ||ε - ε_ψ(A_t^τ, τ, z_t)||_2^2 ]

语言损失:
L_lang = -Σ_{j∈S_t} log p_θ(x_{t,j} | x_{t,<j})

总损失 (r 为余弦调度权重):
L = (1-r)·L_action + r·L_lang

Action QFormer 前向:
Q~^k = [SelfAttn^k(Concat(Q^{k-1}, H_t^S))]_{query}
Q^k  = CrossAttn^k(Q~^k, H_t^I)
z_t^{AQF} = AQF(Q^0, H_t^S, H_t^I)
```

**变量说明**:

| 符号 | 含义 | 维度 |
|------|------|------|
| H_t^I | 图像侧继承表征 | R^{N_I × d} |
| H_t^S | 指令侧继承表征 | R^{N_S × d} |
| Q^0 | 可学习查询初始化 | R^{M × d} |
| Q^k | 第 k 层查询输出 | R^{M × d} |
| z_t | 动作面向表征 | R^d |
| r | 语言损失权重 | [0,1] 余弦调度 |
| A_t | H 步局部动作轨迹 | R^{H×4} (位置+航向) |
| ε_ψ | 扩散策略头噪声预测 | — |

> 符号与本文保持一致。动作每步 a_t^h = (p_t^h, u_t^h)，其中 p 为 2D 相对位置，u 为 2D 航向向量。

**直觉**: 直接融合时，∂L/∂(H^I,H^S) 直接由 L_action 驱动，梯度"硬写"继承表征。Action QFormer 通过可学习查询 Q 提供了一个"缓冲层"——动作更新首先优化 Q（∂L/∂Q^0 和 ∂L/∂θ_AQF），只有当查询无法完全吸收更新时，梯度才向上传导到继承通路。这就像在电路中加入了一个电容：高频动作信号被查询吸收，低频的语言表征得以保留。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：

```
设置:
- d = 768 (隐藏维度)
- M = 32 (查询数)
- K = 6 (QFormer 层数)
- H = 8 (动作步数)
- 每步动作: a_t^h = (x, y, yaw_dx, yaw_dy) ∈ R^4

前向传播:
1. Backbone 输出: H^I ∈ R^{196×768} (14×14 patch), H^S ∈ R^{20×768} (20 token 指令)
2. Q^0 ∈ R^{32×768} (随机初始化可学习)
3. Layer 1:
   - Concat(Q^0, H^S) → R^{52×768}
   - SelfAttn → Q~^1 ∈ R^{32×768} (查询吸收了"向左转"指令语义)
   - CrossAttn(Q~^1, H^I) → Q^1 ∈ R^{32×768} (查询从视觉中选择了"左侧走廊"特征)
4. Layer 2-6: 迭代 refine，查询逐步聚焦于与导航指令最相关的视觉区域
5. Pool(Q^6) → R^{768}, 与 H^S 的 [CLS] token 拼接 → z_t ∈ R^{768}

反向传播（梯度分配）:
- 假设 ||∂L/∂z_t|| = 1.0（固定）
- Direct Fusion: ||∂L/∂H^I|| ≈ 0.8（大部分梯度直接流经）
- Action QFormer: 
  - ||∂L/∂Q^0|| ≈ 0.5（查询吸收了 50%）
  - ||∂L/∂H^I|| ≈ 0.3（只有 30% 传到继承表征）
  - 差额 20% 分配到 θ_AQF

效果:
- 继承表征 H^I 的更新幅度减少 62.5%
- 语言生成稳定性提升（OOD 指令从 100%→0% 在 Table 场景）
- 动作方向正确率从 0%→62.5%（Table 场景，给定指令条件）
```

## 4. 工程视角 (Engineering View)

| 工程维度 | Direct Fusion | Action QFormer | 含义 |
|----------|--------------|----------------|------|
| 额外参数 | 仅融合层 (~d^2) | + M×d 查询 + K×(d^2) 注意力层 | M=32, K=6, d=768 时约增加 1.5M 参数（相对 backbone 可忽略） |
| 推理延迟 | 1 次 SelfAttn | K 次 (SelfAttn + CrossAttn) | K=6 时约增加 3-5ms/步（在 30Hz 控制频率下可接受） |
| 内存占用 | 低 | 中（K 层查询状态需存储） | 不影响部署，训练时显存增加 ~10% |
| 控制频率 | 无影响 | 无影响 | 接口在策略头之前，不改变控制回路周期 |
| 训练稳定性 | 可能不稳定（梯度直接写 backbone） | 更稳定（查询缓冲） |  cosine scheduling of r 配合查询缓冲，减少训练早期破坏 |
| 部署复杂度 | 低 | 中（需额外加载查询权重） | 查询权重独立于 backbone，可热插拔 |

**工程含义**: Action QFormer 的设计哲学是"轻量中间件"——不改变 backbone、不改变策略头、只改变两者之间的接口。这意味着可以作为一个即插即用模块集成到现有 VLA 管线中。主要代价是推理时增加 K 层注意力计算，但在 30Hz 以下的控制频率中完全可接受。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **稳定指令生成**: 在真实场景视觉偏移下，几乎消除了 OOD 指令输出（Table II 中 OOD 率从 ~48%→0%）
- **方向控制增强**: 在需要左右方向判别的场景中，动作方向正确率显著提升
- **物体定位鲁棒性**: 在固定指令条件下，对目标物体的视觉 grounding 更可靠
- **减少上游重写**: 表征分析显示，Action QFormer 减少了对预训练通路的大范围梯度重写

### 不能做什么
- **障碍物感知规划**: 论文明确承认——当安全执行需要显式绕开附近障碍物时，如果模型没有选择合适的地标点来描述规避行为，失败仍然会发生（§IV-B 末段）
- **跨任务泛化**: 实验仅限于单目导航，未验证机械臂操作、双臂协作或其他 VLA 任务
- **视觉严重 OOD**: 零样本 sim-to-real 本身就是一个极限测试，但更极端的视觉域偏移（如不同机器人平台、不同传感器）未经验证

### 6.1 隐含假设 (Hidden Assumptions)

1. **单帧足够**: 论文采用单帧导航设定（每步只看当前帧），假设当前观测 + 指令足以做出正确动作决策。但真实导航往往需要时序记忆——这个假设在复杂场景中可能不成立。

2. **GPT 生成指令质量**: 训练用的中间指令由 GPT 从观测+轨迹生成。如果 GPT 指令本身存在系统性偏差或噪声，模型学到的表征可能反映了 GPT 的偏好而非最优导航策略。

3. **查询数 M 足够**: 假设 M=32 个可学习查询足以捕获所有动作相关的视觉-指令交互模式。但未做 M 的消融实验。

4. **扩散策略头兼容性**: 实验使用条件扩散策略头。如果替换为确定性策略或流匹配策略，接口的效果可能不同。
