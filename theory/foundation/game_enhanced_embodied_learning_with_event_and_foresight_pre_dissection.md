💡 **X-Ray 开场**

这篇论文问的是三个问题：**第一**，人类打游戏产生的「屏幕 + 键鼠事件」能不能当成机器人策略的额外监督？**第二**，如果能，怎么保证训练时的未来帧监督不把推理时看不到的信息漏进来？**第三**，学完之后接回原来的机器人接口，性能到底动没动？

作者给出的答案是：游戏里每一帧屏幕配一段 1 秒内的历史，让模型同时做两件事——预测下一秒发生的键鼠事件（NEP），以及用冻结视频模型去预测下一秒的画面（foresight）；关键是把 foresight query 对「未来动作 token」的注意力全部封死。学完后不把键鼠映射成电机指令，而是把权重装回原生机器人前向路径，再走原来的 LIBERO 微调。

对 VLA 研究者的含义：**「数据源」可以换，但接口不能换**——这比「把游戏动作翻译成机器人动作」那种路线更省事，代价是增益来源变得不可分离。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

整条流水线是三段式：**游戏预训练 → 权重桥接 → 机器人微调**。三个阶段的模块归属必须分开看，论文 Table 1 与 Table 3 就是为此设的。

| 阶段 | 起点 | 训练/冻结的模块 | 输入单位 | 预测跨度 | 更新次数 |
|------|------|----------------|---------|---------|---------|
| ① 游戏预训练 | 扩展词表后的 InternVLA-A1.5-base | 可训练：visual encoder、multimodal backbone、expert、50 个 foresight queries、projection；冻结：Wan2.2 TI2V-5B 的 VAE 与 denoiser | 一个 screen anchor + ≤1 s 历史 H_t + 1 s 目标事件 Y_t | 事件：未来 1 s；视频：未来 1 s（5 帧） | 12,400 updates（global batch 128） |
| ② Bridge | 阶段①的 step-12,400 checkpoint | 无训练，只做张量搬运 | — | — | 0 |
| ③ 机器人微调 | bridge 后的权重 / 公共 base | 可训练：visual encoder、backbone、native expert 与动作投影、foresight tokens 与投影；冻结：Wan denoiser/VAE | 机器人 batch（含 state token、语言标签） | 动作：50 步 @20 Hz = 2.45 s；视频：2.50 s | 每 suite 20,000 updates（batch 32） |
| ④ 评测 | ③ 的 step-20,000 | 推理 | LIBERO episode | 8 步执行后 replan | 每 suite 500 episodes |

> 关键归属：**D2E 只贡献数据方向**（桌面事件 + 视觉-动作预训练），本文用的是它的人工录制子集；**InternVLA-A1.5 贡献架构**（原生 robot expert、foresight queries、冻结视频监督）；**Wan2.2 TI2V-5B 只作冻结教师**，其参数 ω 全程不更新。三者的属性不能互相合并。

**已观测 vs 未来预测，先分清**：

- **已观测历史帧**：H_t 是 anchor t 之前「至多 1 秒」的上下文。全语料 median 历史长度 32 个事件、其中 17 屏，median 历史跨度 968.32 ms（§4.1）。它进 language-model 输入。
- **未来预测帧**：偏移 `[0, 0.25, 0.50, 0.75, 1.00]` 秒的 5 帧，**只作 video label，被明确排除在语言模型输入之外**（§3.2）。它的首末跨度是 (5−1)×0.25 = 1.00 s，与「≤1 s 历史」在时长上对齐，但两者是不同角色。
- **注意**：这 1 秒**不是记忆机制**。本文没有跨 episode 或跨任务的长期记忆模块，H_t 只是一个 1 秒滑动上下文窗口。下游机器人的 50 步 action chunk / 8 步执行间隔是另一套完全不同的时间尺度，不能反过来当作预训练的记忆窗口。

### 1.2 关键机制 (Key Mechanism)

**(a) 事件 token 与动作 token 的物理隔离。** 游戏分支把词表扩到 250,416 行，用于预测序列化的键鼠事件 token；同时**连续机器人动作目标被禁用**（§3.1）。这一步是整个方法成立的前提——如果让键鼠 token 直接参与机器人动作回归，就等于隐式假设「按键 ≈ 关节力矩」，作者明确拒绝了这个假设。

**(b) 注意力屏蔽：未来动作 token 不许进入 foresight 查询。** 50 个可学习 foresight queries 产生 F_θ(H_t)，这些 query 对「每一个 target-action 位置」的注意力被全部阻断，且它们的位置索引被锚定在 target suffix 之前（§3.2）。这样就切断了训练时 teacher forcing 泄漏路径：模型在训练时看得到真值未来动作，但 foresight 特征里读不到。**这是本文最实的一个工程约束**，也是唯一能被推理时行为检验的设计。

**(c) 冻结视频教师提供连续监督。** 冻结 Wan VAE 把 5 帧 clip 压成 2 个 temporal latent slices，另一个单独编码的当前图像作为干净的 condition slice。条件 patch 的时间步设为 0，未来 patch 用采样到的噪声等级。denoiser 权重冻结，但**梯度仍可穿过条件路径回传到 foresight projection**（§3.3、§F.3）——这是「冻结教师、训练学生」的标准做法。

**(d) 采样覆盖率优先，不追求密集。** 250 ms 节奏的贪心 anchor 选择会漏掉一些动作序号，于是加一轮 coverage recovery，恢复了 3,038 个合法 anchor，把动作覆盖率从 99.94% 提到 100%（§4.1）。注意恢复后局部 anchor 间隔可以短于 250 ms。

⚡ **Eureka Moment**：把「游戏动作 → 机器人动作」的翻译问题，降级成「游戏事件作为额外监督 + 保住原机器人接口」的复用问题。前者要求动作空间对齐，后者只要求权重能装回去——bridge 只搬张量，不学映射。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L = L_NEP(H_t → Y_t, 因果)  +  L_video(冻结 denoiser, 条件仅来自 H_t)
```

两项目标共享同一个 H_t，但**互不偷看**：事件头走因果链，前瞻头被 mask 挡住未来动作。

### 2.1 目标一：Next-Event Prediction

```
L_NEP = - (1/B) · Σ_{b=1..B} (1/|T_b|) · Σ_{j∈T_b} log p_θ(y_bj | H_{t_b}, y_{b,<j})
```

| 符号 | 含义 | 本文取值 |
|------|------|---------|
| B | batch size | 128（8 设备 × 1 样本 × 16 累积） |
| T_b | 第 b 个样本的目标 token 集合 | 由 1 秒窗口内实际键鼠事件序列化决定 |
| H_{t_b} | 已观测历史（≤1 s） | median 32 事件 / 17 屏 / 968.32 ms |
| y_{b,<j} | 同一样本内 j 之前的 token | 因果 |

**直觉**：先对每个样本内的目标 token 求平均，再对 batch 求平均。这使每个样本权重相等，不受该样本事件密度影响——论文 §3.2 明确写了这个归约顺序，附录 F.3 也强调它和附录 E 的验证损失归约是两套不同实验。

### 2.2 目标二：冻结视频的 flow-matching 监督

构造带噪潜变量与条件：

```
z~_σ = [ z_c , (1 - σ)·z_f + σ·ε ]
c_θ   = P_θ · F_θ(H_t)
```

损失：

```
L_video = E[ || M ⊙ ( v_ω(z~_σ, c_θ, σ) - v* ) ||²₂ / N_z ]

v* = [ 0 , ε - z_f ]
```

| 符号 | 含义 | 本文取值 |
|------|------|---------|
| z_f | 未来 temporal latent slice | 48×1×14×14 = 9,408 元素 |
| z_c | 干净条件 slice（独立编码的当前图像） | 48×1×14×14 |
| z~_σ | 拼接后的输入 | 48×2×14×14 = 18,816 元素 |
| M | 遮掉条件 slice 的 mask | — |
| N_z | 归一化分母，**含被 mask 的条件 slice** | 18,816 |
| σ | 噪声等级，从 1,000 项 shift-5.0 scheduler 均匀取 index | {0,…,999} |
| ω | denoiser 权重，**冻结** | Wan2.2 TI2V-5B |

**关键细节（容易写错的地方）**：分母 N_z 数的是**全部 latent 元素**，不是只有未来部分。因为两个 temporal slice 大小相等，除以 18,816 恰好等于「未来 slice 均方误差的一半」。所以 `L_video` 的绝对值天然带一个 0.5 因子，读论文里的 loss 数值时必须记住这一点。另外，σ 是**均匀采样时间步索引**再查 scheduler，而不是均匀采样噪声水平——这两者不等价。

### 2.3 联合优化

```
L = L_NEP + L_video      （系数均为 1.0）
```

作者在 §3.3 明确警告：**单位系数不等于梯度贡献相等**。两项目标的梯度量级由数据、token 数、latent 维度共同决定，本文没有做权重调参实验。

> 符号与本文一致：θ 为可训练参数；ω 为冻结视频教师参数；P_θ 为 foresight projection；F_θ 为 foresight query 输出。

## 3. 带数字走一遍：玩具例子 (Worked Example)

> 以下四段均为**基于论文公开数字的算术验算**，不是论文原表，也不是新实验。标注「假设」的地方为构造性设定。

### 3.1 验算一：anchor 计数是否闭合（假设：无其它未记录损耗）

论文 Table 2 给了两串数字，可以互相对账：

```
250 ms 选择后样本数            2,356,278
+ coverage recovery 恢复 anchor     3,038
= 应为最终样本池               2,359,316

Table 2 最终 train + val
= 2,072,084 + 287,232 = 2,359,316   ✓ 完全一致
```

这说明 3,038 个恢复 anchor **也进入了 train/val 划分**，没有被当成额外附属品。同时可算恢复带来的覆盖率：

```
10,732,300 / 10,738,981 = 99.9378% ≈ 99.94%   ✓ 与正文一致
6,681 个动作 / 3,038 个 anchor ≈ 2.20 个动作/anchor
```

后一个比值说明恢复的 anchor 是「欠采样」的——平均每个恢复 anchor 要覆盖 2 个以上此前未覆盖的动作。这正是 §4.1 说「局部 anchor 间隔可短于 250 ms」的来源。

### 3.2 验算二：训练预算折算成 epoch 比例

```
12,400 updates × 128 global batch = 1,587,200 sample presentations
1,587,200 / 2,072,084 = 0.76599… ≈ 76.6%   ✓ 与 §3.4 一致
```

**注意单位**：12,400 是 **optimizer updates**，不是 epoch，也不是样本数。1,587,200 是 **sample presentations**（样本被看到的次数），与 anchor 总数 2,072,084 是不同量纲。论文用「名义 epoch 的 76.6%」来描述，但没有跑满一个 epoch——这是一个滚动 checkpoint 选择，不是收敛点。

### 3.3 验算三：跨阶段 5 帧的物理跨度差 2.5 倍

**游戏阶段**：偏移 `[0, 0.25, 0.50, 0.75, 1.00]` s，K=5，Δt=0.25 s：

```
首末跨度 = (K - 1) × Δt = 4 × 0.25 = 1.00 s
```

**机器人阶段**：20 Hz，Δt=0.05 s，50 步动作。视频帧用 `k_i = floor(50·i/4)`，i=0..4：

```
i=0 → k=0  → 0 × 0.05 = 0.00 s
i=1 → k=12 → 0.60 s
i=2 → k=25 → 1.25 s
i=3 → k=37 → 1.85 s
i=4 → k=50 → 2.50 s
```

注意这里第 4 帧落在 k=50，而 50 步动作的**最后一帧是 2.45 s**（第 50 个偏移 = 49×0.05，末值 2.45 s），2.50 s 是按 `floor` 规则外推出的一个额外采样点。跨度：

```
2.50 s / 1.00 s = 2.5 倍   ✓ 与 §3.4「2.5 times the physical duration」一致
```

**这个算式的用途**：它证明「同样是 5 帧」在两个阶段代表完全不同的物理时长。但作者在 §5 明确写了——这是**跨阶段规格对比，不是对增益的解释**；初始化实验把下游 horizon 固定住了，没有估计改变 horizon 的效应。所以不能反过来推论「因为跨度不同所以效果变好」。

### 3.4 验算四：成功率聚合与贡献拆解

```
总增益 = 1,811 - 1,718 = 93 次
93 / 2,000 = 4.65%  ✓ 与 Table 4 一致

等权平均（Base）  = (83.4 + 92.0 + 88.4 + 79.8) / 4 = 343.6 / 4 = 85.90%  ✓
等权平均（Game）  = (92.6 + 98.8 + 88.6 + 82.2) / 4 = 362.2 / 4 = 90.55%  ✓

Spatial + Object 贡献 = 46 + 34 = 80 次
80 / 93 = 86.0%   ✓ 与「80 of the 93 net additional successes」一致
```

因为四个 suite 的 episode 数相同（各 500），「等权平均」与「池化成功率」在数值上重合——论文 §D.1 专门指出了这一点。但这**不**意味着聚合分是单个策略的成绩：每个臂由四个**各自独立微调**的策略组成（Table 7「One policy per suite and initialization」）。

### 3.5 一个条件性对照（假设，仅用于说明归因困难）

### 4.1 时间预算与吞吐

| 环节 | 数值 | 工程含义 |
|------|------|---------|
| 游戏预训练 | 12,400 updates，BF16 + DeepSpeed ZeRO-2，8 设备 × 1 样本 × 16 累积 | 显存按单样本 + 梯度累积设计，适合单机 8 卡 |
| 可训练参数 | 2,682,148,480（配置值） | 冻结 Wan VAE/denoiser 后仍需 ~2.68 B 可训练，全参微调量级 |
| 上下文上限 | 8,192 positions；实测最大 4,686 token | 还有约 43% 余量，可考虑放长历史窗口（未做） |
| 下游微调 | 每 suite 20,000 updates，2 GPU × 16 = 32 batch | 单 suite 规模可控，四 suite 顺序跑 |
| 评测 | 每 suite 500 episodes，10 settling steps，224×224 | episode 数固定，与训练 update 数无关 |

### 4.2 三种「时间」不能混用

这是本文最容易在复述时讲错的地方，工程上要严格分开：

```
① 帧数：5 帧（游戏和机器人都用 5 帧，纯巧合）
② 预测跨度：游戏 1.00 s  vs  机器人 2.50 s（§3.4 的 2.5 倍）
③ 执行间隔：8 步 = 0.4 s（replan 周期，与②无关）
```

- ②是**标签跨度**，决定监督信号覆盖多远的未来。
- ③是**控制周期**，决定策略多久重新规划一次。
- 二者的比值 2.50 / 0.40 ≈ 6.25 意味着：模型每次被调用时，对 2.5 秒的未来有监督，但只对最近 0.4 秒负责。这是常见的 action chunking 折中（只执行前 8 步以换取反应速度），**但不是本文提出的机制**，而是沿用的下游配置。
- ①的「5」在两阶段相同，但**不构成任何共享的记忆窗口或上下文长度**。游戏历史 H_t 是 ≤1 s 的已观测帧序列，机器人 50 步 chunk 是未来动作预测——这两者方向相反、角色不同。

### 4.3 Bridge 的工程风险

Bridge 做的是：从 expanded seed 重建原生架构 → 合并 ZeRO-2 checkpoint → 覆盖保存的可训练张量 → 保留冻结的 seed 组件 → 保留扩表词表 / foresight queries / projection / temporal metadata → 设 native forward mode 为 robot（§B）。

**风险点**：这是一次「打包格式转换」，论文说它「retains the trained parameter values」，并声称有 reload 与配置检查（§B），但没有报告转换前后的数值一致性指标（如逐层权重校验、前向输出差）。如果读者要复现，这一环需要自己加断言。这是**条件性建议**，不是论文的主张。

### 4.4 部署约束

论文全程在 LIBERO 仿真中评测（§4.2、Ethics Statement），**没有任何真实机器人实验**。因此关于延迟、抖动、量化误差的结论一概不适用于真实系统。反过来，本文的推理侧改动很小：桥接后前向路径是原生的，游戏分支的词表扩展被保留但推理时不激活——这意味着**运行时开销理论上与 base 相同**，但论文没有给出实测 latency 对比，只能标注为「设计意图」。

**数据开放范围**：论文写的是「a selected human-recorded subset of D2E」，正文与附录**均未给出本文数据或代码的公开下载地址**。Reproducibility Statement 只声明 manuscript package 内含英文源文件、编译 PDF、数值表、数据/机器人配置的来源记录、转写的定性案例分箱、算术核对、冻结图像资源与归档的绘图代码。因此外部目前只能复现「表格与图」，不能复现「训练」。

**四 suite 结果**（Table 4，每格 500 episodes）：

| Suite | Base | Game 初始化 | Δn | Δpp |

### 5.3 真实机器人

**无**。论文 Ethics Statement 写的是「Robot evaluation is conducted in simulation」。所有指标都是仿真 benchmark 任务成功率，不对应真机部署。

### 5.4 附录中的独立诊断（不属于迁移流程的 ablation）

附录 E/G 有一组游戏动作重建实验，用 H-Base / T-Real / T-Unknown / T-Neutral / No-Time 几个变体。**§5 与 §D 都明确说这些 checkpoint 不用于机器人预训练，它们的预测不提供机器人标签**。几个值得记住的数字（Table 16，5 分钟 Apex 序列）：

| 模型 | Teacher-forced loss | Held completeness | Kbd F1 | Events |
|------|--------------------|-------------------|--------|--------|
| H-Base（生成参考，不参与 loss 比较） | – | 99.5% | .4942 | 3,427 |
| T-Real | **.24934（最低）** | **0.0%** | .0017 | 1,735 |
| T-Unknown | .26507 | 0.0% | .0000 | 0 |
| T-Neutral | .77015 | 53.7% | .3572 | 43 |

**读法**：loss 最低的臂自由生成结构完全崩掉（0% completeness）。作者据此论证 teacher-forced loss 不能描述自回归输出的结构质量。但这组结果只在一个 checkpoint、一个 5 分钟序列上，作者自己写了「identify functional dependence on a trained pathway, not the superiority of an independently trained LoRA-only model or a general defect of relative-time representations」（§E.6）。把它当成「时间编码有害」的普遍结论是过度解读。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**

- 在不改变机器人动作接口的前提下，把一类异构数据（键鼠事件 + 屏幕）接入已有 VLA 的预训练阶段。这一点是论文最可迁移的部分。
- 用注意力 mask 在结构上保证「训练时的未来动作真值」不进入推理可用的特征，这个约束是可验证的（虽然论文只做了设计说明，没做消融）。
- 在 LIBERO 四个 suite 上给出完整的 40 任务分解，而不是只报均值——这让读者能看到 Goal 的 +1 和 Long 的 ±30 pp 级波动。

**不能做什么**

- **不能归因**。作者原话：比较包含额外优化，「does not isolate the effects of game data, the two objectives, or training variability」（Abstract、§4.4、§5）。事件目标和视频目标各自的贡献没有测。
- **不能声称统计显著**。每 suite 一次训练运行，500 episodes 是同一策略的 rollout，不是独立训练重复；论文 §5 写明「we report no significance or equivalence claim」。Goal 的 +1 episode 只能当小观察。
- **不能声称跨游戏泛化**。within-game split，20 个游戏全部在训练分布内（按 session 分组）。
- **不能声称跨架构或跨机器人泛化**。只在 InternVLA-A1.5 一个模型、LIBERO 一个仿真基准上测。
- **不能声称真机可用**。零真机实验。

**具体失败模式**

| 现象 | 证据 | 位置 |
|------|------|------|
| Goal suite 几乎不动 | 442→443，净 +1 次 | Table 4 |
| Long 内部剧烈对冲 | L05 +32 pp 同时 L01 −36 pp | Table 10–11 |
| 任务级回归 | 40 任务中 10 个下降 | §4.4 |
| 事件目标与视频目标的贡献不可分 | 两目标系数均 1.0，无消融 | §3.3、§5 |
| 训练量混杂 | 游戏臂多 12,400 updates × 128 | Table 3、§4.4 |

### 6.1 隐含假设 (Hidden Assumptions)

**(1) 「游戏交互结构与机器人交互结构同构」这个假设只在很粗的粒度上被检验。** 论文的论证是「玩家观察场景 → 发出键鼠命令 → 观察后果」，与「机器人观察 → 动作 → 环境变化」结构相同（§1）。但键鼠是离散事件、机器人动作是 50 步动作块（action chunk）的连续量；两者的因果粒度、延迟特性、可逆性都不同。论文用「禁用连续动作目标 + 不学映射」回避了这个差异，**但也因此没有回答「哪些东西真的迁移过去了」**。

**(2) 冻结视频教师提供的监督，其质量没有被独立评估。** Wan2.2 TI2V-5B 在游戏画面上能提供多好的未来预测信号，论文没有报告。§3.3 只说明了 loss 的构造与归一化，没有说明教师的预测误差。如果教师对游戏画面（HUD、菜单、快速镜头切换）本身就预测不准，那么 foresight 目标的信噪比是未知的。

**(3) 「1 秒」这个窗口的选择没有依据。** 250 ms anchor 节奏、1 秒历史、1 秒目标，这三个数是设计选择。论文对比了游戏 1.00 s 与机器人 2.50 s 的跨度差（Figure 8），但明确说这是规格对比、不解释增益。窗口长度本身没有做敏感性分析。

**(4) 单 seed 下的 +4.65 pp 被当作可复现的方向性结论。** 作者在 §5 已经限定了「The unit of the reported result is a fixed suite-specific policy」，但读者仍容易把 4.65 读成方法属性。严谨表述应是：**在这一个 seed、这一个下游配方、这四个 suite 上观测到 4.65 pp**。

**(5) Bridge 的「保权重」未经数值验证。** §B 说保留了训练好的参数值，但没有报告转换前后的逐层对比或前向一致性检查。

## 7. 与相关工作对比 (Comparison)

| 工作 | 数据来源 | 与机器人动作空间的关系 | 训练目标 | 本文的差异 |
|------|---------|---------------------|---------|-----------|
| VPT (2022) | 无标注游戏视频 | 逆动力学伪标注动作 | 行为克隆 | 本文用**真实人类事件**而非逆动力学标签 |
| Gato (2022) | 异构任务 | 统一序列化 | 多任务序列建模 | 本文不做统一动作空间，保留原生机器人路径 |
| SIMA (2024) | 虚拟环境 | 指令跟随 | 语言条件策略 | 本文不追求跨环境指令泛化，只做预训练增广 |
| D2E (2026) | 桌面交互 | 视觉-动作预训练迁移 | 桌面事件 + 动作 | **本文的数据方向来源**；本文加的是 foresight 目标与 bridge 协议 |
| InternVLA-A1.5 (2026) | 机器人 | 原生 action expert | 动作 + 语言 + 视频 | **本文的架构宿主**；本文只改预训练阶段的监督 |
| 本文 | 游戏录屏子集 | 键鼠事件不映射为电机指令 | L_NEP + L_video | 事件与前瞻联合、mask 隔离、bridge 后原生微调 |

**一代际对照的关键句**：VPT 走的是「视频 → 伪动作标签 → 行为克隆」，本文走的是「视频 + 真实键鼠事件 → 辅助监督 → 权重初始化」，**绕开了动作空间翻译**。代价是增益来源不干净；收益是工程上不需要设计键鼠到关节的映射函数。

**面试 Tip**：如果被问「这篇和 D2E 有什么不同」，一句话答——**D2E 证明了桌面数据能迁移，本文证明了「不需要把键鼠翻译成机器人动作」也能迁移，方法是在已有 VLA 上加一个 mask 隔离的事件+前瞻预训练阶段再 bridge 回去**。如果被追问「提升可信吗」，就答：**+93/2000 是实测，但作者自己写明了无法与额外算力解耦，也没有统计检验**。

## 8. 精讀建議 (Reading Guide)

**值得精读原文的人**

1. **做「非机器人数据 → 策略」的数据增广研究者**：§3.2 的 attention mask 设计和 §3.1 的「禁用连续动作目标」是最可直接借用的两个决策，它们回答的是「怎么在不污染接口的前提下加监督」。
2. **要评估迁移方案落地可行性的工程师**：§3.4 + Figure 8 的跨阶段时长对照，和 §B 的 bridge 流程，是复现时最容易踩坑的两处。
3. **写 VLA 评测方法论的人**：§5 + §D.1 对「rollout 不是训练重复」「等权平均 = 池化成功率的前提是 suite 等 episode 数」的表述，是很好的写法范例。

**建议章节路径**

先读 **Abstract + §4.3 的 Table 4**（3 分钟拿到结论与规模）→ 再读 **§3.2 + §3.3**（核心机制，约 15 分钟）→ 然后读 **§5 的 Interpretation and Scope**（作者的自我限定，比方法节更重要）→ 最后按需读 **§4.4 + Table 8–11**（任务级异质性，决定你信不信这个均值）。可以跳过 **附录 E/G**（游戏动作诊断，与迁移流程无因果关系，作者自己也划清了界限），除非你对「teacher-forced loss 与自由生成脱节」这个现象本身感兴趣。

**不值得精读的理由**

如果你不做机器人策略预训练、或者只关心单阶段端到端架构创新，读摘要 + Table 4 就够了：这篇没有新架构，价值在于一个具体的数据接入协议和一份诚实的、带大量自我限定的实验报告。另外，如果你需要的是「可直接复现的代码」，目前无法满足——论文未提供数据或代码地址。
