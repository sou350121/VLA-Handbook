### 1.2 关键机制 (Key Mechanism)

**核心问题**：为什么关节空间命令或末端执行器命令都无法作为跨具身的通用条件？

- **关节空间命令**直接编码了机器人结构——同一组关节角对不同长度/自由度的臂毫无意义
- **末端执行器命令**虽然抽象了运动学，但相同的末端位移在不同机器人上会产生不同的可见连杆运动——模型仍须学习具身依赖的映射

**Hydra-0 的解法**：把动作表示为图像平面上的稀疏轨迹。这些轨迹：
1. 在训练时从视频跟踪恢复（AllTracker + SAM 3 分割）
2. 在部署时从 Isaac Lab 仿真 rollout 中正向投影
3. 用同一格式描述机械臂、夹爪、甚至人类手部——不暴露任何原生动作空间

⚡ **Eureka Moment**：动作流是"用视觉坐标描述动作"——既然世界模型最终预测的是视觉后果，为什么不直接用视觉坐标来描述动作条件？这样消除了具身依赖的中间映射层。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
x_n,t = π(K · [I₃ 0] · T_CW · T_ℓ(n)(q_t) · X̄_n)
```

**目标**：将任意具身的可执行命令映射到图像平面轨迹，使世界模型的条件输入具身无关。

**公式分解**：
- **x_n,t** = 点 n 在时间 t 的图像坐标 (u, v)
- **π** = 透视投影
- **K** = 相机内参矩阵
- **T_CW** = 相机到世界的外参
- **T_ℓ(n)(q_t)** = 连杆 ℓ 在构型 q_t 下的齐次变换
- **X̄_n** = 机器人表面点 n 的齐次 3D 坐标

**变量说明**：

| 符号 | 含义 | 维度 |
|------|------|------|
| x_n,t | 图像平面轨迹点 | 2D |
| m_n,t | 可见性标志 | {0,1} |
| F | 动作流 = {τ_n} (N 条轨迹) | 集合 |
| s_0 | 初始潜状态 | 取决于 VAE |
| M_k(p̃) | 潜空间时刻 k 位置 p̃ 的运动特征 | C 维 |
| g_k(p̃) | 存在门控 | [0,1] |
| β | 高斯局部性参数 | 220 |

**直觉**：公式 (1) 是几何感知的动作流构造核心——它把机器人的 3D 表面点通过运动学变换和相机投影"压扁"到 2D 图像平面。训练时这些轨迹从视频跟踪恢复，部署时从仿真命令正向计算。无论哪种方式，世界模型看到的都是同一格式的图像平面轨迹，完全不关心底层是 Franka 还是人类手。

**流匹配目标** (Eq 5)：

```
L(θ) = E[‖v_θ(Z_t, t, c, C_motion) - v_t*‖²]
```

标准流匹配损失，只是条件中额外加入了运动条件 C_motion。

> 符号与本文保持一致：所有公式基于论文原文。训练时 LoRA rank=64，逆模式动作头 LoRA rank=32。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2D 场景：

**设置**：
- 机器人单臂，初始帧 o_0 中可见夹爪中心在图像坐标 (320, 240)
- VLA 输出命令：夹爪向右移动 50 像素、向下移动 30 像素，持续 H=5 步
- Isaac Lab 仿真 rollout 给出每步连杆变换

**动作流构造**（部署时）：

```
时间 t=0: x = (320, 240), m=1  (初始可见)
时间 t=1: x = (330, 246), m=1  (投影: 50/5=10px/步 右, 30/5=6px/步 下)
时间 t=2: x = (340, 252), m=1
时间 t=3: x = (350, 258), m=1
时间 t=4: x = (360, 264), m=1
时间 t=5: x = (370, 270), m=1
```

**运动特征传播**（Eq 3-4）：

```
假设潜空间网格分辨率为 40×30，β=220:

在潜时间 k=2，位置 p̃=(25, 18) 对应的轨迹 n*:
  w̃_n*,k(p̃) = m̃_n*,0 · m̃_n*,k · exp(-220 · ‖p̃ - x̃_n*,k‖²)
             = 1 · 1 · exp(-220 · 0.01²)    (假设轨迹恰好经过该网格点)
             = exp(-0.022) ≈ 0.978

  M_k(p̃) = 0.978 · h_n*                    (h_n* = s_0 在轨迹起点处的特征)
  g_k(p̃) = clip[0,1](0.978) = 0.978
```

**世界模型预测**：

```
输入: Z_t (噪声潜变量) + C_motion = (M, g)
DiT 去噪: v_θ(Z_t, t, c, C_motion) → 更新 Z_{t-1}
4 步 DMD2 蒸馏后: Z_0 → d_ψ → o_hat_1:H (5 帧未来视频)
```

**闭环验证**：如果 VLA 命令正确，o_hat 中夹爪应从 (320,240) 移动到 (370,270)，与实际物理后果一致。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|-----------|----------|
| 训练算力 | 32×H100 × 5 天 × 40K steps (A14B) | 约 3,840 GPU-hours；小模型 (5B) 资源需求显著更低 |
| 推理速度 | 4 步 DMD2 蒸馏后 16.0× 加速 | 从全窗口多步采样降到每 chunk 4 步，接近实时 |
| 预测窗口 | 81 帧 ≈ 5 秒 (16 fps) | 适合短期后果预测，长 horizon 需 AR chunking |
| 动作流采样 | Embodiment: 11-128 tracks; All: 256-1024 tracks | 轨迹数直接影响计算量和条件信息量 |
| 标定要求 | 相机内参 K + 外参 T_CW | 中等误差仅扰动条件不改变目标；大误差破坏空间对应 |
| 仿真依赖 | Isaac Lab controller + physics | 部署时必须有可用的仿真环境来 rollout 候选命令 |
| LoRA 参数量 | rank-64 (正向) / rank-32 (逆向) | 参数高效微调，冻结主干大幅降低显存 |
| KV Cache | AR chunking 复用已生成 chunk | 长 horizon rollout 时避免重复计算 |

**关键 trade-off**：动作流表示牺牲了精确的 3D 物理建模，换取了跨具身的通用性。对于刚性物体操作，物理仿真可能更精确；但对于可变形物体（布料、线缆），显式状态重建和物理仿真仍然困难——这正是 Hydra-0 选择数据驱动视觉预测的原因。

### 不能做什么 / 失败模式

| 失败模式 | 原因 |
|----------|------|
| 大标定误差场景 | 动作流投影失真 → 空间对应关系破坏 |
| 无仿真环境的机器人 | 部署时无法从命令构造动作流（需 Isaac Lab） |
| 快速动态/运动模糊 | AllTracker 跟踪质量下降 → 轨迹断裂 |

| 非可变形物体操作 | 训练数据主要聚焦布料/线缆/纸张；刚性物体交互泛化未系统评估 |
| 长 horizon 累积误差 | AR chunking 中生成 chunk 替换干净历史，误差累积 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **仿真→真实的运动学桥接足够准确**：部署时依赖 Isaac Lab 的连杆变换和物理仿真来生成动作流。如果仿真中的运动学/动力学与真实机器人偏差较大，动作流投影位置会偏移，直接影响预测质量。
2. **相机标定在部署时可用且稳定**：公式 (1) 需要精确的 K 和 T_CW。实际部署中相机抖动、温度漂移、重新安装都会改变标定。
3. **AllTracker 在训练数据上足够鲁棒**：视频构造路线依赖密集跟踪质量。如果训练视频有大量运动模糊或遮挡，恢复的轨迹质量会下降。
4. **可变形物体交互是主要应用场景**：论文明确以可变形物体为核心目标域。对于刚性物体的精确操作（如插孔、精密装配），动作流的像素级表示可能不够精细。
5. **动作流足以编码任务意图**：对象流模式（Object mode）在推理时提供期望的对象运动，但对象运动本身可能无法唯一确定所需的机器人动作（多解性）。
