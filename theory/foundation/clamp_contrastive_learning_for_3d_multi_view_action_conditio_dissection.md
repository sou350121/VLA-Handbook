💡 **X-Ray 开场**
现有机器人预训练大多基于 2D 图像（如 CLIP 式图文对齐），但 2D 表征丢失了物体间的三维空间关系——这正是精密操作（如把杯子放到盘子上、打开抽屉）失败的关键原因。CLAMP 的做法是：从 RGB-D 重建场景点云，渲染出含深度和 3D 坐标的多视图图像，然后用对比学习让图像、动作、文本三种表征在同一个空间中对齐。结果：在 6 个仿真任务和 5 个真实任务上全面超越 ALOHA Unleashed 和 ACT 等 SOTA。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 参数量 | 预训练用途 | 微调时是否使用 |
|------|------|------|--------|-----------|-------------|
| 图像编码器 | 5 视图 × 4 通道 (D,X,Y,Z) | 768-d 嵌入 | 94M (ViT-B/16) | 三模态对比学习 | 冻结，提取特征 |
| 动作编码器 | 历史动作序列 (chunk size H) | 768-d 嵌入 | 18M (2-layer Transformer) | 三模态对比学习 | 冻结，提取特征 |
| 文本编码器 | 任务描述 + 物体名/位置 + 进度 | 768-d 嵌入 | 277M (CLIP text) | 三模态对比学习 | **不使用**（特权信息） |
| Diffusion Policy | RGB 特征 + CLAMP 嵌入 + proprio | 50×14 动作噪声 | 192M (4+7 layer Transformer) | 并行预训练 | 解冻微调 |

**关键设计决策**：文本编码器仅在预训练阶段使用，利用仿真器提供的物体名称和位置等特权信息来锚定图像和动作表征；部署时不需要文本输入，避免了"依赖不可用信息"的问题。

### 1.2 关键机制 (Key Mechanism)

**三模态对比学习**：CLAMP 同时优化三对模态的对比损失——图像-文本、图像-动作、文本-动作。每对使用 SigLIP-style loss，将匹配三元组的嵌入拉近、非匹配对推远。

**多视图 4 通道渲染**：从 RGB-D + 相机内外参重建场景点云（去掉 RGB 颜色以提升外观泛化），然后从 5 个虚拟视角重新渲染：俯视、左前、右后、左手腕、右手腕。每个像素 4 通道 = (深度, X, Y, Z)。

**STRING 相对位置编码（首次用于点云坐标）**：这是 CLAMP 最具理论深度的创新。传统 ViT 的位置编码是 2D 网格或可学习的；STRING 则用每个图像 patch 对应的点云子集的 3D 质心坐标来计算 token 之间的相对位置偏差。效果：来自不同视图但对应同一 3D 区域的 token 会自动获得高注意力分数，而空间距离远的 token 注意力会被衰减。

⚡ **Eureka Moment**：用点云的 3D 质心坐标直接驱动 ViT 的相对位置编码——不需要显式匹配跨视图的 patch，注意力机制自动学会"把空间中相邻的 token 关联起来"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L_total = 1/3 · (L_I-T + L_I-A + L_T-A)
其中 L_X-Y = -E[log σ(t·cos(x,y) + b)]  （SigLIP-style，t 和 b 可学习）
```

**目标**：让同一三元组 (I, T, A) 的嵌入在共享空间中彼此靠近，不同三元组的嵌入彼此远离。

**公式详解**：

以图像-文本损失为例：

```
L_I-T = -(1/|B|) · Σ_i Σ_j log[ 1 / (1 + exp(ℓ_ij · (-t · x_i^T · y_j + b))) ]
```

其中：
- `x_i = f(I_i) / ||f(I_i)||_2` — L2 归一化的图像嵌入
- `y_j = g(T_j) / ||g(T_j)||_2` — L2 归一化的文本嵌入
- `ℓ_ij ∈ {+1, -1}` — 匹配对为 +1，非匹配对为 -1
- `t = exp(log(10)) ≈ 10`（可学习温度参数，初始值）
- `b = -10`（可学习偏置，初始值）

**变量说明**：

| 符号 | 含义 | 维度 |
|------|------|------|
| I ∈ R^{H×W×4} | 四通道图像 (D,X,Y,Z) | H×W×4 |
| T | 文本 (任务描述+物体信息+进度) | 256 tokens |
| A_t = {a_{t-1}, ..., a_{t-H}} | 历史动作序列 | H × 14 |
| x, y, z | 归一化后的图像/文本/动作嵌入 | 768-d |
| t, b | 温度和偏置（SigLIP 技巧） | scalar |

**直觉**：当 ℓ=+1（匹配对）时，损失函数鼓励 x^T·y 变大（cosine 相似度接近 1）；当 ℓ=-1（非匹配对）时，鼓励 x^T·y 变小。三对损失取平均，确保图像-动作-文本三者形成三角对齐。

> 符号与论文保持一致。t 和 b 的 SigLIP 初始化（t=10, b=-10）是为了防止训练初期梯度爆炸。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 mini-batch 中有 2 个三元组 (N=2)：

```
Triplet 1: I_1 = "杯子在左侧", A_1 = [左臂伸向杯子, 夹紧, 提起]
Triplet 2: I_2 = "螺丝刀在右侧", A_2 = [右臂伸向螺丝刀, 夹紧, 移动]
```

**Step 1 — 编码**：
```
f(I_1) → x_1 (768-d, L2 归一化后)
f(I_2) → x_2
h(A_1) → z_1
h(A_2) → z_2
```

**Step 2 — 计算图像-动作相似度矩阵**：
```
        z_1    z_2
x_1  [ +0.85, -0.32 ]   ← x_1 与 z_1 匹配（高相似），与 z_2 不匹配
x_2  [ -0.28, +0.91 ]   ← x_2 与 z_2 匹配，与 z_1 不匹配
```

**Step 3 — SigLIP 损失计算**（以 x_1, z_1 匹配对为例）：
```
logit = t · x_1^T · z_1 + b = 10 × 0.85 + (-10) = -1.5
L_pair = log(1 / (1 + exp(-1 × (-1.5)))) = log(1 / (1 + exp(1.5)))
       = log(1 / (1 + 4.48)) = log(0.182) ≈ -1.70
```

负损失值表示模型已经做出了正确判断（匹配对得分高）。如果模型判断错误（如 x_1^T·z_1 = -0.5）：
```
logit = 10 × (-0.5) + (-10) = -15
L_pair = log(1 / (1 + exp(-1 × (-15)))) = log(1 / (1 + exp(15))) ≈ 0
```

等等——这里 ℓ=+1，所以应该是：
```
L_pair = log(1 / (1 + exp(+1 × (-15)))) = log(1 / (1 + exp(-15))) ≈ log(1) = 0
```

实际上当模型判断错误时，梯度会推动 x_1^T·z_1 增大。正确的数值演示：
```
假设 x_1^T·z_1 = 0.2（模型不够确信）
logit = 10 × 0.2 + (-10) = -8
L = log(1/(1+exp(-1×(-8)))) = log(1/(1+exp(8))) ≈ log(0.00034) ≈ -8.0

假设 x_1^T·z_1 = 0.85（模型确信）
logit = 10 × 0.85 + (-10) = -1.5
L = log(1/(1+exp(-1×(-1.5)))) = log(1/(1+4.48)) ≈ -1.70
```

损失从 -8.0 变到 -1.70——更小的绝对值意味着梯度在推动模型提高相似度。

**Step 4 — 总损失**：
```
L_total = 1/3 × (L_I-T + L_I-A + L_T-A)
        ≈ 1/3 × (-1.70 + -1.55 + -1.62) ≈ -1.62
```

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|----------|---------|
| 预训练数据量 | 358M 三元组（553K episodes × 多模态） | 需要大规模 VLA 或遥操作数据收集 |
| 图像编码器 | 94M ViT-B/16 | 单卡可加载；推理时冻结，无额外开销 |
| 动作编码器 | 18M Transformer | 轻量，推理开销可忽略 |
| 文本编码器 | 277M CLIP | **仅预训练需要**；部署时完全移除 |
| Diffusion Policy | 192M (4+7 layer) | 推理时需 50 步去噪，延迟较高 |
| 动作 chunk | 50 steps / 14 DOF | 每步输出 14 个关节目标位置 |
| 视图数量 | 5 个（3 固定 + 2 动态手腕） | 渲染开销：每帧 5 次点云重投影 |
| 微调数据 | 4,500 demos/task | 相比无预训练减少 5-10× 数据需求 |
| Sim→Real | 策略在真实数据上预训练 | 减少 sim-to-real gap；真实数据 63-500 demos/task |

**部署延迟估算**：Diffusion Policy 需要 50 步去噪，每步经过 11 层 Transformer（4 enc + 7 dec）。在单 GPU 上约 50-100ms/step → 总推理延迟 2.5-5s。这是 CLAMP 最大的工程瓶颈——实际部署可能需要减少去噪步数或蒸馏。

**内存占用**：预训练阶段需同时加载 4 个模型（94M + 18M + 277M + 192M ≈ 581M params），约 2.3GB FP16。微调阶段文本编码器移除，降至约 304M params。

### 6.1 隐含假设 (Hidden Assumptions)

1. **点云质量足够**：假设 RGB-D 相机能提供准确的深度信息。在反光/透明物体场景下，点云质量下降会直接影响 4 通道渲染质量。
2. **仿真器生成的预训练数据质量可靠**：依赖 GR1.5 VLA 生成 55 万 episodes，且只保留成功轨迹。如果 VLA 本身存在系统性偏差，预训练会继承这些偏差。
3. **动作模式可迁移**：假设不同任务共享"共同的动作模式或轨迹片段"。这在桌面操作范围内可能成立，但跨形态（如桌面→移动）的迁移性未验证。
4. **5 视图覆盖充分**：假设 overhead + front-left + back-right + 2 手腕 能覆盖操作所需的所有视角。如果任务需要侧面或底部视角，可能遗漏关键信息。
