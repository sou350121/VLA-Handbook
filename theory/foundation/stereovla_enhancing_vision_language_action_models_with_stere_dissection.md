💡 **X-Ray 开场**
VLA 模型（如 OpenVLA、π₀.₅）在语义理解上很强，但缺乏精细的空间感知——它们"知道"要抓什么，但经常"抓不准"。根本原因是单目 RGB 编码器没有深度信息。StereoVLA 的回答是：给 VLA 装上"双眼"，用双目视差提供几何线索，同时保留语义理解能力。对研究者而言，这意味着 VLA 的空间感知可以从"猜深度"走向"测深度"，且不需要昂贵的深度传感器。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 训练/推理差异 |
|------|------|------|---------------|
| **GeoSem 视觉编码器** | 双目图像对 I_l, I_r | 混合视觉 token（几何+语义） | 训练时冻结；推理时同样冻结 |
| FoundationStereo 特征提取 | I_l, I_r | 过滤代价体 V_c'（几何特征） | 仅前向传播，跳过迭代优化 |
| SigLIP + DINOv2 | I_l（仅左图） | 语义特征 token | 冻结，同 PrismaticVLM |
| MLP 投影融合 | 几何特征 + 语义特征 | 统一视觉 token 序列 | 可训练 |
| **LLM 主干** | 视觉 token + 语言 token | 中间层 KV cache | InternLM-1.8B，冻结预训练权重 |
| **动作专家** | KV cache | 动作块（flow-matching） | 300M 参数，可训练 |
| **辅助任务 1** | KV cache + 交互区域坐标 | 深度值（文本生成） | 仅训练时激活 |
| **辅助任务 2** | KV cache | 相机内外参（文本生成） | 仅训练时激活 |
| **2D BBox 预测** | 左图视觉 token | 目标 2D 框 + 关键帧位姿 | 仅训练时激活（渐进式动作生成） |

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **几何特征来源选择**：FoundationStereo 有两条计算路径——代价体路径和互相关路径。作者选择过滤代价体 V_c' 而非原始代价体 V_c，因为前者通过混合代价滤波模块捕获了长程相关性，提供了更丰富的几何特征。跳过迭代优化步骤以节省计算开销。

2. **语义特征仅用左图**：左右视图的语义信息高度冗余，仅在左图上运行 SigLIP + DINOv2 可大幅减少计算量而不损失语义质量。

3. **特征融合策略**：将 FoundationStereo 特征空间池化到 14 像素步长（与 SigLIP/DINOv2 对齐），然后沿通道维度拼接。**避免 token 序列拼接**，因为那会增加训练和推理时的 token 数量。

4. **辅助任务设计哲学**：深度估计和相机参数估计仅在训练时激活，推理时不需要——它们的作用是"引导模型学习空间推理"，而不是增加推理延迟。

⚡ **Eureka Moment**：VLA 的空间感知瓶颈不是"缺少传感器"，而是"预训练 RGB 编码器缺乏几何表征能力"——用立体视差的几何特征替换单目 RGB 编码器的几何盲区，比增加更多相机更有效。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L = L_action + L_depth + L_camera + L_bbox + L_pose
```

**目标**：通过多任务联合训练，让 VLA 同时学会动作预测、空间深度推理、和相机坐标系对齐，而不增加推理开销。

**完整训练损失**：

```
L = L_action + L_depth + L_camera + L_bbox + L_pose
```

| 符号 | 含义 | 类型 |
|------|------|------|
| L_action | Flow-matching 动作块预测损失 | 连续值回归 |
| L_depth | 交互区域深度估计交叉熵 | 文本生成（深度值→字符串） |
| L_camera | 相机内外参估计交叉熵 | 文本生成（参数→字符串） |
| L_bbox | 2D 目标框预测交叉熵 | 文本生成 |
| L_pose | 关键帧位姿预测交叉熵 | 文本生成 |

**样本配比**：动作:深度:相机:框:位姿 = 1:2:2:2:1

**直觉**：
- L_action 是主任务——预测下一个动作块（delta end-effector pose）
- L_depth 和 L_camera 是"空间推理引导器"——它们迫使模型在内部表示中编码几何信息，但不增加推理延迟（仅在训练时激活）
- 将连续值（深度、相机参数）转化为文本生成而非回归头，保持了统一的架构，利用了预训练知识

> 符号与本文保持一致：L_action 使用 flow-matching 目标（与 Diffusion-Policy / π₀ 一致）；辅助任务全部使用交叉熵损失，将连续值离散化为文本 token。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的抓取场景：

**场景设置**：
- 相机到目标物体的真实距离：d = 0.5m
- 双目基线距离：b = 0.1m
- 相机焦距：f = 500 像素
- 图像分辨率：224×224

**步骤 1 — 视差计算**：
```
视差 disp = f · b / d = 500 × 0.1 / 0.5 = 100 像素
```
左图中目标在 x_l = 120，右图中在 x_r = 20，视差 = 100。

**步骤 2 — GeoSem 编码**：
- FoundationStereo 从视差 100 像素生成过滤代价体 V_c'，维度 C × D/4 × H/4 × W/4
- SigLIP/DINOv2 从左图提取语义特征，维度 D_sem × 16 × 16（14px stride）
- 空间池化后拼接：混合特征维度 = (C + D_sem) × 16 × 16

**步骤 3 — 深度估计辅助任务**：
```
模型接收 prompt: "What is the depth at x=120, y=112?"
模型输出文本: "0.50"（目标深度 0.5m）
L_depth = -log p("0.50" | 视觉 token, 语言 token)
```

**步骤 4 — 动作预测**：
```
目标动作: delta = [dx=0.02, dy=-0.01, dz=-0.48, roll=0, pitch=0, yaw=0, grip=close]
L_action = flow-matching loss（预测速度场使噪声分布→动作分布）
```

**步骤 5 — 总损失**：
```
L_total = L_action(权重1) + L_depth(权重1) + L_camera(权重1) + L_bbox(权重1) + L_pose(权重1)
```

训练 300k 步后，模型学会了从视差模式直接映射到精确的 3D 空间动作，而不需要显式计算深度图。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|-----------|----------|
| 模型规模 | InternLM-1.8B + 300M 动作专家 = ~2.1B 总参数 | 可在单卡 A100/H100 上推理 |
| 训练资源 | 32×H800 GPU，batch size 384，300k 步 | 大规模训练，约需数天 |
| 推理延迟 | FoundationStereo 特征提取约 70ms（迭代优化版本）；GeoSem 跳过迭代优化后显著降低 | 但 70ms 仍不适合高频控制（典型控制频率 10-30Hz） |
| 输入分辨率 | 224×224 | 小物体（1-2cm）仅占几个像素，是性能瓶颈 |
| 动作表示 | Delta end-effector pose（7D：3平移+3旋转+1夹爪） | 与 OpenVLA/π₀ 一致，易于集成现有控制栈 |
| 推理时辅助任务 | 不激活（深度估计 + 相机参数估计仅在训练时） | 推理延迟与单目 VLA 基本一致 |
| 训练数据 | 5M 合成立体轨迹（Franka + 人形机器人） | 零真实数据微调，纯 sim-to-real |
| 控制策略 | 准静态 + 位置控制 | 不适合动态/高速操作场景 |

**部署约束**：
- 需要双目相机硬件（如 Intel RealSense 或类似设备），但无需深度传感器
- 推理时不需要 FoundationStereo 的迭代优化，仅需前向特征提取
- 224×224 分辨率是硬性限制——更高分辨率需要更大的视觉编码器，增加计算负担

## 5. 数据与评测 (Data & Eval)

### 训练数据

| 属性 | 详情 |
|------|------|
| 数据量 | 500 万立体轨迹 |
| 数据来源 | 高保真合成（ray-traced rendering） |
| 机器人形态 | 桌面 Franka + 人形机器人 |
| 域随机化 | 光照、纹理、相机参数 |
| 动力学 | 准静态假设 + 摩擦随机化 |
| 视觉对齐 | 冻结预训练编码器 + GRIT 2D box 联合训练 |

> 关键观察：作者发现现代渲染在 RGB 逼真度上很高，但无法准确模拟传感器特定的深度噪声。因此立体视觉成为比深度图更鲁棒的 sim-to-real 模态——视差模式在仿真和真实之间更一致。

### 评测任务设置

| 任务类别 | 描述 | 评估重点 |
|----------|------|----------|
| Common | 日常物品抓取和堆叠 | 基本空间协调 |
| Distractor | 9 个相似干扰物中的目标识别 | 视觉 grounding |
| Environment | 不同背景和光照 | 环境鲁棒性 |
| Transparent Object | 透明塑料物体 | 深度传感器弱点对比 |
| Small Object | 1-2cm 小物体抓取 | 毫米级精度 |
| Bar-shaped Object | 叉子等长条物体（0°/45°/90°） | 长轴视觉重叠鲁棒性 |

**评测严格度**：
- 每次试验仅允许一次抓取尝试（夹爪关闭一次 + 打开一次）
- 禁用"夹爪粘附"启发式（人为延迟夹爪动作的 hack）
- 仅完整成功才算成功，无部分分数
- 每个测试集 15 次试验，总计 450 次真实机器人试验

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能力

| 场景 | 表现 | 原因 |
|------|------|------|
| 一般抓取/放置 | 77.2% 成功率（小随机化） | 立体视差提供精确深度 |
| 小物体（1-2cm） | 33% 成功率（基线全部 0%） | 几何感知使毫米级操作成为可能 |
| 大相机位姿变化 | 53.9% 成功率（基线 11.1-42.2%） | 相机参数估计辅助任务 |
| 移动相机 | 52.2% 成功率（基线 7.2-39.4%） | 同上 |
| 透明物体 | 优于 RGB-D 基线 | 立体视差不受透明表面反射影响 |

### 失败模式

| 场景 | 失败原因 |
|------|----------|
| 极小物体（<1cm） | 224×224 分辨率下仅占 1-2 像素，语义 grounding 不足 |
| 极端遮挡 | 立体视觉需要左右图都能看到目标区域 |
| 动态/高速操作 | 准静态假设不适用 |
| 超出训练分布的物体形态 | 合成数据未覆盖的物体类别 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **夹爪和目标始终在视野内**：相机位姿随机化时保证目标可见，但真实部署中目标可能移出视野
2. **准静态操作**：假设物体在操作过程中基本静止，不适合动态抓取
3. **合成数据的几何一致性**：假设仿真中的视差模式与真实传感器足够相似——作者承认深度噪声建模不足，但认为视差比深度图更鲁棒
4. **单臂操作**：实验仅在单臂 Franka 上验证，未测试双臂协调
5. **桌面操作域**：所有任务在 0.5m×0.4m 工作空间内，未测试更大范围或移动机器人

## 7. 与相关工作对比 (Comparison)

| 模型 | 感知模态 | 几何编码 | 训练数据 | 小物体成功率 | 大位姿鲁棒性 |
|------|----------|----------|----------|-------------|-------------|
| OpenVLA | 单目 RGB | 无 | 真实数据 | ~0% | 低 |
| SpatialVLA | RGB-D（单目深度估计） | 深度位置编码 | 真实+合成 | ~0% | 中 |
| SpatialVLA-ED | RGB-D（立体估计深度） | 深度位置编码 | 真实+合成 | ~0% | 中 |
| π₀.₅ | 前+腕多相机 | 无显式几何 | 真实数据 | ~0% | 中高 |
| GraspVLA | 前+侧多相机 | 无显式几何 | 合成数据 | ~0% | 低 |
| **StereoVLA** | **双目立体 RGB** | **GeoSem 混合编码** | **5M 合成** | **33%** | **高** |

**关键差异**：
- 与 GraspVLA-S（相同的 GraspVLA 架构 + 立体输入）对比：StereoVLA 的 GeoSem 编码器 + 辅助任务带来显著增益，证明增益来自方法论而非仅仅是相机更换
- 与 SpatialVLA-ED 对比：两者都使用 FoundationStereo 深度，但 SpatialVLA-ED 在空间编码时降采样丢失了几何细节，而 StereoVLA 直接在特征层面融合

💡 **面试 Tip**：当被问"立体视觉 vs 深度传感器哪个更好"时，回答：立体视觉的 sim-to-real 几何迁移更鲁棒（视差模式比深度噪声更一致），但深度传感器在理论上提供直接测量——实际选择取决于你的 sim-to-real 策略和硬件约束。
