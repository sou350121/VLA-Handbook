💡 **X-Ray 开场**
VLA 模型（如 OpenVLA、π0.5）擅长语义理解但缺乏精细空间感知——它们"知道"要拿什么，但"看不清"精确位置。StereoVLA 的核心发现是：与其加更多相机（腕部/侧面/第三视角），不如用一对立体相机提供显式几何线索，并通过 GeoSem 编码器将几何特征和语义特征融合到同一个 token 序列中。对 VLA 研究者的意义：这提供了一条比 RGB-D 传感器更便宜、比多目相机更鲁棒的硬件方案。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 训练/推理差异 | 关键设计选择 |
|------|------|------|---------------|-------------|
| **GeoSem 视觉编码器** | 立体图像对 (Il, Ir) | 混合视觉 tokens | 训练+推理 | 选 FoundationStereo 的过滤代价体 V'c（非原始代价体 Vc 或相关体 Vcorr） |
| **LLM Backbone** | 视觉 tokens + 语言 tokens | 中间特征 (KV cache) | 训练+推理 | InternLM-1.8B，冻结预训练权重 |
| **Action Expert** | KV cache 特征 | delta 末端执行器姿态 chunk | 仅推理 | 300M 参数，flow-matching 策略 |
| **交互区域深度估计** | 采样坐标 (x,y) + 图像 | 深度值 d (文本生成) | 仅训练 | 任务感知采样（夹爪+目标物体 bbox 区域），非均匀采样 |
| **相机参数估计** | 图像 | 外参 T_camera^robot + 内参 K (文本生成) | 仅训练 | 预测 (x,y,z, roll,pitch,yaw, fx,fy,cx,cy) |
| **Bbox + Pose 预测** | 左视图 | 2D bbox + 关键帧姿态 | 仅训练 | 仅在左图预测 bbox（右图语义冗余） |

### 1.2 关键机制 (Key Mechanism)

**为什么用立体视觉而不是其他传感器？**

| 传感器方案 | 优势 | 劣势 |
|-----------|------|------|
| 腕部相机 | 夹爪-物体交互的自中心视图 | 易遮挡、增加碰撞风险、缺乏精确空间感知 |
| RGB-D 传感器 (RealSense) | 直接深度测量 | 透明/反射表面失效、受光照影响、深度噪声与仿真不一致 |
| 多目相机 (π0.5 四角) | 互补视角 | 硬件复杂（移动/人形机器人）、视角多样性阻碍鲁棒性 |
| **立体视觉 (StereoVLA)** | 显式几何线索、硬件简单、对透明物体有效、sim-to-real 几何迁移鲁棒 | 需要合成立体数据训练、224×224 分辨率限制小物体 |

⚡ **Eureka Moment**：不直接预测深度图，而是从 FoundationStereo 的过滤代价体 V'c 中提取稠密几何特征，与 SigLIP+DINOv2 的语义特征在 channel 维度拼接——这样既保留了立体匹配的几何精度，又避免了额外深度估计的推理延迟。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L = L_action + L_depth + L_camera + L_bbox + L_pose
  (总损失 = 动作 + 深度 + 相机参数 + 边界框 + 关键帧姿态)
```

**目标**：通过多任务联合训练，让模型在单一前向传播中同时学会空间感知（深度、相机参数）和动作生成（bbox、姿态、动作 chunk），而不增加推理延迟。

**变量说明**：

| 符号 | 含义 | 损失类型 | 任务比例 |
|------|------|---------|---------|
| L_action | flow-matching 损失，预测 delta 末端执行器姿态 chunk | flow-matching | 1 |
| L_depth | 交互区域深度估计的交叉熵（深度值转为文本生成） | cross-entropy | 2 |
| L_camera | 相机内外参估计的交叉熵（8个参数转为文本） | cross-entropy | 2 |
| L_bbox | 2D 边界框预测的交叉熵 | cross-entropy | 2 |
| L_pose | 关键帧姿态预测的交叉熵 | cross-entropy | 1 |

> 符号与本文保持一致：所有辅助任务的连续值（深度、相机参数）都被转换为纯文本字符串，用标准交叉熵损失监督，避免了任务特定的回归头或离散化 bin。

**直觉**：5 个任务的样本按 1:2:2:2:1 比例平衡，总训练 300k steps，32 块 H800，batch size 384，learning rate 1.6e-4。辅助任务（深度 + 相机参数）只在训练时存在，推理时只需 Action Expert——这意味着空间推理能力被"蒸馏"到了 LLM 的中间表示中，不增加推理开销。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个抓取任务：目标物体在 (x=0.1m, y=0.05m, z=0.3m)，夹爪当前位置在 (x=0, y=0, z=0.5m)。

**Step 1 — 视觉编码**：
- 立体图像对 (224×224) 输入 GeoSem 编码器
- FoundationStereo 产生过滤代价体 V'c ∈ R^{C × D/4 × H/4 × W/4}
- SigLIP+DINOv2 产生语义特征（14-pixel stride）
- 拼接后得到混合 tokens

**Step 2 — 深度估计（训练时）**：
- 模型被问："What is the depth at x,y?"（采样自夹爪+目标 bbox 区域）
- 真实深度 d = 0.3m
- 模型生成文本 "0.30"，L_depth 监督

**Step 3 — 相机参数估计（训练时）**：
- 模型被问："What are the camera extrinsics and intrinsics?"
- 真实外参：平移 (0.1, -0.05, 0.5)，旋转 (0.1, -0.05, 0.0) rad
- 真实内参：fx=256, fy=256, cx=112, cy=112
- L_camera 监督

**Step 4 — 动作预测**：
- 先预测 bbox（左图）→ 再预测关键帧姿态 → 最后预测动作 chunk
- delta pose = (0.1, 0.05, -0.2, ...) 表示向目标移动
- L_action 用 flow-matching 监督连续轨迹

**推理时**：只需 Step 1 + Step 4，辅助任务全部移除，零额外延迟。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|----------|---------|
| 推理延迟 | FoundationStereo 特征提取 ≈ 0ms（跳过迭代优化） | 相比完整 FoundationStereo 深度估计节省 70ms |
| 分辨率 | 224×224 | 小物体 (1-2cm) 仅占几个像素，成为精度瓶颈 |
| 训练成本 | 300k steps × 32×H800 × batch 384 | 大规模训练，但合成数据可无限生成 |
| 相机自由度 | 俯仰 20-30°，方位 -10~10°，半径 1.2-1.3m（小范围）| 大范围：俯仰 15-45°，半径 0.9-1.6m，方位 -150~150° |
| 部署硬件 | 单目立体相机（前置） | 比 π0.5 的四角/腕部方案简单得多 |
| 量化/内存 | InternLM-1.8B + 300M action expert | 总参数量约 2.1B，适合边缘部署 |
| Sim-to-Real | 零样本迁移（无 real fine-tuning） | 人形机器人微调后 Cleaning 73.3% vs 无预训练 26.6% |

**关键 trade-off**：224×224 分辨率是当前的主要瓶颈。在 1-2cm 小物体抓取任务中，所有基线成功率 0%，StereoVLA 达到 33%——但作者承认这受限于分辨率。更高分辨率 backbones 会提升语义 grounding，但计算开销是 critical trade-off。

## 5. 数据与评测 (Data & Eval)

### 数据集
- **规模**：500 万条合成立体轨迹
- **覆盖**：桌面 Franka 机器人 + 人形机器人
- **渲染**：光线追踪 + 广泛 domain randomization（光照、纹理、相机参数）
- **动力学**：quasi-static 假设 + 简单位置控制 + 摩擦随机化

### 评测任务（6 类，450 次真实试验）

| 任务类别 | 评估重点 | 试验设置 |
|---------|---------|---------|
| Common | 基本抓取/堆叠 | 日常物品（碗、立方体） |
| Distractor | 视觉 grounding | 目标 + 9 个相似干扰物 |
| Environment | 环境泛化 | 变化背景和光照 |
| Transparent Object | 透明物体处理 | 塑料等材质 |
| Small Object | 精细操作 | 1-2cm 小物体 |
| Bar-shaped Object | 长条物体抓取 | 0°/45°/90° 朝向 |

### 严格评测标准
- 每次试验仅允许单次执行（一次夹爪闭合 + 一次打开）
- 禁用 "gripper sticking" 启发式（OpenVLA/SpatialVLA/π0.5 中使用）
- 仅记录完全成功，无部分分数

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能力
- ✅ 零样本 sim-to-real 迁移（桌面 Franka）
- ✅ 对近半球形相机位姿变化鲁棒（大范围随机化下 53.9% vs π0.5 的 42.2%）
- ✅ 小物体抓取（33% 成功率，基线 0%）
- ✅ 透明物体处理（立体视觉不受表面反射影响）
- ✅ 人形机器人迁移（Cleaning 73.3%，Laundry 53.3%）

### 失败模式
- ❌ **分辨率瓶颈**：224×224 下 1-2cm 物体仅占几个像素，限制了精细操作上限
- ❌ **合成数据动力学 gap**：quasi-static 假设限制了动态任务（如抛接、快速抓取）
- ❌ **仅单目立体前置相机**：无法提供夹爪自中心视图（腕部相机的优势）
- ❌ **深度估计辅助任务的文本生成方式**：将连续深度转为文本可能损失精度

### 6.1 隐含假设 (Hidden Assumptions)

| 假设 | 说明 | 风险 |
|------|------|------|
| 几何 sim-to-real gap < RGB sim-to-real gap | 作者声称渲染无法准确模拟传感器深度噪声，因此立体视觉几何迁移更鲁棒 | 未直接验证——可能因任务而异 |
| 过滤代价体 V'c 包含足够的几何信息 | 跳过 FoundationStereo 的迭代优化以节省计算 | 迭代优化确实提升了深度精度，但 70ms 延迟不可接受 |
| 左视图语义足够 | 右视图语义信息被视为冗余 | 对于极端视角差异可能不成立 |
| 相机参数文本生成可行 | 将 8 个连续参数转为文本字符串用交叉熵监督 | 文本 token 的离散化可能限制精度 |
