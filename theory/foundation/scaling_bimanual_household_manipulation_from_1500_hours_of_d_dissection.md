### 1.2 关键机制 (Key Mechanism)

**为什么这样设计：**

1. **两阶段全参数微调**：不同于 LoRA/Adapter 只微调部分参数，本文对 VLM 骨干和动作专家全部 5B 参数进行微调（"火焰"标记），确保双臂操作的精细控制能力不被冻结参数限制。

2. **深度对齐交叉注意力**：动作专家的 18 个 Transformer block 分别交叉注意力到骨干的第 1-18 层隐藏状态（block i → layer i），而非全部汇聚到最后一层。这使动作预测能渐进式地利用从低级视觉特征到高级语义特征的层次化信息。

3. **动作前缀条件（Action Prefix Conditioning）**：推理时动态计算最近 R 轮的平均执行延迟 d，将前 d 个动作 token 锚定为已提交值（时间步固定为 t=1），仅对后续后缀序列做去噪。这解决了异步执行中的时序不一致问题。

4. **DAgger 数据按需分配**：不是均匀分配纠正数据，而是根据各子任务的当前成功率 si，将更多纠正预算分配给表现差的子任务（公式见 §2）。

⚡ **Eureka Moment**：离线演示数据和在线纠正数据是互补的——演示数据覆盖"成功路径"，纠正数据覆盖"策略访问的失败状态"；当演示数据收益递减时，纠正数据是唯一的持续增长引擎。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L_CFM(θ) = E[ || π_θ(a_t, o, s, l) - (a - ε) ||² ]    其中 a_t = (1-t)ε + t·a
```

**目标**：用条件流匹配（Conditional Flow Matching）训练一个统一的多任务策略，使其能从噪声动作中恢复出目标动作流。

**变量说明**：

| 符号 | 含义 |
|------|------|
| θ | 模型参数（5B） |
| a_t | t 时刻的噪声动作块 |
| a | 目标动作（专家演示或纠正） |
| ε | 高斯噪声 ~ N(0, I) |
| t | 时间步 ~ Beta(1.0, 1.5)（偏早期，更多噪声） |
| o | 视觉观察（头相机 + 双腕相机） |
| s | 89 维本体感知状态 |
| l | 语言指令 |
| π_θ | 策略网络，预测目标流 (a - ε) |

**直觉**：流匹配将动作生成建模为从纯噪声到目标动作的连续变换。模型学习的是这个变换的"速度场"——给定任意中间状态的噪声动作和上下文条件，预测应该朝哪个方向"流"向目标动作。Beta(1.0, 1.5) 分布确保训练时更多接触高噪声状态，增强鲁棒性。

> 符号与本文保持一致：s_t 为 89 维本体状态向量，a_t 为 25 维控制变量（22 关节位置 + 3 轮速）。

**DAgger 数据分配公式**：
```
w_i = w_min + (1 - N·w_min) · (1 - s_i + ε)^α / Σ_j (1 - s_j + ε)^α
```

| 符号 | 含义 |
|------|------|
| w_i | 子任务 i 分配的 DAgger 轨迹比例 |
| s_i | 当前策略在子任务 i 上的成功率（验证集） |
| α | 集中度参数（α=0 均匀分配，α↑ 更集中于弱项） |
| ε | 小常数，确保所有子任务都有非零分配 |
| w_min | 最小分配比例，防止完全忽略任何子任务 |

**直觉**：(1 - s_i) 是"需求信号"——成功率越低的子任务获得更多纠正数据。α 控制倾斜程度，类似"智能体应该花多少精力补弱项"的超参。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有一个简化的折叠任务场景，包含 3 个子任务：

| 子任务 | 当前成功率 s_i | 需求信号 (1-s_i) | α=1.0 权重 |
|--------|---------------|-----------------|------------|
| 折叠衣服 | 0.70 | 0.30 | 35% |
| 放入洗衣机 | 0.45 | 0.55 | 52% |
| 转移物体 | 0.80 | 0.20 | 13% |

假设 w_min = 0.05, N = 3, ε = 0.01, α = 1.0：

```
归一化因子 = (0.30+0.01) + (0.55+0.01) + (0.20+0.01) = 1.08

w_折叠 = 0.05 + (1 - 3×0.05) × 0.31/1.08 = 0.05 + 0.717×0.287 ≈ 0.256
w_洗衣机 = 0.05 + 0.717 × 0.56/1.08 ≈ 0.421
w_转移 = 0.05 + 0.717 × 0.21/1.08 ≈ 0.189
```

结果：成功率最低的"放入洗衣机"获得 42% 的纠正预算，而成功率最高的"转移物体"仅获得 19%。这确保有限的 DAgger 收集资源被用在刀刃上。

**数据混合的实际效果**（论文实验数据）：
- Expert 数据 10h → 120h：成功率持续提升（线性增长区）
- Expert 数据 120h → 160h：收益明显递减（平台期）
- Stage 1 (120h expert) 部署 → DAgger Round 1：58% → 72%
- DAgger Round 2：72% → 83%
- DAgger Round 3：83% → 93%

## 4. 工程视角 (Engineering View)

| 维度 | 数值/设计 | 工程含义 |
|------|----------|----------|
| 模型参数量 | 5B（Qwen3-VL-4B + 18-block Action Expert） | 需要 A100 80GB 单卡或双卡训练；推理可量化至 INT8 |
| 动作块长度 K | 未明确披露（典型 VLA 为 8-16 步） | 动作 chunk 越长，单步推理开销越大但执行更平滑 |
| 去噪步数 | 5 步 Euler 前向积分 | 低延迟关键：5 步 vs 50 步 DDPM 快了 10 倍，但可能牺牲动作平滑度 |
| 控制频率 | 30 Hz | 与大多数 VLA 一致；但双臂协调可能需要更高频率（>50Hz）处理快速接触 |
| 动作前缀延迟 d | 动态计算（最近 R 轮平均推理耗时） | 自适应异步执行，但 R 的选择影响延迟估计的稳定性 |
| 数据收集速度 | VR 遥操作 ≈ 1:1 实时；DAgger 自动收集 | DAgger 可扩展：部署更多机器人 = 更多失败 = 更多纠正数据 |
| 混合比例 | DAgger:Expert = 1:1（按轨迹数，非帧数） | 按轨迹混合防止长轨迹子任务主导训练；但可能浪费短轨迹的冗余帧 |

**部署约束**：
- 需要 3 个相机（1 头 + 2 腕），每路视频流 ~30fps，推理端带宽需求约 50-100 MB/s
- 89 维本体状态需要所有关节的 position/velocity/torque 反馈，对执行器通信总线有要求
- 移动基座的 3 轮独立驱动需要低层运动控制器与 VLA 动作输出的协调

### 6.1 隐含假设 (Hidden Assumptions)

1. **VR 遥操作质量一致**：假设不同操作员在不同时间段的演示质量是均匀的，但实际可能存在操作员疲劳、技能差异等系统偏差。
2. **SOP 覆盖充分**：假设预定义的 SOP 覆盖了所有合理的操作路径，但真实家务场景中存在大量 SOP 未定义的边缘情况。
3. **DAgger 纠正不会引入分布偏移**：假设纠正数据与演示数据来自兼容的分布，但纠正操作可能包含与演示风格不同的动作模式（更急促、更保守等）。
4. **30 Hz 控制频率足够**：假设 30 Hz 对双臂协调足够，但接触丰富操作（如挤压衣物）可能需要更高频率的力控回路。
5. **成功率作为子任务难度的充分指标**：DAgger 分配公式假设 s_i 能充分反映子任务的"需求程度"，但忽略了子任务的"可改进空间"——有些子任务可能因为架构限制而非数据不足导致低成功率。
