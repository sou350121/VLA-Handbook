### 1.2 关键机制 (Key Mechanism)

Embodied-R1.5 的核心设计围绕三个互补的能力维度，它们构成从感知到决策到执行的递进推理链：

1. **具身认知与空间推理**（4 个子维度）
   - 空间关系理解：物体相对方位、支撑关系、包含关系、遮挡
   - 度量空间推理：距离估计、物体大小判断、空间容纳性
   - 3D 场景感知：单目深度估计、跨视角几何推理、视频帧间空间一致性
   - 物体与场景认知：机器人视角的场景理解，区分目标与障碍物

2. **具身规划与修正**（5 个子维度）
   - 长程任务分解：将语言指令分解为结构化子任务序列
   - 下一步规划：执行中根据当前进度和观测生成原子动作指令
   - 过程检测：判断子任务是否完成
   - 错误定位：识别失败的具体原因（执行/规划视角）
   - 错误修正：生成具体的纠正建议（重规划或回退重试）

3. **具身定位与指向**（4 种类型）
   - REG（指代表达 grounding）：自然语言 → 物体坐标
   - RRG（区域指代 grounding）：如"能放盘子的空区域"
   - OFG（物体功能 grounding）：定位物体的功能部位（壶嘴、把手、按钮）
   - VTG（视觉轨迹生成）：生成操作轨迹的有序点序列，支持对象流和末端执行器流

⚡ **Eureka Moment**：当 VLM 内部化了足够的具身推理能力后，下游动作头只需要学习从"已理解的意图"到连续动作的简单映射——这意味着**大规模动作预训练不再是必需的，更强的具身骨干可以大幅降低下游动作学习的数据需求**。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L_total = L_SFT + α · E[ -log π_θ(a|s) · A(s,a) ] + β · KL(π_θ || π_ref)
```

其中：
- **L_SFT**：标准因果语言建模损失，构建多任务基础能力
- **α · E[...] **：RL 阶段的 GRPO 策略梯度，A(s,a) 为优势函数
- **β · KL(...)**：KL 正则化（β=0.01），防止策略偏离 SFT 分布

**关键创新在优势函数的归一化方式**：

```
A_i = (R_i - μ_group) / (σ_batch + ε)
```

与传统 GRPO 使用组内标准差不同，这里用**全局批次标准差** σ_batch 归一化，消除不同任务间的奖励尺度差异。

**变量说明**：

| 符号 | 含义 | 值/范围 |
|------|------|---------|
| R_i | 第 i 个 rollouts 的奖励 | [0,1] |
| μ_group | 组内平均奖励 | 实数 |
| σ_batch | 全局批次标准差 | 正实数 |
| β | KL 惩罚系数 | 0.01 |
| α | RL 损失权重 | 隐含为 1 |
| n | 并行 rollouts 数 | 8 |

**直觉**：组内均值保留"哪个 rollout 更好"的相对排序，批次级标准差统一不同任务的梯度量级——不需要任务标签或历史状态，就能解决多任务奖励尺度不一致的问题。

**分段线性奖励衰减函数**（核心奖励设计）：

```
φ(d; τ_p, τ_z) = clip((τ_z - d) / (τ_z - τ_p), 0, 1)
```

当距离 d < τ_p 时给满分，d ≥ τ_z 时给零分，中间线性衰减。这避免了二元奖励的稀疏性问题，为 RL 提供密集梯度信号。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的点定位任务：模型需要指出"红色杯子把手"的坐标。

**场景设定**：
- 图像分辨率 224×224，坐标归一化到 [0, 1000]
- Ground truth 把手坐标：(450, 320)
- 模型输出 3 个候选点：(460, 330), (445, 315), (470, 340)

**Step 1: 计算最近邻距离**

```
d_nn = mean([dist((460,330),(450,320)), dist((445,315),(450,320)), dist((470,340),(450,320))])
     = mean([14.1, 7.1, 28.3]) / (224/1000)  // 归一化到像素空间
     ≈ 16.5 (归一化单位)
```

**Step 2: 应用分段线性衰减**

```
R = φ(16.5; 40, 150) = clip((150 - 16.5) / (150 - 40), 0, 1)
  = clip(133.5 / 110, 0, 1) = clip(1.21, 0, 1) = 1.0
```

→ 满分奖励，因为距离远小于阈值 τ_p=40。

**Step 3: RL 优势计算**

假设同批次 8 个 rollouts 的奖励为 [1.0, 0.85, 0.6, 1.0, 0.3, 0.92, 0.75, 0.45]：

```
μ_group = mean([1.0, 0.85, 0.6, 1.0, 0.3, 0.92, 0.75, 0.45]) = 0.734
σ_batch = 0.245 (整个混合批次的标准差，包含其他任务样本)

A_i = (1.0 - 0.734) / (0.245 + ε) ≈ 1.09
```

→ 正优势，策略被强化。

**Step 4: 自适应推理长度**

在 RL 优化过程中，模型发现对于简单定位任务，不输出推理链直接给出坐标也能获得满分奖励，因此逐渐学会"少想多做"——推理 token 数从 SFT 阶段的平均 ~200 tokens 减少到 RFT 后的 ~30 tokens。

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/约束 | 含义 |
|----------|-----------|------|
| 模型参数量 | 8B | Qwen3-VL-8B-Instruct 基座，适合单台 8×A100 训练 |
| SFT 学习率 | 2×10⁻⁶ | 较低，cosine decay + 10% warmup |
| RFT 学习率 | 3×10⁻⁶ | 略高，AdamW + gradient clipping 1.0 |
| 批次大小 | 512 (全局) | 需要多卡梯度累积 |
| 上下文长度 | 8192 tokens | 足够容纳单轮推理+规划+定位 |
| 视觉编码器 | 联合训练（不冻结） | 具身视觉分布与通用预训练数据差异大 |
| RFT rollouts | n=8 | 每个 prompt 采样 8 个并行输出 |
| KL 惩罚 | β=0.01 (KL-in-reward) | K1 无偏估计直接作为奖励惩罚项 |
| 裁剪比率 | 0.2/0.28 | 实际裁剪率极低（具身推理响应较短） |
| 训练轮数 | SFT 1 epoch + RFT 2 epochs | 全数据系统 15B tokens |
| 推理延迟（EFM） | 中等 | 自回归文本生成，定位任务 ~30 tokens 输出 |
| 推理延迟（VLA） | 中高 | 文本推理 + DiT 动作生成（action chunking） |
| 部署方式 | 单模型异步调用 | PGC 框架中 Planner/Grounder/Corrector 共用同一推理服务 |

**关键工程洞察**：
- **坐标作为纯文本输出**（归一化到 [0,1000]）而非特殊 token，预测更稳定且词表开销可忽略
- **自适应推理长度**：RL 阶段模型自发学会简单任务少推理、复杂任务多推理——这是奖励驱动的计算资源自适应分配
- **语义泛化假设**：轨迹生成不依赖高保真仿真，低精度仿真数据也能提供有效的运动语义监督（拓扑结构和方向语义）

### 6.1 隐含假设 (Hidden Assumptions)

1. **"具身推理可以替代动作数据"** — 核心假设，论文通过在 4 个仿真基准上的实验提供了初步证据，但真实世界中的泛化性仍需更多验证
2. **"单一模型可以同时服务 Planner/Grounder/Corrector 三个角色"** — 假设 8B 模型的容量足以覆盖三种不同抽象层次的能力，无需模型间通信开销
3. **"低精度仿真的轨迹数据足够"** — "语义泛化"假设，VTG 关注拓扑结构和方向语义而非渲染保真度，这在桌面操作场景成立，但对精细操作可能不够
4. **"分段线性奖励衰减在所有任务上都有效"** — 统一的 φ 函数应用于 IoU、点距离、轨迹 RMSE 等异构奖励，但不同任务的阈值 (τ_p, τ_z) 需要手动调优
5. **"PGC 框架的极简 FIFO 内存足够"** — 作者承认更复杂的记忆策略可能增强设计，但未做对比实验
