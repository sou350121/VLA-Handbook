💡 **X-Ray 开场**
这篇论文解决什么问题？现有 V2V 模型只能单视角运行，但机器人学习通常用多相机同步拍摄（如 DROID 有 3-5 个视角）。直接对每个视角独立跑单视角模型会导致跨视角外观不一致，破坏 3D 连贯性。

发现了什么？VideoWeaver 是首个多视角 V2V flow 模型，核心洞见是：与其在 2D 图像空间强制一致性，不如用一个共享的 4D 点云（来自 Pi3）统一所有视角的潜空间表示。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练/推理差异 |
|------|------|------|-----------|---------------|
| 基础 V2V model | 单视角深度 + 草图序列 + 文本 prompt | 单视角 RGB 视频 (81 帧) | 30 步 Euler 积分 | 训练用均匀时间步采样；推理用线性 flow scheduler |
| MoE fusion | 深度潜特征 fs, 草图潜特征 fd | 融合控制信号 $c^\tau$ | 每 patch 每时间步 | 训练时随机丢弃单一模态增强鲁棒性 |
| 4D 点云编码器 | Pi3 输出的 (K, T, p) | 注入潜空间的坐标特征 | 每 8 帧采样一次 | Pi3 固定权重，只训练轻量 MLP |
| Factorized 4D Attention | 3 视角潜 tokens | 跨视角一致的潜表示 | 每 DiT block 内 | 先 intra-view 再 cross-view 注意力 |
| 异质时间步训练 | 部分视角 $\tau=1$ (干净), 部分 $\tau\in(0,1)$ (噪声) | 条件分布 p(x_new | x_given) | 训练时随机采样路径 | 推理时支持自回归生成>3 视角 |

### 1.2 关键机制 (Key Mechanism)

**为什么用 4D 点云而不是 camera ray embedding？**
- Camera ray 只给粗略几何线索，当视角相距远、重叠少时（如人形机器人的手部相机 vs 头部相机），cross-view attention 容易被小物体或部分可见物体混淆
- Pi3 直接回归每像素 3D 点，提供 dense、pixel-aligned 的对应关系，且对视角排列不变（permutation-invariant）

**为什么用 MoE 而不是简单相加/拼接？**
- 深度在薄物体或小物体上可能无信息，草图在边缘重叠或前后景相似时可能模糊
- MoE 让模型在每个时空位置自适应选择依赖哪个模态，而不是强制均匀对待

**为什么用异质时间步训练？**
- 原生模型只学联合分布 p(x1,x2,x3 | c,y)，但自回归生成新视角需要条件分布 p(x4 | x1,x2,x3, c4, y)
- 训练时随机冻结部分视角（设 $\tau=1$）作为条件信号，让模型练习条件生成任务

⚡ **Eureka Moment**：与其在 2D 图像空间强制跨视角一致性，不如用一个共享的 4D 点云统一所有视角的潜空间表示——一致性来自底层 3D 世界，而不是 2D 像素对齐。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
p_θ({x_k}_k=1^K | {s_k, d_k}_k=1^K, y) 用 4D 点云统一潜空间 + 异质时间步学联合 + 条件分布
```

**目标函数**（Flow Matching）：

```
L(θ) = E_{x,y,τ} [ || v_θ(x^τ, y, τ) - (x - x⁰) ||² ]
```

其中：
- `x^τ = (1-τ)·x⁰ + τ·x¹` 是噪声 x⁰ 到数据 x¹ 的线性插值
- `v_θ` 是可学习的速度场，由 DiT 建模
- 采样时积分 ODE: `dx^τ/dτ = v_θ(x^τ, y, τ)` 从 τ=0 到 τ=1

**MoE 融合公式**：

```
c^τ = α^τ · E_s(f_s) + (1 - α^τ) · E_d(f_d)
```

其中：
- `α^τ` 是 gating network 预测的 patch-wise 混合权重
- `E_s, E_d` 是 sketch/depth expert（轻量卷积网络）
- `f_s, f_d` 是编码后的潜特征

**4D 点云注入**：

```
F_Pi3({x_k,t}) → (K̂_k, T̂_k,t, p̂_k,t)
```

- `K̂_k`: 相机内参
- `T̂_k ∈ SE(3)`: 相机位姿
- `p̂_k,t`: 点云（每像素一个 3D 点）

> 符号与本文/相关文档保持一致：下标 $k$ 表示视角索引 $(1..K)$，$t$ 表示时间步，$\tau$ 表示 diffusion/flow 时间步。

**直觉解释**：
- Flow model 比 diffusion 更稳定，训练时用 rectified flow 目标直接对齐速度场与噪声到数据的位移方向
- MoE 让模型在每个时空 patch 自适应选择"相信深度还是草图"，而不是强制融合
- 4D 点云作为全局坐标系，让所有视角的潜特征在同一个几何框架下对话

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有一个桌面抓取场景，用 3 个相机拍摄（左、右、手部）：

**输入**：
- 每个视角：81 帧 $480\times640$ 深度图 + 草图序列
- Text prompt: "a robot arm picking up a red cube on a wooden table"

**Step 1: Pi3 4D 重建**
- Pi3 处理所有 $3\times81=243$ 帧，输出：
  - 3 个相机内参 K̂_k（焦距、主点）
  - 243 个相机位姿 $\hat{T}_{k,t} \in \mathrm{SE}(3)$
  - 243 个点云 $\hat{p}_{k,t}$，每个是 $480\times640\times3$ 的 3D 点阵

**Step 2: 点云下采样与编码**
- 空间下采样：每 $8 \times 8$ patch 保留离相机最近的点 → $60 \times 80$ 点阵  
- 时间下采样：每 $8$ 帧保留 $1$ 帧 → $11$ 帧  
- 最终点云网格：$11 \times 60 \times 80 \times 3$ ($t \times h \times w \times xyz$)  
- 通过轻量 MLP 编码为潜特征，注入 DiT

**Step 3: MoE 融合**
- 对每个时空 patch，gating network 输出 $\alpha^\tau \in [0,1]$  
- 例如：在物体边缘 patch，$\alpha^\tau = 0.8$（更信草图）；在平坦深度区域，$\alpha^\tau = 0.2$（更信深度）  

**Step 4: Flow 采样**
- 从 $x^0 \sim \mathcal{N}(0,I)$ 开始  
- 用 Euler solver 积分 30 步：`x^{τ+Δτ} = x^τ + Δτ · v_θ(x^τ, y, c^τ, τ)`
- 每步 DiT 内部：先 intra-view 注意力（每视角内 $81 \times 60 \times 80$ tokens），再 cross-view 注意力（$3$ 视角间对应位置 tokens）  

**Step 5: 输出**
- $3$ 个视角的 RGB 视频，每视角 $81$ 帧 $480 \times 640 \times 3$  
- 跨视角颜色一致（因为共享 4D 坐标）
- 深度/草图对齐误差：Edge-F1 $\approx 0.38$, Depth-siRMSE $\approx 0.35$（表 $1$）  

**如果要做第 4 视角（自回归）**：
- 固定 View1-3 的 $\tau = 1$（干净），对 View4 从 $\tau = 0$ 开始去噪  
- 条件分布：`p(x_4 | x_1,x_2,x_3, c_4, y)`
- Met3R 跨视角一致性分数提升 10%（表 2）

## 4. 工程视角 (Engineering View)

| 指标 | 数值 | 含义 |
|------|------|------|
| 模型参数量 | 11B (DiT 基础) + 轻量 MoE/点云编码器 | 需要 $8 \times$Ascend 910B (64GB) 训练约 $1$ 周   |
| 推理时间 | ~10 分钟 / 3 视角 81 帧 | 不适合实时应用；适合离线数据增强 |
| 帧数限制 | 固定 81 帧 | 无法自回归延长时间序列（局限） |
| 视角数 | 原生 3 视角；>3 需自回归 | 自回归会增加累积误差风险 |
| 分辨率 | $480 \times 640$ (VAE 潜空间 $8 \times$ 下采样)   | 时间下采样 $8 \times$ 可能导致轻微模糊   |
| 控制模态 | 深度 + 草图（可单用） | 推理时可丢弃单一模态，指标影响<5% |

**部署约束**：
1. **需要 Pi3 基础设施**：Pi3 是独立的空间基础模型，需预先部署或调用 API
2. **显存需求**：$3$ 视角联合注意力需要约 $40$GB 显存（$81 \times 60 \times 80 \times 3$ tokens）  
3. **延迟敏感场景不适用**：10 分钟生成时间只适合离线数据增强，不适合在线策略执行

**Trade-off 分析**：
- **时间下采样 vs 长序列**：$8 \times$ 时间下采样让训练更长 clip 成为可能，但牺牲了高频运动细节  
- **联合生成 vs 自回归**：3 视角联合保证一致性；>3 视角自回归会引入累积误差，但 Met3R 显示条件训练后一致性仍好

### 6.3 隐含假设 (Hidden Assumptions)

1. **相机标定可用或可从视频估计**：Pi3 需要多视角图像来重建 4D 点云，假设视角间有足够重叠或运动视差
2. **深度/草图与动作轨迹对齐**：假设控制信号（深度/草图）准确反映机器人动作，否则生成视频会保持错误轨迹
3. **文本 prompt 足够描述目标风格**：如果 prompt 模糊（如"make it look nice"），模型可能无法准确捕捉目标域
4. **3 视角联合分布足够代表场景**：>3 视角自回归时，累积误差可能随视角数增加而放大（论文未测试>5 视角）
