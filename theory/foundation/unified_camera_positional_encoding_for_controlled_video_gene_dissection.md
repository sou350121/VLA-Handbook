## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练/推理差异 |
|------|------|------|-----------|---------------|
| Relative Ray Encoding | 每像素 ray (o, d) + 相机向下方向 | 局部 ray-to-world 变换矩阵 T_tw^r | 每 token 独立计算 | 训练/推理一致 |
| Absolute Orientation Encoding | 世界空间 ray 方向 d_t | Lat-Up map (纬度角 + 上方向向量) | 每 token | 可选输入 |
| Spatial Attention Adapter | 输入 tokens + UCPE 编码 | 相机感知 tokens | 每 DiT 块并行分支 | 零初始化保证预训练不变 |
| UCPE 混合编码 | D_t^Ray (光线变换) + D_t^RoPE (图像位置) | 块对角算子 D_t^UCPE | 每 attention 层 | 与 RoPE 融合 |

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **从相机级到光线级的范式转变**: 现有相对编码（如 PRoPE、GTA）假设同一视图内所有 token 共享单一投影函数——这在针孔相机下成立，但无法建模镜头畸变导致的空间变化投影行为。UCPE 将每个 token 关联到其特定的 viewing ray，使 attention 机制在光线空间而非相机帧内推理。

2. **局部射线坐标系的构建**: 对每个 token t，以相机中心为原点，取 ray 方向 d_t 为局部 z 轴，基于相机向下方向构建正交基 [x_t, y_t, z_t]。这保证了编码的几何可解释性。

3. **绝对方向的必要性**: 相对编码无法确定第一帧的全局朝向（pitch/roll 模糊）。Lat-Up map 通过编码每条光线的纬度角和上方向向量，提供重力对齐的全局参考。

4. **轻量级适配器设计**: 直接替换预训练 DiT 的位置编码会破坏先验。UCPE 采用并行分支（类似 LoRA），仅增加 35.5M 参数（0.5%），零初始化保证训练初期模型行为不变。

⚡ **Eureka Moment**: 这篇论文最核心的洞见是——**将相机编码从"相机到相机"的变换重新表述为"光线到光线"的变换**。每个 token 不再共享相机的位置编码，而是拥有自己独立的几何变换算子，使 Transformer 能在光线空间直接推理，天然兼容任意镜头模型。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
UCPE = RelativeRay(T_trw) ⊕ AbsoluteOrientation(Lat, Up) → 光线空间 attention
```

**目标**: 将完整相机几何（6-DoF 位姿、内参、畸变）编码进 Transformer attention，使模型能在光线空间进行几何一致的推理。

**核心公式**:

1. **光线到世界变换矩阵** (Eq. 7):
```
T_trw = [R_trw  t_trw]
        [0^T    1   ]  ∈ SE(3)

其中 R_trw = [x_t, y_t, z_t],  z_t = d_t (光线方向)
             x_t = y_cam × z_t
             y_t = z_t × x_t
```

2. **混合编码算子** (Eq. 10):
```
D_t^UCPE = blkdiag(D_t^Ray, D_t^RoPE) ∈ R^(d×d)

D_t^Ray = I_(d/8) ⊗ T_trw  (光线变换，占一半维度)
D_t^RoPE                    (图像位置，占一半维度)
```

3. **UCPE 注入的 attention** (遵循 GTA 格式，Eq. 4):
```
O = D^UCPE ⊙ Attn((D^UCPE)^T ⊙ Q, (D^UCPE)^(-1) ⊙ K, (D^UCPE)^(-1) ⊙ V)
```

4. **纬度角编码** (Eq. 8):
```
Lat_t = arctan2(-d_t,y, sqrt(d_t,x^2 + d_t,z^2))

正值表示向上看的光线
```

**变量说明**:
| 符号 | 含义 | 来源 |
|------|------|------|
| o_t, d_t | token t 对应光线的原点/方向 | 相机模型 ray mapping |
| T_trw | ray-to-world 变换矩阵 | Eq. 7 |
| D_t^UCPE | UCPE 混合编码算子 | Eq. 10 |
| Lat_t | 纬度角 (绝对俯仰) | Eq. 8 |
| Up_t | 上方向向量 (绝对翻滚) | Eq. 9 |
| ⊙ | token-wise 矩阵 - 向量乘法 | 逐 token 应用变换 |

**直觉**: 传统方法对整个图像应用同一个相机编码，UCPE 对每个像素应用其对应光线的独立编码——这就像从"给整个房间贴一个标签"变成"给房间里每个物体贴独立标签"，精度自然更高。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有一个 480×832 分辨率的视频帧，使用鱼眼镜头（xFoV=150°, ξ=1.5）。

**步骤 1: 计算单像素的光线**
- 像素坐标 (u,v) = (416, 240)（图像中心）
- 通过 UCM 反投影得到相机坐标系光线 d_cam = [0, 0, 1]^T（正前方）
- 相机位姿 R = I, t = [0, 0, 0]^T（原点）
- 世界空间光线 d = R·d_cam = [0, 0, 1]^T

**步骤 2: 构建局部射线坐标系**
- z_t = d = [0, 0, 1]^T
- 相机向下方向 y_cam = [0, 1, 0]^T（图像 y 轴向下）
- x_t = y_cam × z_t = [1, 0, 0]^T
- y_t = z_t × x_t = [0, 1, 0]^T
- R_trw = [[1,0,0], [0,1,0], [0,0,1]] = I（此例中巧合为单位阵）

**步骤 3: 应用 UCPE 到 attention**
- Query 向量 Q_t ∈ R^d（假设 d=512）
- D_t^Ray = I_(64) ⊗ T_trw = I_512（此例中）
- D_t^RoPE 根据图像位置 (240, 416) 计算标准 RoPE
- D_t^UCPE = blkdiag(I_256, RoPE_256)
- 变换后 Query: Q'_t = (D_t^UCPE)^T ⊙ Q_t

**关键观察**: 对于图像边缘的像素（如鱼眼畸变区域），d_t 方向显著偏离针孔假设，R_trw 不再是单位阵，UCPE 会应用非平凡的几何变换——这正是它优于固定针孔编码的地方。

## 4. 工程视角 (Engineering View)

| 指标 | UCPE | ReCamMaster | Wan CameraCtrl |
|------|------|-------------|----------------|
| 可训练参数 | 35.5M (0.5%) | 354M (4.8%) | 1.5B (20.5%) |
| 训练 GPU 时 | ~8 A800 × 1 天 | 类似 | 类似 |
| 推理开销 | 几乎为零（并行分支） | 中等 | 中等 |
| 支持的相机类型 | 任意中心相机（针孔/广角/鱼眼/全景） | 需扩展 | 仅针孔 |
| 绝对方向控制 | 是（Lat-Up map） | 需扩展 | 否 |

**部署约束**:
- 需要预训练 Wan DiT 或类似 Diffusion Transformer 架构
- 相机参数需在推理时提供（位姿 + 内参 + 畸变系数）
- Lat-Up map 为可选输入，若不需要绝对方向控制可省略

**Trade-off**:
- 压缩比 1/8（192×1 head）在效率与表达能力间最佳平衡（Table 1 ablation）
- Pre-Attn / Post-Attn 插入位置性能显著下降——并行架构是关键
- 训练需相机标定数据，但推理时可泛化到未见过的相机配置（RealEstate10K 零样本验证）

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 6.1 能做什么
- ✅ 统一编码任意中心相机模型（针孔/广角/鱼眼/全景）
- ✅ 同时控制镜头类型（FoV + 畸变）、相机位姿、绝对方向（pitch/roll）
- ✅ 零样本泛化到未见过的相机配置和运动轨迹
- ✅ 以 0.5% 参数开销实现 SOTA 相机可控性

### 6.2 不能做什么
- ❌ 非中心相机（如折反射系统）需扩展公式（论文假设 central camera）
- ❌ 变焦镜头（intrinsics 随时间变化）未验证
- ❌ 极度激进的相机运动（超出训练数据分布）可能失效
- ❌ 当前仅在视频生成任务验证，VLA/3D 感知任务需迁移验证

### 6.3 隐含假设 (Hidden Assumptions)
- **假设 1**: 所有相机是中心相机（所有光线交于一点）——对大多数消费级相机成立，但对折反射/光场相机不成立
- **假设 2**: 重力方向已知且一致——依赖 360° 相机的 IMU 稳定，真实世界手持拍摄可能不满足
- **假设 3**: 相机标定参数准确——推理时若内参估计有误，控制精度下降
- **假设 4**: 训练数据覆盖足够多样性——PanShot 虽大但仍是合成数据，真实世界长尾分布可能未覆盖
