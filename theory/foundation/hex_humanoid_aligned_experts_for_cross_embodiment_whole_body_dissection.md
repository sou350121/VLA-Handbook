## 1. 核心架构/方法总览 (Overview / Architecture)

HEX 采用**分层架构**：高层 VLA 策略 + 低层 RL 全身控制器。

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练方式 |
|------|------|------|-----------|----------|
| **VLM（视觉-语言）** | 语言指令 L、当前视觉 V_t、历史查询 Q_t | 视觉-语言特征 L'_t, V'_t, Q'_t | 每步推理；$\tau_v=2$ 历史窗口 | 冻结 Qwen3-VL-2B 微调接口 |
| **UPP（本体预测器）** | 身体部位潜变量 P_t、VLM 特征、历史缓存 | 未来 $\tau_p=50$ 步本体潜变量 | 每步预测；与 VLM 并行 | 4-layer Transformer, hidden=768 |
| **Action Expert（动作专家）** | VLM 特征 + UPP 预测特征 + 噪声动作 | 100 步动作 chunk（手臂+手部） | 16 层 DiT-B 去噪迭代 | Flow matching, hidden=1024 |
| **低层 RL 控制器** | 高层动作指令 + 本体状态 | 全身关节力矩（高频） | 站立/行走（DeepMimic）/半跪（AMP） | 技能专用 RL 策略 |

### 1.2 关键机制 (Key Mechanism)

HEX 的三个核心设计围绕一个统一理念：**全身控制需要同时"回顾过去"和"预测未来"**。

1. **回顾（Review）— 轻量历史缓存**：VLM 每步只编码当前帧，但生成一个紧凑查询特征存入固定长度缓存（$\tau_v=2$）。避免重复编码历史图像，同时保留短时视觉上下文。

2. **预测（Forecast）— MoE 本体预测器**：将异构本体状态映射到 9 个规范身体部位槽位（左右臂/手/腿、头、腰、others），用带形态感知 MoE 的 Transformer 预测未来 50 步本体状态演化。

3. **融合（Fuse）— 残差门控自适应融合**：Action Expert 用双交叉注意力分别接入 VLM 语义特征和 UPP 预测特征，再通过 sigmoid 门控自适应调节状态分支的贡献度。

⚡ **Eureka Moment**：与其让 VLA 直接从视觉-语言映射到动作，不如先预测未来身体状态会如何演化——这个"预测状态"提供了比当前观察更丰富的全身协调线索，让动作生成同时兼顾语义意图和动力学可行性。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L = L_action + α·L_state
  = ||D_a(Z_t^a) - Vel_{t:t+τa}||²₂ + α·||D_s(P'_{t+1:t+τp}) - s_{t+1:t+τp}||²₂
```

**目标**：联合优化动作生成（flow matching）和状态预测（MSE），让 UPP 学会预测未来身体状态，让 Action Expert 学会在双条件（语义+动力学）下生成动作。

**公式拆解**：

| 符号 | 含义 |
|------|------|
| $A_{t:t+\tau_a}$ | 干净的未来动作轨迹（ground truth） |
| N | 同形状高斯噪声 |
| $\tilde{A} = (1-\lambda)N + \lambda A$ | 噪声动作轨迹，$\lambda \sim U(0,1)$ |
| Vel = A - N | 速度目标（flow matching 核心） |
| $Z_t^a$ | Action Expert 最终隐藏表示 |
| $D_a(\cdot)$ | 动作解码器 → 速度预测 |
| $P'_{t+1:t+\tau_p}$ | UPP 预测的未来本体潜变量 |
| $D_s(\cdot)$ | 状态解码器 → 未来本体状态 |
| $\alpha$ | 状态损失权重（论文未给出具体值） |

**直觉**：flow matching 学习从噪声到干净动作的"速度场"，状态预测学习身体各部位如何在未来 $\tau_p$ 步内协同演化。两者共享身体部位对齐的潜表示，因此天然支持跨具身迁移。

> 符号与本文保持一致：$L$ 为总损失，$L_a$ 为动作生成损失，$L_s$ 为本体预测损失。$\alpha$ 的具体数值论文未明确给出，标注为 TODO。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：机器人需要"倒酒到指定杯子"。

**时刻 t=0**：
- 视觉：看到 3 个杯子，人类指向中间杯子
- 本体：手臂在起始位，关节角 θ_arm = [30°, 45°, ...]
- 语言指令 L = "把酒倒进中间的杯子"

**VLM 编码**：
- $f_{\text{vlm}}(L, V_0, Q_0) \to L'_0, V'_0, Q'_0$
- $Q'_0$ 存入缓存 $M_0^{\text{vl}} = \{Q'_0\}$（$\tau_v=2$，第一步只有 1 个）

**UPP 预测未来 50 步**：
- 当前本体 $P_0 \to$ 部位槽位编码 $\to$ Transformer + MoE
- 输出 P'_1:50：预测手臂将先向酒瓶移动（步 1-15），然后倾斜瓶身（步 16-35），最后回到中立位（步 36-50）
- L_s = ||D_s(P'_1:50) - s_1:50^gt||²₂ = 0.023（训练时）

**Action Expert 去噪生成动作**：
- 噪声动作 X_T（T=16 层 DiT 的初始噪声）
- 每层去噪：$H_{\text{vl}} = \text{Attn}_{\text{vl}}(X_{\text{norm}}, [L', V', M^{\text{vl}}])$，$H_p = \text{Attn}_p(X_{\text{norm}}, P_0:50)$
- 门控：$g = \sigma(W_g \cdot [H_{\text{vl}}; H_p; X_{\text{norm}}])$
  - 假设 $g \approx [0.3, 0.8, 0.5, \dots]$：在"倾斜瓶身"阶段状态分支权重高（需要精确动力学控制）
- 融合：$F = H_{\text{vl}} + g \odot H_p$
- 最终输出：$D_a(Z^a) = \text{Vel}_{\text{pred}}$，与 $\text{Vel}_{\text{gt}} = A_{\text{gt}} - N$ 计算 $L_a = 0.015$

**总损失**：$L = 0.015 + \alpha \cdot 0.023$（假设 $\alpha=1.0 \to L \approx 0.038$）

**推理时**：UPP 预测的状态引导动作生成，确保手臂运动与身体平衡一致——不会在倒酒时重心偏移导致摔倒。

## 4. 工程视角 (Engineering View)

| 维度 | HEX | 工程含义 |
|------|-----|----------|
| 总参数量 | 2.4B | 比 $\pi_{0.5}$ (3.3B) 和 GR00T N1.5 (3B) 更小 |
| 推理延迟 | 73.34 ms (RTX 4090) | 比 $\pi_{0.5}$ 快，适合实时全身控制 |
| VLM 编码频率 | 每步仅编码当前帧 | 历史缓存 $\tau_v=2$ 避免重复编码，显著降低算力 |
| UPP 预测步数 | $\tau_p=50$ 步 | 提供约 1 秒动力学前瞻（假设 50Hz 控制频率） |
| 动作 chunk | 100 步 | 与 GR00T/$\pi_{0.5}$ 一致，平衡响应延迟和平滑度 |
| MoE 专家数 | 16 routed + 2 shared, top-1 | token 级路由，每步激活 2 个专家（1 routed + 1 shared） |
| 预训练算力 | ~1K A100 GPU hours | $200\text{k}$ steps $\times$ batch $16$，中等规模 |
| 微调算力 | 每任务 20k steps | 单任务微调成本可控 |
| 低层控制频率 | 高频（未明确，通常 500Hz+） | 高层 $50\text{Hz}$ 输出 $\to$ 低层插值/追踪 |

**关键 trade-off**：
- UPP 的 50 步预测增加了推理开销，但提供了全身协调所必需的动力学前瞻——在快反应任务中，这个开销是值得的
- MoE 的 top-1 路由减少了计算量（只激活 1 个 routed expert），但可能限制了复杂场景下的专家组合能力
- 历史缓存仅存 $Q'_t$ 特征（非原始图像），内存占用极小，但 $\tau_v=2$ 的窗口可能不足以处理长时依赖

### 6.1 隐含假设 (Hidden Assumptions)

1. **规范身体部位槽位足以覆盖所有具身变体**：9 个槽位（左右臂/手/腿 + 头 + 腰 + others）是一个合理的抽象，但对于非常规构型（如多臂、无腿）可能不够。

2. **50 步本体预测足够指导动作生成**：$\tau_p=50$ 的预测窗口假设未来 $1$ 秒内的动力学演化足以支撑当前决策。在极端快反应场景（如突然被推搡），可能需要更短的预测窗口 $+$ 更高的控制频率。

3. **遥操作数据质量足够高**：整个框架依赖高质量的遥操作轨迹。如果遥操作本身存在噪声或不一致，UPP 学到的预测模型可能偏差较大。论文未讨论数据质量对 UPP 预测精度的影响。

4. **视觉-语言和本体预测的残差门控融合是最优策略**：$F = H_{vl} + g \odot H_p$ 的设计假设本体预测是对语义特征的"补充"而非"替代"。在某些纯动力学任务中（如保持平衡），可能需要更强的状态分支主导。
