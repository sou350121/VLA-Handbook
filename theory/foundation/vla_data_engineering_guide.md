## 0. VLA 数据的独特挑战

VLA 数据不是"图文对"也不是"视频标注"——它是**多模态时序信号的精密同步采集**：

```
时间轴 →
  RGB 相机 1:  ████████████████  30Hz
  RGB 相机 2:  ████████████████  30Hz
  深度相机:    ████████████████  30Hz
  关节角:     ████████████████████████████████  100Hz
  末端位姿:   ████████████████████████████████  100Hz
  夹爪状态:   ████████████████████████████████  100Hz
  语言指令:   █                               1x（任务开始时）

  → 所有信号必须在 <10ms 内对齐，否则动作标签对不上图像
```

**和 NLP/CV 数据的本质区别**：
- NLP：文本是离散的，没有时间同步问题
- CV：图像是静态的，没有动作标签
- VLA：**连续、多模态、时序对齐、物理耦合**——任何一个环节出错，整条轨迹都废了

## 0.1 第一性原理：为什么数据是当前 VLA 的真正瓶颈

> 🧠 **本节为作者推理框架**，不是论文结论。但推理的出发点（π₀/OpenVLA/GR00T 架构趋同）和落脚点（数据瓶颈）是领域共识。

> **问**：π₀ / OpenVLA / GR00T 用的都是 Transformer + Flow Matching 的类似架构。差距主要来自哪里？
> **答**：🧠 作者判断——**数据**。模型架构的边际收益已接近饱和，数据的边际收益还远没到。

### 信息论视角：VLA 学什么（🧠 作者归纳框架）

VLA 要学的是一个**条件分布** `p(action | vision, language, state)`。这个分布的**熵上限**由三件事决定（🧠 以下是作者提出的思考框架，非某篇论文的定理）：

1. **覆盖度**（support）：轨迹分布是否覆盖了部署时会遇到的 `(vision, state)` 组合？没覆盖的点模型只能外插——外插能力来自架构先验，但先验能做的有限。
2. **信噪比**（SNR）：给定 `(vision, state)`，动作是否**一致**？同一状态下两个采集员用完全不同的策略 → 模型学到的是两者的**平均**，往往哪个都不像。
3. **对齐度**（alignment）：时间戳 / 坐标系 / 模态对齐是否正确？错位 = 加噪声 = 降 SNR。

🧠 **作者推论**：增加模型参数只能更好地**拟合**已有分布，不能**扩展**分布的 support。如果数据 support 没变，参数翻倍≠真机泛化翻倍。（这是作者对"扩参收益递减"现象的解释，尚未见到针对 VLA 的严格定量研究——LLM scaling law 假设数据同步扩，不直接适用。）

### 三个领域的 Scaling 差异

| 领域 | 数据来源 | 一次标注的边际成本 | Scaling 走到哪 |
|------|---------|:---------------:|:--------------:|
| **NLP** | 互联网语料 | ≈ 0（已存在） | 万亿 token，开始撞墙 |
| **CV** | 互联网图像 + 人工标注 | $0.01-0.1/label | 十亿图像，仍有空间 |
| **VLA** | 遥操作 + 机器人 | **$0.08-1/轨迹 + 机器人时间** | 千万级轨迹是瓶颈 |

VLA 数据每条的**物理边际成本**比 NLP/CV 高 3-5 个数量级。这决定了 VLA 的 Scaling Law 不是"不想做大"，而是**物理上做大的速度被机器人小时数限制**。

### 哪里投入边际收益最高

1. 📎 **数据多样性（环境/物体）** > 数据数量（同环境多次重复）—— [ICLR 2025 Scaling Law](https://data-scaling-laws.github.io/) 定量论证：环境数和物体数呈幂律关系主导泛化，单环境加数据收益远小。
2. 🧠 **失败案例 + 恢复轨迹** > 只有成功案例 —— 作者推理 + RoboMIND 2.0 收录 5K 失败案例的设计动机间接支持，尚未见严格消融实验。
3. 📎 **跨形态的共享表示**（基础模型做法） > 单一形态堆数据 —— OpenVLA / π₀ / GR00T 三篇论文的实验都显示跨形态预训练+目标微调优于从零单形态训练。
4. 📎 **标注质量（语言 / 子任务 / 失败原因）** > 仅有轨迹 —— [LIBERO-PRO](https://arxiv.org/abs/2510.03827) 的语言消融实验直接证实模板化标注会让模型忽略语言。

> 📐 🧠 **一句话原理**（作者观点）：当前 VLA 的上限不是"能不能拟合"，而是"**数据能让它拟合成什么**"。模型不可能学到数据里没有的东西；模型会忠实地学到数据里的所有偏见。

## 1.5 三大沉默杀手：坐标系、动作表示、归一化

> 🧠 **本节为作者经验与领域共识的归纳**。具体数字（如"能力差 30%"）是作者的估计而非某篇论文的测量——尚未见到严格的对照消融研究。

### 杀手 1：坐标系不统一

每条轨迹至少涉及 4 个坐标系：

| 坐标系 | 定义 | 谁用它 |
|--------|------|--------|
| **机器人基座系** | 机器人底盘原点 | 关节角、机器人本体指令 |
| **末端执行器系** | 末端工具原点 | EE pose、grasp 姿态 |
| **相机系** | 相机光心 | 图像特征、深度图 |
| **世界系 / 桌面系** | 固定参考 | 人类标注、物体位置 |

**典型错误**：
- 两批采集员，一组用机器人 A（基座在左前方），另一组用机器人 B（基座在右前方）—— 动作数值看起来一样但实际方向相反
- 相机重装后没重新手眼标定，导致新数据的图像-动作空间关系偏移了几厘米
- 从仿真迁移到真机时，Z 轴方向（Isaac 是 Z-up，某些系统是 Y-up）

**防御策略**：
1. **记录变换矩阵**：每条轨迹元数据里存 `T_base_to_camera` + `T_base_to_world`——事后可以重标定
2. **采用统一的工作系**：推荐 **EE-in-base** 作为动作空间（EE 相对基座），base-in-world 作为场景参考
3. **跨机器人训练时**：一定要转换到**相对动作**（见下面动作表示）

### 杀手 2：动作表示（action representation）

🧠 **作者观察**：不同动作表示带来的性能差异非常显著。常见说法是"能差 10-30%"——作者未找到严格 head-to-head 的消融论文，这个数字应视为**经验估计**，不是论文结论。

| 表示 | 形式 | 优 | 劣 |
|------|-----|----|----|
| **Joint-space abs** | `(q1...qN)` 绝对关节角 | 简单、无逆运动学 | 不跨形态、不利于视觉 |
| **Joint-space delta** | `(Δq1...ΔqN)` 增量 | 平移/旋转不变性好 | 累计误差 |
| **EE-pose abs** | `(xyz, rpy)` 绝对位姿 | 直观、跨形态共享 | 需要 IK |
| **EE-pose delta** | `Δ(xyz, rpy)` 增量 | 跨形态最好、视觉友好 | **累计误差显著** |
| **EE-velocity** | `(vx...vyaw)` 速度 | 平滑、适合 Diffusion Policy | 需要积分 |

📎 **π₀**：输出 EE delta（`[Δx, Δy, Δz, Δrx, Δry, Δrz, gripper]`）在基座系 —— [π₀ 论文](https://www.pi.website/download/pi0.pdf) + OpenPi 社区讨论确认。
📎 **π₀.₅**：训练时同时预测 target joint 和 EE pose，并按数据集归一化 —— [π₀.₅ 论文 arXiv:2504.16054](https://arxiv.org/html/2504.16054v1)。
📎 **OpenVLA**：将 OXE 中各数据集的动作空间统一到 7 维，base frame 下的 delta EE（非 gripper frame），1-99% 百分位归一化后离散化到 256 bin —— [OpenVLA 论文](https://openvla.github.io/) + [GitHub](https://github.com/openvla/openvla)。
📎 **ACT**：Joint-space absolute —— [ACT 原论文](https://tonyzhaozh.github.io/aloha/) 的 ALOHA 平台设定，行动即目标关节角。

**经验法则**：
- 只做一个机器人 → joint-space abs 最省事
- 想做跨形态 / 预训练 → **必须** EE-pose delta + 基座对齐
- Diffusion Policy / 长程任务 → velocity / trajectory chunks（消除累计误差）

**陷阱**：直接把"机器人指令"（比如 MoveIt 发的目标点）当动作标签—— 但机器人**实际执行**的可能是带滤波的轨迹。动作标签应该是**实际执行的关节 / EE 值**，不是目标值。

### 杀手 3：归一化策略

📎 OpenVLA / π₀ / π₀.₅ 的官方实现都使用**百分位归一化 + per-dim** 作为标准做法。

| 方法 | 怎么做 | 问题 |
|------|--------|------|
| **Min-Max** | `(x - min) / (max - min)` | 🧠 极值敏感，一条异常轨迹污染整个数据集 |
| **Percentile (1-99%)** | 用 1/99 百分位替代 min/max | 📎 OpenVLA 采用；抗异常值 |
| **Per-dim** | 每维独立归一化 | 📎 OpenVLA/π₀ 标准做法 |
| **Joint global** | 所有维共享统计 | 🧠 作者经验：不同维度量纲差距大，共享统计会压扁小量纲维度 |
| **Z-score** | `(x - μ) / σ` | 🧠 动作分布通常是多峰的（不同任务/策略），高斯假设通常不成立 |

**必坑**：
- **训练集和验证集的归一化统计不同** → 评测失效
- **部署时忘了反归一化** → 机器人抽风
- **新数据混入时没更新统计** → 新数据的极值被误判为异常
- **关节角 + 夹爪混着归一化** → 0/1 开合信号被"平滑"成 0.3/0.7

**最佳实践**：
```python
# 1. 用百分位算归一化参数
stats = {
    'q_min': np.percentile(q, 1, axis=0),
    'q_max': np.percentile(q, 99, axis=0),
}
# 2. 参数固化存 modality.json / norm_stats.json
# 3. 训练、评测、部署用同一份文件
# 4. 夹爪是离散信号，不归一化——直接保持 {0, 1}
```

> ⚠️ **最隐蔽的 bug**：坐标系错、动作表示错、归一化错——**Loss 曲线都正常**。只有真机一上才出问题。训练 Loss 低 ≠ 模型学对了。

## 2. 数据格式标准

### 当前主流格式

| 格式 | 推动者 | 用谁 | 特点 |
|------|--------|------|------|
| **LeRobot v2** | HuggingFace | SmolVLA, GR00T-N1.7, LingBot | Parquet + MP4 · `modality.json` 定义键映射 · **当前推荐** |
| **OXE / RLDS** | Google | OpenVLA, Octo, RT-2 | TFRecord · Open X-Embodiment 标准 · 数据量最大 |
| **HDF5** | Stanford | ACT, ALOHA | 单文件 · 简单 · 不适合大规模 |
| **Zarr** | — | Diffusion Policy | 分块存储 · 随机访问快 |

### LeRobot v2 结构（推荐）

```
dataset/
├── meta/
│   ├── info.json          # 数据集元信息（fps, robot_type, shapes）
│   ├── episodes.jsonl     # episode 列表（start_idx, end_idx, task）
│   ├── tasks.jsonl        # 任务描述列表
│   └── modality.json      # state/action/video 键映射（GR00T 特有）
├── data/
│   └── chunk-000/
│       └── episode_000.parquet   # 数值数据（关节角、动作、时戳）
└── videos/
    └── chunk-000/
        └── episode_000.mp4       # 视频（压缩存储）
```

**为什么推荐 LeRobot v2**：
1. HuggingFace 维护 → 社区最大 → 兼容性最好
2. Parquet 列存储 → 读取特定列极快（只读动作不读图像）
3. MP4 视频 → 存储小（比原始帧小 10-50x）
4. `modality.json` → 一个文件描述所有模态映射，换机器人只需改这个文件

### 格式转换

```python
# OXE → LeRobot
from lerobot.common.datasets.push_dataset_to_hub import convert_oxe_to_lerobot

# HDF5 → LeRobot
from lerobot.common.datasets.push_dataset_to_hub import convert_hdf5_to_lerobot
```

## 3. 数据质量

### 什么是"好的 demo"

| 维度 | 好 | 差 |
|------|-----|-----|
| **速度** | 匀速、流畅 | 突然加速/停顿/犹豫 |
| **轨迹** | 最短路径或自然路径 | 绕路、来回纠正 |
| **抓取** | 一次到位 | 抓了放、放了抓 |
| **视角** | 目标始终可见 | 遮挡、出框 |
| **一致性** | 同一任务的不同 demo 策略相似 | 每次做法完全不同 |

### 常见采集错误

| 错误 | 后果 | 检测方法 |
|------|------|---------|
| 时间戳漂移 | 动作对错帧 | 对比 action 与 image 的时间差分布 |
| 遥操卡顿 | 轨迹中插入"冻结帧" | 检测连续相同的 action 值 |
| 相机曝光变化 | 训练数据分布不一致 | 检查图像亮度直方图 |
| 夹爪状态丢失 | 模型不知道什么时候该抓 | 检查 gripper 信号的变化频率 |
| 坐标系不统一 | 不同采集批次的动作不可比 | 标定验证 |

### 质量检查 Pipeline

```python
# 建议在采集后立即运行
def check_episode_quality(episode):
    checks = {
        'timestamp_gap': max(diff(timestamps)) < 50ms,
        'action_frozen': count(identical_consecutive_actions) < 5,
        'image_brightness': std(brightness) < threshold,
        'gripper_active': count(gripper_changes) > 0,
        'duration': 5s < episode_length < 120s,
    }
    return all(checks.values()), checks
```

## 3.5 数据失效模式分类学

> 🧠 **本节是作者提出的分类法**——不是某篇论文的标准定义。但每一类的"症状"都有对应的真实论文证据（标 📎 处）。

### F1. 虚假相关（Spurious Correlation）

**症状**：仿真/同分布上完美，换颜色/背景/位置就崩
**根因**：模型找到了"捷径"——比如"任务 A 永远在桌子左边"→ 学到的是**位置**，不是**任务**
📎 **典型论文**：[LIBERO-PRO (arXiv:2510.03827)](https://arxiv.org/abs/2510.03827) 标准 90%+ vs 泛化设定 0.0%
🧠 **检测建议**：语言消融、遮蔽部分视觉——作者归纳的排查方法
🧠 **修复建议**：多样化采集 + RoboEngine 类增强——基于 [RoboEngine (arXiv:2503.18738)](https://arxiv.org/abs/2503.18738) 的 +210% 结果推断

### F2. 分布外偏移（OOD Shift）

**症状**：训练集和部署环境差一点点，性能腰斩
**根因**：数据覆盖不够——光照、相机位置、桌面纹理、物体尺寸
🧠 **典型例子**（作者估计值）：实验室→家庭场景性能跌 30-50%，具体幅度随任务变化很大；没有单一论文给"40%"的统一数字
📎 **间接证据**：[警告 3 LIBERO-Plus/X](https://arxiv.org/abs/2510.13626) 扰动导致 95%→30%
🧠 **修复建议**：Domain Randomization + 多场景数据（如 [DROID](https://droid-dataset.github.io/) 的 564 场景）

### F3. 时序错位（Temporal Misalignment）

🧠 **本类以下皆为作者归纳的经验**——属于机器人工程的常见痛点，但很少有论文专门论证 VLA 性能对时序对齐的敏感度。
**症状**：模型预测动作总是"慢半拍"，抓取时机差一帧
**根因**：图像时戳和动作时戳对齐差 30-100ms（经验值）
**检测**：画图对比连续帧的图像变化方向和 action 方向，应该**同步变化**
**修复**：硬件触发、PTP 或 ROS2 /clock 同步；采集后用**光学事件**（闪光灯）标定时延

### F4. 坐标系/动作漂移（Frame Drift）

🧠 **作者经验分类**——常见工程痛点，见 [§1.5 杀手 1](#15-三大沉默杀手坐标系动作表示归一化)
**症状**：同一个模型，上周跑得好，这周不行
**根因**：相机位置变了没重新标定 / 机器人零位漂移 / 新批次采集员坐标系定义不同
**检测**：对比新旧数据的 EE 轨迹统计分布——均值/方差差异过大=漂移
**修复**：每次重装相机必须重手眼标定；元数据里记录变换矩阵；按批次分 chunk

### F5. 语言-动作解耦（Language-Action Decoupling）

**症状**：换任务描述，模型行为不变
**根因**：🧠 作者假设——语言标注是模板化的（`pick up the {obj}`），视觉已经有足够信息识别任务 → 语言成摆设
📎 **论文证据**：[LIBERO-PRO (arXiv:2510.03827)](https://arxiv.org/abs/2510.03827) + [LIBERO-Para (arXiv:2603.28301)](https://arxiv.org/abs/2603.28301) vision-only 44.6% ≈ language-conditioned 47.8%
**检测**：**语言消融**——mask 语言看成功率是否下降（📎 LIBERO-PRO 直接使用的方法）
**修复**：
1. 用 **LLM 重写**同一任务的多种表述（"pick up the red block" / "grab the crimson cube" / "move the scarlet piece"）
2. 让视觉**不能单独识别任务** —— 同一场景布置多个物体，必须靠语言消歧
3. 引入需要**世界知识**的指令（"pour a small amount"——"small" 不是视觉可见的）

### F6. 动作分布偏斜（Action Distribution Bias）

🧠 **作者归纳的失效模式**——直接论文证据较弱，间接证据为 RoboMIND 2.0 的失败案例设计。
**症状**：模型在常见动作上表现好，罕见动作（回退、重试、微调）完全不会
**根因**：只收集"完美 demo" → 模型没见过"失败后怎么恢复"
**检测**：部署时人为制造"偏离态"（挪一下物体），看模型能否自动纠正
**修复**：
1. 📎 **保留失败 + 恢复轨迹**——[RoboMIND 2.0](https://x-humanoid-robomind.github.io/) 收录了 5K 失败案例专门应对此问题
2. 🧠 **DAgger 类数据增强**（Ross et al. 的 DAgger 原理应用于 VLA 场景，作者建议）
3. 🧠 **动作扰动**训练——作者建议

### 一张速查表

| 失效类 | 训练 Loss | 仿真成功率 | 真机成功率 | 典型检测方法 |
|--------|:--------:|:---------:|:---------:|------|
| F1 虚假相关 | 低 | 高 | **崩** | LIBERO-PRO 扰动测试 |
| F2 OOD 偏移 | 低 | 高 | **下降** | 主动边角测试 |
| F3 时序错位 | 正常 | 中 | 持续偏差 | 图像-动作同步性可视化 |
| F4 坐标漂移 | 正常 | 高 | 新数据后变差 | 分布对比 |
| F5 语言解耦 | 低 | 高 | 换指令无反应 | 语言消融 |
| F6 动作偏斜 | 低 | 高（无扰动）| 失败后卡死 | 人为扰动恢复测试 |

> 📐 **核心规律**：F1-F6 **都不会在训练 Loss 上体现**。只能通过**主动对抗性评测**发现。这是为什么 LIBERO-PRO / LIBERO-Plus / LIBERO-X 这些扰动 benchmark 如此重要。

**关键发现**：
- 泛化性能与环境/物体数量呈**幂律关系**
- **多样性比数量更重要**：10 个环境各 5 条 demo > 1 个环境 50 条 demo
- 4 个采集员 1 个下午的数据 → 2 个任务在新环境/新物体上 ~90% 成功率

| 数据量 | 典型效果 | 参考 |
|--------|---------|------|

| 100 demos + 触觉 | 等效 200 demos 纯视觉（2x 数据效率） | [TaF-VLA](../tactile/taf_vla_tactile_force_alignment_2026.md) |
| 1 hr 数据 | 99% 成功率（特定任务，GEN-1 级别） | [GEN-1 报告](https://generalistai.com/blog/apr-02-2026-GEN-1) |

### 2026 新发现：人类第一人称视频也遵循 Scaling Law（EgoScale）

📎 **[EgoScale (arXiv:2602.16710, NVIDIA GEAR)](https://arxiv.org/abs/2602.16710)** 用 **20,854 小时** 带动作标签的人类第一人称视频做 VLA 预训练，规模比此前人类视频 VLA 工作大 **20×**。

关键结论（均为 📎 论文原始数据）：
- **log-linear scaling law（R²=0.9983）**：从 1k 到 20k 小时，验证 loss 与数据量几乎完美对数线性相关
- **验证 loss 强相关于真机性能**：这是人类数据作为 VLA 监督信号"可预测"的关键证据
- **22-DoF 机械手 5 个灵巧任务（叠衬衫、卡片分类、开瓶盖等）**：预训练相比无预训练 **+54%** 成功率
- **one-shot 泛化**到未见技能；可迁移到低 DoF 手

🧠 **作者解读**：
1. 这是第一次有人**严格证明**人类视频对 VLA 有可预测的缩放性——此前大家猜测"人类数据有用"，但不知道加一倍人类数据换多少真机性能。EgoScale 给出 log-linear 的答案。
2. 人类数据的**边际物理成本**远低于机器人遥操作（无需机械臂、无需精确标定、全球数千万小时存量）——把 VLA 的物理成本瓶颈**从机器人小时数转移到了视频小时数**。
3. 但 EgoScale 只证了 loss 的 scaling，没证真机成功率的 scaling——"loss 下降" → "真机成功率提高"这一环的斜率还未量化。

### 人类视频 vs 机器人遥操作：数据经济学对比

| 维度 | 机器人遥操作 | 人类第一人称视频（EgoScale 路线） |
|------|-------------|--------------------------------|
| 每小时成本 | 📎 $50-500（人工+机器人） | 🧠 $5-50（单人 + 摄像机 + 手套） |
| 扩展上限 | 📎 受机器人小时数限制（DROID 用了 18 个月） | 🧠 理论上无限（可众包） |
| 形态适配 | ✅ 直接 | 📎 需要 retarget（EgoScale 的 3 阶段训练） |
| 动作精度 | ✅ 高（编码器级） | 🧠 中（MANUS 手套约 ±5°） |
| 失败案例 | ✅ 可主动采集 | ❌ 人类视频几乎没有"失败"数据 |
| 任务多样性 | 🧠 受机器人能做的限制 | ✅ 人类日常的所有任务 |

📎 EgoScale 实际采用**3 阶段流程**：
1. 在 20k+ 小时**人类**视频上预训练 VLA（只学运动先验）
2. 用少量**人-机对齐的 play data** 做 mid-training（桥接人机形态差）
3. 在**目标机器人任务**上做 post-training（少量真机数据即可）

### 边际效用曲线：第 51 条 demo 值多少

🧠 **本节为作者基于 [ICLR 2025 Scaling Law](https://data-scaling-laws.github.io/) 的幂律结论做的工程经验总结**。具体数字（甜点区间、停止信号的阈值）为作者估计，非论文实验结果。

**核心直觉**：📎 demo 数量 vs 性能呈幂律关系（ICLR 2025 Scaling Law 量化），对数坐标下近似 S 曲线。

```
性能 ↑
 95% │       ╱────────── 平台期（多样性瓶颈）
 90% │     ╱╱
 80% │   ╱╱                  ← 单任务 50-100 demos 的"性价比甜点"
 60% │  ╱
 40% │ ╱
 10% │╱
     └─────────────────→ demo 数量（对数坐标）
      10   50  100  500  2K  10K
```

**关键判断点**：

| 阶段 | demo 量 | 主要瓶颈 | 下一步边际投入 |
|------|:-------:|---------|---------------|
| 0 → 50 | 冷启动 | **量** | 继续采集 |
| 50 → 200 | 覆盖率不够 | **多样性**（环境/物体） | 多样化 >> 数量 |
| 200 → 1K | 单任务过拟合 | **任务多样性** | 增加任务数（不是同任务加量） |
| 1K → 10K | 形态局限 | **跨形态** | 用 OXE 做预训练，少量目标微调 |
| 10K+ | 架构 / 数据质量 | **架构天花板** | 回头改架构 / 清洗数据 |

🧠 **停止采集的信号**（作者经验阈值）：
1. 同一任务再加 50 条 demo，验证集成功率涨不到 2% → 过拟合单一任务
2. 仿真成功率 > 95%，真机差 20%+ → Sim2Real gap（📎 参考 π₀.₅/VGA/WVA 的 sim-real 差距 [警告 4]）
3. LIBERO-PRO 扰动掉到 30% 以下 → 📎 [LIBERO-PRO](https://arxiv.org/abs/2510.03827) 的扰动基准

> 💡 🧠 **作者观察**：多数 VLA 场景下多样性压过数量——这是对 [ICLR 2025 Scaling Law](https://data-scaling-laws.github.io/) 主论点的延伸判断，不是该论文的原文数字。

### 另一个维度：任务数 vs 单任务 demo 数

🧠 **以下表格是作者提出的定性归纳**（★ 为相对强弱示意，不是测量值）。灵感来自 GR00T-N1.7 "5 demos 起步"和 π₀ 跨任务预训练策略，但对于"相同总预算下的任务数 vs demo 数权衡"没有见到严格定量的对照实验。

| 配置 | demo 总数 | 单任务泛化 | 跨任务泛化 | 新任务迁移 |
|------|:--------:|:---------:|:---------:|:---------:|
| 1 任务 × 500 demo | 500 | ★★★★ | ✗ | ✗ |
| 10 任务 × 50 demo | 500 | ★★★ | ★★ | ★ |
| 50 任务 × 10 demo | 500 | ★★ | ★★★★ | ★★★ |
| 100 任务 × 5 demo | 500 | ★ | ★★★★★ | ★★★★ |

🧠 **作者规律判断**：同样 500 条总预算，多任务少 demo 泛化得更好；前提是每任务 demo 足够覆盖任务本身。📎 GR00T-N1.7 用 5 demo/任务做多任务微调，这支持"少量 demo 足以教会一个任务"的方向性判断——但不直接等于"500 条总预算最优分配在 100 任务上"。

## 5. 数据模态

### 核心模态

| 模态 | 维度 | 频率 | 必要性 | 说明 |
|------|------|:----:|:------:|------|
| **RGB** | H×W×3 | 30Hz | 必须 | 主视觉输入 |
| **关节角** | N_joints | 100Hz+ | 必须 | 本体感觉 |
| **末端位姿** | 6D (xyz+rpy) | 100Hz+ | 推荐 | FK 计算或直接读 |
| **夹爪状态** | 1 (开/合) | 100Hz+ | 必须 | 抓取动作的关键信号 |
| **深度** | H×W×1 | 30Hz | 推荐 | 3D 感知 · 可蒸馏 |
| **语言指令** | 文本 | 1x/task | 推荐 | 多任务需要 |
| **触觉** | 变化大 | 30-200Hz | 可选 | 接触操作 |

### 多模态同步对齐

```
采集时：
  所有传感器 → 统一时间戳（ROS2 /clock 或 PTP）

存储时：
  高频信号（关节 100Hz）和低频信号（图像 30Hz）分开存
  用时间戳做对齐索引

训练时：
  按图像帧率采样 → 高频信号插值到图像时间戳
  action chunk 从当前帧开始的未来 k 步
```

## 5.5 按数据类型的处理规范

> 🧠 **本节为作者按模态归纳的工程规范**。每类的"标准做法"多来自 LeRobot/OpenVLA/π₀ 的开源代码实现（📎），具体参数（分辨率、滤波常数）是工程经验值（🧠）。

### 5.5.1 RGB 图像

| 环节 | 做法 | 标注 |
|------|------|------|
| **采集分辨率** | 640×480 或 720p 原生；训练时裁到 224/256 | 📎 OpenVLA 用 224²，π₀ 用 224² |
| **色彩空间** | BGR→RGB 转换必须在数据读取层统一 | 🧠 OpenCV 默认 BGR，忘了转是经典 bug |
| **压缩格式** | 训练存 MP4（H.264/AV1），推理用原始帧 | 📎 LeRobot v2 标准 |
| **编码压缩率** | CRF 18-23（视觉上接近无损） | 🧠 经验值；CRF 28+ 会损失细节 |
| **归一化** | `(x/255.0 - mean) / std`，用 ImageNet 统计 | 📎 所有基于 VLM 的 VLA 都这样（继承 ViT 预处理） |
| **增强** | ColorJitter / 随机裁切（轻度），不要做强翻转 | 🧠 水平翻转会反转左右手指令，破坏语言关联 |

**常见坑**：
- 🧠 白平衡漂移：不同时段/不同环境的相机自动白平衡 → 同一物体颜色不一致 → 锁定白平衡
- 🧠 MP4 的 I-frame 间隔：随机访问单帧解码会很慢，设置 `-g 1`（每帧都是 I-frame）存储会大 3-5x 但加载快 10x
- 📎 不同数据源的 RGB 分布差异会破坏跨数据集预训练 —— 这是 OXE 预处理要统一色彩空间的原因

### 5.5.2 深度（Depth）

| 环节 | 做法 | 标注 |
|------|------|------|
| **存储单位** | uint16 以 mm 为单位（RealSense 标准） | 📎 RealSense SDK 默认 |
| **对齐** | 必须对齐到 RGB 相机（`rs.align`），不是原始深度相机坐标 | 📎 RealSense 最佳实践 |
| **空洞处理** | 双边滤波或 `cv2.inpaint` 填小洞；大洞保留 NaN mask | 🧠 经验做法 |
| **无效值** | 远距（>2m）和近距（<0.2m）设 0/NaN | 🧠 大部分机械臂工作空间在此范围内 |
| **归一化** | `depth_m / max_depth`，clip 到 `[0, 1]` | 🧠 简单稳定；不要 per-image 归一化，会破坏绝对尺度 |
| **蒸馏替代** | 部署时可用 Depth Anything v2 估计，训练时用真值 | 📎 LingBot-VLA 采用的做法 |

**常见坑**：
- 🧠 反光/透明物体的深度完全错——别依赖深度做唯一线索
- 🧠 深度和 RGB 时间未对齐：RealSense 内部延迟约 16ms（可通过 SDK 时戳修正）
- 🧠 uint16 mm 存成 float32 会浪费 2x 空间

### 5.5.3 3D 点云

| 环节 | 做法 | 标注 |
|------|------|------|
| **来源** | 深度图反投影 或 LiDAR 直接点云 | — |
| **下采样** | FPS (Farthest Point Sampling) 到固定 N 点（如 1024/2048/4096） | 📎 PointNet++ 以来的标准 |
| **坐标系** | 机器人基座系；**不要**用相机系做训练 | 🧠 基座系下跨相机通用 |
| **中心化/缩放** | 减去工作空间中心，除以工作空间半径（固定值，不是 per-frame） | 🧠 per-frame 归一化会丢失尺度 |
| **颜色融合** | 6D (XYZ+RGB) 优于纯 3D | 📎 3D-VLA / RVT 等工作 |
| **Voxel 代替** | 如用 VGGT/Sparse ConvNet，voxel size 1-5cm | 🧠 工作空间 1m 用 1cm voxel 是典型选择 |

**常见坑**：
- 🧠 FPS 每次运行采样点不同 → 训练不稳定 → 用固定随机种子或网格采样
- 🧠 视角边缘的点云密度低、噪声大——考虑裁掉边缘 10%

### 5.5.4 关节角（Proprioception）

| 环节 | 做法 | 标注 |
|------|------|------|
| **revolute 关节** | 解包裹（unwrap）：连续两帧跳 2π 判为穿越 0 | 🧠 常见 bug 来源 |
| **编码器分辨率** | 浮点 rad 存储；不要用 deg（精度损失） | 🧠 工程惯例 |
| **归一化范围** | 用关节**物理极限**（每个关节不同）做 per-dim 归一化 | 📎 OpenVLA/π₀ 做法 |
| **频率对齐** | 100Hz 采，下采样或插值到图像帧率（30Hz） | 🧠 最近邻插值通常够 |
| **本体+动作同在** | state 记"当前关节角"，action 记"下一关节角或增量" | 📎 LeRobot modality.json 约定 |

**常见坑**：
- 🧠 revolute 关节的 `-π` 和 `+π` 是同一位置，但归一化后变成 0 和 1——必须**在归一化前**处理穿越
- 🧠 关节零位在不同机器人个体间可能差几度——同一批次用同一台机器人标定

### 5.5.5 末端位姿 / 旋转表示

| 表示 | 维度 | 优 | 劣 |
|------|:---:|----|----|
| **Euler (rpy)** | 3 | 直观 | 📎 万向节死锁 · 不连续 |
| **四元数** | 4 | 紧凑 | 🧠 双覆盖（q 和 -q 同姿态）导致训练不稳 |
| **旋转矩阵** | 9 | 稳定 | 冗余、需正交约束 |
| **6D 连续表示** | 6 | 📎 [Zhou et al. 2019](https://arxiv.org/abs/1812.07035) 证明神经网络友好 | 需要 SVD 反投影 |

🧠 **作者建议**：VLA 回归姿态时用 **6D 连续表示**，Euler/四元数仅用于人类可读的存储。

**常见坑**：
- 📎 四元数双覆盖：`q=[0,0,0,1]` 和 `q=[0,0,0,-1]` 是同一姿态。直接 MSE 会让网络在两个目标间震荡——必须取最近半球。
- 🧠 旋转 loss 不能用 MSE：用 geodesic distance 或 6D rotation loss

### 5.5.6 夹爪状态

| 类型 | 处理 | 标注 |
|------|------|------|
| **二值（开/合）** | 保持 `{0, 1}`，**不归一化** | 🧠 归一化会让分类问题变回归问题 |
| **连续宽度** | 按物理行程归一化（如 0-85mm → [0,1]） | 🧠 工程惯例 |
| **目标 vs 实际** | 记录**实际**夹爪状态（不是指令）——指令是离散阶跃，实际有动力学延迟 | 🧠 区分 command vs actual 是常见坑 |
| **训练 loss** | 二值用 BCE，连续用 L1/L2 | 🧠 不要把二值与连续动作混合用同一 loss |

### 5.5.7 力 / 力矩（F/T）

| 环节 | 做法 | 标注 |
|------|------|------|
| **零偏校准** | 每次开机做 **gravity compensation** + **零偏归零**（机器人自由悬停时读零偏） | 📎 ATI / Robotiq F/T 传感器标准流程 |
| **漂移补偿** | 长时间采集需周期性重校零（每 10-30 分钟） | 🧠 经验值，具体看传感器 |
| **滤波** | 低通 Butterworth（截止 20-50Hz） | 🧠 高频噪声很大 |
| **采样频率** | 500-1000Hz 原生，下采样到 30-100Hz | 🧠 保留 30Hz 以上信息对接触事件够用 |
| **归一化** | per-axis 百分位归一化（F 和 τ 量纲不同，不能 joint global） | 🧠 Fz 可能比 Fxy 大一个量级 |

**常见坑**：
- 🧠 力传感器装在腕部还是末端——测到的是"包含夹爪重力"还是"只有外力"；训练前必须重力补偿
- 🧠 温度漂移：F/T 传感器随温度漂移可达 5-10%——环境温控或定期重校

### 5.5.8 触觉（Tactile）

🧠 **触觉是 VLA 里最"无标准"的模态**——不同传感器的输出形式完全不同。

| 传感器 | 输出形式 | 处理策略 |
|--------|---------|---------|
| **GelSight / DIGIT** | 图像 (320×240×3) | 📎 当 RGB 处理；用预训练 ViT/CNN encode |
| **BioTac** | 19 维向量 + 阻抗 | 🧠 MLP encode，或 1D conv 处理时序 |
| **电容阵列（如 Xela）** | N×M 网格值 | 🧠 可视为低分辨率图像 |
| **压阻织物** | 稀疏点云 | 🧠 视为点云或栅格 |

🧠 **作者建议的跨触觉统一**：所有触觉先 encode 到固定维度 embedding（如 256 维），再送入主干——这样换触觉传感器不需要改架构。📎 TaF-VLA / TaF-Dataset 采用的"触觉 tokenizer"是这个思路的实现。

**常见坑**：
- 🧠 GelSight 没接触时也有基线纹理——必须做 background subtraction（存一张未接触帧做基准）
- 🧠 触觉和视觉/动作的频率差异：触觉可能 200Hz，图像 30Hz——不要简单下采样到 30Hz，会丢接触事件

### 5.5.9 语言指令

| 环节 | 做法 | 标注 |
|------|------|------|
| **标注数量** | 📎 每任务 ≥ 5 种不同表述（对抗 F5 语言解耦） | 📎 LIBERO-PRO 的警告直接支持 |
| **生成方式** | LLM 重写 > 人工撰写 > 模板填空 | 🧠 成本 vs 多样性权衡 |
| **tokenization** | 用对应 VLM 的 tokenizer（Llama/PaliGemma 不同） | 📎 必须和预训练匹配 |
| **存储** | UTF-8 明文，每 episode 多条候选指令 | 🧠 训练时随机抽一条增强 |
| **语言消融测试** | 训练后必做：mask 语言看成功率是否下降 | 📎 LIBERO-PRO 的评测方法 |

**常见坑**：
- 📎 全模板化标注（`pick up the {obj}`）→ 模型完全忽略语言（[LIBERO-Para](https://arxiv.org/abs/2603.28301) 44.6%≈47.8%）
- 🧠 中英文混用时要确保 tokenizer 支持（Llama-2 对中文差，Qwen/InternLM 更好）

### 5.5.10 音频（如 OmniAction）

🧠 **VLA 中较新的模态**（2025-2026），主要见于 [OmniAction](https://huggingface.co/datasets/OpenMOSS-Team/OmniAction)。

| 环节 | 做法 | 标注 |
|------|------|------|
| **采样率** | 16kHz 足够语音；48kHz 用于环境音 | 📎 Whisper/音频模型标准 |
| **特征** | 梅尔频谱图 (mel-spectrogram, 80-128 bins) | 📎 语音/音频 SOTA 做法 |
| **时间窗口** | 200ms-1s 滑动窗口 | 🧠 工程经验 |
| **对齐** | 音频时戳必须和动作对齐——声学事件（砰、啪）是关键信号 | 🧠 音频通常比图像有更精确时戳 |

### 5.5.11 IMU / LiDAR（移动/人形形态）

🧠 **主要用于移动操作和人形机器人**（AgiBot World 2026、Humanoid Everyday 含这些模态）。

| 模态 | 关键处理 | 标注 |
|------|---------|------|
| **IMU** | 陀螺仪零偏补偿、重力分离、Madgwick/Mahony 姿态融合 | 📎 惯性导航标准 |
| **LiDAR** | ICP 去畸变（高速运动时单帧扫描有畸变）+ 点云处理（同 5.5.3） | 📎 LiDAR SLAM 标准 |

### 5.5.12 人类第一人称视频（Egocentric Human Video）

📎 **代表工作**：[EgoScale (arXiv:2602.16710)](https://arxiv.org/abs/2602.16710) · [EgoVLA](https://rchalyang.github.io/EgoVLA/) · [Ego4D](https://ego4d-data.org/) · [Project Aria](https://www.projectaria.com/)

🧠 **为什么它变得重要**（2026 年起）：人类视频是机器人数据的 100x 存量、1/10 成本——EgoScale 证明了 log-linear scaling law 后，从"实验性用法"跃升为 VLA 预训练的主线路径之一。

| 环节 | 做法 | 标注 |
|------|------|------|
| **视频规格** | 30 FPS · RGB · 带 IMU 的可穿戴相机（Aria / Meta Quest 等） | 📎 EgoScale 采用 |
| **手部动作标注** | MANUS 手套 / MoCap / 从视频估计（HaMeR、ACE） | 📎 EgoScale 用 MANUS |
| **动作表示** | 📎 EgoScale 用"**wrist-level 统一表示**"——腕部位姿 + 手指关节 | 📎 关键设计决定 |
| **Retargeting** | 人手 21 关节 → 机器人手（7/16/22 DoF）的映射必须保持接触拓扑 | 🧠 工程难点 |
| **人-机桥接** | 必须加 **mid-training**（人-机对齐的 play data） | 📎 EgoScale 3 阶段 |
| **什么不要做** | ❌ 直接把人类视频当机器人数据训练——形态差太大，会学到不可执行的动作 | 🧠 EgoScale 论文的反面教材 |

**典型坑**：
- 🧠 人类视频的视角（头戴相机）和机器人视角（腕部+第三视角）分布差异巨大——纯靠视觉特征难泛化，要**配合本体感受**做跨域对齐
- 🧠 人手接触力**未测量**——灵巧操作的力控制信号丢失；需要力预测模型补偿
- 🧠 视频中手被遮挡很常见（手在身体前方时被其他物体挡住）——需要**手部 pose 的 uncertainty 估计**而不是点估计
- 📎 EgoScale 指出只 scale 了 validation loss，"loss → 真机成功率"的转换率未量化——不要盲目以为 1000 小时视频换来固定比例提升

🧠 **和机器人数据如何配比**（作者建议，尚无论文定量依据）：
- 人类视频预训练 > 10k 小时 → 获取运动先验
- 人-机 play data 100-500 小时 → 桥接形态差
- 目标机器人 demo 50-500 条 → 特化到具体任务
- 总算下来：**人类:人-机:机器人 ≈ 100:5:1 的小时比**

### 一张速查：**千万别混着用的坑**

| 错误 | 后果 |
|------|------|
| 二值夹爪当连续归一化 | 🧠 抓取点模糊化 |
| 四元数直接 MSE | 📎 双覆盖导致震荡 |
| 关节 revolute 未 unwrap | 🧠 π 附近数据废 |
| 深度 per-frame 归一化 | 🧠 丢失绝对尺度 |
| 触觉下采样到 30Hz | 🧠 丢失接触瞬态 |
| RGB 忘了 BGR→RGB | 🧠 颜色全反 |
| F/T 未重力补偿 | 🧠 学到"末端向下拉" |
| 模板化语言标注 | 📎 语言被完全忽略 |

#### 🚨 Benchmark 可信度警告（2025-2026 多篇论文证据）

> **这不是一个警告——是五个。** 每一个都有论文支持。

**警告 1：LIBERO 高分 = 记忆，不是泛化**

> "尽管现有模型在标准 LIBERO 上 90%+，在泛化设定下**跌到 0.0%**。模型依赖的是对训练集动作序列和环境布局的死记硬背，而不是真正的任务理解。"
> — [LIBERO-PRO (arXiv:2510.03827)](https://arxiv.org/abs/2510.03827)

**警告 2：VLA 完全忽略语言指令**

> "模型对语言变化基本不敏感。进一步实验揭示模型倾向于**完全忽略语言指令**。只喂视觉观测（遮蔽语言）的 vision-only 模型达到 44.6%，接近语言条件 baseline 的 47.8%。"
> — [LIBERO-PRO](https://arxiv.org/abs/2510.03827) + [LIBERO-Para (arXiv:2603.28301)](https://arxiv.org/abs/2603.28301)

**含义**：VLA 的 "L"（Language）在很多 benchmark 上可能是摆设。模型靠视觉快捷方式做任务，不需要理解指令。

**警告 3：轻微扰动导致崩溃**

> "模型对摄像头视角和机器人初始状态的扰动极端敏感，成功率从 95% 跌到 **30% 以下**。"
> — [LIBERO-Plus (arXiv:2510.13626)](https://arxiv.org/abs/2510.13626) · [LIBERO-X (arXiv:2602.06556)](https://arxiv.org/abs/2602.06556)

4 种扰动维度全部导致崩溃：
| 扰动 | 标准 LIBERO | 扰动后 |
|------|:----------:|:------:|
| 换物体 | 90%+ | <30% |
| 换初始位置 | 90%+ | ~0% |
| 换指令措辞 | 90%+ | 不变（因为根本不读指令）|
| 换环境 | 90%+ | ~0% |

**警告 4：仿真排名 ≠ 真机排名**

| 模型 | LIBERO (仿真) | 真机 | 跌幅 |
|------|:---:|:---:|:---:|
| π₀.₅ | 96.9% | 52-77% | -20~45 |
| VGA | 98.1% | 58-75% | -23~40 |
| WVA | 99.6% | 75.6% | -24 |

仿真 99.6% 和 96.9% 的差距（2.7%）在真机上完全消失。

**警告 5：真机 benchmark 也有问题**

> RoboChallenge Table30 只有 30 个桌面任务。GM-100 只测了 3 个机器人平台。两者都不包含移动操作、柔软物体、动态环境。真机 benchmark 的覆盖面仍然远远不够。

**警告 6：数据污染与评测泄漏（🧠 作者提出的风险假设）**

> 🧠 **这是作者根据 LLM 领域数据污染问题的类推，提出的 VLA 风险假设**。作者**未找到** VLA 领域针对 OXE-LIBERO 重叠的定量研究论文——这是领域的盲点，也是本警告价值所在：**提请关注，呼吁后续研究**。

📎 **LLM 数据污染已是成熟议题**：[How Contaminated Is Your Benchmark (arXiv:2502.00678)](https://arxiv.org/abs/2502.00678) 论证了预训练-评测重叠严重影响 LLM 性能读数。

🧠 **作者在 VLA 领域的类推推理**：
- OXE 包含 22 个子集（📎 事实，Google OXE 文档），其中若有子集的视觉内容与 LIBERO/CALVIN 的测试场景相似——相当于预训练时见过相关分布
- HuggingFace 上 "LIBERO demo" 数据集存在，预训练混合时是否过滤取决于实现者
- **但是没有论文系统测过 OXE-LIBERO 的 pHash / 嵌入空间重叠率**——这个数字我给不出

🧠 **建议的检测方法**（作者提出）：
1. pHash 比对——LLM 污染研究常用方法的类推
2. 语义嵌入空间距离
3. 新物体/场景的真机评测作为替代 benchmark

🧠 **作者观点**：真机 benchmark 相对仿真 benchmark 的可信度优势之一，是"物理世界无法被预训练数据完全覆盖"——这是定性论点，不是定量结论。

### 对研究者的建议

1. **不要只报 LIBERO 标准分**——必须同时报 LIBERO-PRO/Plus/X 的扰动结果
2. **做语言消融**——遮蔽语言后如果成功率不变，说明你的模型没用到语言
3. **报真机数字**——仿真 95%+ 的论文，如果没有真机验证，价值存疑
4. **报失败案例**——RoboMIND 2.0 包含了 5K 失败案例数据，这比只报成功率更有价值
5. **披露数据混合的来源**——预训练语料的子集构成必须可审计，否则无法判断是否泄漏

> - 快速验证想法 → LIBERO（⚠️ 注意饱和 + LIBERO-PRO 验证鲁棒性）

## 7. 仿真数据

### 仿真 vs 真实的权衡

| | 仿真 | 真实 |
|--|------|------|
| **成本** | 几乎为零 | $50-500/小时人工 |
| **规模** | 无限 | 受限于人力 |
| **物理精度** | 接触/摩擦/变形差 | 完美 |
| **视觉真实度** | Domain gap | 完美 |
| **安全** | 无风险 | 可能摔坏 |

### 主流仿真器

| 仿真器 | 维护者 | GPU 加速 | 适用 |
|--------|--------|:-------:|------|
| **Isaac Lab** | NVIDIA | ✅ | GR00T 训练标准 |
| **MuJoCo** | Google | ❌ | 物理精度最高 |
| **RoboCasa** | UT Austin | ✅ | 家庭场景 |
| **RoboGen** | — | ✅ | 自动生成任务 |

### Sim2Real 策略

1. **Domain Randomization**：随机化纹理/光照/物理参数 → 减少 domain gap
2. **仿真预训练 + 真实微调**：大部分数据仿真，少量真实做适配
3. **深度蒸馏**：在仿真中用完美深度训练，部署时用 Depth Anything 估计

→ 详见 [Isaac Lab](../deployment/isaac_lab.md)

## 9. MVP 数据集配方（从零到可用）

> 🧠 **本节为作者提出的工程建议**，不是某篇论文或产品的官方配方。具体数字（60/150/200-500）是作者基于 ACT/π₀/GR00T 论文的典型数据量的经验综合。你的实际需求可能差 2x。

### 单任务 MVP（比如"pick-and-place 积木"）

```
总量：60 条 demo（不是 50，留 10 条给验证集）
时长：约 2 人 × 半天
```

| 维度 | 数量 | 目的 |
|------|:---:|------|
| 桌面布置 | 3 种（整齐 / 杂乱 / 多物体） | 视觉多样性 |
| 物体颜色 | 4 种（红/蓝/绿/黄） | 语言-视觉关联 |
| 物体位置 | 6 个（2×3 网格） | 空间泛化 |
| 光照条件 | 2 种（明/暗） | 光照鲁棒性 |
| 采集员 | 2 人 | 策略多样性 |
| 失败+恢复 | 5 条 | F6 防御 |

**验收标准**：
- 所有 episode 质量检查通过（timestamp gap < 50ms 等）
- 归一化统计稳定（移除任何一条，统计不漂移 > 5%）
- **真机验证**：在采集外的位置能达到 70%+

### 多任务 MVP（比如"桌面操作套件"）

```
总量：10 任务 × 15 demo = 150 条
时长：约 2 人 × 3 天
```

每任务 15 条分布：
- 10 条**完美成功** demo
- 3 条**边界情况**（物体近边缘 / 视角边缘）
- 2 条**失败+恢复** demo

**语言标注**：每任务 ≥ 5 种不同表述（用 LLM 生成），避免 F5 语言解耦。

### 跨机器人 MVP（跨形态预训练）

如果你想做跨形态：**不要自己从零采**。现实的路径：
1. 拉 OXE 子集做基础（**CC BY 4.0，可商用**）
2. 自己采集 200-500 条目标机器人数据做微调
3. 用 GM-100 或自建真机 benchmark 评测

> 💡 **最易错**：不做真机验证就宣布 MVP 完成。仿真 95% 的 MVP 在真机可能 30%——**真机跑通才算数**。

## 10. 如何批判性阅读 VLA 论文的数据章节

> 🧠 **本节为作者总结的批判性阅读清单**——红旗/绿旗的依据主要来自 [§6 的 6 条警告](#6-开放数据集地图) 和 [§3.5 失效模式](#35-数据失效模式分类学)。

### 🚩 红旗（论文的数据声明存疑）

1. **只有 LIBERO 数据**，没有扰动版本（LIBERO-PRO/Plus/X）
   → 可能在刷记忆分，换物体就 0%
2. **没有真机实验**，纯仿真
   → Sim2Real gap 未知，结果价值存疑
3. **预训练数据只说"we use OXE + HuggingFace data"**，不披露具体子集
   → 可能与评测集泄漏
4. **语言标注是单一模板**（比如全是 `pick up the {obj}`）
   → 模型大概率忽略语言（F5）
5. **只报成功率，不报恢复能力**
   → 不知道真实部署遇到扰动会不会死机
6. **没有失败案例讨论**
   → 通常意味着作者没测过失败模式，或者测了没说
7. **算力/数据成本对比缺失**
   → "我们用 100x 数据 + 10x 算力"胜过 baseline，不是算法胜利

### ✅ 绿旗（论文的数据声明可信）

1. **LIBERO-PRO / LIBERO-Plus / LIBERO-X 扰动评测**
2. **真机实验，≥ 3 个环境 / 物体集**
3. **数据混合成分明细**（`OXE-subset-A 30% + DROID 40% + 自采 30%`）
4. **语言消融实验**（遮蔽语言后的性能）
5. **报失败案例**（至少定性分析）
6. **一致的数据集许可证披露**
7. **发布了数据清洗脚本 / 预处理代码**

### 读 OpenVLA / π₀ / GR00T 的数据章节的问题列表

| 问题 | 在论文里找 |
|------|-----------|
| 总轨迹数？每条平均长度？ | "Dataset Statistics" 表 |
| 形态分布？（单臂 / 双臂 / 人形） | "Embodiment" 子表 |
| 时戳同步方式？ | Appendix 的 Hardware Setup |
| 动作表示？归一化策略？ | "Action Space" / "Preprocessing" |
| 过滤了哪些数据？留下多少？ | "Data Curation" |
| 评测集与预训练集是否重叠？ | 通常**不说**——自己去比 pHash |

> 📐 **一个简单判准**：如果作者**没提**"我们怎么防止评测泄漏 / 我们怎么处理 F5 语言解耦"——大概率他们没处理。
