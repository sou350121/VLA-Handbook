## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 训练/推理 | 关键超参 |
|------|------|------|-----------|----------|
| 视觉编码器 | 224×224 图像 | D=768 DINOv2 CLS 特征 | 冻结（预训练） | DINOv2 vs DINOv3 vs CLIP |
| 视觉/动作投影器 | v_t ∈ R^D, a_t ∈ R^14 | z_t^v, z_t^a ∈ R^512 | 可训练 | 投影维度 512 |
| Mamba 编码器 | 交错序列 [z_1^v, z_1^a, ..., z_L^v, z_L^a] | h ∈ R^(2L×256) | 预训练 | 6 层, state_dim=256 |
| Transformer 解码器 | mask tokens + m=h_L^v | 重建的视觉+动作特征 | 预训练 | 2 层 |
| 下游策略 (DP/ManiFlow) | v_t ∥ m, p_t | a_t | 策略训练 | action_horizon=8, exec_chunk=6 |

**关键设计选择**：
- 预训练窗口 L=32 步，推理窗口 16 步（不帧跳过）
- 掩码比例 70%（时间步级别对齐掩码，视觉+动作同时掩）
- 最终视觉 token 始终保持可见——作为压缩锚点

### 1.2 关键机制 (Key Mechanism)

**为什么用交错序列而不是纯视觉序列？**
因为操作是动作驱动的——世界变化不是因为时间流逝，而是因为机器人执行了动作。纯视觉历史无法区分"灯自己亮了"和"我按了按钮灯亮了"。交错序列强制模型学习 action→state_transition 的因果结构。

**为什么用 Mamba 而不是 Transformer？**
Transformer 的输出 token 数与输入成正比，不适合压缩历史为固定大小。Mamba 的 selective SSM 机制天然维护一个隐状态，每个位置的输出都聚合了前面所有上下文，且计算复杂度线性于序列长度。

**为什么复用最终视觉 token 而不是添加专用 memory token？**
- 不引入额外参数（无 dedicated memory token）
- 最终视觉 token 本身编码了当前观测，在此基础上叠加历史信息，形成"当前感知 + 历史记忆"的融合表示
- 强制形成信息瓶颈——所有历史必须压缩进一个 512-D 向量

⚡ **Eureka Moment**：不添加专用记忆 token，而是复用序列中最后一个视觉 token 的 Mamba 编码输出作为历史压缩锚点——既零参数开销，又天然对齐下游策略的视觉输入接口。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
m = Enc_Mamba([(v_1,a_1),...,(v_L,a_L)])[v,last]
a_t = π(v_t, m, p_t)
L_AEM = λ_v·Σ_{t∈M} ℓ(v̂_t, v_t) + λ_a·Σ_{t∈M} ℓ(â_t, a_t)
```

**目标**：学习一个映射函数 g，将长程交互历史压缩为固定维度的紧凑状态 m，使得 m 既保留足够的时序信息用于重建被掩码的观测和动作，又能在下游策略中作为全局上下文提升控制性能。

**核心方程分解**：

```
重建损失: ℓ(ŷ, y) = ‖ŷ - y‖₂² + α·(1 - cos(ŷ, y))
总损失:   L_AEM = λ_v·Σ_{t∈M} ℓ(v̂_t, v_t) + λ_a·Σ_{t∈M} ℓ(â_t, a_t)
```

| 符号 | 含义 | 数值/范围 |
|------|------|-----------|
| v_t | t 时刻 DINOv2 CLS 视觉特征 | R^768 |
| a_t | t 时刻机器人动作 | R^14 |
| z_t^v, z_t^a | 投影后的 token | R^512 |
| M | 被掩码的时间步集合 | 70% 随机采样 |
| m | 紧凑历史表示 (h_L^v) | R^512 |
| α | 余弦距离权重 | 0.1 |
| λ_v, λ_a | 视觉/动作损失平衡系数 | 论文未明确给出具体值 |
| L | 预训练窗口长度 | 32 步 |

> 符号与本文保持一致。Mamba 状态转移 s_t = F(s_{t-1}, x_t)，输出 h_t = G(s_t)。最终视觉 token 位置 h_L^v 即为压缩后的历史表示 m。

**直觉**：掩码重建迫使模型学习"如果我看到了这些动作和观测，但缺少中间某些步骤，我能推断出什么"——这本质上是在学习 action→effect 的因果映射。最终 token 作为唯一的信息出口，必须编码所有对下游控制有用的时序依赖。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 4 步交互历史（论文实际用 32 步）：

```
t=1: v_1=[0.3, 0.7], a_1=[0.1, 0.0]  (手在物体上方，未接触)
t=2: v_2=[0.3, 0.7], a_2=[0.0, 0.1]  (闭合夹爪，物体被抓住)
t=3: v_3=[0.5, 0.2], a_3=[0.0, 0.0]  (物体离开原位置)
t=4: v_4=[0.5, 0.2], a_4=[0.1, 0.0]  (放置到新位置)
```

**掩码设置**：假设 t=2, t=3 被掩码（50% 掩码率，论文用 70%），t=1 和 t=4 可见。

**编码过程**：
1. 投影：z_1^v = P_v(v_1), z_1^a = P_a(a_1), 同理 t=4
2. 掩码后序列：[z_1^v, z_1^a, MASK, MASK, MASK, MASK, z_4^v, z_4^a]
3. Mamba 编码：h = Enc([z_1^v, z_1^a, MASK, MASK, MASK, MASK, z_4^v, z_4^a])
4. 提取：m = h_4^v（最终视觉 token 的编码输出）

**关键问题**：m 需要编码什么信息才能让解码器重建 t=2 和 t=3？
- 夹爪在 t=2 闭合了（动作信息）
- 物体在 t=3 离开了原位置（视觉信息）
- 这两个事件之间的因果关系：夹爪闭合 → 物体被提起 → 位置变化

**解码重建**（假设值）：
```
v̂_2 ≈ [0.3, 0.7]  (正确重建：物体仍在原处但夹爪状态变化)
â_2 ≈ [0.0, 0.1]  (正确重建：夹爪闭合动作)
v̂_3 ≈ [0.5, 0.2]  (正确重建：物体位置变化)
â_3 ≈ [0.0, 0.0]  (正确重建：无新动作)
```

**损失计算**（假设 MSE 误差为 0.05，余弦相似度为 0.95）：
```
ℓ(v̂_2, v_2) = 0.05 + 0.1·(1 - 0.95) = 0.055
L_AEM ≈ λ_v·(0.055 + 0.06) + λ_a·(0.04 + 0.05)
     ≈ 0.5·0.115 + 0.5·0.09 = 0.1025
```

这个损失通过反向传播更新 Mamba 编码器和投影器，使得 m 逐渐学会编码 action-effect 因果关系。

**关键工程洞察**：
- AEM 的 Mamba 编码仅需 0.80 GFLOPs（6 层 SSM，极轻量），而直接堆叠 16 帧 DINOv2 特征使 UNet 推理从 15.80G 增至 33.40G（+111%）
- AEM 总 FLOPs (41.70G) 与单帧 DINOv2 Concat (41.20G) 几乎相同，但成功率从 0.52→0.76（+46% 相对提升）
- 推理延迟：AEM 730ms vs 16 帧堆叠 824ms（-11%），因为 UNet 输入维度不变
- **工程含义**：AEM 把历史编码从策略侧（UNet/扩散去噪）移到了预训练编码器侧，用一次性的轻量 Mamba 前向传播替代了策略网络中的冗余计算

### 部署约束

- **预训练编码器冻结**：下游策略训练时 AEM 编码器参数固定，不增加策略训练负担
- **历史窗口固定**：推理时维护固定 16 步滑动窗口，内存占用 O(1) 不随任务时长增长
- **即插即用**：只需在策略输入拼接处加一个 concat 操作，不改动策略网络结构
- **视觉编码器依赖**：DINOv2 CLS token 效果最佳，替换为其他编码器需重新验证

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **非马尔可夫推理**：在 RMBench 上带来比标准任务更大的提升（图 5），说明历史表示确实编码了任务相关的时间依赖
- **抗视觉干扰**：在 randomized scenes 下 DP+AEM 保持比基线更高的成功率（图 4），历史上下文弥补了单帧的不确定性
- **跨策略迁移**：对 Diffusion Policy 和 ManiFlow 都有稳定提升，不绑定特定策略架构
- **真实世界迁移**：Franka 机械臂上平均成功率 43.3%→81.7%，在干扰物场景下 15%→68.3%

### 不能做什么 / 局限
- **未大规模验证**：论文明确承认"lack of large-scale pretraining validation"——所有实验基于小规模仿真+单台真实机械臂
- **单臂/双臂桌面局限**：实验仅覆盖桌面操作任务，未验证移动机器人、双臂协调（超出 RoboTwin 范围）、人形机器人等场景
- **窗口长度限制**：预训练用 32 步、推理用 16 步，对于需要更长记忆的复杂任务可能不够（图 8b 显示 32 步预训练+16 步推理最优，但也暗示更长窗口可能有害）
- **单向量瓶颈的信息损失**：512-D 向量要编码 32 步交错序列的全部信息，必然有信息损失——对于需要精细时序重建的任务可能不够
