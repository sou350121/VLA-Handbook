💡 **X-Ray 开场**
传统机器人视觉预训练只编码当前帧——但机器人操作是连续的，当前帧经常因为遮挡、接触变化或部分可观测而信息不足。AEM 的核心发现是：你不需要把历史帧堆起来喂给策略，而是可以在预训练阶段就把"动作导致了什么变化"压缩成一个向量，这个向量能显著提升策略在非马尔可夫任务和随机场景下的鲁棒性。对 VLA 研究者意味着——时间记忆可以像视觉特征一样被预训练和迁移，而不是在策略阶段临时拼凑。

### 1.2 关键机制 (Key Mechanism)

AEM 的设计围绕三个核心问题展开：

**问题1：什么构成有效的记忆表示？**
作者提出三个必要条件：
- 必须来自 vision-action 交互历史（而非纯视觉），因为操作是动作驱动的
- 必须是紧凑的——尺寸不随历史长度增长
- 必须捕获跨时间的交互结构，尤其是动作与状态转移的依赖关系

**问题2：如何做到紧凑？**
不添加专用记忆 token，而是**复用交错序列中最后一个视觉 token**，取其 Mamba 编码后的输出作为压缩锚点。Mamba 提供上下文序列建模能力，最终视觉 token 充当固定大小的信息瓶颈。

**问题3：如何确保压缩后的表示结构化可用？**
采用**掩码自编码 (MAE)** 目标——要求模型从不完整历史中恢复缺失内容。这迫使最终token表示必须编码跨时间依赖关系，包括"动作如何导致后续状态变化"。

⚡ **Eureka Moment**：不添加专用记忆 token，而是复用交错序列中最后一个视觉 token 的 Mamba 编码输出——它天然处于序列末端，已经"看到"了所有历史上下文，同时保持固定维度，完美充当信息瓶颈。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
m = Enc_Mamba({(v₁,a₁),...,(v_L,a_L)})[v_last]
L_AEM = λv·Σ L_mse(v̂,v) + cos(v̂,v) + λa·Σ L_mse(â,a) + cos(â,a)
```

**目标**：学习一个从长程 vision-action 历史到固定维度向量的映射函数 g，使得该向量 m 包含下游策略推断任务进度和交互状态所需的全部时间信息。

**核心方程**：

```
输入序列: x = [z₁ᵛ, z₁ᵃ, ..., z_Lᵛ, z_Lᵃ]     (交错投影)
编码器:   h = Enc_Mamba(x \ M)                  (可见token编码)
记忆提取: m = h_Lᵛ                              (最终视觉token输出)
解码重建: v̂_t, â_t = Dec(m, mask_tokens)       (对掩码位置t∈M)
损失函数: L_AEM = λv·Σ_{t∈M} l(v̂_t, v_t) + λa·Σ_{t∈M} l(â_t, a_t)
单步损失: l(ŷ, y) = ||ŷ - y||₂² + α·(1 - cos(ŷ, y))
下游策略: a_t = π(v_t, m_t, p_t)
```

**变量说明**：

| 符号 | 含义 | 维度 |
|------|------|------|
| v_t | t时刻视觉特征 (DINOv2 CLS) | 768D |
| a_t | t时刻机器人动作 | 14D |
| z_tᵛ, z_tᵃ | 投影到共享空间的 token | 512D |
| M | 掩码时间步集合 (70%采样) | — |
| h | Mamba编码器输出序列 | 512D × T |
| m | 紧凑历史表示 (最终token输出) | 512D |
| L | 历史窗口长度 | 32步 |
| α | 余弦距离权重 | 0.1 |
| λv, λa | 视觉/动作重建损失权重 | 论文未明确 |

> 符号与本文保持一致。论文未明确给出 λv 和 λa 的具体数值，推测为 1.0（标准MAE设置）。

**直觉**：Mamba 的选择性状态机制让它能"记住重要的、遗忘无关的"——不同于 Transformer 对所有 token 一视同仁地 attention。最终视觉 token 处于序列末尾，经过 Mamba 的递归状态传递后，它的编码输出已经聚合了所有可见历史步的上下文。掩码重建任务则确保这个聚合不是简单的平均，而是编码了"动作→状态变化"的因果结构。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的2D操作场景，历史窗口 L=4 步：

```
步骤 t=1:  v₁=[0.1, 0.3],  a₁=[0.0, 0.0]   (初始状态, 无动作)
步骤 t=2:  v₂=[0.2, 0.5],  a₂=[0.1, 0.2]   (手移动, 物体位置变化)
步骤 t=3:  v₃=[0.2, 0.4],  a₃=[0.0, 0.1]   (微调, 物体轻微偏移)
步骤 t=4:  v₄=[0.3, 0.6],  a₄=[0.1, 0.3]   (抓取完成)
```

**预训练阶段**（假设 t=2, t=3 被掩码，t=1 和 t=4 可见）：

```
可见序列: [z₁ᵛ, z₁ᵃ,  MASK,  MASK,  z₄ᵛ, z₄ᵃ]
                              ↑ 最终视觉token保持可见

Mamba编码后:
h₁ᵛ = f_Mamba(z₁ᵛ, z₁ᵃ)                              (仅看到第1步)
h₂ᵛ = f_Mamba(h₁ᵛ, MASK, MASK)                        (状态传递, 但输入为空)
h₃ᵛ = f_Mamba(h₂ᵛ, MASK, MASK)                        (继续传递)
h₄ᵛ = f_Mamba(h₃ᵛ, z₄ᵛ, z₄ᵃ)                          (看到最终状态)

提取: m = h₄ᵛ  (512D向量)

解码器从 m 重建掩码位置:
v̂₂ = Dec(m, pos=2), â₂ = Dec(m, pos=2)
v̂₃ = Dec(m, pos=3), â₃ = Dec(m, pos=3)

损失计算 (以 v₂ 为例):
l(v̂₂, v₂) = ||v̂₂ - v₂||₂² + 0.1·(1 - cos(v̂₂, v₂))
          = 0.05 + 0.1·(1 - 0.92)                     (假设重建余弦相似0.92)
          = 0.05 + 0.008 = 0.058

总损失 L_AEM = λv·(l(v̂₂,v₂)+l(v̂₃,v₃)) + λa·(l(â₂,a₂)+l(â₃,a₃))
```

**关键观察**：m 必须编码足够的信息来回答"t=2和t=3发生了什么"——但 t=1 和 t=4 之间只有两个动作 (a₁→a₄ 的间接影响)。Mamba 的选择性机制让 h₄ᵛ 能"记住" a₂ 和 a₃ 对状态转移的影响（通过 v₂ 和 v₃ 的变化间接推断），即使这两个时间步的原始 token 被掩码了。

**推理阶段**（下游策略使用 m）：

```
当前帧: v₅ = [0.35, 0.65]   (抓取后状态)
记忆向量: m = [0.12, -0.03, ..., 0.45]  (512D, 编码了前4步的交互历史)
策略输入: concat(v₅_proj, m) = [768D + 512D] = 1280D
策略输出: a₅ = π(v₅, m, "place object") = [0.05, -0.1, ...]
```

策略不再需要看到 v₁...v₄ 的原始帧——m 已经包含了所有必要的历史信息。

## 4. 工程视角 (Engineering View)

### 计算开销拆解 (Table II, Place Shoe 任务)

| 组件 | DP基线 (1帧) | DINOv2堆叠 (16帧) | DP+AEM (16步记忆) |
|------|-------------|------------------|-------------------|
| DINOv2 编码 | 0 G (ResNet backbone) | 22.0 G | 22.0 G |
| Mamba 编码 | 0 G | 0 G | **0.8 G** |
| ResNet 策略 | 2.37 G | 2.37 G | 2.37 G |
| U-Net 去噪 | 15.80 G | 33.40 G | 16.50 G |
| **总 FLOPs** | **18.20 G** | **57.80 G** | **41.70 G** |
| **总延迟** | **623.30 ms** | **824.21 ms** | **730.01 ms** |
| **FPS** | **1.60** | **1.21** | **1.37** |
| Clean 成功率 | 0.40 | 0.40 | **0.76** |
| Random 成功率 | 0.08 | 0.12 | **0.20** |

**工程含义**：

1. **Mamba 编码器开销极低**：6层 Mamba (d=256) 仅增加 0.8G FLOPs 和约 107ms 延迟，相比 16 帧堆叠节省 15.7G FLOPs 和 94ms
2. **U-Net 去噪是主要瓶颈**：占 DP 总 FLOPs 的 87%，AEM 通过提供紧凑记忆避免了 U-Net 处理多帧堆叠的额外开销（33.40G→16.50G）
3. **吞吐量影响**：AEM 的 1.37 FPS 低于纯单帧 DP 的 1.60 FPS，但远高于 16 帧堆叠的 1.21 FPS。对于需要 10Hz 控制频率的操作任务，两者都远低于要求——这意味着视觉编码和去噪都需要量化/蒸馏优化
4. **内存占用**：AEM 不需要缓存历史帧，仅需存储一个 512D 向量（2KB FP16），对嵌入式部署友好
5. **预训练成本**：200 epochs, batch_size=128, AdamW, 单卡 RTX 4090。预估约 24-48 小时（取决于数据量）

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **部分可观测任务**：当当前帧被遮挡或信息不足时，m 提供历史上下文帮助策略推断完整状态
- **非马尔可夫操作**：RMBench 上显著提升——策略能"记住"之前看到的物体配置
- **视觉扰动鲁棒性**：随机场景下 Place Shoe 从 40%→76%，Handover 也有显著提升
- **跨策略迁移**：对 DP 和 ManiFlow 两种不同策略家族均有效，证明 m 不绑定特定策略架构
- **低开销部署**：相比帧堆叠，FLOPs 降低 28%，延迟降低 11%，同时性能大幅提升

### 不能做什么（已知局限）
- **超长程依赖**：32步窗口外的历史无法编码——如果任务需要记住 60 步前的状态，AEM 无能为力
- **人形/移动机器人**：实验仅在双臂操作仿真和有限实机上验证，未测试全身控制或导航+操作
- **多任务泛化**：预训练似乎是任务特定的（在特定操作数据集上），未评估跨任务迁移能力
- **语言条件化**：AEM 本身不编码语言指令——语言条件由下游策略处理，AEM 只提供视觉-动作记忆

### 6.1 隐含假设 (Hidden Assumptions)

1. **最终视觉 token 足以承载全部历史**：论文假设 Mamba 编码后的最终视觉 token 能包含所有必要的历史信息。但 512D 向量对 32 步交互历史的压缩率极高——信息论上存在瓶颈。论文通过解码重建验证了信息保留度（Fig. 6 的对角线），但未量化信息损失的下界
2. **动作空间一致**：预训练和推理使用相同的 14D 动作空间。如果下游策略使用不同的动作表示（如关节空间 vs 末端执行器空间），需要额外的动作投影适配
3. **DINOv2 特征充分**：假设 DINOv2 CLS token 已经编码了足够的视觉信息。如果场景需要细粒度空间理解（如小物体抓取），CLS token 可能不够
4. **仿真到真实的 gap 可跨越**：预训练在仿真数据上进行，但直接用于真实机器人。论文声称实机验证成功，但未给出详细的 sim2real 分析

| **AEM (本文)** | **vision-action 历史** | **固定512D单向量** | **掩码联合重建** | **低 (+0.8G)** | **✅ 显式** |

**面试 Tip**：当被问到"AEM 和帧堆叠有什么区别"时，回答："帧堆叠把原始历史帧直接喂给策略，让策略自己学习时间依赖——这增加了计算开销且把表征学习和问题求解耦合在一起。AEM 在预训练阶段就把历史压缩成一个 512D 向量，策略只需接收当前帧加一个向量，计算开销更低且表征可迁移。"

## 8. 精讀建議 (Reading Guide)

- 需要评估在操作策略中引入时间上下文的工程师——AEM 的即插即用设计（仅 concat 一个向量）几乎不增加部署成本
- 对 Mamba 在机器人领域应用感兴趣的研究者——这是 Mamba 作为时序压缩器的一个干净案例

**建議章節路徑**：
