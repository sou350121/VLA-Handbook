### 1.2 关键机制 (Key Mechanism)

测量协议由四层组成：

1. **嵌套预算采样**：同一套件的训练集里使用相同的 B 条示范（较小预算嵌套于较大预算内），B 是**整个十任务套件**的条数，不是每任务条数。π 模型在 Spatial/Object/Goal 用 B ∈ {5,10,15,25,50}，在 Long 用 B ∈ {25,50,75,100}（作者说每套件 5 条在 Long 上“不足以取得进展”）。
2. **算力轴对齐**：所有 run 用 AdamW、有效 batch size 48，因此“一个 training step”在各模型间处理同样多样本，step 数可直接当作适应算力的度量。
3. **统一评测**：每个 checkpoint 评 400 episodes（每子任务 40 个），报告成功率；一次 run 的“best success”是所评 checkpoint 上的最高值。
4. **两个适应成本指标**：data-efficiency multiplier（数据轴）与 steps-to-X%（算力轴）。

⚡ **Eureka Moment**：把“预训练好坏”拆成两个可分别测量的量——**开箱即用能力**和**被改造的便宜程度**——然后证明这两者在现有开源 VLA 上并不相关，甚至反相关（GR00T N1.5 vs N1.6/N1.7）。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
multiplier = B_ref / B'，其中 B' = min{ B_test | best_success_cmp(B_test) ≥ best_success_ref(B_ref) }
```

**目标**：在只有离散预算网格可用的条件下，量化“模型 X 追上模型 Y 在 B 条示范下的成绩，需要多少条示范”。

**变量说明**：

| 符号 | 含义 | 本文取值 |
|------|------|---------|
| B_ref | 参考模型的示范预算（整套件条数） | 25 / 50 / 75 / 100 |
| B' | 被比较模型达到参考成绩的最小**已测**预算 | 5 / 10 / 15 / 25 / 50 / 75 / 100 |
| multiplier | 数据效率倍率 | 1.0×–5.0× |
| steps-to-X% | 全量数据下首次连续两次评估 ≥ X% 的训练步 | X ∈ {70, 80, 90} |

**算力轴指标**：

```
steps_to_X% = min{ s | succ(s) ≥ X% 且 succ(s_next_eval) ≥ X% }
```

其中 s 以“有效 batch size 48 的优化步”计，`s_next_eval` 是下一次被评测的 checkpoint。

**直觉**：这是一个**离散化的、保守的下界估计**。因为 B' 被限制在已测预算里，若被比较模型在最小已测预算（如 5 条）就已经达标，真实所需条数可能更少，此时 multiplier 是下界而非点估计（作者原文：`becomes a lower bound when B' is the smallest tested budget`）。

> **单位与时序一致性告警（本文自身的模糊点）**：正文说 π0.5 在 Spatial 全量数据上跑 1.6k steps“约 1.5 epoch”，而 Spatial 训练集只有 432 条示范、有效 batch 为 48。若 epoch 按“示范条数”定义，1.6k 步应约为 1600×48/432 ≈ 177.8 epoch，与“1.5”差两个数量级。因此本文的 “epoch” 几乎必然是在**时间步/帧层面**定义的，但正文没有给出这一定义。这意味着：**steps 与 epochs 之间不能跨套件随意换算**；同一套件内部（同一数据量）的 steps 比较仍然有效。

```
→ B' = 5（已是最小已测预算），multiplier = 25/5 = 5.0×
```

**例 3：反推 epoch 的隐含单位（验证 §2 的告警）**

> 假设：每条 LIBERO 示范平均含 F 帧，有效 batch 为 48，则每 epoch 步数 ≈ N_demo·F/48。

```
π0.5 on Spatial（全量）：N_demo=432，1.6k steps ≈ 1.5 epoch
  1.5 epoch → 1600 steps  ⇒ 每 epoch ≈ 1067 steps
  每 epoch 样本数 ≈ 1067×48 ≈ 51,200
  ⇒ F ≈ 51,200/432 ≈ 118.5 帧/条

π0 on Long（全量）：N_demo=379，16.9k steps ≈ 8 epoch
  每 epoch ≈ 2112.5 steps ⇒ 样本 ≈ 101,400 ⇒ F ≈ 101,400/379 ≈ 267.5 帧/条
```

两个反推值（约 119 与约 268 帧/条）落在同一数量级，说明“epoch 建立在帧层面”这一假设是自洽的；但 **F 本身正文未给出**，故以上仅为一致性检验，不能当作论文数据引用。

## 4. 工程视角 (Engineering View)

**吞吐与算力口径**：

- 有效 batch size 统一为 48，使“step”成为跨模型可比的**数据吞吐量**单位，但它**不是**可比的**真实计算量**单位——π 与 GR00T 的参数量、动作头结构（flow-matching vs diffusion-transformer）都不同，单步 FLOPs 必然不同。工程上若要换算墙钟时间，必须再乘各自的单步耗时，本文未给。
- 全量数据 run 长度从 1.6k steps（π0.5 on Spatial，约 1.5 epoch）到 16.9k steps（π0 on Long，8 epoch），跨度约 10 倍。这意味着**固定 step 预算做跨模型公平比较是危险的**：对 π0.5 是过训，对 π0 是欠训。

**评测分辨率与抖动**：

- 每 checkpoint 400 episodes（每子任务 40 个），单点成功率的名义分辨率为 0.25 个百分点，但正文**未报告置信区间或方差**，因此 1–2 个点的差异不可断言为真实差异（作者自己在讨论冻结 VLM 的小幅增益时就说“within evaluation noise”）。
- 部分全量数据 run 为省算力“每 200–1,100 steps 评一次”，作者明确说这会“bound the precision” of steps-to-X%。工程含义：**表 4 中相差几百步的两个数字不应被当作显著差异**，尤其当评估间隔本身就有上千步时。

**部署约束**：

- 若适配侧只能承受“只更新动作头”的成本（显存、优化器状态、训练时长都显著更低），本文的信号是：GR00T N1.5–N1.7 在 Spatial/Long 全量数据上冻结 VLM 后变化在 -5.5 到 +1.2 个点之间（Table 5），基本可用；π0/π0.5 则掉 23（Spatial）到 51–56（Long）个点，不可用。**这是条件性结论**：本文未测量显存与墙钟，只说“只训动作头”这一约束下的成功率后果。
- 训练配方差异是跨族对比的混淆项：π 用 lr 5e-5；GR00T 用 lr 与 weight decay 1e-5、5% warmup、cosine decay、grad clip 1。作者自己把跨族对比标为 “indicative only”。

### 6.1 隐含假设 (Hidden Assumptions)

1. **行为克隆即默认适应方式**。作者明确限定在这个范围内，但这也意味着结论不覆盖 LoRA、正则化微调、未来条件化等其他适应策略。
2. **“best checkpoint success” 是合理的 run 级指标**。这是一个取上确界的量，会系统性高估模型在任意时刻的可用性；正文未同时报告最终 checkpoint 或平均 success。
3. **不同模型的 step 可比**。有效 batch 相同使数据吞吐可比，但单步 FLOPs 不同，因此“算力”轴实际度量的是“样本消耗”而非“计算消耗”。
4. **示范的抽取方式不影响结论**。正文只说小预算嵌套于大预算，未说明抽样是否随机、是否分层到十任务。
5. **400 episodes 的评测噪声可忽略**。正文未给置信区间，而多处结论依赖 1–2 个点的差异比较（如 Table 3 中 1.7× 与 2.0× 的区别）。
6. **族内比较近似单变量**。π0 vs π0.5 架构相同（较强），但 GR00T 族内是同时改多因素（较弱）。
7. **“epoch” 单位统一**。见 §2 告警，正文未定义，跨套件换算不可靠。

## 8. 精读建议 (Reading Guide)

- **值得精读原文的人**：
  1. 正在为某个新场景做示范采集预算规划的机器人学习工程师——你需要 §3 的预算设定和 Table 2 才能估“采多少条起效”。
  2. 在多个开源 VLA 之间做基座选型的研究者——你需要 §4/§5 理解“零样本排名不能直接当选型依据”。
  3. 研究参数高效适配（冻结主干、只训 head）的人——§6 提供了“冻结 VLM 的代价随预训练配方而变”的对照证据。

- **建议章节路径**：先读 §3（Experimental Setup，尤其 B 的单位与 batch size 口径）→ 再读 §4 与 §5（两族内部结论，这是全文最扎实的部分）→ 然后 §6（最有意思但因果最弱的部分）→ 附录 Table 2 / Table 4 / Table 5 核对具体数字 → 可跳 §2 Related Work（领域定位清楚但非本文重点）。

- **不值得精读的理由**：如果你不做机器人策略学习、或已经熟悉“数据效率曲线 + compute-efficient fine-tuning”这套评估范式，读摘要加 §5.1 的跨族结论即可；本文的方法论贡献大于任何单点数字，而单点数字又受限于单一仿真基准与单种子。若你的关注点是真机部署、双臂/人形平台或真实世界泛化，本文当前版本提供不了证据，作者也自述真机实验尚在进行中。
