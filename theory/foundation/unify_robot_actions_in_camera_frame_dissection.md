💡 **X-Ray 开场**
这篇论文解决的核心问题是：不同机器人平台（Franka、UR5e、ALOHA 等）的动作表示互不兼容——关节维度不同、末端执行器定义不同、局部坐标系约定不同。作者发现，与其在策略网络中用多个 action head 或潜在空间来"绕过"这个问题，不如从根本上把动作统一到相机坐标系中。因为相机坐标系就是视觉观测的坐标系，动作和观测天然共享同一个几何参考系。

### 1.2 关键机制 (Key Mechanism)

**问题诊断**：现有动作表示的三大不一致
1. **关节角**：不同机器人关节数不同（Franka 7DOF vs UR5e 6DOF），语义也不同
2. **末端执行器位姿**：定义在机器人基座坐标系中，不同机器人基座位置不同；且通常记录的是法兰盘位姿而非工具中心点（TCP）
3. **Delta 动作**：局部坐标系约定不一致

**解决方案**：相机帧统一
- 核心观察：相机坐标系 = 视觉观测坐标系
- 动作表达在相机帧中 → 动作和观测天然共享几何参考
- 单臂：相机帧提供与基座位置无关的一致参考
- 双臂：两臂被同一相机观测，相机帧隐式编码了双臂空间关系

⚡ **Eureka Moment**：与其让策略网络学习"不同机器人的动作是什么意思"，不如把所有动作都放到相机坐标系中——这样动作和视觉观测共享同一个几何语言，策略网络只需要学习"在看到的坐标系中移动到哪里"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
T_tcp^c = T_b^c · T_flange^b · T_tcp^flange · S_tcp
```

**目标**：将任意机器人的末端执行器动作统一到相机坐标系中

**公式拆解**：

| 符号 | 含义 | 来源 |
|------|------|------|
| $T_b^c$ | 相机外参（基座→相机） | CalibAll 标定输出 |
| $T_{\text{flange}}^b$ | 法兰盘位姿（基座坐标系） | 正向运动学（关节角+URDF） |
| $T_{\text{tcp}}^{\text{flange}}$ | 工具偏移（法兰盘→TCP） | 夹爪 URDF |
| S_tcp | 标准化变换（统一局部帧约定） | 人工设计（z=前进方向, y=闭合方向） |
| $T_{\text{tcp}}^c$ | 最终动作（相机坐标系中的TCP位姿） | 上述四者链式乘积 |

**直觉**：这是一个四步坐标变换链。原始动作（关节角）→ 正向运动学得到法兰盘位姿 → 偏移得到 TCP → 标准化局部帧 → 变换到相机帧。每一步都在消除一种不一致性。

> 符号与本文保持一致：上标表示目标坐标系，下标表示源坐标系。$T_b^c$ 表示从基座坐标系 $b$ 到相机坐标系 $c$ 的刚体变换（$4 \times 4$ 齐次变换矩阵）。

**CalibAll 核心优化目标**（可微渲染 refinement）：
```
L(T_b^c) = || M - M_hat ||_2
M_hat = min(1, Σ_l π(T_b^c · T_l^b · l))
```

| 符号 | 含义 |
|------|------|
| M | SAM 分割得到的真实机器人掩码 |
| M_hat | 当前相机外参下渲染的机器人掩码 |
| $\pi$ | 可微分掩码渲染器 |
| l | 机器人连杆 |
| $T_l^b$ | 连杆到基座的变换（正向运动学） |

**直觉**：调整相机外参 $T_b^c$，使得用该外参渲染的机器人掩码与真实分割掩码尽可能一致。这是一个"渲染-比较-优化"的闭环。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有一个 Franka 机器人，相机固定在机器人侧前方。

**场景**：机器人执行"抓取杯子"动作，某一帧的关节角为 q = [0.1, -0.5, 0.3, -1.2, 0.0, 0.8, 0.5]

**Step 1 — 正向运动学**：
```
q → FK → T_flange^b = [R_3x3 | t_3x1]
R = [[0.9, -0.1, 0.4], [0.1, 0.99, -0.1], [-0.4, 0.1, 0.9]]
t = [0.35, 0.12, 0.45]^T  （米）
```

**Step 2 — Flange → TCP**（假设夹爪长度为 0.08m）：
```
T_tcp^flange = [I | [0, 0, 0.08]^T]
→ t_tcp = t + R·[0,0,0.08]^T = [0.382, 0.128, 0.457]^T
```

**Step 3 — CalibAll 标定得到相机外参**（假设）：
```
T_b^c = [R_bc | t_bc]
R_bc = [[0, 0, 1], [1, 0, 0], [0, 1, 0]]  （相机坐标系旋转90°）
t_bc = [-0.5, 0, 0.3]^T  （相机在基座左侧0.5m，上方0.3m）
```

**Step 4 — 变换到相机帧**：
```
t_tcp^c = R_bc · t_tcp + t_bc
       = [0.457, 0.382, 0.128]^T + [-0.5, 0, 0.3]^T
       = [-0.043, 0.382, 0.428]^T
```

**结果**：动作从基座坐标系的 [0.35, 0.12, 0.45] 变为相机坐标系的 [-0.043, 0.382, 0.428]。无论机器人基座放在哪里，只要相机位置不变，同一个视觉场景中的动作在相机帧中是一致的。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|-----------|----------|
| 标定精度（ADD） | 0.008m（8mm） | 亚厘米级，满足桌面操作精度需求 |
| 粗阶段误差 | 旋转 4.0°，平移 5.5cm | 足够进入细阶段收敛域 |
| 细阶段收敛域 | 旋转 ≤10°，平移 ≤7.5cm | 粗阶段必须保证在此范围内 |
| 数据规模 | 97K episodes, 527K frames | 中等规模，适合跨具身预训练 |
| 训练硬件 | 预训练 32×A100, SFT 8×A100 | 需要多卡集群，个人研究者难以复现 |
| 人工介入 | 追踪失败时需手动标注 | 大规模自动化仍有瓶颈 |
| 动作维度 | 统一 14D（7D×2臂） | 单臂用零填充，计算略有浪费 |

**关键 trade-off**：
- **精度 vs 自动化**：CalibAll 在 DREAM 数据集上达到 97.6 AUC，但在 DROID 上追踪成功率仅 15/20。复杂场景中的自遮挡是主要瓶颈
- **统一性 vs 灵活性**：14D 统一动作维度牺牲了单臂机器人的计算效率（50% 填充），但换来了单臂/双臂数据混合训练的便利性

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **跨平台动作统一**：Franka、UR5e、XArm7、ALOHA 四种平台动作统一到相机帧
- **单臂/双臂混合训练**：14D 统一维度允许单臂和双臂数据在同一 batch 中训练
- **离线数据集标定**：不需要访问物理机器人，从已有视频中恢复相机外参
- **辅助标注生成**：自动产生机器人 mask、bounding box、2D/3D 轨迹

### 不能做什么
- **复杂场景完全自动标定**：DROID 数据集上 5/20 场景追踪失败（论文 Appendix D）
- **动态相机**：假设相机-机器人相对位姿固定，不适用于手眼系统（eye-in-hand）
- **超出收敛域的初始化**：细阶段 refinement 在旋转 >10° 或平移 >7.5cm 时成功率急剧下降（表 3）

### 6.1 隐含假设 (Hidden Assumptions)

| 假设 | 验证情况 | 风险 |
|------|----------|------|
| 相机-机器人相对位姿固定 | 论文未明确讨论动态场景 | 手眼系统（camera on arm）不适用 |
| 末端执行器在视频中全程可见 | 需手动选择视频片段 | 长序列操作中 EEF 出帧会导致标定失败 |
| URDF 可用且准确 | 假设所有数据集提供准确 URDF | 非标准机器人或自定义夹爪可能无准确 URDF |
| 相机内参已知或可估计 | 部分数据集需通过 Moge 估计 | 内参误差会传播到外参标定 |
| SAM 分割足够准确 | 在杂乱场景/挑战性视角下可能不准确 | 需要人工介入选择正确 mask |
