### 1.2 关键机制 (Key Mechanism)

**三维度能力统一**：论文将 EFM 所需能力组织为三个互补维度，形成从感知→决策→执行的递进推理链：

1. **具身认知与空间推理**（4 个子维度）：空间关系理解、度量空间推理、3D 场景感知、物体/场景认知
2. **任务规划与修正**（5 个子维度）：长程任务分解、下一步规划、过程检测、错误定位、错误修正
3. **具身指向与定位**（4 种类型）：指代表达 grounding (REG)、区域指代表达 (RRG)、物体功能 grounding (OFG)、视觉轨迹生成 (VTG)

**关键设计选择**：
- 坐标作为普通文本 token 输出（归一化到 [0,1000]），而非引入特殊 token——更稳定且词汇表开销可忽略
- 坐标在推理步骤间持久化为可引用符号，保持多步推理中的视觉锚定
- 视觉编码器与 LLM 骨干联合训练（不冻结），因为具身场景的视觉分布与通用预训练数据差异显著

⚡ **Eureka Moment**：当 VLM 充分内部化了具身推理能力后，下游动作头的学习从"需要大规模动作预训练"降级为"只需学习从理解意图到连续动作的简单映射"——推理能力的内部化可以直接替代动作数据的规模扩张。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L_total = L_SFT + λ·L_RFT
L_SFT = -Σ_i log p_θ(y_i | x, y_{<i})    (标准因果语言建模)
A_i = (R_i - μ_group) / (σ_batch + ε)    (全局批次优势归一化)
```

**目标**：在单一模型中联合优化异构能力输出（自然语言推理、点坐标、轨迹序列），同时通过多任务平衡 RL 缓解不同能力间的梯度冲突。

**变量说明**：

| 符号 | 含义 |
|------|------|
| θ | 模型参数（8B，全参数微调） |
| x | 输入（图像/视频 + 文本指令） |
| y | 输出序列（文本推理 / 坐标 / 轨迹） |
| R_i | 第 i 个 rollout 的奖励（5 种奖励函数之一） |
| μ_group | 组内平均奖励（n=8 个并行 rollout 的平均值） |
| σ_batch | 全局批次标准差（混合批次中所有样本的 std） |
| λ | RL 阶段权重（KL 正则系数 β=0.01） |

**直觉**：SFT 阶段建立多任务基础能力；RFT 阶段用可验证奖励精炼——关键在于用全局批次 std 替代组内 std 做优势归一化，从而统一不同能力维度的梯度尺度，避免高资源任务主导梯度。

**奖励函数族**（5 类，匹配不同输出结构）：

| 奖励类型 | 适用输出 | 计算方式 |
|----------|----------|----------|
| Exact Matching | 文本 QA | 0/1 精确匹配 |
| IoU | 空间 grounding | 预测框与 GT 的 IoU |
| Point Distance | 点坐标 | 分段线性衰减 φ(d; τ_p, τ_z) |
| Trajectory RMSE | 轨迹序列 | 连续 RMSE + 分段线性衰减 |
| Semantic Similarity | 复杂推理 | 奖励模型 (RM) 打分 |

分段线性衰减函数：
```
φ(d; τ_p, τ_z) = clip((τ_z - d) / (τ_z - τ_p), 0, 1)
```
其中 d 为距离度量，τ_p 为正样本阈值，τ_z 为零奖励阈值。

> 符号与本文/相关文档保持一致：坐标归一化到 [0,1000]，轨迹为有序坐标序列。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个长程任务："把桌上的杯子放到碟子上"。

**Step 1 — Planner（规划）**：
```
输入: 图像 + "把杯子放到碟子上"
输出: [Sub-task 1: 定位杯子] → [Sub-task 2: 定位碟子] → [Sub-task 3: 抓取杯子] → [Sub-task 4: 移动到碟子上方] → [Sub-task 5: 放置杯子]
```

**Step 2 — Grounder（定位）**：
```
Sub-task 1 输入: "杯子"
输出: (x=450, y=320)  [归一化坐标, 图像分辨率假设为 640x480]

Sub-task 2 输入: "碟子"
输出: (x=720, y=380)
```

**Step 3 — 执行 + Corrector（修正）**：
假设执行 Sub-task 3（抓取）时失败（杯子滑落）。

```
Corrector 输入: 当前观察 + 失败信号
检测: "Sub-task 3 未完成"
定位: "执行失败 — 抓取力度不足或角度偏差"
修正: "回退到 Sub-task 3，调整抓取角度为 15°，增加夹持力度"
→ 重新进入 Planner 循环
```

**数字验证**：假设 PGC 循环中，Planner 生成 5 个子任务，每个子任务 Grounder 输出 1 个坐标点。如果 Sub-task 3 失败，Corrector 生成修正指令后重新执行。假设修正后成功，总执行时间 = 5 个子任务 × 平均 2.5 秒/任务 + 1 次修正 × 3 秒 = 15.5 秒。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|-----------|----------|
| 参数量 | 8B | 单卡 A100 80GB 可推理（bf16 约需 16GB）；微调需多卡（bs=512 暗示分布式训练） |
| 上下文长度 | 8192 tokens | PGC 多轮循环中需注意上下文累积——长程任务可能接近上限 |
| 训练批次 | 512（全局） | SFT 阶段需要大规模分布式训练集群 |
| SFT 学习率 | 2e-6, cosine decay, 10% warmup | 较小学习率，全参数微调需谨慎避免灾难性遗忘 |
| RFT 学习率 | 3e-6 | 比 SFT 略高，KL 正则 β=0.01 约束策略漂移 |
| RFT rollouts | n=8 并行 | 每步采样 8 个输出计算奖励差异，计算开销 ≈ 8×推理成本 |
| 坐标输出 | [0,1000] 整数 | 纯文本输出，无需特殊 token，推理时可直接解析 |
| VLA action chunk | 连续 7 维动作 | DiT flow-matching action expert 从 VLM 中间层提取特征 |
| 自适应计算 | 简单任务近零推理 token，复杂任务充分推理 | 推理时动态分配计算——指向任务快，规划任务慢 |

**部署约束**：PGC 闭框架在真实机器人上需要 2-5Hz 的控制频率。单次推理延迟（8B 模型 + 图像编码）若 >200ms，则闭环频率受限于 5Hz 以下。自适应计算机制天然适配这一需求——高频定位任务不需要长推理链。

### 6.1 隐含假设 (Hidden Assumptions)

1. **"推理能力可以替代动作数据规模"** — 这是论文的核心假设，实验在 4 个仿真/模拟基准上验证了这一点，但真实世界的分布偏移可能削弱这一结论。论文没有提供真实世界的大规模对比实验。
2. **"坐标作为普通文本 token 输出是最优方案"** — 论文声称这比特殊 token 更稳定，但没有与特殊 token 方案做消融对比。
3. **"低保真仿真数据足够训练轨迹生成"**（语义泛化假设） — 论文声称 VTG 关注拓扑结构和方向语义而非渲染保真度，但未提供高/低保真仿真的消融实验。
4. **"单一 8B 模型可以统一所有能力而不退化"** — 实验显示通用视觉能力保持良好（与 Qwen3-VL-8B 对比），但未量化各具身能力之间的相互影响（正/负迁移）。
5. **"PGC 闭框架的实时性可行"** — 论文展示了长程任务的成功执行，但未报告单次推理延迟和控制频率，实际部署时可能成为瓶颈。
