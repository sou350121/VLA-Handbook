### 1.2 关键机制 (Key Mechanism)

**核心思路**：将 VLA 的每个 action chunk 视为一个独立的"回答"，用 GRPO 算法在同一组 G=8 个采样结果中做组内相对优势估计，然后用三维过程奖励评估每个采样的质量。

**三个奖励维度**：

| 奖励 | 作用域 | 计算方式 | 取值范围 | 消融影响 |
|------|--------|----------|----------|----------|
| QACR (Quantized Action Consistency Reward) | 离散 token 层 | 预测 token 序列与 ground truth 的位置匹配率 | [0, 1] | 去掉降 2.8% |
| CTAR (Continuous Trajectory Alignment Reward) | 连续轨迹层 | 解码后位姿 L1 距离指数衰减 + 夹爪匹配 | [0, 1] | 去掉降 90.9% |
| FCR (Format Compliance Reward) | 格式层 | 二值：是否符合 Fast+ 分词器格式 | {0, 1} | 去掉降 2.6% |

**组合公式**：
```
r = ω·QACR + (1-ω)·CTAR + λ·FCR
其中 ω=0.7, λ=0.1
```

⚡ **Eureka Moment**：不需要环境交互也能做 RL——把整个 trajectory 评价拆解为每个 action chunk 的三维过程奖励，用专家演示的 ground truth 作为"参考答案"，模型自己采样、自己对比、自己优化。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
J_GRPO(θ) = E [ (1/G) Σ_i min[π_θ/π_old · A_i, clip(π_θ/π_old) · A_i] - γ·D_KL ]
```

**目标**：最大化 on-policy 采样的期望回报，同时用 KL 正则防止策略偏离参考模型过远。

**GRPO Advantage 计算**：
```
A_i = (r_i - mean({r_1, ..., r_G})) / std({r_1, ..., r_G})
```
组内归一化，不需要 critic network——这是 GRPO 相比 PPO 的关键简化。

**三维奖励组合**：
```
r = ω·QACR + (1-ω)·CTAR + λ·FCR
```

**QACR（离散动作一致性）**：
```
QACR = Σ_{ℓ=1}^{min(U,V)} I(a_ℓ = a~_ℓ) / max(U,V)    （格式合法时）
     = 0                                                （格式非法时）
```

**CTAR（连续轨迹对齐）**：
```
CTAR = (1/H) Σ_{t=1}^{H} [ β·exp(-α·d_t) + (1-β)·I(y_t^grip = y~_t^grip) ]
其中 d_t = (1/dim) · ||y_t^pose - y~_t^pose||_1
```

**符号说明**：
| 符号 | 含义 |
|------|------|
| $\pi_\theta$ | 当前策略参数 |
| $\pi_{\text{ref}}$ | 参考策略（SFT 后的初始模型） |
| G | 采样组大小（=8） |
| $\varepsilon$ | GRPO clip 范围（通常 0.2） |
| $\gamma$ | KL 正则系数 |
| $\omega$ | 离散/连续奖励权重（=0.7） |
| $\lambda$ | 格式奖励权重（=0.1） |
| $\alpha$ | 位姿误差敏感度（=5） |
| $\beta$ | 位姿/夹爪权重（=0.8） |
| U, V | 预测/ground truth token 序列长度 |
| H | action chunk 大小 |

> 符号与论文保持一致。QACR 和 CTAR 的"valid"条件均由 Fast+ 分词器格式检查决定。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2D 场景：

**场景**：机械臂需要将物体从 A 点移动到 B 点。
- action chunk 大小 H = 4（4 步动作）
- 每个动作 = (x, y, grip) 三维向量
- ground truth 轨迹: [(0,0,0), (1,0,0), (2,0,1), (2,1,1)]

**模型采样 3 个 action chunk**：

```
采样 1: [(0,0,0), (1,0,0), (2,0,1), (2,1,1)] → 完美匹配
采样 2: [(0,0,0), (1,0,0), (1,0,1), (2,1,1)] → 第 3 步 x 偏差 1
采样 3: [(0,0,0), (2,0,0), (2,0,1), (2,1,1)] → 第 2 步 x 偏差 1
```

**CTAR 计算**（$\alpha=5$, $\beta=0.8$）：

```
采样 1: d = [0, 0, 0, 0]
  r_pose = [1.0, 1.0, 1.0, 1.0]
  r_grip = [1, 1, 1, 1]
  CTAR = (1/4) × Σ [0.8×1.0 + 0.2×1] = 1.0

采样 2: d = [0, 0, 1/3, 0]  (第3步 x 偏差 1，dim=3)
  r_pose = [1.0, 1.0, exp(-5/3)=0.19, 1.0]
  r_grip = [1, 1, 1, 1]
  CTAR = (1/4) × [1.0 + 1.0 + (0.8×0.19+0.2×1) + 1.0]
       = (1/4) × [1.0 + 1.0 + 0.35 + 1.0] = 0.84

采样 3: d = [0, 1/3, 0, 0]
  r_pose = [1.0, 0.19, 1.0, 1.0]
  CTAR = 0.84（对称情况）
```

**GRPO Advantage**（假设 QACR=1.0, FCR=1.0 对所有采样）：

```
r_1 = 0.7×1.0 + 0.3×1.0 + 0.1×1.0 = 1.1
r_2 = 0.7×1.0 + 0.3×0.84 + 0.1×1.0 = 1.05
r_3 = 1.05

mean = 1.067, std ≈ 0.029

A_1 = (1.1 - 1.067) / 0.029 ≈ 1.14
A_2 = (1.05 - 1.067) / 0.029 ≈ -0.59
A_3 = -0.59
```

采样 1 获得正优势，参数更新会提高该轨迹的概率；采样 2/3 获得负优势，概率降低。这就是"自我对比、自我优化"的闭环。

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/描述 | 含义 |
|----------|-----------|------|
| GPU 需求 | 8×H20 (96GB HBM) | 全参数优化，不是 LoRA |
| GRPO group size | G=8 | 每次前向 8 个采样，显存占用大 |
| 学习率 | 1e-6 | 极小的 LR，反映 RL 微调的谨慎态度 |
| 数据需求 | 新任务 10 demo + 旧任务 5 demo replay | 相比 SFT 的 50 demo，数据效率提升 5× |
| 训练轮次 | 未明确（论文未给出 epoch 数） | TODO: 待补充 |
| 推理延迟 | 与 NORA-Long 相同（SFT 推理无额外开销） | RL 仅用于训练阶段 |
| 奖励计算开销 | 每个 chunk 需 decode + token match + L1 距离 | 轻量，无网络前向 |

**关键 trade-off**：
- **全参数 vs LoRA**：论文选择全参数优化，显存成本高但遗忘率低。LoRA 可能更高效但 KL 约束可能不足。
- **CTAR 主导**：消融实验显示 CTAR 占绝对主导（去掉降 90.9%），QACR 和 FCR 贡献较小。这可能意味着方法本质上是一个"连续轨迹监督信号"，RL 框架只是包装。
- **离散动作限制**：仅支持 Fast+ 分词器的离散动作模型，不直接适用于 $\pi_0$、OpenVLA-OFT 等连续动作模型。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **持续学习新任务**：LIBERO 上 4 个 suite 依次学习，平均成功率 94.8%（Object）、91.2%（Spatial）、90.3%（Goal）、64.5%（Long）—— Table IV
- **少样本适应**：5 demo 即可达到 SFT 50 demo 的效果（Fig 4）
- **真机部署**：Franka 机器人 4 个任务平均 87.5% 成功率，比 SFT 高 8.7%—— Table III
- **保持旧知识**：NBT 仅 1.5-12.8（LIBERO）和 6.1（真机），远低于 SFT 的 6.8-25.2

### 不能做什么 / 局限
- **长程任务仍弱**：LIBERO-Long 的 AUC 仅 64.5，显著低于其他 suite（Table IV）
- **仅离散动作**：论文明确承认"discrete action models performance falls short of continuous action models"—— §VI
- **奖励设计敏感**：CTAR 占绝对主导，方法本质上依赖轨迹对齐质量
- **无泛化到新机器人**：实验仅在 NORA-Long + Fast+ 框架下验证
