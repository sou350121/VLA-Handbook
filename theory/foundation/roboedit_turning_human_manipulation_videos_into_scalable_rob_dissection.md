## 1. 核心架构/方法总览 (Overview / Architecture)

RoboEdit 包含三个核心组件，形成从原始人类视频到机器人训练数据的完整流水线：

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 核心功能 | 是否需要训练 |
|------|------|------|----------|-------------|
| **RoboEdit-ADC** | RGB 人类视频 + 目标具身 e | 对齐的人类/机器人视频对 + 3D 轨迹 | 3D 重建 → 物理优化重定向 → 视频合成 | 否（工具链组装） |
| **RoboEdit-Trans** | 掩码人类视频 + 稀疏机器人关键帧 | 编辑后的机器人视频 + 3D 手部状态 | 跨具身视频编辑 + 3D 状态解码 | 是（微调 + LoRA） |
| **RoboEdit-14M** | 24,197 人类视频片段 | 174K 视频对 (14.1M 帧) | 大规模配对监督数据集 | 数据集（由 ADC 生成） |

**训练 vs 推理差异**：
- ADC 管线：一次性数据生成，无需训练
- Trans 编辑器：两阶段训练（先微调 backbone，再冻结 backbone 训练 LoRA + residual adapter）
- 3D State Decoder：两阶段训练（帧级空间估计 → 时序 Transformer  refinement）

### 1.2 关键机制 (Key Mechanism)

**为什么选择视频编辑而非从零生成？**
生成完整机器人交互视频容易破坏场景上下文并产生物理不可信的运动。RoboEdit-Trans 直接编辑 RGB 人类视频，保留原始场景、相机运动和物体动力学，只替换手部具身部分。

**跨具身适配的双模块设计**：
1. **LoRA 适配器**：适配不同机器人的外观和运动模式（时空表示层）
2. **Residual Adapter**：细化具身特定的手部几何和交互模式（特征层）

两者互补：LoRA 处理宏观差异，Residual Adapter 处理微观几何。

⚡ **Eureka Moment**：与其从零生成机器人视频（容易丢失场景上下文），不如直接编辑人类视频——保留一切不变，只替换手部具身，同时用 3D 状态解码器从编辑后的视频中"读懂"机器人的关节角度。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
F_θ(v^h_{1:T}, e) → (v̂^{r,e}_{1:T}, q̂^e_{1:T})
     │                      │            │
     │                      │            └─ 预测的机器人手部轨迹
     │                      └─ 编辑后的机器人视频
     └─ 以人类视频和目标具身为条件的映射函数
```

**重定向优化目标**（RoboEdit-ADC 的核心）：

```
L_ret = λ_track · Σ_t ‖q^e_t - q^{e,IK}_t‖²₂
      + λ_geo   · L_geo(穿透惩罚)
      + λ_contact · Σ_t Σ_k ‖p^e_k(q^e_t) - a_{t,k}‖²₂
      + λ_temp  · Σ_t ‖q^e_t - q^e_{t-1}‖²₂
```

| 符号 | 含义 |
|------|------|
| q^e_t | 目标机器人 t 时刻的关节配置 |
| q^{e,IK}_t | 逆运动学初始解 |
| L_geo | MuJoCo 碰撞检测的穿透 L2 惩罚 |
| L_contact | 接触点约束：机器人指尖到物体表面最近点的距离 |
| L_temp | 时序平滑：相邻帧关节差异 |
| p^e_k(·) | 正向运动学，将关节角映射为指尖 3D 位置 |
| a_{t,k} | 接触点 k 在 t 时刻的物体表面最近 3D 点 |

> 符号与本文保持一致：上标 h 表示人类域，r 表示机器人域，e 表示目标具身。

**视频编辑的目标函数**（基于 flow matching）：

```
ẑ^{r,e} = G_θ(z^h, z^{c,e})
```

其中 z^h 和 z^{c,e} 分别是掩码人类视频和稀疏机器人关键帧的隐表示，G_θ 是机器人条件编辑器。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有一段 81 帧的人类抓杯子视频：

**步骤 1 — 3D 重建**：
- HaMeR 估计每帧手部 21 关节：假设第 0 帧掌心深度估计为 0.8m（单目模糊）
- VGGT 估计场景深度图：掌心对应位置真实深度 0.6m
- 深度正则化计算缩放因子：0.6/0.8 = 0.75
- 将手部轨迹整体缩放 0.75 倍，掌心深度对齐

**步骤 2 — 重定向优化**：
- 初始 IK 解：Franka Panda 7 关节配置 q^{IK} = [0.1, -0.3, 0.0, 1.2, 0.5, 1.8, 0.8]
- 物理优化后：q = [0.08, -0.28, 0.02, 1.18, 0.52, 1.79, 0.79]
- 穿透惩罚从 0.015m 降至 0.002m，接触点误差从 8mm 降至 1.5mm

**步骤 3 — 视频编辑**：
- 输入：81 帧人类视频 + 9 个稀疏关键帧（索引 0, 10, 20, ..., 80）
- LoRA 适配 Franka 外观：rank r=16，参数量增加约 0.2%
- Residual Adapter 细化手指几何：down-projection 64→16→64
- 输出：81 帧机器人视频，编辑区域 LPIPS = 0.089（SOTA）

**步骤 4 — 3D 状态解码**：
- 帧级估计：2D 掌心 + 指尖 → PnP → 3D 腕部姿态
- 时序 Transformer refinement：帧间抖动从 3.2° 降至 0.8°
- 下游 PPO 跟踪：Franka 成功率 71%，XHand 成功率 62%

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- 将任意人类操作视频转化为 7 种机器人具身的交互视频
- 同步输出每帧 3D 手部状态（关节角 + 腕部姿态）
- 保留原始场景、相机运动和物体动力学
- 编辑质量 SOTA：SSIM 0.847、LPIPS 0.089、编辑区域 LPIPS 0.112

**不能做什么**（局限性）：
- 仅覆盖 7 种机器人具身，不支持任意新具身（需训练新 LoRA）
- 依赖高质量 3D 重建——极端视角/遮挡/快速运动下重建质量下降
- 编辑质量受限于 NovaEdit backbone 的生成能力
- 下游控制仅在仿真 + 单一 Franka 平台上验证，未测试多臂/移动操作

### 6.1 隐含假设 (Hidden Assumptions)

1. **单目 3D 重建足够准确**：HaMeR + VGGT 的组合在理想条件下工作良好，但实际人类视频（互联网规模）的视角和光照变化远大于训练数据分布
2. **物理优化可修复所有重建误差**：L_ret 优化能减少穿透和浮动，但对于严重误重建的交互（如手在物体内部），优化可能陷入局部最优
3. **编辑后的视频足以训练下游策略**：实验验证了 PPO 跟踪编辑后的轨迹，但未证明编辑视频直接用于 VLA 预训练的效果
4. **7 种具身覆盖主要机器人形态**：缺少人形双手、软体手、特殊工具等形态
