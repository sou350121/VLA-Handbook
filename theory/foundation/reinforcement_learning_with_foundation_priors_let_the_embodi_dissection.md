## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 维度 | Vanilla RL (DrQ-v2) | FAC (本文) |
|------|---------------------|------------|
| **奖励来源** | 人工设计 dense reward | FM 成功奖励 MR + 价值塑形 F = γ·MV(s') - MV(s) |
| **策略初始化** | 随机探索 | 策略先验 Mπ 引导（GPT-4V 代码 / 视频扩散） |
| **探索机制** | 纯随机噪声 (σ=0.1) | KL 正则到 Mπ + Critic 选优（actor vs prior） |
| **成功利用** | 无 | Success Buffer 存储成功轨迹，KL 模仿 |
| **样本效率** | 1M 帧仍多数失败 | 100k 帧 7/8 任务 100% 成功 |
| **人工工程** | 每个任务需设计 reward | 仅需低级 skill 接口 + FM 调用 |
| **泛化性** | 依赖 reward 设计质量 | 对噪声先验鲁棒（50% 噪声仍有效） |

### 1.2 关键机制 (Key Mechanism)

FAC 的核心设计哲学：**用基础模型回答三个问题**

1. **"我现在该做什么？"** → 策略先验 Mπ(s, T) 给出行为指导
   - 真实机器人：GPT-4V 生成代码策略（调用 move_to、grasp 等低级接口）
   - 仿真：视频扩散模型（Seer 微调）生成视频 + 逆动力学推断动作

2. **"我离目标更近了吗？"** → 价值先验 MV(s, T) 评估状态优劣
   - 使用 VIP 模型，输入当前图像 + 目标图像，输出状态价值
   - 通过 Potential-based Reward Shaping：F(s, s', T) = γ·MV(s', T) - MV(s, T)
   - 保证塑形奖励与原始 0-1 奖励共享最优策略（理论证明见论文 App A.1）

3. **"我成功了吗？"** → 成功奖励先验 MR(s, T) ∈ {0, 1}
   - 真实机器人：GPT-4V 判断最终帧是否成功（准确率极高，仅 Watering Plants 有 25% 误报）
   - 仿真：ground-truth 0-1 奖励 + 蒸馏噪声模型做消融

⚡ **Eureka Moment**：把基础模型的能力**对齐到 MDP 的三个核心函数**（策略 π、价值 V、奖励 R），而不是把它们当作黑盒特征提取器或策略生成器——这一对齐使得每个 FM 都有清晰的数学角色，可以分别优化、分别消融、分别替换。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L_actor = -E[min_k Q_k(s,a)] + KL(πφ || N(Mπ, σ²)) + KL(πφ || N(asucc, σ²))
R_total = λ·MR(s',T) + γ·MV(s',T) - MV(s,T)
```

先用目标，再给公式，再给变量说明。

**目标**：在仅有 0-1 成功奖励的 MDP 中，利用三个基础模型先验，使 Actor-Critic 在极少交互次数内学到成功策略。

**核心方程**：

```
奖励函数:
  R_G2(s, a, s') = λ · MR(s', T) + γ · MV(s', T) - MV(s, T)
  λ = 100

Actor 损失:
  L_actor(φ) = -E_D[min(Qθ1(s,a), Qθ2(s,a))]
              + α · KL(πφ(s), N(Mπ(s,T), σ²))
              + β · KL(πφ(s), N(asucc, σ²))   [仅当 Success Buffer 非空]
  α = β = 1, σ = 0.1

Critic 损失:
  L_critic(θ) = E_D[(Qθ(s,a) - y)²]
  y = Σ(i=0→n-1) γ^i · r(i) + γ^n · min(Qθ1'(s+n), Qθ2'(s+n))
```

**变量说明**：

| 符号 | 含义 | 来源 |
|------|------|------|
| Mπ(s, T) | 策略先验，输出高斯均值 | GPT-4V 代码 / 视频扩散逆动力学 |
| MV(s, T) | 价值先验，输出标量 | VIP 模型（当前图 + 目标图输入） |
| MR(s, T) | 成功奖励，0 或 1 | GPT-4V 判断 / ground-truth |
| πφ | 可训练 Actor 策略 | DrQ-v2 Actor 网络 |
| Qθ1, Qθ2 | 双 Q 网络 | Clipped Double Q-learning |
| D | 经验回放缓冲区 | 标准 RL replay buffer |
| asucc | 成功轨迹中的动作 | Success Buffer 采样 |
| λ | 成功奖励权重 | 100（强调稀疏成功信号） |

> 符号与本文保持一致。γ = 0.99（折扣因子），n = 3（n-step TD，论文未明确给出但 DrQ-v2 标准设置）。

**直觉**：策略先验给出"起点"（不要从零开始探索），价值先验给出"方向"（往价值高的状态走），成功奖励给出"终点信号"（做到了就强化）。KL 正则确保策略不会偏离先验太远（但有足够自由度去改进先验）。

## 3. 带数字走一遍：玩具例子 (Worked Example)

以一个简化的 2D 桌面操作任务为例：机械臂需要将方块推到目标位置。

**初始状态** s0：臂在 (0, 0)，方块在 (2, 0)，目标在 (5, 0)

**Step 1 — 策略先验 Mπ 引导**：
- GPT-4V 生成代码：先 move_to(2, 0) → grasp → move_to(5, 0) → release
- Mπ(s0) = (0.5, 0.0)（向右移动 0.5 单位）
- Actor 初始化接近随机，但 KL 正则将其拉向 Mπ

**Step 2 — 价值先验 MV 评估**：
- MV(s0) = -0.5（离目标远，价值低）
- 执行 a = (0.5, 0.0) 后到达 s1：臂在 (0.5, 0)，方块仍在 (2, 0)
- MV(s1) = -0.3（稍近了一些）
- 塑形奖励 F = γ·MV(s1) - MV(s0) = 0.99 × (-0.3) - (-0.5) = -0.297 + 0.5 = **+0.203**
- 正值！价值先验确认这个方向是对的

**Step 3 — 综合奖励**：
- MR(s1) = 0（还没成功）
- R = λ·0 + 0.203 = **0.203**

**Step 4 — 继续学习**：
- 若干步后到达 s5：臂接触方块在 (2, 0)，开始推动
- MV(s5) = 0.1（开始接近目标区域）
- F = 0.99 × 0.1 - (-0.3) = 0.099 + 0.3 = **+0.399**（更大正值，奖励增强）

**Step 5 — 成功**：
- 到达 s_final：方块在 (5, 0)
- MR(s_final) = 1
- R = 100 × 1 + 0 = **100**（巨大成功信号！）
- 该轨迹存入 Success Buffer

**Step 6 — KL 模仿**：
- 从 Success Buffer 采样动作 asucc
- L_succ = KL(πφ(s_final) || N(asucc, 0.01))
- Actor 被强化：在类似状态下更可能输出成功动作

**关键观察**：
- 塑形奖励 F 在整个过程中提供了**连续的梯度信号**，解决了 0-1 奖励的稀疏性问题
- Potential-based 保证了 F 不会改变最优策略（Ng et al. 1999 经典结论）
- 成功信号 λ=100 确保了最终目标的优先级远高于中间状态

## 4. 工程视角 (Engineering View)

| 维度 | 数值/设置 | 工程含义 |
|------|-----------|----------|
| 真实机器人训练时间 | 1 小时/任务 | 每次交互约 1-2 秒，~2000-3000 步 |
| 仿真训练帧数 | 100k-400k 帧 | 约 1-4 小时 GPU 训练（单卡） |
| UTD 比率 | 高（DrQ-v2 默认 10-20） | 每步数据多次更新，提升样本效率但增加计算 |
| Actor 标准差 | 固定 σ = 0.1 | 简化探索，不学习方差参数 |
| 策略先验调用频率 | 每步（初始）→ 逐渐减少 | 随训练进行，Critic 更多选择 Actor 动作（图 4） |
| GPT-4V 调用频率 | 每轨迹 1 次（仅最终帧） | 极低频，API 成本可控 |
| VIP 调用频率 | 每步 2 次（s 和 s'） | 高频但本地推理，延迟 ~10-20ms |
| λ 参数 | 100 | 成功信号远强于塑形奖励，确保最终目标优先 |

**部署约束**：
- 需要实时访问 VIP 模型（本地 GPU）和 GPT-4V（API）
- 代码策略先验需要预定义低级 skill 接口（move_to、grasp 等），这是**最大的人工工程点**
- 仿真中使用视频扩散先验需要微调 Seer 模型（每任务 10 个视频），虽然少但仍需领域数据

**Trade-off**：
- 策略先验质量 vs 泛化性：更好的先验 → 更高的样本效率，但需要领域微调
- 成功奖励精度 vs 通用性：GPT-4V 通用但偶有误报（Watering Plants 25%），GT 精确但不通用

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

| 能力 | 证据 | 条件 |
|------|------|------|
| 1 小时内学会新操作任务 | 真实机器人 86% 平均成功率 | 有 GPT-4V 代码先验 + VIP 价值先验 |
| 适应物体位置变化 | 评测时物体位置在范围内变化 | 变化范围不大 |
| 从粗糙先验中学习 | 离散化策略（-1/0/+1）仍有效 | 困难任务需要更多帧 |
| 容忍噪声先验 | 50% 均匀噪声下多数任务仍 100% | 系统性 50% 错误方向时失败 |
| 无需人工 dense reward | 仅用 0-1 成功信号 | 需要 FM 提供成功判断 |

### 不能做什么

| 失败模式 | 原因 |
|----------|------|
| 50% 系统性错误方向先验下崩溃 | 误导性信息过多，KL 正则将策略拉向错误方向 |
| 无策略先验时困难任务（bin-picking, door-unlock）收敛慢 | 缺乏初始行为指导，探索空间过大 |
| 无价值先验时样本效率下降 | 缺少中间梯度信号，依赖稀疏成功反馈 |
| GPT-4V 在仿真图像上表现差 | 域差异（渲染图 vs 真实照片） |
| 需要预定义低级 skill 接口 | 限制了可自动化程度 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **成功判断可以高度准确**：假设 MR 的误报率很低。但 Watering Plants 任务中 GPT-4V 有 25% 误报率（将水平持壶误判为浇水成功），这可能污染 Success Buffer。
2. **价值先验至少有一定相关性**：VIP 模型在未见任务上的价值估计可能完全错误，但论文假设"噪声但有方向性"。消融中直接移除 MV 而非测试更差的替代方案。
3. **低级 skill 接口已存在**：真实实验依赖预定义的 move_to、grasp、release、rotate_anticlockwise 接口。如果机器人平台不同，需要重新工程化。
4. **任务有明确的成功判定**：0-1 成功奖励假设任务有清晰的终点状态。对于连续任务（如持续跟踪），框架需要扩展。
5. **单任务学习**：每个任务独立训练 1 小时，没有测试多任务/持续学习场景。
