## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | VLA-Adapter 基线 | ReflexVLA 增强 | 输入 | 输出 |
|------|-----------------|---------------|------|------|
| 视觉编码器 | DINOv2 + SigLIP ViT @ 224×224 | 同基线 + 批处理优化 | 多视角 RGB | patch-level 特征 |
| 时间建模 | 无（单帧） | 因果时序注意力（中间层特征） | T=2 帧历史 | 融合后单帧特征 |
| 未来预测 | 无 | 潜空间预测（H=8 个 learnable tokens） | 当前多模态序列 | 未来 DINOv3 特征 |
| 语言骨干 | Qwen2.5-0.5B | 同基线（token 数不变） | 视觉+语言 tokens | 隐状态 |
| 动作头 | 连续回归 head | 同基线 | action queries | 8-step action chunk |
| 推理优化 | 逐帧编码 + 标准 GPU 调用 | 批编码 + CUDA Graph 回放 | 观测 buffer | 动作 chunk |

**训练/推理差异**：未来预测和时间融合仅在训练时激活，推理时仅保留前向通路；CUDA Graph 仅在部署时捕获一次，后续直接 replay。

### 1.2 关键机制 (Key Mechanism)

**设计动机**：动态操作需要两个能力——(1) 预判未来状态而非仅响应当前观测；(2) 在有限延迟内完成推理。现有方法要么只做预测（引入额外计算开销），要么只做加速（缺乏未来感知），ReflexVLA 将两者统一。

**关键设计决策**：
- **潜空间预测而非像素预测**：直接在 DINOv3 语义特征空间做预测（1024 维），避免像素级生成的计算浪费和低层细节干扰
- **时间融合放在视觉骨干内部**：对中间层特征做因果注意力，而非将多帧 token 全部送入语言模型——这样语言模型的 token 消耗量与单帧设置完全相同
- **系统级优化与架构解耦**：批编码和 CUDA Graph 不修改策略架构或学习目标，纯粹减少部署开销

⚡ **Eureka Moment**：在视觉骨干的中间层做因果时序融合，语言模型只看到融合后的单帧表征——用零额外 token 代价获得时序感知能力。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L = L_act + 0.05 · Σᵢ mᵢ[1 - cos(ŷ_{t+i}, y_{t+i})] / Σᵢ mᵢ
  └── 动作损失 ─┘  └────────── 潜空间未来预测损失 ──────────┘
```

**目标**：让 VLA 在预测动作的同时，学习对未来视觉状态的内隐表征，从而在动态场景中做出更有预判性的决策。

**核心方程分解**：

步骤 1 — 未来语义特征提取（冻结编码器）：
```
y_{t+i} = φ_DINOv3(o_{t+i}),   y_{t+i} ∈ R^1024
```

步骤 2 — 未来 token 预测：
```
ŷ_{t+i} = f_pred(h_i^future),   i = 1, ..., H
```
其中 H = chunk size（与动作预测的步数对齐），每个未来步仅用 1 个 token 表示。

步骤 3 — 掩码余弦相似度损失：
```
L_future = Σᵢ mᵢ[1 - cos(ŷ_{t+i}, y_{t+i})] / Σᵢ mᵢ
```
mᵢ 是有效性掩码（未来观测不可用时为 0）。

步骤 4 — 总损失：
```
L = L_act + λ_future · L_future,   λ_future = 0.05
```

**时间融合方程**：
```
z_{v,p,1:T} = Down(LN(x_{v,p,1:T}^mid)) + e_{1:T}     (降维 + 位置编码)
Δx_{v,p,t} = Up(MHA_causal(z_{v,p,1:T})_T)             (因果注意力 → 运动线索)
x̃_{v,p,t} = x_{v,p,t}^final + Δx_{v,p,t}              (残差融合)
```

> 符号说明：V=视角数, T=历史帧数(=2), P=patch数, D=特征维度, H=预测步长(=8), mᵢ=有效性掩码

**直觉**：未来预测损失鼓励表征空间"知道"下一步会发生什么；时间融合让每个 patch 的特征携带运动历史。两者都不增加推理时的 token 数量——预测 token 仅在训练时存在，时间融合的输出被折叠进单帧表征。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设 Conveyor Belt 任务中，机器人在 t=0 时刻看到传送带上的立方体位置为 (x=0.3, y=0.1)。

**时间融合**：
- T=2 帧：t=-1 时立方体在 (0.2, 0.1)，t=0 时在 (0.3, 0.1)
- 中间层特征对同一 patch 位置：x_{v,p,-1}^mid 和 x_{v,p,0}^mid
- 因果注意力处理后：Δx_{v,p,0} 编码了"向右移动"的运动方向
- 融合后：x̃_{v,p,0} = x_{v,p,0}^final + Δx_{v,p,0}，单帧特征现在隐含了运动趋势

**未来预测**：
- H=8 个 learnable future tokens 被追加到多模态序列
- 经过 Transformer 后，第 i 个 future token 的隐状态 h_i^future 被投影到 R^1024
- 假设 i=1（下一步）：ŷ_{t+1} 预测 DINOv3 特征，与真实 y_{t+1} 的余弦相似度 = 0.85
- L_future 贡献 = 1 - 0.85 = 0.15（对该步）
- 总 L_future = 平均 across H=8 步（假设平均余弦相似度 0.78 → L_future ≈ 0.22）
- 总损失 = L_act + 0.05 × 0.22 = L_act + 0.011

**关键洞察**：λ_future = 0.05 很小，说明未来预测是辅助目标——主要信号仍来自动作损失。但消融实验显示，去掉这个辅助目标，成功率从 73.8% 降至 62.8%（+26.0% 差距），说明即使权重很小，预测信号对表征质量影响显著。

**消融实验关键数字**（Table III）：

| 渐进组件 | 成功率 SR(%) | 延迟 Lat(ms) | 增量 |
|---------|-------------|-------------|------|
| Baseline (VLA-Adapter) | 36.8 | 81.5 | — |
| + 未来预测 (frozen DINOv3) | 62.8 | 82.5 | +26.0 |
| + 时序融合 (MHA, 中间层) | 71.7 | 125.1 | +34.9 |
| + 批编码 + CUDA Graph | 73.8 | 65.0 | +37.0 |

注意：时序融合增加了延迟（125ms vs 82ms，因为处理 2 帧），但批编码 + CUDA Graph 将延迟大幅降至 65ms——比基线还低 20%。

## 4. 工程视角 (Engineering View)

### 延迟分解

| 阶段 | 基线 (ms) | ReflexVLA (ms) | 优化手段 |
|------|----------|---------------|---------|
| 视觉编码 (V×T 次前向) | ~30 | ~12 | 批处理：V×T 张图一次前向 |
| 时间融合 | 0 | ~15 | 新增模块（中间层 MHA） |
| 语言模型推理 | ~40 | ~35 | CUDA Graph 消除 kernel 调度 |
| 动作头 | ~10 | ~8 | CUDA Graph 优化 |
| **总计** | **~81.5** | **~65.0** | **净降 20%** |

### 部署约束

- **GPU 要求**：论文使用 NVIDIA RTX 5880 Ada（单卡），1B 参数模型内存占用约 2-4 GB（含 KV cache）
- **控制频率**：异步推理 + chunk size=8 + horizon=2 → 有效执行频率 = 推理频率 / 2。在 30Hz 推理频率下，每 2 步执行后重新推理
- **显存 trade-off**：多帧融合在视觉骨干内完成，语言模型 token 数不变 → 不增加 KV cache 压力。这是与"直接拼接多帧 token"方案的关键区别
- **CUDA Graph 前提**：计算图必须固定。ReflexVLA 的架构满足此条件（固定层数、固定输入形状），但动态路由或条件计算的 VLA 不适用

### 工程含义

ReflexVLA 的延迟优化策略（批编码 + CUDA Graph）是**架构无关的**——可以应用于任何计算图固定的 VLA 部署。对于需要高控制频率（≥30Hz）的反应关键型任务，这两个优化是"低 hanging fruit"，实现成本远低于模型压缩或蒸馏。

### 延迟感知评估协议

ReflexBench 的核心创新之一是**不暂停环境**的评估方式：
- **同步推理**：模拟器暂停 → 推理 → 等待延迟 → 执行动作
- **异步推理**：机器人在执行上一周期动作的同时，策略在推理新动作
- **RTF (Real-Time Factor)**：RTF = t_sim / t_wall，用于将真实推理延迟映射到仿真延迟

### 6.1 隐含假设 (Hidden Assumptions)

1. **DINOv3 特征空间是稳定的预测目标**：论文发现可训练目标导致性能崩溃（36.8% → 4.9%），冻结目标才有效。这隐含假设了预训练视觉表征的稳定性——如果换用不同的预训练模型，效果可能不同。

2. **中间层特征比最终层更适合时序融合**：消融实验证实了这一点（71.7% vs 较低值），但未解释为什么——可能是中间层保留了更多局部运动线索，也可能是最终层过度语义化丢失了位置信息。

3. **CUDA Graph 适用于所有 VLA 部署**：前提是计算图固定。对于支持动态 token 数量或条件路由的 VLA（如 MoE 架构），CUDA Graph 不适用。

4. **200 条演示/任务足够**：在 ReflexBench 的 6 个任务上，200 条演示即可训练出超越大模型的策略。但这可能因为仿真任务的演示质量高（规划+RL 生成），真实世界可能需要更多数据。
