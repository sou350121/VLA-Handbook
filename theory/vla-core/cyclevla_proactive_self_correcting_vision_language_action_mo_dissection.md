💡 **X-Ray 开场**
传统 VLA 一旦执行出错就会"一条道走到黑"——它没有自我意识来判断自己做得好不好。CycleVLA 的核心突破是让 VLA 学会"感知自己做到哪了"（进度预测），在子任务快完成时请 VLM 判断"这样下去会不会失败"，如果会就回溯到前一个子任务重试，并用 MBR 从多个候选动作中选最稳健的一个。这就像给机器人装了一个"内省"机制。

### 1.2 关键机制 (Key Mechanism)

**为什么扩展动作维度而不是单独的分类头？**
论文选择将 stop 信号 s_t 和进度 p_t 直接拼接到 7 维连续动作输出中，形成 9 维输出。这样做的好处是：
- 不需要修改 VLA 架构（仅增加 2 个输出维度）
- 与现有 VLA 的连续动作空间天然兼容
- 共享表征让进度预测受益于动作预测的梯度信号

**子任务分解的数据构建策略：**
1. LLM 将任务指令分解为原子子任务序列
2. 从机器人 proprioception 提取 gripper 状态（open/close/idle）和运动基元
3. 如果 LLM 子任务数量与 gripper 状态段数量匹配 → 直接对齐
4. 否则 → 用 LLM 从运动基元序列推断子任务时间边界

⚡ **Eureka Moment**： failures 最常发生在子任务转换点，而子任务接近完成时的进度信号是预测失败的最强线索——与其等失败了再补救，不如在"快做完但可能做歪了"的时候提前预判。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
a_MBR = argmin_{a⁽ⁱ⁾ ∈ A}  (1/N) · Σ_j d( φ(a⁽ⁱ⁾), φ(a⁽ʲ⁾) )
```
选那个跟所有候选都"最像"的动作——共识即稳健。

### 2.1 扩展动作空间

标准 VLA 输出 7 维：
```
a_t = [Δx_t, Δy_t, Δz_t, Δu_t, Δv_t, Δw_t, γ_t] ∈ R^7
```

CycleVLA 扩展为 9 维：
```
a_t = [Δx_t, Δy_t, Δz_t, Δu_t, Δv_t, Δw_t, γ_t, s_t, p_t] ∈ R^9
```

| 符号 | 含义 | 范围 | 离散化 |
|------|------|------|--------|
| s_t | 子任务停止信号 | {0, 1} | 阈值化 |
| p_t | 子任务进度 | [0, 1] | 0.1 步长 bins |

**训练策略**：每个子任务最后一步过采样 ×8（NaVILA 策略），强化终止检测。

### 2.2 MBR 解码

目标：从 N 个采样候选中选出贝叶斯风险最小的动作序列。

```
L(a⁽ⁱ⁾) = (1/N) · Σ_{j=1}^{N} d( a⁽ⁱ⁾, a⁽ʲ⁾ )
a_MBR = argmin_{a⁽ⁱ⁾ ∈ A} L(a⁽ⁱ⁾)
```

距离函数 d 作用于累积轨迹特征：
```
φ(a) ∈ R^{6H}  // 累积平移(x,y,z) + 旋转(u,v,w)，每步6维，共H步
d = L2 距离
```

**直觉**：成功的行为在策略输出空间中聚集在高密度区域。MBR 选的是"跟大多数采样结果最一致"的动作——它不一定最优，但最不可能出错。

> 符号与本文保持一致：π_θ 为 VLA 策略，H 为动作 chunk 大小，N=8 为采样数，τp=0.9 为进度触发阈值。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个"把牛奶放进篮子"的子任务，chunk 大小 H=4：

**Step 1 — 正常执行：**
- VLA 输出 a_t，解析出 ã_t（7 维动作）、s_t=0（不停止）、p_t=0.3（进度 30%）
- 继续执行

**Step 2 — 进度达到阈值：**
- p_t=0.9（进度 90%），触发 VLM 检查
- VLM 看到：夹爪偏离牛奶盒 5cm，即将推倒而非抓起
- VLM 输出：backtrack → 回到子任务 1（"移动到牛奶上方"）

**Step 3 — 回溯 + MBR 重试：**
- 反向执行 delta 动作，回到子任务 1 起始位姿
- 从 π_θ 采样 N=8 个候选动作 chunk
- 计算 8×8 距离矩阵：

```
        cand1  cand2  cand3  ...  cand8
cand1    0.0    0.8    1.2    ...  0.9
cand2    0.8    0.0    0.5    ...  0.7
cand3    1.2    0.5    0.0    ...  1.1
...
```

- 计算每个候选的平均距离（行均值）：
```
L(cand1) = (0.0+0.8+1.2+...+0.9)/8 = 0.85
L(cand2) = (0.8+0.0+0.5+...+0.7)/8 = 0.52  ← 最小！
L(cand3) = (1.2+0.5+0.0+...+1.1)/8 = 0.91
```
- 选择 cand2 作为 MBR 最优候选，推入动作队列执行

**Step 4 — 成功：**
- cand2 对应的轨迹更"保守"（与多数采样一致），成功抓起牛奶
- p_t 继续增长，VLM 再次检查 → transit
- s_t=1 → 子任务完成，进入下一个

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|-----------|----------|
| VLA 推理 | 1×A10 GPU, 扩散采样 | 每步一次前向传播，chunk H 步动作 |
| VLM 查询 | GPT-5.2, temperature=1.0 | 每个子任务边界 1 次 API 调用（τp=0.9 触发） |
| MBR 采样 | N=8 次前向传播 | 回溯后额外 7 次推理（第 1 次已做） |
| 回溯延迟 | 反向执行 delta 动作 | 无环境重置，仅机械臂回到位姿 |
| 最大重试 | R 次（论文未明确，需配置） | 防止无限回溯循环 |
| 超时 | T_max | 防止单个 episode 无限运行 |
| 训练硬件 | 4-8×A100 (40GB) | 标准 VLA 微调规模 |

**关键 trade-off**：
- MBR 采样数 N 越大 → 共识越可靠，但推理成本线性增长
- 论文 Table IV 显示：N=8 时 Psucc 显著提升，但 N>8 后收益递减（待补充具体数字）
- VLM 查询频率 = 子任务数量 K（每个子任务边界最多 1 次），长程任务 K 大时 API 成本累积

**部署约束**：
- 真实机器人使用 AgileX PiPER 臂，控制频率未明确披露
- VLM 使用闭源 GPT-5.2，生产环境需考虑替代方案（开源 VLM 如 Qwen-VL）
- 回溯不恢复物体状态 → 适用于物体位置不变的场景，不适用于动态环境

| 人为注入扰动 | 修正 ~80% 注入失败 | Abstract, §V-C |

### 不能做什么 / 局限

1. **感知偏移严重时收益有限**：相机和机器人状态扰动下，OpenVLA-OFT-Diff 增益较小——因为底层策略本身不可靠，纠错无法弥补感知失效
2. **依赖外部 VLM**：GPT-5.2 是闭源 API，延迟和成本在生产环境中是瓶颈
3. **不恢复物体状态**：回溯只恢复机械臂位姿，如果物体已被推远/打翻，重试仍可能失败
4. **子任务分解质量依赖 LLM**：GPT-4.1 的子任务分解质量直接影响整个系统的上限
5. **仅适用于有明确子任务边界的操作任务**：连续控制任务（如平衡、跟踪）不适用

### 6.1 隐含假设 (Hidden Assumptions)

1. **失败发生在子任务边界**：核心假设，但某些失败（如突然的物体滑动）可能发生在子任务中间
2. **VLM 能可靠判断失败**：依赖 GPT-5.2 的视觉推理能力，开源 VLM 可能达不到同等水平
3. **随机采样产生多样性**：MBR 依赖扩散采样的随机性，如果策略输出过于集中（低温度），候选间差异小，MBR 退化为任意选择
4. **反向执行可精确恢复位姿**：假设 delta 动作可逆且执行无累积误差，真实系统中机械臂控制误差可能使回溯不到位
5. **子任务分解是确定性的**：同一任务指令每次分解结果一致，但 LLM 可能有随机性（尽管温度设为 0.2）

## 7. 与相关工作对比 (Comparison)

| 方法 | 纠错时机 | 是否需要训练 | 是否需要外部模型 | 目标 |
|------|----------|-------------|-----------------|------|
| **CycleVLA** | proactive（执行中） | VLA 微调（+2 维） | VLM（零样本） | 通用 VLA 主动修正 |
| PAINT | proactive | 需要人工标注 | 需要人类介入 | 通用机器人 |
| Bellman-Guided Retrials | proactive | 需要训练 value function | 不需要 | 特定任务策略 |
| RoboMonkey | test-time | 需要训练 verifier VLM | 需要（训练好的） | 动作选择 |
| Rover / V-GPS | test-time | 需要训练 reward model | 需要（训练好的） | 动作评分 |
| Conformal Prediction | post-hoc | 不需要 | 不需要 | 不确定性估计 |
| 状态异常检测 | post-hoc | 需要训练检测器 | 不需要 | 异常识别 |

**面试 Tip**：当被问到"CycleVLA 和其他 VLA 容错方法有什么区别"时，回答："核心区别是 proactive vs post-hoc。CycleVLA 在子任务快完成时就预判失败，而不是等失败了再补救。另一个关键区别是零样本——MBR 不需要额外训练，而 RoboMonkey、Rover 都需要训练 verifier 或 reward model。代价是需要外部 VLM 做决策。"
