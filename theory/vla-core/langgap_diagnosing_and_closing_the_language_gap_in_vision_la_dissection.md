### 1.2 关键机制 (Key Mechanism)

**四维语义扰动分类法**——核心创新在于保持视觉场景不变，仅变更语言指令的四个正交维度：

1. **Change Object Category**: 变更操作对象类别（"pick bowl" → "pick ramekin"）——测试物体类别名词理解
2. **Change Target**: 变更目标位置（"place on plate" → "place on stove"）——测试空间目标理解
3. **Spatial Description**: 对同类物体的不同实例，通过空间描述区分（"ramekin 右侧的 bowl" → "plate 右侧的 bowl"）——测试空间关系理解
4. **Drawer Action**: 变更动作类型（"put bowl" → "open drawer"）——测试动作语义理解

**设计原则**：相同场景多任务（Same-scene multi-task）——多个任务共享完全相同的初始视觉状态，彻底消除视觉捷径。忽略语言的模型在同场景 k 个任务中最多只能达到 1/k 成功率。

⚡ **Eureka Moment**：现有基准（如 LIBERO）每个场景只对应一个任务，模型可通过视觉记忆完成；LangGap 让同一场景对应多个不同语言指令的任务，使语言成为唯一可区分信号——这是首个"通过设计强制语言依赖"的 VLA 评估基准。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
语言理解缺口 = 原始任务成功率 - 语义扰动任务成功率 = 93.8% - 21.4% = 72.4%
```

**形式化定义**：

对于场景 S 中的 k 个任务 {T₁, T₂, ..., Tₖ}，所有任务共享相同的初始视觉状态 V₀，但语言指令 {L₁, L₂, ..., Lₖ} 语义不同。

```
理想语言理解模型：P(成功 | V₀, Lᵢ) ≈ 1.0  ∀i ∈ {1,...,k}
视觉捷径模型：P(成功 | V₀, Lᵢ) ≈ 1/k      ∀i ∈ {1,...,k}
```

**四维扰动空间**：

```
扰动维度 D = {d_object, d_target, d_spatial, d_action}
任务生成：T' = perturb(T_original, d ∈ D, 保持 V₀ 不变)
评估指标：Success_rate(d) = (1/|T_d|) × Σ_{T∈T_d} Success(T)
```

**变量说明**：

| 符号 | 含义 | 本文数值 |
|------|------|----------|
| V₀ | 初始视觉状态 | LIBERO 场景布局 |
| Lᵢ | 第 i 个语言指令 | 英文自然语言 |
| k | 同场景任务数 | 2-4 个/场景 |
| d_object | 物体类别扰动维度 | 38 任务 |
| d_target | 目标位置扰动维度 | 13 任务 |
| d_spatial | 空间描述扰动维度 | 5 任务 |
| d_action | 动作类型扰动维度 | 3 任务 |

**直觉解释**：如果模型真正理解语言，那么即使视觉场景相同，不同指令应产生不同行为；如果模型依赖视觉记忆，同场景多任务的成功率会被稀释到随机水平（1/k）。LangGap 通过测量这种稀释程度来量化语言理解能力。

## 3. 带数字走一遍：玩具例子 (Worked Example)

让我们用 **libero_spatial** 场景中的一个具体任务走一遍评估流程：

**场景设置**：
- 桌面上有：bowl、ramekin、plate、stove
- 初始视觉状态 V₀ 固定

**原始任务**（来自 LIBERO）：
- 指令 L₁: "pick up the bowl and place it on the plate"
- π0.5 成功率：95%（20 轮中 19 轮成功）

**扩展任务 1**（Change Target 扰动）：
- 指令 L₂: "pick up the bowl and place it on the stove"（目标从 plate 改为 stove）
- 视觉场景 V₀ 完全相同
- π0.5 成功率：**0%**（20 轮全部失败）
- 失败原因：模型忽略"stove"这个目标位置词，仍执行原始任务（放到 plate 上）

**扩展任务 2**（Change Object 扰动）：
- 指令 L₃: "pick up the ramekin and place it on the plate"（对象从 bowl 改为 ramekin）
- 视觉场景 V₀ 完全相同
- π0.5 成功率：**45%**（20 轮中 9 轮成功）
- 分析：模型对物体类别名词有部分理解，但不稳定

**扩展任务 3**（Spatial Description 扰动）：
- 指令 L₄: "pick up the bowl to the right of the ramekin and place it on the plate"
- 场景中有两个 bowl，需通过空间关系区分
- π0.5 成功率：**15%**（20 轮中 3 轮成功）
- 分析：空间关系理解较弱

**训练后改进**（单任务微调）：
- 用 L₂ 任务收集 150 条演示数据，微调 π0.5
- 重新评估 L₂：成功率从 0% 提升至 **90%**
- 但评估 L₃（未见过的任务）：成功率仍为 0%
- 结论：模型学会的是任务特定模式，而非通用语言理解

**数据收集成本**：
- 每任务 ~150 条演示，使用脚本化 waypoint 控制器
- OSC_POSE 控制，robosuite 仿真环境
- 总训练数据：2400 轮演示（16 任务 × 150）
- 收集时间：约 2-3 小时/任务（自动化脚本）

**部署约束**：
- 仅仿真环境验证（LIBERO/robosuite），真实机器人迁移待验证
- 评估协议：每任务 20 轮，二元成功判定
- 总评估轮次：99 任务 × 20 轮 = 1980 轮

**关键工程发现**：

1. **稀释效应**（Dilution Effect）：6 任务配置在 5 个空间扩展任务上达到 28% 成功率；加入官方数据形成 45 任务后，同一批任务的成功率降至 4%。官方数据稀释了扩展任务的训练信号。

2. **规模双刃剑**：16 任务（仅扩展数据）成功率 6.2%；56 任务（扩展 + 官方）整体 27.5%，但在空间维度仅 6.7%。官方数据对熟悉任务有效，但无法迁移到新语义变体。

3. **架构限制**：π0-FAST 在扩展任务上仅 2.7%，远低于 π0.5 的 21.4%。FAST 的动作分块设计可能更依赖视觉模式匹配。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**π0.5 能做什么**：
- 在标准 LIBERO 基准上达到 93.8% 成功率（与训练数据分布一致的任务）
- 对物体类别名词有部分理解（Change Object 29.3%）
- 对动作语义有基础理解（Drawer Action 31.7%）
- 单任务微调可从 0% 提升至 90%（任务特定学习能力强）

**π0.5 不能做什么**：
- **完全无法理解目标位置变更**（Change Target 0%）——这是最严重的失败模式
- 空间关系理解弱（Spatial Description 11.0%）
- 多任务泛化能力有限（16 任务仅 6.2%）
- 无法将单任务学到的语言理解迁移到新任务

### 6.1 隐含假设 (Hidden Assumptions)

**X-Ray 批判视角**——作者默认成立但未明确验证的前提：

1. **仿真到真实的可迁移性**：论文假设在 LIBERO/robosuite 中发现的语言理解缺陷会迁移到真实机器人场景，但未验证。真实世界的视觉噪声、语言多样性可能加剧或缓解这一问题。

2. **四维扰动的完备性**：论文声称四维分类法覆盖"组合性语言理解"的核心元素，但未覆盖时序结构（"先拿碗再开抽屉"）、否定句（"不要放到盘子上"）、条件句（"如果有碗则拿碗，否则拿盘子"）等复杂语言结构。

3. **成功率作为充分指标**：假设二元成功/失败能充分反映语言理解程度。但可能存在"部分理解"的中间状态（如轨迹正确但最终位置偏差几厘米），这些被二元判定忽略。

4. **数据量足够**：每任务 150 条演示的假设是"足够学习该任务"，但对于需要真正语言理解而非模式匹配的任务，这个数量级可能远远不够。

5. **LoRA 微调的充分性**：假设 LoRA 微调能充分释放 π0.5 的语言理解潜力。但可能冻结的骨干网络本身就缺乏语言 grounding 能力，需要全参数微调或架构修改。
