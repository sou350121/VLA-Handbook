## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 模型/方法 | 输入 | 输出 | 训练/推理状态 |
|------|-----------|------|------|---------------|
| **策略模型 (Policy)** | Qwen3-VL-4B | 系统指令 + 检索到的3个微演示 + 当前观测 + 本体状态 | k=25步动作块（文本化） | 离线微调，推理冻结 |
| **检索器 (RD-Encoder)** | Qwen3-VL-Embedding-2B | 查询: ⟨全局指令, 子任务指令, 观测, 本体⟩ | 与库中演示的相似度分数 | 离线对比训练，推理冻结 |
| **演示库 (Library)** | ~139,659 微演示 | 长轨迹经 Qwen3-VL 分割 | 子任务级演示 E=⟨T, T_sub, O, Z, A⟩ | 离线预构建 |
| **视觉规划器** | Qwen3-VL（启发式） | 全局指令 T | 有序子任务序列 T_sub | 推理时运行 |

**关键区分**：与主流 VLA（扩散头/离散 token/定制架构）不同，ICI-VLA 采用 VLA-0 的"零结构修改"范式——不添加任何动作专用参数或头，将连续动作表示为数值文本字符串。

### 1.2 关键机制 (Key Mechanism)

ICI-VLA 的三阶段框架解决三个核心问题：

1. **时序失配问题**：长轨迹 vs 短动作块 → 用 Qwen3-VL 将长轨迹分解为子任务级微演示
2. **语义-动力学失配**：视觉相似但动作不兼容 → DTW 几何排序 + 语义硬过滤双重筛选
3. **动作复制捷径**：模型直接续写演示动作而非基于当前观测 → Target Action Masking 随机遮蔽上下文动作

⚡ **Eureka Moment**：把演示从"需要微调的数据"变成"推理时的对齐上下文"——检索的质量（时空对齐）比继续训练更重要。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
E* = argmax_E∈D s_φ(I_q, E)    →    A_{t:t+k} ~ π_θ(· | I_q, E*)
   ↑ 检索最对齐的演示                  ↑ 基于对齐演示生成动作
```

**目标**：在参数全冻结的条件下，通过检索最匹配的演示 E* 作为上下文条件，让策略模型 π_θ 生成正确的动作序列。

**检索器对比损失**（InfoNCE）：
```
L_CL = -log [ exp(e_A^T · e_P+ / τ) / (exp(e_A^T · e_P+ / τ) + Σ_i exp(e_A^T · e_Ni- / τ)) ]
```
- e_A: 查询编码
- e_P+: DTW  mined 正例编码
- e_Ni-: 15 个相位错位的硬负例编码
- τ = 0.07（温度参数）

**策略损失**（Target Action Masking）：
```
L_act = -Σ_{j∈U} log π_θ(a_{q,j} | I_q, E*, ã_{q,<j})
```
- M: 采样的目标 token 位置（被遮蔽）
- U: M 的补集（未遮蔽位置）
- ã_{q,<j}: 包含被遮蔽动作 token 的前缀

**变量说明**：

| 符号 | 含义 |
|------|------|
| I_q | 查询 = ⟨T, T_sub, O_t, Z_t⟩ |
| E | 微演示 = ⟨T_e, T_e,sub, O_e, Z_e, A_{e:e+k}⟩ |
| k | 动作块长度 = 25 |
| s_φ | RD-Encoder 相似度分数 |
| δ | DTW 中 waypoint 间的欧氏距离 |
| τ | InfoNCE 温度 = 0.07 |
| ε | 收敛阈值 = 5%（正例变化率） |

> 符号与本文保持一致。DTW 仅在离线检索器训练中使用；推理时 RD-Encoder 仅基于可观测输入排序，不计算 DTW。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个双阶段任务：**"把黑色碗放进底层抽屉，然后关上它"**。

**Step 1 — 检索**：
- 当前观测 O_t：机械臂在抽屉前，碗在桌面上
- 子任务 T_sub："打开抽屉"
- RD-Encoder 从 139,659 条微演示中检索：
  - Rank 1: 打开抽屉的演示（语义匹配 + DTW 距离最小）
  - Rank 2: 类似抓取动作（语义相近但 DTW 距离较大）
  - Rank 3: 放置碗的演示（语义相关但相位不同）
- 选择 Rank 1 作为 E*

**Step 2 — 策略生成**（训练时带遮蔽）：
- 假设 k=25，遮蔽率 50%，则 U 中有 ~12 个未遮蔽位置
- 模型不能简单地"续写"演示动作（因为一半被遮蔽了）
- 必须基于当前观测 O_t（碗的位置、机械臂状态）+ 检索到的 E*（打开抽屉的动作模式）来生成动作
- 输出 25 步动作：[x, y, z, gripper_open, ...] × 25

**Step 3 — 相位切换**：
- 当视觉检测到抽屉已打开，规划器推进到 T_sub = "放入碗"
- RD-Encoder 重新检索，此时 Rank 1 变为"放置碗"的演示
- 策略基于新的 E* 生成放置动作

**数值假设**（论文未给出具体推理延迟数据，以下为合理推测）：
- RD-Encoder 推理：~50ms（2B 模型单次 forward）
- 策略生成：~200ms（4B 模型自回归 25 步）
- 总周期：~250ms → 控制频率 ~4Hz

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|-----------|----------|
| 动作块长度 k | 25 步 | 每 25 步重新生成，与典型 VLA 控制频率匹配 |
| 检索演示数 | 3-shot（默认） | 上下文窗口可控，但增加推理延迟 |
| 检索器刷新条件 | 策略置信度 < 0.65 | 避免每步都检索，降低计算开销 |
| 演示库规模 | ~139,659 条 | 检索需遍历全库或近似索引，延迟 O(N) |
| 训练硬件 | 8×A100 (80GB) | 离线训练成本较高；推理可用单卡 |
| 推理参数冻结 | 策略 4B + 检索器 2B = 6B | 总参数量可控，可部署到单 GPU |
| 训练超参 | LR=2e-5, AdamW, WD=0.01 | 标准 LLM 微调配置，无特殊技巧 |
| 检索器挖掘周期 | 5 轮（或 ε<5% 收敛） | 离线训练迭代次数少，训练成本可控 |

**关键 trade-off**：
- 检索器精度 vs 推理延迟：全库检索 O(N)，实际部署可能需要 FAISS 等近似索引
- 演示数量 vs 上下文窗口：3-shot 是验证集选定的平衡点；更多演示可能引入噪声
- 纯文本动作 vs 精度：数值字符串表示无量化损失，但依赖模型对数字的理解能力

| 抗动作复制 | Target Action Masking 减少续写捷径 | 消融：无遮蔽 RoboTwin 仅 10.7% |

### 不能做什么（失败模式）

| 失败场景 | 原因 |
|----------|------|
| 演示库未覆盖的新任务 | 检索器找不到匹配演示 → 上下文无效 |
| 语义相似但动力学不同的任务 | 即使有 DTW，检索器仍可能选错（ Recall@1 非 100%） |
| 需要精细力控的任务 | 纯视觉+本体状态，无力/触觉反馈 |
| 超出训练分布的物体/场景 | 未见过的物体可能导致检索失败或动作错误 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **演示库覆盖假设**：假设目标任务的子任务在演示库中有足够相似的微演示——但库外泛化能力未评估
2. **Qwen3-VL 分割质量假设**：假设 Qwen3-VL 能可靠地将长轨迹分割为语义子任务——但分割错误会直接影响检索质量
3. **文本化动作无损假设**：假设将连续动作表示为数值文本字符串不会丢失关键信息——但数字精度和格式依赖模型对数值的理解
4. **基线公平性假设**：Table 1 的跨论文对比标注为"benchmark-level"而非配对对比——不同论文的训练数据、评估协议可能有差异
5. **置信度阈值通用性假设**：0.65 的刷新阈值在验证集上选定，但不同任务/机器人的最优阈值可能不同
