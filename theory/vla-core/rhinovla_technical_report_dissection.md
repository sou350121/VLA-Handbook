### 1.2 关键机制 (Key Mechanism)

RhinoVLA 的三大核心机制解决三个不同层面的问题：

- **View Registry（机制 A）→ 解决摄像头异构**：将不同数据集的相机字段映射为固定角色-模态词表（如 `[head|rgb]`、`[left_wrist|rgb]`），解耦相机身份与数据集特定的图像顺序。
- **72D 统一槽位空间（机制 B）→ 解决动作异构**：所有机器人共享同一 $72$ 维物理语义空间（手臂/腕部/头部/腰部用弧度，平行夹爪用 $[0,1]$ 闭合比，移动底座用速度），二元 Mask 标记哪些槽位对当前机器人有效。
- **实例 LoRA（机制 C）→ 解决本体残差**：在 Action Expert 的 FFN 层插入机器人实例级 LoRA 适配器，共享注意力模块和最终动作投影不变，部署时可合并到基线权重中。

⚡ **Eureka Moment**：VLA 部署延迟的本质瓶颈不是模型参数量，而是视觉 Token 数量 — 减少 $4\times$ Token 比减少 $4\times$ 参数在边缘硬件上更有效，因为 MLP GEMM 的计算量与 Token 数线性相关。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L_FM = Σ_{h,d} m_a(d)·w(h,d) · ||v̂_θ(h,d) - (z(h,d) - a(h,d))||² / (Σ_{h,d} m_a(d)·w(h,d) + ε)
```

**目标**：在统一 72D 槽位空间上，用 Flow Matching 学习从噪声到干净动作的速度场，仅对有效动作槽位施加监督。

**公式分解**：

```
构造插值:  x_t = (1-t)·a + t·z,   a ~ N(0,I), t ∈ [0,1]
预测速度:  v̂_θ = f_θ(x_t, t, s, m_s, m_a, c_vlm, r)
损失函数:  L_FM = 加权Masked MSE(v̂_θ, z - a)
```

| 符号 | 含义 |
|------|------|
| x_t | $t$ 时刻的插值动作（噪声→目标的过渡状态） |
| a | 高斯噪声 (N(0,I)) |
| z | 干净目标动作 chunk ($H\times72$) |
| t | Flow Matching 时间步 |
| s | 72D 机器人当前状态 |
| m_s, m_a | 状态/动作二元 Mask（哪些槽位有效） |
| c_vlm | Qwen3-VL 最后 18 层 KV Cache |
| r | 机器人实例 ID（选择对应 LoRA） |
| w(h,d) | 每槽位权重（平衡不同动作组） |

**直觉**：Action Expert 不直接预测动作，而是预测从噪声到目标的速度方向。Mask 确保只有当前机器人实际存在的关节维度参与损失计算——不存在的手不会「被训练到零」，而是被完全忽略。

> 符号与本文/相关文档保持一致。Flow Matching 目标为 $z - a$（速度），非 $\sigma_t$ 缩放版本。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：单臂机器人，仅 4 个有效动作槽位（肩俯仰、肩偏航、肘屈伸、夹爪开合），预测 horizon H=5 步。

**Step 1 — 构造目标**：干净动作 chunk $z \in \mathbb{R}^{5\times4}$
```
z = [[0.1, 0.2, -0.3, 0.5],   ← t=1: 目标姿态
     [0.1, 0.2, -0.3, 0.5],
     [0.1, 0.2, -0.3, 0.5],
     [0.1, 0.2, -0.3, 0.5],
     [0.1, 0.2, -0.3, 0.5]]
```

**Step 2 — 采样噪声并插值**：a ~ N(0,I)，取 t=0.6
```
a = [[0.3, -0.1, 0.2, -0.4],
     [-0.2, 0.1, -0.1, 0.3],
     ...]

x_0.6 = 0.4·a + 0.6·z
     = [[0.10, 0.08, -0.06, 0.14],
        [0.10, 0.16, -0.18, 0.42],
        ...]
```

**Step 3 — Action Expert 预测速度**：
```
v̂_θ = f_θ(x_0.6, t=0.6, s, m_s, m_a, c_vlm, r=0)
     = [[0.00, 0.00, -0.50, 0.90],   ← 预测 z - a
        [0.00, 0.00, -0.50, 0.90],
        ...]
```

**Step 4 — 计算 Masked Loss**：假设 m_a = [1,1,1,1]（全部有效），w=1
```
L_FM = Σ ||v̂_θ - (z-a)||² / 4
     = Σ ||[0.00, 0.00, -0.50, 0.90] - [0.1-0.3, 0.2-(-0.1), -0.3-0.2, 0.5-(-0.4)]||² / 4
     = Σ ||v̂_θ - [-0.2, 0.3, -0.5, 0.9]||² / 4
     ≈ 0.01 (假设预测接近目标)
```

**Step 5 — 推理时采样**：从 $a \sim \mathcal{N}(0,I)$ 开始，用 Euler 方法沿 $\hat{v}_\theta$ 方向积分 10 步到达 $z$。

## 4. 工程视角 (Engineering View)

### 4.1 延迟分解（Huixi R1 优化后）

| 阶段 | 延迟 (ms) | 占比 | 优化手段 |
|------|-----------|------|----------|
| 视觉编码 (3图并行) | ~24.3 | ~21% | Batch并行编码 (原34.5ms→24.3ms) |
| VLM Backbone | ~55.0 | ~47% | Qwen3-VL 64-token (vs 256); W8A16量化 |
| Action Expert | ~30.7 | ~26% | W8A16 GEMM (1.69$\times$加速); 实例LoRA硬路由 |
| 其他 (通信/调度) | ~6.0 | ~6% | 细粒度任务调度 |
| **总计** | **~85.6** | **100%** | **= 11.69 Hz** |

### 4.2 关键 Trade-off

| 权衡点 | 方案 | 收益 | 代价 |
|--------|------|------|------|
| 视觉 Token 数 | 64 vs 256 | 4$\times$ MLP GEMM 减少 | 空间细节损失（Qwen3-VL 的空间合并可能丢失精细特征） |
| 量化精度 | W8A16 vs W16A16 | 权重存储减半, up_proj 1.69$\times$加速 | W8A8 准确率下降 → 激活必须保持 FP16 |
| 跨本体适配 | Instance LoRA vs 独立输出头 | 统一推理图, 可合并权重 | LoRA 容量有限，极端本体差异可能无法完全捕获 |
| 部署芯片 | Huixi R1 vs Jetson Orin | 500 TOPS vs 275 TOPS (INT8) | R1 生态不成熟, 工具链封闭 |

### 4.3 部署约束

- **内存带宽**：R1 提供 200 GB/s 类带宽，Attention tiling 和算子融合将中间激活保留在 SPM（片上缓存），减少 DDR 访问
- **计算利用率**：Attention kernel 达到理论峰值 80%+；W8A16 GEMM 达到 50.6% 利用率
- **多核并行**：8 核 SIMT 架构，GEMM 子任务按内存通道感知方式分配到各核

### 6.3 隐含假设 (Hidden Assumptions)

1. **72D 槽位映射完备性**：假设所有目标机器人的关节都能映射到 72 个预定义物理槽位。灵巧手按 4-3-3-3-3 分配（拇指 4 DoF，其余各 3 DoF），但实际手的自由度可能不匹配（如 Shadow Hand 有 20 DoF）。
2. **Instance LoRA 容量足够**：假设每个机器人的残差行为可以用小 LoRA 适配器捕获。对于结构差异极大的机器人（如轮式 vs 足式），LoRA 可能不足以建模。
3. **R1 芯片可用性**：整个性能优势建立在 Huixi R1 芯片上（500 TOPS INT8），该芯片生态尚不成熟，外部研究者难以复现。
4. **视觉 Token 压缩无损**：假设 64 token/图 足以保留操作所需的空间细节。对于需要精细手眼协调的任务（如灵巧操作），可能不够。
5. **Qwen3-VL 冻结主干足够**：VLM 主干完全冻结，仅通过 LoRA 适配。对于与预训练分布差异较大的机器人视角，可能不够灵活。
