## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 维度 | LIBERO（原版） | LIBERO-PRO（扩展） |
|------|---------------|-------------------|
| 训练/测试差异 | 仅物体初始位置微小扰动（视觉上几乎不可辨） | 四维正交扰动：物体属性、空间配置、指令语义、环境背景 |
| 任务指令 l | 训练=测试 | 语义改写 + 无意义字符注入 |
| 物体集合 O | 训练=测试 | 颜色/纹理/尺寸替换；目标物体移除；无关物体替换 |
| 初始配置 $R_0$ | 微小扰动 | 系统性位移（0.2~0.4+ 单位） |
| 环境背景 W | 固定 | 背景/光照/纹理变化 |
| 跨维度组合 | 无 | $O \times R \times L \times E$ 自由组合（T 类任务级扰动除外） |
| 典型成功率 | >90% | 扰动下 0%~40%（依赖模型和扰动类型） |
| 评测目标 | 标准任务完成 | 泛化性 + 鲁棒性 + 组合性 |

### 1.2 关键机制 (Key Mechanism)

LIBERO-PRO 的核心设计哲学是**通过受控扰动暴露 memorization**：

1. **物体属性扰动 (O)**：修改物体的颜色、纹理、尺寸，但保持语义等价。测试模型是否真的"看到"了目标物体，还是只是记住了场景中的某个位置。

2. **初始配置扰动 (R)**：改变物体的绝对和相对位置，保持物理合理性。测试模型是否在做在线空间推理，还是只是记忆了训练集中的坐标。

3. **指令扰动 (L)**：包括语义改写（同义句）和任务级扰动（修改目标物体/动作）。测试模型是否真正理解了语言指令，还是只是用视觉上下文检索记忆的动作模式。

4. **环境扰动 (E)**：修改背景、光照、纹理等视觉上下文。测试模型是否依赖特定的环境特征做决策。

**约束条件**：每个扰动被限制在维度特定的邻域内（$\mathrm{dist}_k(x, x^{(k)}) \leq \delta_k$），同时确保扰动后的任务与原始任务有足够的总变差距离（$d_{\mathrm{TV}}(T, T^{(k)}) > \varepsilon$），避免扰动过小（无意义）或过大（不可执行）。

⚡ **Eureka Moment**：LIBERO 的高分不是模型能力的证明——它是评测协议缺陷的副作用。当训练和测试任务几乎相同时，>90% 的成功率主要反映的是 memorization 而非 genuine understanding。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
J(π_θ; T) = P_πθ,e [∃t∈{0,...,H} : G(s_t, l) = 1]
```

**目标**：评估策略 $\pi_\theta$ 在有限视界 $H$ 内成功完成任务 $T$ 的概率。

**公式分解**：

| 符号 | 含义 |
|------|------|
| T = (l, e, G) | VLA 任务实例：指令 l、环境 e、成功谓词 G |
| $e = (W, O, R_0)$ | 环境实例：视觉上下文 $W$、物体集合 $O$、初始配置 $R_0$ |
| π_θ(a_t \| o_t, l) | 策略：从观测 o_t 和指令 l 到动作 a_t 的映射 |
| P(· \| s_t, a_t) | 环境动力学模型 |
| $G(s, l) \in \{0,1\}$ | 二值成功谓词 |
| $J(\pi_\theta; T)$ | 任务成功率（标量指标） |

**直觉**：标准 LIBERO 下，测试任务 $T'$ 与训练任务 $T$ 几乎相同（$l'=l$, $W'=W$, $O'=O$, $G'=G$，仅 $R_0'$ 有微小扰动），因此 $J(\pi_\theta; T')$ 高并不要求模型真正理解 $(o_t, l) \to a_t$ 的映射——它只需要记住训练集中的动作序列。LIBERO-PRO 通过引入 $T^{(k)} = \varphi_k(T)$，确保 $d_{\mathrm{TV}}(T, T^{(k)}) > \varepsilon$，迫使 $J(\pi_\theta; T^{(k)})$ 真正反映泛化能力。

> 符号与本文保持一致：$W=$视觉环境上下文, $O=$可交互物体集合, $R_0=$初始空间配置, $G=$成功判定函数

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简单任务：**"拿起沙拉调味瓶放入篮子"**。

**训练阶段**（LIBERO 标准设置）：
- 物体：沙拉调味瓶在位置 (0.3, 0.0, 0.85)
- 指令："Pick up the salad dressing and place it in the basket"
- 背景：厨房台面
- 演示轨迹：50 条，位置扰动范围 $\pm 0.05$

**模型学到的**（memorization 假设）：
```
π_θ ≈ "看到厨房台面 → 移动到 (0.3, 0.0, 0.85) 附近 → 抓取 → 移动到篮子 → 释放"
```

**测试阶段**（LIBERO-PRO 扰动）：

| 扰动类型 | 变化 | 模型行为 | 成功率 |
|---------|------|---------|--------|
| 无扰动（LIBERO 标准） | 位置 (0.32, 0.01, 0.86) | 移动到记忆位置 → 抓取 → 放入篮子 | 0.95 |
| 物体替换 (O) | 沙拉调味瓶 → 罐头汤 | 仍移动到 $(0.3, 0.0, 0.85)$ → 抓取罐头汤 | 0.0 |
| 位置偏移 (R) | 位置 (0.5, 0.1, 0.85)，偏移 0.2 | 移动到记忆位置 $(0.3, 0.0, 0.85)$ → 抓取空气 | 0.0 |
| 指令篡改 (L) | "fdsgfdsgsd" | 仍执行相同轨迹（忽略指令语义） | ~0.9（讽刺地"成功"） |
| 物体移除 | 沙拉调味瓶不在场景中 | 仍移动到记忆位置 → 抓取空气 | 0.0 |
| 组合扰动 $(O \times R)$ | 罐头汤 + 位置 (0.5, 0.1, 0.85) | 移动到记忆位置 → 抓取空气 | 0.0 |

**关键发现**：模型在指令变成无意义字符时仍然执行正确的抓取动作——这证明指令输入对决策过程几乎没有贡献，模型主要依赖视觉上下文检索记忆的动作模式。

## 4. 工程视角 (Engineering View)

| 维度 | 分析 |
|------|------|
| **计算开销** | LIBERO-PRO 本身是评测框架，不增加训练开销。评测时需要为每个扰动类型生成变体任务，评测时间 ≈ 原版 × 扰动组合数（通常 5-10 倍） |
| **部署约束** | 作为 plug-and-play 扩展，兼容现有 LIBERO 流程。只需替换评测脚本，不需要修改模型代码 |
| **并行化** | 所有扰动任务相互独立，可完全并行评测。官方推荐使用 HuggingFace 数据集格式进行并行评估 |
| **评测成本** | 每个任务 $50$ episodes（与 LIBERO 一致）。$5$ 种扰动 $\times$ $4$ 个任务套件 $\times$ $50$ episodes $= 1000$ episodes/模型（vs 原版 $200$ episodes） |
| **可复现性** | 高：所有 bddl 和 init 文件已上传 HuggingFace，支持确定性复现 |

**工程含义**：LIBERO-PRO 的价值在于它不要求你改变训练方法——它只要求你用更严格的评测来报告结果。这意味着：
1. 论文中的历史 >90% LIBERO 分数需要重新解读
2. 新论文的评测成本增加 5-10 倍，但结果更有意义
3. 模型比较从"谁在 memorization 上更强"转向"谁在泛化上更强"

## 5. 数据与评测 (Data & Eval)

**模型**：
- OpenVLA：4 个官方 checkpoint（训练于不同 LIBERO 套件）
- Pi0：官方 checkpoint（单次评测）
- Pi0.5：官方 checkpoint（更大架构 + 更多训练数据）

**评测设置**：
- 每个任务 50 episodes（与原始 LIBERO 协议一致）
- 扰动幅度 $\delta_k$ 通过网格搜索确定，确保扰动"有意义但可执行"
- 任务级扰动 (T) 不参与跨维度组合（避免不可行组合）

**主要结果**（论文 Figure 7）：

| 模型 | LIBERO 标准 | 物体扰动 | 位置扰动 | 语义指令 | 环境扰动 | 任务扰动 |
|------|-----------|---------|---------|---------|---------|---------|
| OpenVLA | >0.90 | ~0.30-0.50 | 0.0 | ~0.60-0.80 | ~0.40-0.70 | 0.0 |
| Pi0 | >0.90 | ~0.20-0.40 | 0.0 | ~0.50-0.70 | ~0.30-0.60 | 0.0 |
| Pi0.5 | >0.90 | ~0.40-0.60 | ~0.38 (libero-goal) | ~0.70-0.85 | ~0.50-0.70 | ~0.10-0.20 |

**关键数据点**（论文 §2.3, Figure 4）：
- OpenVLA 和 Pi0：物体位移 >0.2 单位后成功率骤降至 0
- Pi0.5：在 libero-goal 任务上，位移 $\leq 0.4$ 单位时保持 $0.38$ 成功率，之后也降至 $0$
- 所有模型在任务扰动下均为 0%（即使新任务由训练组件构成）

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **标准 LIBERO 评测**：在训练/测试任务几乎相同时，所有模型都能达到 >90% 成功率
- **小幅语义改写**（部分模型）：Pi0.5 对某些指令改写保持一定鲁棒性（~0.70-0.85）
- **单维度弱扰动**：物体颜色/纹理变化时，部分模型保持 30-60% 成功率

### 不能做什么
- **位置泛化**：物体位移 >0.2 单位时，OpenVLA/Pi0 完全失败（§2.3, Figure 4）
- **指令理解**：无意义字符指令下仍执行相同动作（§2.2, Figure 3）——指令输入几乎不起作用
- **物体识别绑定**：目标物体被替换为无关物品时仍执行抓取（§2.1, Figure 2）
- **组合推理**：两个已学会的子任务组合后完全失败（§2.4, Figure 5）——"拿起碗放炉子上"+"打开炉子" = 学会，但"拿起碗放炉子上然后打开炉子" = 失败
- **任务泛化**：即使新任务由训练组件构成，模型也无法适应

### 6.1 隐含假设 (Hidden Assumptions)

1. **扰动幅度 $\delta_k$ 的设定是合理的**：论文没有提供 $\delta_k$ 的敏感性分析。如果 $\delta_k$ 设置过大，所有模型都会失败（无区分度）；如果过小，无法暴露 memorization。这个平衡点的主观选择可能影响结论。

2. **仿真环境足以代表真实泛化需求**：所有实验在 MuJoCo 仿真中进行。真实机器人部署中的分布偏移（光照变化、传感器噪声、物体形变）可能与仿真中的扰动模式不同。

3. **LIBERO 的 4 个任务套件足以代表 VLA 能力**：LIBERO-SQL、LIBERO-90、libero-object、libero-goal 覆盖了桌面操作的主要场景，但未涉及移动操作、双臂协调、人形机器人等更复杂的场景。

4. **50 episodes 的评测样本量足够**：对于成功率接近 0 或 1 的情况，50 episodes 可能不够精确。特别是当成功率在 0.3-0.5 区间时，置信区间较宽。

5. ** memorization 是唯一解释**：论文将性能坍缩归因于 memorization，但其他因素（如视觉表征的分布偏移敏感性、语言-视觉对齐不足）可能也贡献了部分失败。
