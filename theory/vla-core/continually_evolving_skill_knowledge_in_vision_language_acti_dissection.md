### 1.2 关键机制 (Key Mechanism)

**三层递进设计：**

1. **Dirichlet Process 知识空间** — 不预设聚类数量，让模型从数据中自动发现任务/技能簇。DP 的"中国餐馆过程"直觉：新任务到来时，要么加入已有簇（共享知识），要么开新桌（新知识）。

2. **自演化学习** — VAE 编码的隐表示和知识空间分布交替优化。VAE 把 (语言, 视觉) 映射到隐空间 $z$；DP 模型对 $z$ 做聚类得到知识分布 $\Theta$；$\Theta$ 又通过 KL 损失约束下一轮 VAE 编码。两者互相促进。

3. **知识引导 MoE 路由** — 不同于 MoDE 用噪声级别路由，Stellar 用知识嵌入（关系距离 + Top-K 语义）引导专家选择。相关任务路由到相似专家，不相关任务路由到不同专家。

⚡ **Eureka Moment**：用知识空间（而不是噪声级别）来路由 MoE 专家——让"模型知道自己在做什么任务"，从而实现参数共享与隔离的智能平衡。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
f_know = [z ‖ f_R ‖ f_S]  →  Router(f_know, e_noise)  →  Σ_i w_i · Expert_i(e)
```

知识嵌入 = 隐表示 + 到各簇中心的加权距离 + Top-K 语义聚合，三者拼接后输入路由器，动态组合 MoE 专家预测动作。

**目标函数分解：**

```
L_total = L_recon + L_KL(Θ) + L_diffusion
```

| 符号 | 含义 |
|------|------|
| L_recon | VAE 重建损失：T-Stellar 单层；TS-Stellar 双层 (语言→任务隐变量, 视觉→技能隐变量) |
| L_KL | DP 感知的 KL 正则化：约束隐变量 z_j 在当前知识簇假设下推断 |
| L_diffusion | 扩散模型的动作预测损失（继承自 MoDE） |

**T-Stellar KL 项：**
```
L_KL_j = Σ_{k=1}^{K_c} p_jk · L_KL_jk
```
其中 p_jk 是任务 j 的隐变量分配到簇 k 的概率，K_c 是当前知识簇数量。

**TS-Stellar 分层 KL 项：**
```
L_KL_j^TS = L_KL_j(z_j^task, θ^task) + L_KL_j(z_j^skill, θ^skill)
```
任务级隐变量受任务知识约束，技能级隐变量受技能知识约束。

**HDP 技能聚合公式：**
```
μ_j^task = Σ_{i∈task j} π_ji · μ_i^skill
σ_j^task = sqrt(Σ_{i∈task j} π_ji · [(σ_i^skill)^2 + (μ_i^skill - μ_j^task)^2])
```
任务的分布参数由其组成技能的加权均值和方差聚合而成。

**知识关系嵌入：**
```
f_R = Σ_{k=1}^{K_c} p_k · |z - μ_k|
```
到每个簇中心的加权距离，反映当前输入与各知识的关联强度。

**Top-K 语义嵌入：**
```
f_S = Σ_{k∈I_T} p_k · Embed(k),  I_T = TopKIndices(p_1,...,p_K, z)
```
取隶属概率最高的 K 个簇，用可学习嵌入加权聚合。

> 符号与本文保持一致：$z$ 为隐表示，$\Theta$ 为知识空间分布，$p_k$ 为隶属概率，$\mu_k/\sigma_k$ 为簇参数，$\pi_{ji}$ 为技能混合权重。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 3 任务持续学习场景：

**任务序列**：$T_1=$"pick red cube" $\to$ $T_2=$"pick blue cube" $\to$ $T_3=$"place red cube on plate"

**Step 1 — 学习 T1：**
- VAE 编码 $(l=$"pick red cube", $o)$ $\to$ $z_1 \in \mathbb{R}^{64}$
- DPMM 初始化：新开一簇，$\mu_1 = z_1$, $\sigma_1 = I$
- 路由：$p_1=1.0$ $\to$ $f_R = |z_1 - \mu_1| = 0$, $f_S = \text{Embed}(1)$
- MoE 路由到 Expert_1，学习 T1 动作

**Step 2 — 学习 T2：**
- VAE 编码 $(l=$"pick blue cube", $o)$ $\to$ $z_2$
- DPMM 更新：$z_2$ 与 $\mu_1$ 距离近（都是"pick"动作），以概率 $0.7$ 分配到簇 $1$，以 $0.3$ 开新簇 $2$
- 假设分配到簇 $2$：$\mu_2 \approx z_2$, $\sigma_2 \approx I$
- 路由：$p_1=0.3$, $p_2=0.7$ $\to$ $f_R = 0.3\cdot|z_2-\mu_1| + 0.7\cdot|z_2-\mu_2|$
- MoE 主要路由到 Expert_2，但 Expert_1 也有少量激活（共享"pick"知识）

**Step 3 — 学习 T3：**
- VAE 编码 $(l=$"place red cube on plate", $o)$ $\to$ $z_3$
- DPMM 更新：$z_3$ 与 $\mu_1$ 距离中等（共享"red cube"），与 $\mu_2$ 距离远（不同动作类型）
- 假设 p_1=0.4, p_2=0.1, p_3=0.5（开新簇）
- 路由：$f_R = 0.4\cdot|z_3-\mu_1| + 0.1\cdot|z_3-\mu_2| + 0.5\cdot|z_3-\mu_3|$
- MoE 主要路由到 Expert_3，但 Expert_1 有 40% 激活（共享"red cube"抓取知识）

**结果**：T3 学到了新动作"place"，但通过 Expert_1 的共享保留了"pick red cube"的技能。1% 回放（T1 的 10 条演示存入 buffer）配合知识路由，比纯 20% 回放的 ER 基线遗忘率更低。

## 4. 工程视角 (Engineering View)

| 维度 | 分析 |
|------|------|
| **推理延迟** | 增加 DPMM/HDP 推断和知识嵌入计算，但相比扩散模型的去噪步骤，这部分开销可忽略（~5-10ms） |
| **训练开销** | 每 N_dp 步更新一次知识空间（memoVB），额外计算量约 5-10%。相比 MoDE 无显著增加 |
| **存储开销** | 知识空间仅存储 {μ_k, σ_k} 和 Embedding 表，远小于 20% 数据回放的 buffer。1% 回放 + 知识空间 << 20% 纯回放 |
| **扩展性** | DPMM 簇数随任务数增长，但路由只取 Top-K，推理时不受影响。训练时 memoVB 保证全局统计共享 |
| **部署约束** | 模型总参数量不变（MoE 专家数固定），适合边缘部署。知识空间需持久化以支持增量学习 |
| **量化误差** | 未报告量化实验。知识嵌入 f_R/f_S 为浮点向量，量化到 INT8 可能影响路由精度 |

**工程含义**：知识引导路由将"任务识别"从隐式（通过噪声级别间接区分）变为显式（通过知识嵌入直接表达）。这降低了扩散头部的负担——每个专家只需关注特定知识域的动作分布，而不是在所有任务上拟合单一分布。

### 6.1 隐含假设 (Hidden Assumptions)

1. **任务边界清晰** — CIL 设定假设任务序列 $\{T_j\}$ 有明确边界（完成 $T_j$ 后才学 $T_{j+1}$）。真实场景中任务边界可能是模糊的或连续的。

2. **技能可复用** — HDP 假设不同任务共享可复用的子技能。但对于高度特异化的任务（如精细手术操作），技能共享可能有限甚至有害。

3. **1% 回放足够** — 论文声称 1% 回放足够，但这建立在知识空间有效组织了已有知识的前提下。如果知识空间聚类质量差（如任务差异大但特征重叠），1% 可能不够。

4. **MoE 专家数固定** — 路由在固定 N_e 个专家间分配，但知识簇数 K_c 由 DP 自动增长。当 K_c > N_e 时，多个知识簇共享同一专家，可能导致干扰。
