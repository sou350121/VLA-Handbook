## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练/推理 |
|------|------|------|-----------|-----------|
| DA360 | 全景 RGB | 全局结构深度（相对值） | 一次前向 | 预训练模型 |
| DepthPro | 全景 RGB | 高频细节深度（米制） | 一次前向 | 预训练模型 |
| Laplacian 融合 | DA360 逆深度 + DepthPro 逆深度 | 融合深度图（4 层金字塔） | 一次融合 | 无训练 |
| Cubemap 投影 | 全景 RGB + 融合深度 | 6 个立方体面 RGB-D | 一次投影 | 无训练 |
| SHARP | 每个面的 RGB-D | 每个面的 3D Gaussians (PLY) | 6 次前向（并行） | 预训练模型 |
| Frustum Culling + Merge | 6 个 PLY | 单一全景 3DGS 场景 | 一次合并 | 无训练 |

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **全景→立方体分解**：直接处理 2:1 等距柱状投影会导致极点畸变 + 分辨率浪费。分解为 6 个 90° 立方体面可复用现有针孔相机模型的前馈重建器（如 SHARP）。

2. **深度融合策略**：DA360 提供全局一致但粗糙的深度，DepthPro 提供细节丰富但尺度不一致的深度。用逆深度拉普拉斯金字塔融合，低频取自 DA360（保全局结构），高频取自 DepthPro（保细节边界）。

3. **训练-free 深度注入**：SHARP 原本有自己的深度估计 backbone。本文证明：只需替换中间深度预测为融合深度图，并修改高斯初始化方案，即可直接驱动 SHARP 在预定义深度约束下生成几何一致的高斯场景——无需重新训练。

⚡ **Eureka Moment**：全景 3D 重建的核心矛盾是"全局一致性 vs 局部细节"，本文用逆深度金字塔融合 + 训练-free 深度注入，在保持前馈效率的同时解决了跨视口几何错位问题。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
D_fused = LaplacianFuse(α·D_DA360⁻¹, (1-α)·D_DepthPro⁻¹)
```

**目标**：在保持全局尺度一致的前提下注入高频细节。

**公式拆解**：

| 符号 | 含义 | 来源 |
|------|------|------|
| D_fused | 融合后的深度图（米制） | 本文输出 |
| D_DA360⁻¹ | DA360 输出的逆深度（视差空间） | DA360 论文 |
| D_DepthPro⁻¹ | DepthPro 输出的逆深度（米制） | DepthPro 论文 |
| α | 融合权重（默认 SHARP 贡献 0.6） | 本文超参 |
| LaplacianFuse | 4 层拉普拉斯金字塔融合操作 | 本文 §III-A |

**直觉解释**：
- 逆深度空间融合比深度空间更稳定（避免远平面插值畸变）
- 拉普拉斯金字塔分离频率：低频层用 DA360（保全局），高频层用 DepthPro（保细节）
- 默认 α=0.6 意味着更信任 DepthPro 的细节，但用 DA360 锚定尺度

> 符号与本文/相关文档保持一致：逆深度 = 1/深度 = 视差 (disparity)

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设输入一张 2048×1024 的室内全景图，桌面操作场景：

**步骤 1：深度估计**
- DA360 输出：2048×1024 相对深度图，值域 [0.0001, 10000]，全局一致但边界模糊
- DepthPro 输出：2048×1024 米制深度图，值域 [0.5m, 8m]，桌沿/键盘细节清晰但尺度漂移

**步骤 2：逆深度转换 + 融合**
- 转换：D⁻¹ = 1 / D（对两图分别操作）
- 金字塔分解：4 层，每层下采样 2×
- 融合：第 0 层（最粗糙）100% DA360，第 3 层（最细）100% DepthPro，中间层线性插值
- 输出：融合逆深度图，转换回深度空间得 D_fused（米制）

**步骤 3：立方体投影**
- 每个面分辨率：1536×1536（与 SHARP 内部对齐）
- 投影后：6 个 RGB + 6 个深度 EXR 文件
- 双边滤波细化：可选，软化阶梯伪影

**步骤 4：SHARP 前向推理**
- 每个面输入：RGB (1536×1536) + 深度 EXR (1536×1536)
- SHARP 输出：约 50k-200k 个高斯/面（取决于场景复杂度）
- NDC Frustum 掩码：剔除视锥外高斯（避免天空面空洞）

**步骤 5：合并**
- 6 个 PLY 合并为单一文件
- 总高斯数：约 300k-800k（桌面场景）
- 文件大小：50-200 MB（取决于高斯数量）

**推理时间**（RTX 5090）：
- DA360 + DepthPro：~2s
- 融合 + 投影：~1s
- SHARP × 6（并行）：~3-5s
- 合并：~0.5s
- **总计：6-8 秒**

## 4. 工程视角 (Engineering View)

| 指标 | 数值/范围 | 工程含义 |
|------|-----------|----------|
| 输入分辨率 | 2048×1024（默认） | 更高分辨率需超分模块（Real-ESRGAN），但引入伪纹理 |
| 输出高斯数 | 300k-800k（桌面场景） | 影响渲染吞吐和内存占用 |
| 推理延迟 | 6-8s（RTX 5090） | 适合离线资产生成，不适合在线重建 |
| GPU 内存峰值 | ~12GB（取决于面分辨率） | RTX 4090/5090 可轻松运行，消费级卡需调低分辨率 |
| 立方体面分辨率 | 1536×1536（默认） | 与 SHARP 内部对齐，修改需同步调整 |
| 深度量化 | EXR float32 | 保留精度，避免 uint16 量化误差 |
| Frustum Culling FOV | 91°（默认，略大于 90°） | 避免硬切割导致接缝处高斯丢失 |

**部署约束**：
- 仅适用于室内桌面级场景（~1m³，有限视差）
- 户外/大视差/移动机器人场景不适用（论文明确声明）
- 需要 CUDA 环境（依赖 PyTorch + 自定义 CUDA kernel）
- 依赖链较长：DA360 + DepthPro + SHARP + Real-ESRGAN（可选）

**Trade-off 决策**：
- 超分 vs 伪纹理：Real-ESRGAN 提升视觉效果但引入非真实纹理，仿真训练可能受影响
- 面分辨率 vs 内存：1536→2048 会显著增加显存，收益递减
- Frustum 掩码 vs 天空面：启用掩码可能使天空面"消失"，可 --no-ndc-frustum-mask 调试
