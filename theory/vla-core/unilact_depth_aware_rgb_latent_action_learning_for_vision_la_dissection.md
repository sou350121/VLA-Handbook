现有 VLA 预训练依赖昂贵的遥操作标注数据，或用纯 RGB 视频学潜在动作——但 RGB 潜在动作只编码外观动态，不懂 3D 几何。UniLACT 的答案是：用 RGB-D 视频学一个"统一潜在动作空间"，让 RGB 和深度在潜在层对话，预训练出的 VLA 在推理时只需 RGB 就能做出有几何意识的动作。对 VLA 研究者的意义：无标注 RGB-D 视频（如 Kinect 录制的互联网视频）可以成为比纯 RGB 视频更高效的预训练数据源。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 频率/时序 | 训练/推理差异 |
|------|------|------|-----------|---------------|
| UniLARN (潜在动作学习器) | 配对 RGB-D 帧 (o_t, o_{t+H}) | 模态特定潜在 z^r, z^d + 统一潜在 z^u | 预训练阶段离线生成 | 仅训练时使用 |
| UniLACT (VLA 主干) | RGB 观测 + 任务指令 + z^u | 预测潜在动作序列 z_{1:N}^m | 自回归逐 token 预测 | 训练时预测 z^r/z^d/z^u，推理时只输出动作 |
| Action Decoder (动作解码器) | Transformer 隐藏状态 + 动作 query tokens | 7-DoF 末端执行器增量 (Δp, Δr, g) | 每步推理输出一次 | 仅微调阶段使用 |
| 深度模态 | RGB-D 视频帧 | 不参与推理 | 训练时提供几何先验 | **推理时不需要深度输入** |

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **两阶段向量量化**：先对 RGB 和深度分别量化得到模态特定潜在，再融合后二次量化得到统一潜在——这样既保留模态特性，又强制统一潜在编码跨模态交互
2. **解耦重建目标**：用统一潜在 z^u 条件化模态特定的前向动力学模型 (FDM)，强制 z^u 必须包含足够信息来重建两种模态的未来帧
3. **推理时深度可选**：深度只在训练时提供几何监督，推理时 VLA 只需 RGB——这对部署至关重要（多数机器人只有 RGB 相机）

⚡ **Eureka Moment**：**潜在动作本身可以携带几何先验**——不需要在像素/特征层融合深度，而是在动作抽象层注入 3D 结构，让下游策略继承"懂几何"的动作表示。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
z^u = VQ( W_f · [e^r; e^d] + b_f )  其中 e^m = C^(s)[ VQ( I_m(o_t^m, o_{t+H}^m) ) ]
```

**目标**：学习一个统一潜在 z^u，同时编码 RGB 的外观动态和深度的几何结构。

**公式拆解**：

| 符号 | 含义 | 来源 |
|------|------|------|
| o_t^m | 模态 m 在 t 时刻的观测 (m∈{r,d}) | 输入 |
| I_m | 模态 m 的逆动力学模型 (IDM) | 公式 (1) |
| VQ(·; C) | 向量量化操作，使用码本 C | 公式 (2)(5) |
| z^m | 模态特定潜在动作 | 公式 (2) |
| e^m | z^m 对应的码本嵌入向量 | 公式 (3) |
| W_f, b_f | 线性投影参数 | 公式 (4) |
| z^u | 统一潜在动作表示 | 公式 (5) |
| F_m | 模态 m 的前向动力学模型 (FDM) | 公式 (6) |

**直觉**：IDM 从帧对中提取"发生了什么动作"，VQ 将其离散化为 token，融合后二次量化得到统一潜在。这个统一潜在必须能让 FDM 重建两种模态的未来帧——因此它被迫编码跨模态的动态共性。

**预训练损失**（公式 8）：

```
L_latent^m = -Σ_{i=1}^{N} log p_θ(z_i^m | z_{1:i-1}^m, o_t, l, z^u)
```

**微调损失**（公式 10）：

```
L_ft = L_latent^u + L_reg(Δp) + L_reg(Δr) + L_bce(g)
```

> 符号与本文/相关文档保持一致：上标 m 表示模态 (r=RGB, d=depth, u=unified)，下标 t 表示时间步。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有一个"抓取胡萝卜"任务的 RGB-D 视频片段：

**输入**：
- t=0: RGB 帧 o_0^r（看到胡萝卜在桌上），深度帧 o_0^d（胡萝卜距离相机 0.5m）
- t+H=10: RGB 帧 o_{10}^r（手已抓住胡萝卜），深度帧 o_{10}^d（手距离相机 0.3m）

**Step 1: UniLARN 编码**
```
z~_0^r = IDM_r(o_0^r, o_{10}^r) → VQ → z_0^r = 42  (码本索引)
z~_0^d = IDM_d(o_0^d, o_{10}^d) → VQ → z_0^d = 17  (码本索引)
e_0^r = C^(s)[42], e_0^d = C^(s)[17]
h_0 = W_f · [e_0^r; e_0^d] + b_f  → VQ → z_0^u = 89  (统一潜在索引)
```

**Step 2: 验证统一潜在质量**
```
o^_10^r = FDM_r(o_0^r, z_0^u)  应接近真实 o_{10}^r
o^_10^d = FDM_d(o_0^d, z_0^u)  应接近真实 o_{10}^d
```
如果重建误差低，说明 z_0^u=89 确实编码了"手向前移动 0.2m 并闭合夹爪"这个动作的跨模态动态。

**Step 3: UniLACT 预训练**
```
输入：o_0^r + 指令"pick up the carrot" + z_0^u=89
输出：预测潜在序列 z_{1:N}^u (例如 [89, 91, 95, ...])
损失：L_latent^u = -log p_θ(z_1^u|...) - log p_θ(z_2^u|...) - ...
```

**Step 4: 微调后推理**
```
输入：o_0^r + "pick up the carrot"  (无需深度！)
输出：Δp = [0, 0, -0.2], Δr = [0, 0, 0], g = 1  (向下 20cm，闭合夹爪)
```

## 4. 工程视角 (Engineering View)

| 工程指标 | 数值/约束 | 含义 |
|----------|-----------|------|
| 训练 GPU | 4× NVIDIA H200 | 大规模预训练需要高显存 |
| 视觉编码器 | ViT-L (冻结，MAE 初始化) | 复用现成权重，减少训练成本 |
| 语言编码器 | T5 (冻结) | 标准选择 |
| VLA 主干 | GPT-2 causal transformer | 轻量级，适合自回归预测 |
| 动作输出 | 7-DoF (Δp∈R³, Δr∈R³, g∈{0,1}) | 覆盖常见机械臂控制 |
| 时间偏移 H | 未明确（典型值 5-10 帧） | 影响潜在动作的时间粒度 |
| 推理模态 | 仅 RGB | **关键优势**：部署无需深度传感器 |
| 训练模态 | RGB-D | 需要配对深度数据（仿真易得，真实世界需 Kinect/RealSense） |

**Trade-off 分析**：
- **计算开销**：三阶段训练比端到端 BC 复杂，但预训练数据无需标注
- **数据要求**：需要 RGB-D 视频（非标注轨迹），互联网规模的 RGB-D 数据集有限
- **部署友好**：推理时深度可选，适合只有 RGB 相机的机器人

**任务级分析**（来自项目页面）：

| 动态障碍物避让 | ⚠️ 未测试 | 实验为静态场景 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **RGB-D 标定准确**：假设 RGB 和深度帧已精确对齐，标定误差会污染潜在空间
2. **深度质量足够**：假设深度图噪声低（仿真完美，真实世界 RealSense/Kinect 有噪声）
3. **时间偏移 H 固定**：假设所有动作在 H 帧内完成，但实际动作时长可变
4. **码本容量充足**：VQ 码本大小未详细分析，过小会限制表示能力
