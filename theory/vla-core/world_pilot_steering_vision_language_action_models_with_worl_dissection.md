### 1.2 关键机制 (Key Mechanism)

**为什么是两条通路而非一条？**

WAM 的两个输出携带不同类型的信息：
- **场景演化潜变量 Z^w_t**：描述"场景将如何变化"——物体运动、接触结果、局部状态变化。这是**时空动力学预期**。
- **粗动作轨迹 A~^w_t**：描述"应该做什么动作"——产生上述场景变化的动作假设。这是**意图到运动的映射**。

两者来自 WAM 的共享编码器，在联合训练中结构对齐，天然互补。

**为什么用潜变量而非解码的未来图像？**

论文通过消融实验验证（Table 5）：用解码的未来图像通过 VLA 图像编码器注入，Total 成功率从 84.7% 降至 83.5%（下降 1.2 个百分点）。原因是像素级解码引入了与动作无关的细节（纹理、光照、背景、生成伪影），稀释了潜变量中编码的动力学结构。

**为什么动作轨迹压缩为单个 token 而非逐步 token？**

消融实验（Table 6）表明：
- 单 token：84.7%（最佳）
- 逐步编码 token：83.6%（绑定噪声步级信号，误差累积）
- 流匹配初始化：84.1%（受限于 WAM 动作质量，生成器修正空间小）
- 原始轨迹：83.0%（最弱）

单 token 概括轨迹的整体形状，让生成器自由地结合先验和动力学增强隐状态做出具体决策。

⚡ **Eureka Moment**：VLA 缺的不是更强的语义理解，而是对"场景在动作下如何演化"的预期——这个预期恰好被视频预训练的 WAM 以潜变量形式编码着，且不需要对 WAM 做动作微调就能生效。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L = E[ w(τ) · ||ĝ_θ(X_τ,t, τ, u_t, s^w_t, Q_t | H̄_t) - A^*_t||² ]
    └─ 流匹配损失    └─ 动作生成器           └─ 专家动作块
    H̄_t = H_t + CrossAttn(H_t, f_dyn(Z^w_t) + ρ_fut)
    └─ 动力学增强隐状态 = 原始 + 交叉注意力注入的场景演化先验
```

**目标**：训练 VLA 策略 π_θ 学会利用 WAM 提供的两个先验（场景演化潜变量 Z^w_t 和粗动作轨迹 A~^w_t），生成比纯语义 conditioning 更鲁棒的动作块。

**完整公式链**：

1. **WAM 前向**（冻结）：
```
(Z^w_t, A~^w_t) = W_φ(O_t, ℓ, q_t)
```

2. **Latent Steering**（残差交叉注意力）：
```
D^w_t = f_dyn(Z^w_t) + ρ_fut
H̄_t = H_t + CrossAttn(H_t, D^w_t)
```
- H_t ∈ R^{L×d}：VLM 隐状态
- f_dyn：动态编码器（投影层）
- ρ_fut：时间嵌入标记"未来场景 token"（无此标记时先验贡献显著下降）
- CrossAttn 让每个 VLM token 选择性关注 $D^w_t$ 中最相关的空间区域

3. **Action Steering**（单 token 压缩）：
```
s^w_t = f_act(Align_K(A~^w_t))
```
- Align_K：将 WAM 轨迹重采样到 VLA 动作视界 K
- f_act：动作编码器
- $s^w_t$ 作为前缀 token 进入流匹配生成器，不被去噪

4. **流匹配动作生成**：
```
X_τ,t = τ·A^*_t + (1-τ)·ε    (带噪轨迹)
Â_θ,t = g_θ(X_τ,t, τ, u_t, s^w_t, Q_t | H̄_t)  (预测干净动作)
```

5. **训练损失**（速度空间加权 L2）：
```
L = E_{τ,ε} [ w(τ) · ||Â_θ,t - A^*_t||² ]
w(τ) = 1 / (1-τ)²
```
- $w(\tau)$ 实现速度空间等效损失（ABot-M0 的 clean-action 参数化）
- WAM 先验仅通过 conditioning 路径进入，不需要单独的先验损失

> 符号与本文保持一致：上标 $w$ 表示 WAM 输出，下标 $t$ 表示时间步，$\theta$ 表示 VLA 可训练参数，$\phi$ 表示冻结的 WAM 参数。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2D 操作场景：机械臂需要将一个红色方块推到目标区域。

**Step 1: WAM 前向**
- 输入：当前帧 O_t（方块在位置 (2, 3)），指令 ℓ = "推方块到目标"
- WAM 输出：
  - $Z^w_t$：场景演化潜变量，编码"方块将向右上方移动"
  - A~^w_t：粗轨迹 = [(0.1, 0.05), (0.15, 0.08), (0.12, 0.06), ...]（10 步）

**Step 2: Latent Steering**
- $f_\text{dyn}(Z^w_t)$ 投影到 $d=2048$ 维，加上 $\rho_\text{fut}$ 时间戳
- H_t 有 50 个 token（对应图像 patch），每个 2048 维
- $\text{CrossAttn}(H_t, D^w_t)$：每个 patch token 注意力权重集中在与方块运动区域相关的 $D^w_t$ 部分
- 假设 CrossAttn 输出约为 $0.3 \cdot H_t$（残差比例），则 $\overline{H}_t \approx 1.3 \cdot H_t$（在运动方向上增强）

**Step 3: Action Steering**
- Align_K 将 10 步 WAM 轨迹重采样到 K=8 步（VLA 视界）
- $f_\text{act}$ 编码为单个 token $s^w_t \in \mathbb{R}^{2048}$，概括"向右上方推"的整体形状
- 流匹配生成器输入：$[u_t$（本体状态）; $s^w_t$（运动先验）; $Q_t$（未来查询）; $X_{\tau,t}$（噪声轨迹）$]$

**Step 4: 去噪生成**
- $\tau=0.5$ 时：$X_{\tau,t} = 0.5 \cdot A^*_t + 0.5 \cdot \varepsilon$
- 生成器预测：Â_θ,t = g_θ(...)
- 假设专家动作 A^*_t = [(0.12, 0.06), (0.14, 0.07), ...]
- 生成器输出：Â_θ,t = [(0.11, 0.05), (0.13, 0.06), ...]（接近专家但有自己的微调）

**Step 5: 损失计算**
- 假设 ||Â_θ,t - A^*_t||² = 0.002（L2 误差）
- $w(0.5) = 1/(1-0.5)^2 = 4$
- 当前样本损失 $L = 4 \times 0.002 = 0.008$

**OOD 场景下的差异**：
- 如果方块颜色从红色变为蓝色（OOD），纯 VLA 的 H_t 可能无法正确编码，导致动作偏差大
- 但 WAM 的视频预训练覆盖了多种颜色，$Z^w_t$ 仍然编码正确的运动方向
- Latent Steering 将正确的运动预期注入 $\overline{H}_t$，Action Steering 提供正确的运动形状 $s^w_t$
- 最终 Â_θ,t 更接近专家动作，成功率更高

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|-----------|----------|
| **训练硬件** | 8× RTX PRO 6000 | 中等规模集群，非超大模型训练 |
| **训练步数** | 10,000 步（真实机器人） | 相对较少，WAM 先验加速收敛 |
| **WAM 训练** | 冻结，不参与梯度 | 训练时可预计算并缓存，不增加训练 FLOPs |
| **WAM 推理** | 在线运行，5 步去噪 | 每决策步需额外运行 WAM，增加延迟 |
| **Dropout** | 0.3 作用于 WAM 条件 | 防止策略过度依赖先验，提升鲁棒性 |
| **动作视界 K** | 8 步（与 ABot-M0 一致） | WAM 轨迹需重采样对齐 |
| **VLM 主干** | Qwen3-VL | 开源多模态模型，可替换 |
| **WAM** | Cosmos Policy (NVIDIA) | 闭源，依赖外部 API 或本地部署 |

**部署约束分析**：
- WAM 在线推理是主要延迟瓶颈。如果 WAM 需要 100ms 完成 5 步去噪，则系统控制频率上限约 10Hz
- 训练时 WAM 可预计算——这意味着训练和推理的融合行为必须一致，论文声称"identically shaped priors"保证了这一点
- 单个 prior token 的设计减少了 Action Steering 的参数量和计算开销

### 6.1 隐含假设 (Hidden Assumptions)

1. **WAM 质量是上限**：论文假设 WAM 提供的先验质量足够高。如果 WAM 的场景演化预测错误，两个通路都会注入错误信号。论文未系统研究 WAM 误差传播。

2. **WAM 与 VLA 的观测对齐**：假设 WAM 和 VLA 接收相同的视觉观测。如果传感器模态不同（如 WAM 用 RGB-D，VLA 只用 RGB），需要先验对齐。

3. **动作视界可对齐**：假设 WAM 的轨迹视界可通过重采样对齐到 VLA 的 K 步。对于视界差异大的情况（如 WAM 预测 50 步，VLA 需要 8 步），重采样可能丢失关键信息。

4. **单臂桌面操作泛化性**：所有实验在单臂桌面设置下完成。未验证对移动机器人、双臂、人形机器人的适用性。

5. **WAM 推理延迟可接受**：论文未量化 WAM 在线推理的延迟开销。在高频控制场景（如 >30Hz）中可能成为瓶颈。

- Being-H0.7 和 WoG 使用潜变量但仍依赖静态未来快照
- World Pilot 是唯一同时利用场景演化潜变量（连续时空预期）和动作轨迹先验（意图-运动映射）的方法

💡 **面试 Tip**：当被问"World Pilot 与之前世界模型+VLA 方法的核心区别是什么"时，回答："核心区别在于信号形式和注入位置。之前的方法要么用像素级未来图像（引入噪声），要么用静态快照（缺乏连续性）。World Pilot 用 WAM 的连续场景演化潜变量注入感知层、用压缩动作轨迹注入生成层，两个信号在 WAM 共享编码器中结构对齐，天然互补。"
