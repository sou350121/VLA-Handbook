### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **选择性模块复制**：只复制 VLM 主干（决策层），共享视觉编码器和动作头（感知和执行层）。理由：视觉理解和低级控制是具身无关的，而动作决策需要臂特定策略。

2. **联合注意力 (Joint Attention)**：在每层 Transformer 中，将左右臂的 Q/K/V 拼接后执行自注意力，再拆分回各自流。这允许双臂直接"看到"对方的观测令牌。

3. **MoE 处理共享输入**：语言指令和 ego-centric 图像对双臂是相同的，通过 MoE 动态路由到左右臂专家，避免冗余处理，VRAM 降低 21%。

4. **注意力重加权 (Attention Re-weighting)**：微调时重新缩放共享模态的注意力分数，防止新引入的臂特定令牌破坏预训练注意力模式。

⚡ **Eureka Moment**：双臂协调的本质不是训练一个更大的单片模型，而是让两个已经学会"如何操作"的单臂策略学会"如何互相配合"——就像人类大脑通过胼胝体连接左右半球，而不是重新训练一个"双臂大脑"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
π_twin(A^L, A^R | o_twin) = JointAttn(π_single(A^L | o^L), π_single(A^R | o^R))
```

**目标**：将预训练单臂策略 $\pi_{\text{single}}$ 组合成双臂策略 $\pi_{\text{twin}}$，无需重新预训练。

**条件流匹配损失 (Conditional Flow Matching)**：

```
L^T(θ) = E_{p(A_t|o_t), q(A_t^τ|A_t)} [ ||v_θ(A_t^τ, h_t, d_t) - u(A_t^τ|A_t)||² ]
```

**变量说明**：
| 符号 | 含义 |
| --- | --- |
| A_t | 目标动作块 $(a_t, \dots, a_{t+T-1})$，$T=20$ |
| $A_t^\tau$ | 噪声动作（从 $\tau=0$ 到 $\tau=1$ 的扩散过程） |
| h_t | VLM 输出嵌入（来自 readout token） |
| d_t | 本体感知（关节位置/速度） |
| $v_\theta$ | 动作头预测的流（从噪声到目标的向量场） |
| u | 参考流（从 $A_t^\tau$ 到 $A_t$ 的理想路径） |

**推理时的动作采样**（前向 Euler 积分）：

```
A_t^{τ+δ} = A_t^τ + δ · v_θ(A_t^τ, h_t, d_t),   δ = 1/10, 迭代 10 步
```

**MoE 路由公式**（共享输入处理）：

```
MoE(x) = w_left · FFN_left(x) + (1 - w_left) · FFN_right(x)
```

其中 w_left 通过线性层 + softmax 从输入嵌入计算得到。

> 符号与本文/相关文档保持一致：$\pi$ 表示策略，$A$ 表示动作块，$o$ 表示观测，$h$ 表示 VLM 嵌入。

**直觉解释**：条件流匹配让模型学习"如何从噪声动作走到目标动作"的向量场，而不是直接预测动作。这比行为克隆更稳定，因为模型看到的是连续流而非离散点。联合注意力让左右臂的流预测互相影响——左臂知道右臂在做什么，反之亦然。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设 TwinVLA 执行"把毛巾折叠进篮子"任务：

**输入观测**（t=0）：
- 语言指令："Fold the towel and put it in the basket"
- Ego 图像：$640\times480$ RGB，看到桌子上的毛巾和篮子
- 左腕图像：看到左 gripper 靠近毛巾左角
- 右腕图像：看到右 gripper 靠近毛巾右角
- 本体感知：左臂 [x,y,z,roll,pitch,yaw] = [0.3, -0.2, 0.1, 0, 0, 0]，右臂对称

**前向传播**：
1. 视觉编码器提取图像特征 $\to$ $256$ 维令牌
2. 语言指令 $\to$ $32$ 维令牌
3. 左右臂 VLM 各处理：256 (视觉) + 32 (语言，MoE 路由) + 64 (臂特定) = 352 令牌
4. 联合注意力层：$352 \times 2 = 704$ 令牌拼接 $\to$ 自注意力 $\to$ 拆分回 $352 + 352$
5. 经过 $12$ 层 Transformer $\to$ 左右臂各输出 $1$ 个 readout token ($768$ 维)

**动作预测**：
- DiT 动作头接收：$2 \times 768$ (左右 readout) $+ 12$ (本体感知) $= 1548$ 维
- 预测动作块：左右臂各 $20$ 步 $\times 10$ 维 ($6$D 位置 $+ 4$D gripper) $= 200$ 维
- 使用条件流匹配：从噪声 $A^0 \sim \mathcal{N}(0,I)$ 开始，迭代 $10$ 步得到最终动作

**假设数值**（第 1 步采样后）：
- 左臂动作：$\Delta x=-0.01$, $\Delta y=0.02$, $\Delta z=-0.005$, gripper 闭合 $0.1$
- 右臂动作：$\Delta x=0.01$, $\Delta y=0.02$, $\Delta z=-0.005$, gripper 闭合 $0.1$
- 关键：联合注意力让左右臂的 $\Delta x$ 符号相反（对称抓取），这是通过跨臂注意力学到的协调  

**控制频率**：20 Hz，每个动作块覆盖 1 秒（20 步 $\times$ 0.05 s），执行完第 1 步后重新观测并预测新块。  

## 4. 工程视角 (Engineering View)

| 工程指标 | SingleVLA | TwinVLA | 含义 |
| --- | --- | --- | --- |
| 参数量 | 0.8B | 1.3B | 增加 62.5%，但仅复制 VLM |
| VRAM 占用 (训练) | ~15 GB | ~19 GB | MoE 降低 21%，否则 ~24 GB |
| 推理延迟 | ~50 ms | ~80 ms | 联合注意力增加 ~30 ms |
| 控制频率 | 20 Hz | 20 Hz | 与单臂相同，实时性足够 |
| 动作块大小 | 20 步 | 20 步 | 覆盖 1 秒，平衡平滑性与响应 |
| 采样步数 | 10 | 10 | 流匹配迭代次数，可降至 5 加速 |
| 微调数据需求 | N/A | 50 条/任务 | 约 2-3 小时遥操作收集 |
| 微调时间 | N/A | ~2 天 (1$\times$ L40S)   | 每任务独立微调 |

**部署约束**：
- **计算资源**：推理可在单张 RTX 4090 上运行（~12 GB VRAM），但训练需要 A100/H100
- **延迟预算**：80 ms 推理 + 50 ms 通信 + 20 ms 控制 = ~150 ms 端到端，对于 20 Hz 控制足够
- **量化误差**：论文使用 BF16 精度，未测试 INT8/FP8 量化，部署时可能需要校准
- **抖动问题**：绝对 EEF 控制避免了相对控制的误差累积，但对相机外参标定敏感

**工程含义**：TwinVLA 的核心优势是"预训练一次，微调多次"——SingleVLA 的 800 小时预训练是固定成本，之后每个新双臂任务只需 50 条演示和 2 天微调。相比之下，RDT-1B 每个新任务都需要重新训练单片模型。

### 6.1 隐含假设 (Hidden Assumptions)

**X-Ray 批判视角**：

1. **双臂视觉对称假设**：论文假设左右腕相机视角对称，但真实机器人可能存在安装误差或遮挡。未测试非对称相机配置。

2. **绝对 EEF 控制足够假设**：选择绝对末端执行器控制是因为"具身无关"，但这牺牲了关节空间的可解释性。对于冗余自由度机器人（7 DoF+），逆运动学可能引入额外误差。

3. **预训练数据质量假设**：SingleVLA 在 OXE 子集上预训练，但 OXE 包含大量低质量演示。论文通过"仅保留成功轨迹"过滤，但未分析过滤标准对泛化的影响。

4. **任务独立性假设**：每个双臂任务独立微调 50 条演示，但未测试多任务联合微调或持续学习场景。真实场景中任务可能是相关的。

5. **仿真到真实迁移假设**：RoboTwin 和 Tabletop-Sim 结果良好，但仿真到真实的域差异未系统评估（仅 5 个真实任务）。
