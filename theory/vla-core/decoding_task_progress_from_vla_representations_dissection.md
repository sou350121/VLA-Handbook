### 1.2 关键机制 (Key Mechanism)

**为什么 VLA 内部会有进度信号？**

1. **预训练阶段已有雏形**：信号在 PaliGemma  backbone（纯视觉-语言预训练）中已可弱解码，说明语言-视觉对齐本身编码了某种"任务感"
2. **机器人预训练强化信号**：π0.5 基座（大规模机器人预训练后）显著优于 PaliGemma，证明动作数据让进度表征更精确
3. **微调不改变信号**：VLABench 微调后性能与基座相当，说明进度信号是预训练建立的稳定表征，不受下游微调破坏

**三层定义体系——从"存在"到"有用"到"可控"：**

- **弱可解码性**：在分布内数据上，线性探针能预测进度（R²=0.95 at layer 0）
- **强可解码性**：同一探针在语言反事实扰动下仍正确响应（需对比训练，代价是 ID R² 降至 0.33）
- **可控性（Steerability）**：沿探针方向注入激活能否改变策略输出——**答案是否定的**

⚡ **Eureka Moment**：VLA 内部已经编码了"任务还剩多少没做完"的信号——你不需要训练一个额外的模型来检测机器人是否卡住，只需要在 VLA 自己的激活上画一条线。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
τ(x_t) = 1 - t / T,  φ(z⁰_t) = wᵀz⁰_t + b ≈ τ(x_t)
```

任务进度 τ 定义为归一化剩余时间。线性探针 φ 从第 0 层残差激活 z⁰ 中恢复 τ。

**目标**：从 VLA 内部激活 zⁱ_t 中预测标量 τ(x_t) ∈ [0, 1]。

**核心方程**：

```
探针预测:  φ(zⁱ) = wᵀzⁱ + b
训练损失:  L = (1/K) Σ_k ||φ(zⁱ_k) - τ_k||₁
风险定义:  R(φ; D) = (1/K) Σ_k L(φ(zⁱ_k); τ_k)
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| zⁱ_t | 第 i 层、时间步 t 的残差流激活（d 维，token 平均池化） |
| τ(x_t) | 任务进度 = 1 - t/T，T 为轨迹总步数 |
| w, b | 线性探针的权重向量和偏置 |
| L | L₁ 损失（连续回归） |
| R(φ; D) | 探针在数据集 D 上的期望风险 |

**可控性注入方程**（尝试但失败的干预）：

```
z̃ⁱ(x) = zⁱ(x) + [ζ(T(x)) - ζ(x)] / ||w||² · w
```

沿 w 方向注入激活偏移，使探针读出反事实值，但策略输出不跟随变化。

**OOD 检测残差**：

```
V_τ(t) = τ_pred - (1 - t / E[T|ℓ])
判定: V_τ(t) > δ → 标记为 OOD
```

> 符号与本文保持一致：τ 表示进度（0=刚开始，1=刚完成，随时间递减），zⁱ 表示第 i 层激活，φ 表示线性探针。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个 100 步的"把红杯子放到盘子上"任务：

**步骤 1：探针训练**
- 收集 400 条 ID 轨迹（100 条/任务 × 4 任务）
- 每条轨迹 t=0,...,99，标签 τ_t = 1 - t/100
- 在 layer 0 激活上训练线性回归，得到 w, b
- 结果：ID 测试集 R² = 0.95（论文 §4.2）

**步骤 2：正常运行**
```
t=0:  τ_true=1.00,  τ_pred=0.98  (误差 0.02)
t=25: τ_true=0.75,  τ_pred=0.73  (误差 0.02)
t=50: τ_true=0.50,  τ_pred=0.51  (误差 0.01)
t=75: τ_true=0.25,  τ_pred=0.24  (误差 0.01)
t=99: τ_true=0.01,  τ_pred=0.02  (误差 0.01)
```
误差很小，τ_pred 单调递减——一切正常。

**步骤 3：机器人卡住（OOD）**
假设在 t=40 时遇到未见过的视觉扰动（比如突然变暗）：
```
t=40: τ_true=0.60, τ_pred=0.61  (正常)
t=45: τ_true=0.55, τ_pred=0.58  (开始偏离)
t=50: τ_true=0.50, τ_pred=0.56  (进度停滞！)
t=55: τ_true=0.45, τ_pred=0.55  (τ_pred 不降了)
t=60: τ_true=0.40, τ_pred=0.54  (明确异常)
```

**步骤 4：OOD 检测触发**
```
E[T|ℓ] = 100（从 ID 轨迹估计）
δ = 0.15（阈值）

t=50: V_τ(50) = 0.56 - (1 - 50/100) = 0.56 - 0.50 = 0.06 < δ → 正常
t=55: V_τ(55) = 0.55 - (1 - 55/100) = 0.55 - 0.45 = 0.10 < δ → 正常
t=60: V_τ(60) = 0.54 - (1 - 60/100) = 0.54 - 0.40 = 0.14 ≈ δ → 预警
t=65: V_τ(65) = 0.53 - (1 - 65/100) = 0.53 - 0.35 = 0.18 > δ → 触发 OOD！
```

探针检测到进度停滞，在 t=65 触发 OOD 告警。

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/评估 | 含义 |
|----------|----------|------|
| 探针参数量 | d（嵌入维度，PaliGemma 约 2048-4096） | 极小，可忽略 |
| 推理开销 | 一次矩阵向量乘法 wᵀz⁰ | 单次前向 < 1ms（GPU） |
| 训练数据量 | 400 条 ID 轨迹（100/任务 × 4 任务） | 中等，但无需 OOD 数据 |
| 训练时间 | 线性回归，秒级 | 几乎为零 |
| 部署位置 | VLA 推理管线中的 layer 0 激活之后 | 零额外延迟 |
| 内存占用 | w (d 维) + b (标量) + E[T|ℓ] (每任务标量) | KB 级 |
| 跨任务复用 | 单探针用于 10 个任务 | 无需每任务重训 |
| 跨扰动鲁棒性 | 未见扰动 AUROC 0.871（per-replan） | 优于需监督的基线 |

**工程含义**：
- 探针可以作为一个"监控 sidecar"附加到任何基于 π0.x 的部署中，不影响主策略推理延迟
- 阈值 δ 需要根据具体任务的 E[T|ℓ] 校准——不同任务可能有不同合理进度衰减率
- 对于 replan-based 策略（如 π0.5 的 5Hz 重规划），每次 replan 只需额外计算一次 wᵀz⁰，增量成本可忽略

## 5. 数据与评测 (Data & Eval)

**数据集**：VLABench [30]
- 10 个操作任务，带语义变化（目标物体名称不同）
- 每任务 500 条专家轨迹
- 训练：400 条（100/任务 × 4 任务）
- 测试：50 条/任务（held-out）

**OOD 生成**：
- 4 种图像增强：高斯噪声、颜色偏移、模糊、遮挡
- 3 个注入点：轨迹的 25%、50%、75% 处
- 每任务每条件 50 条 OOD 轨迹

**评测指标**：
- 弱可解码性：ID 测试集 R² / L₁ loss
- 强可解码性：反事实扰动下探针输出一致性
- 可控性：注入后动作分布与真实反事实动作的距离
- OOD 检测：per-replan AUROC + per-episode AUROC

**关键实验设置**：
- 层 0（SigLIP 输出）用于弱可解码性和 OOD 检测
- 层 10（Gemma 中间层）用于强可解码性（对比训练）
- 对比基线：Mahalanobis、VAE、SAFE-MLP、SAFE-LSTM

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

| 能力 | 条件 | 性能 |
|------|------|------|
| 解码任务进度 | ID 任务，layer 0 | R² = 0.95 |
| 跨任务泛化 | 未见任务，零样本 | per-replan AUROC 0.833 |
| 跨扰动泛化 | 未见扰动类型 | per-episode AUROC 0.960 |
| 语言敏感性 | 对比训练后，layer 10 | 反事实下 τ ≈ 1.0 |

### 不能做什么

| 失败模式 | 原因 |
|----------|------|
| 策略控制（Steering） | 注入激活不改变后续层输出，进度信号存在于"读通道"而非"写通道" |
| 纯视觉层强可解码性 | Layer 0 探针依赖视觉输入，忽略语言指令（R²=0.95 但对语言扰动无响应） |
| 语义进度 vs 时间进度区分 | 进度定义为归一化时间，可能只是"过了多久"而非"完成了多少" |
| 跨架构迁移 | 仅在 π0.x 系列验证，未测试 OpenVLA、RT-2 等 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **进度 = 归一化时间**：论文用 τ = 1 - t/T 定义进度，但这假设所有成功轨迹步数一致。如果任务可以在不同步数内完成，这个定义会混淆"时间流逝"和"语义完成"。
2. **E[T|ℓ] 可估计**：OOD 检测器需要预先知道每个语言指令的预期完成时间。在开放词汇场景下，新指令的 E[T|ℓ] 如何获取未讨论。
3. **仿真到真机可迁移**：所有实验在 VLABench 仿真中完成。真实世界的传感器噪声、延迟、动力学差异可能改变进度信号的线性可读性。
4. **单模型家族结论**：仅测试 π0.x 系列。不同 backbone（如 SigLIP vs CLIP）、不同训练数据配比可能产生不同表征结构。
5. **对比训练标签的近似性**：强可解码性训练中，反事实指令的进度标签被近似为 τ=1.0（零进度），这是一个粗糙代理——真实语义进度难以定义。
