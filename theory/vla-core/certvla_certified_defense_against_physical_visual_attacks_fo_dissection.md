💡 **X-Ray 开场**
VLA 模型把视觉感知和语言指令直接映射到机器人动作，但这也创造了物理攻击面——场景中的一个补丁或物体上的对抗纹理可以持续破坏整个闭环轨迹。CertVLA 首次解决了"如何为连续 VLA 动作提供可认证防御"的问题：它用确定性覆盖掩码保证至少一次推理擦除了攻击区域，再用校准的一致性区域判断恢复后的动作是否可信。对 VLA 研究者意味着——安全关键部署首次有了不依赖特定攻击方法的数学保证。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 输入 | 输出 | 阶段 | 关键参数 |
|------|------|------|------|----------|
| R-覆盖掩码族 M | 图像尺寸 | K 个确定性掩码 | 预定义 | 掩码大小 M、步长 s、认证补丁大小 P（需 P ≤ M−s+1） |
| 位置尺度矩阵 Q | 干净校准数据 C_scale | K×K 矩阵，每对掩码的 benign 变化尺度 | 校准阶段 I | β 分位数（默认 0.95） |
| 回合级阈值 τ | 干净校准数据 C_row + Q | 标量接受阈值 | 校准阶段 II | 误覆盖率 α（默认 0.5） |
| DualMaskRecover | 观测 x、指令 ℓ、Q、τ | 动作 Â、选中行 î、认证标志 c | 部署 | K² 次 VLA 前向推理 |
| DefendedRollout | 环境 E、π、Q、τ | 任务结果 S_def、回合认证 C | 部署 | 回合最大步数 T |

**训练/推理差异**: CertVLA 不需要修改 VLA 模型权重——它是模型无关的后处理防御层。所有计算开销发生在推理时。

### 1.2 关键机制 (Key Mechanism)

CertVLA 的核心设计围绕三个关键洞察：

1. **连续动作不能用精确匹配认证**。离散分类中两个掩码输出相同标签即可认证；但 VLA 输出连续动作块，行为等价的动作不需要完全一致。CertVLA 引入"校准动作一致性区域"——只要双掩码预测落在以单掩码锚点为中心、由位置尺度归一化的区域内，即视为一致。

2. **不同掩码位置有不同的 benign 变化尺度**。掩码 i 和 j 遮挡不同场景内容，导致即使在没有攻击的情况下，动作变化幅度也不同。CertVLA 用干净数据估计每对掩码的参考尺度 Q_{i,j}，使不同位置的归一化偏差可比。

3. **查询级认证可组合为回合级认证**。单个策略查询的认证只约束当前动作块；CertVLA 通过逻辑合取（C = ∧_t c_t）将每个查询的认证标志组合为完整回合的认证，即使攻击位置随时间变化也成立。

⚡ **Eureka Moment**: 用 max_q min_i max_j 的标量分数精确编码 "∀查询 ∃锚点 ∀第二掩码" 的逻辑结构——将嵌套量化判断转化为一个可校准的连续阈值问题。

### 1.3 信息流/架构图 (Flow / Diagram)

```
                    ┌─────────────────────────────────────────┐
                    │          校准阶段 (离线)                    │
                    └─────────────────────────────────────────┘
  干净回合 C_scale ──→ 每对掩码 (i,j) 收集距离集合 D_scale ──→ Q_{i,j} = β-分位数
  干净回合 C_row  ──→ 计算每回合分数 S_e = max_q min_i max_j z ──→ τ = (1-α)-分位数

                    ┌─────────────────────────────────────────┐
                    │          部署阶段 (在线)                    │
                    └─────────────────────────────────────────┘
  观测 x ──→ DualMaskRecover(x, ℓ, π, M, Q, τ):
    for i = 1..K:                              ← 遍历每个单掩码作为锚点
      A_i = π(M_i(x), ℓ)                       ← 单掩码预测
      R_i = 0
      for j = 1..K:                            ← 对每个锚点，检查所有第二掩码
        A_{i,j} = π(M_j(M_i(x)), ℓ)            ← 双掩码预测
        R_i = max(R_i, d(A_{i,j}, A_i) / (Q_{i,j}+ε))  ← 更新行分数
        if R_i > τ: break                      ← 早停：该行不可能通过
      if R_i ≤ τ: return (A_i, i, TRUE)        ← 认证通过！
    return (A_best, i_best, FALSE)              ← 无认证行，返回最佳未认证动作

  回合级: C = ∧_t c_t（所有查询都通过 → 回合认证）
```

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
认证通过 ⟺ ∃i: max_j [ d(A_{i,j}, A_i) / (Q_{i,j} + ε) ] ≤ τ
```

**目标**: 在未知攻击位置的情况下，从 K 个候选单掩码锚点中选出至少一个——其所有 K 个双掩码检查都落在校准的一致性区域内。

**核心方程**:

```
方向性动作距离:
  d(A, B) = (1 / hD) · Σ_r Σ_u |A_{r,u} − B_{r,u}| / η_u(B_{r,u})
  其中 η_u(b) = max(|a⁺_u − b|, |b − a⁻_u|, ε)

归一化一致性分数:
  z_{e,q,i,j} = d(A_{e,q,i,j}, A_{e,q,i}) / (Q_{i,j} + ε)

回合分数:
  S_e = max_q min_i max_j z_{e,q,i,j}

阈值校准 (共形):
  τ = S_{(k)},  k = ⌈(n+1)(1−α)⌉

认证条件:
  ∃i: max_j z_{q,i,j} ≤ τ
```

**变量说明**:

| 符号 | 含义 |
|------|------|
| A, B | 动作块矩阵 (H×D)，分别为双掩码和单掩码预测 |
| h | 执行步数（动作块中实际执行的前 h 个动作） |
| D | 动作维度 |
| Q_{i,j} | 掩码对 (i,j) 的 β-分位数参考尺度 |
| τ | 回合级接受阈值（由共形校准确定） |
| α | 干净回合误覆盖率目标 |
| β | 位置尺度估计的分位数 |
| ε | 数值稳定性常数（默认 10⁻⁸） |
| K | 掩码数量（如 8×8=64） |

> 符号与本文保持一致。方向性距离 d(A,B) 在锚点 B 处评估，因此 d(A,B) ≠ d(B,A)。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：

- 动作维度 D=2（x, y 平移），执行步数 h=1
- 动作范围: x ∈ [−1, 1], y ∈ [−1, 1]
- K=3 个掩码（M1, M2, M3）
- 位置尺度矩阵 Q（从干净数据校准得到）:

```
Q = [[0.10, 0.15, 0.12],
     [0.13, 0.08, 0.11],
     [0.14, 0.10, 0.09]]
```

- 校准阈值 τ = 1.5

**部署时**，观测被攻击，VLA 输出:

```
A_1 (锚点) = [0.5, 0.3]
A_{1,1} = [0.52, 0.31]  ← M1(M1(x))
A_{1,2} = [0.58, 0.35]  ← M2(M1(x))
A_{1,3} = [0.75, 0.50]  ← M3(M1(x)) — 可疑！
```

计算各行分数:

```
行 1 (锚点 A_1):
  d(A_{1,1}, A_1) = (|0.02|/1.5 + |0.01|/1.7) / 2 ≈ 0.0103
  z_{1,1} = 0.0103 / (0.10 + ε) ≈ 0.103

  d(A_{1,2}, A_1) = (|0.08|/1.5 + |0.05|/1.7) / 2 ≈ 0.0347
  z_{1,2} = 0.0347 / (0.15 + ε) ≈ 0.231

  d(A_{1,3}, A_1) = (|0.25|/1.5 + |0.20|/1.7) / 2 ≈ 0.1275
  z_{1,3} = 0.1275 / (0.12 + ε) ≈ 1.063

  R_1 = max(0.103, 0.231, 1.063) = 1.063 ≤ 1.5 ✓ 认证通过！
```

即使 A_{1,3} 偏差较大（可能是 M3 擦除了攻击区域后的干净预测），只要归一化后不超过 τ，该行就通过认证。

```
行 2 (锚点 A_2):
  假设 R_2 = 2.1 > 1.5 ✗ 该行被拒绝（早停在某个 j 处）

行 3 (锚点 A_3):
  假设 R_3 = 1.8 > 1.5 ✗ 该行被拒绝

最终: 返回 (A_1, i=1, c=TRUE) — 认证动作
```

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 含义 |
|------|-----------|------|
| 推理开销 | K² 次 VLA 前向传播/查询 | K=64 (8×8) → 4096 次推理/查询；早停可削减常数因子但最坏情况不变 |
| 控制频率影响 | 若 VLA 以 1Hz 查询，单次查询 4096 次前向 ≈ 秒级延迟 | 对高频控制（10-100Hz）不可行；适合低频率决策场景 |
| 内存开销 | 需缓存 K 个单掩码 + 最多 K² 个双掩码预测 | 与 VLA 模型大小成正比；OpenVLA-7B 约 14GB/次 |
| 校准数据需求 | 需要两类干净回合：C_scale（估计 Q）和 C_row（校准 τ） | 数据量 n 影响共形覆盖保证；太少则 τ 不稳定 |
| 量化误差 | 方向性距离的分母 η_u 用动作有效范围归一化 | 对动作范围敏感；不同机器人平台的动作空间需分别校准 |
| 早停优化 | 行分数单调不减，超 τ 即可 break | 实际平均推理次数 < K²；取决于 τ 松紧 |

**工程含义**: CertVLA 的认证保证以显著计算代价换取。对于 OpenVLA 等 7B 参数模型，每次策略查询需要数千次前向传播，这使其更适合离线或低频安全关键场景（如医疗/工业操作），而非高频实时控制。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

| 场景 | 能力 | 原因 |
|------|------|------|
| 已知大小未知位置的补丁攻击 | ✅ 可认证防御 | R-覆盖保证至少一个掩码擦除攻击 |
| 对抗纹理攻击 | ✅ 可认证防御 | 认证只依赖可见污染的支撑集大小，与生成方式无关 |
| 攻击位置随时间变化 | ✅ 回合级认证仍有效 | 每个查询独立认证，合取组合 |
| 任意补丁内容/生成方法 | ✅ 内容无关 | 定理不假设补丁内容，只要求支撑集有界 |

### 不能做什么

| 场景 | 限制 | 原因 |
|------|------|------|
| 超大补丁（超过 P×P） | ❌ 无法认证 | R-覆盖不再保证有掩码完全擦除攻击 |
| 认证 = 任务成功 | ❌ 不保证 | 认证只保证动作一致性，不保证任务完成（需额外假设） |
| 高频实时控制 | ❌ 计算开销过大 | K² 次推理/查询 |
| 无校准数据 | ❌ 无法工作 | 需要干净回合估计 Q 和 τ |

### 6.1 隐含假设 (Hidden Assumptions)

1. **干净校准数据可获得且代表部署分布**。如果校准数据与真实部署环境差异大（不同机器人、不同物体、不同光照），Q 和 τ 的估计会偏差，导致过度拒绝或过度接受。

2. **双掩码 rollout 正确性**（Definition 3）。认证保证任务成功的前提是：在每个查询时刻，存在一对掩码 (i_t, j_t) 使得干净双掩码预测落在一致性区域内。这个条件未被论文直接验证——它假设"擦除攻击后的动作自然能完成任务"，但某些场景下掩码本身可能遮挡关键视觉信息导致动作失效。

3. **动作范围已知且固定**。方向性距离的分母 η_u 依赖动作有效范围 [a⁻_u, a⁺_u]，这需要预先知道或估计。

4. **单连通攻击区域**。威胁模型假设攻击区域是单个连通区域 Ω_t ∈ R(P)。多个分散的小补丁或全局性攻击超出此模型。
