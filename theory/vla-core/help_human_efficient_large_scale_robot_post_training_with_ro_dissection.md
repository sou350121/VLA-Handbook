## 1. 核心架构/方法总览

### 1.1 系统对比概览

| 维度 | HITL-only（基线） | HELP（本文） |
|------|-------------------|-------------|
| 人类角色 | 单一操作员（遥操作 + 重置 + 监控） | 双角色分工：Teleoperator（遥操作）+ Floor Operator（监控 + 重置） |
| 机器人规模 | 通常 1-4 台 | 12 台并发 |
| 轨迹处理 | 整条轨迹用于训练（含失败片段） | VLAC-CUT 自动分割：保留 progress-making + recovery，丢弃 idle + failure-inducing |
| 数据配比 | HITL 恢复数据 + 基础演示 | HITL +  curated rollout + 基础演示 $\approx$ 1:1:1 |
| 训练方式 | SFT on HITL data | SFT on curated autonomous + HITL data |
| 核心瓶颈 | 人类任务切换成本高、认知过载 | 需要 VR 基础设施和专用网络（ZeroMQ/UDP） |

### 1.2 关键机制

HELP 的设计围绕两个核心问题：

1. **人类效率瓶颈**：传统 HITL 中，同一操作员既要远程遥操作、又要现场重置、还要监控多台机器人——任务切换导致认知过载和效率衰减。HELP 将工作拆分为两个专业化角色：
   - **Teleoperator**： stationary，通过 VR 界面远程操控，专注于高质量恢复数据采集（需要数周至数月的专业技能训练）
   - **Floor Operator**：现场监控 12 台机器人，用蓝牙键盘触发 takeover 信号，执行物理场景重置

2. **轨迹数据质量问题**：自主采集的 rollout 包含 progress、idle、failure、recovery 混合片段。直接训练整条轨迹会让策略学习可避免的失败；丢弃整条轨迹又浪费有价值的 recovery 数据。VLAC-CUT 在进程级别自动分割轨迹。

⚡ **Eureka Moment**：人类效率 ≠ 样本效率——优化每单位人类劳动的策略提升，比优化固定数据集上的样本利用率更重要。

## 2. 数学核心

### 2.1 并行推理（Eq. 1）

每个控制步，集中式 GPU 集群并行运行三个模型：

```
a_t^i = π_θ(s_t^i)     -- VLA 策略输出动作块
γ_t^i = φ(s_t^i)       -- Takeover 预测 (0/1)
d_t^i = ψ(s_t^i)       -- 任务终止预测 (0/1)
```

其中 $i \in \{1, \dots, 12\}$ 表示机器人索引，$s_t^i$ 为多模态观测（图像 + 本体感知）。

### 2.2 客户端状态机（Eq. 2）

```
S_client^i ← S_takeover  if u_t^i = takeover
           S_hitl       if S_client^i = S_takeover AND VR streaming active
           S_reset      if u_t^i = reset
           S_model      if u_t^i = step(a_t^i)
```

优先级：takeover > hitl > reset > model（自主执行）。

### 2.3 人类监督放大因子（Eq. 4）

这是 HELP 的核心量化指标——在匹配 HITL 恢复预算下，VLAC-CUT 带来的额外策略提升：

```
A_M = [M(π_HELP) - M(π_start)] / [M(π_HITL) - M(π_start)]
```

其中 M 可以是吞吐量（TP）或成功率（SR）。A_M > 1 表示 VLAC-CUT 从相同的 HITL 预算中获得了更大的策略提升。

> **Napkin Formula**（一行抓住本质）：
>
> 人类效率 = 策略提升 / 人类劳动
>
> HELP 通过两条路径最大化这个比值：系统级（角色分工 $\times$ 并发规模）+ 学习级（VLAC-CUT 轨迹分割放大每单位 HITL 数据的利用率）

> 符号与本文保持一致：$\pi_\theta$ 为 VLA 策略，$\varphi$ 为 takeover 预测器，$\psi$ 为终止预测器，$\gamma$ 为 takeover 信号，$d$ 为终止信号。

## 3. 带数字走一遍：玩具例子

考虑一个简化的 Refrigerator 任务后训练场景：

**基线状态**：$\pi_{0.5}$ 基础模型
- 吞吐量：10 tasks/hour
- 成功率：20%
- 平均执行时间：72.3s

**第一轮 HITL-only**：201 条 HITL 恢复轨迹
- 吞吐量：14（+4）
- 成功率：35%（+15pp）
- 但执行时间增至 89s（策略学会了恢复动作，但更慢了）

**第一轮 HELP**：201 条 HITL + 100 条 VLAC-CUT 分割片段
- 吞吐量：19（+9）
- 成功率：45%（+25pp）
- 执行时间：85s

**放大因子计算**：
```
A_TP = (19 - 10) / (14 - 10) = 9 / 4 = 2.25x
A_SR = (45% - 20%) / (35% - 20%) = 25 / 15 = 1.67x
```

**直觉**：VLAC-CUT 从自主 rollouts 中提取了 100 条高质量片段（progress-making + recovery），去除了 idle 和 failure-inducing 片段。这些片段让策略在相同 HITL 预算下学到了更直接的执行路径，而非依赖冗余的恢复动作。

**第二轮迭代**（仅 Refrigerator）：
- HITL(i=2)：吞吐量 33，成功率 60%
- HELP(i=2)：吞吐量 42，成功率 80%
- A_TP = (42-10)/(33-10) = 32/23 = 1.64x
- A_SR = (80%-20%)/(60%-20%) = 60/40 = 2.33x

第二轮增益更大，因为更强的策略产生了更多成功的自主 rollout，VLAC-CUT 从中提取了更高质量的数据。

| 数据配比 | 基础:HITL:curated $\approx$ 1:1:1 | 每轮迭代重新平衡 |

**部署约束**：
- 需要集中式 GPU 服务器运行 Ray 集群（至少能并行 12 路 VLA 推理 + VLAC-CUT + takeover/termination 模型）
- Floor Operator 需要物理在场执行场景重置——限制了远程部署可能性
- Teleoperator 需要 VR 设备（头显 + 手柄）和稳定的低延迟网络

| 匹配预算下超额回报 | 相同 HITL 轨迹数下更大提升 | Table 6 放大因子 |

### 6.2 不能做什么

| 局限 | 原因 |
|------|------|
| 泛化到非桌面操作 | 实验仅限 4 种桌面操作任务（冰箱、微孔板、试管、搅拌器） |
| 单台机器人场景 | 角色分工的价值在单机场景大幅降低 |
| 无 VR 基础设施部署 | Teleoperator 依赖 VR 遥操作界面 |
| 完全无人值守 | 仍需 2 名人类操作员在场 |

### 6.3 隐含假设 (Hidden Assumptions)

1. **12 台机器人并发是可扩展的**：论文只在单一实验室部署中验证了 12 台，未讨论扩展到 24/48 台时的通信/计算瓶颈
2. **Teleoperator 技能可迁移**：假设经过训练的遥操作技能可以跨任务迁移，但未量化迁移程度
3. **VLAC-CUT 的段级分割足够精细**：假设四分类（progress/idle/failure/recovery）能覆盖所有有用的轨迹质量维度，但实际可能存在更细粒度的质量差异
4. **Floor Operator 的失败模式识别能力**：假设现场操作员能凭经验准确判断何时触发 takeover，但未量化其判断准确率
5. **相机视角不变**：Refrigerator 任务成功率卡在 80%，作者归因于相机视角和机械结构限制——暗示系统对硬件配置敏感
