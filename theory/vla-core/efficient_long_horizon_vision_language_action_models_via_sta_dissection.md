💡 **X-Ray 开场**
VLA 模型有两个死穴：上下文窗口装不下多帧历史（每张图 256 个 token，10 帧就是 2560 个 token），以及每次推理都要重新算所有 token 导致延迟高。DySta 的核心发现是——机器人场景中大部分视觉信息是静态的（背景、静止物体），只有少量在动。把 token 拆成"静态"和"动态"两层，静态的只算一次然后缓存复用，动态的每帧都算。结果：上下文长度砍掉 94%，推理速度提升 2.2 倍，成功率还更高了。对 VLA 研究者意味着：效率提升不必靠牺牲信息量——靠结构先验就能双赢。

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？** 核心洞察是机器人场景的视觉信息具有强烈的时间冗余性——桌面背景不变、静止物体不变、甚至被移动过的物体外观也基本不变。传统 VLA 每帧都重新编码全部 256 个 token，其中大量是冗余计算。

**三级 token 拆分**（论文用两级静态 + 一级动态）：
- **L1 静态缓存 (133 tokens, 52%)**: 最持久的信息——全局场景布局、背景结构
- **L2 静态缓存 (107 tokens, 42%)**: 中等持久——物体级外观，可能因遮挡或交互偶尔变化
- **动态 token (16 tokens, 6%)**: 每帧必变——机器人末端位置、被抓取物体的位移

**Recache Gate**：不是简单地"永远缓存"或"永远重算"，而是用一个轻量级可学习门控网络预测"当前帧是否需要刷新缓存"。训练时用 Gumbel-softmax 实现端到端可微的二值决策；推理时概率超过阈值 $\delta$ 就刷新，否则复用 KV cache。

⚡ **Eureka Moment**：Transformer 架构中，即使两个帧的像素完全相同，经过 attention 后它们的 hidden representation 也会不同——所以基于像素相似度的启发式缓存（TTF-VLA, VLA-Cache）本质上是错误的。DySta 通过在 token 级别做动静解耦 + 可学习 gate，从根本上解决了这个问题。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L = L_Task + Σ_l α_l · L_InfoNCE^l + β · L_gate
```

**目标**：在标准 VLA 任务损失之上，加入两个正则项——让静态 token 跨时间稳定（对比学习），让 recache gate 学会何时刷新（二分类 + 时间先验）。

**公式拆解**：

```
[1] 动静解耦: Z_t = {Z_t^{s1}, Z_t^{s2}, ..., Z_t^d}
    其中 N = N_s1 + N_s2 + ... + N_d

[2] 多帧输入: a_t = π_LLM(Z^{s1}, Z^{s2}, d_{t-T}, ..., d_t, I)
    静态 token 只出现一次，动态 token 跨 T 帧拼接

[3] Recache Gate: g_l(Z_{t-Δ}, Z_t) ∈ [0,1]
    训练: Gumbel-softmax 可微二值决策
    推理: g_l > δ_l → 刷新, 否则复用 KV cache

[4] 对比学习 (静态 token 稳定性):
    L_InfoNCE^l = -log exp(sim(z_i^+, z_i^-)/τ) / Σ exp(sim/τ)
    同轨迹不同时刻 = 正例对, 不同轨迹 = 负例对

[5] Gate 正则化 (防止 gate 退化到"每次都刷新"):
    L_gate = -p_Δ · log(g) - (1-p_Δ) · log(1-g)
    其中 p_Δ = 1 - exp(-λ·Δ)
    Δ 小时 p_Δ 小 → gate 偏向复用; Δ 大时 p_Δ 大 → gate 偏向刷新

[6] 加速理论: FLOPs 减少因子 = (1 - r), r = 静态token比例
    上下文长度: NT → NT - rN(T-1)
```

**变量说明**：

| 符号 | 含义 | 论文中的值 |
|------|------|-----------|
| N | 每帧总 token 数 | 256 |
| N_s1, N_s2 | L1/L2 静态 token 数 | 133, 107 |
| N_d | 动态 token 数 | 16 |
| r | 静态 token 占比 | 94% (240/256) |
| T | 历史帧数 | 论文未明确给出具体值 |
| $\delta_l$ | recache 阈值 | 论文 Appendix D |
| $\lambda$ | gate 时间先验衰减 | 固定值，论文未给出 |
| $\alpha_l$, $\beta$ | 损失权重 | 论文 Appendix I.1 有敏感性分析 |

> 符号与原文保持一致。论文中 $\alpha_l$ 和 $\beta$ 的具体数值需查阅 Appendix I.1。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个桌面操作场景，机器人需要把玉米从 A 点移到 B 点，然后打开抽屉。

**第 1 帧 (t=0)**：
- 视觉编码: 256 tokens
- Token Router 拆分: L1=133, L2=107, D=16
- 全部计算: 256 tokens 过 VLM → LLM → action_0 = "移动到玉米上方"
- Recache gates: 首次运行，全部缓存

**第 2 帧 (t=1)**：
- 新帧编码: 256 tokens
- Recache gate 判断: $g_{L1} = 0.12 < \delta_{L1}$ (假设 $\delta=0.5$) → 复用 L1 cache ✓
- $g_{L2} = 0.08 < \delta_{L2}$ → 复用 L2 cache ✓
- 只需计算 16 个动态 token
- LLM 输入: [L1_cached(133), L2_cached(107), d_0(16), d_1(16), I] = 288 tokens
- 对比传统: $256\times2 + I = 512+$ tokens → **节省 44% 上下文**

**第 5 帧 (t=4)**：机器人已经抓起玉米，开始移动
- Recache gate 判断: $g_{L1} = 0.72 > \delta_{L1}$ → **刷新 L1** (背景变了)
- L1 刷新 → L2 强制刷新
- 256 tokens 全部重算
- 但之前的 4 帧中，假设 3 帧复用了 cache → 5 帧总计算量 ≈ $2\times256 + 3\times16 = 560$ tokens
- 传统方法: $5\times256 = 1280$ tokens → **节省 56% FLOPs**

**理论加速验证**：
```
r = 240/256 = 0.9375
理论 FLOPs 减少 = 1 - r = 6.25% (单帧)
但考虑 KV cache 复用 + 多帧场景:
实际加速 = 2.26x (SimplerEnv) / 2.21x (真实世界)
```

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值 | 含义 |
|----------|------|------|
| 单帧延迟 (SimplerEnv) | 601ms (DySta) vs 1360ms (CogACT) | 每步少等 759ms |
| 单帧延迟 (LIBERO) | 437ms vs 741ms | 少等 304ms |
| 单帧延迟 (真实世界) | 493ms vs 1089ms | 少等 596ms |
| Recache gate 开销 | $\approx1.27\%$ | 可忽略 |
| 静态 token 比例 | 94% (240/256) | 极高，动态 token 仅 16 个 |
| 动态 token 数 | 16 | 非常小——信息密度极高 |

**关键 trade-off**：
- **动态 token 越少 → 加速越大，但信息损失风险越高**。论文中 16 个动态 token 是否足够表达所有关键变化？Appendix I.2 有敏感性分析，但具体数值未在主文明确。
- **Recache 阈值 $\delta$ 是唯一的操作旋钮**：$\delta$ 高 → 少刷新 → 更快但可能 stale；$\delta$ 低 → 多刷新 → 更准但更慢。
- **部署约束**：需要修改 VLM backbone 的 token 路由逻辑和 KV cache 管理——不是即插即用的插件，需要框架级改造。
- **控制频率含义**：601ms 的推理延迟意味着 ~1.6Hz 的控制频率，对于桌面操作足够，但对于需要高频响应的任务（如接住掉落物体）仍不够。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么
- **多帧记忆任务**: 在 LIBERO-Memory 上比基线高 24.5%，在真实世界记忆依赖任务上高 23.3%
- **高效推理**: SimplerEnv 2.26x, LIBERO 1.70x, 真实世界 2.21x
- **成功率不降反升**: 在 SimplerEnv 上比 CogACT 高 4.9%，比最强基线高 3.9%
- **真实世界泛化**: 7 个真实任务中有 5 个成功率最高

### 不能做什么（局限性）
- **动态场景未验证**: 所有实验都在桌面操作场景（SimplerEnv / LIBERO / Cobot Magic），背景相对稳定。如果场景频繁变化（如移动机器人穿越不同房间），静态 token 的缓存命中率会急剧下降
- **双臂/人形机器人未测试**: 实验仅在单臂 Cobot Magic 上验证
- **极端遮挡场景**: 16 个动态 token 是否能充分表达复杂遮挡关系？论文未给出针对性实验
- **长 horizon 的具体上限**: 论文声称支持多帧，但没有给出 T 的最大有效值

### 6.1 隐含假设 (Hidden Assumptions)

1. **场景静态性假设**: 论文明确假设"agent 在相对稳定场景中操作"。这个假设在桌面操作中成立，但在更广泛的具身智能场景中可能不成立。
2. **Token 比例先验**: L1/L2/D 的比例 (133/107/16) 是预定义的超参数，不是学习得到的。这个分配是否最优？Appendix I.2 有敏感性分析，但搜索空间有限。
3. **对比学习的正负对定义**: 同轨迹 = 正例，不同轨迹 = 负例。但不同轨迹中可能有相同的静态背景——这些会被错误地当作负例推开，可能损害静态 token 的质量。
4. **Recache gate 的输入**: gate 需要访问当前帧和缓存参考帧的 token——这意味着即使不刷新，也需要编码当前帧来给 gate 做决策。这 256 个 token 的编码开销是否计入了加速分析？
5. **L1 刷新强制 L2 刷新**: 这个级联设计合理但缺乏消融验证——如果 L1 和 L2 独立决策会怎样？
