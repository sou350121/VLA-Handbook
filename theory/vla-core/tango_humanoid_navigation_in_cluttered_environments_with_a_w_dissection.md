## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

TANGO 采用**三层系统架构（Triple-System）**，每一层对应不同的控制频率和抽象层级：

| 组件 | System | 模型/方法 | 输入 | 输出 | 频率 | 职责 |
|------|--------|----------|------|------|------|------|
| System-2 | 感知 | Qwen2.5VL-7B (warm-started from InternVLA-N1) | 前后摄像头 RGB + 语言指令 + 本体感受 | 潜上下文 token z | 2 Hz | 视觉-语言理解，生成导航意图的潜表示 |
| System-1 | 决策 | MM-DiT (Flow Matching) | 潜 token z + 当前关节角 q_t | 29-DoF 关节动作块 (H=15 steps) | 2 Hz | 从感知意图到全身动作的映射 |
| System-0 | 执行 | SONIC Tracker | 动作块 A_t + 实时本体感受 | 高频关节力矩命令 | 200 Hz | 低层运动跟踪，确保物理可行性 |

**训练/推理差异**：训练时 System-2 和 System-1 端到端联合训练（单 epoch，LR=1e-5）；推理时 System-2 和 System-1 运行在云端服务器（RTX PRO 6000），System-0 运行在机载 Jetson Orin NX，通过 IP 网络通信（~20ms 延迟）。

### 1.2 关键机制 (Key Mechanism)

**为什么这样设计？**

1. **全身动作而非 2D 速度**：传统 VLN 输出 2D 速度/航向，由下层控制器执行。但类人机器人的身体几何随运动连续变化——手臂位置、躯干倾斜、步态调整都影响能否通过狭窄通道。TANGO 直接输出 29-DoF 关节角 + 基座 6D 旋转，让导航决策内建身体可行性。

2. **稳定化动作表示**：原始动作定义为 `a_i = {q_d,i, r_b,i}`（29 维关节角 + 6 维基座旋转）。TANGO 将其变换为 `a~_i = {q_d,i, r~_b,i, Δx_i, Δy_i, Δψ_i}`——基座偏航角相对块首帧参数化，并附加显式的平面位移和航向变化量。这降低了回归难度，让 MM-DiT 更容易学习。

3. **实时动作分块（RTC）**：训练时对已提交的随机前缀 d 个动作进行 inpainting，预测剩余 horizon。这弥合了离线训练（一次性输出整块）和在线推理（逐 step 流式输出）之间的差距。

4. **PET 数据管线**：Plan（A* 路径规划）→ Edit（SoftMimic 伪力编辑全身运动）→ Track（SONIC 验证物理可行性）。关键设计：用编辑后的参考运动而非跟踪后的轨迹作为训练监督，保留类人运动质量。

⚡ **Eureka Moment**：导航和全身控制不需要拆成两个模块——用一个 VLA 模型直接输出 29-DoF 关节动作，配合仿真生成的物理可行数据训练，可以同时学会语义导航和身体几何感知，且零样本迁移到真机。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
L = L_CE + 20 · L_FM
  where L_CE = cross-entropy(VideoQA)  // 保持语言理解
        L_FM = flow-matching(A_t, A_t_pred)  // 学习全身动作
```

**目标**：联合优化视觉语言理解（保持通用知识）和全身动作生成（学会导航穿越）。

**公式分解**：

- **L_CE**：交叉熵损失，用于 VideoQA 文本解码分支。输入为历史帧 + 语言指令，输出文本回答。权重 w_FM = 20，表明动作生成占主导。
- **L_FM**：Flow Matching 损失，训练 MM-DiT 从噪声到动作块的流。具体形式为预测速度场与真实速度场的 MSE。
- **动作块定义**：A_t = {a_1, ..., a_H}，其中 a_i = {q_d,i ∈ R^29, r_b,i ∈ R^6}，H=15。

**变量说明**：

| 符号 | 含义 | 维度 |
|------|------|------|
| ℓ | 自然语言导航指令 | 文本 |
| I_t^fr, I_t^dn | t 时刻前/下摄像头 RGB | H×W×3 |
| q_t | t 时刻本体感受（关节角） | R^29 |
| z | VLM 输出的潜上下文 token | R^d |
| A_t:t+H | 预测的 H 步动作块 | R^(H×35) |
| a~_i | 稳定化动作表示 | R^35 = 29 + 4 + 3 |

> 符号与本文保持一致：q_d 为期望关节角，r_b 为基座旋转，Δx/Δy/Δψ 为平面位移和航向变化。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：类人机器人需要穿过一条 0.8m 宽的狭窄走廊。

**Step 1 — 感知（System-2）**：
- 输入：前方摄像头看到走廊入口，下方摄像头看到地面，指令 ℓ = "穿过走廊到对面"
- BATS 采样：保留最近 5 帧（细粒度 GridPool）+ 历史 3 帧（粗粒度）
- 输出潜 token z，编码"狭窄通道 + 需要侧身"

**Step 2 — 动作预测（System-1）**：
- 当前关节角 q_t = [0, 0, 5, -5, 0, ...]（正常站立姿态，单位：度，简化为 5-DoF 示意）
- MM-DiT 生成 H=3 步动作块（简化）：
  ```
  a_1 = {q_d = [0, 15, 3, -3, 90], Δx=0.05, Δy=0.02, Δψ=0.1}  ← 开始侧身，偏航+90°
  a_2 = {q_d = [0, 20, 2, -2, 90], Δx=0.08, Δy=0.01, Δψ=0.0}  ← 侧身通过，手臂外展
  a_3 = {q_d = [0, 10, 4, -4, 0],  Δx=0.10, Δy=0.0,  Δψ=-0.1} ← 恢复正向，继续前进
  ```
- 关键：第 1 步的 Δψ=+90° 触发 heading adjustment 模块，系统自动插入侧身行走

**Step 3 — 执行（System-0）**：
- SONIC tracker 以 200Hz 跟踪 a_1→a_2→a_3 的参考轨迹
- 实际关节角可能因动力学略有偏差，但 tracker 保证物理可行性
- 最终效果：机器人侧身通过狭窄走廊，无碰撞

**损失计算示例**（训练时）：
```
假设 ground truth 动作块 A_gt = [a_gt_1, a_gt_2, a_gt_3]
预测动作块 A_pred = [a_pred_1, a_pred_2, a_pred_3]

L_FM = (1/3) · Σ_i ||a_pred_i - a_gt_i||^2
     = (1/3) · [(0.02^2 + 0.01^2 + ...) + ...]  // 每步 35 维 MSE
     ≈ 0.005（假设平均每维误差 0.02）

L_CE = 1.2（VideoQA 交叉熵，独立计算）

L_total = 1.2 + 20 × 0.005 = 1.3
```

## 4. 工程视角 (Engineering View)

| 维度 | 数值 | 含义 |
|------|------|------|
| VLA 推理频率 | 2 Hz（每 0.5s） | 云端 GPU 推理，受 Qwen2.5VL-7B 吞吐量限制 |
| Tracker 控制频率 | 200 Hz | Jetson Orin NX 本地闭环，确保低延迟响应 |
| 网络延迟 | ~20ms | 摄像头→服务器→机器人双向通信 |
| 动作执行 horizon | 15 steps @ 30Hz | 每块 0.5s，与 VLA 推理周期对齐 |
| 重采样 | 15→15 steps @ 50Hz | 动作块从 30Hz 重采样到 50Hz 再送 tracker |
| 训练成本 | 211 GPU-hours（RTX PRO 6000） | PET 管线 86h + 渲染 125h |
| 数据集规模 | 64,633 条轨迹 | 来自 578 个增强场景 |
| 推理硬件 | 1×RTX PRO 6000（云端）+ Jetson Orin NX（机载） | 云边分离架构 |

**工程含义**：
- **模块边界清晰**：System-2/1 在云端（计算密集，低频率），System-0 在机载（低延迟，高频率）。网络故障时 tracker 可短暂维持运动。
- **部署约束**：需要稳定的 IP 网络连接（~20ms 延迟），不适合高延迟场景（如远距离 5G）。
- **量化误差**：未提及模型量化，7B VLM 在 RTX PRO 6000 上应以 FP16/BF16 运行。若需部署到更小 GPU，量化可能影响导航精度。
- **内存 trade-off**：BATS + GridPool 管理长视频历史的 token 预算，近期帧保留细粒度，历史帧降采样。

## 6.1 隐含假设 (Hidden Assumptions)

1. **仿真到真实的动力学鸿沟可被 tracker 弥补**：PET 管线在 IsaacSim 中生成数据，但真实 G1 的动力学、摩擦、传感器噪声与仿真不同。零样本成功部分归功于 SONIC tracker 的鲁棒性，但这不是 VLA 本身的功劳。
2. **静态环境假设**：所有训练和评测场景都是静态障碍物。真实室内环境有人走动、门开关等动态变化，TANGO 未涉及。
3. **语言指令的粒度假设**：指令如"跨过这个障碍物"明确指定了穿越行为。实际用户指令可能模糊（"走过去"），模型是否能自动推断合适的穿越方式未验证。
4. **29-DoF 动作空间的平台通用性**：TANGO 的输出维度与 Unitree G1 的关节数绑定。迁移到不同 DoF 的机器人需要重新设计输出头和重新训练。
