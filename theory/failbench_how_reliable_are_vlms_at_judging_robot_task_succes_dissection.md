当前 VLA 和机器人学习管线广泛依赖 VLM 作为自动"裁判"——判断一次操作尝试是成功还是失败，然后用这个判断做 RL 奖励、数据过滤或策略评估。但问题是：这个裁判本身可靠吗？FailBench 用 14 个独立来源、2,197 条真实操作轨迹给出了答案：**最好的模型也只有约 1/4 的判断是错的，而且你花力气微调的专用检测器反而比直接用通用 VLM 更差。** 对 VLA 研究者而言，这意味着你管线中那个"当作 ground truth 用"的 VLM 裁判，可能正在系统性污染你的训练数据。

| 组件 | 输入 | 输出 | 说明 |

### 1.2 关键机制 (Key Mechanism)

**FailBench 的设计哲学：让变量真正"变"起来。**

现有基准的致命缺陷是"固定一切"——同一台机器人、同一场景、同一任务族、同一标注流程。FailBench 反其道而行：

| 变量 | 现有基准 | FailBench |
|------|----------|-----------|
| 数据来源 | 单一采集活动 | 14 个独立公开来源 |
| 失败来源 | 人为构造（扰动/重标注） | 75% 自然发生 |
| 任务类型 | 单一任务族 | 桌面抓取/厨房家务/接触密集装配/双臂操作 |
| 机器人平台 | 单一机械臂 | UR5, WidowX, Franka, SO-100/101, DROID |
| 视觉输入 | 单一视角 | 单目/双目/三目/腕部相机/首尾帧 |
| 标签来源 | 作者自标 | 原始数据提供者的原生标签 |

⚡ **Eureka Moment**：**失败检测的性能瓶颈不在"机器人知识"，而在"视觉证据类型"——当成败取决于可观察的物体运动时检测接近饱和，但当成败取决于是否建立了物理接触时，所有模型退化到接近随机猜测（<0.60）。**

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
balanced_acc = 0.5 × [ P(pred=1 | actual=1) + P(pred=0 | actual=0) ]
```

**目标**：在跨 14 个独立数据源的异构分布上，最大化 VLM 检测器的平衡准确率。

**为什么用平衡准确率而非普通准确率？** 各子集的成功/失败比例不同（有些接近 50/50，有些高度倾斜）。普通准确率会奖励模型"猜多数类"，平衡准确率将随机基线固定为 0.50，跨子集可比。

**变量说明**：

| 符号 | 含义 |
|------|------|
| P(pred=1 \| actual=1) | 真正率 (TPR) — 失败被正确识别的比例 |
| P(pred=0 \| actual=0) | 真负率 (TNR) — 成功被正确识别的比例 |
| Macro avg | 13 个子集平衡准确率的算术平均（等权） |
| Micro avg | 所有样本池化后计算单一平衡准确率（按样本量加权） |

> 符号与本文保持一致。论文未提出新的数学公式——这是一个实证评测工作，核心贡献在于评测协议设计和系统性发现。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设你在自己的 VLA 训练管线中使用 VLM 裁判，每天产生 1,000 条 rollout。

**场景 A：桌面抓取（物体运动可见）**
- 真实成功率：60%（600 成功，400 失败）
- VLM 裁判（Gemini 3 Flash 在此类任务上 ~0.85 balanced acc）：
  - TPR = 0.88 → 400 失败中识别出 352 条
  - TNR = 0.82 → 600 成功中识别出 492 条
  - 错误：48 条失败被误判为成功（污染训练数据）+ 108 条成功被误判为失败（丢弃可用数据）
  - **污染率 = 48/1000 = 4.8%**

**场景 B：接触密集装配（REASSEMBLE 类型）**
- 真实成功率：50%（500 成功，500 失败）
- VLM 裁判（最佳模型在 REASSEMBLE 上仅 ~0.60 balanced acc）：
  - TPR = 0.62 → 500 失败中识别出 310 条
  - TNR = 0.58 → 500 成功中识别出 290 条
  - 错误：190 条失败被误判 + 210 条成功被误判
  - **污染率 = 400/1000 = 40%** —— 近一半的裁判判断是错的

**场景 C：应用证据定位干预后（场景 B）**
- REASSEMBLE 上 +2.3 点 → balanced acc ≈ 0.623
  - TPR ≈ 0.64, TNR ≈ 0.606
  - 错误：180 条失败被误判 + 197 条成功被误判
  - **污染率 = 377/1000 = 37.7%** —— 改善有限，根本瓶颈未解决

**工程含义**：如果你的 VLA 训练管线在接触密集型任务上使用 VLM 裁判做奖励标注，**噪声水平可能高达 40%**，远超通常 RL 训练能容忍的范围。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/权衡 | 工程含义 |
|------|-----------|----------|
| 推理延迟 | 通用 VLM 每次调用 ~1-5s（API）；本地部署 ~200-800ms | 每条 rollout 一次调用，1000 条/day 需 17-83 分钟 |
| 证据定位管线开销 | 额外一次 VLM 调用（定位器） | 推理成本翻倍；但无需训练，可即插即用 |
| 集成收益 | 多数投票 (top-3) → 0.78 vs 0.77 | 边际改善 +1 点，但成本 ×3，性价比低 |
| 裁剪干预收益 | +2.3 点（macro），p=0.0015 | 223 样本修复 vs 160 样本破坏；净收益显著 |
| 模拟到真实差距 | 模拟平均高 1.3 点，但排名一致 (ρ=0.95) | 可在模拟上选型，但真实部署性能需下调 ~1.3 点预期 |
| 内存/显存 | 31B 模型需 ~62GB（FP16）；8B 模型需 ~16GB | 本地部署 31B 模型需 A100 80GB |

**部署建议**：
- 如果你的任务主要是**物体运动可见**的桌面操作 → 直接用 Gemini 3 Flash 或 Gemma-4-31B-it，无需微调
- 如果你的任务涉及**接触判断**（装配/插拔/插接）→ VLM 裁判不可靠，需结合力传感器或其他模态
- 证据定位管线值得集成：固定相机场景下裁剪到关键区域，零训练成本 +2.3 点

## 5. 数据与评测 (Data & Eval)

### 数据来源组成

| 来源类型 | 数量 | 代表数据集 | 失败产生方式 |
|----------|------|------------|-------------|
| 有机失败 (Organic) | 75% | UR5Fail, PHail, RoboArena, RH20T, REASSEMBLE | 自然发生 |
| 计划失败 (Planned) | ~13% | BotFails, RoboFAC, REFLECT | 人工驱动机械臂故意犯错 |
| 合成失败 (Synthetic) | ~8% | BDV2Fail, RoboReward | 录制后编辑轨迹 |
| 未记录 (Undocumented) | ~4% | RoboMeter | 标签来源不明 |

### 评测任务设置

- **输入格式**：每条样本 = (任务指令, 视觉输入 [视频/32帧/首尾帧], 二元标签)
- **检测器配置**：每个模型使用其官方 prompt 和推荐解码设置（不统一 prompt 以反映实际使用场景）
- **视频处理**：支持视频输入的模型直接喂视频；不支持的均匀采样 32 帧
- **标签质量**：随机抽查 25% 样本人工复核，发现错误/模糊标签则从同分布替换

### 评测指标

- **主要指标**：平衡准确率 (balanced accuracy) — 随机基线 0.50
- **聚合方式**：Macro（13 个子集等权）为主报告；Micro（全样本池化）为辅助
- **REFLECT 子集**：仅含失败样本，无平衡准确率；仅纳入 Micro 聚合

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

| 场景 | 性能 | 原因 |
|------|------|------|
| 桌面抓取/放置（物体运动可见） | 0.80-0.93 | 成败由物体最终位置决定，视觉信号强 |
| 模拟环境操作 | 0.75-0.86 | 视觉干净、背景简单、物体对比度高 |
| 厨房/家务操作 | 0.65-0.74 | 中等复杂度，部分依赖接触判断 |

### 不能做什么

| 场景 | 性能 | 原因 |
|------|------|------|
| 接触密集装配（REASSEMBLE） | <0.60 | 成败取决于"是否建立了接触"，视觉信号极弱（关键区域仅几十像素） |
| 插拔/线缆夹持/工具操作 | 0.52-0.65 | 需要判断微小位移或接触力，纯视觉难以分辨 |
| 双臂协同操作 | 0.68-0.74 | 多臂遮挡、复杂交互，定位困难 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **二元标签足够**：论文将每个尝试简化为成功/失败二元标签。但实际 VLA 管线中，失败有多种类型（规划失败 vs 执行失败 vs 部分成功），二元标签丢失了这些结构化信息。
2. **视觉输入充分**：评测假设"给定了足够的视觉信息来判断成败"。但许多真实场景中，成败取决于力/触觉信号而非纯视觉——论文本身也承认"Non-visual streams are not used"。
3. **单帧/首尾帧足够**：部分来源只提供首尾帧（无中间视频），评测假设这足以判断成败。但对于需要推理中间过程的任务（如"是否在中途掉落过"），首尾帧信息不足。
4. **VLM 裁判 = Ground Truth**：论文批评了当前管线"将 VLM 判断当作 ground truth 使用"的做法，但评测本身也假设标签是正确的一一如果原始数据源的标签本身有噪声，FailBench 的分数会被高估或低估。
5. **诊断泛化性**：错误分析和推理轨迹分析仅基于 Gemma-4-31B-it（最强可 inspect 的模型），其他模型的错误机制是推测性的。
