### 1.2 关键机制 (Key Mechanism)

**双路令牌设计**：不同于 StereoPolicy 将两路视图融合后替换原始主视图令牌，EATR-Stereo 保留主视图令牌 M 不变，单独构造一条辅助令牌流 C（CVAT），两者在最后的动作头才汇合。

**Cross-View Attention**：CVAT 构造器使用主视图令牌作为 Query、辅助视图令牌作为 Key/Value，做多头交叉注意力，产出与主视图 token 索引对齐的辅助令牌。

**具身分段路由**：将 37 维本体状态按身体部位分为 5 组（腿、臂、头、腰、机器人姿态），每组独立编码后做 attention-weighted 池化，得到全局本体条件 h^s。对每个 CVAT token，用主令牌、CVAT 令牌、两者差值、两者乘积、本体条件拼接后过一个轻量 MLP，输出一个 0-1 的门控标量 r_i，逐 token 缩放 CVAT 令牌。

⚡ **Eureka Moment**：不修改预训练 VLM 的视觉表示，而是用一条"旁路"辅助令牌流 + 身体状态门控，让 VLA 自己决定什么时候需要看第二路相机——便宜、可插拔、不破坏预训练知识。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
r_{t,i} = σ( f_r( [LN(M_i); LN(C_i); |LN(M_i)-LN(C_i)|; LN(M_i)⊙LN(C_i); h^s] ) )
C̃ = r ⊙ C,    E_VLA = [L; M; C̃]
```

**目标**：让每个 CVAT token 根据当前机器人身体状态和主-辅视图差异，自适应地决定"这个辅助信息该用多少"。

**变量说明**：

| 符号 | 含义 | 维度 |
|------|------|------|
| M_t | 主视图令牌序列 | N×d |
| A_t | 辅助视图令牌序列 | N×d |
| C_t | CVAT 令牌流（交叉注意力输出） | N×d |
| z_{t,g} | 第 g 个身体分段的编码 | d_s |
| h^s_t | 聚合后的本体条件 | d_f |
| r_{t,i} | 第 i 个 token 的门控标量 | 标量 ∈ (0,1) |
| C̃_t | 路由后的辅助令牌 | N×d |

**直觉**：门控 r_i 本质上是一个"这个辅助 token 对当前动作有多重要"的评分。当机器人手臂遮挡主视图时，对应区域的 r_i 应该升高（需要更多辅助视图信息）；当主视图已经足够清晰时，r_i 应该降低（保持预训练表示的稳定性）。

**CVAT 构造公式**（交叉注意力）：

```
Q_h = LN(M_t) W_h^Q,    K_h = LN(A_t) W_h^K,    V_h = LN(A_t) W_h^V
O_h = softmax(Q_h K_h^T / sqrt(d_h)) V_h
C_t^{(0)} = Concat_h(O_h) W^O
C_t = C_t^{(0)} + MLP(LN(C_t^{(0)}))
```

**训练损失**（流匹配）：

```
L_FM = E_{t,τ} [ || v_θ(Y_t^τ, τ | E_VLA, S_t) - u_τ ||^2 ]
```

> 符号与本文保持一致：Y_t^τ 为目标动作块在流时间 τ 的插值状态，u_τ 为目标速度场，v_θ 为预测速度场。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：

- 主视图令牌维度 d=4，序列长度 N=2（简化为 2 个 token）
- 辅助视图在 token 1 处有额外信息（比如主视图被手遮挡）

**Step 1: CVAT 构造**

```
M = [[0.8, 0.1, -0.2, 0.5],     ← 主视图 token 0（场景背景）
     [0.3, 0.6, 0.1, -0.4]]     ← 主视图 token 1（被遮挡区域）

A = [[0.7, 0.2, -0.1, 0.4],     ← 辅助视图 token 0（同场景）
     [0.9, 0.8, 0.5, -0.1]]     ← 辅助视图 token 1（遮挡物后方可见）

经过交叉注意力后（简化）：
C = [[0.75, 0.15, -0.15, 0.45],   ← CVAT token 0（与 M 相似）
     [0.85, 0.75, 0.4, -0.15]]    ← CVAT token 1（与 M 差异大！）
```

**Step 2: 本体条件**

```
假设当前机器人手臂前伸（arm segment 值高），头向下看。
h^s = [0.8, 0.3, 0.6, 0.2, 0.4]  （5 段聚合后）
```

**Step 3: Token Router 逐 token 计算门控**

Token 0（背景区域，M≈C）：
```
q_0 = [LN(M_0); LN(C_0); |M_0-C_0|≈小; M_0⊙C_0≈大; h^s]
→ r_0 = σ(f_r(q_0)) ≈ 0.2  ← 辅助信息用处不大，门控关闭
→ C̃_0 = 0.2 × C_0 ≈ 小值
```

Token 1（遮挡区域，M≠C）：
```
q_1 = [LN(M_1); LN(C_1); |M_1-C_1|≈大; M_1⊙C_1≈小; h^s(arm=高)]
→ r_1 = σ(f_r(q_1)) ≈ 0.85  ← 辅助信息关键，门控打开
→ C̃_1 = 0.85 × C_1 ≈ 保留大部分辅助信息
```

**Step 4: 拼接送入动作头**

```
E_VLA = [L_t; M; C̃] = [语言; 主视图2token; 路由后辅助2token]
→ 动作头基于此预测 30 步连续动作
```

**关键观察**：Token 0 的门控 0.2 意味着背景区域几乎不需要辅助视图；Token 1 的门控 0.85 意味着遮挡区域高度依赖辅助视图。这就是"具身感知"——门控不仅看视觉差异，还看本体状态（手臂位置高 → 更可能遮挡 → 更需要辅助视图）。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/设计 | 工程含义 |
|------|-----------|----------|
| 推理频率 | 10 Hz（RTX 4090） | 每 100ms 预测 30 步动作，步长 3.3ms/步 |
| 动作块大小 | H=30 步 | 异步预测 + B-Spline 拼接，平滑切换 |
| VLM 冻结 | Cosmos VLM 全冻结 | 零推理开销增加，仅路由+动作头可训练 |
| 本体状态维度 | 37-D（33 关节 + 4D 四元数） | K=6 帧历史 → 222 维输入到分段编码器 |
| 图像分辨率 | 240×320 | 较低分辨率，适合头载相机带宽限制 |
| 训练资源 | 16×H20 GPU, batch=512, 60K steps | 大规模训练，但推理仅需单卡 4090 |
| 部署延迟 | 异步缓冲 + B-Spline | 新旧动作块间用三次 B-Spline 平滑过渡，避免突变 |

**部署管线**（论文 §III-D）：
1. 外部 VLM 评估子任务完成（慢时间尺度）
2. 检测到完成 → 切换语言指令
3. 策略异步预测新动作块 → 放入执行缓冲
4. B-Spline 拼接：保留已提交前缀 + 局部窗口平滑 + 未修改后缀
5. 每维动作独立拟合 spline，8 个采样点 + 8 步混合

**关键 trade-off**：
- 保留主视图令牌冻结 → 不增加 VLM 推理成本，但可能限制立体几何的深度融合
- 轻量路由 MLP → 参数量小、推理快，但门控质量依赖特征设计（差值+乘积拼接）
- 低分辨率 240×320 → 带宽友好，但可能丢失远距离小目标细节

### 6.1 隐含假设 (Hidden Assumptions)

1. **立体相机同步精度足够**：论文假设左右相机时间同步，但未给出同步误差指标。实际部署中，异步可能导致 CVAT 构造时对齐偏差。
2. **主/辅视图角色固定**：训练和部署使用固定的左=主、右=辅分配。如果机器人转头 180°，原来的辅助视图可能变成更优的主视图，但系统无法动态切换。
3. **本体状态低延迟可用**：路由依赖 K=6 帧本体历史（600ms @ 10Hz）。如果关节编码器延迟高或丢包，路由质量可能下降。
4. **演示数据覆盖关键场景**：1000 条演示是否覆盖了足够的遮挡/光照/背景变化？论文未做数据多样性分析。
5. **外部 VLM 子任务检测可靠**：慢时间尺度的指令切换依赖外部 VLM 的二值完成信号。如果检测延迟或误判，会影响整体任务流程。

**面试 Tip**：当被问到"为什么不用 StereoPolicy 的融合方案"时，回答核心是——StereoPolicy 替换了预训练的主视图令牌结构，可能破坏 VLM 的语义表示；EATR-Stereo 通过旁路 CVAT + 门控路由，在不触碰预训练表示的前提下注入立体信息，这是一种更安全的增强策略。
