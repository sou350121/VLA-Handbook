### 1.2 关键机制 (Key Mechanism)

**两阶段解耦设计哲学**：动力学建模需要低时间分辨率下的物理交互推理（接触、滑动、遮挡），不需要高分辨率纹理；而高清帧合成需要高层语义和丰富纹理，但不需要反复迭代动力学。传统方法用一个单体视频生成器同时做两件事，导致计算浪费。

**Flow Matching 级联**：传统级联扩散把低分辨率动力学当作 conditioning 输入，从高斯噪声重新开始 denoising——冗余。DVG-WM 用 Flow Matching 直接建立 LR 潜变量 → HR 潜变量的映射，学习一个向量场 v_θ，沿直线路径从 z_lr 推进到 z_hr。

**潜空间退化（Latent Degradation）**：训练 refinement 阶段时，不用像素级降采样（会造成 LR-HR 强相关，模型走捷径做超分），而是在潜空间对 z_lr 加扰动，迫使模型重建接触细节而非简单上采样像素。

⚡ **Eureka Moment**：动力学和视觉合成不应该共享同一个计算图——把它们拆开，各自在最优分辨率下运行，再用 Flow Matching 高效桥接，就能同时获得速度和精度。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
z_{k+1} = z_k + Δτ · v_θ(z_k, τ_k | z_lr, x_0, c),  其中 v_θ → z_hr - z~lr
```

**目标**：用最少 NFEs（仅 4 步）将低分辨率动力学潜变量 z_lr 映射到高分辨率视频潜变量 z_hr，而非从头 denoise。

**核心方程**：

Flow Matching 学习目标向量场，使其预测从粗到细的位移：
```
u*(z_τ, τ) = z_hr - z~lr          (真实速度/位移方向)
L_FM = E[||v_θ(z_τ, τ | z_lr, x_0, c) - u*(z_τ, τ)||²₂]   (训练损失)
```

插值路径：
```
z_τ = (1 - τ) · z~lr + τ · z_hr,    τ ~ U(0,1)
```

推理过程（确定性 ODE）：
```
z⁰ = z~lr
z^{k+1} = z^k + Δτ · v_θ(z^k, τ_k | z_lr, x_0, c),   k = 0,...,K-1
z_hr = z^K    (K=4)
```

> 符号说明：
> - x₀: 初始观测帧 (720p)
> - x₀ᵈ: 降采样初始帧 (256×384)
> - c: 语言指令 conditioning
> - z_lr: Preview 输出的低分辨率潜变量 (h×w×t, h=H/8, w=W/8)
> - z~lr: z_lr 线性上采样到 HR 尺寸
> - z_hr: 目标高分辨率潜变量
> - v_θ: 神经向量场 (CogVideoX-2B backbone)
> - τ: 插值步, τ ∈ [0,1]
> - NFE: Number of Function Evaluations (去噪/推进步数)

**直觉**：Flow Matching 学的是一个"从粗到细的箭头"——给定 LR 潜变量，它知道该往哪个方向走、走多远才能到达 HR 潜变量。因为起点（z_lr 上采样）已经包含了正确的动力学结构，所以只需要 4 步就能到达终点，而不是像传统扩散那样从随机噪声开始走 50 步。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设我们有一个 49 帧的机械臂开抽屉任务，初始帧 x₀ 分辨率 480×720。

**Step 1: VAE 压缩**
- 原始视频 x₄₉ ∈ ℝ^(480×720×49)
- 3D VAE 编码 → z ∈ ℝ^(60×90×13) （h=480/8=60, w=720/8=90, t=(49-1)/4+1=13）

**Step 2: Preview 阶段（LR）**
- 降采样 x₀ᵈ: 256×384 → 对应潜空间约 32×48
- CogVideoX-5B + LoRA 运行 50 步 denoising
- 输出 z_lr ∈ ℝ^(32×48×13)
- 耗时：约 2.1 秒（单 A100）

**Step 3: 线性上采样**
- z~lr = upsample(z_lr) → ℝ^(60×90×13) （与 HR 尺寸对齐）
- 此时 z~lr 已有正确的动力学结构（机械臂接触抽屉、拉开），但纹理模糊

**Step 4: Refinement 阶段（FM, 仅 4 步）**
- τ₀=0.0: z⁰ = z~lr （起点）
- τ₁=0.25: z¹ = z⁰ + 0.25 · v_θ(z⁰, 0.0 | ...) → 机械臂纹理开始清晰
- τ₂=0.50: z² = z¹ + 0.25 · v_θ(z¹, 0.25 | ...) → 抽屉表面纹理恢复
- τ₃=0.75: z³ = z² + 0.25 · v_θ(z², 0.50 | ...) → 接触区域细节（夹爪-抽屉接触面）重建
- τ₄=1.00: z⁴ = z³ + 0.25 · v_θ(z³, 0.75 | ...) = z_hr → 完整高清潜变量
- 耗时：约 0.3 秒

**Step 5: 解码**
- x_hr = VAE_Decoder(z_hr) → 480×720×49 高清视频

**总耗时对比**：
- DVG-WM: 2.1 + 0.3 = 2.4 秒
- LVP (单体 50 NFE @ HR): ~9.5 秒
- 加速比: 3.97×

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/约束 | 含义 |
|----------|-----------|------|
| Preview 推理 | 50 NFE @ 256×384 | 低分辨率下 50 步仍可行，每步计算量约为 HR 的 1/4 |
| Refinement 推理 | 4 NFE @ 480×720 | Flow Matching 是关键——仅 4 步完成 HR 合成 |
| 总推理延迟 | ~2.4 秒/49帧 | 相比 LVP 的 9.5 秒，适合迭代规划（可多次查询） |
| 训练成本 | Preview: 1×A100, 10K iter; Refinement: 8×A100, 24h | 两阶段独立训练，可并行优化 |
| 模型大小 | Preview: 5B (LoRA 128); Refinement: 2B | 总参数量 ~7B，LoRA 仅增加 ~0.6B |
| 显存占用 | 推理时 ~20-30GB（单卡可跑） | 两阶段串行，无需同时加载全部参数 |
| 量化友好度 | 中高 — Flow Matching 是确定性 ODE，无扩散随机性 | 适合 INT8 量化部署 |

**工程含义**：解耦设计的核心工程价值在于**非对称计算分配**——把大部分计算（50 NFE）放在低分辨率空间，把少量计算（4 NFE）放在高分辨率空间。这直接对应到控制频率：如果迭代规划需要每 5 秒查询一次世界模型，DVG-WM 的 2.4 秒延迟在预算内，而 LVP 的 9.5 秒会导致控制回路失步。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- 语言指令条件的未来视频预测（49 帧, 720p）
- 保持接触丰富区域的细节（夹爪-物体接触面不模糊）
- 作为迭代规划的世界模型（2.4 秒/次查询，支持多次 rollout）
- 输出可执行动作（通过 vision-only Diffusion Policy）

**不能做什么**：
- 不支持 action-conditioned 预测（本文 focus goal/language-conditioned）
- 仅在单臂桌面操作验证，未测试移动机器人/双臂/人形
- 依赖预训练 CogVideoX 基座——如果基座不支持的场景，泛化能力有限
- 49 帧 horizon 限制了长程任务规划（~5-10 秒操作）

### 6.1 隐含假设 (Hidden Assumptions)

1. **预训练视频生成模型的知识可迁移**：假设 CogVideoX 在 in-the-wild 视频上学到的视觉合成能力，通过 LoRA 微调后能适配机器人场景。但如果训练数据分布差异过大（如光照、视角、物体类别），迁移效果存疑。

2. **语言指令足够指导规划**：本文用语言作为 goal condition，假设自然语言能充分表达操作目标。但对于需要精细空间推理的任务（如"把红色积木放在蓝色积木左侧 2cm 处"），语言可能不够精确。

3. **两阶段独立性假设**：Preview 和 Refinement 分开训练，假设 Preview 输出的动力学结构足以初始化 Refinement。但如果 Preview 产生严重错误（如机械臂穿过物体），Refinement 无法纠正——错误会传播。

4. **单视角假设**：所有实验基于单摄像头，未评估多视角融合场景。实际机器人系统常有多个摄像头，信息融合策略未讨论。
