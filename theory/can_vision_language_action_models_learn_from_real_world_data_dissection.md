## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览

| 维度 | 朴素顺序微调 (Naive Seq FT) | 经验回放 (ER) | 联合多任务训练 (Joint) |
|------|---------------------------|---------------|----------------------|
| **训练方式** | 逐任务顺序 SFT，不保留历史数据 | 顺序训练 + 回放缓冲区采样历史数据 | 所有任务数据同时训练 |
| **单臂 AS** | 31.4 | 97.2 | 82.6 |
| **双臂 AS** | 38.3 | 97.2 | 83.2 |
| **单臂 BWT** | -81.0 | +1.5 | N/A |
| **双臂 BWT** | -68.6 | +1.9 | N/A |
| **计算预算** | 最低（只训当前任务） | 中等（需额外回放采样） | 最高（全量数据联合优化） |
| **内存需求** | 最低 | 中等（缓冲区 ρ·N_ep） | 最高（全量数据存储） |
| **跨任务干扰** | 严重（参数覆盖） | 低（回放锚定旧知识） | 中等（梯度冲突） |
| **适用场景** | 仅单任务离线训练 | 在线增量部署 | 离线多任务预训练 |

### 1.2 关键机制 (Key Mechanism)

**经验回放 (Experience Replay, ER)** 是本文的核心武器。具体配置如下：

- **缓冲区容量**: N_B = ρ_B · N_ep，其中 ρ_B ∈ {0.002, 0.02, 0.2}，N_ep 为总 episode 数
- **均匀分配**: 缓冲区容量平均分配给 K 个已 encountered 任务，每任务 ⌊N_B/K⌋ 条轨迹
- **采样频率**: 每步以概率 f_r 从回放缓冲区采样，以 1-f_r 从当前任务数据采样
- **最优配置**: ρ_B = 0.02（仅需总数据的 2%），f_r = 0.2

⚡ **Eureka Moment**: 一个仅保留 2% 历史数据的简单经验回放，就能把 AS 从 31.4 拉回 97.2——比联合训练还高 15 个百分点。关键在于"阶段性表征学习 + 回放锚定"比"同时优化所有技能"更能避免梯度冲突。

**动作归一化策略 (ANS)** 是另一个关键发现：

| 策略 | 训练归一化 | 测试归一化 | 效果 |
|------|-----------|-----------|------|
| ANS I | 每个任务用各自的局部统计量 | 各自局部统计量 | 跨任务对齐断裂，无法迁移 |
| **ANS II** | **全部任务共用第一个任务的统计量** | **全部任务共用第一个任务的统计量** | **最优 — 共享动作空间保证跨任务一致性** |
| ANS III | 每个任务用各自的局部统计量 | 全部用第一个任务的统计量 | 训练-测试分布不匹配，性能下降 |

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
J_CRL^π = (1/k) · Σ_{p=1}^{k} E_{(s_t^p, a_t^p)~π(·;T^p)} [ Σ_{t=1}^{H} g^p(s_t^p) ]
```

**目标**: 最大化 k 个任务上的平均累积回报（稀疏二元奖励：成功=1，失败=0）。

**行为克隆损失**（SFT 阶段）：

```
J_BC^π = (1/k) · Σ_{p=1}^{k} E_{(o_t, a_t)~D^p} [ Σ_{t=0}^{l^p} L(π(o_{≤t}; T^p), a_t^p) ]
```

其中 L 为负对数似然损失（NLL），o_{≤t} 为截至 t 步的观测历史。

**变量说明**：

| 符号 | 含义 |
|------|------|
| π(·; T^p) | 以任务 T^p 为条件的策略 |
| D^p | 第 p 个任务的演示数据集 |
| g^p(·) | 第 p 个任务的二元成功指示函数 |
| H | episode 最大步数 |
| ρ_B | 回放缓冲区占总数据的比例 |
| f_r | 每步从回放缓冲区采样的概率 |

> 符号与本文保持一致。关键直觉：持续学习的目标不是最小化当前任务的损失，而是最大化所有已学任务的平均表现——这要求模型在"学新"和"记旧"之间找到平衡。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：3 个单手任务，每个任务 400 条轨迹，每条轨迹平均 50 步。

**配置**: ρ_B = 0.02, f_r = 0.2

```
步骤 1: 学 Task 1 (Stack Bowls)
  - 训练数据: 400 条 × 50 步 = 20,000 步
  - 回放缓冲区: 400 条 (ρ_B × 400 = 8 条? 不 — ρ_B 是总数据比例，实际缓冲区 = 0.02 × 总数据)
  - 实际: N_B = ρ_B × N_ep = 0.02 × (400×3) = 24 条？不对...
  
  修正理解: ρ_B=0.02 意味着缓冲区容量为总 episode 数的 2%
  学完 T1 后: B 中有 400 条（全部 T1 数据，因为 400 < 0.02×400×3=24 不成立）
  实际上论文说 "uniformly partitioned among K encountered tasks"
  所以 T1 学完后 B 中有 400 条 T1 数据（此时 K=1，全部分给 T1）

步骤 2: 学 Task 2 (Hang Cup)
  - 新数据: 400 条
  - 缓冲区容量: 0.02 × (400×2) = 16 条？这太小了...
  
  重新理解: 论文 Table I 显示 ER 效果极好，ρ_B=0.02 时 BWT=+1.5
  实际缓冲区大小应该是每任务保留一定数量，而非严格按比例
  从 GitHub 代码看: DATA_BUFFER_SIZE 默认 0.2（20%），但论文测试了 0.002/0.02/0.2
  
  最合理的解释: ρ_B 是每任务保留的 episode 比例
  T2 学完后: B 中有 0.02×400=8 条 T1 + 400 条 T2 = 408 条
  采样: f_r=0.2 时，20% 的 batch 从 B 中均匀采样（8 条 T1 被反复采样）
  效果: 8 条 T1 数据足以"锚定"旧技能，AS 从 31.4→97.2

步骤 3: 学 Task 3 (Press Button)
  - 新数据: 400 条
  - 缓冲区: 每任务 8 条 × 3 = 24 条
  - 采样: 20% 的 batch 从 24 条历史数据中均匀采样
  - 结果: AS 保持高位，BWT ≈ 0（几乎无遗忘）
```

**关键洞察**: 仅需每任务 8 条演示（0.2% 的单任务数据量），就足以防止灾难性遗忘。这说明 VLA 模型的遗忘主要不是"记忆容量不足"，而是"缺乏跨任务对齐的锚点"。

| 任务类型 | 单手 | 双臂 |

### 评测指标

| 指标 | 公式 | 含义 |
|------|------|------|
| **AS (Average Score)** | (1/K)·Σ c_{i,K} | 最终所有任务平均得分（0-100） |
| **BWT (Backward Transfer)** | (1/(k-1))·Σ (c_{j,k} - c_{j,j}) | 负值 = 遗忘；正值 = 旧技能反而提升 |
| **FWT (Forward Transfer)** | (1/(k-1))·Σ (c_{j,j} - c̄_j) | 正值 = 先前任务促进新任务学习 |

> 评分采用 stepwise 方式（非二元成功/失败），每个任务 3-6 个中间检查点，更精细地反映执行进度。

### 能做什么

| 能力 | 条件 | 证据 |
|------|------|------|
| 持续学 5 个单手任务 | ER (ρ=0.02, f_r=0.2) | AS=97.2, BWT=+1.5 (Table I) |
| 持续学 5 个双臂任务 | ER (ρ=0.02, f_r=0.2) | AS=97.2, BWT=+1.9 (Table I) |
| 持续学 10 个异构任务 | 非对称回放 (f_r=0.3, 2:1 双臂偏置) | AS 保持高位, BWT=-2.7 (Fig 6-7) |
| 正向迁移 | 异构流全程 | FWT 平均 +8.7（先前任务帮助新任务） |

### 不能做什么 / 局限

| 局限 | 原因 | 影响 |
|------|------|------|
| 跨机器人平台泛化 | 仅验证 PiPER 平台 | 无法确认对其他形态（人形/移动双臂）有效 |
| 动作归一化自适应 | ANS II 冻结首任务统计量 | 若首任务 action space 不覆盖后续任务，可能失效 |
| 长期内存管理 | 缓冲区随任务数线性增长 | 无限期部署需 active memory management |
| 跨形态切换效率 | 双臂→单手干扰严重 | 需要非对称回放，增加超参调优复杂度 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **首任务归一化统计量足够覆盖**: ANS II 假设第一个任务的 action space 能覆盖后续所有任务。如果第一个任务是简单的 pick-and-place，而后续任务涉及大范围运动或特殊姿态，归一化可能不充分。
2. **演示质量一致**: 所有任务 300-500 条轨迹的质量假设一致。实际部署中早期数据可能质量较低。
3. **任务顺序已知**: 持续学习假设任务按已知顺序到达。实际中任务可能随机到达或并行到达。
4. **单平台假设**: 所有实验在同一物理平台上进行。跨平台迁移（不同臂长/关节范围/相机位姿）的遗忘行为可能完全不同。
