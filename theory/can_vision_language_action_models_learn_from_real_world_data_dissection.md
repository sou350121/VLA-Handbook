### 1.2 关键机制 (Key Mechanism)

论文系统考察了三个核心因素：

1. **经验回放（ER）配置**：缓冲区容量（ρ_B）和回放频率（f_r）共同决定稳定性-可塑性权衡
   - ρ_B = 0.02（保留 2% 历史数据）已足够有效
   - f_r = 0.2 是最优回放频率，兼顾旧技能保持和新任务适应
   - f_r = 0.5 过度正则化，损害新任务学习能力

2. **动作归一化策略（ANS）**：这是本文最关键的工程发现
   - ANS I（每任务独立归一化）：破坏跨任务对齐，即使 ER 也无效
   - **ANS II（冻结首任务统计量）**：最佳策略，整个任务流使用同一套归一化参数
   - ANS III（训练时各自归一化、测试时用首任务）：训练阶段已产生错位

3. **异构任务流的非对称回放**：单臂→双臂切换时，统一 f_r = 0.2 对双臂任务不够，需要提高双臂任务的回放频率

⚡ **Eureka Moment**：VLA 在真实世界持续学习中的稳定性不依赖复杂算法，而依赖两个工程细节——**适度的经验回放 + 一致的动作归一化空间**。仿真中观察到的"天然抗遗忘"可能是预训练数据重叠和归一化统计量泄露造成的假象。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
J_BC^π = (1/k) · Σ_{p=1}^{k} E_{(o_t, a_t)~D^p} [ Σ_t L(π(o_{≤t}; T^p), a_t^p) ]
```

**目标**：在持续学习阶段 k，最小化所有已 encountered 任务的平均行为克隆损失。

**关键约束**：{D^p : p < k}（历史任务数据）在学第 k 个任务时不可完全获取——只能从有限容量缓冲区 B 中近似采样。

**变量说明**：

| 符号 | 含义 |
|------|------|
| π(o_{≤t}; T^p) | 以观测历史 o_{≤t} 和任务指令 T^p 为条件的策略 |
| L(·) | 行为克隆损失（负对数似然 / MSE） |
| D^p | 第 p 个任务的专家演示轨迹集合 |
| B | 容量受限的经验回放缓冲区，|B| = ρ_B · N_ep |
| f_r | 每步从 B 采样的概率 |

**直觉**：这个目标函数本质上是一个"加权平均的行为克隆"——理想情况下需要对所有历史数据联合优化，但受限于存储，只能用回放缓冲区近似。ER 的有效性取决于两个因素：(1) 缓冲区是否足够代表历史分布；(2) 动作空间是否在所有任务间保持一致（归一化一致性）。

> 符号与本文保持一致：o_t 为观测（4 相机 RGB），a_t 为 7 维或 14 维动作（单臂/双臂），T^p 为任务条件。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化场景：3 个顺序任务（T1, T2, T3），每个任务 100 条轨迹，每条 50 步。

**步骤 1：学完 T1**
- 模型在 D^1 上 FT，在 T1 上达到 score = 90
- 缓冲区 B：分配 ⌊N_B/1⌋ = 2 条 T1 轨迹（假设 ρ_B = 0.02, N_ep = 100）

**步骤 2：学 T2（朴素 FT，无回放）**
- 仅在 D^2 上 FT
- 模型权重大幅偏移以拟合 T2
- T1 的 score 从 90 跌至 15（遗忘率 83%）
- T2 的 score = 85
- AS = (15 + 85) / 2 = 50

**步骤 2'：学 T2（有 ER，ρ_B = 0.02, f_r = 0.2）**
- 每步 20% 概率从 B 采样 T1 数据 + 80% 概率采样 D^2
- B 中有 2 条 T1 轨迹（100 步），与 D^2（5000 步）混合
- T1 score 保持 88（仅降 2 分），T2 score = 86
- AS = (88 + 86) / 2 = 87
- BWT = (88 - 90) / 1 = -2（远优于朴素 FT 的 -75）

**步骤 3：学 T3**
- 缓冲区均匀分配：⌊N_B/3⌋ ≈ 0.67 → 每任务 0~1 条轨迹
- 实际论文中 ρ_B = 0.2 时缓冲区更大，每任务约 100 条轨迹
- 最终 AS ≈ 97，BWT ≈ +1.5（甚至略有正向迁移）

**关键洞察**：只需要极少量的历史数据回放（2%）就能将遗忘从 83% 降到接近 0。这是因为 VLA 预训练模型已有强大的表征基础，FT 阶段主要是"微调"而非"从头学习"，少量回放即可锚定旧知识的参数区域。

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/配置 | 含义 |
|----------|----------|------|
| 基础模型 | π0.5 (Physical Intelligence) | 基于 openpi 框架，Gemma 视觉语言 backbone + 连续流匹配动作头 |
| GPU 需求 | 8×A100/H100 | 论文训练配置，基于 openpi 的分布式训练 |
| 数据格式 | LeRobot v2.1 | HuggingFace 标准格式，可直接用 LeRobotDataset 加载 |
| 控制频率 | 30 Hz | 4 路 RGB 相机 (480×640) |
| 动作维度 | 7D (单臂) / 14D (双臂) | 6 关节 + 1 夹爪 per arm |
| 单任务数据量 | 500 条 (单臂) / 300 条 (双臂) | 遥操作采集，每条轨迹长度不等 |
| 数据集总大小 | 35 GB | 4000 条轨迹，~560K 帧 |
| ER 缓冲区 | ρ_B = 0.2 (默认) | 保留 20% 历史数据，均匀分配到各任务 |
| 回放频率 | f_r = 0.2 (默认) | 每步 20% 概率从缓冲区采样 |
| 归一化 | ANS II (冻结首任务) | 训练和测试使用同一套归一化统计量 |

**工程含义**：
1. **归一化一致性是硬约束**：部署时必须在首个任务收集时计算归一化统计量并持久化，后续所有任务复用。这意味着新任务的数据分布不能偏离首任务太远（否则归一化后的动作可能超出合理范围）。
2. **ER 缓冲区开销可控**：2% 的缓冲区意味着 4000 条轨迹只需保留 80 条，存储和计算开销极低。
3. **异构臂切换需非对称回放**：单臂↔双臂切换时，双臂任务需要更高的回放频率（论文中均匀 f_r = 0.2 导致双臂任务性能下降），这提示实际部署中可能需要任务感知的自适应回放策略。

### 评测协议

论文采用三个标准持续学习指标（来自 [alkaifi et al. 2019](https://arxiv.org/abs/2605.26820) 引用 [5]）：

| 指标 | 公式 | 含义 |
|------|------|------|
| AS (Average Score) | (1/K) · Σ_{i=1}^{K} c_{i,K} | 最终所有任务的平均得分（0-100） |
| BWT (Backward Transfer) | (1/(k-1)) · Σ_{j=1}^{k-1} (c_{j,k} - c_{j,j}) | 负值 = 遗忘，越高越好 |
| FWT (Forward Transfer) | (1/(k-1)) · Σ_{j=2}^{k} (c_{j,j} - c̄_j) | 正值 = 正向迁移，负值 = 可塑性损失 |

**评分方式**：每个任务有独立的 rubric，按中间进度给分（0-100），非二值成功/失败。这比纯成功率更能反映长程操作的渐进完成度。

### 6.1 隐含假设 (Hidden Assumptions)

1. **归一化统计量可提前获取**：ANS II 要求用首任务的统计量冻结到整个任务流。这假设首任务的动作分布能"覆盖"后续所有任务的合理动作范围。如果后续任务需要首任务从未出现过的动作（如新的关节角度），归一化后可能产生极端值。

2. **遥操作数据质量一致**：论文假设所有任务的 300-500 条轨迹质量相当。但实际部署中，不同任务的演示质量可能差异很大（接触丰富任务更难采集高质量数据）。

3. **单一策略可处理异构臂**：论文让同一个 π0.5 策略交替处理单臂（7D 动作）和双臂（14D 动作）。这假设模型的表征空间能自然编码不同维度的动作空间——但论文未提供消融实验验证这一点（例如对比"共享策略 vs 独立策略"）。

4. **稀疏奖励设定**：论文使用二元目标指示器 g(s) 而非密集奖励。这符合大多数操作任务的实际情况，但也意味着方法可能不适用于需要密集奖励反馈的连续控制任务。
