💡 **X-Ray 开场**
VLA 模型在长时程操作中面临一个根本问题：仅仅堆叠历史帧并不能让模型"理解"物理状态的变化——一个失败的抓取看起来和抓取前的状态几乎一样，但需要完全不同的下一步动作。TemporalFlow-VLA 的核心洞察是：不需要在部署时做任何运动估计，只需在训练时用机器人运动学投影出"机器人表面看起来是怎么动的"，用这个物理接地的信号去监督两个紧凑的时序查询 token，就能让动作专家获得结构化的历史感知。

### 1.2 关键机制 (Key Mechanism)

**问题诊断**：论文首先做了一个关键诊断实验——打乱 3 个历史帧的顺序，保持当前帧不变，结果 action flow-matching loss 几乎不变（仅增加 ~4.6%）。这说明标准 VLA 对历史帧的时序顺序"不敏感"，历史帧的存在本身有一定帮助，但模型并没有真正利用时序信息。

**核心设计思路**：
1. **物理接地监督**：用机器人关节状态、URDF 几何和相机标定，将机器人表面运动投影到 224×224 策略图像平面，生成 robot-surface temporal flow 作为训练目标
2. **两个 chunk-aligned 时序查询**：Q8 编码 t-8 到 t 的短期运动，Q15 编码 t-15 到 t 的长期演化，两者形成层次结构
3. **查询瓶颈**：动作 token 只能通过 Q8/Q15 获取历史信息，不能直接访问历史图像 patch——强制历史视觉信息压缩为 flow-supervised 查询表示
4. **训练/部署分离**：几何监督管线仅在训练期存在，部署时只有时序查询 + 动作生成

⚡ **Eureka Moment**：「用训练期的物理监督给每个时序 token 分配明确的运动语义，而不是让模型自己从多帧中无监督地学习时序表示——这样历史帧不再是一堆模糊的视觉上下文，而是每个 token 都知道自己该编码什么物理变化。」

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L = L_action + 1.0 · 0.5 · (L_flow^8 + L_flow^15)
```

**目标**：在标准动作流匹配损失之外，加入两个时序查询的 flow 重建损失，让 Q8 和 Q15 分别学会编码短期和长期的机器人表面运动。

**公式分解**：

```
Step 1: 运动学投影 — 将机器人表面点从源帧传输到目标帧
x_link(p) = [T_B^{l(p)}(q_s)]^{-1} · X_s^B(p)     (反变换到 link 系)
X_t^B(p)  = T_B^{l(p)}(q_t) · x_link(p)          (正变换到目标帧 base 系)
u_t(p)    = Π_K(T_{C←B} · X_t^B(p))              (投影到图像平面)

Step 2: 归一化位移
f_ρ(p) = (u_t(p) - u_s(p)) / 224                  (归一化到图像尺寸)

Step 3: Patch 级聚合 (14×14 → 16×16×2)
F_ρ(k) = (1/|V_k|) · Σ_{p∈V_k} f_ρ(p)            (有效 robot 像素均值)
M_ρ(k) = 1[c_ρ(k) ≥ 0.1]                         (coverage 门控)

Step 4: Flow 重建损失
L_flow^ρ = Σ_k M_ρ(k) · Huber(F_hat_ρ(k), F_ρ(k)) / (Σ_k M_ρ(k) + ε)

Step 5: 联合优化
L = L_action + λ_temp · L_temp
L_temp = 0.5 · (L_flow^8 + L_flow^15)
```

**变量说明**：

| 符号 | 含义 | 维度/值 |
|------|------|---------|
| q_τ | τ 时刻关节配置 | — |
| T_B^l(q_τ) | link-to-base 正运动学变换 | 4×4 齐次矩阵 |
| T_{C←B} | base-to-camera 标定变换 | 4×4 齐次矩阵 |
| Π_K | 透视投影 (内参 K) | — |
| f_ρ(p) | 像素 p 的归一化位移 | 2D, 归一化到 224 |
| F_ρ(k) | patch k 的 flow 目标 | 16×16×2 |
| c_ρ(k) | patch k 中有效 robot 像素占比 | [0, 1] |
| M_ρ(k) | coverage 门控掩码 | {0, 1} |
| Q_8, Q_15 | 可学习时序查询 token | 2048D each |
| z_ρ | Q_ρ 的最终状态 | ℝ^{2048} |
| γ_ρ, β_ρ | FiLM 投影参数 | channel-wise |
| λ_temp | 时序损失权重 | 1.0 (所有实验) |

> 符号与本文保持一致。ρ ∈ {8, 15} 表示两个时间间隔（step 数）。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个简化的 2D 场景：机械臂末端执行器在图像平面上从位置 A 移动到位置 B。

**设置**：
- 图像尺寸：224×224
- 源帧 t-8 中，末端执行器中心像素 u_s = (100, 120)
- 目标帧 t 中，末端执行器中心像素 u_t = (112, 128)
- Patch 大小：14×14，假设该 patch 中心在 (100, 120)

**Step 1: 运动学生成 ground truth flow**

```
位移 = u_t - u_s = (112-100, 128-120) = (12, 8) 像素
归一化 flow f_8(p) = (12/224, 8/224) = (0.0536, 0.0357)
```

假设该 patch 内 20 个像素都属于机器人表面（coverage c_8 = 20/196 ≈ 0.102 > 0.1），则：

```
F_8(patch) = mean of all f_8(p) for valid p ≈ (0.0536, 0.0357)
M_8(patch) = 1  (因为 c_8 ≥ 0.1)
```

**Step 2: 时序查询预测 flow**

假设 Q8 经过 FiLM 调制 + MLP 后预测：

```
F_hat_8(patch) = (0.0480, 0.0320)  (略低估了运动幅度)
```

**Step 3: 计算 Huber 损失**

```
误差 = F_hat_8 - F_8 = (0.0480-0.0536, 0.0320-0.0357) = (-0.0056, -0.0037)

Huber loss (δ=1.0): 由于 |误差| << δ，退化为 MSE
L = 0.5 · (0.0056² + 0.0037²) = 0.5 · (0.0000314 + 0.0000137) = 0.0000225
```

**Step 4: 梯度回传**

这个 loss 会回传到：
1. Q8 token 的表示（让它学会编码这个运动方向）
2. FiLM 参数 γ_8, β_8（改善调制）
3. MLP 权重 W_8^h, W_8^o（改善 flow 预测）

**Step 5: 动作专家受益**

经过训练后，当动作专家看到 Q8 的表示时，它"知道"末端执行器最近向右上方向移动了约 5% 图像宽度——这告诉它上一个动作 chunk 产生了有效的位移，当前可能需要继续推进而非重新开始。

## 4. 工程视角 (Engineering View)

| 工程维度 | 数值/设计 | 含义 |
|----------|-----------|------|
| 训练开销 | +20% wall-clock | 相比基线 π0.5，增加时序模块和 flow 解码器的训练时间 |
| 部署推理延迟 | T_cache ≈ T_vision + T_joint + T_action | 异步缓存后，仅当前帧编码在关键路径上 |
| Naive 同步延迟 | T_naive = 3·T_vision + T_joint + T_action | 无缓存时需编码 3 帧视觉，延迟增加约 2× |
| 历史帧数 | 2 (t-15, t-8) | 对 16-step action chunk，覆盖前一个 chunk 的起始和中点 |
| 时序查询维度 | 2048D × 2 | 每个查询 token 仅 2048 维，非常紧凑 |
| Action chunk 长度 | 16 steps | 标准设置，Q8/Q15 间隔与之对齐 |
| GPU 需求 | 8×H100, batch=32/GPU | 训练配置；部署时单卡即可 |
| 部署额外组件 | 无 | 几何渲染器、flow 解码器均不部署 |

**工程含义**：

1. **关键路径优化**：异步特征缓存是此方案可落地的关键。历史帧编码与当前动作执行重叠，推理延迟不随历史帧数线性增长。
2. **训练-部署不对称性**：训练时需要 URDF + 相机标定 + 渲染器生成监督信号，但部署时完全不需要——这是一个"训练期教师、部署期孤儿"的设计，降低了部署复杂度。
3. **模块边界清晰**：时序模块与动作专家通过 joint masked attention 交互，不需要额外的 cross-attention 模块或 history-specific residual gate，保留了 π0.5 原有的 AdaRMS 调制。
4. **启动期处理**：episode 开始时历史不可用，用最早观测填充并标记无效，缓存直到两个历史帧 token 都可用后才启用。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 能做什么

| 场景 | 表现 | 原因 |
|------|------|------|
| 多阶段桌面操作 (H=2/3) | 显著提升 | 时序查询编码了前序 chunk 的物理变化 |
| 长时程任务 (LIBERO Long) | +2.1pp | 历史感知帮助识别当前阶段和进展 |
| 随机化环境 (RoboTwin) | 84.2% | 物理接地监督提高了泛化性 |
| 视觉相似状态区分 | 诊断实验证实 | 打乱历史帧会显著增加 loss |

### 不能做什么 / 局限

| 局限 | 原因 |
|------|------|
| **仅仿真验证** | 无真实机器人实验结果（论文未报告 real-robot） |
| **依赖机器人运动学** | 需要准确的 URDF 和关节状态；运动学误差会污染监督信号 |
| **仅跟踪机器人表面** | flow 监督仅覆盖 robot-surface 像素，不跟踪物体运动或场景变化 |
| **H=1 无显著优势** | 单步任务不需要历史感知，甚至可能因额外参数略降 |
| **固定时间间隔** | Q8/Q15 间隔硬编码为 8/15 step，不自适应任务节奏 |
| **需要相机标定** | 训练期需要准确的 T_{C←B} 标定；标定误差直接影响 flow 质量 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **机器人运动学足够准确**：论文假设 URDF 模型和关节编码器精度足够生成可靠的 flow 监督信号。但在真实机器人上，齿轮间隙、柔性变形、标定漂移都会引入误差。
2. **机器人表面运动是物理变化的充分代理**：flow 监督仅覆盖机器人自身表面，假设机器人运动足以编码决策相关的物理变化。但如果关键物理变化发生在物体-物体交互（如两个物体之间的相对滑动），这个信号可能不够。
3. **固定 chunk 长度合理**：Q8/Q15 间隔针对 16-step chunk 设计。如果部署时使用不同长度的 action chunk，时序对齐可能需要重新调整。
4. **训练期监督在部署期有效迁移**：flow 监督仅在训练期存在，假设 Q8/Q15 学到的表示在部署期（无监督）仍然有效。论文通过 ablation 间接验证了这一点，但没有做分布外测试。
