- **日期**：2026年
- **链接**：https://www.xiaohongshu.com/explore/（搜索可见）

**帖子摘要**：详细记录XVLA+RobotTwin多卡训练的踩坑经验。核心优化包括：
- DeepSpeed vs Accelerate 选型：DeepSpeed ZeRO-2在VLA训练中更稳定
- Dataloader参数调优：num_workers和prefetch_factor对训练速度影响巨大

- OMP_NUM_THREADS设置：不设置会导致CPU过载，建议设为4

## 帖子 13：VLA实时执行：从演示到部署的4层地狱

- **作者**：（部署工程师）
- **日期**：2026年
- **链接**：https://www.xiaohongshu.com/explore/（搜索可见）

**帖子摘要**：总结VLA从demo到真机部署的4大挑战：
1. **推理延迟**：大模型推理慢，动作跟不上实时需求
2. **Action chunk跳变**：chunk边界处动作不连续，机械臂抖动
3. **预测-执行不匹配**：预测的是未来轨迹，但执行时环境已变化
4. **动力学变化**：负载变化、摩擦变化导致同一动作效果不同

推荐解决方案论文：RTC、Training-time RTC、VLASH、SAIL

## 社区观点综合分析

### 一、核心路线之争：VLA vs WAM vs 融合

社区当前最激烈的分歧在于技术路线选择：

**1. VLA质疑派（主流声音）**
- VLM不具备足够具身知识，VQA预训练范式难以推演时空变化
- VLA目前只能用到VLM 30%的能力（导师级别的判断）
- 静态图像的2D学习解决3D世界问题是死胡同
- "L起不到作用反而导致难以学习"（工业界直言）
- 小鹏VLA 2.0被多人指出"没有L"
- 操作行为不需要语言能力也可以执行，小模型action policy也很强

**2. WAM支持派**
- 视频预训练实现物理动态理解，时序学习才能泛化
- LDA-1B在DINO latent space统一dynamics和action
- Motus确定了1.6秒/48action/8帧的有效setting
- 但WM技术路线本身也没收敛，有人说"WAM也已死"

**3. 融合派 / 快慢双系统**
- WM+VLA配合，世界模型学习+扩散模型预测+VLA执行
- 具身language的reasoning能力（LLM提供）是WM没法替代的
- 快慢双系统是值得挖掘的空间
- VLA+residual RL：VLA做粗动作，RL做精细修正（已有团队实践）

**4. 全都不对派**
- 绕开传感器不建模，死守视频图片一条路都是死胡同
- 需要3D传感器建模，不能只靠2D

### 二、工程实践经验汇总

**训练相关：**
- Motus训练：最低80G显存，推理1.6秒chunk需1秒（5090，T5预先encode）
- OpenPI finetune：LoRA单卡bs=1约20G，全参数约70G；预测绝对量优于delta值
- π0部署灵巧手：预训练没见过灵巧手，新增dim模型用不了，跨模态泛化远不够
- OpenVLA复现：LIBERO Object任务实测62.6%，论文报85.7%——复现差距显著
- 多卡训练VLA：DeepSpeed ZeRO-2更稳定，HDF5推荐lzf压缩，OMP_NUM_THREADS=4
- LeRobot框架复现：ACT在小数据量（164 episodes）下远优于π0/SmolVLA/DP

**部署相关：**
- 机械臂冷启动温度低→关节摩擦力变大→VLA预测偏差（建议空跑10分钟热机）
- Action chunk边界处动作不连续→机械臂抖动
- 推理延迟是核心瓶颈，预测-执行不匹配
- 固件更新后运动学指标全部得重调

**数据采集：**
- 多视角RGBD数据采集场地和设备门槛高
- VLA数据不一定需要标定（calib），遥操用VR或gello映射
- 带力/触觉数据采集成本过高，行业不愿投入

**VLA后训练（Post-training）：**
- World Model in the Loop：用WM做模拟器给VLA做RL，但WM必须用真机数据训
- Human in the Loop：SOP方案（多机+多任务+人类反馈），工程量巨大
- RL方法共识：advantage-conditioned（CFGRL/AWR）类supervised RL成为主流

### 三、行业现实

## 帖子 34：为什么GRPO很容易训飞？

- **作者**：代码Lin
- **日期**：2025-08-11
- **链接**：https://www.xiaohongshu.com/explore/689954680000000003030308
- **填补缺口**：❌ RL Reward / 训练不稳定的实操经验

**帖子摘要**：GRPO 训练不稳定的四大原因+踩坑经验：
1. **强化学习的蝴蝶效应**：每次策略更新改变数据分布，reward暴跌
2. **组内相对奖励的双刃剑**：样本质量参差时相对奖励不稳定，好样本被忽视、差样本被错误惩罚
3. **梯度爆炸与熵崩塌**：长序列推理最头疼；熵崩塌更隐蔽——模型重复输出、loss在降但模型已死
4. **超参数极度敏感**：学习率稍高→梯度爆炸；clip_ratio设错→直接崩盘；多卡并行时batch size变化也加剧敏感性

**实战建议**：
- Reward 监控不能只看平均值，方差和分布也很重要，设预警机制
- 梯度裁剪是必须的
- 定期保存checkpoint，出问题快速回滚——"别问我怎么知道的，血的教训"

## 第二轮新增关键发现

### RL 后训练的工程现实（最大新发现）

1. **RECAP 已可在低成本硬件复现**（帖36 Evo-RL）：SO101 机械臂上实现完整的 π*0.6 RECAP 闭环，基于 LeRobot 框架。证明 RL 后训练不再是 PI 的专利。
2. **但 RL 的上界被预训练锁死**（帖32）：如果 BC 阶段的预训练知识不够丰富，RL 再怎么搜索也解不出来——这与专家记忆中 B2（RL 后训练突破 BC 天花板 81%）形成张力。
3. **GRPO 极易训飞**（帖34）：梯度爆炸、熵崩塌、超参敏感性是真实痛点；组内相对奖励在收敛期区分度下降。

### 灾难性遗忘已成已知问题（但解决方案不成熟）

1. **VLA 微调会"弄瞎"视觉能力**（帖31）：OOD 泛化降 10%+，首次有定量证据
2. **视觉表征对齐**是一个方向，但社区讨论热度不高——说明大多数人还没意识到这个问题
3. 与专家记忆中 B7（Action Expert 解耦 78%）直接相关：Knowledge Insulation 正是为了解决这个问题

### 评论区补充洞察（第二轮留言复查）

1. **Evo-RL 训练成本**：Policy 8卡A800约10小时，Value Function 约0.5小时；干预使用语音控制而非脚踏板
2. **GRPO 在 MOE 模型上特别危险**：qwen3 论文已确认 GRPO 的 token 维度优化在 MOE 架构上导致 reward 暴跌，解决方案是 GSPO

4. **VLA 注意力分布异常**：有用户实测发现 VLA 的 attention 集中在背景而非目标物体上——直接印证灾难性遗忘/视觉退化问题

# 📊 60 篇帖子综合分析

## 一、社区共识与分歧全景

### 高度共识区域（Bull + Bear + Arbiter 三方一致）

1. **VLA 的 "L" 当前贡献有限**
   - 帖2/57/60：工业界和学术界都在讨论"VLA去掉L效果不差甚至更好"
   - 小鹏 VLA 2.0 "没有L"被多人反复提及
   - 作者原话："L起不到作用，反而导致难以学习"
   - **社区判断**：Language 模块在当前 VLA 中更多是 overhead 而非 enabler

2. **ACT 在小数据单任务场景仍是最佳选择**
   - 帖45/46/55：ACT 31K 步收敛、50 episodes 就能 work、成功率 90%+
   - 但泛化差、CVAE posterior collapse、temporal ensemble 只是 trick
   - **对比**：π0/SmolVLA/Diffusion Policy 在相同条件下全部失败

3. **数据采集是当前最大瓶颈**
   - 帖44/47：硬件组装成本高（~7万）、遥操作不可持续
   - 帖47 预测"很多数采路线要被炮灰"
   - 未来方向：仿真合成 + 少量真实数据微调

4. **Sim2Real gap 被严重低估**
   - 帖41/42/51：friction model 不校准、URDF 颤抖、MuJoCo XML 名称冲突
   - 帖33（第二轮）：sim2sim 都有 bug
   - **社区经验**：多数团队的 Sim2Real 失败根因是物理参数不准，而非算法不行

### 激烈分歧区域

1. **VLA vs WAM/WA/VA 路线之争**
   - Bull：WAM 的多任务性能 scaling 更好（Motus +37% vs π0.5）
   - Bear："wm技术路线都没有收敛，WAM都来了？"、"WAM也已死"
   - Arbiter：两者可能是互补关系而非替代（"打配合"）

2. **RL post-training 的实用性**
   - Bull：RL 能发现 demo 之外的解（帖43）
   - Bear：GRPO 在 MOE 上失败（帖34）、训练成本 8xA800 10小时（帖32）
   - Arbiter：on-policy RL on real robot 是方向，但工程门槛极高

3. **学术界 vs 工业界的价值**
   - 帖48/49/59：实习经历揭示巨大落差
   - "课题组培养 leader，公司培养螺丝钉" vs "公司培养体系很乱"
   - **真实结论**：两边都有问题，关键看具体团队而非学/工二分
