**优化策略清单**：
1. **消除计算开销** — 用 CUDA Graph 机制消除 CPU 开销。CUDA Graph 预先记录内核调用，由 GPU 直接执行，避免大量 Python 代码执行延迟。

   - 合并 RMSNorm 与后续 Linear 层
   - 折叠动作时间编码（不必要操作合并为单个 kernel call）

3. **内核深度优化**：
   - 调整 GEMM 块参数（用 Triton 手动调优）→ 进一步减少 1.5ms
   - 优化门控线性层的内存加载/存储
4. **实时推理框架** — 全流式推理（Full Streaming Inference）：
   - 30Hz 图像输入频率
   - 480Hz 高频控制输出
   - **VLM 与 AE（Action Expert）并行执行**，充分利用计算资源

**实际验证**：机器人需在有限时间内抓住一个移动的正方块（实时反应任务）。

## 帖子 4：VLA 实时执行 — 推理延迟、动作块不连续性（5 类工程问题清单）🔺

- **作者**：AI椰青
- **日期**：2025-12-15
- **互动**：86 赞 / 128 收藏
- **链接**：https://www.xiaohongshu.com/explore/6940be80000000001e031724
- **Score**：5 分（5 个独立工程问题 + 对应解决方案）

**5 类工程问题**：

1. **推理延迟问题** — VLA 模型推理时间可能超过控制步骤所需时间。同步执行下推理与控制相互阻塞，机器人停滞。**异步推理**能减少延迟，但带来状态-动作不一致性。

2. **动作块不连续性** — 块化策略降低延迟但导致连续动作块之间不连续（例：左走与右走之间跳跃，块边界出现不平滑、分布外运动）。**RTC（Real-Time Chunking）**：执行当前动作块的同时生成下一个动作块，通过修补生成缺失部分。**仅在推理阶段，不需要重新训练模型**。

3. **预测与执行的错位** — 异步推理中，动作基于当前状态 sₜ 预测，但在 s_{t+Δ} 上执行。**VLASH（MIT/NVIDIA）**解决方案：在推理过程中通过已知动作预测未来状态，将策略条件设定为执行时的状态。**特别适用于乒乓球和打地鼠等快反应任务**。

4. **训练时 RTC** — 与传统 RTC 在推理阶段修复不同，**训练时 RTC 将实时约束转移到训练过程**。模拟推理延迟 + 在策略中加入动作前缀条件，模型在面对高延迟时更鲁棒。**避免推理阶段开销，部署时无缝替代传统 RTC**。

5. **动力学与控制器变化** — 当执行速度超过演示时，机器人会面临控制器和系统动力学的变化（高速下的非线性效应）。

**对信念网络的影响**：填补 §10.3 关于"VLA 实时执行"的具体方法论——**RTC（推理阶段修复）vs 训练时 RTC vs VLASH 三条路径在 2026 年并存**。建议在 §10.3 增设子节"VLA 异步推理三路径对比"。

**核心发现**：OXE 这种混合数据集上训练的 VLA 模型泛化能力差的关键因素是 **shortcut learning**。

**Takeaways**（作者亲自总结）：
1. **为避免用无关特征作预测（shortcut）以提升泛化性，通用机器人数据集得是连结成一片的整体，而不是分割的孤岛**。
2. 如果不是连结一体的数据集，至少**每个子数据集的每个变化因子必须足够 diverse**：
   - π0.5 是环境因子
   - Gemini Robotics 是指令和干扰物体因子
3. 在当前 robot 数据集规模下，**应该专注在几个急需泛化因子的变动，尽量保持其他因子不变**（例如 π0.5 的任务类型、Gemini 的环境背景）。
4. **对已有数据集**，可以通过特殊数据增强方式增加子数据集多样性、减小子数据集间隔阂（**例如 VISTA 作用于 viewpoint 因子**——和 §14.1 印证）。

   - **劣势**：仅提供无约束位置信号，**缺乏力反馈与手指微操通道**，导致插拔 USB / 旋钮开关等任务演示方差过大

4. **视觉/惯性动捕** — 多刚体 IK 优化。
   - **配置**：Vicon / OptiTrack / 青瞳视觉（亚毫米精度）/ 诺亦腾（无遮挡、全场景）
   - **春晚人形群舞**就是惯性动捕输出全身关节角，经 retargeting 完成
