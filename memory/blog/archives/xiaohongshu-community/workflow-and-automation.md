### 1.3 技术实现细节

#### 为什么只能用 Chrome 直连

小红书的内容抓取有三重防护：
1. **外部爬虫封锁**：`site:xiaohongshu.com` 在 Google/Bing 搜索返回极少结果
2. **未登录限制**：未登录状态下内容被截断，评论不加载
3. **反爬机制**：频繁请求触发人机验证

因此唯一可行路线：**用户先在 Chrome 中登录 → Claude 通过 Chrome MCP 操作已认证的浏览器会话**

#### DOM 提取模式（经过多次迭代优化）

```javascript
// 搜索结果页提取
const items = document.querySelectorAll('.note-item, section.note-item');
// → 标题 + 链接

// 帖子详情页提取
const title = document.querySelector('#detail-title')?.textContent;
const desc = document.querySelector('#detail-desc')?.textContent;
const author = document.querySelector('.username')?.textContent;
const date = document.querySelector('.date')?.textContent;

// 评论提取（含去重——小红书 DOM 评论会重复 2-3 次）
const comments = [];
document.querySelectorAll('.comment-item, .parent-comment, [class*="comment-inner"]')
  .forEach((c, i) => {
    if (i >= 15) return;
    const user = c.querySelector('.name, .user-name, .author-name')?.textContent;
    const text = c.querySelector('.content, .note-text, .comment-text')?.textContent;
    if (text && text.length > 5) comments.push({user, text: text.slice(0, 250)});
  });
// 去重：Set 跟踪 user+text前40字
const seen = new Set();
const unique = comments.filter(c => {
  const k = c.user + c.text.slice(0, 40);
  if (seen.has(k)) return false;
  seen.add(k);
  return true;
});
```

#### 踩过的坑

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| WebSearch subagent 全部返回空 | 小红书封锁外部爬虫 | 放弃 subagent，改 Chrome 直连 |
| `read_page` 字符超限 | 小红书页面 DOM 极大 | 改用 `javascript_tool` 精准提取 |
| `await` 语法错误 | javascript_tool 不支持顶层 await | 改用同步 DOM 查询 |
| 评论重复 2-3 倍 | 小红书 DOM 结构多层嵌套 | Set 去重 |
| 部分帖子 `[BLOCKED]` | Cookie/query string 数据触发安全策略 | 跳过，记录为"内容未提取" |
| 图片帖无文字内容 | 核心信息在图片中 | 记录标题+评论，标注"图片帖" |

## Part 2：VLA Expert 视角讨论

### 2.1 社区声音 vs 专家记忆的交叉验证

加载 VLA Expert Memory（328+ 篇论文），将 60 篇社区帖子的核心判断与专家记忆做交叉验证：

#### 🔴 Bull（社区声音的信号价值）

**社区提供了专家记忆中没有的"实操真相"：**

1. **"L 起不到作用反而导致难以学习"**（帖57）
   - 专家记忆中 C3（VLA不需要语言）置信度仅 24%
   - 但社区的工业界实践者+多位研究者重复印证这一点
   - [信号] 这应该推动 C3 上调至少 +10%，至 34%
   - **什么能推翻**：如果 π0.5 级别的 co-training 证明 L 在 long-horizon 任务上不可或缺

2. **ACT 50ep work vs VLA 200ep 仍失败**（帖55）
   - 专家记忆提到 ACT 但没有给出具体数据门槛
   - [信号] 社区给出了明确的数据量门槛：ACT ~50ep，VLA >200ep 才有希望
   - 这直接挑战了"VLA 能解决数据效率"的叙事

3. **推理卡顿是真实部署的头号问题**（帖50）
   - 专家记忆提到边缘部署策略但没强调"推理-执行异步"
   - [信号] 工程实践中"推理时继续执行上一个 chunk"是标准方案
   - "拍demo视频加速就可以了"——学术界 demo 的可信度问题

4. **硬件坑是被论文完全忽略的巨大时间成本**
   - Piper 逆解失败（帖54）、Franka 底座组装 7 万（帖44）、MuJoCo XML 名称冲突（帖51）
   - 专家记忆中几乎没有这类内容
   - [推断] 论文到真机之间有一个巨大的"暗物质"时间成本

#### 🔵 Bear（社区声音的偏差和盲区）

**社区存在系统性偏差：**

1. **幸存者偏差**：成功的实验更容易被分享，失败的可能直接放弃不发帖
2. **硬件局限偏差**：社区大多用低成本臂（Piper/ALOHA/SO-100），对 Franka/UR5 级别的经验稀少
3. **小数据偏差**：几乎所有经验都在 <500 episodes，无法外推到 π0.5 级别（10K+ episodes）的场景
4. **中国生态偏差**：小红书用户集中在中国学术/工业圈，对 PI/Google/NVIDIA 的一手经验几乎为零
5. **知识盲区持续存在**：
   - FAST tokenization：0 篇实操分享
   - Co-training 数据混合比：0 篇
   - 视觉编码器定量对比：0 篇
   - 量化/蒸馏到边缘设备：0 篇

#### 🟢 Arbiter（对你的研究意味着什么）

**社区声音最大的价值不是"告诉你方向"，而是"告诉你暗礁在哪"。**

1. **如果你要开始 VLA 实验**：
   - 先用 ACT 50ep 验证你的数据采集和部署 pipeline——这是最低成本的验证
   - VLA 微调至少需要 100-200ep 才有希望，且需要精心调配置
   - 推理-执行异步是必须的工程设计，不是可选优化

2. **如果你要选硬件**：
   - 远离 Piper（多人投诉）
   - Franka 底座自组装成本约 7 万，不如买整机
   - 相机标定（TCP + 手眼 + 视觉）是最容易低估的时间黑洞

3. **如果你要做研究方向判断**：
   - "L 的价值有限"是工业界共识但学术界尚未完全接受——这里有时间套利
   - WAM/WA/VA 路线尚未收敛，但 Motus 的多任务 scaling 数据（+37% vs π0.5）是强信号
   - 力觉/触觉即将成为必需模态——"当视觉无法起作用时"

## Part 3：自动化方案设计

### 3.1 需求分析

**目标**：自动化从小红书持续收集 VLA 相关的复现经验、踩坑经验、个人观点，形成一个持续更新的"社区知识雷达"。

**约束**：
1. 小红书无公开 API
2. 必须通过浏览器 + 用户登录状态访问
3. 反爬机制限制请求频率
4. 评论区才是信息富矿，但需要点进帖子才能看到
5. 图片帖的核心内容在图片中（当前无法自动提取）

#### Step 3：Chrome MCP 自动提取

每次执行流程：

```
1. 打开小红书搜索页（需用户预先登录）
2. 依次搜索关键词矩阵中的每组关键词
3. 每组提取前 5 条搜索结果（标题+链接）
4. 与已收集帖子 URL 库去重
5. 对新帖子：
   a. 导航至帖子详情页
   b. 提取标题、正文、作者、日期
   c. 提取评论（含去重）
   d. 间隔 3-5 秒（避免触发反爬）
6. 每次最多处理 15 条新帖（控制时间在 20 分钟内）
```

#### Step 4：VLA Expert 质量筛选

对每条新帖自动执行信息价值评估：

```
评估标准（按优先级）：
1. 是否包含具体数据（epoch数、成功率、GPU型号、训练时间）→ +3分
2. 是否描述失败模式和根因分析 → +3分
3. 是否有作者一手经验（"我试过"而非"我觉得"）→ +2分
4. 评论区是否有补充洞察 → +2分
5. 是否覆盖当前知识盲区 → +2分（参考盲区列表）
6. 扣分：求职帖 -10 / 纯转发 -5 / 广告 -5

阈值：≥4 分入库，<4 分记录标题但不详细分析
```

#### Step 5：增量更新报告

```
输出：
1. 追加新帖子到 小红书_VLA_社区声音_{date}.md
2. 更新"社区知识盲区"列表
3. 如果新帖触发信念更新条件 → 生成更新建议
4. 每月生成一份"社区声音月报"摘要
```

### 3.4 去重与增量机制

```python
# URL 去重库（持久化到本地文件）
COLLECTED_URLS = set()  # 从 collected_urls.json 加载

# 内容相似度去重（标题 + 前100字）
from difflib import SequenceMatcher
def is_duplicate(new_post, existing_posts):
    for p in existing_posts:
        ratio = SequenceMatcher(None,
            new_post['title'] + new_post['desc'][:100],
            p['title'] + p['desc'][:100]
        ).ratio()
        if ratio > 0.7:
            return True
    return False
```

### 3.5 实现限制与缓解

| 限制 | 严重程度 | 缓解方案 |
|------|----------|----------|

| 评论需要展开才能加载全部 | 🟡 中 | 自动点击"展开更多"按钮（最多3次） |
