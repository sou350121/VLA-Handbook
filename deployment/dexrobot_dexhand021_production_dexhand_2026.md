# DexHand021 量产版（DexRobot）：19-DOF 多模态感知灵巧手的工程落地拆解 (DexHand021 Production Dexterous Hand)

> **页面来源**：DexRobot 产品页（访问日期：2026-01-28）  
> **产品名**：DexHand021 量产版（商用高自由度多模态感知智能通用灵巧手）  
> **核心定位**：把“灵巧手”从实验室原型推向**可买、可装、可维护、可二次开发**的量产件：19 DOF（12 主动 + 7 被动），CANFD + ROS1/ROS2/micro-ROS，带触觉/力觉/滑觉/接近觉，用于多指抓取与手内操作。  

如果你关心的是“这只手能否成为 VLA 的可靠末端执行器”，关键不是 DOF 数字，而是：**通信稳定性（CANFD）、控制模式边界（位置/轨迹/力控）、传感可用性（触觉+滑觉+接近的可观测性）、以及维护成本（腱绳系统的漂移/更换/标定）。**

**官方来源**：[DexHand021 产品页](https://www.dex-robot.com/productionDexhand)

### 1.2 一个“量产灵巧手”的现实解读

- **腱绳传动**通常意味着你会遇到：迟滞、回零误差、张力变化、温度相关漂移。  
  这不是坏事（腱绳也能带来顺应性和安全性），但它会把 VLA 的难点从“模型会不会”迁移到“系统会不会长期一致”。  
- 页面强调“**5 根手指均可独立更换**”，这是很务实的量产信号：真正跑数据/跑 demo 的团队，宕机多半来自机械与线缆，而不是模型。

## 2. 工程含义拆解：可用性 = 稳 + 可控 + 可维护

### 2.1 “>150,000 次寿命”到底算不算长？

你需要把“次数”换成你的工作节拍：

- 若按 1 Hz 的“开合循环”（每秒 1 次），150,000 次约 41.7 小时  
- 若按 0.1 Hz（每 10 秒 1 次），约 416.7 小时（~17 天）  
- 若按 0.01 Hz（每 100 秒 1 次，偏真实任务节奏），约 4,167 小时（~173 天）

结论：**寿命数字本身不够**，必须知道测试工况/载荷/速度/环境。否则在项目里无法作为“可交付性承诺”使用。

### 2.2 “姿态保持不耗电”的两种可能

在工程上，常见实现包括：

- **机械自锁/减速器自锁**：保持不需要持续电流，但会影响回驱与力控细腻度  
- **低功耗保持（低增益/间歇控制）**：仍会有静态电流（与页面的 0.2A 更一致）

这点直接影响你是否能做：安全回驱、柔顺控制、以及“碰撞后被动让开”。

## 3. 通信与软件栈：CANFD + ROS 的落地路径 (Integration Stack)

典型可落地架构如下（与本仓库的“通讯与部署实战”文档一致）：

```text
   VLA Policy (GPU / Edge)             Hand Controller (embedded)
 ┌──────────────────────────┐         ┌──────────────────────────┐
 │ obs (cam/state/tactile)  │         │ motor control loops       │
 │  -> action (12-DoF cmd)  │         │ + safety limits           │
 └───────────┬──────────────┘         └───────────┬──────────────┘
             │ ROS2 topic/service                    │ CANFD frames
             v                                       v
     ┌────────────────┐                      ┌───────────────────┐
     │ ROS2 driver node │<------------------->│  CANFD interface   │
     │ (control + state)│                      │  + termination     │
     └────────────────┘                      └───────────────────┘
```

**你需要厂商明确提供**：
- ROS1/ROS2 的节点/消息定义（关节列表、触觉/力觉 topic）  
- 频率：控制指令频率上限、状态回传频率、触觉采样频率  
- 标定流程：开机零位、张力补偿、温漂补偿策略

## 4. 控制模式 → VLA 动作空间映射 (Action Space Mapping)

DexHand021 给了三种控制模式。对 VLA 来说，你要明确“策略输出是什么、下位机闭环是什么”。

| 控制模式 | 策略输出（推荐） | 下位机闭环职责 | 适合的 VLA/策略类型 |
|---|---|---|---|
| **位置控制** | 12 主动 DOF 的关节角/电机位置（或增量 \(\Delta q\)） | 电机位置环 + 限位/速度/电流保护 | BC、Diffusion/Flow（输出 chunk 也可） |
| **轨迹控制** | 一段 horizon 的关节轨迹（chunk）+ 时间标记 | 轨迹插值 + 平滑（jerk 限制） | Diffusion Policy / Flow Matching / ACT（天然 chunk） |
| **力控制** | 目标力/阻抗参数（或抓握力） | 高速力环/阻抗环 + 稳定性保证 | 需要强“接触相位”任务；策略更像“调参器” |

**经验法则**：如果你没有 1kHz 级别稳定力环与足够可靠的触觉/力觉标定，VLA 直接输出力控目标往往会更不稳定；更稳健的做法是：**策略输出位置/轨迹，力控作为下位机的安全/稳定层**。

## 5. 传感多模态对训练的价值：触觉/滑觉/接近觉怎么用？

### 5.1 推荐的 observation 结构（面向数据采集）

- **视觉**：手外相机 + wrist 相机（若有）  
- **本体状态**：12 主动关节位置/速度/电流（如果能拿到）  
- **触觉阵列/接触特征**：每指/每指腹的接触强度、接触面积、中心点（或原始阵列）  
- **滑觉**：滑移事件（binary）或滑移速度估计（continuous）  
- **接近觉**：距离/阈值触发（用于预接触相位）

对训练的直接好处：
- **滑觉**能把“抓稳/没抓稳”的反馈变成密集信号，减少只靠成功率的稀疏监督。  
- **接近觉**能把“即将接触”的相位可观测化，减轻视觉遮挡/曝光导致的状态缺失。  

### 5.2 数据质量的关键：时间对齐与漂移

腱绳系统的漂移会导致：同一个关节命令对应的真实指尖位姿慢慢变化。  
这会让你的数据出现“隐性 domain shift”。对策：
- 采集时把**温度/运行时间/张紧维护记录**作为元数据（哪怕是手工日志）  
- 定期插入“基准姿态校验段”（例如每 N 条 episode 回到一套标准张开/闭合姿态并记录误差）

## 6. 上线 Checklist：从开箱到能跑策略 (Bring-up Checklist)

### 6.1 硬件/供电

- 24V 电源按 **7.4A 峰值**留余量（建议 >10A 级别），线缆按压降与热设计  
- 做浪涌/反电动势保护（TVS、输入电容），避免松开/撞击导致电压尖峰

### 6.2 CANFD（高频故障点）

- 终端电阻：测 CAN_H 与 CAN_L 约 **60Ω**（两个 120Ω 并联）  
- 共地：信号地与电源地要处理好，必要时用隔离 CAN

### 6.3 ROS1/ROS2

- 明确 driver 的 QoS（ROS2）、时间戳口径、状态与指令 topic  
- 用 `rosbag2` 录全量：视觉 + 关节 + 触觉 + 指令，先把“可回放”做出来

## 7. 对比：DexHand021 vs Wuji vs Optimus（从“落地维度”看）

| 维度 | DexHand021（本页） | Wuji Hand（本仓库已有解析） | Optimus Hand V2（本仓库已有解析） |
|---|---|---|---|
| 传动 | **腱绳** | **独立驱动（非腱绳）** | 多数公开资料倾向腱绳/连杆混合（以文档为准） |
| 控制风险 | 迟滞/松弛/回零漂移 | 映射更直接，维护逻辑不同 | 取决于机构与传感闭环 |
| 通信 | **CANFD** | 常见为 EtherCAT/CAN 等（看具体版本/驱动） | 体系化集成（外部难复现） |
| 传感 | 位置+触觉+力觉 +（滑觉/接近） | 依赖具体版本与集成 | 以内部系统为主 |
| 生态 | ROS1/ROS2/micro-ROS + 工具包宣称 | 开源生态更明确（仓库可查） | 非开源为主 |

## 8. 采购/对接前必须问清楚的 12 个问题（不问清楚就别做 VLA）

1) 12 主动 DOF 的**关节列表**与关节极限（URDF/MJCF）  
2) 控制频率上限（位置/轨迹/力控分别是多少 Hz）  
3) 状态回传频率（关节、触觉、滑觉、接近）与时间戳口径  
4) 是否有**电流/力矩**回读（对力控与安全很关键）  
5) 零位/张紧/温漂的标定流程（需要多频繁？需要工具吗？）  
6) “5kg 负载”的定义与测试工况  
7) “1000g 单指力”的定义（指尖/指腹/哪种抓型？）  
8) 滑觉/接近觉的传感原理与分辨率（阈值还是连续量？）  
9) 过热保护阈值、降额策略、连续工作时长（在室温/高温）  
10) CANFD 帧格式/ID 表、带宽占用、是否支持错误恢复策略  
11) 是否提供仿真环境与标定一致的模型（用于 Sim2Real）  
12) 维修件与更换后是否需要重新标定（“独立更换”落地细节）

## 9. 常见坑与风险 (Failure Modes)

- **腱绳迟滞**：同样命令重复执行，抓取成功率慢慢下滑（需要张紧维护与软件补偿）  
- **CAN Bus Off**：现场最常见死法（优先查接线/终端电阻/共地，而不是查模型）  
- **热退化**：连续抓握/高电流动作导致温升→降额→动作变慢或失真  
- **传感口径不一致**：网页写“多模态”，但你拿到的是“阈值事件”，训练价值会完全不同
