# 机器人数据采集验收与有效成本 (Collection Acceptance & Useful-Data Cost)

> ⚙️ 本文由 Codex 辅助整理 | 2026-10-25
> **核心定位**：给自建采集、外包采集和开放数据接入提供同一套验收问题。
> **证据边界**：以下清单与算例是本文的工程建议，不是统一行业标准，也不是本仓库已运行的软件功能。

录到视频、导出数据和训练有效是三个不同阶段。建议先用一个小批次完成“采集→回放→加载→训练→真机评测”，再增加人手或采购规模。

## 1. 先约定交付物

```text
任务及失效场景 → 采集合同/实验设计
                         ↓
不可变原始记录 + 版本化标定/动作定义
                         ↓
自动检查 → 可疑片段隔离 → 人工抽检/重标
                         ↓
独立 episode 清单 + 分组 split + loader 回放
                         ↓
固定训练配方和留出评测 → 接收/退回/定向补采
```

| 交付层 | 至少包含 | 不能用来替代它的东西 |
|---|---|---|
| 原始层 | 传感原始记录、时间戳、记录器版本、文件校验值 | 剪辑过的视频合集 |
| 几何与控制层 | 单位、坐标变换方向、标定版本、动作／状态定义 | 只有列名的数组 |
| 标注层 | 任务、阶段、结果、失败／干预原因、标注版本 | 未抽检的模型生成标签 |
| 数据清单层 | episode ID、原始来源、派生关系、质量状态、split | 文件夹中“看起来有很多文件” |
| 接入层 | 固定 loader／转换版本、加载与时间对齐报告 | “支持 LeRobot”一句话 |
| 效用层 | 留出任务、评测样本和训练配方、比较结果 | 只报告训练 loss 或采集小时 |

格式可以不同，但转换后必须保留上述语义。当前 [LeRobotDataset v3 文档](https://huggingface.co/docs/lerobot/en/lerobot-dataset-v3)用元数据定位 episode 边界；选用 v2 或 v3 时，应固定训练栈兼容版本，并抽查转换前后记录，避免仅凭文件名推断边界。

## 2. Episode 最小验收清单

| 检查域 | 要检查的证据 | 常见拒收／隔离原因 |
|---|---|---|
| 身份与来源 | 全局唯一 ID、来源 session、设备、原始文件 hash | 重复 ID、丢失原始来源、派生数据冒充独立采集 |
| 时间 | 各流原始时间戳、共同时间基准、丢帧与漂移报告 | 时间倒退、错误重采样、按数组行号硬拼不同传感流 |
| 视觉 | 分辨率、实际帧率、曝光、遮挡和标定 | 黑帧、关键接触不可见、相机被移动却沿用旧外参 |
| 机器人状态 | 实测关节／末端状态、关节顺序和单位 | 指令与实测混用、米／毫米或弧度／角度混淆 |
| 动作 | 指令何时发出、参考坐标、绝对／增量、夹爪语义 | 记录目标 pose，却按实际执行轨迹训练而不说明 |
| 几何 | 变换方向、旋转表达、坐标系关系、工具中心点 | 四元数顺序不明、手持接口与执行器 TCP 未对应 |
| 接触 | 触觉原始帧／状态、力传感零点与标定、音频时钟 | 把光学触觉亮度直接当牛顿值；错用接触 onset 标签 |
| 结果 | 成功判据、失败类别、人工接管和复位记录 | 所有中断都记成成功；失败样本没有标识 |
| 权限与访问 | 数据卡／许可版本、使用条件、必要的采集授权记录 | 只有代码许可；无法说明原始数据可用于何种用途 |

门槛应在采集前按任务约定。**不要复制一个“通用 5 ms”或“通用 95% 合格率”作为所有项目的标准。** 同步和几何误差必须与动作速度、允许接触误差、相机位置及控制系统一起评估。

### 2.1 一个只作说明的元数据片段

下面不是 LeRobot 原生 schema，也不是可直接部署的配置；它示意哪些约定需要显式保存。

```json
{
  "episode_id": "toy-0001",
  "source_session": "toy-session-a",
  "capture_kind": "robot_teleoperation",
  "units": {"position": "m", "joint_angle": "rad", "time": "s"},
  "pose_convention": "T_world_ee maps ee coordinates into world",
  "rotation_order": "quaternion_xyzw",
  "action_semantics": "commanded absolute end-effector pose",
  "observed_state_semantics": "measured joint and end-effector state",
  "timestamp_semantics": "per-stream acquisition time",
  "calibration_version": "example-calibration-v1",
  "annotation_version": "example-labels-v1",
  "outcome": "failure",
  "intervention": true,
  "quality_status": "candidate",
  "split_group": "session-and-environment",
  "data_terms_review": "pending"
}
```

`outcome=failure` 不等于 `quality_status=rejected`：清晰记录的失败轨迹可能有研究价值。反过来，动作任务完成的视频也可能因时钟、来源或标定错误而不能接收。

### 2.2 可填写的批次验收记录

> **2026-11-08 工程归纳**：把上面的检查域变成可交付记录，不另立一套质量标准。启发来自本轮社区案例，**不是已运行的验收程序，也不是案例作者验证过的统一配方**。

先填批次身份：`batch_id=____`、原始记录清单／hash `____`、任务与本体 `____`、数据／转换器／loader revision `____`、标定与统计量版本 `____`、抽样方法及数量 `____`。把每项的任务预算和成功判据在读取结果前写下；空白、缺日志和“看起来正常”均不能记为通过。

| 验收项 | 最小核查动作 | 待填记录 | 不通过时的处理 |
|---|---|---|---|
| 时间与因果顺序 | 从实际 loader 解码后检查各流的采集／到达／指令时刻；保留原始时间与映射，不只比帧数 | 时钟口径、偏移／漂移／丢帧实测、抽检帧数、任务预算、证据路径：`____` | 隔离错配片段，修记录或转换；不能把统一帧率当作已同步 |
| 动作与回放 | 对同一片段核对命令、实测状态、joint／EE、绝对／增量及参考帧；离线回放与实机跟踪分开验 | 动作约定、转换前后差异、跟踪误差及样本数、标定版本：`____` | 先修语义或控制接口；只有离线可视化时，把实机项留待验 |
| 相机与任务覆盖 | 在训练／部署实际输入中确认相机名称和顺序；分别检查目标在全局／腕部视野内外的预定测试条件 | 条件清单、每条件独立 episode 数、可见性／预处理核查、留出结果：`____` | 定向补覆盖或修输入映射；不能因装了两台相机就判通过 |
| 接触与多本体 | 按本体、传感器、频率和标定分组，重建接触前后原始信号；其余检查复用§4 | 分组清单、接触标签来源、缺失模态处理和抽检结果：`____` | 先分组定位，不把不兼容记录直接混训；没有传感器时须写明不适用理由 |
| 失败／接管／复位 | 将任务成败、记录技术质量、人工接管和场景复位分别标注；可关联接管前后片段 | 结果类别计数、接管／恢复／复位时间、原始来源关联、抽检分母：`____` | 保留原始记录；坏帧可隔离，清晰的失败不因任务失败自动删除 |
| 清洗与派生关系 | 保留原始版本、筛选原因、派生映射；在同一来源分组内切分，不能派生后重新随机拆分 | 原始→技术可用→去重→接收数量、原因、split group：`____` | 追回来源与划分；过滤、加权、条件化分开比较，不宣称清洗必然增益 |
| 下游效用 | 固定模型初始化、训练预算、数据划分与留出任务，再比较本批加入前后结果 | 各条件成功数／总数、失败分布、预算及不确定性：`____` | 标记效用未证实；技术可读不能代替训练有效，不能只凭loss验收 |

每行附 `状态=待验／通过／隔离／不适用（理由）`、核查人、日期和证据位置。**任务失败、数据技术不合格、下游效用未证实是三种状态**；不要合成一个“坏数据”标签。整批是否接收按预先约定的关键项与覆盖条件决定，不能把只抽检的结论写成全量保证。

## 3. 带数字走一遍：时钟与控制误差

**本文假设算例，非任何产品实测。** 末端以近似恒定速度 `v = 0.25 m/s` 运动，观测与动作错开 `Δt = 0.04 s`，仅平移项就可能对应：

```text
e_time ≈ v × |Δt|
       = 0.25 m/s × 0.04 s
       = 0.01 m = 10 mm
```

若任务给平移错位分配的预算只有 `2 mm`，同样速度下，这个简化模型给出 `|Δt| ≤ 0.002 / 0.25 = 0.008 s = 8 ms`。

这不是完整误差上界：还要考虑旋转、加速度、控制响应、标定和测量误差。正确做法是保留原始时序，测量端到端延迟与漂移，再按任务分配预算；把不同流改成同一帧率不会自动消除错位。

## 4. 触觉＋VLA：增加传感器时多验什么

[PolyUMI](https://arxiv.org/abs/2609.29760v2)记录视觉、触觉和接触音频，并强调采集／执行端感知几何的一致性。接入此类数据时，建议把以下检查独立列出：

- **采集和部署是否看到同一种信号？** 传感器型号、安装姿态、采样和预处理变化都要有记录。
- **零点与漂移是否可重建？** 保存无接触参考、温度或设备状态等实际可测信息；不要只留“已归一化”图像。
- **接触标签从哪里来？** 视频、力阈值、声音和人工判断可能不同步，保留标签来源与不确定区间。
- **有没有故意缺失／损坏模态的验证？** 分别检查掉帧、遮挡和单模态失效时的行为，避免静默填零掩盖故障。
- **模型真正使用了接触信息吗？** 固定任务与训练预算，对照有／无该模态的留出结果；不要把额外数据量误当成传感器贡献。

相关背景：[OmniUMI](../theory/tactile/omniumi_towards_physically_grounded_robot_learning_via_human_dissection.md)、[灵巧手采集](./dexterous_hand_data_collection.md)、[多模态同步](./multimodal_data_synchronization.md)。

## 5. 划分数据时避免“看起来泛化”

按原始 session、操作者、物体实例和场景分组，再设计 train／validation／test。按相邻帧随机拆分会把几乎一样的画面和轨迹分到两侧，不能检验跨环境泛化。

对多来源数据，额外记录：

| 来源类型 | 需要保留的关系 |
|---|---|
| 同一 episode 的 LeRobot／MCAP 导出 | 共用原始身份；两种格式不是两份独立示范 |
| 同一视频的不同切片、镜像和重标版本 | 源视频与时间区间；派生版本随源分组 |
| 人类视频生成的多种机器人形态 | 源示范与合成版本；不能都计入独立实采量 |
| 合并数据集中的重复来源 | 原始数据集／episode ID；先交叉去重再统计 |

例如 [EgoPro 数据卡](https://huggingface.co/datasets/LightwheelAI/EgoPro)明确把 LeRobot 和 MCAP 描述为同一 episodes 的不同表示。数据规范最好直接禁止这种双重计数。

## 6. 算有效成本，不只算录制成本

```text
每合格独立 episode 成本
  = (人员 + 设备摊销 + 场地 + 复位 + 处理/标注 + 质检 + 返工成本)
    / 实际接收的独立 episode 数
```

**本文假设算例，单位为任意成本单位，不是市场报价：**

| 阶段 | 剩余 episode 数 | 本阶段处理 |
|---|---:|---|
| 录制完成 | 100 | 总成本 4,500 |
| 技术可用 | 80 | 排除 20 条时序／标定等不合格记录 |
| 去重完成 | 60 | 再排除 20 条重复或不算独立的派生记录 |
| 标注验收 | 50 | 再隔离 10 条待重标记录 |
| 访问条件／交付清单齐备 | 45 | 再保留 5 条待处理记录 |

原始口径是 `4,500 / 100 = 45`；最终接收口径是 `4,500 / 45 = 100`。这里用实际顺序计数，没有假设各类失效相互独立。后续若追回合格数据或发生返工费用，分子和分母都要更新。

接收率也不能代替学习收益：比较方案时还应固定训练与评测条件，观察新增场景覆盖和留出任务收益。厂商的“每小时成本”如果没有说明复位、标注、去重和验收，暂不能和上式直接比较。

## 7. 开放数据接入前的最小试验

1. 固定数据版本、数据卡、许可／访问条件和 loader 版本。
2. 选取包含不同任务、设备、场景与结果类型的小批次；记录抽样方法，不只挑成功演示。
3. 实际读取每种传感流，核对 episode 边界、时间、标定与动作定义。
4. 做同步回放和数据分布检查，留出人工抽检记录及失败类别。
5. 在不与训练来源重叠的目标任务上做小规模训练比较；报告样本数、训练预算及失败，而非只展示视频。
6. 根据失败类别选择补采、重标、修转换器或更换路线；通过后再扩大规模。

对于 [ABC-130K](https://huggingface.co/datasets/XDOF/ABC-130k)这类多相机／多记录流数据，应按其时间戳和格式说明接入，不能假定各数组同下标就对应同一时刻。本文没有替读者下载数据、接受访问条款或验证其个人使用授权。

## 8. 怎样判断本轮采集真的完成

完成条件应是：交付清单可重建、质量状态可追溯、独立数据量可复算、训练输入能回放，以及预先定义的留出评测有记录。单独的设备运行、上传成功或数据文件数量都不够。

面试 Tip：先说清楚监督信号、独立样本和验证闭环，再回答“要采多少小时”。
